## 先把一个元素放对位置

数组 `[7, 4, 9, 2, 6, 5]` 要升序。以末尾的 `5` 为**主元**，把不大于它的元素放左边，其余放右边，得到 `[4, 2, 5, 7, 6, 9]`。此时只有主元 `5` 的最终位置被确定；左右两边各自还要继续排序。这个“分划、再递归处理两侧”的思路就是快速排序。

下面采用 Lomuto 分划：`pivot` 是区间末元素；`i` 表示“不大于主元”区域的尾端；`j` 逐项扫描。每看见一个不大于主元的值，就扩大左区域并交换到前面。最后把主元放在两个区域之间。

```cpp
int partition(int a[], int left, int right) {
    int pivot = a[right];
    int i = left;
    for (int j = left; j < right; ++j) {
        if (a[j] <= pivot) {
            std::swap(a[i], a[j]);
            ++i;
        }
    }
    std::swap(a[i], a[right]);
    return i;
}
```

每轮扫描时，`[left, i)` 中的元素都不大于主元，`[i, j)` 中的元素都大于主元，`[j, right)` 尚未检查。这个**循环不变量**能帮你检验代码，而不只是记住两个指针的名字。

## 复杂度来自分得均不均

一轮分划要扫描当前区间一次，耗时 $O(n)$。若每轮大致对半分，递归深度约为 $\log n$，每一层的总扫描量仍为 $O(n)$，总时间为 $O(n\log n)$。若每次只分出一个空区间和一个大小为 $n-1$ 的区间，扫描量是 $n+(n-1)+\cdots+1$，总时间为 $O(n^2)$。

用“末元素做主元”的实现，已经有序的数组就会造成极端分划，递归栈最坏需要 $O(n)$ 空间。随机选主元或三数取中可以降低经常遇到坏分划的概率；处理大量重复元素时，三路分划能把等于主元的部分一次放好。快速排序通常不是稳定排序，因为交换可能改变相等元素的先后次序。

## 用数组走一遍

对 `[7, 4, 9, 2, 6, 5]` 使用上面的代码：主元为 `5`，扫描 `7` 时不动；扫描 `4` 时与首位 `7` 交换，变为 `[4, 7, 9, 2, 6, 5]`；扫描 `9` 时不动；扫描 `2` 时与当前位置的 `7` 交换，变为 `[4, 2, 9, 7, 6, 5]`；扫描 `6` 时不动；最后把主元 `5` 与 `9` 交换，得到 `[4, 2, 5, 7, 6, 9]`，主元下标为 `2`。左侧 `[4, 2]` 与右侧 `[7, 6, 9]` 仍要继续排序。
