## 从删除第一个结点开始

假设待办事项顺序是 `A → B → C`。若只用 `head` 指向 `A`，删除 `B` 时让 `A->next` 指向 `C`；删除 `A` 时却必须直接改 `head`。两个位置需要两套逻辑，因为第一个结点没有普通的前驱。

在最前面加一个不存有效数据的**哨位结点** `S`，链就变成 `S → A → B → C`。现在删除 `A` 的前驱是 `S`，删除 `B` 的前驱是 `A`。两种操作都可以写成“让前驱跳过目标结点”。哨位不计入表长；空表就是 `S->next == nullptr`。

## 指针顺序决定是否丢链

在已知 `previous` 指向前驱的前提下，要把新结点 `node` 插入它后面，先让新结点接住原后继，再改前驱：

```cpp
node->next = previous->next;
previous->next = node;
```

如果先执行第二句，原后继地址可能失去访问入口。删除则先保存目标结点，再越过它并释放：

```cpp
Node* removed = previous->next;
if (removed != nullptr) {
    previous->next = removed->next;
    delete removed;
}
```

这里的两段修改都是 $O(1)$；如果题目只给“删除值为 7 的结点”，仍需从头找前驱，总时间为 $O(n)$。这种“定位成本”和“改链接成本”的区分，比背“链表插删是常数时间”更重要。

## 走一遍具体例子

表为 `S → 4 → 7 → 9`，要求删除值为 `7` 的结点。扫描时 `previous` 先指向 `S`，随后指向 `4`；这时 `previous->next` 正好是 `7`。保存 `7`，让 `4->next` 改指 `9`，最后释放原来的 `7`。结果是 `S → 4 → 9`，长度从三变成二。

如果目标是第一个有效结点 `4`，前驱就是 `S`，后面的代码完全相同。若目标不存在，不应解引用空指针；若有多个 `7`，要提前说明删除第一个还是全部。

## 易错边界与下一步

- 空表只有哨位，`S->next` 为 `nullptr`，不能直接读目标结点的数据。
- 哨位负责统一边界，不意味着任何查找都会变成 $O(1)$。
- 删除前要明确结点所有权；示例使用 `new` 创建的结点才用 `delete` 释放。
