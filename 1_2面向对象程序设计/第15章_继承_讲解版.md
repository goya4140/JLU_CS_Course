## 1. 黑盒复用和白盒复用

### 是什么
"复用"就是让一个类去使用另一个已经写好的类的功能，而不是重新写一遍代码。C++ 里有两条实现复用的路径：

- **黑盒复用**：通过"水平关系"——普通关联、聚合、组合、依赖——来复用一个类。之所以叫"黑盒"，是因为使用者只需要知道被复用类"能做什么"（它的公开接口），完全不需要知道它内部是怎么实现的，就像一个封闭的黑盒子。
- **白盒复用**：通过"垂直关系"——也就是继承——来复用一个类。之所以叫"白盒"，是因为派生类和基类之间的耦合更深：派生类清楚地知道基类内部有哪些成员（哪怕访问不了），基类的实现细节对派生类而言是"透明"的。

### 为什么要区分
这两种方式复用的"东西"不一样：
- 黑盒复用复用的是**功能**（通过调用对象的接口）。
- 白盒复用复用的是**实现**（直接把基类的代码"继承"过来，变成自己的一部分）。

### 怎么用（对比示例）

| 黑盒复用（组合/关联） | 白盒复用（继承） |
|---|---|
| `class C { A* mpA; void cfunc1(){ mpA->afunc1(); } };` | `class C : public A { void cfunc1(){ afunc1(); } };` |
| C 通过一个指向 A 的指针来"借用"A 的功能 | C 直接把 A 的实现纳入自身，可以直接调用 `afunc1()` 而不用加对象前缀 |
| 改变 A 的内部实现，不影响 C（只要接口不变） | 派生类与基类实现紧密绑定，基类实现改变可能影响派生类 |

**生活化类比**：黑盒复用就像你雇了一个装修师傅（对象A），你只管告诉他"帮我刷墙"（调用接口），不关心他用什么牌子的漆、怎么刷；白盒复用则像你"继承"了父母的手艺——你不仅会用这门手艺，还清楚地知道这门手艺具体的每一个步骤（继承了实现细节）。

## 2. 继承和派生

### 是什么
继承是指一个新类（**派生类/子类**）在保留已有类（**基类/父类**）全部特性的基础上，再增加一些新特性，或者对基类特性进行调整。

### 语法
```cpp
class <派生类名> : <继承方式> <基类名称>, <继承方式> <基类名称2>, ...
{
    // 派生类自己新增的内容
};
```

例：
```cpp
class Child : public Parent1, private Parent2
{
public:
    Child(int n);
    void childFunc();
private:
    int mData;
    OtherClass* mpOther;
};
```
`public Parent1, private Parent2` 这部分叫**继承列表**，可以同时继承多个基类（多重继承）。

### 关键点

| 概念 | 说明 |
|---|---|
| 继承方式 | `public`、`protected`、`private` 三选一；**不写时默认是 private** |
| 单继承 | 只有一个基类，如 `class B : public A` |
| 多（重）继承 | 两个及以上基类，如上面 Child 的例子 |
| 多层继承 | 派生类本身还可以继续作为基类被别人继承，形成"继承树" |
| 父类/子类 | 只有在 **public 继承**下，才习惯称基类为"父类"、派生类为"子类"（因为只有 public 继承体现出真正的"父子"血缘关系） |

**为什么默认是 private**：这是 C++ 的历史设计，class 关键字默认所有东西都是"最保守/最封闭"的（成员默认 private，继承默认 private），struct 则相反默认 public。写代码时最好总是显式写出继承方式，避免踩到这个默认值的坑。

## 3. 派生类中的成员及访问控制

### 3.1 派生类由哪些成员组成

派生类对象里包含：
1. 派生类自己新定义的成员函数、数据成员；
2. 基类的**所有**成员（**除了**基类的构造函数、析构函数、拷贝构造函数、赋值函数、类型自动转换函数——这几类函数不会被自动继承，派生类要么自己写、要么用编译器生成的默认版本）。

### 例子（教材 P8）

```cpp
class A {
public:
    void afunc1();
    void afunc2();
private:
    static void fA();
    void afunc3();
private:
    int mData;
    static int sDataA;
};

class B : public A {
public:
    void bfunc1() { bfunc3(); }
    void bfunc2();
    static void fB();
private:
    void bfunc3();
private:
    int mNum;
    static int sDataB;
};
```

B 中实际含有的成员：

| 来源 | 成员 |
|---|---|
| B 缺省（自动生成） | 构造、析构、拷贝构造、赋值函数 |
| B 自己定义 | `bfunc1()`、`bfunc2()`、`bfunc3()`、`mNum` |
| 从 A 继承而来 | `afunc1()`、`afunc2()`、`afunc3()`、`mData` |

注意：`A::afunc3()` 虽然是 private，B 也继承了它（存在于 B 对象内部），只是 B 访问不了它。这就引出下面访问控制的问题。

**易混淆点辨析**：不能把"B 继承了 A 的哪些成员"简单理解为"B 只继承了 A 中 sizeof 可计量的数据"，这两者是不同的概念：
- **"继承"看的是成员本身**：无论是非静态数据成员（如 `mData`）、成员函数（如 `afunc1()`），还是静态成员（如 `sDataA`），只要不是构造/析构/拷贝/赋值/自动转换函数，都算被派生类继承了。
- **"sizeof" 看的是每个对象实际占用的内存**：真正会让 `sizeof(B)` 变大的，只有**非静态数据成员**（`mData`、`mNum`）；静态数据成员（`sDataA`、`sDataB`）属于类而不属于对象，不计入 `sizeof`；成员函数（`afunc1()`、`afunc2()`、`afunc3()` 等）本身是共享的一段代码，不管有没有被继承，都**不占用**每个对象的存储空间（除非基类有虚函数，那样每个对象会多一个虚函数表指针 vptr，但那也不是"因为继承了函数"，而是"因为有虚函数机制"）。

简单说：**继承的范围 ≠ sizeof 计量的范围**，函数是被继承了（可以被调用/访问受控），但不占对象的内存空间；只有非静态数据成员才是真正撑大对象体积的部分。

### 3.2 访问控制映射表

派生类中，自己定义的成员按声明的访问符处理；**继承来的成员**则要看"基类中原本的访问级别"和"继承方式"两者共同决定：

| 继承方式 \ 基类中的访问级别 | public | protected | private |
|---|---|---|---|
| **public 继承** | public | protected | 不可访问（/） |
| **protected 继承** | protected | protected | 不可访问（/） |
| **private 继承** | private | private | 不可访问（/） |

**记忆口诀**：
- 基类里的 **private 成员，无论怎么继承，派生类都访问不了**（但它仍然存在于对象内存中）。
- 继承方式决定了"上限"：public 继承不改变原有访问级别（除 private 外），private 继承会把所有能继承下来的成员都"压"成 private，protected 继承会把 public 也"压"成 protected。

### 例子（教材 P10）

```cpp
class Base {
public:
    Base();
    void funcPub();
protected:
    void funcProt();
    int mNum2;
private:
    void funcPriv();
    int mNum1;
};

class Derived : public Base {
public:
    Derived();
    void g1();
protected:
    void g2();
    int mVal2;
private:
    void g3();
    int mVal1;
};
```

`Derived` 的构造函数体内：

| 语句 | 是否合法 | 原因 |
|---|---|---|
| `funcPub();` | 合法 | 继承自基类的 public 成员 |
| `funcProt();` | 合法 | 继承自基类的 protected 成员，派生类内部可访问 |
| `funcPriv();` | **非法** | 基类 private 成员，派生类无权访问 |
| `mNum2 = 5;` | 合法 | protected 数据成员，派生类内部可访问 |
| `mNum1 = 6;` | **非法** | 基类 private 数据成员 |
| `g1(); g2(); g3();` | 都合法 | 都是派生类自己的成员，在类内部访问不受限 |

### 一个值得思考的问题（PPT 原文留的思考题）
> 既然基类中 private 的成员在派生类中都不可访问，为什么派生类对象里还要"带着"这些不可访问的基类数据成员和函数？

**解答**：因为这些 private 成员仍然是基类对象"完整状态"的一部分。基类自己的成员函数（比如 `funcPriv()`）在运行时仍然需要操作 `mNum1` 这类数据。如果派生类对象中不保留它们，那基类留下来的那部分功能（哪怕派生类看不见）就无法正常工作了——毕竟一个 Derived 对象在逻辑上"包含"一个完整的 Base 子对象。

## 4. 派生类的构造和析构函数

### 是什么、为什么
基类的构造、析构、拷贝构造、赋值、类型自动转换函数**不会被派生类自动继承**——这些函数太"特殊"了，它们跟"这个类自己是谁"强相关，不适合直接照搬给派生类用。

因此：
- 如果派生类没有显式写构造函数，编译器会生成一个默认构造函数，它会自动调用基类的默认构造函数。
- 如果派生类想用基类某个"非默认"的构造函数来初始化基类部分，就必须在**初始化列表**里显式指定。

### 构造/析构顺序（核心结论）

- **构造**：先构造基类部分，再构造派生类部分（多重继承时按继承列表书写的先后顺序依次构造各个基类）。
- **析构**：顺序完全相反——先析构派生类部分，再自动析构基类部分。

这是符合逻辑的：派生类的东西是"建立在"基类之上的，所以造房子先打地基（基类）再盖楼（派生类）；拆房子则要先拆楼再拆地基。

### 例子（教材 P12）

```cpp
class Base {
public:
    Base(int n) : mNum(n) { ++mNum; funcPriv(); }
    ~Base() { --mNum; funcPriv(); }
private:
    void funcPriv() { cout << mNum; }
    int mNum;
};

class Derived : public Base {
public:
    Derived(int n1, int n2) : Base(n1), val(n2) { }
    ~Derived() { cout << val; }
    int val;
};

int main() {
    Derived d(1, 99);
    return 0;
}
// 输出：2 99 1
```

**逐步拆解输出为什么是 `2 99 1`**：
1. `Derived d(1,99)` 触发构造：初始化列表先调用 `Base(1)` → `mNum=1`，`++mNum` 变成 2，`funcPriv()` 输出 `2`。
2. 基类构造完成后，`val(n2)` 把 `val` 设为 99，Derived 构造体为空，不再输出。
3. `main` 结束，`d` 被销毁：先执行 `~Derived()`，输出 `val` 即 `99`。
4. 再自动执行 `~Base()`：`--mNum` 变回 1，`funcPriv()` 输出 `1`。

所以整体输出顺序是 `2`（Base构造）→`99`（Derived析构）→`1`（Base析构）。

## 5. 派生类的拷贝构造和赋值函数

### 是什么、为什么
和普通构造函数一样，拷贝构造函数、赋值运算符也不会被自动继承。如果派生类自己写了拷贝构造/赋值函数，**必须手动负责把基类那部分数据也拷贝/赋值好**，否则基类的数据成员会用"默认方式"处理，可能不符合预期（尤其涉及指针、资源管理时）。

### 怎么用（关键写法对照）

| 场景 | 正确写法 | 说明 |
|---|---|---|
| 拷贝构造 | `B(const B& other) : A(other) { mNum = other.mNum; }` | 在初始化列表里显式调用 **A 的拷贝构造函数**，把基类部分交给基类自己处理 |
| 赋值函数 | `A::operator=(rhs); mNum = rhs.mNum;` | 显式调用基类的 `operator=`（要写明作用域 `A::`，否则会被认为在调用自己） |

### 例子（教材 P13）

```cpp
class A {
public:
    A(int num) : mData(num) { }
    int getData() const { return mData; }
    operator float() { return 0.6 * mData; }
protected:
    int mData;
};

class B : public A {
public:
    B(int n1, int n2) : A(n1), mNum(n2) { }
    ~B() { }
    B(const B& other) : A(other) { mNum = other.mNum; }
    B& operator=(const B& rhs) {
        if (this != &rhs) {
            A::operator=(rhs);
            mNum = rhs.mNum;
        }
        return *this;
    }
private:
    int mNum;
};
```

**易错点**：很多初学者写拷贝构造时忘了在初始化列表里写 `A(other)`，这样基类部分就会走**默认构造**而不是拷贝，`mData` 值就丢了、没能正确复制。

## 6. newdefine、redefine、overload、overwrite(hide)、override

这五个词长得像、意思却不同，是本章最容易混淆的点。先给出总览，再逐个讲。

### 是什么（对比表）

| 术语 | 含义 | 判断依据 |
|---|---|---|
| **newdefine** | 派生类新定义的函数，基类中**没有**同名函数 | 名字在基类中查无此"号" |
| **redefine** | 派生类新定义的函数，基类中有**同名同原型**的函数（完全一致的签名） | 名字、参数都一样 |
| **overload**（重载）| 派生类（或同一个类）中**多个同名**但参数列表不同的函数 | 同名不同参 |
| **overwrite / hide**（隐藏）| 派生类定义了某函数，只要**名字和基类中的某函数相同**（参数是否相同不影响），基类中**所有同名**函数（包括重载的多个版本）都会被隐藏，在派生类作用域内不可直接调用 | 只要重名就整组隐藏 |
| **override**（覆盖，C++11起可加 `override` 关键字）| 基类中该函数是 **virtual**（虚函数），派生类定义了同名同签名的函数 | 前提：基类函数必须是 virtual |

### 为什么这几个概念容易搞混

关键在于 **overwrite/hide 和 overload 的边界**：C++ 的名字查找规则是"作用域优先"——只要派生类作用域里出现了一个和基类同名的标识符，编译器在派生类作用域内查找这个名字时，**根本不会往基类的作用域里继续找同名的重载版本**，哪怕参数完全不同也一样会被"连坐"隐藏掉。这跟很多人以为的"重载版本互不干扰"的直觉是相反的，所以特别容易出错。

### 例子（教材 P15）

```cpp
class A {
public:
    void f();
    void f(int n);
    void g();
    virtual void h();
private:
    void k();
    int data;
};

class B : public A {
public:
    void bf() { }              // newdefine：A中没有bf
    void g() { }                // redefine：与A::g()同名同参数

    void f(int n, int m) {      // overwrite了A中所有的f（包括f()和f(int)）
        f();      // 非法！B作用域内的f只有f(int,int)这一个
        f(n);     // 非法！同上
        // 解决办法：using A::f;
    }

    virtual void h()             // override：h在A中是virtual
    { /* ... */ }
};
```

**解决 overwrite 问题的写法**：
```cpp
class B : public A {
public:
    using A::f;   // 把A中所有的f都"拉"进B的作用域，恢复可见性
    void f(int n, int m) { ... }
};
```
加了 `using A::f;` 之后，`f()`、`f(int)`、`f(int,int)` 在 B 中都能直接调用了。

## 7. 继承的含义

### 是什么
不同的继承方式，表达的是不同的**逻辑关系**，不是随便选的：

| 继承方式 | 表达的逻辑关系 | 举例 |
|---|---|---|
| `public` | **"is a"、"is a kind of"、"like a"**（是一个……） | MTCar "is a" Car（手动挡汽车是一种汽车） |
| `private` | **"has-a"、"contain-a"、"implement of"**（有一个/用……来实现） | Player "has-a" Bike（运动员有一辆自行车，或者说运动员的移动行为借助了自行车的实现） |
| `protected` | 与 private 含义相同，但在**多层继承**中能把这种"有一个"的关系继续往下传 | Bag → Box → Pen 三层，Pen 的成员对 Bag 依然保持 protected |

**共同点**：无论哪种继承方式，**基类的源代码都必须存在**（因为白盒复用要拿到实现代码），这一点区别于组合——组合时子对象所属类可以只有头文件/接口，不一定需要源码。

### 例子对照：public vs private 继承的语义差异

| public 继承（is-a） | private 继承（has-a） |
|---|---|
| `class MTCar : public Car { ... };` | `class Player : private Bike { ... };` |
| MTCar 对象**本身就是**一辆 Car，可以在任何需要 Car 的地方直接传一个 MTCar 对象进去 | Player **不是**一辆 Bike，只是内部借用了 Bike 的功能来实现"移动"，外部不能把 Player 当 Bike 用 |

### public 继承的"方便之处"（例子，教材 P19）

```cpp
class Car { ... };
class MTCar : public Car { ... };
class ATCar : public Car { ... };

class My {
public:
    My(Car& c) { mpCar = &c; }
    void func(Car& c) { c.run(); }
private:
    Car* mpCar;
};

int main() {
    Car car;
    MTCar mtcar;
    ATCar atcar;
    My mycar(atcar);       // 传ATCar对象，可以！
    mycar.func(mtcar);     // 传MTCar对象，也可以！
}
```

因为 MTCar、ATCar 都 **is-a** Car，所以凡是"需要一个 Car"的地方（比如函数形参是 `Car&`），实际传一个 Car、MTCar 或 ATCar 对象都合法——这种"能互相替代"的便利性，是黑盒复用（水平关联）无法做到的。这也是面向对象里**多态**得以成立的基础（虽然本章还没正式讲多态，但这里已经埋下了伏笔）。

## 8. 继承和组合的选择

### 组合 vs 继承 —— 核心对比

| | 组合（黑盒复用） | 继承（白盒复用） |
|---|---|---|
| 逻辑关系 | has-a / contain-a | public: is-a；private/protected: has-a（等价于组合） |
| 子对象类的源码要求 | 可有可无（只需接口） | **必须有源码** |
| 类之间的关系 | 水平关系，层次更浅 | 垂直关系，容易形成较深的继承树 |
| 灵活性 | 运行时可以换成员对象（如换一辆 Bike） | 编译期绑定，改起来更"僵硬" |

### 怎么选（PPT 结论）
- **优先选择组合，而不是继承。**
- 只有在**确实需要 is-a 关系**、需要利用多态/需要派生出新的子类去替代基类使用的场景，才应该采用 **public 继承**。
- 如果只是想"借用"某个类的实现（has-a 语义），**用组合替代 private/protected 继承**几乎总是更好的选择，因为组合耦合更松、类的层次更浅、更容易维护。

### 例子：用组合改写 private 继承（教材 P20 → P23）

| private 继承写法 | 组合改写后 |
|---|---|
| `class Player : private Bike { void startRace(){ Move(); } };` | `class Player { Bike mBike; void startRace(){ mBike.move(); } };` |
| Player "隐式"拥有一辆 Bike 的全部实现，且不能对外暴露 Bike 的接口 | Player 显式持有一个 `Bike` 类型的成员对象 `mBike`，通过 `mBike.move()` 调用功能，语义更直观，也更容易替换成别的交通工具 |

**为什么这个改写更好**：private 继承本质上只是"拿继承的语法来实现 has-a"，但它带来了继承特有的复杂性（比如构造/析构顺序、访问控制表这些规则都要遵守），却没享受到 public 继承 is-a 带来的多态好处。用组合，一样能达到"复用实现"的目的，代码却更清晰、耦合更低。

## 本章小结

1. **复用分两条路**：黑盒复用（关联/聚合/组合/依赖，水平关系，复用功能）和白盒复用（继承，垂直关系，复用实现）。
2. **继承语法**：`class 派生类 : 继承方式 基类 { };`，继承方式默认为 private；可单继承也可多继承；派生类还能继续被别人继承（多层继承）。
3. **派生类成员 = 自己定义的 + 基类继承来的**（基类的构造/析构/拷贝/赋值/自动转换函数不算在内）；访问权限由"基类原有访问级别"和"继承方式"两者共同决定，牢记那张三行三列的映射表。
4. **构造先基类后派生类，析构顺序相反**——这是保证对象"从底层到上层"正确建立、"从上层到底层"正确销毁的基本原则。
5. **拷贝构造和赋值函数不会自动继承基类的对应部分**，必须在初始化列表或函数体中显式调用基类版本，否则基类那部分数据处理会不符合预期。
6. **newdefine / redefine / overload / overwrite(hide) / override 要分清**：核心区别在于"基类中有没有同名函数"“是否virtual”“是否会连带隐藏基类所有重载版本”；被 hide 掉的基类函数可以用 `using 基类::函数名;` 找回来。
7. **继承方式即语义**：public = is-a（能被当作基类对象使用，是多态的基础），private/protected = has-a（等价于组合，但耦合更紧）。
8. **选型原则**：优先用组合；只有确实需要 is-a 关系、需要向上转型或多态时，才使用 public 继承。
