## 一、自定义构造函数

### 1.1 构造函数是什么？

**类比理解**：如果把"类"看作一张空白的产品设计图，那么"对象"就是按图纸造出来的实体产品。构造函数就是产品出厂前的"装配工序"——在产品（对象）被造出来的**同一时刻**，把各个零件（数据成员）都安装、赋上初值，让对象一诞生就是"可用状态"，而不是一堆没有初始化的垃圾内存。

### 1.2 语法格式（三个硬性规定）

| 规则 | 说明 |
|---|---|
| 名字 | 必须和类名完全相同 |
| 返回值 | 没有返回值，连 `void` 都不写 |
| explicit | 可选关键字，用来禁止"隐式类型转换" |

```cpp
class Name {
public:
    Name();                      // 无参构造
    explicit Name(int val);      // 单参数，禁止隐式转换
    Name(int, int);              // 双参数
private:
    Name(Other& other);          // 也可以是私有的
};
```

### 1.3 构造函数的四个自由度

- **可重载**：一个类可以有多个构造函数，只要参数列表不同（个数或类型不同）。
- **可设置不同访问控制**：可以是 `public`（正常创建对象），也可以是 `private`（不允许外部直接创建，常用于单例模式）。
- **可选 `explicit` 关键字**：只对**单参数**（或除第一个外其余参数都有默认值）的构造函数有意义，作用是**禁止编译器做隐式类型转换**。
- **可带缺省参数**：和普通函数一样，可以给参数设默认值。

### 1.4 explicit 的作用——为什么要"禁止隐式转换"？

**生活化类比**：假设你的类是"人民币"，构造函数 `RMB(int fen)` 接收"分"。如果不加 `explicit`，别人写 `void pay(RMB r)`，然后调用 `pay(100)`，编译器会"自作主张"地把整数 100 隐式转换成 `RMB(100)` 传进去——这在很多场景下是危险的（明明想传的是"件数"却被当成了"金额"）。加上 `explicit` 后，这种"偷偷摸摸"的转换会被禁止，必须显式写 `pay(RMB(100))`。

```cpp
class Name {
public:
    Name();
    explicit Name(int);
    Name(Other& other);
private:
    Name(int val, int);
};
void f(const Name & o) { }

int main() {
    Name obj1;             // 调用无参构造
    Name obj2(100);        // 调用 explicit Name(int)
    Other oth;
    Name obj3(oth);        // 调用 Name(Other&)
    f(100);                // ❌ 报错！explicit 禁止了 int→Name 的隐式转换
    f(obj2);                // ✅ OK，obj2 本来就是 Name 类型
    Name obj4(1, 2);        // ❌ 报错！Name(int val,int) 是 private
}
```

### 1.5 带缺省参数引发的"二义性问题"

当一个类里同时存在多个构造函数，而其中某些构造函数的参数是"可省略"的，就容易出现**编译器不知道该调用哪一个**的情况，这叫**二义性（模棱两可）**。

| 反例：三个构造函数并存，产生歧义 | 正例：合并为一个带缺省值的构造函数 |
|---|---|
| ```cpp<br>class Name {<br>public:<br>  Name();<br>  Name(int v1);<br>  Name(int v1,int v2=999);<br>  ...<br>};``` | ```cpp<br>class Name {<br>public:<br>  Name(int v1=0,int v2=999);<br>  ...<br>};``` |

```cpp
int main() {
    Name obj1;            // OK，调用 Name()
    Name obj2(200);       // ❌ 二义性错误：Name(int v1) 和
                           //    Name(int v1,int v2=999) 都能匹配
    Name obj3(100, 400);  // OK，只有一个构造函数能匹配两个参数
}
```

> **记忆要点**：只要编译器面对一次调用，能找到**不止一个"同样合适"**的候选构造函数，就报二义性错误。解决办法通常是**只保留一个带缺省参数的构造函数**，而不是写多个功能重叠的构造函数。

### 1.6 私有构造函数的应用——单例模式

把构造函数设为 `private`，外部就无法直接 `new` 或声明该类对象，只能通过类提供的**静态成员函数**来获取唯一的实例。这是设计模式中经典的"单例模式（Singleton）"。

```cpp
// 版本一：返回引用（对象存在于静态区，程序结束自动析构）
class Name {
public:
    static Name & create() {
        static Name obj;      // 只在第一次调用时构造
        return obj;
    }
private:
    Name() { }
};

int main() {
    Name & obj = Name::create();
}
```

```cpp
// 版本二：返回指针（对象存在于堆区，需要手动释放）
class Name {
public:
    static Name * create() {
        static Name * pObj = nullptr;
        if (pObj == nullptr) pObj = new Name;
        return pObj;
    }
    static void release() {
        delete pObj;
        pObj = nullptr;
    }
private:
    Name() { }
    static Name * pObj;
};
Name * Name::pObj = nullptr;   // 静态成员类外初始化

int main() {
    Name * pObj = Name::create();
    Name::release();
}
```

> **理解要点**：单例模式保证"全程序只存在一个该类对象"，靠的正是把构造函数私有化，切断外部创建对象的通路。

## 二、缺省的构造函数

### 2.1 什么是"缺省构造函数"

当你**没有为类写任何构造函数**时，编译器会**自动**免费送你一个：
- 无参数
- `public` 访问权限
- 什么也不做（对内置类型成员不做初始化）

这就是所谓"缺省（默认）构造函数"。

### 2.2 一旦满足下列任一条件，缺省构造函数就会"消失"

| 情况 | 代码示例 | 结果 |
|---|---|---|
| 用户自定义了带参数的构造函数 | `A(int n) { }` | 编译器不再提供无参构造，`A a;` 报错 |
| 用户把构造函数声明为 private | `private: A(int n){}` | 外部无法创建对象 |
| 只声明没实现 | `A(int n);` （无函数体） | 链接时报错 |
| 显式禁用 | `A() = delete;` | 明确告诉编译器：不允许无参构造 |
| 只自定义了拷贝构造函数 | `A(const A&) {...}` | C++新标准下，这也会阻止缺省构造函数的生成 |

```cpp
class A {
public:
    A(int n) { }
};

int main() {
    A a;   // ❌ 报错！只要用户提供了任意一个自定义构造函数，
           //    编译器就不再自动生成无参构造函数
}
```

> **记忆口诀**："自己动手，丰衣足食" —— 只要你写了一个构造函数（不管什么样），编译器就认为你已经"接管"了初始化工作，不再帮你兜底。

## 三、对象的初始化——三种写法

一个对象的数据成员，理论上有三条初始化途径：

```
class Card {
public:
    Card(int aId) {
        mX = 0;      // 方式一：构造函数体内赋值
        mY = 0;
    }
private:
    int mX;
    int mY;
};
```

### 方式一：构造函数体内赋值
最直观，写在 `{ }` 里面。但要注意：这**已经不算"初始化"，而是"赋值"**——对象已经存在（哪怕值是垃圾值），你只是又给它赋了一次值。对于 `const` 成员和引用成员，这种方式行不通（后面会讲原因）。

### 方式二：C++1z（即C++17）类内指定初值
直接在成员声明处写 `= 初值`，作为"没有在初始化列表里指定时"的默认取值。

```cpp
class Card {
public:
    Card(int aId, Player& aPlayer)
        : player(aPlayer)
    { }
private:
    float mX = 5;                          // ✅ 类内初值
    float mY = 6;
    const float mDdelta = 0.1;             // ✅ const 也可以
    const int mID = 100;
    static const int CARD_COUNT = 52;      // ✅ 静态常量整型
    Player& player;                        // 引用不推荐类内初值
    static const float AA = 99.88;         // ❌ 错误！static const 浮点型不能类内初始化
    static int bb = 10000;                 // ❌ 错误！非 const 静态成员不能类内初始化
    inline static int cc = 200;            // ✅ C++17 起，inline static 可以
};
```

### 方式三：构造函数的初始化列表
写在构造函数参数列表和函数体之间，用 `:成员名(初值)` 的形式罗列。

## 四、初始化列表——为什么、必须用在哪

### 4.1 反例：为什么"体内赋值"会出问题

```cpp
class Card {
public:
    Card(int aId, Player& aPlayer) {
        mX = 0; mY = 0;
        mID = aId;           // ❌ 错误！const 成员不能被赋值
        mPlayer = aPlayer;   // ❌ 错误！引用不能被重新绑定
    }
private:
    int mX;
    int mY;
    const int mID;           // 常量成员
    Player& mPlayer;         // 引用成员（不建议使用引用作为成员）
};
```

**为什么会错？** `const` 成员的值一旦确定就不能再变；引用成员从"出生"起就必须绑定到一个具体对象，且终生不能改绑。而构造函数体内的语句属于"函数已经开始执行之后"的赋值操作，此时对象早已构造完毕，`mID`、`mPlayer` 早就"定型"了，再赋值当然不行。

### 4.2 正例：用初始化列表

```cpp
class Card {
public:
    Card(int aId, Player& aPlayer)
        : mX(99), mID(aId), mPlayer(aPlayer), mDesc(aId)
    {
        mY = 88;   // 普通成员也可以放在函数体里赋值
    }
private:
    int mX;
    int mY;
    const int mID;
    Player& mPlayer;      // 不建议使用
    Description mDesc;    // 对象成员
};
```

### 4.3 必须使用初始化列表的三种成员

| 成员类型 | 是否必须用初始化列表 | 原因 |
|---|---|---|
| 普通数据成员（int、float…） | 可选 | 函数体内赋值也可以 |
| **常量数据成员（const）** | **必须** | 值一旦确定不可更改，只能"初始化"不能"赋值" |
| **引用数据成员** | **必须** | 引用必须在诞生时就绑定对象，不能事后绑定 |
| **对象数据成员（无无参构造函数时）** | **必须** | 若该成员类没有无参构造函数，编译器不知道该怎么"先造出来再赋值" |

```cpp
class Description {
public:
    Description(int n);   // 只有带参构造，没有无参构造
};
// 所以 Card 的成员 mDesc 必须在初始化列表中显式调用 Description(int)
```

### 4.4 数据成员的真实初始化顺序 ⚠️（易错点）

很多初学者以为"初始化列表写的顺序决定初始化顺序"，**这是错的**！真实规则如下：

1. **严格按照成员在类中"定义"的顺序**依次初始化（和初始化列表里写的先后顺序**无关**）；
2. 对每个成员，先去初始化列表里找有没有指定初始化方式：
   - 找到了 → 按列表里指定的初始化；
   - 没找到，但类内有指定初值（方式二）→ 按该初值初始化；
   - 都没有 → 尝试调用该成员类型的**无参构造函数**初始化（内置类型此时值不确定，处于栈内的垃圾值状态）；
   - 如果连无参构造函数都没有 → **编译报错**；
3. 全部数据成员初始化完毕后，才真正进入构造函数 `{ }` 里的语句。

```cpp
class Card {
public:
    Card(int aId, Player& aPlayer)
        : mDesc(aId), mX(99), mID(aId), mPlayer(aPlayer)   // 写的顺序是 mDesc→mX→mID→mPlayer
    {
        mY = 88;
    }
private:
    int mX;              // 但实际初始化顺序按"定义顺序"：
    int mY;               // mX → mY → mID → mPlayer → mDesc
    const int mID;
    Player& mPlayer;
    Description mDesc;
};
```

> ⚠️ **强调**：无论初始化列表里写成什么顺序，编译器都会按照**成员在类体中声明的先后顺序**去初始化。如果初始化列表的书写顺序和成员声明顺序不一致，很多编译器会给出警告（如 `-Wreorder`），这是非常经典的坑。

### 4.5 C++11 委托构造（Delegating Constructor）

**是什么**：一个构造函数可以在初始化列表中"委托"调用**本类的另一个构造函数**，避免多个构造函数中重复相同的初始化代码。

| 反例：多个构造函数重复代码 | 正例：委托构造，复用代码 |
|---|---|
| ```cpp<br>class AA {<br>public:<br>  AA(int n) { ... }<br>  AA(int n,const string& str) { ... }<br>  AA(const Dog& dog) { ... }<br>};``` | ```cpp<br>class AA {<br>public:<br>  AA(int n): AA(n,"张三") { ... }<br>  AA(int n,const string& str) { ... }<br>  AA(const Dog& dog) { ... }<br>};``` |

**类比理解**：就像装修新房子有"标准套餐"和"豪华套餐"，豪华套餐可以说"先按标准套餐装修一遍，再额外加装吊灯"——`AA(int n)` 委托给 `AA(int n, "张三")`，相当于说"先按双参数版本走一遍流程，再做点自己的事"。

## 五、析构函数

### 5.1 是什么

析构函数负责在**对象销毁前**做最后的清理工作（比如释放对象内部申请的堆内存、关闭文件句柄等）。它执行完自己的代码后，还会**自动**帮你把所有数据成员依次释放：
- 如果成员是**对象类型**，自动调用该成员的析构函数；
- 如果是内置类型（int、指针本身等），直接回收内存（注意：指针指向的堆内存不会自动 `delete`，需要你在析构函数里手动写）。

### 5.2 格式

| 规则 | 说明 |
|---|---|
| 名字 | `~类名` |
| 参数 | 无（不能重载，一个类只能有一个析构函数） |
| 返回值 | 无 |
| 访问控制 | 一般为 `public` |

```cpp
class Card {
public:
    Card(int aId, Player& aPlayer);
    ~Card();
    ...
private:
    int mX;
    int mY;
    const int mID;
    Player& mPlayer;
    Description mDesc;
};
```

### 5.3 缺省析构函数

和构造函数类似，如果你不写析构函数，编译器会自动提供一个**默认的、`public`** 的析构函数，只是它什么"额外"清理工作都不做（仅做成员的自动释放）。

## 六、构造和析构函数的访问

### 6.1 总览

| 操作 | 触发的函数 |
|---|---|
| 创建对象 | 构造函数 |
| 销毁对象 | 析构函数 |

### 6.2 构造函数的三种访问方式

- **显式调用**：直接写 `A a(5);`，明明白白告诉编译器要调用哪个构造函数。
- **隐式调用（自动转换）**：没加 `explicit` 的单参数构造函数，可以被编译器"偷偷"用来做类型转换。
- **对象成员的创建**：一个类里包含另一个类的对象作为成员时，成员对象的构造函数会在外层对象构造时被自动调用（初始化列表环节）。

### 6.3 析构函数的两种触发方式

| 存储区域 | 何时析构 |
|---|---|
| 程序区（静态/全局对象）、栈区（局部对象） | 生存期结束后**自动**执行，无需程序员操心 |
| 堆区（`new` 出来的对象） | 必须**显式调用 `delete`**，否则不会析构，造成内存泄漏 |

### 6.4 综合示例

```cpp
class B {
public:
    B();
    explicit B(int n);
};

class A {
public:
    A();
    A(int n);
    void method(const B & aB);
    ~A();
private:
    int num;
    B b1;
    B b2;
    static B globalB;
};

B A::globalB(200);              // 静态对象，存放在数据区，程序启动时构造

A::A(): num(0), b2(2) { }                 // b1 用 B() 无参构造（未列出）
A::A(int n): num(n), b1(n), b2(n+1) { }   // b1、b2 分别显式构造

void func() {
    A a1;                        // 栈对象，func结束时自动析构
    A a2(5);                     // 栈对象
    A * pa = new A(8);           // 堆对象
    pa->method(2);                // ❌ 报错！B 的 explicit B(int) 要求显式调用，
                                   //    method 参数是 const B&，2 不能隐式转成 B
    delete pa;                    // 必须手动 delete，否则内存泄漏、~A() 不会执行
}

int main() {
    A a0;        // 栈对象
    func();
    return 0;
}
```

**逐行理解要点**：
1. `A::globalB` 是类的静态成员，在类外初始化，存放在**数据区**，程序运行期间始终存在。
2. 两个构造函数 `A()` 和 `A(int n)` 分别通过初始化列表给 `num`、`b1`、`b2` 赋初值；没在列表里写的成员（如第一个构造函数里的 `b1`）会调用其**无参构造函数**。
3. `pa->method(2)` 报错的原因：`B` 的单参数构造函数带了 `explicit`，禁止了 `int → B` 的隐式转换，而 `method` 需要一个 `const B&`。
4. `a1`、`a2`、`a0` 都是栈上局部/自动对象，生存期结束（函数返回）时自动析构；`pa` 指向堆对象，**必须**手动 `delete pa` 才会触发 `~A()`。

## ✅ 本章小结

1. **构造函数**在对象创建的同时完成初始化，名字与类名相同、无返回值，可以重载、可设不同访问权限、可选 `explicit`、可带缺省参数。
2. **`explicit`** 用来禁止单参数构造函数被用于隐式类型转换，避免"不小心"发生的类型转换。
3. **缺省构造函数**只有在用户**完全没有**自定义任何构造函数（含拷贝构造）时，才由编译器自动提供；写了任意一个构造函数、或用 `= delete`、或把构造函数设为 `private`，都会导致它"消失"。
4. **对象初始化有三种方式**：构造函数体内赋值、C++17类内指定初值、构造函数初始化列表——其中初始化列表功能最全，能力最强。
5. **`const` 成员、引用成员、没有无参构造函数的对象成员**，这三类**必须**通过初始化列表来初始化，函数体内赋值会报错。
6. **成员的初始化顺序由"类中声明的顺序"决定**，与初始化列表书写顺序无关——这是最容易出错的知识点之一。
7. **C++11 委托构造**允许一个构造函数调用本类的另一个构造函数，减少重复代码。
8. **析构函数**格式为 `~类名()`，无参数无返回值，一般为 `public`，负责对象销毁前的清理工作，会自动级联析构对象类型的成员。
9. **析构函数的触发时机**：栈区/静态对象生存期结束时自动执行；堆区对象必须显式 `delete` 才会触发，否则内存泄漏。
10. **私有构造函数**是实现单例模式的关键手段，外部只能通过类提供的静态函数获取唯一实例。
