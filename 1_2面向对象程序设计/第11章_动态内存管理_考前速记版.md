## 一、存储空间与静态存储

| 区域 | 内容 | 释放方式 |
|---|---|---|
| 全局/常量数据区 | 全局变量、全局常量、static变量 | 程序结束自动 |
| 栈区 | 局部自动变量 | 作用域结束自动 |
| 堆区（动态） | new出来的对象 | 必须手动delete |

**★★★ 静态存储三大不足（易考选择/简答）**：
1. 栈区容量有限
2. 生存期/作用域不灵活（构造参数一旦定死无法改）
3. 对象数组三限制：① 大小必须编译期常量 ② 元素类型/大小必须一致 ③ 通常要求无参构造函数
4. （附加）增大类间编译期依赖，成员对象需要 `#include` 完整定义，不能只用前向声明

**易错辨析**：
- `static A obj;`（类外初始化）✅ 可传参，因为是单独初始化语句
- `A aA;` 作为成员，可在初始化列表里传参 ✅
- `A objs[50];` ❌ 若A无无参构造函数则编译失败（数组批量构造只能调无参构造）

## 二、单对象动态分配及释放 ★★★

### new 的语法
```cpp
T * p = new T(参数);   // T可以是内置类型/自定义类型/指针类型
```

### ★★★ new 的3步过程（高频考点，务必背熟顺序）
1. 调用 `static void* operator new(size_t)` 申请裸内存（失败→跳转 `new_error_handle`）
2. 执行构造函数 `T::T(ptr, 参数...)`
3. `void*` 转 `T*` 返回

### ★★★ delete 的3步过程（顺序与new相反）
1. 判空，`nullptr` 直接退出
2. 先执行析构函数 `T::~T()`
3. 再调用 `operator delete(void*)` 释放内存

| 记忆口诀 | 内容 |
|---|---|
| new | 先要空间，后造对象 |
| delete | 先拆对象，后还空间 |

**易错点**：不能颠倒顺序去理解——delete时必须先析构，再释放内存，否则析构函数无法访问对象数据。

`set_new_handler` 用于自定义内存分配失败时的处理函数（理解即可，不深究写法）。

## 三、重载 operator new / operator delete ★★★

**★★★ 核心规则（必考）**：
- 无论是否写 `static`，`operator new`/`operator delete` **一定是静态成员函数**（因为调用时对象尚未构造或已析构，没有this）
- 若类未显式重载，默认使用**全局的** `::operator new` / `::operator delete`
- 可以重载多个 `operator new`（参数不同，类似函数重载），调用时按参数匹配

```cpp
class A {
public:
    void * operator new(std::size_t);                      // 版本1
    void * operator new(std::size_t, const string&);         // 版本2
    void   operator delete(void *);                          // 版本3
};

A * p1 = new A(9);          // 调用1
A * p2 = new("张三") A(8);   // 调用2
delete p2;                    // 调用3
```

**典型应用**：在 `operator new` 中多申请几字节存统计信息（如累计创建/释放次数），常考"计算最终 newCount/deleteCount/existCount 值"的追踪题。

**判断技巧**：
- `newCount` = 累计 new 的次数（含拷贝构造产生的new）
- `deleteCount` = 累计 delete 的次数
- `existCount`（某对象创建时）= 创建那一刻，`newCount - deleteCount - 1`（不含自己）

## 四、数组的动态分配及释放 ★★★

### 语法与过程
```cpp
T * p = new T[size];   // 1.申请空间 2.执行size次无参构造 3.转换返回
delete[] p;              // 1.判空 2.执行多次析构 3.释放空间
```

**★★★ 极易考的对比（静态数组 vs 动态数组）**：

| | `const int N=50; T objs[N];` | `int n=50; T*p=new T[n]; delete[]p;` |
|---|---|---|
| 大小要求 | 必须编译期常量 | 可运行时变量 |
| 存放区域 | 栈/全局区 | 堆区 |
| 释放 | 自动 | 手动delete[] |

**★★★ 易错点（考试常设陷阱）**：`new T[n]` 分配的内存**必须用 `delete[]` 释放，绝不能用 `delete`**！混用是未定义行为（只析构第一个元素，其余泄漏）。

### 对象数组三种实现方式对比 ★★★

| 方式 | 写法要点 | 要求无参构造？ | 大小可运行时定？ |
|---|---|---|---|
| 值数组 | `Card cards[54];` | ✅要求 | ❌不可 |
| 指针数组 | `Card* cards[54];`，构造/析构中 for循环 new/delete | ❌不要求 | ❌不可（指针数组本身大小固定） |
| 动态指针数组 | `Card** cards;`，先`new Card*[54*num]`再逐个new | ❌不要求 | ✅可以 |

**记忆技巧**："放开一个限制就多套一层指针"：值数组→指针数组（放开构造要求）→动态指针数组（再放开大小限制）。

## 五、智能指针和共享指针 ★★★

### auto_ptr（了解，C++17已废弃，不深考写法，但理解思想）
核心思想：把裸指针包装进对象，利用对象析构自动调用 `delete`，避免忘记释放。

### ★★★ shared_ptr 标准库用法（高频实操题）
```cpp
shared_ptr<A> pA = make_shared<A>(3);   // 推荐用make_shared，保证堆区分配
pA->getN();       // 成员访问
(*pA).getN();      // 等价写法
pA.get();          // 获取原始指针
```

**易错点**：`shared_ptr<A>(new A(3))` 不如 `make_shared<A>(3)` 推荐（前者理论上多一次内存操作且异常安全性较差）。

### ★★★ shared_ptr 内部结构（必考图示题）
```
shared_ptr<A> pA
├── 实际对象指针 → 真实分配的对象
└── 引用计数指针 → 引用计数（0,1,2,...；减到0才释放对象）
```

**判断规则**：拷贝构造/赋值 → 计数+1；析构/改变指向 → 计数-1；计数为0 → 真正delete对象。

**考点**：类成员若用 `shared_ptr` 代替裸指针，**编译器默认生成的拷贝构造/赋值函数即可正确工作**（逐成员拷贝会自动调用shared_ptr自身的拷贝/赋值，正确增减计数），不需要程序员手写拷贝构造和赋值运算符。

### 单例场景
```cpp
static GlobalObject * getInstance() {
    static shared_ptr<GlobalObject> obj(new GlobalObject());
    return obj.get();
}
```
要点：局部static shared_ptr只构造一次；程序结束自动释放；配合删除拷贝构造/赋值/移动，防止外部复制单例。

## 六、共享指针的实现 ★★★

### 问题起点：浅拷贝的double free
```cpp
class B {
    A* pa;
    B(int num=0):pa(new A(num)){}
    ~B(){delete pa;}   // 默认浅拷贝下，b1、b2的pa指向同一内存，各自析构会delete两次！
};
```

### ★★★ 两种手写共享指针方案对比（必考对比题）

| | 方法一：计数放A类 | 方法二：计数放B类 |
|---|---|---|
| 是否改动被共享类 | 是，A类需加 `mUse`、`addRef()`、`releaseRef()` | 否，A类不变 |
| 计数存储 | A对象内部 | B类多一个 `int* mpUse`，指向堆上单独分配的计数 |
| 适用场景 | 能修改A源码 | A是第三方库/不便改动（更通用，接近标准库实现思路） |

**共同套路（拷贝构造/赋值都要做这三步）**：
1. 拷贝构造：`mpa(mpUse) = rhs.mpa(mpUse); addRef();`
2. 赋值运算符：判断自赋值 → `release()`旧资源 → 指向新资源 → `addRef()`
3. 析构：`release()`，计数减到0才真正delete

**★★★ 易错点**：赋值运算符必须先判断 `this != &rhs`，且**先release旧资源，再指向新资源，再addRef**，顺序不能反。

### 写时复制 Copy On Write ★★★
```cpp
void B::writeA(int n) {
    if (*mpUse == 1) {
        mpA->setData(n);              // 独占，直接改
    } else {
        releaseRef();                  // 与共享组分手
        mpUse = new int(1);
        mpA = new A(*mpA);             // 深拷贝独立副本
        mpA->setData(n);
    }
}
```
**判断依据**：读操作（`readA`）永远直接共享读，不触发复制；只有**写操作**且**计数>1（被共享）**时才复制。

### 定位分配 placement new
```cpp
new (地址) T(参数);   // 不申请新空间，只在已有内存上构造对象
```
- 用途：内存池/自定义容器（如Stack），提升效率
- **★易错**：手动构造的对象要**手动调用析构函数** `p->~T();`，绝不能用 `delete`（因为空间不是单独new的，通常是`new char[]`整体分配、整体`delete[]`释放）

### ★★★ weak_ptr 解决循环引用（高频概念题）

**问题**：A→shared_ptr<B>→B→shared_ptr<C>→C→shared_ptr<A>→A，形成闭环，计数永远无法归零，造成内存泄漏。

**解决**：用 `weak_ptr` 打破环。**核心区别**：`weak_ptr` 的构造/析构**不会**增减所指对象的 `shared_ptr` 引用计数（`use_count`），只影响weak_ptr自身计数。
