## 1. ADT ★

- ADT = 数学模型 + 操作集合 = **类型名称 + 数据集 + 关系 + 操作集**
- 三大特点：与具体表示无关 / 与现实世界无关 / 任意性和无穷性
- 同一事物（如"人"）可抽象出多种不同 ADT，取决于关注角度

## 2. C++ 类型体系 ★★★

| 大类 | 包含 |
|---|---|
| 内置类型 | 基本类型(char, wchar_t, int, float, void) / 扩展类型(short,long,signed,unsigned,double 修饰) / bool |
| 自定义类型 | typedef/using 别名 / enum、enum class / class,struct,union |
| 导出类型 | 数组 / 指针 / 引用(左值引用、右值引用) |
| 模板类型 | 泛型(参数化类型) |

**C++1z 新增：** `long long`；`auto`（类型推导）、`decltype`（表达式类型推导，不求值）

- `auto b = a+99;` → b 类型由右侧表达式推导
- `decltype(sqrt(a)) b = ...;` → b 类型由 `sqrt(a)` 表达式类型决定
- ★ `decltype` 常用于返回类型依赖参数类型的模板函数（后置返回类型 `auto f(...) -> decltype(...)`）
- ⚠️ 易混：C++98 中 `auto` 是"自动变量"存储类关键字，与 C++11 的类型推导 `auto` 含义完全不同

### 2.1 typedef / using ★

- `typedef <已知类型> <新类型>;` 或 `using <新类型> = <已知类型>;`（C++11起）
- **本质：不产生新类型，只是改名**
- 函数指针别名：`typedef int (*MyFuncType)(int,int);` 等价于 `using MyFuncType = int(*)(int,int);`

### 2.2 枚举类型 ★★★（高频考点）

**C++98 传统 enum 规则：**
- 枚举值必须是整数；首值缺省为0；后一个未指定则=前一个+1
- 三大问题：① 内部本质是int ② int与枚举可随意转换，不安全 ③ **同名枚举值冲突**（不同enum不能有重名成员）

**enum class（C++1z 强类型枚举）：**
- 可指定底层类型和数值
- **不允许**与 int 隐式转换，必须显式 `(int)` 强转
- 使用时**必须**带作用域前缀（枚举类名::）

| 对比 | enum | enum class |
|---|---|---|
| 名字冲突 | ★可能冲突 | 不冲突（需加前缀） |
| int转换 | 可隐式转换 | 必须显式 (int) 强转 |
| 调用写法 | `f(0)` | `f((Dir)0)` |

- ★ 解决 enum 同名冲突的另一思路：把 enum 放进 class 内部，用 `类名::枚举值` 访问

### 2.3 class / struct / union ★

- **class 与 struct 除默认访问控制不同外，完全一致**（struct默认public，class默认private）
- ⚠️ 易错点：`class X{...};` 花括号后**必须加分号**

### 2.4 导出类型

- 数组：`int a[5];`　指针：`int *p; int **pp=&p;`　左值引用：`int &b=a;`（别名，共享内存）
- **右值引用**（C++1x/1z）：`void f(T&& aT){...}` 只能绑定临时对象（右值），如 `f(T())`

## 3. 声明和定义 ★★★（高频考点）

| | 声明 declaration | 定义 define |
|---|---|---|
| 含义 | 说明名字的含义和属性 | **声明的子集**，具有确定内容 |
| 判定标准 | 只说明存在 | 有函数体/类内容/具体值/存储空间/别名 |
| 数量限制 | 可以多次 | ★★★ 只能一次（ODR） |

**关键例句判断（常考）：**

```cpp
extern int a;              // 只是声明
int a;                      // 定义（分配了存储空间）
int f(int);                 // 只是声明
int f(int x){return x+a;}   // 定义
struct S;                   // 声明（前置声明）
struct S{int a;};           // 定义
```

⚠️★★★ **易错点：class 内 static 数据成员**
```cpp
struct X {
    static int y;    // 仅仅是"声明"！不是定义！
};
int X::y = 1;         // 这里才是真正的"定义"
```

## 4. 声明和定义的使用规则 ★★★

### 4.1 就近原则
现代C++提倡"现用现定义"，如 `for(int i=0;...)` 而不是把变量都堆在函数开头（老C写法）。

### 4.2 先声明后使用
名字必须先声明才能使用；只需指针/引用时可用**前置声明**（如 `class Bone;`），无需完整定义，可减少头文件依赖。

### 4.3 单一定义规则 ODR ★★★
**同一标识符在一个编译单元中只能定义一次，声明可以多次。**

⚠️★★★ **重要辨析：`#ifndef` 包含警戒解决的问题范围**

| 场景 | #ifndef 能否解决 |
|---|---|
| 同一个 .cpp 文件重复 `#include` 同一头文件 | ✔ 能解决 |
| 不同的 .cpp 文件分别 `#include` 同一头文件，且头文件里有变量/函数**定义** | ✘ **不能解决**，会在链接阶段报"重复定义" |

### 4.4 obj 文件与链接机制（理解型考点）
- 每个 .cpp 编译生成 .obj，内含"外部链接表"记录本文件对外符号地址
- 链接器把各 .obj 中"未定义但用到的符号"与"已定义的符号"配对
- 这就是为什么"定义只能一份"——否则链接器不知道该用哪个地址

### 4.5 头文件规范 ★★★（必考结论）

1. **头文件中只能放声明、以及类的定义**，**不应放变量定义和函数定义**
2. **函数定义及变量定义，在整个工程中只能定义一次**（应放到对应的 .cpp 中，谁提供功能定义归谁）

### 4.6 变量定义格式

| C++98 | C++11新增 |
|---|---|
| `[存储类]类型 变量名表[=初始化表];` | `[存储类]类型 变量名表[{初始化表}];` |

⚠️ 易混：`static long count;`（函数外）表示**文件级变量**，C++1z建议改用匿名命名空间

## 5. 存储空间与作用域 ★★★（高频考点）

### 5.1 存储空间（5区）

| 区域 | 存放内容 |
|---|---|
| 代码区 | 函数体机器指令 |
| 常量数据区 | 字符串字面量、const常量 |
| 变量数据区 | 全局变量、static变量 |
| 栈区 | 局部变量、函数形参 |
| 堆区 | new出来的对象 |

★★★ **static 局部变量核心特性：只初始化一次，跨函数调用保留上次的值**（存放在变量数据区，不是栈区）

```cpp
void func(int a,int b,int c){
    static int n=0;                 // 变量数据区，跨调用保留
    int result=(a+b+c)*(++n);       // 栈区
}
// 两次调用func(a,b,20)，因n被保留，两次result结果不同！
```

### 5.2 作用域（5种）

| 作用域 | 说明 |
|---|---|
| 全局作用域 | 整个程序可见（跨文件，需extern） |
| 文件作用域 | 仅本.cpp内可见（static修饰的全局变量） |
| 块级作用域 | {}内可见 |
| 类级作用域 | 通过 对象.成员 / 类名::成员 访问 |
| 命名空间作用域 | 需 :: 或 using 访问 |

### 5.3 链接性 ★★

| 链接性 | 对应情形 |
|---|---|
| 外部链接 external | 默认全局变量/非static全局函数，可被其它.cpp通过extern引用 |
| 内部链接 internal | static修饰的全局变量/函数，仅本文件可见 |
| 无链接 no linkage | 局部变量（栈区），不参与链接 |

⚠️★ static 把外部链接改为内部链接——这是"文件作用域"限制的底层原理

## 6. 表达式和语句

### 6.1 表达式类型速览
- 逗号表达式：`x=100, y=x-1000;`（整体值=最后一个表达式的值）
- 赋值表达式可连续：`x=y=100+f(5);`

### 6.2 左值 vs 右值 ★★

| 类型 | 特征 | 例子 |
|---|---|---|
| 左值 lvalue | 有确定内存地址，可在 `=` 两侧 | 变量名a、`*p`、`a[0]` |
| 右值 rvalue | 无持久地址，只能在 `=` 右侧 | 字面量100、`a+b`、临时对象 |

### 6.3 Lambda 表达式（C++1z）★★★

**语法格式（由繁到简，4种）：**
```
[capture](params) mutable exception attribute -> retType { body }
[capture](params) -> retType { body }
[capture](params) { body }
[capture] { body }
```

**capture 捕获方式（必考）：**

| 写法 | 含义 |
|---|---|
| `[a,&b]` | a传值捕获(只读副本)，b引用捕获(可修改原值) |
| `[this]` | 传值捕获this指针 |
| `[&]` | 引用捕获所有外部自动变量，**可修改** |
| `[=]` | 传值捕获所有外部自动变量，**默认不可修改**（除非加mutable） |
| `[]` | 不捕获任何外部变量 |

★★★ 核心判断依据：
- **传值捕获**（`[a]`、`[=]`）→ 拿到的是**创建时刻的值拷贝**，之后外部变量变化不影响lambda内部，且默认不能修改
- **引用捕获**（`[&b]`、`[&]`）→ 直接操作原变量，lambda内修改会真实影响外部变量

## 速记 Checklist

- [ ] ADT = 类型名称 + 数据集 + 关系 + 操作集，四要素能背出来
- [ ] C++类型三大类：内置 / 自定义 / 导出，各自包含什么要记熟
- [ ] auto（C++98存储类 vs C++11类型推导）不要混淆
- [ ] decltype 用于返回类型依赖参数类型的模板函数
- [ ] enum vs enum class：能否隐式转int？是否需要作用域前缀？谁更容易同名冲突？
- [ ] class 花括号后必须加分号
- [ ] 声明可多次，定义只能一次（ODR）
- [ ] class 内 `static int y;` 是声明，`int X::y=1;` 才是定义 —— 这条必考
- [ ] `#ifndef` 只能防止同一.cpp重复include，不能防止不同.cpp都定义同一变量/函数
- [ ] 头文件只放声明+类定义，不放变量/函数定义
- [ ] 五大存储区：代码区/常量区/变量数据区/栈区/堆区
- [ ] static局部变量存放在变量数据区，跨调用保留值 —— 结合"两次调用func结果不同"的例子理解
- [ ] 五种作用域：全局/文件/块级/类级/命名空间
- [ ] 链接性：外部链接（默认）/ 内部链接（static）/ 无链接（局部变量）
- [ ] 左值有地址可在=两侧，右值是临时值只能在=右侧
- [ ] Lambda 的 capture：`[=]`/`[a]` 传值不可改，`[&]`/`[&b]` 引用可改——这是判断题高发点
