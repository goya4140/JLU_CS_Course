## 一、成员函数的实现

**是什么**：类里声明的函数（成员函数），需要有函数体来"实现"它具体做什么。

**为什么**：类的定义（`class Student {...}`）本质是一个"蓝图"，蓝图里的函数只是声明了"有这个动作"，真正的动作逻辑要单独写出来。

**怎么用**：在类外用 `返回类型 类名::函数名(参数) { 函数体 }` 的格式实现。

```cpp
class Student {
public:
    Student(int sc, int st) { mScore = sc; mStrength = st; } // 构造函数直接写在类内
    void study(int hours);
    void exercise();
private:
    int otherFunc();
private:
    int mScore;
    int mStrength;
};

// 类外实现
void Student::study(int hours) {
    this->mScore += hours;
    this->mStrength -= 2;
    this->otherFunc();
}
void Student::exercise() {
    this->mStrength += 3;
}

int main() {
    Student s1(0, 100), s2(50, 80);
    s1.study(4);    // 操作的是 s1 自己的 mScore/mStrength
    s2.study(2);    // 操作的是 s2 自己的 mScore/mStrength
    return 0;
}
```

**关键理解**：`s1.study(4)` 和 `s2.study(2)` 调用的是**同一份代码**（函数只有一份，不会因为对象多就复制多份），但操作的是**不同对象的数据**。这就引出了下一节的 `this` 指针——函数是怎么知道"这次该操作哪个对象"的。

## 二、this指针

**是什么**：`this` 是一个关键字（保留字），是**非静态成员函数**里隐含的**第一个形参**，它的类型相当于 `T * const this`（一个指向当前类型、且指针本身不能改指向的常量指针）。

**为什么需要它**：成员函数的代码只有一份，被所有对象共用。函数体里写的 `mScore`，编译器实际上要知道是"哪个对象的 mScore"——这就是 this 的作用：**this 永远指向当前正在调用这个函数的那个对象**。

**怎么用**：

上一节的 `s1.study(4)` 在编译器眼里，本质上等价于：

```cpp
// 内部调用（编译器视角，非用户可写的语法）
Student::study(&s1, 4);
Student::exercise(&s1);
Student::study(&s2, 2);
Student::exercise(&s2);
```

也就是说，`s1.study(4)` 把 `&s1` 隐式地传给了 `study` 函数作为 `this`，函数体内的 `this->mScore` 也就自然是 `s1.mScore`。

**this的两个常见妙用**：

1. **在同名参数场景下明确"我说的是成员变量"**（配合 `this->` 显式指明）
2. **返回 `*this` 实现链式调用**（对象连续调用多个方法）

```cpp
class Ultraman {
public:
    Ultraman() { mHappiness = 0; }
    int getHappiness() const { return mHappiness; }
    Ultraman& fight(Monster&);   // 返回引用，支持链式调用
    bool fight(Boss&);           // 重载：打Boss返回胜负
private:
    int mHappiness;
};

Ultraman& Ultraman::fight(Monster& m) {
    // ... 战斗逻辑
    mHappiness += 5;
    return *this;      // 返回当前对象本身，才能继续 .fight(...)
}

bool Ultraman::fight(Boss& b) {
    bool win = /* ... */;
    if (win) mHappiness += 100;
    else this->mHappiness = 0;   // this-> 可省略但语义相同
    return win;
}

int main() {
    Ultraman super;
    Monster m1, m2;
    Boss b;
    // 链式访问：因为 fight(Monster&) 返回的是 Ultraman&（即 *this）
    cout << super.fight(m1).fight(m1).fight(m2).getHappiness() << endl;
}
```

> 💡 **生活化类比**：this 就像你去银行办业务时柜员手里的"你的身份证"。柜员（成员函数）的操作流程只有一套，但通过身份证（this），柜员知道这次是在给谁办理业务、扣谁的余额。

**要点**：this 的作用域和生存期仅限于非静态成员函数的 `{ }` 内，且 this 永远指向当前对象。

## 三、外联实现和内联实现

**是什么**：成员函数体写在哪里，分为两种方式：

| 对比项 | 外联实现 | 内联实现 |
|---|---|---|
| 写法位置 | 类外，`.cpp` 文件中，用 `类名::函数名` | 类内直接写函数体，或类外加 `inline` 关键字 |
| 编译器处理 | 正常函数调用（跳转） | **建议**编译器在调用处直接展开代码（只是建议，不强制） |
| 典型用途 | 逻辑较复杂的函数、避免头文件膨胀 | 简单、短小、频繁调用的函数（如 getter/setter） |

```cpp
// 外联实现示例
class Car {
public:
    Car(Person& owner);
    int move(int miles);
    void brake();
};
// car.cpp
Car::Car(Person& owner) { }
int Car::move(int miles) { }
void Car::brake() { }
```

```cpp
// 内联实现示例（两种写法效果一样）
class T {
public:
    void f() { cout << "void f(){}" << endl; }   // 类内实现=天然内联
    void g();                                     // 类外声明
};
inline void T::g() {   // 用 inline 关键字修饰类外实现
    cout << "inline void g(){}" << endl;
}
```

**关于 inline 关键字的两个易忽略细节**：

- `inline` 只在**声明和实现同时出现**时才有意义（C++17 之前）；C++17 后语法有所放宽。
- 如果一个函数**声明**处加了 `inline`，但**实现**处没加，这个 `inline` 没有实际意义；反之，只要**实现**处加了 `inline` 就有效。

```cpp
class T {
public:
    void h();
    inline void k();   // ← 这里的 inline 无实际意义（因为实现处才是关键）
};
inline void T::h() { }  // ← 这里的 inline 才真正起作用
```

### 外联/内联导致的"循环引用"问题

**是什么问题**：两个类互相调用对方的成员函数，如果都写成"内联"（在类定义里直接调用对方的函数），会因为头文件包含顺序导致编译错误（B还没定义完，A里就想调用B的函数）。

| 反例（内联实现，编译出错） | 正例（外联实现，解决问题） |
|---|---|
| `class A { public: void af(B& b) { b.bf(); } };`<br>问题：写`af`时B还只是前置声明，编译器不知道`b.bf()`合不合法 | `class A { public: void af(B& b); };`<br>`// a.cpp`<br>`void A::af(B& b) { b.bf(); }`<br>此时 a.cpp 里已经 `#include "b.h"`，B 是完整类型，没问题 |

**解决思路**：类定义中只做**前置声明**（`class B;`），函数体的具体实现放到 `.cpp` 文件里（外联实现），因为 `.cpp` 里可以同时包含两个类的完整头文件，不会有"谁先谁后"的矛盾。

## 四、访问控制

**是什么**：C++ 通过 `public` / `private` / `protected` 三个关键字控制类成员"谁能访问"。

| 权限 | 谁能访问 |
|---|---|
| `public` | 任何类（外部代码）都可访问 |
| `private` | 本**类**内部（不是本**对象**！）或友元可访问 |
| `protected` | 对本类相当于 private；对派生类可访问（后续章节讲解） |

**最容易踩坑的一点**：`private` 限制的是"类"这个边界，不是"对象"这个边界。也就是说，**同一个类的不同对象，可以互相访问对方的 private 成员**——只要访问代码写在这个类自己的成员函数里。

```cpp
class Student {
public:
    Student(int sc, int st);
    void study(Course& course);
    void help(Student& other);   // 注意：这里操作了"别的对象" other
    void exercise();
private:
    int otherFunc();
private:
    int mScore;
    int mStrength;
};

void Student::study(Course& course) {
    mScore += 1;
    mStrength -= course.getDifficulty();   // course是Course对象，getDifficulty是public，OK
    otherFunc();                            // OK：自己类里调用自己的private方法
    int n = course.periodCount();           // ❌ wrong：periodCount是Course的private，Student访问不了
}

void Student::help(Student& other) {
    other.mScore += 2;        // ✅ OK！other虽是"别的对象"，但help是Student类自己的成员函数
    mStrength -= 2;
    other.mStrength -= 4;     // ✅ OK
    other.exercise();         // ✅ OK（exercise是public）
    other.otherFunc();        // ✅ OK（otherFunc是private，但因为在同一个类Student内部访问，允许）
}
```

> 💡 **类比**：private 就像"家规"——同一家人（同一个类的对象）之间可以互相知道对方的私事，但外人（其他类）不行。

## 五、常成员函数（const 成员函数）

**是什么**：函数声明/实现的参数列表后面加 `const` 修饰的成员函数，格式为：

```cpp
<返回类型> <函数名>(<参数表>) const;
```

**为什么需要它**：

1. **承诺不修改对象**：常成员函数向调用者承诺"我不会修改这个对象的数据成员"（除非成员被 `mutable` 修饰，本章未涉及）。
2. **常量对象只能调用常成员函数**：当函数收到的是 `const T&` 类型的对象时，只有常成员函数能被调用。

**实现机制**：

| 函数类型 | this 指针类型 |
|---|---|
| 普通成员函数 | `T * const this` （指针不能改指向，但指向的对象内容可改） |
| 常成员函数 | `const T * const this` （指针不能改指向，指向的对象内容也不能改） |

```cpp
class MyClass {
public:
    void add() { }                      // 普通成员函数
    int func() { return --mValue; }      // 普通成员函数，会修改mValue
    void func(int n) { mValue = n; }     // 普通成员函数
    int func() const { return mValue; }  // 常成员函数：与上面构成重载
private:
    int mValue;
};
```

| 普通对象调用 | 常量对象调用 |
|---|---|
| `void ff(MyClass& va) {`<br>`  va.add();      // OK`<br>`  va.func();     // 调用非const版本 func()`<br>`  va.func(2);    // OK`<br>`}` | `void gg(const MyClass& ca) {`<br>`  ca.add();      // ❌ wrong，add不是const函数`<br>`  ca.func();     // ✅ 只能匹配const版本 func() const`<br>`  ca.func(2);    // ❌ wrong，func(int)不是const函数`<br>`}` |

**要点总结**：

- 常量对象（`const T&` 或 `const T` 变量）**只能**调用常成员函数。
- 普通对象调用时，如果同名函数既有 const 版本又有非 const 版本，编译器**优先匹配非 const 版本**。
- 常成员函数**内部**不能调用非 const 的其他成员函数（因为非const函数可能修改对象，违反const承诺）。

**什么时候该写成常成员函数？**（PPT里的思考题）

> 判断标准很简单：**只要这个成员函数不会修改当前对象的数据，就应该加 const**。这不是可有可无的"锦上添花"，而是关系到该函数**能不能被 const 对象调用**：

```cpp
// 反例：不使用常成员函数，会导致 const 对象完全无法使用
class A {
public:
    void f();   // 没加const，即使f内部根本没改数据
    void g();
};
void func(const A& a) {
    a.f();   // ❌ wrong！即使f逻辑上没改任何东西，编译器也不允许
    a.g();   // ❌ wrong
}
```

如果不给"只读"函数加 const，那么这个类的对象一旦被声明为 const，或者以 `const T&` 形式传参，**所有函数**（哪怕是纯粹的 getter）都调用不了，等于让这个类和 const 环境彻底绝缘。

### 常成员函数的返回值类型选择

**要点**：常成员函数返回什么类型，要看你想不想让调用者通过返回值**修改**对象内部数据：

```cpp
class Dog {
public:
    int   getID01() const { return mID; }     // ✅ 返回值拷贝，安全
    int&  getID03() const { return mID; }     // ❌ 错误！const函数里不能返回非const引用
                                                //    （相当于开了个后门可以改mID）
    const int& getID04() const { return mID; } // ✅ 返回const引用，只读安全
private:
    const int mID;
};
```

**规律**：常成员函数如果要返回"指向内部数据的引用/指针"，必须加 `const` 修饰返回类型，否则外部拿到这个引用/指针就能绕过 const 限制去修改对象内部数据，等于承诺"不修改"却留了后门。

## 六、实例变(常)量/实例方法 vs 类变(常)量/类方法

这一节是本章最重要的"数据/行为的两种归属方式"的对比。

### 6.1 实例变(常)量 & 实例方法

**是什么**：每个对象**各自独立拥有一份**的数据成员，叫实例变量；访问它们的成员函数叫实例方法。这也是我们目前接触的绝大多数成员（如前面的 `mScore`、`mStrength`）。

```cpp
class Student {
public:
    Student(int n);
    void funcOne();
    int funcTwo(int param) { /* 略 */ }
private:
    const int mID;   // 实例常量：每个学生对象有自己的学号，一旦初始化不可变
    int mScore;       // 实例变量：每个学生对象有自己的分数
};
```

> 类比：mID/mScore 就像每个学生自己的学号和成绩单——**每人一份，互不影响**。

### 6.2 类变(常)量 & 类方法

**是什么**：属于"类"本身、由该类的**所有对象共享**的数据/行为，用 `static` 关键字实现。

| 概念 | C++实现 | 关键特性 |
|---|---|---|
| 类变(常)量 | `static` 数据成员 | 全类只有一份内存；需在类外单独定义并初始化 |
| 类方法 | `static` 成员函数 | 不能直接访问非静态成员；没有隐含this指针；不能加const |

```cpp
// example.h
class Example {
public:
    static int nextNum(Example& ex) {
        // this->funcOne();     // ❌ 错误！类方法没有this指针
        // ++mValue;            // ❌ 错误！不能直接访问非静态成员mValue
        sNum += ex.mValue;      // ✅ 正确！通过传入的对象引用来访问它的实例成员
        return ++sNum;
    }
    Example(int n);
    void funcOne();
private:
    static int sNum;    // 声明类变量（还没分配内存）
    int mValue;          // 实例变量
};

// example.cpp
#include "example.h"
int Example::sNum = 1000;   // 类变量的定义 + 初始化，必须在类外单独写一次

void Example::funcOne() { /* 略 */ }

int main() {
    Example a(10);
    int val = Example::nextNum(a);   // 推荐：用"类名::"调用静态函数
    // a.nextNum(a);                  // 不推荐（虽然语法上也允许，但容易让人误解为实例方法）
}
```

**为什么类方法不能访问非静态成员**：类方法可以在**没有任何对象存在**的情况下被调用（如 `Example::nextNum` 理论上不依赖某个具体对象也能调用其静态逻辑），既然可能压根没有对象，那当然也就没有 this 指针，自然无法访问"属于某个具体对象"的实例成员。

**调用方式的推荐写法**：

| 好的写法 ✅ | 不推荐的写法 ⚠️ |
|---|---|
| `ClassName::OneStaticFunction();` | `objName.OneStaticFunction();` |

虽然语法上对象也能调用静态函数，但这容易让人误以为这个函数跟某个具体对象绑定，实际上它是类级别的，用类名调用更能体现语义。

> 类比：如果说实例变量是"每个学生自己的学号"，那么类变量就像"这所学校今年的招生总数"——它不属于任何一个学生，而是属于"学校"这个类本身，所有学生共享同一个数字。

### 6.3 综合案例：扑克牌 Card 类

PPT 用一个"扑克牌"的例子把本章所有知识点串起来，非常适合复习时对照：

```cpp
enum class Suit { CLUB = 0, DIAMOND, HEART, SPADE };
enum class Rank { TWO = 2, THREE, FOUR, FIVE, SIX, SEVEN, EIGHT,
                   NINE, T, J, Q, K, ACE = 1 };

class Card {
public:
    Card(int id)
        : mID(id), mSuit((Suit)(id / 13)), mRank(Rank(id % 13 + 1)) { }

    // 类方法：背面图案编号是所有牌共享的（一副牌用同一种牌背）
    static int  getBackImageId()          { return sBackImageID; }
    static void setBackImageId(int id)    { sBackImageID = id; }

    // 常成员函数：只读操作，不修改本对象
    const char* suitName() const;
    const char* ranktName() const;
    bool isSameSuit(const Card& c) const  { return mSuit == c.mSuit; }
    bool isSameRank(const Card& c) const  { return mRank == c.mRank; }
    bool isSuit(Suit s) const             { return s == mSuit; }
    bool isRank(Rank r) const             { return r == mRank; }

    // 非常成员函数：会修改对象状态
    void setPosition(int x, int y)        { mPosX = x; mPosY = y; }
    Point getPositionRB() const           { return Point(mPosX + 71, mPosY + 96); }

private:
    static int sBackImageID;   // 类变量：所有牌共享同一个背面图案编号
    const int mID;             // 实例常量：每张牌唯一的编号(1-52)
    const Suit mSuit;          // 实例常量：花色
    const Rank mRank;          // 实例常量：面值
    int mWidth, mHeight;       // 实例变量
    int mPosX, mPosY;          // 实例变量：每张牌各自的位置
};

// card.cpp —— 外联实现 + 静态成员的定义初始化
int Card::sBackImageID = 2;   // 类变量必须在类外定义一次

const char* Card::suitName() const {
    static const char* names[] = {"C", "D", "H", "S"};
    return names[(int)mSuit];
}
```

**这个例子体现了本章几乎所有知识点**：

- `mID`/`mSuit`/`mRank`/`mPosX`/`mPosY` → **实例变(常)量**（每张牌各不相同）
- `sBackImageID` → **类变量**（52张牌共用同一种背面图案）
- `getBackImageId()` / `setBackImageId()` → **类方法**（static，不依赖具体某张牌）
- `isSameSuit()`、`suitName()` 等 → **常成员函数**（只读，不修改牌本身）
- `setPosition()` → 非const，因为它要修改 mPosX/mPosY
- `suitName()` 的外联实现 → 体现**外联实现**写法

## 七、封装与信息隐蔽（本章设计思想的总纲）

**封装**：把事物的特征（数据）和相关信息（行为），通过"打包"的方式包装成一个整体。

- 对**内部**：各成员之间沟通不受访问权限影响。
- 对**外部**：只能通过公开（public）的接口沟通，不需要了解内部实现细节。
- C++ 中封装的实现手段：**class**

**信息隐蔽**：在封装过程中，让事物的部分信息对外部不可见，只公开必要的信息。

- C++ 中信息隐蔽的实现手段：**访问控制**（private/protected/public）

**这两者的现实价值**（面向对象设计的基石）：

1. **分离使用和实现**：调用者只需要知道 `list.push_back(2)` 能把数据加进去，不需要知道链表内部怎么存储。
2. **分离接口与实现**：`game.init(); game.run(); game.term();` —— 调用者只关心"游戏要经过这三步"，不关心每一步内部具体怎么做。
3. **软件复用**：接口稳定不变时，内部实现可以随意替换、优化，不影响使用者的代码。

## ✅ 本章小结

1. **成员函数**在类外实现时格式为 `返回类型 类名::函数名(参数){...}`；一个成员函数只有一份代码，靠 `this` 指针区分具体操作的是哪个对象。
2. **this指针**是非静态成员函数隐含的第一个形参，类型为 `T * const this`，其作用域仅限函数体内；`return *this` 可实现方法链式调用。
3. **外联实现**（类外用 `::` 实现）适合复杂逻辑和解决两个类互相依赖的编译顺序问题；**内联实现**（类内实现或加 `inline`）是"建议"编译器展开代码，只是建议不是强制。
4. **访问控制**中，`private` 限制的边界是"类"，不是"对象"——同类的不同对象可以在类的成员函数内部互相访问对方的私有成员。
5. **常成员函数**（函数头加 `const`）承诺不修改对象，其 this 类型变为 `const T * const this`；**常量对象只能调用常成员函数**；只要函数逻辑上不修改数据，就应当加 const，否则该类无法与 const 环境兼容。
6. **实例变(常)量/实例方法**属于每个对象各自独立的数据和对应的操作；**类变(常)量/类方法**（static）属于类本身、全体对象共享，类方法不能直接访问非静态成员、没有this、不能加const，推荐用 `类名::` 方式调用。
7. **封装**（打包数据+行为，用 class 实现）与**信息隐蔽**（隐藏细节，用访问控制实现）是面向对象编程的基石，目的是分离使用与实现、分离接口与实现、提高软件复用性。
