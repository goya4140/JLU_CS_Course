# 第二章 C++程序结构（考前速记版）

## 知识结构导览

```
C++程序结构
├─ 项目组成：cpp / h·hpp / 库文件 / 资源文件 / 数据文件 → 编译 → exe
├─ 编译三阶段：预编译 → 编译 → 链接（+ make工具）
├─ 入口函数：main() / main(argc, argv[])
└─ 头文件七要点：
    扩展名 / <>vs"" / include顺序 / 前置声明 / 正确用法 / 包含警戒 / #pragma once
```

---

## 一、C++项目组成 ★

| 文件类型 | 说明 |
|---|---|
| 实现文件 | .cpp |
| 头文件 | .h / .hpp |
| 外部库文件 | .dll .lib .exe |
| 资源文件 | .rc .res |
| 数据文件 | 数据库、XML、.dat |

**编译单位** ★★★：C++ 编译是以**实现文件（cpp文件）**为基本单位的。

---

## 二、编译三阶段 ★★★（高频考点）

| 阶段 | 处理什么 | 核心任务 | 是否需要知道具体地址 |
|---|---|---|---|
| 预编译（预处理） | `#`号语句（#include #define #ifdef等） | 文本展开/替换 | 不涉及 |
| 编译 | 单个预处理后的源文件 | 语法检查，生成 .obj | **不要求** |
| 链接 | 所有 .obj + 库文件 | 确定标识符地址，生成可执行文件 | **要求** |

**易错判断题**：main 写成 mian，编译阶段会报语法错误吗？
→ **不会**报"main拼写错"这类错误；mian只是编译器不认识的普通标识符，真正报错的原因通常是"某标识符未声明"（如例题中的 f 未声明会报语法错误），而"找不到程序入口"是链接阶段的问题。

**结论要点**：
- 各阶段均无错误才能生成可执行文件；
- 生成了可执行文件 **不代表程序逻辑正确**；
- 编译通过相对简单，**调试逻辑错误才是真正困难的**。

**make工具原理** ★★：比较目标文件（如 myfile02.obj）与其依赖文件（.cpp、.h）的**时间戳**，依赖文件更新则重新编译，否则跳过。

---

## 三、入口函数（main） ★★★

| 要点 | 内容 |
|---|---|
| 返回值 | 固定为 int |
| 参数形式 | 无参数 / `(int argc, char* argv[])` |
| C++1z标准 | main函数体的 `return 0;` 可省略 |

**命令行参数** ★★★：

| 执行 | argc | argv |
|---|---|---|
| `my.exe` | 1 | argv[0] = 程序自身路径 |
| `my.exe 123 computer` | 3 | argv[0]=程序路径, argv[1]="123", argv[2]="computer" |

**易错点**：argv[0] **永远是程序自身路径**，用户输入的参数从 **argv[1]** 开始；argc 计数**包含** argv[0]。

---

## 四、头文件七要点

### 1. 扩展名
.h / .hpp / 无扩展名（如 `<iostream>`）均可，无强制标准。

### 2. `<>` vs `""` ★★★

| | `#include <a.h>` | `#include "a.h"` |
|---|---|---|
| 查找顺序 | 直接查系统目录 | 先查本地工程目录，找不到再查系统目录 |
| 常用于 | 标准库/第三方库 | 自定义头文件 |

- `#include <xx>`（无.h）：C++风格，内容大体在 `namespace std` 下
- `#include <xx.h>`：偏C风格，内容多在全局命名空间

### 3. include顺序 ★
建议先 `<>`（标准库/第三方库），后 `""`（自定义头文件），便于区分外部/内部依赖。

### 4. 前置声明 ★★

```cpp
class A;   // 前置声明：只说明是类型，不需要完整定义
```

- **作用**：解决类之间相互引用（A用到B、B也用到A）的循环依赖问题
- **限制** ★★★：只适用于**指针/引用**场景（不需要知道对象大小）；若要创建对象、访问成员、计算sizeof，**必须完整定义**（即真正 #include 对应头文件）

### 5. 头文件正确使用方法 ★★★

| 做法 | 说明 |
|---|---|
| ❌ 错误 | 把所有人（多模块）的声明糅进一个公共头文件（如 ourcommon.h）→ 无法明确职责归属，谁维护成疑问 |
| ✅ 正确 | **每个 .cpp 文件把自己要对外公开的内容，放进自己对应的头文件**（谁定义、谁维护） |

### 6. 包含警戒（include guard） ★★★

```cpp
#ifndef MYH
#define MYH
... 内容 ...
#endif
```

- **作用**：防止**同一个 .cpp 文件重复 include 同一个头文件**导致重复定义报错
- **易错点** ★★★：**不能**、也**不需要**限制不同的 .cpp 文件各自 include 同一个头文件（这是正常且必须允许的）

### 7. `#pragma once` ★★

- 与包含警戒（`#ifndef/#define/#endif`）**功能完全等价**，写法更简洁（一行搞定）
- **缺点**：非C++标准，**部分（尤其早期）编译器支持不好**

---

## 五、实现文件（cpp文件）

- 头文件负责**声明接口**（对外公告有什么），实现文件负责**具体实现**
- 调用方只需 `#include` 头文件即可使用，**无需了解实现细节** → 接口与实现解耦，降低耦合度

---

## 六、C++多文件结构关系图（精简）

```
实现文件(.cpp) + 头文件(.h/.hpp) → 可执行文件
可执行文件 = 入口函数(main) + 头文件 + 实现文件
```
