## 二、指针（Pointer）

### 1. 是什么、怎么定义

指针本质上是一个"存放地址的变量"。你可以把内存想象成一整条街，每栋房子都有门牌号（地址）；普通变量是"房子里住的东西"，而指针就是"写着门牌号的纸条"。

语法格式：

```
Type * varName [= 地址表达式];
```

例如：

```cpp
int num = 5;
int * pNum = &num;   // pNum存放num的地址
int * pN2  = pNum;   // pN2和pNum存放同一个地址
void * p   = 0;      // void*可以指向任意类型，但不能直接解引用
bool ** p2 = nullptr;// 二级指针，也可以是空指针
int ** ppNum = &pNum;// ppNum存放"pNum这个指针变量"的地址
```

### 2. 空指针的三种写法

| 写法 | 标准 | 说明 |
|---|---|---|
| `int * pName = 0;` | 任意 | 直接用整数0表示空地址，语义不够清晰 |
| `int * pName = NULL;` | C++98 | NULL 其实是宏，通常展开为0，历史遗留写法 |
| `int * pName = nullptr;` | C++11起(1z) | 专门的空指针类型，类型安全，推荐写法 |

**为什么推荐 nullptr**：NULL 本质是整数0，在函数重载等场景下可能和真正的int参数混淆，编译器无法区分你传的是"数字0"还是"空指针"；nullptr 有自己的类型 `std::nullptr_t`，不会产生歧义。

### 3. 解引用（dereference）

解引用就是"根据地址纸条，找到真正的房子，看里面/改里面的东西"，用 `*` 运算符完成。

```cpp
int a = 8;
int * pa = &a;
int ** ppa = &pa;

int b = 9;
*pa = b;     // 通过pa找到a，把a的值改成b的值(9)
*ppa = &b;   // 通过ppa找到pa，把pa指向的地址改成&b（pa现在指向b了）
```

注意 `*pa = b` 和 `*ppa = &b` 的区别：前者是"改指针指向的内容"，后者是"通过二级指针改一级指针本身指向谁"。

### 4. 指针的运算

指针加减不是简单的"数字加减"，而是按照所指类型的大小跳跃的。

```
T * p = ….;
p + n  等价于  (T*)((char*)p + sizeof(T) * n)
```

也就是说 `p+1` 实际上在地址上跳了 `sizeof(T)` 个字节，而不是1个字节。这也是"取数组元素 a[k] 等价于 `*(a+k)`"的原理——编译器帮你自动做了这个换算。

```cpp
int a[2] = {1, 2};
int * p = &a[0];
cout << *(++p);   // ++p先把p指向a[1]（跳过4字节），再解引用，输出2
```

## 三、数组（Array）

### 1. 一维数组

语法格式：

```
Type varName[ constexp ] [= {初值列表}];
```

| C++98 写法 | C++1z（C++17起）新增写法 |
|---|---|
| `int a[5] = {1,2,3,4,5};` | `int a[5] {};` |
| `int* b = a;` | `int* b = a;` |
| `int* c = &a[0];` | `int* c = &a[0];` |

要点：**数组名 `a` 本身在大多数表达式中会"退化"为指向首元素的指针**，所以 `int* b = a;` 和 `int* c = &a[0];` 是等价的。

### 2. 多维数组

语法格式（以二维为例）：

```
(C++98)  Type varName[ constexp1 ][ constexp2 ]… [= {初值列表}];
(C++1z)  Type varName[ constexp1 ][ constexp2 ]… [ {初值列表} ];
```

理解方式：`Type name[constexpr]` 这种语法可以理解成 `Type[constexpr] name`——即"类型是一个数组类型，名字叫name"，多维数组就是"数组的数组"。

### 3. 指针数组 vs 数组指针（重点易混）

这是本章最容易搞混的一对概念，关键在于"谁是修饰谁"。

| | 指针数组 | 数组指针 |
|---|---|---|
| 定义写法 | `int * array[5];` | `int (*p)[5];` |
| 本质 | 是一个"数组"，数组里装的每个元素都是指针 | 是一个"指针"，这个指针指向一整个数组 |
| 记忆技巧 | `[]` 优先级高，先看到 `array[5]`，说明array是数组，元素类型是 `int*` | 括号强制先看 `(*p)`，说明p是指针，指向的是 `int[5]` 这种类型 |
| 类比 | 一排5个抽屉，每个抽屉里放一张写着地址的纸条 | 一张纸条，上面写着"这有一整排5个抽屉的位置" |

配套例子：

```cpp
int a[4] = {1, 2, 3, 4};
int * b[4] = {&a[0], &a[1], &a[2], &a[3]};  // b是指针数组：4个指针分别指向a的每个元素

int (*p)[4] = &a;      // p是数组指针：指向整个a数组（类型是int[4]）
cout << (*p)[3] << endl;  // 先解引用p得到整个数组a，再取下标3，输出4
```

## 四、引用（左值引用）

### 1. 是什么

引用是**已存在的变量/对象的别名**。它不是一个独立的新变量，而是给同一块内存起了第二个名字。

语法格式：

```
<类型> & <变量名> = <对象或变量>;
```

例子：

```cpp
int a = 10;
int & b = a;         // b是a的别名，此时a和b其实是"同一个人"

cout << a << b << endl;  // 输出10和10
a = 6;
cout << a << b << endl;  // 输出6和6，因为b就是a
b = 5;
cout << a << b << endl;  // 输出5和5，改b就是改a
```

类比：这就像一个人有"本名"和"小名"，无论你叫哪个名字，指的都是同一个人；给"小名"改地址，"本名"的地址也跟着变，因为压根就是同一个人。

### 2. 引用的三大规则

1. **是一个别名**——不占用独立的存储概念，编译器把它看作原变量的另一个名字。
2. **对应的变量/对象必须存在**——引用不能凭空产生，必须绑定一个真实存在的东西。
3. **必须初始化**——定义引用的同时就要指定它是谁的别名，不能像指针那样先声明后赋值。

### 3. 引用的价值：和值传递、指针传递的对比

这是本章的核心考点：**为什么C++要引入引用？**

先看不使用引用/指针，单纯值传递的情况——函数内部改的是"拷贝"，改不了原变量：

```cpp
int a = 7, b = 8;
void f(int a, int b) { cout << a << b << endl; }
调用方: f(a, b);
```

如果想在函数内部真正修改调用方的a和b，C语言时代只能用指针：

| 传指针（可以修改，但写法繁琐） | 传引用（可以修改，写法和值传递一样简洁） |
|---|---|
| `int a=7, b=8;` | `int a=7, b=8;` |
| `void f(int *pa, int *pb) { *pa=1; *pb=2; }` | `void f(int & a, int & b) { a=1; b=2; }` |
| 调用方：`f(&a, &b);`（要手动取地址） | 调用方：`f(a, b);`（不需要取地址） |
| 函数体内：要写 `*pa` 才能操作真实值（要手动解引用） | 函数体内：直接写 `a` 就是操作真实值 |

**结论**：引用的价值在于"既能像指针一样修改实参，又能像普通变量一样直接使用，不需要取地址和解引用这两步额外操作"。

### 4. 补充例：为什么引用能让接口更统一

假设有一个函数 `test`，处理一个 `Paper` 对象：

**不使用引用（C风格），修改与不修改要用不同的函数签名和不同的调用写法：**

| 若不修改 paper | 若要修改 paper |
|---|---|
| 定义：`void test(Paper paper) {}` | 定义：`void test(Paper * pPaper) {}` |
| 调用：`test(paper);` | 调用：`test(&paper);` |

**使用引用（C++风格），无论是否修改，调用方写法可以保持一致：**

| 若不修改 paper | 若要修改 paper |
|---|---|
| 定义：`void test(Paper paper) {}` 或 `void test(const Paper & paper) {}` | 定义：`void test(Paper & paper) {}` |
| 调用：`test(paper);` | 调用：`test(paper);` |

**这就是引用最大的工程价值**：调用方永远只需要写 `test(paper)`，不用关心函数内部到底是值传递、常量引用还是普通引用，接口更一致、更不容易出错。

### 5. 指针和引用的核心差异

| 维度 | 指针 | 引用 |
|---|---|---|
| 存取值的方法 | 需要 `*` 解引用才能拿到指向的内容 | 直接用变量名即可，语法上"透明" |
| 初始化 | 可以先声明、后赋值（甚至可以不初始化，虽不推荐） | 必须在定义时立即初始化 |
| 对象或变量的存在性 | 可以是空指针（不指向任何东西），也可以中途改指向 | 必须绑定一个已存在的对象，且一旦绑定不能再改绑别的对象 |

## 五、常量（Constant）

### 1. 文字常量（字面常量）

就是代码里直接写出来的固定值，例如 `100`、`3.14`、`true`、`'C'`、`"吉林大学"`。它们本身没有名字，用完即弃。

### 2. 为什么需要"命名"常量：一个反面例子

PPT给出了一段"能跑但很难读"的代码：

```cpp
if (var == 1) {
    value = 3.14 * 2.5 * 2.5;
} else if (var == 2) {
    value = 3.14 * 2.5 * 2.5 * 2.5 * 4 / 3;
} else {
    value = 2.5 * 2.5;
}
```

问题在于：`3.14` 是谁都能看出来是圆周率，但 `2.5` 到底代表什么（半径？边长？）完全不知道，而且如果这个数值以后要改，要在好几个地方同时改，容易漏改。这就是"魔法数字（magic number）"问题，命名常量正是为了解决它。

### 3. 宏定义 #define

最原始的"命名常量"手段：

```cpp
#define VALUE 98
```

宏本质是**预处理阶段的纯文本替换**，编译器还没开始理解语法之前，预处理器就已经把代码里所有的 `VALUE` 替换成了 `98`。

**#define 的缺点**：没有类型检查。因为它只是文本替换，编译器无法像检查普通变量那样检查类型是否匹配，容易出现难以排查的错误。

**#define 的优点（也是它至今没被淘汰的原因）**：

- **条件编译**：可以根据宏是否定义，让编译器选择性地编译某段代码，常用于调试代码、跨平台代码。

```cpp
#define DEBUG
int main() {
    int a = 100;
#ifdef DEBUG
    cout << a << endl;
    Do1();
#else
    Do2();
#endif
}
```

上面这段代码中，因为定义了 `DEBUG`，所以编译时会保留 `cout<<a<<endl; Do1();` 这部分，`Do2();` 会被直接"消失"（连编译都不会编译到）。如果去掉 `#define DEBUG` 这一行，效果正好相反。

- **字符串化 `#` 和拼接 `##`、`#@`**：

```cpp
#define STR(x)     #x        // 把参数变成字符串
#define VAR(x)     n##x      // 把参数和n拼接成一个新的标识符
#define TOCHAR(x)  #@x       // 把参数变成字符（VC++扩展，非标准）

int n1 = 1, n2 = 4, n3 = 7;
cout << STR(123) << endl;     // 输出字符串"123"
cout << STR(abc) << endl;     // 输出字符串"abc"
cout << VAR(2) << endl;       // VAR(2)被替换成n2，输出变量n2的值：4
cout << TOCHAR(2) << endl;    // 输出字符'2'
cout << TOCHAR(a) << endl;    // 输出字符'a'
```

- **预定义宏**：`__LINE__`（当前行号）、`__FILE__`（当前文件名）、`__FUNCTION__`（当前函数名），常用于日志和调试信息定位。

```cpp
void f() {
    cout << __LINE__ << endl;
    cout << __FILE__ << endl;
    cout << __FUNCTION__ << endl;
}
```

### 4. 命名常量（真正意义上的、有类型的常量）

语法格式：

```cpp
const int CARD_COUNT = 54;
```

和 `#define` 相比，`const` 定义的常量**有类型、受编译器类型检查、遵循作用域规则**，是C++中更推荐的做法。

**枚举量**是"一组相关命名常量"的打包方式：

| C++98：enum | C++1z：enum class |
|---|---|
| `enum Color { RED=0xFF0000, GREEN=0x00FF00, BLUE=0x0000FF };` | `enum class Color { RED=0xFF0000, GREEN=0x00FF00, BLUE=0x0000FF };` |
| 枚举值会"泄漏"到外部作用域，直接用 `RED` 即可 | 枚举值被限制在类型内部，必须写 `Color::RED`，更安全，不容易和其它同名标识符冲突 |

### 5. 常量折叠（编译期优化，理解即可）

```cpp
// xx.h
const int v1 = 100;
const int v2 = 200;

// a.cpp
#include "xx.h"
...

// b.cpp
#include "xx.h"
...
```

因为 `v1`、`v2` 是编译期就能确定的常量，编译器在编译 a.cpp 和 b.cpp 时会直接把用到 `v1`、`v2` 的地方**折叠替换成具体数值**，而不是像普通全局变量那样在多个.cpp文件里保留同一份内存。这也是为什么 `const` 全局变量可以放心地写在头文件里被多个.cpp包含，而不会引发"重复定义"的链接错误。

## 六、const 和指针

这是本章的重点、难点，也是历年常考内容。核心思路：**看 `const` 修饰的是 `*` 前面还是后面**。

### 1. 指向常量的指针（内容不能改，指向可以改）

两种等价写法：

```cpp
const int* pt = &a;
int const* pt = &a;
```

例子：

```cpp
int v1 = 100;
int v2 = 3;
const int * p1 = &v1;   // 正确
cout << *p1 << endl;    // 输出100
const int * p2 = &v2;   // 正确

int * p3 = &v1;   // 正确，p3是普通指针
int * p4 = p1;    // 错误！p1指向常量，不能把它赋给一个"可以修改内容"的普通指针p4
int   v3 = *p1;   // 正确，只是读取值，没问题
```

反过来，如果指向的本身就是真正的 `const` 变量：

```cpp
const int cv1 = 200;
const int cv2 = 4;
const int * pc1 = &cv1;   // 正确
cout << *pc1 << endl;     // 输出200
const int * pc2 = &cv2;   // 正确

int * p1 = pc1;   // 错误！同样是常量指针赋给普通指针
int   v1 = cv1;   // 正确
int   v2 = *pc1;  // 正确
```

**记忆要点**：`const T*` 只是承诺"我不会通过这个指针去修改内容"，它保护的是"内容"，不是"指针本身"。

### 2. 常指针（指针本身不能改，必须初始化）

四种组合，务必分清：

| 写法 | 含义 | 是否必须初始化 |
|---|---|---|
| `T * p [= exp];` | 普通指针：内容能改，指向能改 | 不强制 |
| `const T * pt [= exp];` | 指向常量的普通指针：内容不能改，指向能改 | 不强制 |
| `T * const pt = exp;` | 指向变量的常指针：内容能改，指向不能改 | **必须初始化** |
| `const T * const pt = exp;` | 指向常量的常指针：内容和指向都不能改 | **必须初始化** |

**为什么后两种必须初始化**：`const pt` 里的 `const` 修饰的是"指针变量pt本身"，既然pt本身以后不能再被赋值改指向，那就只能在"出生"（定义）的那一刻把它的值（指向谁）确定下来，否则以后再也没机会赋值了。这和普通的 `const` 变量必须初始化是同一个道理。

### 3. 完整示意与例子

```
T var = exp;
const T * const pt = &var;
```

- 前一个 `const`（`*` 左边）：说明**不能通过 pt 修改它指向的内容**（即 `*pt` 不能被赋值），但不限制其它指针修改 var 的内容。
- 后一个 `const`（`*` 右边，紧跟 pt）：说明 **pt 这个指针变量存放的地址值不能改变**，即不允许 pt 指向其它地址。

配套例子：

```cpp
int var1 = 5, var2 = 10;

int * const pt1 = &var1;
pt1 = &var2;    // 错误，不允许修改pt1存放的地址值
*pt1 = var2;    // 正确，虽不能指向其它变量，但能修改指向的内容

const int * pt2 = &var1;
*pt2 = var1;    // 错误，不能企图通过pt2修改内容
pt2 = &var2;    // 正确，pt2可以改指向其它变量
var2 = 99;      // 正确，只要不通过pt2指针，var2本身可任意修改
cout << *pt2;   // 这时*pt2的值是99（因为pt2现在指向var2）
```

### 4. const 和指针综合判断表

设 `pv`、`pv2`、`pv3`、`pv4` 分别按下面四种方式定义，`v`、`m` 的 const 属性各不相同：

```
int * pv           = &v;
const int * pv2    = &v;
int * const pv3    = &v;
const int * const pv4 = &v;
```

以 `int v; int m;`（v、m均非const）为基准，判断以下语句是否合法：

| 语句 | 是否合法 | 判断依据 |
|---|---|---|
| `pv = &m;` | 合法 | pv是普通指针，指向和内容都能改 |
| `*pv = m;` | 合法 | 同上 |
| `pv2 = &m;` | 合法 | pv2只是不能改内容，指向可以改 |
| `*pv2 = m;` | 不合法 | pv2不能通过自己修改所指内容 |
| `pv3 = &m;` | 不合法 | pv3是常指针，指向不能改 |
| `*pv3 = m;` | 合法 | pv3的内容可以改，只是指向不能改 |
| `pv4 = &m;` | 不合法 | pv4指向不能改 |
| `*pv4 = m;` | 不合法 | pv4内容也不能改 |

**判断口诀**：先看 `pv = &m` 这类"改指向"的操作，只看 `*` 右边有没有 `const`（右边有const → 指向不能改）；再看 `*pv = m` 这类"改内容"的操作，只看 `*` 左边有没有 `const`（左边有const → 内容不能改）。**这条口诀不受 v、m 本身是否是 const 影响**——如果 v 或 m 本身是常量，那么用普通指针（不带const）去指向它们本身就是不允许的（编译器会直接报错，见下方指向常量的指针小节），这是另一层限制。

## 七、关于字符串的说明

### 1. 字符串的内部存储和编码（了解即可）

- **ANSI_C字符串**：以ASCII码为0的字符（即 `'\0'`）作为结尾标志。
- **BSTR**：Windows/COM体系里的一种字符串格式，了解概念即可。
- **字符编码**：MBCS（多字节字符集）、Unicode（又分UTF-8/UTF-16/UTF-32三种具体编码方式），字节数、兼容性各不相同，本章不深入展开。

### 2. char* 和 char[] 定义字符串的区别（重点）

```cpp
char * str = "This is a string!";
```

**这一行等价于：**

```cpp
const char * str = "This is a string!";
```

**为什么**：字符串字面量 `"..."` 在内存中是**只读**的（存放在程序的只读数据段），如果允许用一个普通的 `char*` 去指向它，理论上就可以通过这个指针去修改这段只读内存，这是未定义行为、非常危险。所以虽然语法上写的是 `char*`，编译器实际上把它当成 `const char*` 处理（很多编译器对这种写法会给出警告）。

对比：

```cpp
char str[] = "This is a string!";
```

这一行是把字符串字面量的内容**拷贝**到一个新分配的、可读写的数组 `str` 里，`str` 本身完全可以被修改。

| | `char * str = "..."` | `char str[] = "..."` |
|---|---|---|
| 本质 | str是指针，指向字符串字面量所在的只读内存 | str是数组，内容是字面量的一份拷贝，存在栈上 |
| 能否修改内容 | 不能（等价于const char*，修改是未定义行为） | 能，随便改 |

### 3. 标准库中的 string

```cpp
#include <string>
```

`std::string` 是C++标准库提供的字符串类，自动管理内存、支持 `+`、`==` 等运算符重载、有丰富的成员函数，是实际项目中远比 `char*`/`char[]` 更推荐的选择（本课程后续章节会详细讲解运算符重载、动态内存管理等相关原理）。

## 八、const 和引用

### 1. 变量的引用回顾

```cpp
int val = 100;
int & myval1 = val;

const int & myval2 = val;

myval1 = 300;   // 正确，myval1是val的别名，能改
myval2 = 100;   // 错误！myval2是"常量引用"，不能通过它修改内容
```

`const int &` 表示"这是一个只读的别名"——它依然绑定着同一块内存（val），但通过这个引用名字，你只能读、不能写。

### 2. 常量的引用（★易忽略的知识点）

```cpp
int b = 100;
int & aa = b;          // 正确，普通引用绑定普通变量

const int & aa = b;    // 正确，const引用当然也可以绑定普通变量
const int & bb = 1;    // 正确！const引用可以绑定一个字面量常量

aa = 10;   // 如果aa是const int&，这里错误，不能通过aa修改
bb = 20;   // 错误，bb是const int&，不能修改
```

**这里最反直觉、也最重要的一点是**：`const int & bb = 1;` 是合法的，但如果写成 `int & bb = 1;` 则是**非法**的——因为 `1` 是一个临时的字面量，没有自己的地址（不是"左值"），普通引用要求必须绑定一个真实存在、有地址的对象；而 `const` 引用有一条特殊规则：编译器会**自动生成一个匿名的临时变量来存放这个字面量**，然后让 `bb` 绑定这个临时变量，因为承诺了"只读"，所以这样做是安全的。

### 3. 函数参数中的 const 引用应用（承接第六节"引用的价值"）

```cpp
int var = 100;
const int cvar = 200;

void f(int a1, int & a2, const int & a3) {}
```

| 调用语句 | 是否合法 | 原因 |
|---|---|---|
| `f(1, 2, 3);` | 错误 | 第二个参数 `a2` 是普通引用 `int&`，不能绑定字面量 `2`（字面量没有地址，不是左值） |
| `f(1, var, var);` | 正确 | var是普通变量，能绑定普通引用和常量引用 |
| `f(1, cvar, cvar);` | 错误 | a2是普通引用，不能绑定const变量cvar（会破坏cvar的只读性） |
| `f(1, var, cvar);` | 正确 | a2绑定var（合法），a3是常量引用，绑定cvar也合法 |
| `f(1, cvar, var);` | 错误 | a2（普通引用）不能绑定cvar |
| `f(var, var, var);` | 正确 | 第一个参数是值传递，无所谓const；后两个同上分析 |
| `f(cvar, var, cvar);` | 正确 | 第一个值传递合法；a2绑定var合法；a3（const引用）绑定cvar合法 |

**核心规律**：**普通引用 `T&` 只能绑定"非const的左值"；const引用 `const T&` 什么都能绑定**（普通变量、const变量、甚至字面量/临时对象）。这也是为什么写函数参数时，"只读、不修改"的场景优先使用 `const T&`——它兼容性最好，既不产生拷贝开销（相比值传递），又能接收任意类型的实参。

## 九、本章小结

1. **指针**是存放地址的变量，`*` 用于解引用；指针运算按所指类型的 `sizeof` 跳跃，`a[k]` 本质是 `*(a+k)`。
2. 优先使用 **`nullptr`** 而不是 `NULL` 或 `0` 表示空指针，类型更安全。
3. 数组名在多数场合会退化为指向首元素的指针；**指针数组**（`int* a[5]`，本质是数组）与**数组指针**（`int (*p)[5]`，本质是指针）是完全不同的概念，靠 `[]` 和 `()` 的优先级区分。
4. **引用**是已存在对象的别名，必须初始化、必须绑定真实存在的对象、绑定后不能再改绑。它的核心价值是：既能像指针一样修改实参，又能像普通变量一样直接使用，让"改"与"不改"两种函数接口的调用方式保持一致。
5. **`#define` 宏**是文本替换，没有类型检查，但拥有条件编译、字符串化/拼接、`__LINE__` 等特殊能力；**`const` 命名常量**有类型、受编译器检查，是更推荐的常量定义方式；`enum class`（C++1z）比 `enum`（C++98）作用域更安全。
6. **const 和指针**的判断口诀：`*` 左边的 `const` 决定"内容能不能改"，`*` 右边（紧邻指针名）的 `const` 决定"指向能不能改"；后者作为常指针，定义时必须初始化。
7. `char * str = "字面量";` 等价于 `const char * str = "字面量";`，因为字符串字面量本身只读；而 `char str[] = "字面量";` 是把内容拷贝到一块可写内存中。
8. **const 和引用**：普通引用 `T&` 只能绑定非const的左值；**`const T&` 是万能的**——能绑定普通变量、const变量，甚至能绑定字面量/临时值（编译器会自动生成临时变量），因此在设计"只读参数"的函数接口时应优先使用 `const T&`。
