# 第九章 拷贝与赋值 —— 考前速记版

## 知识结构（精简版）

```
拷贝与赋值
├─ 拷贝必要性：按值传参 / 按值返回
├─ 拷贝构造函数 T(const T&) —— 创建新对象 ★★★
│   ├─ 缺省版本 = 浅拷贝（public）
│   └─ 自定义 → 深拷贝 / 禁止拷贝(=delete) ★★★
├─ 浅拷贝隐患：指针成员共享 → 重复释放/悬空 ★★★
├─ 对象赋值 operator= —— 修改已有对象 ★★★
│   ├─ 缺省版本 = 浅赋值（引用成员禁止）★★★
│   └─ 自定义 → 必须返回 T& ★★★ + 自我赋值判定 ★★★
└─ 推荐实现：copy-and-swap（异常安全）★★★
```

---

## 一、拷贝 vs 赋值：先分清这对最容易混的概念 ★★★

| 判断依据 | 拷贝构造 | 赋值 |
|---|---|---|
| 对象是否已存在 | **不存在**（从无到有） | **已存在**（修改内容） |
| 调用的函数 | 拷贝构造函数 `T(const T&)` | `operator=` |
| 典型写法 | `A a2(a1);` `A a3 = a2;` | `a3 = a1;`（a3 已定义过） |

> ⚠️ 易错点 ★★★：`A a3 = a2;` 虽有 `=`，但因为 a3 是**新定义**变量 → 本质是**拷贝构造**，不是赋值！只有左边对象**已存在**才是赋值。

---

## 二、拷贝构造函数

### 2.1 判定依据

| 要点 | 结论 |
|---|---|
| 参数个数/类型 | 必须且只有一个**本类对象**（引用） |
| 能否传值传参 | ★★★ **不能**，否则调用自身导致无限递归 |
| 常见形式 | `T(const T& rhs);` |
| C++11新增 | `T(T&& rhs)`（移动构造，另一话题） |
| 特殊形式 | `T(T& rhs)` 可用于"所有权转移"（非const） |

### 2.2 调用方式速查

| 场景 | 是否触发 |
|---|---|
| `A a2(a1);` / `A a3 = a1;` | 显式调用 |
| 按值传参 | 隐式调用 |
| 按值返回局部对象 | 隐式调用，但可能被 **RVO** 优化掉 |
| 匿名对象 `return A(2);` | 更利于编译器优化 |

### 2.3 缺省拷贝构造函数 ★★★

| 属性 | 结论 |
|---|---|
| 谁生成 | 未自定义时编译器自动生成 |
| 访问权限 | public |
| 拷贝方式 | **浅拷贝**（位拷贝） |

### 2.4 浅拷贝各类成员处理方式（记忆表）★★★

| 成员类型 | 浅拷贝行为 |
|---|---|
| 静态成员 | 不参与拷贝 |
| 内置类型 | 按字节复制 |
| 指针成员 | 只复制地址，**不复制所指内容** ← 隐患根源 |
| 对象成员 | 自动调用该类自己的拷贝构造函数（递归） |
| 引用成员 | 不推荐使用 |

### 2.5 浅拷贝的问题 ★★★

**判断依据**：类中含指针成员且在构造/析构中 `new`/`delete` 管理资源 → 默认浅拷贝会让两个对象的指针**指向同一块内存** → 析构时**重复释放（double free）**。

```cpp
class B {
public:
    B() { mpA = new A; }
    ~B() { delete mpA; }
private:
    A* mpA;
};
B b1;
B b2(b1);  // 浅拷贝，b1.mpA == b2.mpA，析构时 double free
```

## 三、自定义拷贝构造函数

### 3.1 需要自定义的四种情形 ★★★

| 情形 | 关键词 |
|---|---|
| a. 深拷贝 | 含指针/资源管理 |
| b. 禁止拷贝 | 单件、不可复制类 |
| c. 防止按值传对象 | 避免昂贵/错误的隐式拷贝 |
| d. 其它目的 | 计数、所有权转移、单件 |

### 3.2 三种声明格式

```cpp
T(const T& rhs);              // 自定义实现
T(const T& rhs) = default;    // 显式用默认（浅拷贝）
T(const T& rhs) = delete;     // 禁止拷贝（C++11起）
```

### 3.3 深拷贝写法 ★★★

```cpp
B(const B& b) : mpA(new A(*b.mpA)), mA(b.mA) {}
// 核心：为指针成员重新 new 一块独立内存，再复制内容
```

判断依据：**是否重新分配了独立资源**，而不是简单复制指针值。

### 3.4 禁止拷贝的三种写法对比 ★★★

| 写法 | 报错时机 | 推荐度 |
|---|---|---|
| `private: My(const My&) {}` | 类外调用编译错误；类内部仍可调用 | 一般 |
| `private: My(const My&);`（无实现） | 类外/类内调用均**链接错误** | 较好但发现晚 |
| `My(const My&) = delete;`（C++11起）| **编译错误**（最早发现）| ★★★ 最推荐 |

## 四、对象的赋值

### 4.1 缺省赋值函数 ★★★

| 属性 | 结论 |
|---|---|
| 谁生成 | 未自定义时编译器自动生成 |
| 访问权限 | public |
| 赋值方式 | **浅赋值**（类似浅拷贝逻辑） |
| ★★★ 特别限制 | 类中有**非静态引用成员**时，**禁止**使用默认赋值（编译错误） |

### 4.2 浅赋值的问题 ★★★

比浅拷贝**多一个坑**：赋值前若不先释放原有资源，会造成**内存泄漏**；赋值后两指针指向同一对象，析构时又**重复释放**。

```cpp
B b1, b2;
b1 = b2;  // b1原资源泄漏 + b1.mpA与b2.mpA指向同一对象(后续double free)
```

## 五、自定义赋值函数 operator=

### 5.1 三种声明格式

```cpp
T& operator=(const T& rhs);              // 自定义
T& operator=(const T& rhs) = default;    // 用默认
T& operator=(const T& rhs) = delete;     // 禁止赋值
```

### 5.2 必须返回引用 T&，不能返回 void 或值 ★★★

| 判断依据 | 返回 void | 返回值（非引用） | 返回引用 T&（正确）|
|---|---|---|---|
| `a=b=c;` | 编译错误 | 能编译但多一次拷贝，低效 | 正确、高效 |
| `(a=b)=c;` | 编译错误 | 修改的是临时对象，语义错误 | 正确，与内置类型一致 |

**记忆口诀**：内置类型（int）支持链式赋值和 `(a=b)=c`，自定义类型要保持一致行为 → **必须返回 `*this` 的引用**。

### 5.3 自我赋值判定 ★★★

**触发条件**：`a = a`，或通过引用/指针间接指向同一对象（如 `b1 = b2` 但 `b2` 是 `b1` 的引用）。

**危险原因**：先 `delete` 旧资源，此时 `rhs` 与 `*this` 是同一对象，`rhs` 的数据已被删除 → 复制到野指针 → 出错。

```cpp
B& B::operator=(const B& rhs) {
    if (&rhs != this) {          // 比较地址，不是内容
        delete pch;
        pch = new char(*rhs.pch);
    }
    return *this;
}
```

> ⚠️ 判断依据是 `&rhs != this`（地址比较），不是内容比较。

### 5.4 异常安全实现：copy-and-swap ★★★（推荐记住）

```cpp
// 版本1
B& B::operator=(const B& rhs) {
    B temp(rhs);
    swap(pch, temp.pch);
    return *this;
}
// 版本2（参数按值传递，更简洁）
B& B::operator=(B rhs) {
    swap(pch, rhs.pch);
    return *this;
}
```

**优点**：
- 不需要显式判断自我赋值
- 若拷贝构造中途异常，`*this` 尚未被修改，天然**异常安全**

## 六、易混淆点汇总表 ★★★

| 易混点 | 结论 |
|---|---|
| `A a3 = a2;` 是拷贝还是赋值 | **拷贝构造**（a3是新对象） |
| 拷贝构造参数能否传值 | **不能**，只能传引用 |
| 缺省拷贝构造/赋值 是深还是浅 | 都是**浅**拷贝/浅赋值 |
| 引用成员对赋值的影响 | 有非静态引用成员 → **禁止默认赋值** |
| 禁止拷贝最佳写法 | `= delete`（C++11），编译期报错 |
| operator= 返回类型 | 必须是 `T&`（引用），不能是 `void`/`T` |
| 自我赋值判定写法 | `if (&rhs != this)` |
| 最推荐的赋值实现方式 | copy-and-swap（异常安全） |
