## 1. 黑盒复用 vs 白盒复用

| | 黑盒复用 | 白盒复用 |
|---|---|---|
| 对应关系 | 水平关系：普通关联/聚合/组合/依赖 | 垂直关系：继承 |
| 复用的是 | **功能**（接口） | **实现**（代码） |
| 耦合度 | 低，改基类实现不影响使用方 | 高，直接绑定实现细节 |

---

## 2. 继承语法要点

```cpp
class <派生类名> : <继承方式> <基类名>, ... { };
```

- 继承方式：`public` / `protected` / `private`，**★★★ 不写默认 private**
- 单继承：1个基类；多（重）继承：≥2个基类
- 派生类可继续被继承 → 多层继承/继承树
- **只有 public 继承下**，才称基类=父类，派生类=子类

---

## 3. 派生类成员及访问控制★★★

### 派生类成员构成
- 自己新定义的成员
- 基类**全部**成员（**不含**基类的构造/析构/拷贝构造/赋值/自动类型转换函数）

### 访问控制映射表（必背）

| 继承方式 \ 基类中级别 | public | protected | private |
|---|---|---|---|
| public 继承 | public | protected | 不可访问 |
| protected 继承 | protected | protected | 不可访问 |
| private 继承 | private | private | 不可访问 |

**判断口诀**：
- 基类 private 成员 → 派生类**永远访问不了**（但仍占内存，因为基类自身函数运行时要用）
- 继承方式决定"上限"：private继承把可继承成员全压成private；protected继承把public压成protected

### 易错题型
给一段 Base/Derived 代码，问某语句合不合法 —— 先看该成员在基类中的级别，再对照继承方式查表，最后看是否在类内部（类内部可以访问protected/public，不能访问基类private）。

### ★★★ 继承范围 ≠ sizeof计量范围
- 继承的成员：非静态数据成员 + 成员函数 + 静态成员（构造/析构/拷贝/赋值/自动转换除外）
- 计入 sizeof 的：只有**非静态数据成员**；静态数据成员不计入；成员函数不占对象空间（有虚函数时每对象多一个vptr）

## 4. 派生类构造和析构★★★

| 规则 | 内容 |
|---|---|
| 不自动继承 | 基类的构造、拷贝构造、赋值、自动转换函数**不会被自动继承** |
| 构造顺序 | **先基类，再派生类**（多重继承按继承列表书写顺序依次构造） |
| 析构顺序 | **先派生类，再基类**（与构造完全相反） |
| 初始化列表 | 可指定调用基类的构造函数/拷贝构造函数，如 `Derived(int n1,int n2):Base(n1),val(n2){}` |

**经典例题结论**：
```cpp
Derived d(1,99);
// 输出顺序：Base构造 → Derived析构 → Base析构
```
判断输出题时，先按"先基后派"顺序模拟构造，再按"先派后基"顺序模拟析构。

## 5. 派生类拷贝构造和赋值函数★★★

| 场景 | 正确写法 | 易错点 |
|---|---|---|
| 拷贝构造 | `B(const B& o):A(o){ mNum=o.mNum; }` | 忘记在初始化列表写 `A(o)`，导致基类部分走默认构造而非拷贝 |
| 赋值函数 | `A::operator=(rhs); mNum=rhs.mNum;` | 忘记加 `A::` 作用域，或忘记显式调用基类赋值 |

**结论**：这两类函数同样**不会被自动继承**，必须手动负责基类部分的拷贝/赋值。

---

## 6. newdefine / redefine / overload / overwrite(hide) / override★★★

| 术语 | 判断依据 |
|---|---|
| newdefine | 基类中**无**同名函数 |
| redefine | 基类中有**同名同原型**函数 |
| overload | **同一作用域**内同名不同参 |
| overwrite / hide | 派生类定义了与基类**同名**的函数（不论参数是否相同），**基类所有同名版本（含重载）全部被隐藏** |
| override | 基类函数是 **virtual**，派生类定义同名同签名函数 |

**★★★ 高频坑点**：只要派生类出现和基类同名的函数，基类中该名字下**所有重载版本**在派生类作用域内都不可直接调用（即使参数不同也会被隐藏）。

**解决隐藏问题**：
```cpp
using A::f;   // 把基类中所有f都恢复可见
```

**判断口诀**：
1. 先看基类有没有同名 → 没有=newdefine
2. 有同名，签名完全一致 → redefine
3. 派生类内部多个同名（不看基类）→ overload
4. 派生类同名导致基类同名函数（含重载组）不可见 → overwrite/hide
5. 基类同名函数带 virtual → override

## 7. 继承的含义★★★

| 继承方式 | 逻辑关系 | 关键词 |
|---|---|---|
| public | **is-a / is a kind of / like a** | "是一个……" |
| private | **has-a / contain-a / implement of** | "有一个/借助……实现" |
| protected | 同 private，但可在**多层继承**中保持该关系 | 多层传递 has-a |

**共性**：无论哪种继承方式，**基类源代码必须存在**（区别于组合，组合可以只要接口无需源码）。

**public继承的核心价值（is-a的好处）**：
- 需要一个基类对象的地方，传派生类对象也合法（形参 `Car&` 可传 MTCar/ATCar对象）
- 这种可替代性是黑盒复用（关联）做不到的，是多态的基础

---

## 8. 组合 vs 继承的选择★★★

| | 组合 | 继承 |
|---|---|---|
| 关系 | has-a / contain-a | public=is-a；private/protected=has-a(可被组合替代) |
| 源码要求 | 可有可无 | 必须有源码 |
| 层次 | 水平，层次浅 | 垂直，易形成继承树，层次深 |

**选择结论（必背）**：
1. **优先选择组合，而不是继承**
2. **只有需要派生新子类（即需要 is-a / 多态）时，才采用 public 继承**
3. private/protected 继承表达的 has-a 关系，**完全可以用组合替代**，且组合耦合更松、更易维护

## 速记 Checklist

- [ ] 继承语法默认继承方式是 **private**，不是public
- [ ] 派生类不自动继承基类的：构造、析构、拷贝构造、赋值、自动类型转换函数
- [ ] 访问控制映射表三行三列，能默写：public继承(public→public,protected→protected,private→不可访问)；protected继承(public→protected,protected→protected)；private继承(全压成private)
- [ ] 基类private成员，派生类**内部**代码依然无法直接访问（能背出为什么还要保留：基类自身函数运行需要）
- [ ] 构造顺序：**先基类后派生类**；析构顺序：**先派生类后基类**
- [ ] 拷贝构造/赋值函数要显式调用基类版本：`Base(other)` / `Base::operator=(rhs)`
- [ ] 能区分 newdefine / redefine / overload / overwrite(hide) / override 五个术语的判断依据
- [ ] 记住"同名隐藏"的坑：派生类只要有同名函数，基类**所有重载版本**都被隐藏，可用 `using 基类::函数名;` 解决
- [ ] override 的前提是基类函数为 **virtual**
- [ ] public继承 = is-a；private/protected继承 = has-a（等价于组合）
- [ ] 无论哪种继承方式，基类**源代码必须存在**
- [ ] 选型口诀：**优先组合，需要is-a/多态才用public继承**
