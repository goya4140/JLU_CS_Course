## 二、逐节详解

### 1. 虚机制的引入

**是什么**：先看一个"反常"的例子——`Shape` 基类里有个 `show()` 调用 `area()`，`Rectangle`、`Circle` 各自重新定义了 `area()`。当我们通过基类引用 `Shape&` 去调用 `show()` 时，期望它能自动调用到子类真正的 `area()`，但如果没有 `virtual` 关键字，实际输出永远是 `0`。

**反例（没有 virtual）**：

```cpp
class Shape {
public:
    void show() const { cout << "面积是:" << area() << endl; }
    float area() const { return 0; }        // 普通函数
};
class Rectangle : public Shape {
public:
    Rectangle(float w, float h) { mWidth = w; mHeight = h; }
    float area() const { return mWidth * mHeight; }   // 只是"重定义"，没有多态效果
private:
    float mWidth, mHeight;
};
class Circle : public Shape {
public:
    Circle(float r) : mRadius(r) {}
    float area() const { return mRadius * mRadius * 3.14; }
private:
    float mRadius;
};

int main() {
    Rectangle rect(1, 2);
    Circle    cir(1);
    Shape& sp1 = rect;
    Shape& sp2 = cir;
    sp1.show();   // 输出 0 ，为什么？
    sp2.show();   // 输出 0 ，为什么？
}
```

**为什么会这样**：因为编译器在编译 `sp1.show()` 内部那句 `area()` 调用时，只根据 `sp1` 的**声明类型**（`Shape&`）去查找 `area()` 该调用谁的版本，编译期就"钉死"了调用 `Shape::area()`，完全不管 `sp1` 实际引用的是 `Rectangle` 还是 `Circle` 对象——所以不管 rect、cir 内部数据是多少，算出来的永远是基类那个"返回 0"的版本。

**怎么解决**：给 `area()`（以及析构函数）加上 `virtual` 关键字，让编译器在运行时才决定到底调用哪个版本：

```cpp
class Shape {
public:
    virtual ~Shape() {}
    void show() const { cout << "面积是:" << area() << endl; }
    virtual float area() const { return 0; }        // 加 virtual
};
class Rectangle : public Shape {
public:
    Rectangle(float w, float h) { mWidth = w; mHeight = h; }
    virtual float area() const { return mWidth * mHeight; }   // override
private:
    float mWidth, mHeight;
};
class Circle : public Shape {
public:
    Circle(float r) : mRadius(r) {}
    virtual float area() const { return mRadius * mRadius * 3.14; }
private:
    float mRadius;
};

int main() {
    Rectangle rect(1, 2);
    Circle    cir(1);
    Shape& sp1 = rect;
    Shape& sp2 = cir;
    sp1.show();   // 正确输出 2
    sp2.show();   // 正确输出 3.14
}
```

这就是"虚机制"要解决的核心问题：**让基类指针/引用能够"认出"对象的真实类型，调用到位**。

> 类比：你有一张"经理"的名片（类型是 `Shape`），但名片背后其实是"销售经理"或"技术经理"（真实类型是 `Rectangle`/`Circle`）。不用虚函数，别人永远只按"经理"这张名片上写的通用职责办事；用了虚函数，别人会先看看这个人到底是谁，再按他真实的职责办事。

### 2. 静态编联与动态编联

| 对比项 | 静态编联（早绑定） | 动态编联（晚绑定） |
|---|---|---|
| 决定时机 | 编译期间 | 运行期间 |
| 依据 | 变量的**静态类型**（声明类型） | 变量的**动态类型**（实际对象类型） |
| 例子 | `Shape& sp1 = rect; sp1.show();`（未加 virtual 时） | 加了 `virtual` 后的函数调用 |
| 实现手段 | 普通函数调用（默认方式） | 虚机制（虚函数 + 虚函数表） |

**理解要点**：C++ 默认所有函数调用都是"静态编联"，只有被 `virtual` 修饰、且通过指针/引用调用的函数，才会启用"动态编联"。动态编联正是多态（同一操作作用于不同对象产生不同行为）得以实现的技术基础。

### 3. 虚函数

#### 3.1 声明与定义

```
声明：virtual 返回类型 函数名(参数列表) [const];
定义：和普通成员函数完全一样，只是声明处带 virtual
```

#### 3.2 使用规则

| 规则 | 说明 |
|---|---|
| 必须是成员函数 | 全局函数、友元函数不能是虚函数 |
| 不能是静态成员函数 | 因为虚函数依赖对象的 vptr，静态函数没有 this 指针 |
| 不能是构造函数 | 对象还没构造完，没法通过虚函数表分派 |
| 拷贝构造函数不能是虚的 | 同上原因 |
| **析构函数可以是虚的**，而且**推荐是虚的** | 若类有其他虚函数，析构函数最好也定义为虚函数（原因见第4节） |
| 赋值函数通常不定义为虚的 | 见"最佳实践 7" |
| 可以带 const，也可以不带 | 与普通成员函数一致 |
| 访问控制随意 | public / protected / private 都可以（但不建议 private，见"最佳实践5"） |

#### 3.3 派生类中的虚函数

派生类会自动继承基类的虚函数（析构函数除外，但如果基类析构是虚的，派生类析构也自动是虚的）。派生类中虚函数的三种情况：

1. **继承**：不重写，直接用基类版本；
2. **新增**：派生类自己定义的新虚函数；
3. **override（重写/复写）**：函数名与基类虚函数相同，`virtual` 关键字可省略，返回类型必须相同或"相容"（协变返回类型）。

⚠️ 注意"隐藏"陷阱：如果函数名相同但参数列表不同，派生类的这个函数并没有 override 基类的重载版本，而是**隐藏**了基类中所有同名的重载函数（这个坑在"最佳实践6"会详细讲）。

**例题（虚函数例）**：

```cpp
class Parent {
public:
    Parent();
    virtual ~Parent() {}
    void f();
    virtual void g();
protected:
    virtual void k();
};

class Child : public Parent {
public:
    Child(); ~Child() {}
    void other();
    void g();      // override 基类的 g()
protected:
    void h();       // 新增虚函数
};
```

- Parent 类的 3 个虚函数：`~Parent()`、`g()`、`k()`
- Child 类的 4 个虚函数：`~Child()`（继承并变虚）、`g()`（override）、`k()`（继承自父类，未重写）、`h()`（新增）

### 4. 虚函数表（vtable）与虚函数指针（vptr）

**是什么**：虚函数表是一个"指针数组"，每个元素存放某个虚函数的入口地址（真正的机器码位置）。

**关键规则**：

| 规则 | 解释 |
|---|---|
| 类中至少有一个虚函数才会生成虚函数表 | 没有虚函数就没有 vtable |
| 一个类至多一张虚函数表，所有该类对象**共享**它 | 节省内存，不是每个对象都复制一份 |
| 首次创建该类对象时，内存中同时生成该类的虚函数表 | 虚函数表属于"类"，不属于"对象" |
| 表中按函数声明顺序依次存放入口地址 | 派生类新增的虚函数追加在表末尾，override 的虚函数则**替换**对应位置的地址 |
| 每个对象内部存有一个隐藏指针 **vptr**，指向所属类的虚函数表 | vptr 才是"对象级别"的东西，每个对象都有自己的 vptr |

**图示理解（以 Parent/Child 为例）**：

```
Parent 类的虚函数表          Child 类的虚函数表
┌─────────────────┐        ┌─────────────────┐
│ &Parent::~Parent │        │ &Child::~Child    │
│ &Parent::g       │        │ &Child::g   (覆盖) │
│ &Parent::k       │        │ &Parent::k (继承)  │
└─────────────────┘        │ &Child::h  (新增)  │
                             └─────────────────┘
```

**vptr 的位置**：对象内存布局中，vptr 通常放在对象数据的最前面。当你 `new` 一个对象时，vptr 会被设置为指向对应类的虚函数表。

### 5. 虚函数的作用机制

#### 5.1 静态类型 vs 动态类型

| 类型 | 定义 | 举例 |
|---|---|---|
| 静态类型 | 编译期就能确定的变量类型（声明的类型） | `Parent* pObj = &child;` → pObj 静态类型是 `Parent*` |
| 动态类型 | 运行时才能确定的、变量所指对象的真实类型 | pObj 实际指向 `Child` 对象 → 动态类型是 `Child` |

指针型、引用型的静态类型和动态类型**可以不同**；对象型（值类型）变量的静态类型和动态类型**永远一致**（因为对象赋值会发生"对象切割"，不会真正变成子类对象）。

#### 5.2 函数调用的编译过程（以 `p->func()` 为例）

这是本章最核心的原理，编译器按以下步骤处理：

1. 确定 `p` 的**静态类型**，比如 `A*`；
2. 在 `A` 类中查找名字为 `func`、参数能匹配的函数；
3. 找不到 → 编译错误；
4. 找到了，看它是不是 `virtual`：
   - **不是虚函数** → 编译成 `p->A::func();`（静态编联，写死调用 A 版本）
   - **是虚函数** → 编译成 `(*p->vptr)[index]((void*)p, ...);`（动态编联，运行时查 vptr 指向的虚函数表，按下标取出真正该调用的函数地址）

**重要结论**：不管是不是虚函数，**能不能编译通过，永远只看静态类型里有没有匹配的函数**；虚不虚只决定"调用哪个版本"，不决定"能不能调用"。即使这个匹配到的函数永远不会真正被执行到，也必须在静态类型对应的类里"有名有份"。

#### 5.3 例题演练

**例1**：

```cpp
class A {
public:
    virtual ~A() {}
    virtual void f2();
    virtual void g();
};
class B : public A {
public:
    virtual void f1();
    virtual void f2();   // override
    virtual void f3();
};

A* p1 = new A;
p1->f2();   // 编译成 (*p1->vptr)[1](p1) → 调用 A::f2
p1->g();    // (*p1->vptr)[2](p1) → A::g
p1->f1();   // 编译错误！A 类中没有 f1

A* p2 = new B;
p2->f2();   // (*p2->vptr)[1](p2) → 调用 B::f2（动态编联生效）
p2->g();    // (*p2->vptr)[2](p2) → A::g（B 没重写，继承的）
p2->f1();   // 编译错误！p2 的静态类型是 A*，A 类没有 f1
```

> 注意最后一行：即使 p2 实际指向的是 B 对象（B 有 f1），但 `p2->f1()` 依然**编译不过**，因为查找是按**静态类型 A\*** 找的。这是初学者最容易踩的坑。

**例2 / 例3**：原理相同，都是"基类指针/引用调用虚函数 → 动态编联 → 输出子类真实版本的结果"，可自行对照 PDF 验证结果（如 `pDate1->display()` 输出 USA 格式日期，`func(pDate2)` 输出中国格式日期）。

### 6. 虚函数的访问规则

这一节回答一个问题：**"在什么函数里调用虚函数，才会真正触发动态编联？"**

| 场景 | 编联方式 | 说明 |
|---|---|---|
| 虚函数中访问非虚函数 | 静态编联 | 非虚函数本身就没有多态性，永远用本地（当前类）版本 |
| 非虚函数中访问虚函数 | 动态编联 | 只要是虚函数调用，就看对象真实类型 |
| 虚函数中访问虚函数 | 动态编联 | 同上 |
| **构造函数中调用虚函数** | **静态编联（本地版本）** | 对象正在构造，子类部分还没建好，只能调用当前构造层所在类的版本 |
| **析构函数中调用虚函数** | **静态编联（本地版本）** | 析构是从子类到基类顺序执行，执行到基类析构时子类部分已被销毁，同样只能调本地版本 |
| 私有虚函数 | 依然动态编联 | 这是 C++ 区别于其他语言的地方！private 只影响"谁能直接调用"，不影响虚函数表机制 |

**构造/析构调用本地虚函数 —— 例子**：

```cpp
class A {
public:
    A(): mA(100) { f(); }        // 构造中调用f() → 用 A::f()
    virtual ~A() { f(); }        // 析构中调用f() → 用 A::f()
    virtual void f() { cout << mA; }
private:
    int mA;
};
class B : public A {
public:
    B(): mB(200) { }
    virtual ~B() { f(); }        // 析构中调用f() → 用 B::f()
    virtual void f() { cout << mB; }
private:
    int mB;
};
```

- 创建 `B b;` 时：先构造基类 A，此时 A 的构造函数体内调用 `f()`，此刻对象还只是"半成品"（B 部分尚未构造），所以调用的是 **A::f()**，而不是 B::f()。
- 释放 `b` 时：先执行 `B::~B()`（其中调用的是 B::f()，因为此时 B 部分还在），然后执行 `A::~A()`（此时 B 部分已经析构完毕），其中调用的 `f()` 只能是 **A::f()**。

**私有虚函数的例子（区别于其他语言）**：

```cpp
class A {
public:
    virtual void vPub1() { vPriv(); vProt(); }  // 基类的公有函数里调私有虚函数
private:
    virtual void vPriv() { cout << "A::vPriv()"; }
};
class B : public A {
private:
    virtual void vPriv() { cout << "B::vPriv()"; }  // 重写私有虚函数
};

A* pA = new B;
pA->vPub1();   // 依然会调用 B::vPriv()！因为虚函数表机制不受访问权限影响
```

这说明：**虚函数的"是否能被重写/动态分派"和"访问权限"是两回事**——private 只是限制了"外部代码能不能直接写 `obj.vPriv()`"，但虚函数表内部照样按真实类型分派。

### 7. 具体类和抽象类

| 概念 | 定义 |
|---|---|
| 具体类 | 可以直接 `new` 出对象的类 |
| 抽象类 | 含有至少一个"纯虚函数"的类，**不能被实例化**，但派生类可以（前提是派生类把纯虚函数都实现了） |
| 纯虚函数 | `virtual 返回类型 func(参数) [const] = 0;`，只声明不实现（或只提供"范本实现"） |

**纯虚函数说明**：

1. 必须是成员函数（非静态）
2. 必须是虚函数
3. 访问控制可以是 public/protected/private
4. 函数体后面加 `= 0;`
5. 派生类若想成为"具体类"，**必须显式实现**所有继承来的纯虚函数
6. 本质上是在告诉子类："你必须拥有这个能力，具体怎么实现你自己定"

**纯虚定义（给纯虚函数一个默认实现）**：

纯虚函数虽然要求子类必须重写，但**它自己也可以有函数体**！这叫"纯虚定义"，目的有两个：
1. 给子类提供部分可复用的实现代码（子类重写时可以调用 `基类::函数名()` 来复用这部分逻辑）；
2. 给子类的实现提供一个"范本"。

```cpp
class Table {                       // 抽象类
public:
    virtual ~Table() = default;
    virtual void show() const = 0;  // 纯虚函数
};
// 纯虚定义：给出默认实现
void Table::show() const {
    cout << "显示表格头部内容" << endl;
    cout << "==================" << endl;
}
class ExcelTable : public Table {
public:
    virtual void show() const override {
        Table::show();   // 复用基类提供的"范本"部分
        // ...... 自己的部分
    }
};
```

**接口类**：一种特殊的纯抽象类——除了（可能有的）虚析构函数外，**所有成员函数都是纯虚函数**，且**通常没有任何非静态数据成员**，成员访问权限一般都是 public。它相当于一份"契约"：只规定"必须能做什么"，不关心"怎么做"、也不携带状态。

**类的层次关系小结**：

| 父类 | 子类 | 是否合法 |
|---|---|---|
| 具体类 | 具体类 / 抽象类 | 都合法（一个具体类的子类仍可以再声明纯虚函数变成抽象类） |
| 抽象类 | 具体类 / 抽象类 | 都合法（子类可以只实现部分纯虚函数，剩下的自己仍是抽象类） |

### 8. 运行时类型识别（RTTI）

C++ 提供两种"在运行时问一个对象到底是什么类型"的手段：

#### 8.1 `typeid`

```cpp
typeid(exp)        // exp 是表达式
typeid(type_name)   // 直接给类型名
```

返回一个 `const type_info` 对象，可用 `==` 比较。

| exp 的形式 | 返回的是什么类型 |
|---|---|
| exp 是指针 | 静态类型（指针本身的类型），**不看指向对象的真实类型** |
| exp 是类类型（对象/引用）且该类含虚函数 | 动态类型（对象的真实类型） |

```cpp
class A { /* 含虚函数 */ };
class B : public A {};
A* p1 = new B;
typeid(p1) == typeid(A*)   // TRUE  （p1 本身是 A* 类型的指针变量）
typeid(p1) == typeid(B*)   // FALSE
typeid(*p1) == typeid(A)   // FALSE （*p1 是对象，看真实类型 B）
typeid(*p1) == typeid(B)   // TRUE
```

> 记忆技巧：**"看指针本身，只看它声明的类型；一旦解引用变成对象，且类里有虚函数，就看它骨子里真正是谁。"**

#### 8.2 `dynamic_cast<T>(exp)`

用于"安全的向下转型"（父类指针/引用转成子类指针/引用），要求基类必须**至少有一个虚函数**（否则无法做运行时类型检查）。

| T 的形式 | 转换失败时的表现 |
|---|---|
| T 是指针类型 | 返回 `nullptr` |
| T 是引用类型 | 抛出 `bad_cast` 异常 |

```cpp
class A {};
class B : public A {};
class C : public A {};

A* p1 = new B;
A* p2 = new C;

B* pb = dynamic_cast<B*>(p1);   // 成功，pb 非空
if (pb) { pb->Func(); }         // 转换失败要判空再用！

B& b = dynamic_cast<B&>(*p1);   // 成功则继续；若 p1 实际不是 B，会抛异常
b.Func();
```

> 使用口诀：**指针转失败给你个 nullptr（自己判空），引用转失败直接抛异常（自己 try-catch）**。

### 9. 最佳实践（编码规范）

下面 8 条是编写含虚函数的类时的经验性建议，理解"为什么"比死记更重要。

#### (1) 虚/非虚函数的选择

- 如果一个方法**需要子类给出不同实现** → 定义为虚函数（只提供接口，不强制实现方式）
- 如果一个方法是**所有子类的通用逻辑** → 定义为非虚函数（子类继承的是"接口+实现"，不应该改）

```cpp
class Shape {
public:
    virtual ~Shape() = default;              // 显式定义虚析构
    void show() const                        // 非虚：通用展示逻辑，不需要子类改
        { cout << "面积是" << area() << endl; }
    virtual double area() const = 0;          // 纯虚：每个形状面积算法不同
};
```

#### (2) 使用 `override` 关键字

C++11 起，子类重写虚函数时加上 `override`，编译器会帮你检查：函数名、参数类型顺序、返回类型是否与基类**真的匹配**。不加的话，写错了（比如多加了 `const`、改了返回类型）编译器不会报错，只会悄悄地"新增了一个不相关的函数"，非常隐蔽的 bug。

| ❌ 容易踩坑的写法 | ✅ 推荐写法 |
|---|---|
| `virtual void vf() const;`（父类没有 const，这其实是新增而非重写） | `virtual void vf() override;`（编译器发现不匹配会直接报错） |
| `virtual int vg();`（返回类型对不上） | `virtual void vg() override;` |

#### (3) 不要重定义父类的非虚函数

因为非虚函数走的是静态编联，重定义了子类也不会被多态调用到，容易造成"通过基类指针调用到旧版本、通过子类对象调用到新版本"的行为不一致，逻辑混乱。

```cpp
class Rectangle : public Shape {
public:
    void show() const   // ❌ 不好：重定义了非虚函数
        { cout << "矩形的面积是" << area() << endl; }
    virtual double area() const;
};
```

#### (4) 显式定义虚的析构函数

如果类会被继承、且可能通过**基类指针**删除子类对象（`delete pBase;`），析构函数**必须是虚的**，否则只会调用基类的析构函数，子类部分的资源不会被释放（内存泄漏/资源泄漏）。

```cpp
Shape* p = new Rectangle;
delete p;   // 若 ~Shape() 不是虚的，只会执行 ~Shape()，Rectangle 部分未析构！
```

#### (5) 不要定义私有的虚函数

虽然语法上合法（如第6节例子所示，私有虚函数依然能被动态分派），但会让代码难以理解——别人看基类源码时看不到"这个虚函数其实是可以被子类重写的公共接口"，容易产生误解。建议虚函数至少是 protected，通常是 public。

#### (6) 不要重载虚函数

虚函数一旦被重载（同名不同参数），容易触发"隐藏"问题：子类只重写了一个重载版本，其余重载版本会被**隐藏**（不是重写，是完全遮蔽），导致本以为能通过对象调用的重载版本，编译报错。

```cpp
class Parent {
public:
    virtual void f();
    virtual void f(int n);
};
class Child : public Parent {
public:
    virtual void f() override;   // 只重写了 f()，没碰 f(int)
};

Child child;
child.f(3);      // ❌ 编译错误！Child::f() 隐藏了 Parent::f(int)
Parent& p = child;
p.f(4);          // ✅ 可以，因为是按 Parent 的静态类型找的，没被隐藏
```

#### (7) 不要定义虚的赋值函数

赋值运算符 `operator=` 如果定义成虚函数，参数类型（基类引用）和返回类型（协变）之间的一致性很难保证类型安全，容易出现"用基类对象给子类对象赋值却调用了错误版本"的诡异行为（切割赋值），所以推荐 `operator=` 保持非虚。

#### (8) 使用接口类和抽象类

接口类/抽象类比具体类**抽象层次更高、更稳定**（不容易因为需求变化而改动）。接口类由于**没有实例变量**，在多重继承场景下能避免命名冲突/数据成员冲突的问题，是一种更安全的"接口继承"方式。

## 三、本章小结

1. **虚机制的本质**：让基类指针/引用调用成员函数时，能在**运行时**（而非编译时）根据对象的**真实类型**决定调用哪个函数体，这就是"动态编联"，是实现多态的技术基础。
2. **静态编联 vs 动态编联**：默认是静态编联（编译期定死）；只有 `virtual` 修饰的函数通过指针/引用调用，才走动态编联。
3. **虚函数的实现原理**：每个含虚函数的类有一张共享的"虚函数表"（vtable），每个对象内部有一个指向该表的"vptr"；虚函数调用被编译为"查 vptr → 按下标取函数地址 → 调用"。
4. **函数调用能否编译通过，只看静态类型**；虚不虚只决定运行时调用哪个版本，不决定编译期能不能找到这个函数。
5. **特殊场景的编联规则**：构造函数、析构函数内部调用虚函数一律走**静态编联**（用本地/当前构造层版本）；私有虚函数依然遵循动态编联（不受访问权限影响）。
6. **抽象类与纯虚函数**：含有纯虚函数（`= 0`）的类是抽象类，不能实例化；纯虚函数也可以有函数体（纯虚定义），供子类复用；接口类是特殊的纯抽象类，通常无数据成员。
7. **RTTI**：`typeid` 用来查询/比较类型（对指针看静态类型，对含虚函数的对象看动态类型）；`dynamic_cast` 用于安全的向下转型，指针失败返回 `nullptr`，引用失败抛异常。
8. **8 条最佳实践的核心思想**：虚函数只承载"接口"，非虚函数承载"通用实现"；析构函数在有虚函数时必须显式声明为虚的；避免私有虚函数、虚的重载函数、虚的赋值函数带来的隐蔽陷阱；优先用抽象类/接口类组织稳定的高层设计。
