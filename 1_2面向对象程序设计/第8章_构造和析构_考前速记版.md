## 一、构造函数速记

| 要点 | 结论 |
|---|---|
| 格式 | 名字=类名，**无返回值**（连void都不写） |
| 可重载 | ✅ 参数不同即可 |
| 访问控制 | 可 public / private（单例模式用 private）|
| `explicit` ★★★ | 只对单参数构造函数有意义；**禁止隐式类型转换**（`int→类` 不再自动发生）|
| 判断依据 | 看到 `f(100)` 而形参是类类型 → 先看该类单参数构造有没有 `explicit`，有则报错 |

**单例模式判断依据**：构造函数私有 + 静态成员函数返回唯一实例（引用/指针两种写法均可）。

### 二义性问题 ★★★
- **成因**：多个构造函数因缺省参数产生"参数个数相同、都能匹配"的情况。
- **判断依据**：调用时若有 ≥2 个构造函数同样合适 → 编译报错（二义性/模棱两可）。
- **规避方法**：把多个重叠的构造函数合并成**一个**带缺省值的构造函数。

```cpp
Name(int v1);              // 与下面的重叠 →
Name(int v1,int v2=999);   // Name obj(200) 二义性错误！
// 应合并为：
Name(int v1=0,int v2=999);
```

## 二、缺省构造函数速记

| 判断点 | 结论 |
|---|---|
| 定义 | 无参、public、编译器自动生成 |
| 生成条件 | **仅当用户完全没写任何构造函数**时才生成 |

### 5种让缺省构造函数"消失"的情形 ★★★

| 情形 | 示例 |
|---|---|
| ① 自定义了任意带参构造 | `A(int n){}` |
| ② 构造函数为 private | `private: A(int n){}` |
| ③ 只声明未实现 | `A(int n);`（无函数体，链接报错）|
| ④ 显式 delete | `A()=delete;` |
| ⑤ 只自定义了拷贝构造函数（新标准）| `A(const A&){}` |

→ 上述任一种情况下，`A a;` 都会**编译报错**。

---

## 三、对象初始化三种方式速记

| 方式 | 能否用于const成员 | 能否用于引用成员 | 备注 |
|---|---|---|---|
| ① 构造函数体内赋值 | ❌ | ❌ | 本质是"赋值"不是"初始化" |
| ② C++17类内指定初值 | ✅（const int/静态整型常量）| 不推荐 | `static const 浮点型` ❌不能类内初始化；非const静态成员 ❌不能类内初始化；`inline static` ✅C++17起可以 |
| ③ 初始化列表 | ✅**必须** | ✅**必须** | 功能最全 |

**易错点 ★★★**：
- `static const float AA = 99.88;`（类内）→ ❌ 错误
- `static int bb = 10000;`（类内）→ ❌ 错误
- `inline static int cc = 200;` → ✅ 正确（C++17及以上）

## 四、初始化列表速记

### 必须使用初始化列表的三类成员 ★★★

| 成员类型 | 判断依据 |
|---|---|
| **const 常量成员** | 值不可二次赋值 |
| **引用成员** | 必须在诞生时绑定，不能改绑 |
| **对象成员（该类无无参构造函数）** | 编译器不知道怎么"先造后填" |

### 初始化顺序规则 ★★★★★（最高频考点）

> **成员初始化顺序 = 类中"声明"的顺序，与初始化列表中书写的顺序无关！**

判断步骤：
1. 按**声明顺序**逐个处理每个成员；
2. 该成员是否在初始化列表中被指定？
   - 是 → 按列表值初始化
   - 否，但有类内初值 → 按类内初值初始化
   - 否，也无类内初值 → 调用其**无参构造函数**（内置类型此时值不确定）
   - 若连无参构造函数也没有 → **编译报错**
3. 全部成员初始化完 → 才进入构造函数 `{ }` 内部执行代码。

```cpp
class Card {
    ...
    Card(int aId, Player& aPlayer)
        : mDesc(aId), mX(99), mID(aId), mPlayer(aPlayer)  // 书写顺序
    { mY = 88; }
private:
    int mX;        // 真实初始化顺序：
    int mY;         // mX → mY → mID → mPlayer → mDesc
    const int mID;   // （按声明顺序，不按列表顺序！）
    Player& mPlayer;
    Description mDesc;
};
```

### C++11 委托构造

- 一个构造函数在初始化列表中调用**本类**另一个构造函数，减少重复代码。
- 格式：`AA(int n): AA(n,"张三") { ... }`

## 五、析构函数速记

| 项目 | 结论 |
|---|---|
| 格式 | `~类名()`，**无参数、无返回值**，不能重载（一个类只有一个析构函数）|
| 访问控制 | 一般 public |
| 职责 | 自定义清理代码执行后，**自动**级联析构对象类型成员，回收其它成员 |
| 缺省析构函数 | 无自定义时，编译器自动提供 public 的默认析构函数 |

---

## 六、构造/析构函数的访问速记

| 存储区域 | 构造/析构触发方式 |
|---|---|
| 程序区（静态/全局对象）| 程序启动/结束时自动构造/析构 |
| 栈区（局部对象）| 生存期结束（如函数返回）**自动**析构 |
| **堆区（`new` 出的对象）** | ★★★ 必须**显式 `delete`** 才会触发析构，否则**内存泄漏**，`~类名()` 不会被调用 |

### 构造函数的三种访问方式
- 显式调用：`A a(5);`
- 隐式调用（自动转换）：无 `explicit` 的单参数构造函数可被隐式使用
- 对象成员创建：类中包含的对象成员，会在外层对象构造时（初始化列表阶段）自动构造

### 易错判断 ★★★
```cpp
class B { public: B(); explicit B(int n); };
class A { public: void method(const B& aB); ... };
A * pa = new A(8);
pa->method(2);   // ❌ 报错：B(int) 有 explicit，2 不能隐式转成 B
delete pa;        // ★★★ 堆对象必须手动delete，否则~A()不会执行
```

## ✅ 速记 Checklist

- [ ] 构造函数：名同类名、无返回值、可重载、可 explicit、可带缺省参数
- [ ] `explicit` 只对单参数构造函数有意义，作用是禁止隐式类型转换
- [ ] 二义性问题：多个构造函数因缺省参数产生歧义 → 应合并成一个
- [ ] 缺省构造函数生成条件：**用户完全没写任何构造函数**（含拷贝构造）
- [ ] 5种让缺省构造函数消失的情形：带参构造/private构造/只声明不实现/`=delete`/自定义拷贝构造
- [ ] 对象初始化三种方式：体内赋值 / C++17类内初值 / 初始化列表
- [ ] `static const float` 类内初始化 ❌；`inline static` C++17起 ✅
- [ ] 三类成员**必须**用初始化列表：const成员、引用成员、无无参构造的对象成员
- [ ] ★★★★★ 成员初始化顺序 = **声明顺序**，与初始化列表书写顺序无关
- [ ] 找不到初始化方式又没有无参构造函数 → 编译报错
- [ ] C++11 委托构造：`A(n): A(n,默认值){}`，避免重复代码
- [ ] 析构函数：`~类名()`，无参无返回值，不能重载，一般public
- [ ] 栈区/静态对象析构：自动；**堆区对象析构：必须手动delete**
- [ ] 单例模式核心：构造函数private + 静态成员函数返回唯一实例
