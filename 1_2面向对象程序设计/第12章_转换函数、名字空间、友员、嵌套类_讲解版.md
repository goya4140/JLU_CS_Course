## 一、转换函数

### 1.1 类型转换有三种情形

C++ 里数据类型转换可以归纳为三类：

| 转换方向 | 说明 |
|---|---|
| 内置类型 ↔ 内置类型 | 例如 `int` 和 `float` 之间，靠编译器内建规则（隐式转换）或强制转换 `(int)fVal` |
| 自定义类型 ← 内置类型 | 例如把一个 `int` 变成一个 `Fraction` 对象，靠**转换构造函数** |
| 自定义类型 ↔ 自定义类型 / 内置类型 | 把自定义类型变成别的类型（包括内置类型），靠**转换运算符（自动转换函数）** |

也就是说，"内置类型转内置类型"编译器天生就会；但只要牵扯到"自定义类型"（也就是你自己写的 class），编译器就不知道该怎么转了，必须由你自己告诉它"怎么转"——这就是本节要讲的两种手段。

**为什么需要它？** 因为很多时候我们希望自定义类型能像内置类型一样自然地参与运算、传参、赋值，而不用每次都手写转换代码。比如你写了一个"分数类" `Fraction`，你希望能直接把一个整数 `2` 传给需要 `Fraction` 参数的函数，也希望能把一个 `Fraction` 对象直接当 `float` 用。这两件事分别对应"转换构造函数"和"转换运算符"。

### 1.2 转换构造函数——把"别的类型"变成"自定义类型"

**是什么**：一个只接收一个参数（或除第一个参数外都有默认值）的构造函数，编译器会把它当作"隐式转换入口"。当函数需要一个 `Fraction`，而你给了一个 `int` 或另一个类的对象时，编译器会自动尝试调用这样的构造函数来完成转换。

**怎么用**：

```cpp
class Fraction {
public:
    Fraction(int numerator, int denominator = 1)
        : num(numerator), den(denominator) { }
    Fraction(const A& a) { /* ... */ }   // 也可以从类 A 转换过来
private:
    int mNum; int mDen;
};

class B {
public:
    void UseFraction(const Fraction& fra);
};

int main() {
    A a; B b;
    b.UseFraction(2);   // int 隐式转换成 Fraction(2,1)
    b.UseFraction(a);   // A 隐式转换成 Fraction
    return 0;
}
```

这里 `UseFraction` 期望的参数是 `Fraction`，但调用时给的是 `int` 或 `A`，编译器发现 `Fraction` 里有能接受这种参数的构造函数，于是自动帮你"造"了一个临时 `Fraction` 对象。

**生活化类比**：就像去便利店买东西，你付的是现金（int），但收银机内部会把它换算成"账户余额"（Fraction）来记账——这个换算规则，就是转换构造函数。

### 1.3 自动转换函数（转换运算符）——把"自定义类型"变成"别的类型"

**是什么**：在类内部定义一个特殊成员函数，形式是 `operator 目标类型名()`，没有返回值类型声明（因为返回类型就写在函数名里了），函数体里必须 `return` 一个目标类型的值。

**格式**：

```cpp
class T {
public:
    [explicit] operator DestType() [const] {
        // ...
        return DestType(...);
    }
};
```

**三个要点**（对应 PPT 中"说明"部分，用自己的话解释）：

1. **必须有 return**：因为这个函数的本质就是"生成一个目标类型的值"，没有 return 就无法完成转换。
2. **可以定义多个转换函数，目标类型不同即可**：一个类可以既能转成 `int`，又能转成 `float`，又能转成另一个类 `A`，只要目标类型互不相同。
3. **自定义类型之间互相转换时要小心二义性**：如果编译器发现有两条转换路径都行得通，且无法判断哪条更优，就会报错。

**完整例子**：

```cpp
class Fraction {
public:
    Fraction(int numerator, int denominator = 1)
        : mNum(numerator), mDen(denominator) { }

    operator int() const { return mNum / mDen; }              // 隐式：转 int
    explicit operator float() const                            // 显式：转 float
        { return ((float)mNum) / mDen; }
    operator A() const { return A(mNum); }                     // 隐式：转 A
private:
    int mNum; int mDen;
};

class B {
public:
    void useInt(int val)   { cout << "int ="   << val << endl; }
    void useFloat(float val){ cout << "float =" << val << endl; }
};

int main() {
    Fraction fra(3, 2);
    B b;
    b.useInt(fra);            // 输出 1  （隐式调用 operator int）
    b.useFloat(fra);          // 输出 1  （fra 先隐式转 int，再提升成 float！）
    b.useFloat((float)fra);   // 1.5     （显式调用 operator float）
    b.useFloat(float(fra));   // 1.5     （同上，另一种写法）
    return 0;
}
```

**这里最容易踩的坑**：`b.useFloat(fra)` 你可能以为会调用 `operator float`，输出 1.5，但实际输出是 **1**！原因是 `operator float` 被标记成了 `explicit`，意味着它**不能被隐式调用**，只有 `operator int` 是隐式的。所以编译器退而求其次，先隐式调用 `operator int` 把 `fra` 转成 `1`，再把这个 `int` 提升为 `float` 传进去，结果自然是 `1.0`。

这也说明了 `explicit` 关键字的作用：**加上 `explicit` 后，这个转换函数只能被显式调用（如 `(float)fra` 或 `float(fra)`），不能在编译器"偷偷"进行的隐式转换中被选中**。这是一种"防呆"设计，避免不经意间发生让人意外的类型转换。

### 1.4 转换构造函数 vs 转换运算符 对照

| | 转换构造函数 | 转换运算符（自动转换函数） |
|---|---|---|
| 写在哪个类里 | 写在"目标类型"（转换的终点）的类里 | 写在"源类型"（转换的起点）的类里 |
| 转换方向 | 别的类型 → 本类 | 本类 → 别的类型 |
| 语法形式 | 单参数构造函数（或其余参数有默认值） | `operator 目标类型()` |
| 能否用 explicit 抑制隐式转换 | 可以（`explicit Fraction(int)`） | 可以（`explicit operator float()`） |

## 二、名字空间的引入

### 2.1 为什么需要名字空间

**问题场景**：假设"张三"和"李四"各自写了一个头文件 `zhang.h` 和 `li.h`，两人都定义了函数 `f()` 和类 `T`：

```cpp
/* zhang.h */
void f();
class T { void zhangFunc(); };

/* li.h */
void f();
void q();
class T { void liFunc(); };
```

**是什么问题**：如果项目里同时 `#include "zhang.h"` 和 `#include "li.h"`，编译器会发现 `f` 和 `T` 都被定义了两次——**命名冲突**，直接编译报错。这在多人协作、引入第三方库时非常常见（想象两个库都用了 `Log` 这个类名）。

**为什么会这样**：C++ 早期没有名字空间机制时，全局作用域里所有的名字都"摊在一起"，只要重名就打架，跟两个人在同一个抽屉里放东西、都想用"文件夹1"这个名字一样。

### 2.2 解决方案：namespace

给每个人的代码加一层"命名空间隔离"：

```cpp
/* zhang.h */
namespace Zhang {
    void f();
    void g();
    class T { void zhangeFunc(); };
}

/* li.h */
namespace Li {
    void f();
    void q();
    class T { void liFunc(); };
}
```

在实现文件（.cpp）里，用 `名字空间::名字` 的方式指明"这是谁的东西"：

```cpp
/* zhang.cpp */
#include "zhang.h"
void Zhang::f() { }
void Zhang::g() { }
void Zhang::T::zhangFunc() { }

/* li.cpp */
#include "li.h"
void Li::f() { }
void Li::q() { }
void Li::T::liFunc() { }
```

**类比**：名字空间就像给每个人分配一个"专属抽屉"，两个人都可以在自己的抽屉里放"文件夹1"，互不影响；要用的时候写清楚"张三的抽屉的文件夹1"（`Zhang::T`），就不会拿错。

## 三、名字空间和名字汇入

### 3.1 几种名字空间

PPT 提到了这几类名字空间概念，逐一解释：

- **std 名字空间**：C++ 标准库把所有内容都放进了 `namespace std { ... }` 里，`#include <iostream>` 大致相当于把 `iostream` 里的内容都塞进了 `std` 这个命名空间。
- **当前名字空间**：代码写在哪个 `namespace {}` 块里，那就是它的"当前名字空间"；不在任何 `namespace` 里，就是全局名字空间。
- **全局名字空间**：最外层、没有被任何 `namespace` 包裹的空间，用 `::name` 显式引用其中的内容。
- **自定义名字空间**：程序员自己用 `namespace XXX { }` 定义的空间。
- **嵌套名字空间**：一个 `namespace` 里面还可以再定义 `namespace`，形成层级，如 `my::my1::efg`。
- **名字空间的别名**：给一个长的/深层的名字空间起个短名字，如 `namespace me = my;`，之后 `me::abc` 等价于 `my::abc`。
- **匿名名字空间**：`namespace { ... }`，没有名字，效果类似 C 语言里的 `static` 全局变量——只在当前文件内可见，不会和别的文件里同名的东西冲突。

### 3.2 全局作用域符 `::`

```cpp
#include <iostream>
using namespace std;

int abc = 100;
void myFunc() { cout << "Show string!" << endl; }

int main() {
    ::myFunc();  myFunc();          // 两种写法效果相同，::表示"去全局空间找"
    ::cout << ::abc << abc << endl; // 同理
    return 0;
}
```

`::` 前面不写名字空间名，就代表"全局名字空间"。这在你的局部变量和全局变量重名时特别有用——`::abc` 能明确指出"我要的是全局那个 abc"，而不是被局部同名变量"挡住"的那个。

### 3.3 嵌套名字空间与别名

```cpp
namespace my {
    int abc = 100;
    class T { /*...*/ };
    namespace my1 {
        int efg = 200;
        class T2 { /*...*/ };
    }
}
namespace my {                       // 同一个 namespace 可以分多处书写，会自动合并
    void myFunc() { cout << "Show string!" << endl; }
}

int main() {
    namespace me = my;                // 别名
    my::myFunc();
    cout << me::abc << endl;
    cout << me::my1::efg;             // 多层嵌套要一层层::下去
    return 0;
}
```

要点：**同一个命名空间可以在多个地方（甚至多个文件）反复打开、追加内容**，编译器会把它们合并成一个逻辑空间，这也是标准库能被拆分到很多头文件里实现的原因。

### 3.4 匿名名字空间 vs static 全局变量

| | `static int abc = 100;`（写在头文件） | `namespace { int abc = 100; }`（写在头文件） |
|---|---|---|
| 本质 | C 风格：让变量具有"内部链接"，每个 `#include` 它的 .cpp 文件都会得到**自己独立的一份** `abc` | C++ 风格：效果类似，每个翻译单元里的匿名命名空间互不相同，同样具有"文件私有"的效果 |
| 适用范围 | 只能修饰变量/函数 | 可以包含变量、函数、类等任意内容 |
| 推荐程度 | C++ 中不推荐（历史遗留） | C++ 中更推荐的现代写法 |

例子里 `m1.cpp` 里对 `abc` 的修改（`abc = 200`）不会影响 `m2.cpp` 里的 `abc`，因为它们其实是"同名但不同份"的两个变量——这正是匿名命名空间（或 static）"限制作用域到本文件"的效果。

### 3.5 using 名字汇入：两种写法的差异

```cpp
namespace first  { int x = 5; }
namespace second { double x = 3.1416; }

int main() {
    {
        using namespace first;   // 汇入 first 空间里所有的名字
        cout << x << endl;       // 5
    }
    {
        using namespace second;  // 汇入 second 空间里所有的名字
        cout << x << endl;       // 3.1416
    }
    using first::x;              // 只汇入 first 里的 x 这一个名字
    cout << x << endl;           // 5
    using second::x;             // 错误！x 已经被上一句引入过了，重复引入冲突
    cout << x << endl;
    return 0;
}
```

**两种 using 写法的对照**：

| 写法 | 效果 | 风险 |
|---|---|---|
| `using namespace X;` | 把 X 里**所有**名字都"暴露"到当前作用域 | 容易引入大量你不需要的名字，增加冲突概率，通常不建议在头文件里用 |
| `using X::name;` | 只把 X 里**指定的一个**名字引入当前作用域 | 更精确、更安全，但要针对每个用到的名字单独写 |

上面例子中 `using second::x;` 报错的原因：作用域里已经存在一个通过 `using first::x;` 引入的 `x`，此时再引入 `second::x` 会产生二义性（同一个作用域不能有两个不同含义的同名 `x`）。

## 四、友员和友员类

### 4.1 为什么需要友员

**问题场景**：类的 `private` 成员默认只能被类自己的成员函数访问，外部函数无权访问：

```cpp
class A {
public: /* ... */
private:
    void Func();
    int field;
};

void UseA(A& a) {
    a.field = 5;   // 编译错误！field 是私有的，外部函数不能访问
}
```

**为什么会有这个限制**：这是面向对象"封装"原则的体现——类的内部细节不应该被外界随意修改，只能通过公开接口操作。

**但有时候确实需要"开个后门"**：比如某个独立的辅助函数、或者关系特别紧密的另一个类，确实需要访问某个类的私有细节，又不想把这些成员设成 `public`（那样谁都能改，破坏封装）。这时就用**友元（friend）**机制——由类自己"钦点"谁可以访问它的私有部分，而不是被动地被任何人访问。

### 4.2 声明友元函数

```cpp
class A {
    friend void UseA(A& a);   // 在类内声明：UseA 是我的朋友
public: /* ... */
private:
    void Func();
    int field;
};

void UseA(A& a) {
    a.field = 5;   // 合法！因为 UseA 被声明为 A 的友元
}
```

**要点**：`friend` 声明写在类的内部（哪个访问区段都行，`public`/`private` 对 friend 声明本身没有影响），但被授权的函数本身**不是**这个类的成员函数，它是一个普通的外部函数，只是拿到了"访问私有成员的许可证"。

### 4.3 友元函数的两种来源 + 友元类

友元函数可以是：
1. **自由函数**（如上面的 `UseA`）；
2. **另一个类的成员函数**（比如 `class Parent` 的某个成员函数需要访问 `Wallet` 的私有数据）。

友元类：把**整个类的所有成员函数**都设为友元，比单独声明一个个函数方便。

```cpp
class Wallet;   // 前置声明
class Parent {
public:
    void addMoney(Wallet& w) { /* ... */ w.money += 8888; }
    void checkMoney(Wallet& w) { cout << w.history << endl; }
    void checkCourse(Course& c) { cout << c.score << endl; }
};

class Wallet {
    friend void Show(Wallet&);   // 单个自由函数是友元
    friend class Parent;         // Parent 的所有成员函数都是友元
private:
    int money; int history;
};

class Course {
    friend Parent::checkCourse(Course&);  // 只有 Parent 里的这一个成员函数是友元
private:
    int score;
};
```

**对照表**：

| 友元类型 | 声明位置/写法 | 授权范围 |
|---|---|---|
| 自由函数友元 | `friend void Show(Wallet&);` | 仅这一个自由函数 |
| 类的单个成员函数友元 | `friend Parent::checkCourse(Course&);` | 仅 `Parent` 类中的这一个成员函数 |
| 友元类 | `friend class Parent;` | `Parent` 类的**全部**成员函数 |

### 4.4 一个更完整的例子（含运算符友元、嵌套类友元）

```cpp
class A;
class B { public: void f(A& a); };
class C { public: void OtherFuncs(); };

class A {
    friend A operator+ (const A& lhs, const A& rhs);  // 友元自由函数（常用于重载运算符）
    friend void B::f(A& a);                            // B 类中单个成员函数
    friend class C;                                    // C 类整体
    class D;
    friend class D;                                    // 自己的嵌套类也可以是友元
    class D { /* ... */ };
private:
    int mValue;
};
```

这里可以看到，**运算符重载**（下一章会细讲）经常需要用友元函数，因为像 `operator+` 这种双目运算符往往写成自由函数更自然，但又需要访问两个操作数的私有成员。

### 4.5 友元的几条重要性质

| 性质 | 解释 |
|---|---|
| 友元的本质都是"友元函数"，没有"友元数据成员" | 你不能把一个数据变量声明成某个类的友元，friend 修饰的永远是函数（或整个类） |
| 友元函数不是类的成员 | 它没有隐含的 `this` 指针，也不受访问权限控制的约束——它就是个普通函数，只是有"通行证" |
| 友元关系是单向的 | A 把 B 设为友元，不代表 B 也把 A 设为友元；B 依然不能访问 A 的私有成员，除非 B 也显式声明 A 为友元 |
| 友元关系没有传递性 | A 是 B 的友元，B 是 C 的友元，不代表 A 是 C 的友元 |

**对封装的双重影响**（PPT 的辩证观点）：
- **局部来看**：友元让外部代码能直接碰私有成员，看起来"破坏"了封装；
- **全局来看**：因为访问权限是类自己"精确指定"给谁的（而不是索性把成员设成 public 让所有人都能访问），所以实际上保护了信息——只有被明确信任的少数函数/类能进来，其他人依然被挡在外面。

## 五、嵌套类

### 5.1 什么是嵌套类

**是什么**：在一个类的内部再定义一个类，外层类称为外围类（Outer），内部的类称为嵌套类（Inner）。

**为什么要用**：当某个辅助类只为外层类服务、不希望被外部随意使用时，把它定义在外层类内部，既能表达"这是 Outer 专属的工具类"这层逻辑关系，又能利用外层类的访问控制来隐藏它。

### 5.2 嵌套类的访问权限规则

```cpp
class Outer {
public:
    class InnerPub {          // 公有嵌套类：外部可以用 Outer::InnerPub 访问
    public:
        int F1();
    private:
        static T1* p1;
        T2* p2;
    };
    void F();
private:
    class InnerPri;            // 私有嵌套类：只能先声明，外部不可直接使用
    InnerPub* ppub;
    InnerPri* ppri;
    int val;
};

class Outer::InnerPri {        // 类外定义私有嵌套类的细节
public:
    void F2();
private:
    int n;
};
```

类外定义嵌套类的成员函数、静态成员时，要用完整的限定名：

```cpp
T1* Outer::InnerPub::p1 = nullptr;
int  Outer::InnerPub::F1() { /* ... */ }
void Outer::F() { InnerPri obj; /* ... */ }   // 在 Outer 自己内部可以直接用 InnerPri
void Outer::InnerPri::F2() { /* ... */ }
```

**实例化的可见性对照**：

| 代码 | 是否合法 | 原因 |
|---|---|---|
| `Outer::InnerPub c1;` | ✅ 合法 | `InnerPub` 在 Outer 的 `public` 区，外部可见 |
| `Outer::InnerPri c2;` | ❌ 错误 | `InnerPri` 在 Outer 的 `private` 区，外部不可见，只有 Outer 自己的成员函数能用它 |

### 5.3 嵌套类的访问域细节（另一个例子）

```cpp
class E {
    int x;
    class B { };
    class I {
        B b;              // OK：I 和 B 都是 E 的嵌套类，属于"自己人"
        int y;
        void f(E* p, int i) {
            p->x = i;      // OK：嵌套类的成员函数可以访问外围类的私有成员
        }
    };
    int g(I* p) {
        return p->y;       // 错误！I::y 是 I 的私有成员，即使 g 是外围类 E 的成员，也不能直接访问 I 的私有成员
    }
};
```

**这里最容易搞混的一点**：**外围类和嵌套类是两个不同的类**，"嵌套"只是书写位置上的包含关系，不代表访问权限上互相打通。规则是：

- 嵌套类的成员函数**可以**访问外围类的私有成员（因为标准规定嵌套类被视为外围类的成员，享有相应访问权）；
- 但外围类的成员函数**不能**随意访问嵌套类的私有成员，除非该成员是 `public` 的，或者外围类被显式声明为嵌套类的友元。

### 5.4 嵌套类的使用意义

- 把一个或多个相关的辅助类封装到一个类中，表达"归属关系"；
- 在使用多个嵌套类的同时，一定程度上"隐藏"了这些嵌套类，避免它们污染全局命名空间、被外部误用。

## 六、流

### 6.1 流的基本概念

**是什么**：C++ 用"流（stream）"这个抽象概念统一处理各种输入输出——不管数据是来自键盘、文件还是内存，都可以用同一套操作符（`<<` 和 `>>`）来读写，程序员不需要关心底层具体是怎么传输的。

### 6.2 字节流与字符流 / 文件流的两种方式

| | 二进制方式 | 文本方式 |
|---|---|---|
| 处理粒度 | 字节流（原始字节，不做任何转换） | 字符流（会对换行符等做平台相关的转换） |
| 典型用途 | 图片、可执行文件等非文本数据 | 普通文本文件 |

### 6.3 istream / ostream / cin / cout

- `istream`：输入流的基类，`cin` 就是它的一个实例，代表"标准输入"（通常是键盘）。
- `ostream`：输出流的基类，`cout` 就是它的一个实例，代表"标准输出"（通常是屏幕）。

### 6.4 `"\n"` 与 `endl` 的差异（对照）

```cpp
void func() {
    for (int i = 0; i < 10000; ++i) {
        cout << i << "\n";   // 写法一
        // cout << i << endl;  // 写法二
    }
}
```

| | `"\n"` | `endl` |
|---|---|---|
| 本质 | 一个普通的换行字符 | 一个**操纵符（manipulator）**：换行 + 强制刷新输出缓冲区（flush） |
| 性能 | 更快，因为不触发刷新 | 更慢，因为每次都要把缓冲区内容立刻"逼"出去 |
| 何时该用 | 大量、频繁输出（如循环里打印上万行）时优先用 `"\n"`，减少 I/O 次数 | 需要确保内容**立即**显示（如打印进度提示、程序崩溃前想保证信息已输出）时用 `endl` |

这也是 PPT 例子里特意"对比两种写法"的用意：在一个执行一万次的循环里，`endl` 会造成一万次缓冲区刷新，是明显的性能浪费，绝大多数情况下换成 `"\n"` 更合适。

## 本章小结

1. **类型转换**分为"内置↔内置""自定义←内置""自定义→其它类型"三种情形；后两种需要程序员手动定义**转换构造函数**（单参数构造函数）或**转换运算符 `operator DestType()`**，均可用 `explicit` 抑制其被隐式调用。
2. **名字空间（namespace）**用于解决多模块间的命名冲突，`::` 可显式指定"全局"或某个具体空间；`namespace` 可以嵌套、可以起别名（`namespace 别名 = 原名;`）、可以是匿名的（效果类似文件内 `static`）。
3. **using** 有两种汇入方式：`using namespace X;`（整体引入，方便但易冲突）和 `using X::name;`（精确引入单个名字，更安全）；同一作用域内不能重复引入产生二义性的同名实体。
4. **友元（friend）**是类主动授予外部函数/类访问自己私有成员的"通行证"：可以是自由函数、其它类的成员函数，也可以是整个类；友元关系**单向且不可传递**，友元函数本身不是类的成员。
5. **嵌套类**是定义在另一个类内部的类，用于表达归属关系并隐藏实现细节；其访问权限（public/private）决定了外部能否直接实例化；嵌套类的成员函数可访问外围类私有成员，但反过来不行（除非另有授权）。
6. **流**是 C++ 处理输入输出的统一抽象，`cin`/`cout` 分别是 `istream`/`ostream` 的实例；`"\n"` 与 `endl` 都能换行，但 `endl` 会额外触发缓冲区刷新，大量输出场景下用 `"\n"` 性能更好。
