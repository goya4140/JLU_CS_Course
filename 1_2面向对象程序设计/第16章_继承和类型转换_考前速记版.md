# 第十六章 继承和类型转换（考前速记版）

## 知识结构速览

```
继承下的类型转换
├─ 方向：派生类→基类＝向上转换 ｜ 基类→派生类＝向下转换
├─ protected/private 继承：向上/向下转换均【无意义】
├─ public 继承
│   ├─ 向上转换：有意义、安全 ★★★（指针/引用安全，对象型会裁剪）
│   └─ 向下转换：有意义、不一定安全 ★★★（须用 dynamic_cast）
└─ 4大转换操作符
    ├─ static_cast      —— 常规转换，不能转对象
    ├─ const_cast        —— 只加/去 const、volatile
    ├─ reinterpret_cast  —— 强行重解释，最危险
    └─ dynamic_cast      —— 运行时检查 ★★★（需虚函数/RTTI）
```

---

## 本章核心问题（整章基调）★★★

**当两个类存在继承关系时，一个类型的对象能不能被当成另一个类型来使用？什么时候安全，什么时候危险？**

拆成三个子问题，全章围绕这三点展开：

1. 能不能转 —— 取决于继承方式（只有 public 继承才有意义）
2. 向上转怎么转才不丢数据 —— 选对形式（指针/引用 vs 对象裁剪）
3. 向下转怎么保证不出事 —— 靠 dynamic_cast 运行时把关

---

## 一、继承方式 与 转换是否有意义 ★★★

| 继承方式 | 向上转换（子→父） | 向下转换（父→子） |
|---|---|---|
| `protected` / `private` 继承 | ❌ 无实际意义（public 接口互不相同） | ❌ 无实际意义（行为集不相关，数据不全） |
| `public` 继承 | ✅ 有意义（is-a 关系，泛化） | ✅ 有意义，但可能失败，需运行时判断 |

**判断依据**：只有 `public` 继承才是"is-a"关系，转换才有逻辑基础。

**若 protected/private 下确实要转**：
- 向上：可用强制类型转换 / 自定义自动转换函数
- 向下：可在 Derived 中定义转换构造函数 `Derived(const Base&);`

---

## 二、public 继承下的向上类型转换 ★★★

| 转换形式 | 写法 | 安全性 |
|---|---|---|
| 指针型 | `Car* p = &c;` | ✅ 安全，推荐 |
| 引用型 | `Car& r = c;` | ✅ 安全，推荐 |
| 对象型 | `(Car)c;` | ✅ 安全但产生新对象，发生**对象裁剪**（丢失子类数据） |

**★★★ 高频考点：对象裁剪（Object Slicing）**
- 子类对象按值转为父类对象时，只拷贝父类部分，子类新增数据全部丢失
- 该对象是全新对象，与原对象无关
- **结论：应尽量用指针或引用做向上转换，避免对象型**

**★★★ 高频考点：基类析构函数必须是 virtual**
- 用基类指针 `delete` 派生类对象时，若基类析构非 virtual → 派生类资源不会被正确释放（内存泄漏）

---

## 三、public 继承下的向下类型转换 ★★★

- 语义上有意义，但**编译期无法确定安全性**，只能靠运行时检查
- C 风格/static_cast 强转：编译通过，但若实际类型不匹配 → 运行时未定义行为（可能崩溃）
- **正确做法：使用 `dynamic_cast`**

---

## 四、四大类型转换操作符对比 ★★★

| 操作符 | 格式 | 作用 | 可转对象类型 | 关键限制 |
|---|---|---|---|---|
| `static_cast` | `static_cast<T>(exp)` | 常规转换，替代 `(T)exp` | 指针、引用、内置类型、枚举 | **不能是对象** |
| `const_cast` | `const_cast<T>(exp)` | 添加/去除 `const`、`volatile` | — | T 与 exp 类型除 const/volatile 外必须一致 |
| `reinterpret_cast` | `reinterpret_cast<T>(exp)` | 重新解释类型（如函数指针转换） | — | 最危险，无逻辑检查 |
| `dynamic_cast` | `dynamic_cast<T>(exp)` | 运行时安全的向下转换 | **只能是**类指针、类引用、`void*` | 类中**必须有虚函数**（依赖RTTI/VTable） |

### dynamic_cast 失败行为 ★★★

| T 的形式 | 转换失败时 |
|---|---|
| 指针型 | 返回 `nullptr` |
| 引用型 | 抛出异常，需 `try/catch` |

**原因**：C++ 没有"空引用"概念，所以引用转换失败无法像指针一样返回"空"，只能抛异常。

```cpp
// 指针型
B* pb = dynamic_cast<B*>(p);
if (pb) { pb->...; }

// 引用型
try {
    B& b = dynamic_cast<B&>(*p);
} catch (...) { }
```

---

## 五、const_cast 用法要点

- `const_cast<T>(exp)`：T 与 exp 除 const/volatile 外类型必须一致
- 典型场景1：`const` 对象需要调用非 const 方法时先去 const
- 典型场景2：`const` 成员函数内部用 `const_cast<A* const>(this)` 修改成员（少用，破坏 const 承诺）
- 函数重载可仅凭 `const` 修饰区分（`getVal() const` vs `getVal()`）

---

## 六、附：volatile

- 表示变量可能被外部（硬件/其他线程）修改，禁止编译器优化缓存，每次都从内存读取
- `const_cast` 同样可用于添加/去除 `volatile` 修饰
