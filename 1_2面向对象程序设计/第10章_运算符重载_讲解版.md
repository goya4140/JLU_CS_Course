## 10.1 运算符重载的意义与基本规则

### 是什么

运算符重载（Operator Overloading）就是让 `+`、`-`、`==`、`<<` 这些原本只认识 `int`、`double` 等内置类型的符号，也能"认识"我们自己写的类（比如 `TVector`、`A`）。本质上，运算符重载就是**给运算符符号包装了一个特殊命名的函数**，编译器在看到 `a+b` 这种写法时，会自动把它"翻译"成对应的函数调用。

### 为什么需要它

以 PPT 中的 `TVector` 为例，如果不做重载，两个向量相加只能这样写：

```cpp
TVector result1 = v1.addVector(v2);   // 成员函数形式
TVector result2 = addVector(v1, v2);  // 自由函数形式
```

这两种写法都能用，但都不如 `v1 + v2` 直观。运算符重载的核心价值就是：**让自定义类型的使用体验和内置类型（int、double）保持一致的语义和书写习惯**，代码可读性大大提升。

### 运算符的分类

| 类别 | 举例 |
|---|---|
| 一元运算符 | `+`（正号）、`-`（负号）、`++`、`--`、`[ ]`、`( )`、`->`、`!` |
| 二元运算符 | `+`、`-`、`*`、`/`、`=`、`+=`、`<<` 等 |
| 三元运算符 | `?:`（如 `a>b ? a : b`），**唯一不能重载的运算符类型** |

### 重载的两种形式

可以写成**自由函数**，也可以写成**成员函数**，两者效果类似，但适用场景和限制不同（第10.2节会展开对比）。

### 重载的 5 条限定条件

1. 只能重载一元或二元运算符（三元的 `?:` 不能重载）
2. 操作数中至少要有一个是自定义类型 —— 也就是说**不能改变内置类型原有的运算符语义**（比如你不能重新定义 `int + int` 的行为）
3. 无法改变运算符本身的结合律、优先级等固有属性（重载 `+` 之后它依然是左结合，优先级依然低于 `*`）
4. 不能发明新符号（比如 `⊕`、`∩` 这种是不允许的，只能用 C++ 已有的符号）
5. 有一批操作符/关键字永远不能重载：

```
::   .   .*   ?:   sizeof   new   delete   typeid
static_cast   dynamic_cast   const_cast   reinterpret_cast
```

> **类比理解**：可以把运算符重载想象成"方言翻译官"。`+` 这个符号本身的"语法角色"（比如它是二元的、左结合的、优先级固定）是宪法规定死的，翻译官（重载函数）只能决定"当遇到我们类的对象时该怎么处理"，不能修改宪法本身。

### 可重载运算符全集（速览）

```
operator new / operator delete / operator new[] / operator delete[]
^  &  |  ~  <<  >>          // 位运算
+  -  *  /  %                // 算术运算
<  >  ==  !=  <=  >=  &&  ||  !   // 逻辑运算
=  +=  -=  *=  /=  %=  ^=  &=  |=  >>=  <<=   // 赋值运算
++  --                        // 递增递减
->*  ->
,  ( )  [ ]  等
```

**一条重要原则**：如果内置类型在某个运算符上有某种"默认行为习惯"（比如 `a+b` 和 `b+a` 都合法、`a==b` 和 `b==a` 都合法、`(a=b)=c` 合法、`a=b=c` 合法、`a++` 返回的是自增前的原值），那么自定义类型重载后也**应该**保持同样的习惯，否则会让使用者困惑。

## 10.2 二元运算符重载

### 两种写法对比：自由函数 vs 成员函数

**自由函数形式：**

```cpp
TVector operator+(const TVector& v1,
                   const TVector& v2)
{
    return TVector(v1.x+v2.x, v1.y+v2.y);
}
```

**成员函数形式：**

```cpp
class TVector {
public:
    TVector operator+(const TVector& rhs) const
    { return TVector(x+rhs.x, y+rhs.y); }
};
```

| 对比点 | 自由函数形式 | 成员函数形式 |
|---|---|---|
| `a+b` 编译器翻译成 | `operator+(a, b)` | `a.operator+(b)` |
| 操作数地位 | 两个操作数地位对等，都通过参数传入 | 左操作数 `a` 是隐含的 `this`，右操作数 `b` 是参数 |

**怎么选？** 如果左操作数不一定是自定义类型（比如希望支持 `2 * v1` 这种"内置类型在左边"的写法），就必须用自由函数；如果左操作数总是本类对象，成员函数更简洁自然。

### 结合律与优先级不会因为重载而改变

以成员函数形式为例：

- **左结合**：`a+b+c` 会被编译器翻译成 `a.operator+(b).operator+(c)`
- **右结合**：`a=b=c` 会被编译器翻译成 `a.operator=(b.operator=(c))`

也就是说，重载只是"换了个函数去执行"，但执行的"顺序规则"（谁先谁后）完全遵循原来 `+`、`=` 的结合律，我们没法改变这一点。

### 完整例子

```cpp
class A {
    friend A operator+(const A&, const A&);   // 自由函数需要 friend 才能访问私有成员
public:
    A(int a, int b) : x(a), y(b) { }
private:
    int x; int y;
};

// 推荐：自由函数形式重载 operator+
A operator+(const A& lhs, const A& rhs)
{
    A result(0, 0);
    result.x = lhs.x + rhs.x;
    result.y = lhs.y + rhs.y;
    return result;
}
```

如果改成成员函数形式，就不再需要 `friend` 声明（因为成员函数本来就能访问私有成员）：

```cpp
class A {
public:
    A(int a, int b) : x(a), y(b) { }
    A operator+(const A& rhs) const {
        A result(0, 0);
        result.x = x + rhs.x;
        result.y = y + rhs.y;
        return result;
    }
private:
    int x; int y;
};
```

### 返回类型该怎么定？

**基本原则：参照内置类型在这个运算符上的语义习惯来决定返回值还是引用。**

| 表达式 | 内置类型语义 | 应该重载成 |
|---|---|---|
| `!a` | 返回一个新的 bool 值，不是引用 | `bool T::operator!()` |
| `a*b` | 返回一个新值 | `T operator*(const T&, const T&)` |
| `a=b` | 返回左值本身（可以继续 `(a=b)=c`） | `T& T::operator=(const T&)` |
| `a*=b` | 返回左值本身（可以继续链式操作） | `T& T::operator*=(const T&)` |

**关于 const**：
- 返回**引用**类型时，参照内置类型的语义来判断该不该加 const（比如 `a=b` 返回的引用不加 const，因为要支持 `(a=b)=c`）
- 返回**值**类型时，一般**不加** const（加了反而限制了返回值被继续操作，如移动语义等）

### 返回值优化（RVO）

写代码时，与其先构造一个临时对象再逐步赋值最后 return，不如直接在 return 语句里构造，让编译器有机会做"返回值优化"，省去一次拷贝：

**未优化写法：**

```cpp
A operator+(const A& lhs, const A& rhs)
{
    A result(0,0);
    result.x = lhs.x+rhs.x;
    result.y = lhs.y+rhs.y;
    return result;
}
```

**优化写法：**

```cpp
A operator+(const A& lhs, const A& rhs)
{
    return A(lhs.x+rhs.x, lhs.y+rhs.y);
}
```

**为什么更好**：编译器在很多情况下能把"构造临时对象 + 拷贝返回"直接优化成"在调用者的内存位置直接构造"，减少了一次额外的构造/析构开销。这是现代 C++ 中一个很常见的编码习惯。

## 10.3 成对重载（如 `+` 与 `+=`）

### 是什么、为什么

内置类型里 `+` 和 `+=` 是配套出现的：`a = a + b` 和 `a += b` 效果一样，但书写习惯不同。自定义类型重载时也应该**成对提供**，理由有三：

1. **适应用户的不同使用习惯**——有人喜欢写 `a = a+b`，有人喜欢写 `a += b`，两种都要支持
2. **可以用 `+=` 来实现 `+`，从而去掉 `friend` 声明**——因为 `+=` 本身通常写成成员函数，而 `+` 的自由函数版本可以直接调用 `+=`，不再需要访问私有成员，所以不用再声明友元
3. **便于维护、减少重复代码**——以后如果要修改数据成员的加法逻辑，只需要改 `operator+=` 这一处

### 代码演示

先看基础版本（`+` 和 `+=` 各自独立实现，`+` 需要 friend）：

```cpp
class A {
    friend A operator+(const A&, const A&);
public:
    A(int a, int b) : x(a), y(b) { }
    A& operator+=(const A& rhs) {
        x += rhs.x;
        y += rhs.y;
        return *this;
    }
private:
    int x; int y;
};

A operator+(const A& lhs, const A& rhs)
{
    return A(lhs.x+rhs.x, lhs.y+rhs.y);   // 重复了加法逻辑
}
```

改进版：用 `operator+=` 来实现 `operator+`，`friend` 声明可以去掉：

```cpp
class A {
    // friend 声明已删除，不再需要
public:
    A(int a, int b) : x(a), y(b) { }
    A& operator+=(const A& rhs) {
        x += rhs.x;
        y += rhs.y;
        return *this;
    }
private:
    int x; int y;
};

A operator+(const A& lhs, const A& rhs)
{
    return A(lhs) += rhs;   // 先拷贝一份lhs，再对这份拷贝做 +=，并返回
}
```

> **理解要点**：`A(lhs)` 是用拷贝构造函数造了一个 `lhs` 的副本，然后对这个副本调用 `+=`，最后把这个副本（此时已经是相加的结果）返回出去，原始的 `lhs` 不受影响。这样一来加法的核心逻辑只写了一遍（在 `+=` 里）。

### 好处进一步说明

假如以后类里要新增一个数据成员 `int z`，只需要改动 `operator+=` 内部的加法逻辑（PPT中标红/棕色部分），`operator+` 完全不用动，因为它只是简单地调用 `+=`。这就是"单一职责、减少重复"的体现。

## 10.4 一元运算符重载（以 `++` 为例）

### 是什么

`++` 有前置（`++a`）和后置（`a++`）两种用法，语义不同：

| 内置类型 int | 等价逻辑 |
|---|---|
| `int a=10; ++a;` | 先自增，`a` 变为 11，表达式的值就是自增后的值 |
| `int a=10; a++;` | 先记住原值 10，`a` 自增为 11，但表达式的值是**自增前**记住的 10 |

用伪代码更直观地对比：

**前置 `++a`：**

```cpp
int a = 10;
a += 1;
return a;      // 返回自增后的值
```

**后置 `a++`：**

```cpp
int a = 10;
int temp = a;
a += 1;
return temp;   // 返回自增前的值
```

### 自定义类型怎么区分前置和后置

C++ 用一个"哑元参数"（没有实际意义、只用来区分重载版本的 `int` 参数）来区分两者：

```cpp
++a;   // 编译器翻译成 a.operator++( )     —— 前置，无参数
a++;   // 编译器翻译成 a.operator++(0)    —— 后置，多一个int类型的占位参数
```

对应的声明：

```cpp
A& A::operator++( );      // 前置++，返回引用（因为要支持 ++(++a) 这种链式操作）
A  A::operator++(int);    // 后置++，返回值（因为返回的是"自增前"的一个临时副本）
```

### 完整例子（分数类）

```cpp
class A {
public:
    A(int a=0, int b=1) : num(a), den(b) { }

    A& operator++() {          // 前置++：分子直接加分母（相当于分数值+1）
        num += den;
        return *this;
    }
    A operator++(int) {        // 后置++：先存一份当前状态，再自增，返回旧状态
        A temp(*this);
        num += den;
        return temp;
    }
    void show() const { cout << num << "/" << den << endl; }
private:
    int num;  // 分子
    int den;  // 分母
};
```

调用效果（`a` 初始为 `1/3`）：

```cpp
A a(1,3);
A b(a);
b = ++a;   // 编译成 b = a.operator++( );  → a变成4/3，b也是4/3
b = a++;   // 编译成 b = a.operator++(0);  → a变成7/3，但b拿到的是自增前的值4/3
```

**记忆窍门**：后置版本"多一个不用的 int 参数"，这个参数本身没有任何数值意义，只是编译器用来在重载决议时区分"前置"和"后置"这两个同名函数的标记。

## 10.5 重载 `[ ]`、`( )`、`->`

### 10.5.1 `[ ]` 下标运算符

**是什么**：让自定义类型的对象可以像数组一样用 `obj[i]` 访问内部元素。

**为什么要同时提供 const 和非 const 两个版本**：

```cpp
class A {
public:
    int  operator[](int index) const { return nums[index]; }   // 用于 const 对象，只读
    int& operator[](int index)       { return nums[index]; }   // 用于非 const 对象，返回引用可以被赋值
private:
    int nums[100];
};
```

| 场景 | 调用的版本 | 效果 |
|---|---|---|
| `A a1; a1[i] = i;` | 非 const 版本（返回 `int&`） | 可以作为左值被赋值 |
| `const A& a2 = a1; a2[i];` | const 版本（返回 `int`） | 只能读取，不能赋值 |

这跟内置数组 `int arr[100]` 的行为是一致的：普通数组的元素可读可写，`const` 数组的元素只能读。

### 10.5.2 `( )` 函数调用运算符（仿函数 / Functor）

**是什么**：让对象可以像函数一样被"调用"，这种对象叫**仿函数**。

```cpp
class A {
public:
    int operator()() const { return 999; }
    int operator()(int a, int b) const { return a + b; }
};
```

调用效果：

```cpp
A a;
cout << a() << endl;         // 999，调用无参版本
cout << a(10, 30) << endl;   // 40，调用双参版本
```

`operator()` 可以像普通函数一样重载多个版本（参数不同即可），非常灵活。这种写法在**模板库/STL算法**（比如自定义排序规则传给 `sort`）中大量使用。C++11 之后，很多场景下可以用更简洁的 **lambda 表达式**来代替手写仿函数类。

### 10.5.3 `->` 成员访问运算符

**是什么**：让自定义类型的对象（通常是"智能指针"或"包装类"）可以像原生指针一样用 `->` 访问被包装对象的成员。

**C++ 的硬性规定**：重载 `operator->()` 时必须满足下面两条之一：
1. 返回一个**指针类型**；
2. 返回一个**自定义类型**，且该类型内部**也重载了** `operator->()`（这样才能一直"链式解引用"下去，直到最终拿到一个真正的指针）。

```cpp
class A { public: void f() { cout << "A::f()" << endl; } };

class B {
public:
    B(A* p) : pa(p) { }
    A* operator->() { return pa; }   // 返回指针，满足条件1
private:
    A* pa;
};

class C {
public:
    C(B& bb) : b(bb) { }
    B& operator->() { return b; }    // 返回自定义类型B，且B重载了->，满足条件2
private:
    B b;
};
```

调用效果：

```cpp
A a; B b(&a); C c(b);
b->f();   // 编译成 (b.operator->())->f();          输出 A::f()
c->f();   // 编译成 ((c.operator->()).operator->())->f();  也输出 A::f()
```

> **类比理解**：这就是智能指针（如 `unique_ptr`、`shared_ptr`）背后的核心原理——包装一个真正的指针，重载 `->` 之后，用起来"感觉"跟直接用原生指针一样，但实际上中间多做了一层管理（比如自动释放内存）。

**const 重载版本同样适用于 `->`**（第18页例子）：`operator->()` 也可以分 const/非 const 两个版本，规则和 `[ ]` 类似——const 对象调 const 版本，非 const 对象调非 const 版本。

## 10.6 定向输入输出运算符的重载（`<<` 和 `>>`）

### 是什么、为什么必须用自由函数

`cout << a` 这种写法里，左操作数是 `ostream` 类型的对象（`cout`），不是我们自己的类 `A`。而重载规则要求"左操作数类型决定了函数应该属于谁的成员"——但 `ostream` 是标准库类型，我们没法往里面加成员函数。所以 **`<<` 和 `>>` 的重载只能写成自由函数**（通常需要配合 `friend` 才能访问类的私有成员）。

```cpp
class A {
public:
    A(int n1, int n2) : a(n1), b(n2) { }
    int getA() const { return a; }
    void setA(int n) { a = n; }
    int getB() const { return b; }
    void setB(int n) { b = n; }
private:
    int a;
    int b;
};

// 重载 << ：把A对象的内容输出到流
ostream& operator<<(ostream& out, const A& a) {
    out << a.getA() << endl;
    out << a.getB() << endl;
    return out;    // 返回流本身，这样才能支持 cout << a1 << a2 的链式写法
}

// 重载 >> ：从流里读取数据填充A对象
istream& operator>>(istream& in, A& aA) {
    int a, b;
    in >> a >> b;
    aA.setA(a);
    aA.setB(b);
    return in;
}
```

**返回类型为什么是 `ostream&` / `istream&`**：为了支持连续使用，比如 `cout << a1 << a2` 会被翻译成 `(cout << a1) << a2`，前一个 `<<` 必须返回流对象的引用，后面的 `<< a2` 才能继续在同一个流上操作。这跟内置类型 `cout << 1 << 2` 是一样的道理。

## 10.7 运算符重载的方针与规范

### 各类运算符：成员函数 or 自由函数？

| 运算符 | 建议/要求 |
|---|---|
| 所有一元运算符（操作数为自定义类型） | 建议用**成员**函数 |
| `=`、`( )`、`[ ]`、`->`（左操作数/操作数为自定义类型） | **必须**是成员函数（C++语法硬性规定） |
| `+=`、`-=`、`*=`、`/=`、`^=`、`&=`、`\|=`、`%=`、`>>=`、`<<=`（左操作数是自定义类型，右操作数类型可以不同） | 建议用**成员**函数 |
| 所有其它二元运算符（左操作数不一定是自定义类型，如 `2*v1` 这种） | 建议用**非成员**（自由）函数 |

### 两条铁律

1. **永远不要重载 `&&`、`\|\|`、`,`（逗号运算符）**——因为这三个运算符在内置语义中具有特殊的"短路求值"或"顺序求值"行为，一旦重载成普通函数调用，这种特殊求值顺序会丢失，容易造成难以察觉的 bug。
2. **保持内置类型该操作符的使用习惯**——这是贯穿全章的核心原则：自定义类型的运算符重载，最终目的是让代码"读起来顺手、用起来符合直觉"，而不是标新立异。

## 本章小结

1. **运算符重载的本质**：把 `a+b` 这样的符号表达式，在编译期翻译成对函数（`operator+`）的调用，让自定义类型也能用内置类型的书写习惯。
2. **两种实现载体**：自由函数（两操作数地位对等，左操作数可以不是自定义类型）和成员函数（左操作数隐含为 `this`）。
3. **五条限定规则**：不能重载三元运算符、操作数须至少一个自定义类型、不能改变结合律优先级、不能造新符号、有一批符号（`::`、`.`、`?:`、`sizeof` 等）永远不能重载。
4. **返回类型看齐内置语义**：像 `=`、`+=` 这种"要支持链式操作"的运算符返回引用；像 `+`、`*` 这种"产生新值"的运算符返回值类型。
5. **成对重载（`+`/`+=`）**：用复合赋值运算符实现普通运算符（`return A(lhs) += rhs;`），可以去掉 `friend`、减少重复代码、便于日后维护。
6. **前置/后置 `++`/`--`**：靠一个没有实际意义的 `int` 哑元参数来区分，前置返回引用、后置返回值（保存的是自增/自减前的旧值）。
7. **`[ ]`、`->` 常配 const/非 const 双版本**：const 对象调用只读版本，非 const 对象调用可写（返回引用）版本。
8. **`( )` 仿函数**：让对象可以像函数一样被调用，常用于 STL 算法自定义策略，C++11 之后可用 lambda 表达式替代。
9. **`->` 的两条硬性规则**：要么返回指针，要么返回一个自身也重载了 `->` 的自定义类型，这是智能指针的实现基础。
10. **`<<`/`>>` 必须是自由函数**：因为左操作数是标准库的 `ostream`/`istream`，无法作为我们自定义类的成员函数存在，且要返回流的引用以支持链式输出/输入。
11. **总方针**：一元运算符、`=`/`()`/`[]`/`->`/复合赋值运算符建议或必须用成员函数；其余二元运算符建议用自由函数；`&&`、`||`、`,` 永远不要重载。
