## 二、逐节详解

### 1. 抽象数据类型 ADT (Abstract Data Type)

**是什么：** ADT 是一种"只描述行为，不描述实现"的思维模型。一个 ADT = 一个数学模型 + 一套可以对这个模型施加的操作。它包含四个要素：**类型名称、数据集、数据间的关系、操作集**。

**为什么要有 ADT：** 在写程序之前，我们需要先在头脑中把现实世界的事物"抽象"成一组数据和一组操作，而不用关心将来这些数据具体怎么存储（用数组？链表？）。这样设计出来的模型：

- 与具体表示无关（先不管内存怎么摆放）
- 与现实世界无关（不是"真的人"，只是一个数学上的模型）
- 具有任意性和无穷性（可以设计出无数种模型来描述同一个事物）

**怎么用（例子）：** 用"人"这个事物举例，可以抽象成两种完全不同的 ADT。

**抽象角度一 —— Person（生理属性）：**
```
数据：age
关系：age >= 0
操作：birth, grow, dead
```

**抽象角度二 —— Person（学习/生活属性）：**
```
数据：knowledge, fatigue
关系：knowledge > 0, fatigue >= 0
操作：study, sleep, play
```

同一个"人"，因为关注点不同，抽象出来的数据和操作完全不一样——这正是 ADT "任意性"的体现。PPT 中"整数"的例子也是同理：整数可以抽象为 `{数据：number；关系：0是整数；操作：success（后继）、previous（前驱）}`，这其实就是皮亚诺公理定义自然数的方式，完全不涉及"整数在内存里怎么存"。

**类比：** ADT 就像一份"产品需求说明书"——只规定这个东西"有什么数据、能做什么操作"，至于"用什么材料造"（具体的类实现），是后面（第 6-9 章 class）要解决的问题。

### 2. OOP 语言中的类型 与 C++ 中的类型体系

**是什么：** 面向对象语言把类型分为四层：

1. **基本类型**：语言内置的、不能再分解的类型（如 int）
2. **自定义类型**：程序员自己写的、是 ADT 在计算机语言中的具体表示（如 class）
3. **泛型 generic type**：以"类型"本身作为参数的类型，即"参数化的类型"（如 `vector<T>`，模板）
4. **元类型/元对象 meta type**：类型的类型（比如"class 本身是什么类型？"）——**C++ 目前不支持**，但 Python、Java 的反射机制部分具备这个能力。

**C++ 中的类型全景图：**

```
内置类型   —— 基本类型(char, wchar_t, int, float, void)
           —— 扩展类型(short/long/signed/unsigned/double 修饰基本类型)
           —— bool 型

自定义类型 —— typedef/using 定义的类型别名
           —— 枚举类型 enum / enum class
           —— class, struct, union 定义的类型

导出类型   —— 数组 array
           —— 指针 pointer
           —— 引用 reference（左值引用 / 右值引用）

模板类型（泛型）
```

#### 2.1 内置类型

**基本类型**：`char`、`wchar_t`(宽字符，用于存储 Unicode 等多字节字符)、`int`、`float`、`void`。

**类型修饰**：`short`、`long`、`signed`、`unsigned`、`double` 可以修饰基本类型，组合出更多类型，例如：`long int`、`unsigned long int`、`double float`(等价于 `long double` 的一种老写法，标准写法是 `long double`)。

**bool 型**：非零 = `true`，零 = `false`。

**C++1z 新增**：`long long`；以及编译期类型推导关键字 `auto`、`decltype`。

**auto 用法：**
```cpp
int a = 10;
auto b = a + 99;   // b 的类型由右边表达式的值推导
```

**decltype 用法：**
```cpp
int a = 10;
decltype(sqrt(a)) b = sqrt(a+99) + 1;   // b 的类型由 sqrt(a) 这个表达式的类型决定，而不实际求值
```

`decltype` 最大的用处是在**返回类型依赖于参数类型**的场合，例如模板函数：

```cpp
template<typename A, typename B>
auto multiply(A a, B b) -> decltype(A*B)
{
    return a*b;
}
```

这里用"后置返回类型"语法：先用 `auto` 占位，再用 `->decltype(...)` 在参数都可见之后指明真正的返回类型（因为 `A*B` 这种运算结果的类型必须等 `A`、`B` 都声明完才能推导）。

**"为什么需要 auto/decltype"的类比：** 就像点外卖时你说"随便，跟他一样的"（auto），或者"跟这道菜的价钱一样"（decltype）——你不需要自己算出具体数字，让编译器帮你推导。

#### 2.2 自定义类型 - typedef / using

**是什么：** 给一个已经存在的类型起一个新名字（别名），**本质上没有增加新类型**，只是"改名"。

**格式：**
- 定义类型：`typedef <已知类型> <新类型>`；C++11 起也可写 `using <新类型> = <已知类型>`
- 定义函数指针类型：`typedef ReturnType (*新类型)(参数列表);`

**例1：普通类型别名**
```cpp
typedef unsigned char UCHAR;
typedef unsigned long DWORD;
typedef unsigned int uint;

UCHAR ch = 'a';   // 等价于 unsigned char ch = 'a';
DWORD n = 99;      // 等价于 unsigned long n = 99;
```

**例2：函数指针类型别名**
```cpp
int f(int,int) { ... }
int g(int,int) { ... }

typedef int (*MyFuncType)(int,int);
using MyFuncType = int (*)(int,int);   // C++1z 写法，与上面等价

MyFuncType f1 = f;
MyFuncType f2 = g;
f1(1,2);
f2(3,4);
```

**为什么用 typedef/using 而不直接写原类型：** 一是简化书写（`unsigned long int` → `DWORD`），二是让代码"见名知意"（`MyFuncType` 比裸函数指针语法好读得多）。`using` 是 C++11 引入的现代写法，可读性优于老式 `typedef`，尤其在定义函数指针别名时更直观。

#### 2.3 自定义类型 - 枚举类型

**C++98 传统枚举：** `enum 枚举类型名 { 枚举值列表 };`

规则：
- 枚举值必须是整数
- 第一个枚举值缺省为 0
- 后一个枚举值若未指定，则为前一个值 + 1

```cpp
enum WeekDay { MON=1, TUE, WED, THU, FRI, SAT, SUN=0 };

WeekDay day1, day2;
day1 = SUN;
day2 = THU;
int num = day2 + 100;   // 枚举值可直接和 int 运算
```

**C++98 枚举的三个问题：**
1. 枚举量的内部实现本质就是 int
2. int 与枚举量可以随意隐式转换，不安全（容易把一个无意义的整数硬塞给枚举变量）
3. **同名枚举值冲突**：两个不同的枚举类型不能有同名成员，因为枚举值会被"提升"到外层作用域

```cpp
enum Dir   { LEFT, RIGHT };
enum State { RIGHT, FAILED };   // 编译错误！RIGHT 重复定义
```

**C++1z 强类型枚举 enum class：** `enum class 枚举类名 { 枚举值列表 };`

- 枚举值可以指定底层类型、指定数值
- **不再允许**与 int 随意转换/比较，必须显式 `(int)` 强转
- 使用时**必须**带上作用域前缀（枚举类名）

```cpp
enum class AAA : unsigned int { A = 'a', EF = 120 };

cout << (int)(AAA::A)  << endl;   // 必须显式转换
cout << (int)(AAA::EF) << endl;   // 必须带 AAA:: 前缀
```

**两种枚举对比：**

| 对比项 | 传统 enum | enum class（C++1z） |
|---|---|---|
| 语法 | `enum Dir { LEFT, RIGHT };` | `enum class Dir { LEFT, RIGHT };` |
| 缺点 | 名字可能冲突 | 需要显式转换 |
| 优点 | 不用与 int 相互转换 | 避免名字冲突 |
| 使用示例 | `int f(Dir dir){return dir+1;}` `f(0);` | `int f(Dir dir){return (int)dir+1;}` `f((Dir)0);` |

**解决同名冲突的另一种思路：把枚举放进 class 内部**

```cpp
class My {
public:
    enum Dir { LEFT, RIGHT };   // 传统 enum，但被 class 包裹
public:
    ...
};

int f(My::Dir dir) { return dir; }
f(My::RIGHT);   // 通过 My:: 访问，天然避免了与其它枚举同名冲突
```

一个完整的应用例子（求相对方向）：

```cpp
class Dir {
public:
    // Direction 前缀可省略，直接写枚举值
    enum Direction { NORTH, EAST, SOUTH, WEST };
    ...
};

// 取得 dir 的相对方向（北↔南，东↔西）
int oppositeDirection(int dir) { return (dir + 2) % 4; }

int main() {
    int enterDir = Dir::EAST;
    int leaveDir = oppositeDirection(enterDir);
    ...
}
```

#### 2.4 自定义类型 - class / struct / union

**是什么：** 三者都是把若干个成员打包成一个自定义类型的方式。**在 C++ 中，class 和 struct 除了默认访问控制不同之外，完全一致**（struct 默认 public，class 默认 private）。

**格式：**
```cpp
class <Name> {
    <members>
};   // 别忘了最后的分号！
```

**例：**
```cpp
class Dog
{
public:
    void Eat(int num);
private:
    int weight;
};   // 分号不能省
```

**注意点：** 花括号后面一定要加分号，这是 C++ 语法规定（因为 class 定义本质上也是一种可以被立即用来声明变量的类型表达式），初学者最容易漏掉。

#### 2.5 导出类型

导出类型是"从已有类型派生出来的复合类型"：

- **数组**：`int a[5]; MyClass objs[3];`
- **指针**：`int *p = 0; MyClass *pobjs[4]; int **pp = &p;`（指向指针的指针）
- **引用（左值引用）**：`int a = 100; int &b = a;`（b 是 a 的别名，二者共用同一块内存）
- **右值引用（C++1x/1z 新增）**：

```cpp
void f(T && aT) { aT.doSome(); }
f(T());   // T() 是一个临时对象（右值），可以被右值引用绑定
```

右值引用是为"移动语义 / 完美转发"服务的高级特性，这里先了解语法形态，后续章节（拷贝与赋值）会深入讲解其意义。

### 3. 声明和定义

**声明 declaration 是什么：** 解释说明一个编译单元中某个名字的**含义和属性**，但不一定给出完整实现。

```cpp
extern int a;           // 声明外部整型变量 a
extern const int c;     // 声明外部整型常量 c
int f(int);              // 声明函数 f
struct S;                 // 声明结构 S（前置声明）
typedef int Int;         // 声明类型 Int
extern X anotherX;       // 声明外部变量 anotherX
using N::d;               // 声明名字 d
```

**定义 define 是什么：** **一个声明同时也是一个定义**，当它具有以下之一时：确定的函数体、确定的类内容、具体的值、确定的存储空间、确定的别名等。换句话说，**"定义"是"声明"的子集**——所有定义都是声明，但不是所有声明都是定义。

```cpp
int a;                              // 定义 a（分配了存储空间）
extern const int c = 1;             // 定义 c（给出了具体值）
int f(int x) { return x+a; }        // 定义 f 和 x（有函数体）
struct S { int a; int b; };         // 定义 S、S::a、S::b（有确定的类内容）

struct X {
    int x;                          // 定义非静态数据成员 x
    static int y;                   // 声明静态数据成员 y（注意：这里只是声明！）
    X(): x(0) {}                    // 定义 X 的构造函数
};
int X::y = 1;                       // 这里才是定义 X::y

enum { up, down };                  // 定义 up 和 down
namespace N { int d; }              // 定义 N 和 N::d
namespace N1 = N;                   // 定义 N1（命名空间别名）
X anX;                              // 定义 anX
```

**关键点：类的 static 数据成员比较特殊** —— 在 class 内部写 `static int y;` 只是**声明**，真正的定义（分配存储空间）必须在类外单独写一行 `int X::y = 1;`。这是初学者常见的坑。

**三类常见的声明与定义对比：**

**① 类型的声明和定义**
```cpp
// 类型声明（前置声明）
class Meat;
typedef unsigned int uint;

// 类型定义
class Dog {
public:
    void drink();
    void eat(Meat* pMeat);
private:
    int mNum;
    int mVal;
};

// 变量的声明
extern int b;
```

**② 函数的声明和定义**
```cpp
// 函数(原型)声明
int MyFunc(int);
int YourFunc();

// 函数定义
int MyFunc(int n)
{
    return 2*n;
}
```

**③ 变量的声明和定义**
```cpp
// 变量的声明
extern int a;
int b = 100;      // 声明+定义
extern Dog aDog;

// 变量的定义
int a;             // 无初始化，不建议
float b = 2.5;
Dog aDog;
```

### 4. 声明和定义的使用

#### 4.1 就近原则（现用现定义）

**是什么：** 现代 C++（相对于传统 C 语言）提倡变量在**第一次使用它的地方附近**才定义，而不是像老式 C 那样把所有变量都堆在函数/代码块开头声明。

**C 语言老式写法：**
```c
void main() {
    int i, j, k;
    for (i=0; i<10; ++i) {
        for (j=1; j<20; ++j) {
            k = f(i,j);
            // use k
        }
    }
}
```

**现代 C++ 写法：**
```cpp
int main() {
    for (int i=0; i<10; ++i) {
        for (int j=1; j<20; ++j) {
            int k = f(i,j);
            // use k
        }
    }
}
```

**为什么这样更好：** 变量的作用域被压缩到最小，减少了"变量声明了但很久之后才用、中间又被误用"的风险，也让代码更易读——看到变量定义的地方，马上就能看到它是怎么用的。

#### 4.2 先声明，后使用

**是什么：** 一个名字必须先经过声明（哪怕不是定义），编译器才认识它，之后才能使用。

```cpp
// a.cpp
int count = 1;
int main() { }
```

```cpp
// b.cpp
extern int count;      // 先声明（说明 count 在别处已定义）
void f() {
    count = 10;          // 后使用
}
```

```cpp
// dog.h
class Bone;               // 前置声明（此时还不知道 Bone 具体长什么样）
class Dog {
public:
    void Eat(Bone* p);    // 参数是指针，编译器不需要知道 Bone 的完整定义，前置声明足够
};
```

这里 `class Bone;` 是一种常见技巧：当只需要用到某个类的**指针或引用**时，不需要该类的完整定义，写一个前置声明即可，可以减少头文件之间的依赖，加快编译。

#### 4.3 单一定义规则 ODR (One Definition Rule)

**是什么：** 在一个编译单元中，同一个标识符（变量、函数、类名等）**只能被定义一次**；但声明可以多次。

```cpp
// 例1：违反 ODR，编译错误
int count = 1;
int count = 1;     // Error：重复定义
int main() { ... }
```

```cpp
// 例2：看似重复 include，但因为头文件保护，实际只定义一次

// a.h
#ifndef AH
#define AH
int count = 1;
int f(int n) { return 1; }
#endif

// a.cpp
#include "a.h"
#include "a.h"     // 第二次 include 被 #ifndef 挡住，不会重复展开
void main() {
    count = 10;
    f(count);
}
```

**为什么需要 `#ifndef/#define/#endif`（包含警戒）：** `#include` 本质上就是把文件内容原样"复制粘贴"进来。如果一个头文件被同一个 `.cpp` 文件（直接或间接）`#include` 了两次，而头文件里又有变量/函数的**定义**，就会违反 ODR 导致编译报错。包含警戒（include guard）能保证同一个头文件的内容只会被真正展开一次。

#### 4.4 obj 文件与链接性——理解"为什么会报重复定义"

**是什么：** 每个 `.cpp` 文件编译后会生成一个 `.obj`（目标文件），其中包含"外部链接表"，记录本文件对外提供的符号名和地址；链接器（linker）会把多个 `.obj` 文件合并成一个可执行文件，过程中把不同 `.obj` 文件中"用到但未定义"的符号，和"已定义"的符号一一配对。

```cpp
// a.h
extern int a;
int f();

// a.cpp
#include "a.h"
int a = 20;                 // 真正的定义，出现在 a.obj 的"外部链接表"里
int f() { return a+100; }
```

```cpp
// b.h
extern int b;
int g(int n);

// b.cpp
#include "a.h"
#include "b.h"
int b = 100;
int g(int n) { return a+b+n; }   // 使用了 a.obj 提供的符号 a
```

链接器工作的直观理解：`a.obj` 的"外部链接表"里有 `_a` 和 `_f` 这两个符号的地址；`b.obj` 在编译 `g` 函数时，遇到 `a`，它自己没有定义，只留了一个"待填地址"的占位（`MOV AX,[_a]`），等链接阶段，链接器去 `a.obj` 里查到 `_a` 的真实地址，把这个占位填上。**这就是为什么"定义只能有一次，声明可以有多次"——声明只是告诉编译器"这个符号在别处存在"，真正占用内存地址的只能有一份，否则链接器不知道该用哪一份地址。**

#### 4.5 头文件中的声明和定义——常见错误与最佳实践

**问题引出：** 如果把变量/函数的**定义**直接写进头文件，会发生什么？

```cpp
// a.h（错误示范：把定义放进头文件）
int count = 1;
int f(int n) { return 1; }
```

```cpp
// a.cpp
#include "a.h"
int main() { count = 10; f(count); }
```

```cpp
// b.cpp
#include "a.h"
void g() { int n = f(count); }
```

因为 `a.cpp` 和 `b.cpp` 是两个不同的编译单元，各自 `#include "a.h"` 之后，各自的 `.obj` 里都会生成一份 `count` 和 `f` 的**定义**——链接整个工程时，链接器会发现 `count`、`f` 在两个 `.obj` 里都有定义，**报"重复定义"错误**。

**添加包含警戒能否解决？不能！** `#ifndef/#define/#endif` 只能防止同一个 `.cpp` 文件里重复 include 同一个头文件，**无法防止不同的 .cpp 文件分别 include 同一个头文件**——而恰恰是"不同 .cpp 文件都定义了同一个变量/函数"才是这里报错的真正原因。

**正确做法：头文件里只放声明，定义放进 .cpp**

```cpp
// a.h
#ifndef AH
#define AH
extern int count;     // 只声明
int f(int n);           // 只声明
#endif
```

```cpp
// a.cpp（把定义放这里，因为 a.h 表示的是 a.cpp 对外提供的功能）
#include "a.h"
void main() {
    count = 10;
    f(count);
}
int count = 1;           // 真正的定义
int f(int n) { return 1; }
```

```cpp
// b.cpp
#include "a.h"
void g() { int n = f(count); }   // 只是使用，没有重复定义
```

**结论（本节最重要的两条规则）：**
1. **头文件中可以放声明，以及类的定义**，但**不应该放变量定义和（非 inline）函数定义**
2. **函数定义及变量定义，在整个工程范围内只能定义一次**

> 补充说明：本例中，头文件 `a.h` 表示的是 `a.cpp` 文件对外提供的功能，所以从规范上讲，`count` 和 `f` 的定义放进 `a.cpp` 最合适（谁提供功能，定义就归谁）。

#### 4.6 变量的定义和初始化格式

- **C++98 格式**：`[<存储类>]<类型><变量名表>[=初始化表];`
- **C++11 新增格式**：`[<存储类>]<类型><变量名表>[{初始化表}];`

```cpp
// C++98
int state=1, age, weight=10, val=weight;
static long count;   // 函数外的 static 变量：static 表示"文件级变量"，
                      // 只在本文件（本编译单元）中有效
                      // （C++1z 建议改用匿名命名空间代替）
auto float r = 0.5;   // 注意：这里 auto 是"自动变量"的存储类修饰符，
                       // 含义与 C++1z 的类型推导 auto 完全不同（历史遗留语法）
```

```cpp
// C++1z
int state=1, age, weight=10, val=weight, val2{weight};   // 花括号初始化
float r = 0.5;
auto val3 = r;   // 这里的 auto 才是"自动推导类型"
```

**易混点：** `auto` 在 C++98 里是一个几乎没人用的"存储类"关键字（表示自动变量，和局部变量默认行为一样），C++11 把它废弃重用为"类型自动推导"关键字——两者写法一样，含义完全不同，学习时注意版本背景。

### 5. 存储空间与作用域

#### 5.1 存储空间 storage duration

**是什么：** 程序运行时，内存被划分成几个区域，不同的变量/代码会被分配到不同的区：

```
代码区       —— 存放函数体的机器指令
常量数据区   —— 存放字符串字面量、const 常量等
变量数据区   —— 存放全局变量、static 变量
栈区         —— 存放函数的局部变量、形参
堆区         —— 存放 new 出来的对象
```

**例子：**
```cpp
int n = 100;                  // 变量数据区（全局变量）

int f(int n) {                 // n（形参）在栈区
    static int m = 8;           // m 在变量数据区（static 使其"跨函数调用仍然存在"）
    return m + n;
}

int main() {
    int i = 10;                  // 栈区
    for (int j=i; j<10; ++j) {   // j 在栈区
    }
    std::cout << "吉林大学";      // "吉林大学" 这个字符串字面量在常量数据区
}
```

**关键理解：`static` 局部变量的"跨越"能力。** 普通局部变量（栈区）每次函数调用都会重新创建、函数返回就销毁；而 `static` 局部变量只在**第一次**执行到该语句时初始化一次，之后每次调用函数都**沿用上次的值**（因为它实际存放在变量数据区，而不是栈区）。

#### 5.2 作用域 scope

**是什么：** 一个名字（标识符）在源代码中**可见、可以被引用**的范围。C++ 中有五种作用域：

```
全局作用域       —— 整个程序范围内可见（跨文件，需要 extern 声明）
文件作用域       —— 仅在本 .cpp 文件内可见（用 static 修饰的全局变量）
块级作用域       —— 仅在 {} 包裹的代码块内可见（如函数体、for 循环体）
类级作用域       —— 类的成员，通过 对象.成员 或 类名::成员 访问
命名空间作用域   —— namespace 包裹范围内可见，需要用 :: 或 using 访问
```

**例子逐条对照：**

```cpp
extern int global;              // 全局作用域（声明，定义在别处）
int state = 1;                    // 全局作用域
static int filevar = 99;          // 文件作用域（语法合法，但不推荐，建议用匿名命名空间）

int f(int n) {
    static int sa = 9;             // sa 是块级作用域的名字，但存储在变量数据区（跨调用保留值）
    int m = sa;                     // C++98 下，这里 int 前若写 auto 等价于 auto int m = sa;（老语法）
    auto k = sa + 8;                // 只在 C++1z 下有效：k 的类型由 sa+8 自动推导
    return sa + n;
}

struct A {
    void fff() { }                  // 类级作用域：fff 是 A 的成员函数
    int val;                         // 类级作用域：val 是 A 的成员变量
};

int main() {
    int k = 10;                       // 块级作用域
    A aA;
    aA.val = 2;                        // 通过 对象.成员 访问类级作用域的名字
    aA.fff();
    std::cout << "输出";
    return 0;
}
```

**存储空间与作用域综合例子（PPT 完整例）：**

```cpp
#include <iostream>
using namespace std;

int num = 999;          // 全局数据区 —— 全局作用域
static int num2 = 8;    // 全局数据区 —— 文件级作用域（只在本 .cpp 有效）

void func(int a, int b, int c)   // a,b,c 压入栈区
{
    static int n = 0;              // 全局数据区 —— 块级作用域（跨调用保留值）
    int result = (a+b+c)*(++n);    // result 在栈区 —— 块级作用域
    cout << "Result=" << result << endl;  // 字符串常量在全局数据区（常量区）
}

int main() {
    int a = 10;             // 栈区
    static int b = 20;       // 全局数据区

    func(a,b,20);   // 第一次调用：n 从 0 变为 1
    func(a,b,20);   // 第二次调用：n 从 1 变为 2（n 被保留了！）

    int *p = new int(55);   // p 本身在栈区，p 指向的内存在堆区
    // ...
    delete p;                 // 手动释放堆区内存，避免内存泄漏
}
```

**这个例子最值得琢磨的点：** 两次调用 `func(a,b,20)`，传入的实参完全相同，但两次输出的 `result` 不同——原因就是 `static int n` 不会随函数调用结束而消失，它"记住"了上一次的值。这是 `static` 局部变量最典型的用途：需要在多次函数调用之间"记忆状态"（如计数器）。

#### 5.3 链接性 linkage（与作用域、存储空间的关系）

**是什么：** 链接性描述的是"一个名字能否被其它编译单元（.cpp 文件）看到"。

- **外部链接（external linkage）**：默认情况下，全局变量、非 static 全局函数都具有外部链接性，可以被其它 `.cpp` 文件通过 `extern` 引用。
- **内部链接（internal linkage）**：用 `static` 修饰的全局变量/函数，只在**本编译单元**内可见，其它 `.cpp` 文件即使写 `extern` 也无法引用。
- **无链接（no linkage）**：局部变量（栈区变量）、块级作用域内的名字，根本不参与链接过程。

结合前面 obj 文件的例子理解：`a.obj` 的"外部链接表"里之所以会出现 `_a`、`_f` 这样的符号，正是因为它们具有**外部链接性**；如果 `a.cpp` 里把 `int a=20;` 改成 `static int a=20;`，那么这个符号就不会出现在外部链接表里，`b.cpp` 就无法再引用它——这也是"文件级作用域"名字被限制在本文件内的**底层原理**。

### 6. 表达式和语句

#### 6.1 各类表达式速览

- **一般表达式和返回值**：任何有值的代码片段都是表达式，如 `a+b`、`f(5)`
- **for 循环中的表达式**：`for(初值表达式；条件表达式；步进表达式)`
- **逗号表达式**：用逗号连接多个表达式，整体的值是最后一个表达式的值，例：`x=100, y=x-1000;`
- **条件表达式（用作 if 判断，不是三目运算符）**：例：`if (表达式1 && 表达式2) {...}`
- **赋值表达式**：赋值本身也是一个有返回值的表达式，可以连续赋值，例：`x = y = 100 + f(5);`（先算 `100+f(5)`，赋给 `y`，再把 `y` 的值赋给 `x`）

#### 6.2 左值表达式 vs 右值表达式

**是什么：**
- **左值（lvalue）**：能够作为 `=` 号左侧的表达式（有确定的内存地址），也可以出现在右侧。例如变量名 `a`、`*p`、`a[0]`。
- **右值（rvalue）**：只能作为 `=` 号右侧的表达式（没有持久的内存地址，通常是临时值）。例如字面量 `100`、`a+b`、函数返回的临时对象。

**类比：** 左值像"有门牌号的房子"——你可以往里面搬东西（赋值），也可以从里面搬东西出来（取值）；右值像"路边随手写的一张便条"——只能读它一次性的内容，没法把东西"存"进去。

#### 6.3 Lambda 表达式（C++1z）

**为什么需要 lambda——从一个问题引入：**

```cpp
int gVar = 10;
void func(int arg1);

void fff(int arg2) {
    int localVar = 99;
    func(localVar + 2);
}

void func(int arg1) {
    int temp = 5;
    arg1;       // 形参，可以访问 ✔
    temp;       // 局部量，可以访问 ✔
    gVar;       // 全局量，可以访问 ✔
    localVar;   // fff 函数的局部变量，禁止访问 ✘（不同函数的栈帧互相隔离）
}
```

问题是：如果我们**确实希望** `func` 能访问 `fff` 里的 `localVar`，又不想为了这一个需求大改函数签名（把 `localVar` 当参数传进去，层层传递），怎么办？

**解决方案——闭包 (Closure)：** 把函数连同它需要用到的"最小上下文环境"一起打包，这就是 Lambda 表达式的本质：一个**匿名函数** + 一份**明确指定要捕获哪些外部变量**的说明。

**语法格式（4 种，由繁到简）：**

```
[capture] (params) mutable exception attribute -> retType { body }   // 完整形式
[capture] (params) -> retType { body }                                // 省略 mutable/exception/attribute
[capture] (params) { body }                                            // 省略返回类型，由 body 自动推导
[capture] { body }                                                     // 省略参数列表，相当于无参函数
```

- `mutable`：允许在 body 内修改被"传值捕获"的变量副本，并可调用被捕获对象的 non-const 方法
- `exception`：声明是否抛出异常（如 `noexcept`）
- `retType`：返回类型，可省略（自动推导）
- `capture`：**核心**，规定 body 内可以访问哪些外部变量、以什么方式访问

**capture 捕获方式对照表：**

| 写法 | 含义 |
|---|---|
| `[a,&b]` | 以传值方式捕获 a（body 内是 a 的副本），以引用方式捕获 b（body 内直接操作原始的 b） |
| `[this]` | 以传值方式捕获 this 指针（用于访问所在类的成员） |
| `[&]` | 以引用方式捕获所有用到的外部自动变量，body 内可以修改外部量 |
| `[=]` | 以传值方式捕获所有用到的外部自动变量，body 内不可修改外部量（除非加 mutable） |
| `[]` | 不捕获任何外部变量 |

**完整例子（逐条对照，体会"传值捕获"与"引用捕获"的本质区别）：**

```cpp
int a = 10, b = 20, c = 40;

// [] 不捕获任何外部变量：n 是参数，与 a/b/c 无关
auto func1 = [](int &n) { return n + 5; };
show(a,b,func1(c));   // 输出 a=10 b=20 c=45

// [=] 传值捕获所有外部量：可以读 a、b，但不能修改它们
auto func3 = [=](int &n) { return n += a+b; };
// auto func3 = [=](int &n) { a=b; return n+=a+b; };  // Error：不能修改传值捕获的 a
show(a,b,func3(c));

// [a] 只传值捕获 a，不能访问 b
auto func4 = [a](int &n) { return n += a; };
// auto func4 = [a](int &n) { return n+=a+b; };    // Error：b 未被捕获，不能访问
// auto func4 = [a](int &n) { a=99; return n+=a; }; // Error：不能修改传值捕获的 a

// [&b,a] 引用捕获 b（可修改），传值捕获 a（只读）
auto func5 = [&b,a](int &n) { ++b; return n += a+b; };
show(a,b,func5(c));   // 注意：这里 b 被真正修改了！后续 b 的值也会变化
```

**理解要点：** `[=]` 和 `[a]` 这种"传值捕获"，捕获的是**变量被 lambda 创建那一瞬间的值的拷贝**，之后无论外部变量怎么变，lambda 内部这份拷贝都不受影响（而且默认不可修改，除非加 `mutable`）；`[&]` 和 `[&b]` 这种"引用捕获"，则是**直接操作外部变量本身**，lambda 内的修改会真实影响到外部变量。

## 三、本章小结

1. **ADT** 是"数据+关系+操作"的抽象数学模型，与具体实现无关，是理解后续 class 设计的思想基础。
2. C++ 的类型体系分为三大类：**内置类型**（基本类型/扩展类型/bool）、**自定义类型**（typedef/using、enum、class/struct/union）、**导出类型**（数组/指针/引用）。
3. `enum class`（强类型枚举）相比传统 `enum`：不允许隐式转 int、必须带作用域前缀，从而避免了同名冲突和误用问题。
4. **声明**只说明名字的属性，**定义**是声明的子集，必须具有确定内容（函数体/值/存储空间等）；`class` 内的 `static` 数据成员是"声明在类内、定义在类外"的典型例子。
5. 就近原则（现用现定义）、先声明后使用、**单一定义规则 ODR**（同一标识符在一个编译单元中只能定义一次），是 C++ 代码组织的三条基本纪律。
6. 头文件中**只应该放声明和类定义**，绝不应该放变量定义和普通函数定义；否则多个 `.cpp` 文件包含同一头文件时，链接阶段会报"重复定义"错误——`#ifndef` 包含警戒只能防止同一文件内重复展开，无法解决跨文件重复定义的问题。
7. 内存分为代码区、常量数据区、变量数据区（全局区）、栈区、堆区五个区域；`static` 局部变量存放在变量数据区，具有"跨函数调用保留值"的特性。
8. 作用域（全局/文件/块级/类级/命名空间）决定"名字在哪里可见"；链接性（外部链接/内部链接）决定"名字能否被其它 .cpp 文件引用"，`static` 修饰全局变量/函数会把外部链接改为内部链接。
9. 左值表达式有确定的内存地址（可出现在 `=` 两侧），右值表达式通常是临时值（只能出现在 `=` 右侧）。
10. Lambda 表达式本质是"匿名函数 + 闭包"，`capture` 部分决定了函数体能访问哪些外部变量、以传值（只读副本）还是引用（可修改原值）的方式访问。
