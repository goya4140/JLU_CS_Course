## 一、存储空间、静态存储及其不足

### 1.1 对象存储的四个区域

C++ 程序运行时，对象并不是随便"放"在内存里的，而是按照生命周期和用途被分配到不同区域：

| 区域 | 存放内容 | 生存期 |
|---|---|---|
| 全局数据区/常量数据区 | 全局变量、全局常量、static 变量 | 程序运行期间一直存在 |
| 栈区 | 局部自动变量（函数内的普通变量、形参） | 函数调用开始到结束 |
| **全局堆区（本章重点）** | new 出来的对象 | 程序员用 delete 显式释放 |

前两者归"**静态内存管理**"，第三者归"**动态内存管理**"——这正是本章要讲的内容。

### 1.2 静态存储示例怎么读

PPT 第 3 页给了一个经典例子：`A::func` 是一个递归函数，每次调用都会在栈上产生一份新的"局部变量快照"（`this`、参数 `n`、局部变量 `num`），但 `static int count` 只有**一份**，在所有调用之间共享和累加。

可以把它类比成：普通局部变量像"一次性纸杯"，每次用完就扔；而 `static` 变量像"公用饮水机"，无论你用了多少次纸杯，饮水机本身只有一台，且水量（值）会持续累积。

### 1.3 静态存储的不足

静态存储（局部变量、成员对象、静态成员）虽然"不用操心释放"，但代价是**丧失了灵活性**：

- **栈区容量有限**：栈一般只有几 MB，塞进大数组或深递归容易栈溢出。
- **生存期/作用域死板**：`MyClass obj(val1, val2);` 一旦定义，构造参数就固定死了，作用域一出就自动析构，程序员无法按自己的时间点决定"什么时候创建、什么时候销毁"。
- **对象数组的三重限制**：`MyClass objs[50];`
  1. 数组大小 `50` 必须是**编译期常量**，不能运行时决定；
  2. 数组里每个元素必须是**同一种类型、同一大小**；
  3. 因为数组要一次性批量构造，通常要求类有**无参构造函数**。
- **编译期依赖增大**：想用一个类的对象作为成员，就必须 `#include` 它的完整定义（不能只用前向声明 `class A;`），加深了类之间的耦合。

### 1.4 具体反例（对比表格）

PPT 第 5 页给出一个反例：`A` 类只提供了带参数构造函数 `A(int n)`，没有无参构造函数。

| 写法 | 结果 | 原因 |
|---|---|---|
| `static A obj;`（在类外用 `A SomeClass::obj(100);` 初始化） | ✅ 可以 | 静态成员在类外单独初始化，可以显式传参 |
| `A aA;` 作为普通成员，在构造函数初始化列表中写 `aA(n1+n2)` | ✅ 可以 | 初始化列表允许显式调用带参构造函数 |
| `A objs[50];` | ❌ 编译失败 | 数组要批量构造 50 个 `A`，编译器只能调用无参构造函数，但 `A` 没有 |

**结论**：静态存储的最大优点是"不用担心释放"，但换来的是"创建方式不自由"。这正是引出动态内存管理的动机。

## 二、单对象(变量)的动态分配及释放

### 2.1 为什么需要 new / delete

动态内存管理的核心诉求是：**由程序员自己决定"什么时候创建对象、创建多少个、什么时候释放"**，不再受限于编译期常量、栈容量、类型一致性等静态存储的约束。

格式非常简单：

```cpp
A * p1 = new A(100);      // 创建
A * p2 = new A(*p1);      // 用拷贝构造创建
A * p3 = new A[50];       // 创建数组（后面章节详讲）
delete p2;                 // 释放
delete p1;
delete[] p3;                // 数组要用 delete[]
```

`new T(参数列表)` 中的 `T` 几乎什么都能填：内置类型、自定义类、指针类型：

```cpp
int * p1 = new int(5);
const int * const p2 = new int(*p1);
A * p3 = new A;                     // 无参构造
const A * p4 = new A(100, 200);     // 多参构造
const A ** p5 = new A*(p4);         // 分配一个"指向A的指针"的空间
```

### 2.2 new 的底层执行过程

`T * pobj = new T(3, 2);` 这一行代码，编译器实际上拆成了三步：

1. 调用 `static void * operator new(std::size_t size)` **申请一块原始内存**（只管要空间，不管构造对象），失败则跳转到异常处理函数 `new_error_handle()`；
2. 在这块内存上**执行构造函数** `T::T(ptr, 3, 2)`；
3. 把 `void *` 强转成 `T *` **返回**。

等价伪代码：

```cpp
void * ptr = T::operator new(sizeof(T));   // 若T是自定义类型
// 或 ::operator new(sizeof(T));           // 若T是内置类型/指针
T::T(ptr, 3, 2);                            // 在ptr位置上构造
return (T*)ptr;
```

**理解要点**：`new` 不是一个原子操作，而是"**先分配空间，再构造对象**"两步的组合。这个理解为后面"重载 operator new"和"placement new"打下基础。

### 2.3 内存分配失败怎么办：new_error_handle

如果 `operator new` 申请空间失败（内存不够了），系统会调用一个"错误处理函数"，程序员可以用 `set_new_handler` 自定义这个函数该做什么（比如打印日志、回收无用内存，或者抛异常）。

```cpp
void myFunc() {
    cout << "operator new error." << endl;
    // 回收无用内存、保存数据……
    // 也可以 throw "allocate memory failed";
}

int main() {
    using NewHandler = void (*)();
    NewHandler oldHandler = set_new_handler(myFunc);  // 注册处理函数
    while (1) {
        new MyClass[9000000];   // 疯狂申请内存，触发失败
    }
    set_new_handler(oldHandler);  // 恢复原来的处理函数
}
```

可以把它类比成："银行取钱时余额不足，会触发一次'余额不足'的警报处理程序"——`set_new_handler` 就是在注册这个警报处理程序。这部分内容"理解过程即可"，考试不会深究写法细节。

### 2.4 delete 的底层执行过程

释放的过程是 new 的镜像操作：

```cpp
// delete pobj; 等价于：
if (pobj == nullptr) return;              // 1. 空指针直接退出
T::~T(pobj);                                // 2. 先析构对象
T::operator delete(pobj);                   // 3. 再释放内存（自定义类型）
// 或 ::operator delete(pobj);              //    （内置类型/指针）
```

**记忆口诀**：new 是"先要空间、后造对象"；delete 是"先拆对象、后还空间"——顺序正好相反，这是合理的，因为析构函数可能还要用到对象内部的数据（不能先释放内存再析构）。

## 三、重载 operator new 和 operator delete

### 3.1 为什么要重载

默认的 `operator new`/`operator delete` 只是简单调用系统的内存分配器。但有时我们想在分配内存的同时**附加一些自己的逻辑**，比如：统计对象创建了多少次、用自定义的内存池分配、记录调试信息等。这时就需要重载它们。

### 3.2 重载规则

```cpp
class A {
public:
    A(int n) { }
    void * operator new(std::size_t);                         // 1
    void * operator new(std::size_t, const string& a);         // 2（可以重载多个版本）
    void operator delete(void *);                              // 3
};
```

**关键规则**：

- 无论你有没有写 `static` 关键字，`operator new`/`operator delete` **一定是静态成员函数**（因为调用它们时对象本身还没构造出来，或者已经析构了，不可能有 `this` 指针）。
- 如果类没有显式提供重载版本，则自动使用**全局的** `::operator new` 和 `::operator delete`。
- 可以重载多个 `operator new`，只要参数列表不同（类似函数重载），调用时通过参数匹配决定用哪个：

```cpp
int main() {
    A * p1 = new A(9);              // 调用普通版本（调用1）
    A * p2 = new("张三") A(8);       // 调用带string参数的版本（调用2）
    delete p2;                       // 调用3
    delete p1;                       // 调用3
}
```

### 3.3 实战例子：统计对象创建/释放次数

需求：记录程序运行中，某类型对象在堆区**累计创建了多少次**、**累计释放了多少次**（用于排查内存泄漏），同时记录每次创建时**堆区已存在多少个**该类对象（用于调试）。

```cpp
class A {
public:
    A(int n) { existCount = newCount - deleteCount - 1; }
    A(const A& rhs) { existCount = newCount - deleteCount - 1; }

    static void * operator new(size_t);
    static void   operator delete(void *);

    static int newCount;      // 累计创建次数
    static int deleteCount;   // 累计释放次数
    int existCount;           // 创建本对象时，堆区已存在的对象数
};

void * A::operator new(size_t size) {
    char * p = new char[size + sizeof(int)];   // 多申请4字节存一个int
    *(int*)(p + size) = newCount - deleteCount; // 尾部记录"已存在数量"
    ++newCount;
    return p;
}

void A::operator delete(void * p) {
    ++deleteCount;
    delete[] (char *)p;
}
```

**验证结果**（对照 PPT 第 13 页）：

```cpp
int A::newCount = 0;
int A::deleteCount = 0;

int main() {
    A * p1 = new A(1);
    A * p2 = new A(2);
    A * p3 = new A(*p2);
    delete p1;

    cout << A::newCount << endl;          // 3，累计创建3次
    cout << A::deleteCount << endl;       // 1，累计释放1次
    cout << p2->existCount << endl;       // 1，创建p2时已存在1个（即p1）
    cout << p3->existCount << endl;       // 2，创建p3时已存在2个（p1、p2）

    delete p3;
    delete p2;
    cout << A::newCount << endl;          // 3
    cout << A::deleteCount << endl;       // 3
}
```

**理解要点**：这个例子的巧妙之处在于，`operator new` 里"顺手"多申请了 `sizeof(int)` 字节的空间，把统计信息藏在对象内存的尾部——这是理解"内存布局可以人为控制"的一个很好的示范。

## 四、数组的动态分配及释放

### 4.1 语法与执行过程

```cpp
T * p = new T[size];    // 动态分配
delete[] p;              // 动态释放
```

`new T[size]` 的过程：

1. 调用 `void * T::operator new[](size_t)` 尝试分配空间，失败转 `new_error_handle()`；
2. 对这块空间**执行 size 次无参构造函数**；
3. 转换指针类型并返回。

`delete[] pointer` 的过程：

1. `pointer` 为空则退出；
2. **执行多次**析构函数 `T::~T()`；
3. 调用 `void operator delete[](void *)` 释放空间。

### 4.2 静态数组 vs 动态数组

| 对比项 | `const int N=50; T objs[N];`（静态数组） | `int n=50; T* p=new T[n]; delete[] p;`（动态数组） |
|---|---|---|
| 大小 | N 必须是**编译期常量** | n 可以是**运行时才确定**的变量 |
| 存放位置 | 栈区（或全局区） | 堆区 |
| 释放方式 | 自动（作用域结束） | 手动 `delete[]` |
| 是否要求无参构造函数 | 是（批量构造） | 是（`new T[n]` 同样要无参构造） |

**易错点**：`delete[]` 和 `delete` 不能混用！用 `new T[n]` 分配的必须用 `delete[]` 释放，否则只会析构第一个元素、其余内存泄漏，是典型的未定义行为。

### 4.3 对象数组的三种实现方式对比

当一个类内部需要"一批"对象作为成员时，根据是否要求无参构造函数、数组大小是否要运行时确定，有三种写法，难度递增：

| 方式 | 代码要点 | 是否要求无参构造函数 | 数组大小是否可运行时决定 |
|---|---|---|---|
| **例1：值数组** | `Card cards[54];` | ✅ 必须要求 | ❌ 编译期固定 |
| **例2：指针数组** | `Card * cards[54];`，构造函数里 `for` 循环 `new`，析构函数里 `for` 循环 `delete` | ❌ 不要求（可以传参构造） | ❌ 数组本身大小固定（54个指针） |
| **例3：动态指针数组** | `Card ** cards;`，构造函数里先 `new Card*[54*num]`，再逐个 `new Card(...)` | ❌ 不要求 | ✅ 完全运行时决定 |

**例2 完整代码**（体会"用指针数组绕开无参构造函数要求"的技巧）：

```cpp
class Poker {
public:
    Poker() { for (int i = 0; i < 54; ++i) cards[i] = new Card(i); }
    ~Poker() { for (int i = 0; i < 54; ++i) delete cards[i]; }
private:
    Card * cards[54];   // 指针数组，每个元素单独new，可以传参
};
```

**例3 完整代码**（在例2基础上，连数组大小也变成运行时可变）：

```cpp
class Poker {
public:
    Poker(int n) : num(n) {
        cards = new Card*[54 * num];
        for (int i = 0; i < 54 * num; ++i)
            cards[i] = new Card(i % 54);
    }
    ~Poker() {
        for (int i = 0; i < 54 * num; ++i) delete cards[i];
        delete[] cards;
    }
private:
    Card ** cards;   // 指针的指针：指向"一堆Card指针"组成的动态数组
    int num;
};
```

**记忆技巧**：值数组 → 指针数组 → 动态指针数组，本质上是"**放开一个限制就多套一层指针**"：
- 放开"必须无参构造" → 数组元素变成指针（`Card * cards[54]`）
- 再放开"大小必须固定" → 连指针数组本身也变成动态分配（`Card ** cards`）

## 五、智能指针和共享指针

### 5.1 auto_ptr 的核心思想（了解即可，C++17 已废弃）

普通指针用 `new`/`delete` 管理，最大的问题是：**万一忘记 delete、或者中途 return/异常导致跳过了 delete，就会内存泄漏**。

`auto_ptr` 的思路是：**把指针包装进一个对象里，利用对象"作用域结束自动析构"的特性，让析构函数自动帮你调 delete**。这正是"栈的自动释放优点"和"堆的灵活性优点"的结合。

```cpp
class auto_ptr {
public:
    auto_ptr(T * p) : pt(p) { }
    ~auto_ptr() { delete pt; }              // 关键：析构时自动释放
    T * operator->() { return pt; }
    T& operator*() { return *pt; }
private:
    T * pt;
};

int main() {
    auto_ptr pT(new T);
    pT->f();       // 像指针一样用
    (*pT).f();     // 同上
    // 函数结束，pT自动析构，自动delete，无需手写delete
}
```

**类比**：普通指针像是"你自己拿着一把要还的伞"，忘了还就丢了；`auto_ptr` 像是"一把绑在你手腕上的自动收伞装置"，你下车（作用域结束）它自动收好。

### 5.2 shared_ptr 标准库用法

`shared_ptr` 是标准库（`<memory>` 头文件）提供的、已经写好的"共享智能指针"，原理和本章第六节要手写的共享指针一致，可以直接使用：

```cpp
#include <memory>
using namespace std;

int main() {
    // 不推荐：指针可能指向程序区/栈区
    // shared_ptr<A> pA = shared_ptr<A>(new A(3));

    // 推荐：make_shared 保证在堆区一次性分配
    shared_ptr<A> pA = make_shared<A>(3);

    cout << pA->getN() << endl;   // -> 访问成员
    cout << (*pA).getN() << endl; // 等价写法
    pA->f();

    cout << pA.get() << endl;     // 获取原始指针地址
}   // 作用域结束，自动析构，自动delete
```

**基本共享用法**：

```cpp
shared_ptr<T> ptrT = make_shared<T>(3);
shared_ptr<T> ptrT2(ptrT);     // 拷贝构造：ptrT和ptrT2共享同一个对象
ptrT2->f();

shared_ptr<T> ptrT3(nullptr);
ptrT3 = ptrT2;                  // 赋值：ptrT3也加入共享
ptrT3->f();
```

### 5.3 shared_ptr 的内部结构

`shared_ptr` 内部实际上是**两个指针**：

```
Shared_ptr<A> pA
├── 实际对象指针 ──→ 真实分配的对象
└── 引用计数指针 ──→ 引用的计数（0,1,2,3,...；减到0时释放对象）
```

也就是说，每次 `shared_ptr` 被拷贝或赋值，"引用计数"就 +1；每次一个 `shared_ptr` 析构或改指向，计数就 -1；**计数变成 0 时，才真正 delete 掉被管理的对象**。这正是"多个对象共享同一份资源，但只释放一次"的核心机制。

**思考题（例1）**：

```cpp
class A {
public:
    A(int n) : pB(make_shared<B>(n)) { }
private:
    shared_ptr<B> pB;
};

int main() {
    A a1(88);
    A a2(100);
    A a3(a1);   // 拷贝构造：调用编译器生成的默认拷贝构造
    a1 = a2;    // 赋值：调用编译器生成的默认赋值运算符
}
```

分析：`A` 类没有自定义拷贝构造/赋值函数，编译器会生成默认版本，**逐成员拷贝** `pB`。因为 `pB` 是 `shared_ptr<B>`，逐成员拷贝会自动调用 `shared_ptr` 的拷贝构造/赋值，从而**正确地增加/减少引用计数**，而不会出现"浅拷贝导致 B 对象被多次 delete"的错误。这正是用 `shared_ptr` 替代裸指针作为成员的最大好处——**不用手写拷贝构造和赋值运算符，也不会有内存管理漏洞**。

### 5.4 用 shared_ptr 管理"不再使用的全局大对象"

现代 C++ 规范建议：**不要在栈区/全局数据区存放"大"对象**，应该放堆区，用智能指针管理。典型应用是单例模式：

```cpp
class GlobalObject {
public:
    static GlobalObject * getInstance() {
        static shared_ptr<GlobalObject> obj(new GlobalObject());
        return obj.get();
    }
    ~GlobalObject() = default;
private:
    GlobalObject() = default;
    GlobalObject(const GlobalObject&) = delete;             // 禁止拷贝
    GlobalObject(GlobalObject&&) = delete;                   // 禁止移动
    GlobalObject& operator=(const GlobalObject&) = delete;  // 禁止赋值
};
```

**要点**：局部 `static shared_ptr` 只会在第一次调用时构造一次；程序结束时，`static` 对象自动析构，`shared_ptr` 自动释放堆区对象——比手写全局裸指针（还要操心谁来 delete）更安全。

## 六、共享指针的实现

本节是本章的"手写造轮子"部分：模拟标准库 `shared_ptr` 的实现原理。场景设定：`B` 类内部持有一个指向 `A` 对象的指针 `pa`，希望多个 `B` 对象可以"共享"同一个 `A` 对象，而不是每次拷贝都深拷贝一份。

### 6.1 问题：为什么需要共享指针

原始（浅拷贝）写法：

```cpp
class B {
public:
    B(int num = 0) : pa(new A(num)) { }
    ~B() { delete pa; }
private:
    A * pa;
};
```

如果不写拷贝构造/赋值运算符，编译器默认生成的是**浅拷贝**（只拷贝指针值，不拷贝指向的对象）。这会导致：`b1` 和 `b2` 的 `pa` 指向**同一块内存**，`~B()` 被调用两次时，同一块内存被 `delete` 两次——**程序崩溃（double free）**。

如果改成深拷贝（每次拷贝都 `new A(*rhs.pa)`），虽然安全，但**违背了"共享"的初衷**（本来想让多个 B 共用同一个 A，深拷贝却让它们各自独立）。

### 6.2 共享指针的设计意图

```cpp
B b1(8);
B b2(b1);     // b2 与 b1 共享同一个 A 对象（值为8）
B b3(10);     // b3 独立拥有值为10的 A 对象
```

期望效果：`b1` 和 `b2` 指向同一份数据 `8`，`b3` 指向独立的数据 `10`。**关键是要有一个"计数器"记录"当前有多少个 B 在共用这份 A"**，只有计数归零时才真正释放 A。

### 6.3 方法一：计数变量放在 A 类中

思路：让被共享的资源（`A`）自己记住"有多少人在用我"。

```cpp
class A {
public:
    A(int num) : mData(num), mUse(1) { }   // 一出生就有1个使用者
    ~A() { }
    int getData() const { return mData; }
    void addRef() { ++mUse; }               // 增加使用者
    int releaseRef() { return --mUse; }     // 减少使用者，返回减完后的计数
private:
    int mUse;
    int mData;
};

class B {
public:
    B(int num = 0) : mpa(new A(num)) { }
    ~B() { release(); }

    B(const B& rhs) { mpa = rhs.mpa; mpa->addRef(); }    // 共享指针 + 计数+1

    B& operator=(const B& rhs) {
        if (this != &rhs) {
            release();               // 先放弃自己原来指向的对象
            mpa = rhs.mpa;
            mpa->addRef();           // 再共享对方的对象，计数+1
        }
        return *this;
    }

    A* operator->() { return mpa; }

private:
    void release() {
        if (mpa->releaseRef() == 0) delete mpa;   // 计数归零才真正删除
    }
    A* mpa;
};
```

**执行演绎**（对照 PPT 第 22 页图示）：

```
B b1(8);   →  A对象{8, 计数=1}                    b1 → A(8,1)
B b2(b1);  →  计数+1                              b1,b2 → A(8,2)
B b3(10);  →  新建A对象{10, 计数=1}                b3 → A(10,1)
（作用域结束，先析构b3，再b2，再b1）
~b3: 计数10的A → 0 → delete
~b2: 计数8的A → 2-1=1，不删除
~b1: 计数8的A → 1-1=0 → delete
```

### 6.4 方法二：计数变量放在 B 类中

方法一要求 `A` 类"知道"自己被共享，这**侵入了 A 类的设计**（A 本身可能是别人写的、不方便改）。更常见的做法是：**把计数变量单独拿出来，放在 B 类里，用一个额外的 `int*` 指针指向共享的计数**。

```cpp
class A {
public:
    A(int num) : mData(num) { }
    ~A() { }
    int GetData() const { return mData; }
    // A(const A&) 和 operator= 仍需要（用于其它场景），但共享逻辑不再依赖A
private:
    int mData;
};

class B {
public:
    B(int num = 0);
    ~B();
    B(const B& rhs);
    B& operator=(const B& rhs);
    A* operator->() const { return mpA; }
private:
    void addRef();
    void releaseRef();
private:
    A * mpA;         // 指向共享的A对象
    int * mpUse;      // 指向共享的引用计数（注意：是指针，多个B对象共用同一个int）
};
```

实现：

```cpp
B::B(int num) {
    mpUse = new int(1);     // 新建计数器，初值为1
    mpA = new A(num);
}

B::~B() { releaseRef(); }

B::B(const B& rhs) {
    mpA = rhs.mpA;          // 共享同一个A
    mpUse = rhs.mpUse;      // 共享同一个计数器
    addRef();
}

B& B::operator=(const B& rhs) {
    if (this != &rhs) {
        releaseRef();            // 先放弃原来的资源
        mpA = rhs.mpA;
        mpUse = rhs.mpUse;
        addRef();
    }
    return *this;
}

void B::addRef() { ++(*mpUse); }

void B::releaseRef() {
    if (--(*mpUse) == 0) {
        delete mpA;
        delete mpUse;
    }
}
```

**方法一 vs 方法二对比**：

| 对比项 | 方法一（计数放A类） | 方法二（计数放B类） |
|---|---|---|
| 是否需要修改被共享类 A | 是，要在 A 中加 `mUse`、`addRef`、`releaseRef` | 否，A 类保持原样 |
| 计数存储位置 | A 对象内部 | B 类额外维护一个 `int*` 指针，指向堆上单独分配的计数 |
| 适用场景 | 能修改 A 类源码时 | A 类是第三方库、不方便改动时（更通用，标准库 shared_ptr 采用类似思路） |

### 6.5 写时复制（Copy On Write）

共享指针带来一个新问题：`b2` 和 `b1` 共享同一个 `A` 对象，如果 `b2` 想**修改** `A` 里的数据，会不会连带把 `b1` 看到的数据也改了？——这通常不是我们想要的（各个 B 对象逻辑上应该"看起来"是独立的）。

解决方案叫"**写时复制**"：**只有真正要写入（修改）数据时，才检查是否被共享；如果被共享（计数>1），就先"分家"（复制一份独立的A），再修改这份新的；如果没被共享（计数==1），可以直接原地修改**。

```cpp
int B::readA() const {
    return mpA->getData();     // 读操作：不需要分家，大家可以共享读
}

void B::writeA(int n) {
    if (*mpUse == 1) {
        mpA->setData(n);              // 没人共享，直接改
    } else {
        releaseRef();                  // 与原共享组"分手"
        mpUse = new int(1);            // 建立自己独立的计数
        mpA = new A(*mpA);             // 深拷贝一份独立的A
        mpA->setData(n);               // 在自己的副本上修改
    }
}
```

**类比**：这就像多人合租的 Word 文档，只要大家都是"只读"，就可以共用一份；一旦有人想"编辑"，系统会自动帮 TA 复制一份私人副本再改，不影响其他人看到的原文档。**这样既节省了"人人都读、没人写"时的内存和拷贝开销，又保证了"一旦写，各自独立"的正确性。**

### 6.6 定位分配 placement new（补充，与共享指针配合理解内存布局）

除了普通 `new`，C++ 还提供了一种"**在已有的内存位置上构造对象**"的用法，叫定位分配（placement new）：

```cpp
new (指定的地址) T(构造参数);
```

它与普通 `new` 的核心区别：**不重新申请内存，只是在你指定的、已经存在的一块内存上调用构造函数**。这块内存可以在栈区，也可以在堆区。

```cpp
struct A {
    A(int v) : n(v) { }
    int n;
};

int main() {
    char data[sizeof(A) * 3];             // 手动申请一块原始字节数组（栈上）
    A * pA1 = new (data) A(1);            // 在data起始位置构造A(1)
    A * pA2 = new (pA1 + 1) A(2);          // 在下一个A大小的位置构造A(2)
    A * pA3 = new (pA1 + 2) A(3);

    cout << pA2->n << endl;   // 输出2

    pA1->~A();   // 手动析构（必须手动调用，因为不是new分配的内存，delete不能用）
    pA2->~A();
    pA3->~A();
}
```

**为什么需要它**：普通 `new` 每次都要重新向系统申请内存（有开销）；如果我们已经有一大块预先分配好的内存（比如实现一个高性能的栈/内存池），就可以用 placement new **只构造对象、不重新申请空间**，提升效率。典型应用是自定义容器（如 PPT 第 30 页的 `Stack` 类），`push` 时用 placement new 在预分配的 buffer 上构造元素，`pop` 时手动调用析构函数，而**不使用 delete**（因为空间本身是用 `new char[]` 一次性申请的，要整体 `delete[]` 释放，不能每个元素单独 delete）。

### 6.7 weak_ptr：解决 shared_ptr 的循环引用问题

`shared_ptr` 并非完美——如果出现"**循环引用**"（A 持有指向 B 的 shared_ptr，B 又持有指向 A 的 shared_ptr，形成环），会导致两者的引用计数永远无法降到 0，**造成内存泄漏，即使外部已经没有任何变量引用这两个对象**。

```
A对象 --shared_ptr<B>--> B对象 --shared_ptr<C>--> C对象 --shared_ptr<A>--> A对象
（形成闭环，谁的计数都降不到0）
```

**解决方案**：引入 `weak_ptr`（弱指针）。它的结构与 `shared_ptr` 类似，但**关键区别是**：`weak_ptr` 的构造/析构**不会**增加或减少所指向对象的 `shared_ptr` 引用计数（`use_count`），只会影响 `weak_ptr` 自己的计数。

也就是说：程序员在设计时，可以主动把"容易形成环"的那一条引用关系，从 `shared_ptr` 改成 `weak_ptr`，打破循环，让计数能够正常归零。

（目前 C++ 标准库只提供 `weak_ptr` 这一种应对方式；其它语言的思路包括"指定对象所有者(Owner)统一释放"或"定时自动垃圾回收"，PPT 提到未来 C++ 可能会有更完善的方案，本部分作为拓展了解即可。）

## 本章小结

1. **对象存储分两大类**：静态存储（全局区/常量区/栈区，生存期由编译器/作用域决定，不用操心释放）与动态存储（堆区，需要用 `new`/`delete` 手动管理），后者解决了前者"生存期不灵活、数组大小必须编译期常量、类型必须一致、要求无参构造函数"等痛点。
2. **new 的本质是两步**：先调用 `operator new` 申请裸内存，再在这块内存上调用构造函数；`delete` 反过来：先析构，后调用 `operator delete` 释放内存。数组版本 `new[]`/`delete[]` 要求成对使用，不能与单个版本混用。
3. **operator new / operator delete 可以重载**，即使不写 `static` 也隐式是静态成员；重载常用于统计对象个数、自定义内存池等场景；不重载则默认调用全局版本。
4. **对象数组三种实现方式**：值数组（要求无参构造，大小固定）、指针数组（放开构造要求）、动态指针数组（连大小也运行时决定），本质是通过"多套一层指针"逐步放开限制。
5. **智能指针的核心价值**：用对象的自动析构机制来自动管理裸指针的生命周期，避免忘记 delete；`shared_ptr` 是标准库提供的引用计数式共享智能指针，推荐用 `make_shared` 创建以保证在堆区分配。
6. **手写共享指针的两种思路**：计数变量放在被共享类中（侵入式，需修改原类）或放在包装类中（非侵入式，用额外指针共享同一份计数），后者更通用，是标准库 `shared_ptr` 的实现思路。
7. **写时复制（COW）** 让"共享读"和"独立写"共存：只在真正修改数据、且发现被多方共享时，才复制出独立副本。
8. **定位分配（placement new）** 允许在已有内存上直接构造对象，不重新申请空间，常用于高性能容器/内存池的实现，需手动调用析构函数、不能用 delete。
9. **weak_ptr 用于打破 shared_ptr 的循环引用**：它不参与引用计数的增减，专门用来解决"环状引用导致内存永远无法释放"的问题。
