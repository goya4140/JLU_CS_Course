# 第十九章 多态性及其应用（考前速记版）

## 知识结构导览（精简）

```
多态性
├─ 静态多态（编译期）：模板 / 函数重载
├─ 动态多态（运行期）：虚函数机制 ★★★
│   └─ 依据：对象动态类型 + 参数静态类型（C++不支持参数动态类型参与决议）★★★
├─ 虚机制作用：接口不变，实现可换（子类型化）
├─ 三大应用套路：
│   ├─ 父类给接口，子类给实现
│   ├─ 父类给框架(模板方法)，子类给细节
│   └─ clone()虚拷贝 —— 拷贝构造不能为虚 ★★★
└─ 虚机制不足：多维度独立变化 → 子类爆炸(乘法) → 关联+继承(组合优于继承)
```

---

## 一、多态性定义

| 概念 | 定义 |
|---|---|
| 多态性 | 相同消息请求，执行不同代码体，产生不同行为后果 |
| 静态多态 | 由**目标对象静态类型** + **参数静态类型**确定代码体（编译期） |
| 动态多态 | 由**目标对象动态类型** + **参数静态类型**确定代码体（运行期，即虚机制） |

★★★ **C++ 不支持"目标对象动态类型 + 参数动态类型"共同决议**（即不支持多重派发）。参数永远只按其**声明类型（静态类型）**匹配重载版本，与它实际指向的对象无关。

---

## 二、静态多态

| 实现方式 | 判断依据 | 特点 |
|---|---|---|
| 模板 | 模板参数类型 | 编译期实例化出不同版本的代码 |
| 函数重载 | 实参的静态类型/个数 | 编译期唯一确定调用哪个重载版本 |

```cpp
My<int> obj1;  My<float> obj2;
obj1.f(2);  // i
obj2.f(2);  // f

A obj;
obj.f(2);    // Int  （int 类型匹配）
obj.f('c');  // Char （char 类型匹配）
```

---

## 三、动态多态（★★★核心考点：经典例题）

```cpp
class A {
public:
    virtual void f(A *) { cout<<1; }
    virtual void f(B *) { cout<<2; }
};
class B : public A {
public:
    virtual void f(A *) { cout<<3; }
    virtual void f(B *) { cout<<4; }
};

B b;
A* pa = &b;
pa->f(&b);   // →4
pa->f(pa);   // →3   ★易错
b.f(pa);     // →3   ★易错
```

| 判断步骤 | 依据 |
|---|---|
| 用哪个类的虚表（调用谁的函数） | 调用对象的**动态类型** |
| 匹配哪个重载版本（参数选哪个） | 参数变量的**静态（声明）类型** |

★★★ 判断口诀：**"谁调用看实际指向，传参数看声明类型"**。
易错点：`pa` 实际指向 `B`，但因为 `pa` 被声明为 `A*`，传给参数时永远按 `A*` 匹配，不会因为它实际指向 B 就匹配 `f(B*)`。

---

## 四、虚机制的作用

- 虚机制 = 实现动态多态的手段
- 意义：**保持客户端访问接口不变，可自由变更类的具体实现**
- 基础：**子类型化**——父类指针/引用可以指向/绑定子类对象

```cpp
Parent* p = new Child1;
p->func();          // 自动调用 Child1::func
void Proc(Parent* p) { p->func(); }  // 通用，不用因新增子类而改
```

---

## 五、虚机制三大应用套路（对比表）

| 套路 | 核心结构 | 判断标志 |
|---|---|---|
| ①父类给接口，子类给实现 | 父类全是虚函数，各自独立 | 简单场景，"一个动作多种实现" |
| ②父类给框架，子类给细节（模板方法模式） | 父类有**非虚**总控函数（如 develop），内部调用若干**纯虚**步骤函数 | 固定流程、步骤可变 |
| ③clone() 虚拷贝（原型模式） | 因拷贝构造不能是虚函数，用虚函数 clone() 代替 | 需要"不知道具体类型也能复制对象" |

★★★ **拷贝构造函数不能声明为虚函数**——这是 clone 模式存在的根本原因，务必记住。

```cpp
// clone 模式标准写法
class A {
public:
    virtual A* clone() { return new A(*this); }
protected:
    A(const A&) {}
};
class B : public A {
public:
    virtual B* clone() { return new B(*this); }  // 协变返回类型
protected:
    B(const B&) = default;
};
```

★ 协变返回类型：子类 `clone()` 可以返回 `B*`（父类虚函数返回 `A*`），只要是其派生类指针/引用即可，这是合法的。

## 六、变化的两个层面

| 类型 | 含义 | 虚机制能否解决 |
|---|---|---|
| 接口变化 | 变更外部访问约定（函数原型：参数表、返回类型、增删成员、访问控制） | ❌ 一般不能，客户端要跟着改 |
| 实现变化 | 变更类内部组织或实现细节（函数具体逻辑、数据类型/组织） | ✅ 虚机制主要解决这个 |

---

## 七、虚机制的不足 ★★★

**问题**：一个类里多个虚函数各自独立地有多种实现，用"继承+重写"会导致子类数量**乘法级**爆炸。

> 例：f() 有2种实现，g() 有3种，h() 有4种，若三者任意组合 → 需要 **2×3×4=24** 个子类。

**解决方案：关联/依赖 + 继承（组合优于继承）**

| 方式 | 子类数量 |
|---|---|
| 单纯继承（笛卡尔积组合） | 2×3×4 = 24 个（乘法） |
| 关联+依赖+继承（拆分到独立辅助类） | 2+3+4 = 9 个（加法） |

```cpp
class Parent {
public:
    Parent(ImpF*, ImpG*, ImpH*);
    void f() { pF->f(); }
    void g() { pG->g(); }
    void h() { pH->h(); }
private:
    ImpF* pF; ImpG* pG; ImpH* pH;
};
```
把每个"变化维度"拆给独立的辅助类（ImpF/ImpG/ImpH），各自维护自己的继承体系，互不影响，运行时自由组合——**策略模式**雏形。

## 八、用多态替代 if-else（策略模式实战）★★

| 反例：if-else 硬编码 | 正确：虚函数 execute() |
|---|---|
| 新增/改条件 = 改 func() 主体 | 新增/改条件 = 新增/改一个子类 |
| 违反"对扩展开放对修改关闭" | 符合开闭原则 |

```cpp
class Code {
public:
    virtual void execute() = 0;
};
class Code01 : public Code { void execute() override { 代码块01 } };

class Some {
public:
    void func(Code& code) { code.execute(); }  // 永远不变
};
```
