## 本章核心问题（整章基调）

**这一章从头到尾都在回答一个问题：当两个类存在继承关系时，一个类型的对象能不能被当成另一个类型来使用？什么时候安全，什么时候危险？**

这个大问题具体拆成三个子问题，章节的每一节都是在依次回答它们：

1. **"能不能转"的问题**——继承方式（`public` / `protected` / `private`）不同，转换是否成立的逻辑基础也不同。只有 `public` 继承（is-a 关系）才有资格谈"转换"，`protected`/`private` 继承下转换本身就不成立。
2. **"向上转安全，但怎么转才不丢数据"的问题**——子转父天然安全，但如果用"对象拷贝"的方式转，会丢数据（对象裁剪），需要选对写法（指针/引用 vs 对象）。
3. **"向下转不一定安全，怎么保证不出事"的问题**——父转子编译器管不住，可能转错，需要一种机制在运行时把关（dynamic_cast）。

后面的"protected/private 继承下的转换""public 继承下的向上/向下转换""四大类型转换操作符"这几节，本质上都是围绕这三个子问题给出的具体方法。带着这条主线去读，会比逐节死记更容易理解为什么章节要这样安排顺序。

## 一、什么是"继承下的类型转换"

在有继承关系的两个类之间，我们经常需要把一个类型的指针/引用/对象"看成"另一个类型来使用。这就是本章的核心话题——**类型转换**。

先明确两个方向的说法：

- **向上类型转换（Upcasting）**：把"派生类（子类）"的指针、引用或对象，转换成"基类（父类）"的指针、引用或对象。因为在继承的类图里，基类通常画在上方，派生类画在下方，所以"派生类→基类"叫"向上"。
- **向下类型转换（Downcasting）**：反过来，把"基类（父类）"的指针、引用或对象，转换成"派生类（子类）"的指针、引用或对象，叫"向下"。

**为什么这个转换是否"有意义"要看继承方式（public / protected / private）？**

打个类比：继承方式决定了子类"继承"了父类的哪些"权限"。
- `public` 继承：父类的 `public` 成员在子类里还是 `public`，也就是说子类对外表现出来的行为集合"包含"了父类的行为集合。此时把子类对象当父类用，逻辑上是自然的——就像"金毛犬"是一种"狗"，把金毛犬当狗看待没有问题。
- `protected`/`private` 继承：父类的 `public` 成员在子类里变成了 `protected`/`private`，对外不再可见。子类和父类此时的"公开行为"已经不一样了，谈不上"子类是一种父类"，所以此时的类型转换**没有实际意义**。

## 二、protected/private 继承下的类型转换

### 2.1 向上类型转换（派生类 → 基类）

**结论：无实际意义。**

原因：`private`/`protected` 继承下，`Base` 类原本对外公开的接口在 `Derived` 中被"降级"隐藏了，`Base` 和 `Derived` 对外暴露的 `public` 接口互不相同。既然子类已经不再对外表现为"一种父类"，把它转换成父类指针/引用，在语义上就站不住脚。

如果确实需要做这个转换（比如内部实现需要），可以用**强制类型转换**或**自定义的自动转换函数**来"硬转"。

**例子（PPT 原例）：**

```cpp
class Bike {
public:
    void move();
    void stop();
    void repair();
protected:
    int changeColor(int);
private:
    int mColor;
};

class Player : private Bike {   // 私有继承
public:
    void startRace() { /*....*/ }
    void endRace()   { /*....*/ }
protected:
    int curStrength();
private:
    int mMaxStrength;
    int mAge;
};

int main() {
    Player player;
    Bike * pb = (Bike *)(&player);   // 强制转换，能编译通过，但语义上没意义
    pb->move();

    Bike & b = (Bike)(player);       // error！对象型转换在这里直接报错
}
```

这里要注意：指针的强制转换能"骗过"编译器，但这只是语法层面允许，逻辑上 `Player` 已经不是一种"公开的 Bike"了，所以不建议这样用。

### 2.2 向下类型转换（基类 → 派生类）

**结论：同样无实际意义。**

原因更直接：`Base` 对象本身根本不包含 `Derived` 新增的那些成员和行为，把一个"纯粹的 Base 对象"硬说成是"Derived 对象"，既没有对应的数据，也没有对应的行为（PPT 里说的"行为集不相关，数据也不全"）。

如果确实需要用一个 `Base` 对象"构造"出一个 `Derived` 对象，正确做法不是搞类型转换，而是在 `Derived` 里写一个**转换构造函数**：

```cpp
class Derived : protected Base {
public:
    Derived(const Base & b);   // 用一个 Base 对象来构造 Derived
};
```

这本质上是"新建一个对象"，而不是"转换视角"，两者概念不同，不要混淆。

## 三、public 继承下的类型转换

`public` 继承是 C++ 里表达"is-a"（是一种）关系的标准方式，所以这一节的转换才是**真正常用、真正有意义**的类型转换。

### 3.1 向上类型转换（子类 → 父类）

**结论：有意义，逻辑上是"泛化/一般化"。**

- 逻辑角度：把一个具体的子类对象当作更"一般"的父类来看待，就像把"轿车"当作"车"来处理。
- 语言角度：因为子类只会在父类的基础上"新增"或"重写"能力，绝不会减少父类原有的 `public` 接口，所以从"信息完整性"上说，子类天然具备父类的一切公开行为，转换是安全的。

**例子：**

```cpp
class Car {
public:
    void run();
    void brake();
protected:
    int addWeight(int w);
    int reduceWeight(int w);
private:
    int mWeight;
    int mWheels;
};

class MTCar : public Car {
public:
    void funcMT();
protected:
    // ...
private:
    // ...
};
```

`MTCar` 是一种 `Car`，把 `MTCar` 当 `Car` 用，天经地义。

**三种转换形式的安全性对比：**

| 转换形式 | 写法示例 | 是否安全 | 说明 |
|---|---|---|---|
| 指针型 | `Car * c1 = &c;` | ✅ 安全 | 只是换了个"看待方式"的指针，指向同一块内存 |
| 引用型 | `Car & c1 = c;` | ✅ 安全 | 同上，引用只是别名，没有额外开销 |
| 对象型 | `(Car) c;` | ✅ 安全，但会"对象裁剪"（slicing） | 会**新建**一个 `Car` 对象，把 `c` 里属于 `MTCar` 新增的那部分数据"切掉"，新对象与原对象不是同一个 |

> **对象裁剪（Object Slicing）**：当你把一个子类对象按值赋给/转换成父类对象时，编译器只会拷贝父类那部分的数据成员，子类新增的数据全部丢失，而且这是一个全新的对象，跟原来的子类对象已经没有关系了。这也是为什么 PPT 强调"**应尽可能使用指针或引用型向上类型转换**"——用指针/引用不会发生拷贝，也就不会丢数据。

**PPT 应用例子解读**（子类向父类转换的典型场景——面向接口编程）：

```cpp
class Parent {
public:
    virtual ~Parent() {}
    virtual void doFunc();
};

class Child : public Parent { /* ... */ };

class Example {
public:
    Example() { mp = new Child; }
    ~Example() {
        delete mp;   // 要正确释放，Parent 的析构函数必须是虚函数！
    }
    int func(Parent & obj) { obj.doFunc(); }   // 参数写成父类引用
private:
    Parent * mp;
};

int main() {
    Example exam;
    Child child;
    Parent & parent = child;   // 向上类型转换：引用型，安全
    exam.func(parent);
    exam.func(child);          // 直接传子类对象，也会自动向上转换
}
```

这里体现了向上类型转换最实用的价值：**函数参数写成父类引用/指针，就能接收任意子类对象**，这是实现多态的基础写法。同时也提醒了一个重要细节——**如果基类指针要 `delete` 一个派生类对象，基类的析构函数必须声明为 `virtual`**，否则只会调用基类的析构函数，子类新增的资源不会被正确释放（这是一个常见的内存泄漏坑）。

### 3.2 向下类型转换（父类 → 子类）

**结论：有意义，但"可能成功也可能失败"，只能在运行时确定。**

为什么会失败？因为一个父类指针，实际指向的对象到底是"哪个具体的子类"，编译期是不知道的。比如：

```cpp
Car * pCar = &aMTCar;   // pCar 实际指向一个 MTCar

void func(Car * pCar) {
    MTCar * p1 = (MTCar*) pCar;   // 如果 pCar 实际指向的不是 MTCar 而是别的车型，这里就是"猜错了"
    ...
}
```

如果 `func` 被传入的实际上是一个 `ATCar`（另一种车），用 `(MTCar*)` 强行转换，编译器不会报错，但运行时访问 `MTCar` 特有的成员就会出问题（未定义行为）。

**解决办法：用 `dynamic_cast`**，它会在运行时检查实际对象类型是否匹配，转换失败会给出明确反馈（指针型返回 `nullptr`，引用型抛异常），而不是"看似成功实则出错"。这部分在第四节详细展开。

## 四、C++ 中的类型转换操作符

C++ 里类型转换的方式其实有很多种，PPT 列了 5 大类，我们重点讲第 5 类——4 个专用的类型转换操作符。

**转换方式全景：**

1. 内置类型的自动转换，如 `int → float`
2. 构造函数转换（用一个类型的值构造出另一个类型的对象）
3. 自定义的自动转换函数（`operator T()`）
4. `public` 继承下的向上类型自动转换（上一节讲的）
5. 使用专门的**类型转换操作符**：`static_cast` / `const_cast` / `reinterpret_cast` / `dynamic_cast`

为什么 C++ 要专门造出这 4 个操作符，而不是继续用 C 语言里的 `(T)exp`？因为 C 风格的强制转换"什么都能转"，太粗暴、太危险，编译器很难帮你检查错误。C++ 把转换按"意图"拆成 4 种，让编译器能针对性地做检查，代码也更"自解释"——一看操作符名字就知道这次转换想干什么。

### 4.1 static_cast —— 静态转换

**格式：** `static_cast<T>(exp)`

相当于 C 语言里的强制类型转换 `(T)exp`，是最常规、最"温和"的一种转换，用于类型之间存在"自然联系"的场景（比如数值类型互转、有继承关系的指针互转）。

**限制：** T 只能是指针、引用、内置类型、枚举类型，**不能是对象**。

```cpp
A * pA = new A;
char * pByte = static_cast<char *>(pA);
```

### 4.2 const_cast —— 常量转换

**格式：** `const_cast<T>(exp)`

专门用来**添加或去掉** `const`（或 `volatile`）修饰，除了这个修饰符之外，`T` 和 `exp` 的类型必须完全一致（不能借此机会顺便改变类型本身）。

**为什么需要它？** 常见场景是：你手上只有一个 `const` 引用/指针，但你确实需要调用一个非 `const` 的成员函数，这时候就得先用 `const_cast` "去掉" const 属性。

**例1：对象层面去 const**

```cpp
class A {
public:
    A(int n): val(n) {}
    void setVal(int n) { val = n; }
    int getVal() const  { return val; }     // const 版本
    int getVal()        { return val + 1; } // 非 const 版本
private:
    int val;
};

int main() {
    A va(3);
    const A & ca = va;
    cout << ca.getVal();   // 输出 3，调用 const 版本
    cout << va.getVal();   // 输出 4，调用非 const 版本（va 不是 const）
    va.setVal(5);          // ok，val 改为 5
    ca.setVal(5);          // compile error！ca 是 const 引用，不能调非 const 方法

    A & var = const_cast<A &>(ca);   // 去掉 const
    var.setVal(6);         // ok，val 改为 6
}
```

**要点提醒：** 这个例子也顺带展示了 C++ 的**函数重载可以只靠 const 修饰区分**——`getVal() const` 和 `getVal()` 是两个不同的重载版本，编译器根据调用对象是否为 `const` 来自动选择。

**例2：在成员函数内部给 this 去 const，绕过 const 限制修改成员**

```cpp
int A::getVal() const {
    A * const p = const_cast<A * const>(this);
    p->val = xxx;     // 通过去掉 const 的指针来修改成员
    return val;
}
```

这种写法要谨慎使用——在一个声明为 `const` 的函数里偷偷修改了成员变量，属于"打破承诺"的做法，一般只在特殊场景（比如做缓存、日志计数）下使用，日常业务代码不建议这么写。

### 4.3 reinterpret_cast —— 重新解释

**格式：** `reinterpret_cast<T>(exp)`

这是四个转换符里"最危险"的一个，它不检查任何类型上的逻辑关系，纯粹是让编译器"重新解释"这段内存的类型，常用于**函数指针类型转换**、底层指针间的强制转换等场景。

**例子：**

```cpp
int MyFunc(void * pt) { /* ... */ }

typedef void (* FuncType)(char *);
FuncType f = reinterpret_cast<FuncType>(MyFunc);   // 把函数指针"重新解释"成另一种签名

char * buf = new char[256];
f(buf);
delete[] buf;
```

`reinterpret_cast` 基本等于告诉编译器"我知道我在干什么，别管我"，用它意味着你自己要为潜在的未定义行为负责，日常业务代码应尽量避免。

### 4.4 dynamic_cast —— 动态转换

**格式：** `dynamic_cast<T>(exp)`

这是专门为"继承体系下的**向下类型转换**"设计的操作符，也是本章前面留下的问题（向下转换可能失败）的标准解法。

**核心特点：**

1. 在**运行时**尝试把 `exp` 转换成 `T` 类型，常用于 `public` 继承下把父类类型转换成子类类型。
2. `T` 只能是**类的指针、类的引用、`void *`** 三种形式（不能是对象类型）。
3. `dynamic_cast` 依赖 **RTTI**（Run-Time Type Identification，运行时类型识别），而 RTTI 通常靠**虚函数表（VTable）**实现，所以**类里必须至少有一个虚函数**，才能使用 `dynamic_cast`（这是最容易忘、最容易考的一个前提条件）。

**T 为指针型：转换失败返回 `nullptr`**

```cpp
class A { };
class B : public A { };
class C : public A { };

A * p = new B;                       // 或 A * p = new C;
B * pb = dynamic_cast<B *>(p);
if (pb) {
    pb->....                         // 转换成功，可以安全使用
} else {
    // 转换失败，p 实际指向的不是 B
}
```

**T 为引用型：转换失败抛出异常**

```cpp
A * p = new B;                       // 或 A * p = new C;
try {
    B & b = dynamic_cast<B &>(*p);   // 若失败，产生运行时异常
} catch (...) {
    // 处理转换失败
}
```

**为什么指针型返回空指针、引用型却要抛异常？** 因为引用不像指针那样可以是"空"的——C++ 里没有"空引用"这个合法概念，所以转换失败时无法像指针那样返回一个"空引用"来表示失败，只能用异常机制来报告错误。这是一个非常经典、也非常容易在考试里被问到的细节。

## 附：volatile 关键字小知识

PPT 最后附带提到了 `volatile`，它和本章的 `const_cast` 相关，这里简单说明一下：

`volatile` 用来告诉编译器"这个变量的值可能会被程序之外的因素改变（比如硬件、其他线程），所以每次访问都必须重新从内存读取，不能做优化缓存"。

```cpp
class A {
public:
    A(int n): val(n) {}
    void func1();
    int  func2(volatile int & k);
private:
    volatile int val;
    int other;
};

void A::func1() {
    val = 1;
    val = 2;
    val = 3;
    // 因为 val 是 volatile，编译器不会把这三行优化合并成一行 val = 3，
    // 每一次赋值都会真实地写入内存
}
```

这与本章的联系在于：`const_cast` 除了能去掉/添加 `const`，同样也能去掉/添加 `volatile` 修饰，两者语法和思路是一致的。

## 本章小结

1. **类型转换的方向**：派生类→基类叫"向上转换"，基类→派生类叫"向下转换"。
2. **继承方式决定转换是否有意义**：`protected`/`private` 继承下，向上、向下转换都**没有实际意义**（如需要，只能靠强制转换或自定义转换构造函数硬做）；`public` 继承下，转换才真正"有意义"。
3. **public 继承下的向上转换**：指针型、引用型是安全且推荐的；对象型虽然安全，但会发生"对象裁剪"，产生一个丢失了子类特有数据的新对象——**应尽量用指针或引用做向上转换**。
4. **public 继承下的向下转换**：语义上有意义，但**能否成功要看运行时实际对象类型**，静态强制转换有风险，正确做法是用 `dynamic_cast`。
5. **四大类型转换操作符各司其职**：
   - `static_cast`：常规转换，替代 C 风格强转，不能用于对象。
   - `const_cast`：专门加/去 `const`（或 `volatile`），类型本身不能变。
   - `reinterpret_cast`：底层"重新解释"内存，最危险，常用于函数指针转换。
   - `dynamic_cast`：运行时安全的向下转换，指针失败返回 `nullptr`，引用失败抛异常；**前提是类中必须有虚函数（依赖 RTTI）**。
6. **一个容易忽视但很重要的实践点**：如果会用基类指针 `delete` 一个派生类对象，基类的析构函数**必须**声明为 `virtual`，否则子类资源无法被正确释放。
