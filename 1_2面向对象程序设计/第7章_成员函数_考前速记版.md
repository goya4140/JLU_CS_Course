# 第七章 成员函数（考前速记版）

## 📚 知识结构速览

```
成员函数
├─ 实现：类外用 类名::函数名 实现
├─ this指针 ★★★：T * const this，隐含第一个形参
├─ 外联/内联实现：解决循环依赖用外联
├─ 访问控制 ★★★：public/private/protected，private是"类的私有"非"对象的私有"
├─ 常成员函数 ★★★：函数头加const，this变const T* const this
├─ 实例 vs 类（static）成员 ★★★
│   ├─ 实例：每对象一份
│   └─ 类：static，全类共享，无this，不能const
└─ 封装与信息隐蔽：class + 访问控制
```

---

## 1. this指针 ★★★

| 要点 | 内容 |
|---|---|
| 本质 | 非静态成员函数隐含的**第一个形参** |
| 类型 | `T * const this` |
| 作用域 | 仅在该非静态成员函数 `{}` 内 |
| 用途 | 区分同名参数、`return *this` 支持链式调用 |

**判断依据**：`obj.func(x)` 编译器内部等价于 `Class::func(&obj, x)`。

```cpp
Ultraman& fight(Monster&);   // 返回*this，才能链式：a.fight(m1).fight(m2)
```

---

## 2. 外联实现 vs 内联实现

| | 外联 | 内联 |
|---|---|---|
| 写法 | `.cpp`中 `类名::函数名` | 类内直接写 / `inline`关键字 |
| 编译器处理 | 正常调用 | **只是建议**展开，不强制 |
| 适用 | 复杂逻辑、**两类互相调用需前置声明+外联解决循环依赖** | 简单短小、频繁调用（getter/setter） |

**★★★ 易错点**：`inline` 只在**实现处**加才有意义；只在**声明处**加没有实际意义。

```cpp
void h();          // 声明，无inline
inline void T::h(){}  // ✅ 实现处加inline才真正生效
inline void k();   // ❌ 声明处加inline无意义（除非实现处也加）
```

**循环依赖判断**：两个类互相内联调用对方成员函数会编译出错（前置声明的类型不完整）→ 改成外联实现（.cpp里include两个头文件）即可解决。

---

## 3. 访问控制 ★★★

| 权限 | 谁能访问 |
|---|---|
| public | 任何类 |
| private | **本类**（不是本对象！）或友元 |
| protected | 对本类=private，对派生类可访问 |

**★★★ 最易考的坑**：private限制的边界是"类"，**不是"对象"**。

```cpp
void Student::help(Student& other) {
    other.mScore += 2;     // ✅ OK：other是同类对象，在Student自己的成员函数里访问
    other.otherFunc();     // ✅ OK：otherFunc是private，但同类可访问
}
```

判断口诀：**只要访问代码写在"这个类自己的成员函数里"，不管操作的是哪个对象（自己还是同类的其它对象），都合法。**

---

## 4. 常成员函数（const成员函数） ★★★

| 要点 | 内容 |
|---|---|
| 语法 | `<返回类型> <函数名>(<参数>) const;` |
| this类型对比 | 普通函数：`T * const this`；常函数：`const T * const this` |
| 调用规则 | **常量对象（const T&）只能调用常成员函数** |
| 优先匹配 | 普通对象调用同名函数时，**优先匹配非const版本**（可重载） |
| 内部限制 | 常成员函数内**不能调用非const的其他成员函数** |

**判断题高频考点**：

```cpp
void gg(const MyClass& ca) {
    ca.add();     // ❌ add不是const函数
    ca.func();    // ✅ 匹配 func() const
    ca.func(2);   // ❌ func(int) 不是const函数
}
```

**★★★ 什么时候必须加const**：只要函数**逻辑上不修改对象数据**，就应加const，否则该类完全无法与const环境（如 `const T&` 传参）兼容。

**★★★ 返回值类型陷阱**：常成员函数若返回内部数据的引用/指针，**必须加const**，否则等于开后门绕过const承诺。

```cpp
int&  getID03() const { return mID; }        // ❌ 错误！非const引用+const函数矛盾
const int& getID04() const { return mID; }   // ✅ 正确
```

## 5. 实例成员 vs 类（静态）成员 ★★★

| 对比项 | 实例变(常)量/实例方法 | 类变(常)量/类方法（static） |
|---|---|---|
| 归属 | 每个对象各一份 | 全类对象共享一份 |
| C++关键字 | 无特殊修饰 | `static` |
| 内存 | 随对象分配 | 类外单独定义、只有一份 |
| this指针 | 有 | **没有** |
| 能否加const | 可以 | **不能** |
| 访问非静态成员 | 可以 | **不能直接访问**（需通过对象引用/指针） |
| 推荐调用方式 | `objName.func()` | `ClassName::func()`（不推荐用对象名调） |

```cpp
class Example {
public:
    static int nextNum(Example& ex) {
        // this->funcOne();  ❌ 类方法无this
        // ++mValue;         ❌ 不能直接访问非静态成员
        sNum += ex.mValue;   // ✅ 通过传入对象访问
        return ++sNum;
    }
private:
    static int sNum;   // 声明
    int mValue;
};
int Example::sNum = 1000;  // ★★★ 类变量必须在类外单独定义+初始化
```

**★★★ 易错判断**：类方法能不能直接写 `mValue++`？—— **不能**，必须通过某个对象（如传入的引用/指针）访问。

## 6. 封装与信息隐蔽

| 概念 | 定义 | C++实现手段 |
|---|---|---|
| 封装 | 打包数据+行为成一个整体 | class |
| 信息隐蔽 | 隐藏部分信息，只公开必要接口 | 访问控制（private等） |

作用：分离使用和实现 / 分离接口与实现 / 软件复用。

---

## ✅ 考前速记 Checklist

- [ ] this指针类型是 `T * const this`，常函数中变成 `const T * const this`
- [ ] `return *this` 才能实现链式调用（不是 `return this`）
- [ ] inline要加在**实现处**才有效，加在声明处无意义
- [ ] 两类互相调用对方成员函数 → 用**前置声明+外联实现**解决循环依赖
- [ ] private的边界是**类**，同类不同对象之间可以互相访问private成员
- [ ] 常量对象（const T&）**只能**调用const成员函数
- [ ] 普通对象调用重载函数时**优先匹配非const版本**
- [ ] 常成员函数返回内部数据引用/指针时，返回类型也要加const
- [ ] 只要函数不修改数据就该加const，否则无法配合const对象使用
- [ ] 类方法（static）**没有this**、**不能加const**、**不能直接访问非静态成员**
- [ ] 类变量必须在类外**单独定义+初始化**一次（如 `int Example::sNum = 1000;`）
- [ ] 调用静态成员函数推荐用 `类名::函数名()`，而非对象名调用
