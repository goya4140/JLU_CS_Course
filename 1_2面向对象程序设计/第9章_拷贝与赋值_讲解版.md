## 二、逐节详解

### 1. 为什么需要拷贝对象

**是什么**：C++ 中对象经常需要"复制"出一份新的，最典型的两个场景：

- **按值传递对象作为函数参数**：调用 `Function(a)` 时，形参 `aA` 不是 `a` 本身，而是 `a` 的一份拷贝。
- **按值返回对象**：`Function()` 内部构造的局部对象 `aA` 在函数结束后本应销毁，但 `return aA;` 会把它"拷贝"一份传给调用者继续使用。

**为什么**：如果没有拷贝机制，函数内部对参数的修改会直接影响外部实参（丧失值语义），或者函数返回后局部对象被销毁，调用者拿到的将是"悬空"的东西。拷贝机制保证了值语义的正确性和对象生命周期的安全性。

**怎么用**：

```cpp
class A { /* 略 */ };
void Function(A aA) { /* aA 是 a 的拷贝 */ }

int main() {
    A a;
    Function(a);   // 传值 -> 触发拷贝构造
    return 0;
}
```

```cpp
class A {
public:
    void g() const;
};
A Function() {
    A aA;
    return aA;     // 返回值 -> 可能触发拷贝构造（或被 RVO 优化掉）
}
int main() {
    Function().g(); // 用临时对象直接调用
    return 0;
}
```

> 生活化类比：拷贝就像"复印一份文件"给别人用，原件还在你手里，别人改他那份不会影响你的原件。

### 2. 拷贝构造函数

**是什么**：拷贝构造函数是一种特殊的构造函数，作用是"**根据一个已存在的同类对象，从无到有地创建一个新对象**"。它的参数**必须且只能有一个本类对象**（引用形式）。

**为什么单独强调"从无到有"**：这是区分"拷贝"与"赋值"的关键——拷贝构造发生时，新对象**尚不存在**；赋值发生时，左边的对象**已经存在**，只是内容被修改。

| 拷贝（构造） | 赋值 |
|---|---|
| `B b2(b1);` —— 构造前 b2 不存在 | `a1 = a2;` —— 赋值前 a1 已存在 |
| `B b3 = b1;` —— 构造前 b3 不存在 | 本质是调用 `operator=` |
| 调用拷贝构造函数 | 调用赋值函数 |

**怎么用（基本格式）**：

```cpp
class T {
public:
    T(const T&);   // 拷贝构造函数
    // ...
};
```

```cpp
class MyClass {
public:
    MyClass(int) {}                    // 普通构造函数
    MyClass(const MyClass& obj) { }    // 自定义拷贝构造函数
};
```

**拷贝构造函数的原型细节**：

- 访问控制可以是 `public`、`protected`、`private`（用于限制拷贝行为，见第4节）
- 参数**必须传引用**，不能传值（如果传值，调用它本身又要发生一次拷贝，会造成无限递归！这是"必须传引用"的根本原因）
- 通常用 `const T&`，但也可以是非 const 的 `T&`（当拷贝语义带有"资源转移"的意图时）
- C++11 新增了移动构造函数 `T(T&& rhs)`，用于"窃取"临时对象的资源而非复制，效率更高（本章暂不展开，属于移动语义范畴）

**特殊用法：所有权转移式的"拷贝"构造**

```cpp
class My {
public:
    My(My& rhs) {              // 注意：非 const 引用
        mpValue = rhs.mpValue;
        rhs.mpValue = nullptr; // 转移后原对象置空
    }
private:
    int* mpValue;
};
```

这种写法虽然形式上是拷贝构造函数，但语义上是"资源转移"——拷贝完成后原对象的指针被清空，类似于把钥匙给了新对象，自己不再持有。

**拷贝构造函数的调用方式**：

| 调用方式 | 示例 | 说明 |
|---|---|---|
| 显式调用 | `A a2(a1);` `A a3 = a1;` | 直接以已有对象初始化新对象 |
| 隐式调用（传参） | `Function(a)`（按值传参） | 编译器自动调用 |
| 隐式调用（返回） | `return aA;`（按值返回） | 编译器自动调用，但可能被 RVO 优化掉 |

**返回值优化（RVO, Return Value Optimize）**：编译器在很多情况下会"跳过"本该发生的一次拷贝构造，直接在调用者的内存位置构造对象，以提升效率。例如：

```cpp
return A(2);   // 使用匿名临时对象，更容易被编译器优化
```

**类成员用拷贝构造函数初始化的例子**：

```cpp
class A {
public:
    A(int n);
    A(const A& rhs);
};
class B {
public:
    B(A& aA) : mA(aA) {}   // 用 aA 拷贝构造 mA —— 拷贝构造
    B(int n) : mA(n) {}    // 用 n 构造 mA —— 普通构造
private:
    A mA;
};
```

> 类比：拷贝构造函数就像"照着一个人做一个复制人"——一定是**先有原型，再产生新个体**；而赋值则是"给一个已经活着的人改变身份信息"。

### 3. 缺省拷贝构造函数与浅拷贝

**是什么**：如果程序员没有自己写拷贝构造函数，编译器会自动生成一个默认版本，访问权限是 `public`，采用的策略叫**浅拷贝**（也叫位拷贝、浅复制）。

**浅拷贝的本质**：对不同类型的数据成员采取不同的默认处理方式：

| 数据成员类型 | 浅拷贝的处理方式 |
|---|---|
| 静态数据成员 | 不拷贝（本来就是类共享的） |
| 内置类型（int、指针数值本身等） | 按二进制逐字节复制 |
| 指针数据成员 | 只复制指针的值（地址），**不复制指向的内容** |
| 对象数据成员 | 自动调用该对象所属类的拷贝构造函数（递归处理） |
| 引用数据成员 | 不推荐使用，浅拷贝无法处理引用的重新绑定 |

**为什么"浅"拷贝有时不够用**：因为指针成员浅拷贝后，新旧两个对象的指针会**指向同一块堆内存**。这看起来像"共享"，但实际上会带来严重问题——典型例子：

```cpp
class A { /* 略 */ };
class B {
public:
    B() { mpA = new A; }
    ~B() { delete mpA; }
private:
    A* mpA;
};

int main() {
    B b1;
    B b2(b1);   // 浅拷贝：b2.mpA 和 b1.mpA 指向同一个 A 对象
    return 0;
}
```

问题在于：`b1` 和 `b2` 析构时都会 `delete mpA`，而两个指针指向的是**同一块内存**，于是发生**重复释放（double free）**，这是未定义行为，程序很可能崩溃。

```
浅拷贝示意：
   b1.mpA ──┐
             ├──► 同一个 A 对象（堆区）
   b2.mpA ──┘
```

> 类比：浅拷贝就像复印了一张"房产证的照片"给朋友，但房子实际上只有一套。如果你们两人都拿着各自的"证明"去把房子卖掉（析构时释放），就会出问题——因为房子只能被"处理"一次。

### 4. 自定义拷贝构造函数：深拷贝与禁止拷贝

#### 4.1 深拷贝

**是什么**：深拷贝是"按程序员的目的实现拷贝"——通常意味着：如果成员是指针，就不能只复制指针值，而要**为新对象重新申请一块独立内存，并复制内容过去**。深拷贝**只能通过自定义拷贝构造函数**实现（编译器默认生成的一定是浅拷贝）。

**怎么用**：

```cpp
class B {
public:
    B() { mpA = new A; }
    ~B() { delete mpA; }

    // 深拷贝写法一：函数体内赋值
    B(const B& b) : mA(b.mA) {
        mpA = new A(*b.mpA);   // 重新申请内存并复制内容
    }

    // 深拷贝写法二：初始化列表中完成（更推荐，效率更高）
    B(const B& b) : mpA(new A(*b.mpA)), mA(b.mA) {}

private:
    A* mpA;
    A  mA;     // 对象成员，本身会自动走深拷贝（调用 A 的拷贝构造）
};
```

深拷贝后：

```
   b1.mpA ──► A对象①（堆区）
   b2.mpA ──► A对象②（堆区，b1 的复制品）
```

两个对象各自拥有独立的资源，析构时互不影响。

**深拷贝不一定是"物理"复制**：PPT 特别提到"可以物理意义上，也可以逻辑意义上深拷贝"——意思是深拷贝的核心不是"必须新建内存"，而是"**保证语义正确**"，比如引用计数、写时复制（copy-on-write）等技巧在逻辑上也算深拷贝的一种变体。

#### 4.2 需要自定义拷贝构造函数的四种情形

| 情形 | 说明 |
|---|---|
| a. 深拷贝时 | 成员含指针等资源，需要重新分配 |
| b. 禁止拷贝 | C++11 之前的经典做法（见下） |
| c. 防止按值传递对象 | 拷贝构造被禁用后，按值传参/返回会编译报错，避免无意间产生昂贵或错误的拷贝 |
| d. 其它特殊目的 | 如引用计数、所有权转移、单件模式（Singleton）等 |

**三种声明格式**：

```cpp
T(const T& rhs);              // 格式1：普通自定义实现
T(const T& rhs) = default;    // 格式2：显式要求编译器生成默认版本
T(const T& rhs) = delete;     // 格式3：显式禁止拷贝（C++11起）
```

#### 4.3 禁止拷贝的写法对比

| 写法 | 特点 |
|---|---|
| `private: My(const My& m) {}` | C++98 常见做法，函数体为空，防止外部调用；但**类内部**仍可调用（如成员函数里） |
| `private: My(const My& m);`（不写实现） | 更严格：类内部调用会**编译通过但链接失败**，因为找不到函数体 |
| `My(const My& m) = delete;`（C++11起） | **最推荐**：任何地方尝试拷贝都会在**编译期**直接报错，语义最清晰 |

**对比示例**：

**写法一：只声明不实现（旧式做法）**

```cpp
class My {
public:
    My(const My&); // 无类外实现
private:
    void f() {
        My m1;
        My m2(m1); // 链接错误
    }
};
int main() {
    My m1;
    My m2(m1);     // 链接错误
}
```

**写法二：`= delete`（现代做法，推荐）**

```cpp
class My {
public:
    My(const My&) = delete;
};
int main() {
    My m1;
    My m2(m1);     // 编译错误（更早发现问题）
}
```

**结论**：若要完全禁止拷贝，最好的方式是使用 `= delete`（C++11 及以后），它在编译阶段就能拦截错误，而不是拖到链接阶段才报错。

> 类比：`private` 且不实现，相当于"钥匙孔堵死但没告诉你堵死了"，你走到最后一步（链接）才发现进不去；而 `= delete` 相当于"门上直接贴了封条"，一眼就能看出不能用。

### 5. 对象的赋值

**是什么**：赋值是"根据已有的其它对象，**修改当前已存在的对象**"。

**拷贝 vs 赋值的核心区别**：

| 拷贝（构造） | 赋值 |
|---|---|
| 从无到有，新建一个对象 | 对象已经存在，只是内容被修改 |
| `A a2(a1);` `A a3 = a2;` | `a3 = a1;` |
| 调用拷贝构造函数 | 调用 `operator=` |

> 注意易混点：`A a3 = a2;` 虽然用了 `=` 符号，但因为 `a3` 是**新定义**的对象，这其实是**拷贝构造**，不是赋值！只有当左边对象已经存在时（如 `a3 = a1;`，`a3` 已经定义过），才是真正的赋值。

```cpp
int main() {
    A a1;
    A a2(a1);   // 拷贝构造
    A a3 = a2;  // 拷贝构造（易错点！不是赋值）
    a3 = a1;    // 赋值
    return 0;
}
```

#### 缺省（默认）赋值函数

同拷贝构造一样，如果没有自定义 `operator=`，编译器会生成默认版本，访问权限 `public`，采用**浅赋值**：

- 含义与浅拷贝类似（内置类型逐字节复制，对象成员调用其赋值函数）
- **有非静态引用成员时，禁止使用默认赋值**——因为引用一旦绑定就不能重新指向别的对象，编译器无法生成合理的赋值逻辑

```cpp
class AA { /* 略 */ };
class My {
public:
    My(AA& ra) : mRefAA(ra) {}
private:
    int mVal;
    AA* mpAA;
    AA& mRefAA;   // 引用成员
    AA  mAA;
};

int main() {
    AA a1, a2;
    My m1(a1), m2(a2);
    m1 = m2;   // 编译错误！因为有引用成员，禁止赋值
}
```

**浅赋值的不足**（与浅拷贝问题几乎一样）：

```cpp
class A { /* 略 */ };
class B {
public:
    B() { mpA = new A; }
    ~B() { delete mpA; }
private:
    A* mpA;
};

int main() {
    B b1, b2;
    b1 = b2;   // 浅赋值：b1.mpA 原来指向的内存"泄漏"，
               // 且 b1.mpA 和 b2.mpA 现在指向同一对象，
               // 析构时又会重复释放
    return 0;
}
```

这里比浅拷贝还多一个问题：`b1` 原本 `new` 出来的那块内存，因为直接被覆盖指向了 `b2.mpA`，**没有先 delete，就产生了内存泄漏**。

### 6. 自定义赋值函数（operator=）

**是什么**：程序员自己实现 `operator=`，以解决浅赋值带来的内存泄漏、重复释放等问题，通常配合深拷贝一起写。

**三种声明格式**（与拷贝构造对称）：

```cpp
T& operator=(const T& rhs);              // 格式1：自定义实现
T& operator=(const T& rhs) = default;    // 格式2：使用默认版本
T& operator=(const T& rhs) = delete;     // 格式3：禁止赋值
```

**基本框架**：

```cpp
class My {
public:
    My& operator=(const My& rhs) {
        // ... 赋值逻辑
        return *this;
    }
};
```

#### 6.1 为什么必须返回引用 `*this`

C++ 内置类型的赋值支持**链式赋值**和**赋值表达式作为左值**：

```cpp
int a = 1, b = 2, c = 3;
a = b = c;      // 链式赋值
(a = b) = c;    // 赋值表达式的结果还能再被赋值
```

为了让自定义类型的对象也能保持和内置类型一致的行为，`operator=` 必须返回**当前对象的引用**。

**两种错误写法对比**：

| 对比项 | 反例1：返回 void | 反例2：返回值（非引用） |
|---|---|---|
| 声明 | `void operator=(const My& rhs);` | `My operator=(const My& rhs);` |
| `m1 = m2 = m3;` | **编译错误**（`m2=m3` 返回 void，无法再赋给 m1） | 能编译，但每次赋值都多产生一次拷贝，效率低 |
| `(m1 = m2) = m3;` | 编译错误 | 修改的是一个**临时对象**，不是 m1 本身，语义与内置类型不一致 |

**正确写法**：`My& operator=(const My& rhs);`，保证 `m1 = m2 = m3;` 和 `(m1 = m2) = m3;` 都能像 `int` 一样正确工作。

#### 6.2 自我赋值判定

**是什么**：赋值函数实现中要考虑 `a = a` 这种"自己赋值给自己"的极端情况。

**为什么危险**：如果赋值函数写成"先释放旧资源，再申请新资源并复制"，当 `rhs` 和 `*this` 是同一个对象时，"释放旧资源"这一步会把自己唯一的数据也删掉，之后再想从 `rhs` 复制数据时，数据早已不存在（悬空指针），导致程序出错。

```cpp
class B {
public:
    B() { pch = new char; }
    ~B() { delete pch; }
    B& operator=(const B& rhs) {
        delete pch;                    // 若 rhs 就是 *this，这里把自己删了
        pch = new char(*rhs.pch);      // rhs.pch 已经是野指针，出错！
        return *this;
    }
private:
    char* pch;
};

int main() {
    B b1;
    B& b2 = b1;
    b1 = b1;   // 自我赋值：触发 bug
    b1 = b2;   // 本质上也是自我赋值（b2 是 b1 的引用）！
    return 0;
}
```

**一般实现（加自我赋值判定）**：

```cpp
B& B::operator=(const B& rhs) {
    if (&rhs != this) {                // 判断是否是同一个对象
        delete pch;
        pch = new char(*rhs.pch);
    }
    return *this;
}
```

> 注意：这里比较的是**地址**（`&rhs != this`），而不是内容，因为要判断的是"是不是同一个对象"，不是"内容是否相同"。

#### 6.3 异常安全实现（推荐做法：copy-and-swap）

**是什么**：即使加了自我赋值判定，`if` 分支写法在某些复杂场景下（比如 `new` 抛异常）仍可能出问题。更稳妥、更优雅的方式是 **copy-and-swap（拷贝后交换）惯用法**：先用参数拷贝出一个临时对象，再用 `swap` 交换资源。

```cpp
// 写法一：参数为 const 引用，函数体内拷贝
B& B::operator=(const B& rhs) {
    B temp(rhs);          // 利用拷贝构造函数造一个临时副本
    swap(pch, temp.pch);  // 交换资源，总是安全的
    return *this;
    // temp 离开作用域时自动析构，顺便释放了旧资源
}

// 写法二：参数按值传递（拷贝在传参时已完成），更简洁
B& B::operator=(B rhs) {
    swap(pch, rhs.pch);
    return *this;
}
```

**为什么这样"总是安全"**：

1. 不需要显式判断自我赋值，因为交换指针不会导致资源被提前释放。
2. 如果拷贝构造过程中发生异常（如内存不足），异常会在 `temp` 构造阶段抛出，此时 `*this` 还**没有被修改**，保持原状——这就是"异常安全"的含义。
3. 代码更简洁、更不容易出错，是 C++ 中广泛推荐的赋值运算符实现方式。

> 类比：以前的做法像是"先把自己家的东西全扔了，再去邻居家搬"——万一半路出车祸（异常），家里已经空了。copy-and-swap 则是"先在邻居家门口打包好一份新家当（临时对象），确认打包成功后，直接和自己家整体互换"——哪怕打包过程失败，自己家原来的东西也完好无损。

## 三、本章小结

1. **拷贝的必要性**：按值传参和按值返回都会触发对象拷贝，理解这一点是理解拷贝构造函数存在意义的基础。
2. **拷贝构造函数**：作用是"从无到有"创建新对象，参数必须是本类对象的引用（不能传值，否则无限递归），格式为 `T(const T&)`，区别于"对象已存在"的赋值操作。
3. **缺省拷贝构造函数是浅拷贝**：按字节复制成员，指针成员只复制地址不复制内容，当类中含有指针成员且管理动态资源时，浅拷贝会导致重复释放、悬空指针等问题。
4. **深拷贝需要自定义拷贝构造函数**：为指针成员重新分配内存并复制内容，从根本上让两个对象的资源相互独立。
5. **禁止拷贝的最佳实践**是使用 `= delete`（C++11 起），比"仅声明不实现"更早（编译期而非链接期）发现错误。
6. **赋值与拷贝的本质区别**：赋值针对已存在的对象，是"修改"；拷贝构造针对不存在的对象，是"创建"。`A a3 = a2;` 这种写法虽有 `=` 号，实际上仍是拷贝构造，是常见易错点。
7. **默认赋值函数同样是浅赋值**，存在同样的资源管理问题，且**有非静态引用成员时会被编译器禁止**。
8. **自定义赋值函数（operator=）必须返回 `*this` 的引用**，以支持链式赋值 `a=b=c` 和 `(a=b)=c` 这类合法的内置类型行为。
9. **必须处理自我赋值**（`a = a`），否则先释放后复制的写法会导致数据丢失；简单方式是判断 `&rhs != this`，更推荐的方式是 **copy-and-swap** 惯用法，具备天然的异常安全性。
10. 拷贝构造函数、析构函数、赋值函数常被称为"三大函数"，只要类中有一个需要自定义（通常因为管理了动态资源），另外两个也大概率需要一起自定义，这是后续学习"资源管理类"设计的重要基础。
