## 二、逐节详解

### 1. 函数声明

**是什么**：函数声明（也叫函数原型/函数签名）告诉编译器"这个函数长什么样子"——名字、参数个数、参数顺序、参数类型，但不包含函数体。

**为什么**：C++ 是先声明后使用的语言。如果函数定义在调用之后，编译器需要先看到声明才知道怎么生成调用代码（怎么传参、返回什么类型）。

**怎么用**：

```
格式：[extern] [调用约定] <返回类型><函数名>(<参数表>) [const];
```

举例：

```cpp
void buy(int num);                          // C++98下默认标准C调用；C++1z下默认__stdcall调用
int __cdecl myFunc(int);                     // 显式指定标准C调用，形参名可以省略
int __stdcall sell(Sheep & aSheep);          // 显式指定__stdcall调用
int& max2(int& one, int&) noexcept;          // C++11起用noexcept代替throw()表示不抛异常
```

**关键结论**（划重点）：**返回类型**和**缺省参数值**都不能作为区分两个函数是不是同一个函数的标志。也就是说，编译器判断"是不是同一个函数"，只看：函数名 + 参数个数 + 参数类型 + 参数顺序 + const 修饰（针对成员函数）。

---

### 2. 函数的缺省参数

**是什么**：这一节其实讲了两个独立但容易混淆的问题。

**问题一：仅返回类型不同，算不算两个不同的函数？**

不算。编译器只看函数名+参数列表，返回类型不参与区分，所以下面这段代码会报错：

**错误写法（重复定义）：**

```cpp
int func(){ }
void func(){ }   // 错误！
```

**说明**：参数列表都是空的，仅返回类型不同，编译器认为这是同一个函数被定义了两次。

**问题二：缺省参数是什么时候"生效"的？**

**是什么**：缺省参数指在函数声明中给形参预先指定一个值，调用时如果不传该实参，就用这个预设值。

**为什么容易出错**：很多初学者以为缺省参数是"运行时"决定的，其实它是**编译期（准确说是预编译/预处理阶段）静态匹配**的——调用点在编译时就已经把"缺参数的调用"替换成"补全参数后的调用"。这意味着，如果两个不同的 .cpp 文件对同一个函数写了不同的缺省值声明，各自文件里的调用会各自按照自己看到的声明去匹配，产生"同一个函数在不同地方表现不同"的诡异效果。

**举例对比**：

**a.cpp：**

```cpp
void func(int n=6) { cout<<n; }
void k();
int main() {
  func();  // 预编译 => func(6)
  k();
  return 0;
}
```

**b.cpp：**

```cpp
void func(int =8);
void k() {
  func();  // 预编译 => func(8)
}
```

同一个 `func()` 调用，在 a.cpp 里因为看到 `n=6` 的声明，被解释为 `func(6)`；在 b.cpp 里因为看到 `=8` 的声明，被解释为 `func(8)`。这就是"缺省参数编译期匹配"带来的陷阱：**缺省值必须在所有能看到该函数调用的地方保持一致的声明**，否则会出现难以察觉的不一致行为。

### 3. 函数的调用过程（底层视角）

**是什么**：这一节是从汇编/栈帧的角度，展示一次函数调用在计算机内部到底发生了什么。虽然写业务代码时不需要手写汇编，但理解这个过程能帮你理解"值传递为什么会拷贝""调用约定为什么影响性能和兼容性"这些问题的根源。

**怎么用（以 `func(1,2,3)` 为例，理解整个流程）**：

1. **压参数入栈**：从右至左依次把 3、2、1 压入栈（`__cdecl` 的规则）。
2. **call 指令**：跳转到函数入口地址，同时把"返回地址"也压栈。
3. **记录调用现场**：在函数入口处，把 ebp、ebx、esi、edi 等寄存器的旧值压栈保存，然后 `mov ebp, esp` 建立新的栈帧基址。
4. **在栈中建立局部变量**：把参数（param1/2/3）从栈里取出，拷贝到局部变量 var1/2/3 中；此后定义的局部变量也在这块栈空间里分配。
5. **函数体执行、return**。
6. **恢复调用现场**：把之前保存的寄存器值依次弹出，恢复 ebp、esp 到调用前的状态。
7. **清栈**：把当初压入的参数从栈里清除掉——**清栈的动作由谁来做，是调用者还是被调用者，正是"调用约定"要规定的内容**（见下一节）。

**类比理解**：可以把栈想象成一摞叠起来的盘子（后进先出）。调用函数前，先把"要交代的事情"（参数）一个个叠上去；函数执行时，在这摞盘子上面接着叠自己的"草稿"（局部变量）；函数执行完，要把自己叠的草稿都撤掉，恢复到调用前的高度——这就是"清栈""恢复现场"。

### 4. 调用约定

**是什么**：调用约定（calling convention）规定了函数调用时"参数怎么传、栈由谁清、函数名怎么在编译后表示"这几件事的具体规则。C++ 支持多种调用约定，可以在声明时显式指定。

**为什么需要多种调用约定**：不同调用约定在效率、兼容性、是否支持变参函数上各有取舍。比如标准 C 库函数 `printf` 是变参的（参数个数不确定），只能用调用者清栈的方式（因为只有调用者知道到底传了几个参数）。

**怎么用（对照表）**：

| 调用约定 | 简要说明 | 清栈责任方 | 参数压栈顺序 | 函数名内部表示（示例） |
|---|---|---|---|---|
| `__cdecl` | 标准 C/C++ 调用约定 | 调用者 | 从右至左 | `_MyFuncName` |
| `__stdcall` | 新标准 C/C++ 调用约定 | 被调用者 | 从右至左 | `MyFuncName` |
| `__pascal` | PASCAL 风格调用 | 被调用者 | 从左到右 | `MYFUNCNAME` |
| `__fastcall` | 前两个参数尽量放寄存器 | 被调用者 | 从左到右(VC6.0) / 从右到左(BCB6.0) | `@MyFuncName` |
| `__thiscall` | 成员函数专用，this 放 ECX 寄存器 | 调用者 | 从右至左 | `_MyFuncNameXXX` |

**几个常见疑问的答案**：

- **为什么从右到左压栈？** 历史原因（早期 C 语言为了让变参函数如 printf 能正确找到第一个参数的位置而采用的约定，后来延续下来）。
- **谁负责清栈？** 记忆口诀：**能处理变参函数的（参数个数不固定），必须由调用者清栈**（因为只有调用者在编译时知道自己传了几个参数）；**只能处理确定参数个数的函数，可以由被调用者清栈**（省去每个调用点重复生成清栈代码，编译出的程序更小）。
- **函数名怎么表示？** 同一个项目内，函数名字加上参数信息重整后即可区分（见下节"名字重整"）；跨项目（比如调用别的编译器编译出的库）时，因为不同编译器的重整规则可能不一样，还需要额外处理（如 extern "C"）。

### 5. 函数重载

**是什么**：允许多个函数使用**相同的函数名**，只要它们的参数个数、参数类型、参数顺序、const 修饰、异常说明中至少有一项不同，就可以同时存在——这称为函数重载（overload）。

**为什么**：让语义相近的操作可以共用一个直观的名字（比如 `print(int)`、`print(string)`、`print(double)`），而不用起 `printInt`、`printString` 这种繁琐的名字，提升代码可读性。

**怎么用**：

```cpp
int func();
int func(int);
int func(int,int);
int func(int,int) const;                  // 只能是成员函数
int func(int) noexcept;                   // C++11起
int func(int) noexcept(false);
int func(MyClass obj);
```

**重载的判定规则（哪些能构成重载，哪些不能）**：

**❌ 不合法的"重载"（会被判重复定义）：**

```cpp
int fun();
void fun();          // 仅返回值不同
```

```cpp
int fun(int);
int fun(int&);        // 值传递 vs 引用传递
                       // ——注意，这一条其实是
                       // 合法的！见下方说明
```

```cpp
int fun(int);
int fun(int=5);        // 仅缺省参数不同
```

```cpp
int fun(int);
int fun(const int);    // 值类型的 const 修饰
                        // 不算区分标志
```

```cpp
int fun(int *);
int fun(int* const);   // 指针本身的 const
                        // 不算区分标志
```

**✅ 合法的重载：**

```cpp
void fun();
void fun() const;      // const成员函数

int fun1(int);
int fun1(int *);        // 值 vs 指针

int fun2(int&);
int fun2(const int&);   // 引用的const性不同
int fun2(int&) noexcept;

int fun3(int *);
int fun3(const int *);  // 指向的对象是否
                          // 可修改——可区分
int fun3(int*, int=6);
```

> ⚠️ 注意上表左侧的 `int fun(int); int fun(int&);` 其实是本 PPT 原文里的例子，但根据 C++ 标准，这两者是**不能同时重载**的（在只有值参数、没有其它区分点的情况下，编译器无法从调用点 `fun(x)` 判断你想调用哪个，会产生二义性错误）。请以老师课堂讲解或教材权威说法为准，做题时留意题目具体给出的语境。

**核心结论归纳**：

- 函数参数的**个数、类型、顺序**不同 → 可以重载
- **返回值类型**不同 → 不能作为区分标志（不能重载）
- **缺省参数**不同 → 不能作为区分标志（不能重载）
- 值类型参数的 **const 与非 const**（如 `int` vs `const int`）→ 不能作为区分标志
- **引用**和**指针**类型参数，如果 const 修饰不同、导致"是否可以改变实参"不同 → **可以**作为区分标志

**为什么"值类型的 const"不能区分，而"引用/指针的 const"可以区分**：用值传递时，形参是实参的一份拷贝，函数内部改不改这个拷贝，调用者根本看不见、也不关心，所以编译器在做重载决议时会把 `int` 和 `const int` 形参视为同一种参数类型。而引用和指针传递的是"能不能通过这个参数改到原始对象"，`const int&` 和 `int&` 在这一点上有本质区别（前者不能改，后者能改），所以可以用来区分重载版本。

### 6. 函数重载的实现——名字重整（Name Mangling）

**是什么**：编译器在编译阶段，会在函数的基本名字上，按照参数类型等信息拼接出一个独一无二的"内部名字"，用这个内部名字去区分参数不同的重载函数。

**举例**：`void fun(int)` 经过重整后，可能变成类似 `_fun_int` 这样的内部符号名（具体规则因编译器而异）。

**为什么需要理解这个机制**：这解释了"为什么函数重载在链接阶段依然能正确找到对应版本的函数"——本质上编译器把重载问题转化成了"起不同名字"的问题，链接器看到的从来都不是我们写的原始函数名，而是重整后的名字。

**缺点**：由于不同编译器的重整规则可能不同，一个用编译器 A 编译出的目标文件（.obj/.o），很难被编译器 B 正确识别其中的重整函数名——这是跨编译器 / 跨语言（如 C++ 调用 C 库）互操作性问题的根源之一。

**怎么解决跨语言调用问题：`extern "C"`**

`extern "C"` 告诉编译器："按 C 语言的规则来处理这些函数名，不要做 C++ 风格的名字重整。" 因为 C 语言不支持重载，一个函数名只能对应一个函数，所以 `extern "C"` 块内部**禁止写函数重载**：

```cpp
extern "C" {
    int func();
    int func(int);   // 非法！extern "C" 块内不允许重载
    int otherFun();
}
extern "C" void myFunc(int);
```

**类比理解**：可以把"名字重整"想象成学校里给同名同学编学号——比如两个都叫"张伟"的学生，学校内部用"张伟_2024001""张伟_2024002"来区分（对应重载函数）。但如果换了一套编号系统（不同编译器），别的学校根本不认识你这套编号规则，就没法对上号（跨编译器不兼容）。而 `extern "C"` 相当于说"这些人不用编号系统，就用姓名本身唯一标识"——前提是校内确实没有同名的人（不能重载）。

### 7. 函数的参数表

**是什么**：这一节区分了"声明中的参数表"和"定义中的参数表"两个概念，并说明了它们各自的书写规则。

**声明中的参数表（函数原型）**：

```cpp
void f();
int f(void);
int& f(int, int& var, const int&, const int *, char='a', int=1);
```

**定义中的参数表**：

```cpp
int f(int var, int)      // 注意：第二个参数没有起名字
{
    // ...
    return var;
}
```

**核心结论**：

1. **缺省参数应该写在函数原型（声明）中**；只有当函数根本没有单独的原型声明时，才允许直接在定义中给出缺省值。（原因见前面"函数的缺省参数"一节：缺省值是编译期从声明中匹配的，写在声明里能保证调用点在包含该声明的地方都能"看得到"缺省值。）
2. **定义中的形参可以不起名字**（如上例第二个参数），只要函数体内不需要用到它。这在只是为了"占位区分重载版本"、或参数在函数体内确实用不到时很常见。

### 8. 实参与形参的匹配

这一节讨论调用函数时，"你写的实参"是怎么和"函数期望的形参"对上号的，涉及好几个子问题。

#### 8.1 压栈顺序确定，但求值（计算）顺序不确定

**是什么**：调用约定规定了参数**压栈**的先后顺序（比如 `__cdecl` 是从右到左压栈），但这只是"往栈里放数据"的顺序，并不代表各个实参表达式的**求值顺序**也是确定的。C++ 标准并没有规定函数调用中多个实参表达式的求值先后顺序，这是**未定义行为的雷区之一**。

**举例（危险写法，应避免）**：

```cpp
int a = 10;
f(++a, ++a, ++a);              // 三个 ++a 的求值顺序不确定，结果因编译器而异
func(myF(a), yourF(a)+6);      // myF(a) 和 yourF(a) 谁先执行也不确定
```

**为什么要小心**：如果多个实参表达式之间存在副作用依赖（比如都在修改同一个变量 a），不同编译器/不同优化级别下可能得到不同结果。写代码时应避免这种"同一变量在同一次函数调用的多个实参里被反复修改"的写法。

#### 8.2 缺省参数的匹配规则

1. **在编译时匹配，而不是运行时**（前面已详细讲过原因）。
2. **第一个带缺省值的参数，右侧所有参数也必须都有缺省值**（不能中间空着不给）。

**❌ 非法：**

```cpp
void f(int, char='c', int);
```

**✅ 正确：**

```cpp
void f(int, char='c', int=9);
```

第一种写法非法的原因：`char` 有缺省值，但它右边的 `int` 却没有——一旦调用者省略了第三个参数，编译器无法确定是"只给了 int 的位置留空"还是别的情况，规则上直接禁止这种"中间断档"的写法。

#### 8.3 实参的类型转换

**是什么**：调用函数时，如果传入的实参类型和形参类型不完全一致，编译器会先尝试寻找**完全匹配**的重载版本；如果找不到，就会尝试做**隐式类型转换**，但**每个参数只允许转换一次**（不会做连续两次隐式转换的链式尝试）。

```cpp
void f(int);
void f(double);

f(2.5f);   // 实参是 float，两个重载都不是精确匹配
           // float -> double 是标准转换，会匹配到 f(double)
```

#### 8.4 值传递 / 指针传递 / 数组传递 / 引用传递

这四种传递方式，本质上都是在讨论"const 修饰在实参和形参之间如何匹配"，是这一节的重点和难点。

**① 值传递**：形参是实参的拷贝，因此 **const 与非 const 的实参都能传给 const 或非 const 的值类型形参**——因为反正是拷贝，改不改都不影响原对象。

```cpp
int a = 10;  const int b = 20;
My mObj;     const My cmObj;

void f(int, My);                       // 或 void f(const int, const My);

f(a, mObj);   // OK
f(b, mObj);   // OK —— const int 也能传给 int 形参（拷贝一份）
f(a, cmObj);  // OK
f(b, cmObj);  // OK
```

**② 指针传递**：规则是——**非 const 指针可以传给 const 指针形参（安全，只是"降级"了权限），但反过来不行**（const 指针不能传给非 const 指针形参，因为那样就绕过了 const 保护，可能通过形参改掉本不该改的对象）。

```cpp
int a = 10; My mObj;
int * pa = &a;         My * pmy = &mObj;
const int * cpa = pa;  const My * cpmy = pmy;

void f(int *, My *);                 // 版本(1)
void f(const int *, const My *);     // 版本(2)

f(pa, pmy);     // 对应(1) —— 普通指针精确匹配普通指针形参
f(pa, cpmy);    // 对应(2) —— 只要有一个实参是const指针，就只能匹配全const的版本
f(cpa, pmy);    // 对应(2)
f(cpa, cpmy);   // 对应(2)
```

**记忆窍门**：普通指针"够资格"传给要求更严格（const）的形参，但 const 指针"不够资格"传给要求更宽松（非 const）的形参——这跟现实中"高权限可以降级使用，低权限不能提权"是一个道理。

**③ 数组传递**：数组作为形参时，会**退化（decay）为指针**，因此下面这几种写法本质上是等价的：

```cpp
int a[3] = {1,2,3};

void f(int[]);
void f(int a[]);
void f(int a[3]);
void f(int a[5]);    // 即使写了数字，也不代表真的检查数组大小
void f(int * a);      // 与以上完全等价
```

**关键提醒**：数组形参里写的 `[3]`、`[5]` 这些数字**不会被编译器用来做任何长度检查**，它们全部会被当成 `int*` 处理。这是数组作为参数传递时最容易被误解的一点——**数组传参不带长度信息，函数内部无法知道数组实际大小**，通常需要额外传一个长度参数或使用别的容器（如 `std::vector`）来解决。

**④ 引用传递**：规则本质上和"值传递中的重载匹配"类似，但因为引用能反映"是否可修改原对象"，情况更复杂。下表列出了不同重载声明能接受哪些实参：

```cpp
int a = 1;
const int & b = a;
const int c = 2;
```

| 重载声明 | 能匹配的调用 |
|---|---|
| `void f(int, int);` | `f(a,a)`；`f(a,b)`；`f(a,c)`；`f(a,3)` |
| `void f(int&, int&);` | `f(a,a)`；`f(a,b)`；`f(a,c)`；`f(a,3)` |
| `void f(int, const int&);` | `f(a,a)`；`f(a,b)`；`f(a,c)`；`f(a,3)`；`f(b,3)` |
| `void f(int&, const int&);` | `f(a,a)`；`f(a,b)`；`f(a,c)`；`f(a,3)`；`f(b,b)` |
| `void f(const int&, const int&);` | `f(a,a)`；`f(a,b)`；`f(a,c)`；`f(a,3)`；`f(b,b)`；`f(3,3)` |

**如何理解这张表**：核心原则只有一条——**`const int&` 或按值传递的形参，几乎能接受任何东西（变量、常量、字面量、临时对象都行）；而非 const 的引用形参 `int&`，只能接受"左值"，且不能接受 const 对象或字面量常量**（因为一旦允许，就能通过引用悄悄改掉一个本应是常量的东西）。所以你会看到，只有当形参列表里同时出现非 const 引用位置时，才会出现"字面量 3、const 变量 b/c 不能传"的限制。

### 9. 函数的返回

**是什么**：函数返回值的方式，跟形参的传递方式是"对称"的，也分为按值返回、返回指针、返回引用三种，同样需要关注 const 属性的细节。

#### 9.1 按值返回

- `void`：不返回任何值。
- **内置类型（基本类型/导出类型）**：如果返回的是一个"普通的内置类型值"（不是引用、也不是指针），**这个返回值本身自动带有 const 属性**：

```cpp
unsigned int f();               // 等价于
const unsigned int f();
```

这个 const 主要影响的是——你不能对函数调用结果直接做类似 `f() = 5;` 或 `f()++;` 这样的赋值/自增操作（当然普通类型本来也很少有人这么写，这一点在自定义类型的返回值上更有实际意义，会在后续章节结合运算符重载展开讨论）。

- **自定义类型**：同样遵循这个思路，返回值是一个临时对象。

#### 9.2 返回指针

```cpp
T * f();     // 等价于 T * const f();
             // 但不等价于 const T * f();
```

**怎么理解这个"看似奇怪"的等价关系**：`T* const f()` 里的 const 修饰的是"返回的这个指针变量本身不能被重新赋值指向别处"，这本来就是函数返回值的默认属性（你确实不能对一个函数调用结果做 `f() = otherPointer;`），所以写不写这个 `const` 效果一样。而 `const T* f()` 里的 const 修饰的是"指针指向的内容不能被修改"，这是完全不同的语义，两者不能混为一谈。

#### 9.3 返回引用

```cpp
T & f();     // 不等价于 const T & f();
```

**核心规则**：

1. **`T&` 和 `const T&` 是两个不同的返回类型**，选哪个取决于你希不希望调用者能通过返回的引用修改内部数据。
2. **必须返回一个"有效对象"的引用**——即这个对象在函数返回之后依然存在。**绝对不能返回函数内部局部（非 static）变量的引用**，因为函数结束后局部变量已经被销毁，返回的引用会成为"悬空引用"，后续使用是未定义行为。

**举例（哪些能返回，哪些不能）**：

```cpp
int global = 100;                     // 全局变量
int & other(int &, const int &);

int & f(int a, int & b, const int & c) {
    int lVar = 88;                     // 局部临时量——生命周期随函数结束而结束
    static int sVar = 99;              // 局部静态量——生命周期贯穿整个程序运行期

    return a;              // ✅ a是形参，但本例中是值传递的int，返回其引用要小心——
                            //    这里等价于返回调用者传入的实参本身，是安全的
    return b;               // ✅ b是引用形参，指向调用者的真实对象，安全
    return c;               // ✅ 同理安全（虽然是const引用）
    return global;          // ✅ 全局变量，生命周期足够长，安全
    return global + 8;      // ⚠️ 这是一个临时值的引用，虽然能编译，但要清楚它绑定的是临时对象
    return lVar;             // ❌ 危险！lVar是局部变量，函数结束就销毁，返回的是悬空引用
    return sVar;             // ✅ sVar是static局部变量，生命周期不随函数结束而结束，安全
    return sVar + 2;         // ⚠️ 同"global+8"，是临时值
    return sVar += 3;        // ✅ 赋值表达式的结果是sVar本身（左值），安全
    return other(lVar, b);   // ❌ 危险！取决于other内部返回的是不是lVar的引用
    return other(sVar + 2, global);   // 需结合other的实现具体判断
}
```

**记忆窍门**：判断"能不能返回引用"，只需要问自己一句话——**"函数执行完之后，我引用的这个东西还在不在？"** 全局变量、static 局部变量、通过引用/指针从外部传进来的对象，函数结束后依然存在，可以放心返回引用；普通的局部变量（栈上分配、非 static），函数一结束就被销毁，绝对不能返回它的引用。

**返回引用的经典例子——max2 函数族**

这个例子集中展示了"返回类型不同，导致能否被赋值、行为完全不同"这一知识点：

```cpp
int max21(int a, int b)                          { return a>b?a:b; }
int& max22(int& a, int& b)                       { return a>b?a:b; }
const int& max23(int& a, int& b)                 { return a>b?a:b; }
const int& max24(const int& a, const int& b)     { return a>b?a:b; }
```

**调用方式 1（max21，按值返回）：**

```cpp
int a=3, b=4;
int m1 = max21(a,b);
cout<<a<<b<<m1;     // 344
```
行为：按值返回，m1是独立拷贝，和a、b无关

**调用方式 2（max22，返回非const引用）：**

```cpp
int m2 = max22(a,b);
cout<<a<<b<<m2;     // 344

max22(a,b) = 5;      // 合法！
                      // 因为max22返回的是非const引用
m2 = max22(a,b);
cout<<a<<b<<m2;     // 355
                      // b被改成了5，所以max22(a,b)现在是b(5)
```
行为：返回非const引用，函数调用结果**可以被当左值赋值**，直接改到了原始变量b上

**调用方式 3（max23，形参int&、返回const int&）：**

```cpp
int m3 = max23(a,10);  // ❌ 错误！
                          // 10是字面量（右值），
                          // 不能绑定非const引用形参int&
max23(a,b) = 6;          // ❌ 错误！
                          // 返回类型是const int&，
                          // 不能被赋值

int m3 = max23(a,b);
cout<<a<<b<<m3;         // 355
```
行为：形参是`int&`（不能传字面量），返回类型是`const int&`（不能被赋值）

**调用方式 4（max24，形参const int&、返回const int&）：**

```cpp
max24(a,b) = 7;   // ❌ 错误！同上，返回const引用不能赋值
int m4 = max24(a,b);
cout<<a<<b<<m4;   // 355
```
行为：形参是`const int&`（几乎什么都能传），返回类型是`const int&`（不能被赋值）

这个例子完整体现了本章的核心主线：**形参和返回值的 const 属性，决定了"什么样的实参能传进来"和"函数调用结果能不能被当左值使用"**——这也是后面学习运算符重载（比如 `operator[]` 要不要返回引用）时会反复用到的基础知识。

## 三、本章小结

1. **函数声明**只是给出函数的"签名"（名字+参数信息），返回类型和缺省参数值都不参与"区分函数身份"的判断。
2. **缺省参数是编译期静态匹配的**，必须写在函数原型（声明）里，且一旦某个参数有缺省值，它右侧的所有参数也必须都有缺省值；不同文件对同一函数写不同缺省值会导致行为不一致。
3. 一次函数调用的底层过程是：**压参数入栈 → 保存调用现场 → 建立局部变量 → 执行函数体 → 恢复调用现场 → 清栈**，其中"清栈由谁负责"由调用约定决定。
4. **调用约定**（`__cdecl`/`__stdcall`/`__pascal`/`__fastcall`/`__thiscall`）规定了压栈顺序、清栈责任方和函数名的内部修饰规则；能否处理变参函数，决定了必须由调用者还是可以由被调用者清栈。
5. **函数重载**要求参数的个数/类型/顺序/const修饰/异常说明中至少有一项不同；**返回值类型和缺省参数都不能作为重载的区分标志**；值类型形参的 const 属性不算区分标志，但引用/指针形参的 const 属性可以。
6. 重载的底层实现依赖**名字重整**，编译器把参数信息编码进内部函数名；`extern "C"` 会关闭名字重整，因此其内部**不能写函数重载**。
7. **参数的求值顺序是未定义的**（即便压栈顺序是确定的），避免在同一次调用的多个实参表达式中对同一变量做重复的副作用操作（如多个 `++a`）。
8. 实参与形参的**类型转换**遵循"先找精确匹配，找不到再尝试隐式转换，且每个参数只转换一次"的规则。
9. **值传递**中 const/非const 实参可以自由匹配；**指针/引用传递**中，非const可以"降级"传给const形参，但const不能"升级"传给非const形参；**数组传参会退化为指针**，不带长度信息，写在方括号里的数字不做检查。
10. **按值返回**内置类型时结果自动带 const；**返回指针** `T* f()` 等价于 `T* const f()`，但不等价于 `const T* f()`；**返回引用**必须保证被引用对象在函数结束后依然存在（不能返回非static局部变量的引用），且 `T&` 与 `const T&` 决定了返回值能否被当作左值赋值。
