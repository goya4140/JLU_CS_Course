## 二、核心考点表

### 1. 静态编联 vs 动态编联 ★★★

| | 静态编联 | 动态编联 |
|---|---|---|
| 决定时机 | 编译期 | 运行期 |
| 依据 | 静态类型（声明类型） | 动态类型（实际对象类型） |
| 触发条件 | 默认所有函数调用 | `virtual` 函数 + 通过指针/引用调用 |

- 对象型（值类型）变量：静态类型=动态类型永远一致（对象切割）
- 指针型/引用型：可以不同，这是动态编联发挥作用的前提

### 2. 虚函数使用规则 ★★★

| 能是虚函数 | 不能是虚函数 |
|---|---|
| 普通成员函数 | 静态成员函数 |
| 析构函数（且推荐显式声明为虚） | 构造函数 / 拷贝构造函数 |
| 带 const 或不带 const 均可 | —— |
| 访问权限 public/protected/private 均合法（但不推荐 private） | —— |
| 赋值函数（operator=）**通常不建议**定义为虚的 | |

**派生类中虚函数三种情况**：继承（不重写）/ 新增（子类专属）/ override（重写，函数名相同，返回类型需相同或协变，virtual 可省略）。
⚠️ 参数列表不同 → 不是 override，是**隐藏**基类全部同名重载函数。

### 3. 虚函数表 & vptr ★★★

| 要点 | 结论 |
|---|---|
| 生成条件 | 类中至少 1 个虚函数才有 vtable |
| 归属 | vtable 属于**类**（同类对象共享，仅一张）；vptr 属于**对象**（每个对象一份） |
| 创建时机 | 首次创建该类对象时生成 vtable |
| 表内容 | 按函数顺序存函数入口地址；派生类新增虚函数追加在末尾，override 则替换原位置地址 |

### 4. p->func() 编译规则（核心原理）★★★

```
1. 确定 p 的静态类型（如 A*）
2. 在 A 类中找名为 func、参数匹配的函数
3. 找不到 → 编译错误
4. 找到了：
   - 非虚函数 → 编译成 p->A::func()（静态编联）
   - 虚函数   → 编译成 (*p->vptr)[index]((void*)p, ...)（动态编联）
```

**★★★ 铁律**：能否编译通过 = 只看**静态类型**里有没有匹配函数；调用哪个版本 = 才看是否 virtual。即使子类新增了 f1()，`A* p2 = new B; p2->f1();` 依然**编译错误**（A 类没有 f1）。

### 5. 虚函数的访问规则 ★★★（高频易混）

| 场景 | 编联方式 |
|---|---|
| 虚函数中调非虚函数 | 静态编联 |
| 非虚函数中调虚函数 | 动态编联 |
| 虚函数中调虚函数 | 动态编联 |
| **构造函数中调虚函数** | **静态编联**（本地/当前构造层版本） |
| **析构函数中调虚函数** | **静态编联**（本地/当前析构层版本） |
| **私有虚函数** | **依然动态编联**（不受访问权限影响，C++特有） |

**记忆**：构造是"从基类往子类建"，析构是"从子类往基类拆"，无论哪个阶段，未完成/已销毁的那部分不能被访问，所以只能调用"当前所在类"的本地版本。

### 6. 具体类 & 抽象类 & 接口类

| 概念 | 要点 |
|---|---|
| 具体类 | 可实例化 |
| 抽象类 | 含 ≥1 个纯虚函数，不可实例化，派生类实现全部纯虚函数后才可实例化 |
| 纯虚函数 | `virtual 返回类型 func(...) [const] = 0;` 必须是成员函数、必须虚、访问权限任意 |
| 纯虚定义 | 纯虚函数也可以有函数体（提供部分实现/范本），子类仍**必须重写**，可用`基类::func()`复用 |
| 接口类 | 纯抽象类：除虚析构外全是纯虚函数，通常**无非静态数据成员**，成员多为 public |

父类子类合法性：具体类/抽象类互相都可以作为对方的父类或子类（抽象类的子类可仍是抽象类；具体类的子类可再变抽象类）。

### 7. RTTI ★★★

**typeid(exp)**：返回 const type_info 对象

| exp 形式 | 返回类型判据 |
|---|---|
| 指针 | 静态类型（不看指向对象真实类型） |
| 对象/引用 + 含虚函数 | 动态类型（真实类型） |

**dynamic_cast<T>(exp)**：要求基类至少 1 个虚函数

| T 形式 | 失败表现 |
|---|---|
| 指针 | 返回 `nullptr`（需判空再用） |
| 引用 | 抛 `bad_cast` 异常 |

## 三、最佳实践 8 条速记

| 编号 | 规范 | 一句话原因 |
|---|---|---|
| 1 | 子类需不同实现→虚函数；通用实现→非虚函数 | 虚函数=接口，非虚=接口+实现 |
| 2 | 重写虚函数加 `override` | 编译器自动核对函数名/参数/返回类型，防止"重写成新增" |
| 3 | 不要重定义父类非虚函数 | 非虚走静态编联，会导致基类指针与子类对象调用结果不一致 |
| 4 | 类被继承且可能被基类指针 delete → 析构函数显式声明为虚 | 否则子类部分资源不会被释放 |
| 5 | 不要定义私有虚函数 | 虽然仍能动态分派，但隐藏了"这是可重写接口"的语义，易误解 |
| 6 | 不要重载虚函数（同名不同参数） | 子类重写其中一个会**隐藏**其余重载版本，易致编译错误 |
| 7 | 不要定义虚的赋值函数（operator=） | 类型不安全，易发生对象切割赋值等诡异行为 |
| 8 | 优先使用抽象类/接口类 | 抽象层次更高更稳定；接口类无数据成员，避免多继承命名冲突 |
