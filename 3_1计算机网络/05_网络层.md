## 5.1 网络层基本原理

### 5.1.1 数据报与虚电路

网络层统一寻址，路由选择产生路径信息，转发对具体分组选择出口。

| 方式 | 发送前 | 分组转发依据 | 中间状态 |
| --- | --- | --- | --- |
| 数据报 | 不建立持续的网络层连接 | 每份分组的目的地址 | 路由/转发表等 |
| 虚电路 | 先建立或预配置逻辑路径 | 虚电路标识 | 连接对应的映射 |

IP采用无连接、**尽力而为**的数据报服务：尝试交付，但不保证必达、按序、无重复或固定延迟。需要可靠交付时，由TCP等上层机制补充。

“无连接”不表示没有线缆；虚电路也不表示必然可靠或独占物理链路。

### 5.1.2 路由器怎样处理一跳

```text
收帧 → 去链路封装 → 检查IP → 查转发表 → 确定下一跳 → 重新封装帧
```

二层交换机主要按MAC转发，路由器按IP前缀转发。三层交换机也可执行路由，不能只看设备名字判断职责。

同子网通常直接给目标主机；不同子网通常交给网关。**默认网关是下一跳，不是最终目标**：发往校外服务器的包，IP目的地址仍指向服务器，链路目的地址才指向当前网关。

“网关”还可指应用协议转换设备，具体含义依上下文而定。

### 5.1.3 路由选择的分类与目标

**度量**是比较路径的代价，例如跳数、链路成本或时延。“最短”指所选度量总成本最小，不一定地理最近。

| 分类维度 | 类型 |
| --- | --- |
| 如何配置 | 静态：人工配置；动态：交换信息适应变化 |
| 信息怎样组织 | 距离向量：依赖邻居距离；链路状态：获得拓扑信息 |
| 决策放在哪里 | 集中式：一个逻辑中心；分布式：多个设备协作 |

算法还要考虑正确、稳定、公平、计算和通信开销。**收敛**是拓扑变化后，各设备逐步形成相容的新路由；收敛期间可能出现暂时不一致。

### 5.1.4 距离向量与RIP

**距离向量**告诉邻居：“我到各目的有多远”。本机加上到邻居的代价，再选择最小值：

$$D_x(y)=\min_v\{c(x,v)+D_v(y)\}$$

x是本机，y是目的，v是邻居；c是到邻居的链路代价，D_v(y)是邻居通告的距离。

**理解例子：**A—B成本1，B—C成本2，A—C成本7。B通告到C为2，A算出经B总成本1+2=3，因此优于直连的7，下一跳选B。

但如果B—C断了，B误信A尚未更新的旧通告，A、B可能互相认为对方能到C，形成环路并不断增加距离，叫**计数到无穷**。

RIP是距离向量协议，用跳数作为度量，16表示不可达，最多15个有效跳。

- **水平分割**：不向学到路由的方向再通告同一路由。
- **毒性逆转**：向该方向明确通告该目的不可达。
- **触发更新**：变化后及时通告，不只等周期。

这些减少部分环路问题，不能保证消除所有瞬态环路。计算多轮表时，还要说明每轮统一用上一轮表，还是立即采用新结果。

### 5.1.5 链路状态与Dijkstra

**链路状态**告诉网络：“我连接哪些邻居，各链路成本是多少”。通告经**泛洪**传播，让各路由器建立拓扑数据库，再独立算最短路径。

泛洪要用序列号、老化与重复检测控制，不能让旧通告无限复制。OSPF的周期刷新与故障触发更新不同，不能因为刷新周期长就认为故障也要等那么久。

**Dijkstra算法**适用于非负链路代价：每次选暂定距离最小、尚未确定的结点，再检查经它是否能缩短邻居距离，这一步叫**松弛**。

理解例子：无向图A—B=2，A—C=5，B—C=1，B—D=4，C—D=1。

| 操作 | 已确定结点 | B距离 | C距离 | D距离 |
| --- | --- | --- | --- | --- |
| 从A开始 | A | 2 | 5 | ∞ |
| 选B | A、B | 2 | 3 | 6 |
| 选C | A、B、C | 2 | 3 | 4 |
| 选D | A、B、C、D | 2 | 3 | 4 |

到D路径为A—B—C—D，代价4；转发表只需说明下一跳B，不让包携带整棵最短路径树。本例明确给出边权，不冒充尚未完整核验原图的课件题答案。

### 5.1.6 拥塞与反馈控制

**拥塞**是网络输入超过传输或处理能力，队列、时延与丢包增长。缓存能吸收短时突发，不能永久解决持续超载。

**开环控制**提前预防，如准入、预留、整形；**闭环控制**检测拥塞后反馈调整发送。

| 方法 | 怎样工作 |
| --- | --- |
| 准入控制 | 在新业务进入前检查容量 |
| Drop Tail，尾部丢弃 | 队列满时丢弃新到分组 |
| RED，随机早期检测 | 根据平均队列长度提前概率丢弃或标记 |
| 反馈控制 | 通过状态反馈让源端减速 |

流量控制保护接收端，拥塞控制保护网络，两者可能都限制发送量，但原因不同。

课件“抑制分组”用于讲历史反馈思想。ICMP Source Quench已被规范废弃，不作为应启用的现代控制方法。[RFC 6633](https://www.rfc-editor.org/rfc/rfc6633.html)

### 5.1.7 死锁

**死锁**是一组实体互相等待被对方占用的资源，无法继续。

例如A的缓冲存着要给B的包，B的缓冲存着要给A的包，双方都没有空间先接收。间接等待还可形成A→B→C→A的环。

分片重组也可能出现缓冲被多个不完整报文占满，而补齐任一报文的后续片段都进不来的问题。合理分配、限制占用、超时释放等方法可破坏等待条件。

拥塞通常还有数据缓慢前进，死锁则可能持续停住。“再加一点缓冲”不是通用的正确性证明。

### 5.1.8 QoS、整形与调度

**QoS，服务质量**关注带宽、时延、丢包和**抖动**，即分组延迟的变化。语音可能能容忍少量损失，却对延迟与抖动敏感；文件传输更重完整性。

**整形**控制数据进入网络的节奏；**调度**决定多个等待队列谁先发。

| 方法 | 通俗解释 | 特点 |
| --- | --- | --- |
| 漏桶 | 像固定速率排水 | 平滑输出，过量到达需排队或丢弃 |
| 令牌桶 | 按速率生成发送许可，允许积累 | 长期受限，允许受控突发 |
| 严格优先级调度 | 总先服务高优先队列 | 低优先级可能长期得不到服务 |
| 轮询或加权调度 | 轮流按份额服务 | 分配服务机会 |

令牌桶每秒生成r个令牌，最多积累b个；若每字节消耗一个令牌，时间t内允许流量满足：

$$A(t)\le b+rt$$

r用B/s、b用B、t用s。理解例子：r=1 MB/s、b=2 MB，桶满时可允许约2 MB突发，但物理发送仍需要时间。

**IntServ**强调逐流资源管理和预留；**DiffServ**在边缘分类、标记，在内部按类别处理。优先级标记不能凭空创造带宽，也不自动保证跨所有网络的端到端质量。

## 5.2 IPv4协议

### 5.2.1 地址与前缀

IPv4地址32位，分成4个8位组，以点分十进制表示，每组0～255。

`192.168.1.10/24`中的**前缀长度/24**表示前24位为网络部分，后8位为主机部分。分类地址A/B/C是历史组织方式，显式给出前缀时必须按前缀判断。

| 历史类别 | 首字节范围 | 默认前缀或用途 |
| --- | --- | --- |
| A | 0～127，0和127另有用途 | /8 |
| B | 128～191 | /16 |
| C | 192～223 | /24 |
| D | 224～239 | 多播 |
| E | 240～255 | 保留分类，另有特殊地址用途 |

课件E类写240～247不完整。32位有2³²种编码，不意味着都能分给普通主机。

| 特殊地址或范围 | 含义 |
| --- | --- |
| 0.0.0.0 | 未指定地址；不同于默认路由0.0.0.0/0 |
| 127.0.0.0/8 | 环回，数据留在本机；常用127.0.0.1 |
| 255.255.255.255 | 本地受限广播 |
| 10.0.0.0/8 | 私有地址 |
| 172.16.0.0/12 | 私有地址，仅172.16～172.31 |
| 192.168.0.0/16 | 私有地址 |

私有地址可在不同组织内部重复使用，不作为全球公共路由地址；公网地址也不自动表示服务可达或安全。

### 5.2.2 子网掩码与地址计算

**子网掩码**用连续1指出前缀位置，剩余0指出主机位。网络地址=IP与掩码逐位**相与AND**，即两位都为1时才得1。

普通子网中，主机位全0为网络地址，全1为广播地址。有h个主机位，总地址数2ʰ，常规可分配主机数2ʰ−2；/31点到点和/32主机路由需要单独理解。

**课件例题：**192.168.150.122，掩码255.255.255.248。

```text
248 = 11111000，所以前缀/29，主机位3
122 = 01111010
248 = 11111000
AND = 01111000 = 120
```

结果：网络192.168.150.120，广播.127，可用.121～.126，共6个。

快速算法：最后一字节块大小`256−248=8`，122落在120～127这一块。遇到跨字节前缀，要对实际变化字节计算，不能总看最后字节。

202.198.50.10/25与.140/25分别属于0～127和128～255两块；前24位相同不意味着同子网。

### 5.2.3 CIDR、VLSM与聚合

**CIDR，无类别域间路由**用“地址/前缀”表示地址块，摆脱A/B/C固定边界。**VLSM，可变长子网掩码**按不同容量给子网分配不同前缀。

前缀越长，块越小；划子网通常延长前缀，聚合则把多个连续块用较短前缀概括。

| 课件地址块 | 掩码或范围 |
| --- | --- |
| 88.166.0.1/19 | 掩码255.255.224.0 |
| 10.0.0.0/10 | 掩码255.192.0.0 |
| 128.14.32.0/20 | 32.0～47.255，共4096个地址 |
| 128.123.1.8/28所在块 | 128.123.1.0～.15 |

课件188.66.100.0/22覆盖第三字节100～103，可按大块优先划为：

| 子网 | 地址范围 | 常规可用主机 |
| --- | --- | --- |
| 188.66.100.0/23 | 100.0～101.255 | 510 |
| 188.66.102.0/24 | 102.0～102.255 | 254 |
| 188.66.103.0/25 | 103.0～103.127 | 126 |
| 188.66.103.128/25 | 103.128～103.255 | 126 |

最后一块可保留。块起点必须对齐：例如/23的第三字节起点应为偶数，不能从101.0开始定义一个新的/23块。

精确聚合需要连续、二的幂大小、正确对齐。`192.0.2.0/25`与`192.0.2.128/25`恰好合为`192.0.2.0/24`。较宽聚合若包含无实际可达性的部分，要有相应处理策略，不能仅因地址接近就随意合并。

### 5.2.4 DHCP与租约

**DHCP**自动提供地址、掩码、网关、DNS等参数。IPv4服务器用UDP 67端口，客户端用UDP 68。

```text
Discover：客户端寻找服务器
Offer：服务器提供候选地址
Request：客户端表明选中的配置
ACK：服务器确认租约与参数
```

初始客户端没可用IP，通过广播发现服务器。多个服务器可响应，客户端不被协议强制要求选择第一个。跨广播域要配置**中继代理**，路由器不会默认把所有广播转发过去。

**租约**是地址允许使用的时间。按常用默认，约租期一半T1时找原服务器续租，约0.875T的T2时扩大寻找；实际定时可由服务器指定。到期未续租必须停止使用该租约地址。NAK表示原配置不能继续使用，Release用于主动释放。

| 报文字段 | 作用 |
| --- | --- |
| op、htype、hlen、hops | 消息方向、硬件类型/长度、中继跳数 |
| xid | 事务标识，用于匹配同一轮交换 |
| secs、flags | 已经历时间及广播等标志 |
| ciaddr、yiaddr | 已有地址、给客户端提供的地址 |
| siaddr、giaddr | 引导服务器地址、中继地址 |
| chaddr | 客户端硬件地址区域 |
| sname、file | 服务器名、引导文件名区域 |
| options | 消息类型、租期等可变参数 |

固定部分236 B，后接识别标记和选项，不能把图中的选项长度当作所有报文固定值。

### 5.2.5 NAT与NAPT

**NAT**改写IP地址；**NAPT**同时处理地址和端口，允许多台内网主机共享一个公网地址。

理解例子：内网`192.168.1.10:50000`访问`198.51.100.20:443`，网关改成公网源`203.0.113.5:40001`并记录映射。响应回来时，再把该目的还原给内网主机。这些公网形式地址用于文档示例。

静态地址/端口映射可把外部访问转给内部服务。改写要更新相关校验和；它增加状态并改变端到端可达性，不能当作完整的安全机制。

第125页文字与图的转换后源地址不一致，采用“外发源映射为外部地址”的原理解释，不猜哪一处才是教师原意。

### 5.2.6 IPv4首部

基本首部20 B，有选项时最多60 B。**IHL**以4 B为单位，值5表示20 B；总长度包含首部与载荷。

| 字段 | 位数 | 解释 |
| --- | --- | --- |
| Version、IHL | 4、4 | 版本4，首部长度 |
| DS字段 | 8 | 服务类别与拥塞通知相关，旧称服务类型 |
| Total Length | 16 | 整个IP包字节数 |
| Identification | 16 | 标识同一原包的分片 |
| Flags、Fragment Offset | 3、13 | 分片控制、偏移 |
| TTL、Protocol | 8、8 | 跳数限制、上层协议 |
| Header Checksum | 16 | 只检查首部的反码校验和 |
| 源、目的地址 | 各32 | 两端IPv4地址 |
| Options、Padding | 可变 | 可选信息与4 B对齐填充 |

16位总长最大值是65535 B，不是65536 B。无选项、总长1000 B时，载荷980 B。[RFC 791](https://www.rfc-editor.org/rfc/rfc791.html)

TTL每次路由转发递减，耗尽就丢弃并按条件返回超时消息；在通常处理中是跳数限制，不是毫秒计时。Protocol常见TCP=6、UDP=17、ICMP=1。

校验和计算前将该字段置零，修改TTL后也要更新。它不覆盖IP载荷，算法见[第二章反码校验和](02_数据通信基础.md#sec25)。记录路由、时间戳、源路由等选项表示格式能力，不等于所有网络允许使用。

### 5.2.7 分片：先分清首部与载荷

**MTU，最大传输单元**表示出口链路一次能承载的网络层数据单元上限。IPv4包超过出口MTU且允许分片时，可以拆成多个各带首部的分片。

- **DF**：禁止分片。
- **MF**：后面还有原报文的分片。
- **片偏移**：相对原始载荷起点的位置，单位8 B。

非最后一片载荷必须为8的倍数。重组在最终目的端完成，中间路由器一般不先重组再转发。

**课件例题：**总长3820 B，首部20 B，MTU=1420 B。

```text
原载荷 = 3820−20 = 3800 B
非末片最大载荷 = floor((1420−20)/8)×8 = 1400 B
floor表示向下取整。
```

| 分片 | 原载荷字节区间，从0计 | 载荷 | 总长 | 片偏移 | MF |
| --- | --- | --- | --- | --- | --- |
| 1 | 0～1399 | 1400 B | 1420 B | 0 | 1 |
| 2 | 1400～2799 | 1400 B | 1420 B | 175 | 1 |
| 3 | 2800～3799 | 1000 B | 1020 B | 350 | 0 |

偏移175表示从原载荷第1400字节开始。三片载荷仍合计3800 B，但三份首部使总发送长度增加。

若第2片再遇MTU=820 B，载荷拆成800+600 B：

| 再分片 | 载荷 | 总长 | 相对原包的偏移 | MF |
| --- | --- | --- | --- | --- |
| 2a | 800 B | 820 B | 175 | 1 |
| 2b | 600 B | 620 B | 275 | 1 |

2b的MF仍为1，因为原包后面还有第3片；偏移不能重新归零。各片保留相应原包标识。课件第137页的3280与前页3820矛盾，本文明确按3820计算。

DF=1却过大时不能分片，按条件报告“需要分片”，帮助源端发现路径MTU。最后一片不必补齐8 B倍数。

### 5.2.8 最长前缀匹配

目的地址可以同时匹配多条路由，选择**前缀最长**、范围最具体的一条。默认路由/0在没有更具体匹配时才使用。

课件目标192.168.3.2：

| 表项 | 下一跳 | 匹配情况 |
| --- | --- | --- |
| 192.168.0.0/16 | 10.1.1.2 | 匹配 |
| 192.168.2.0/24 | 20.1.1.2 | 不匹配 |
| 192.168.3.0/24 | 30.1.1.2 | 匹配且更长 |

选30.1.1.2。课件“只匹配一条”不准确，正确理由是/24优先于/16。

度量等策略主要用于同一前缀的候选路由选择，不能直接用较小跳数替代最长前缀规则。查出出口后，还需得到本地下一跳的链路地址。

### 5.2.9 ARP与逐跳MAC

**ARP**在本地链路解析IPv4地址对应的MAC，通常广播请求、单播回答，结果可缓存。它直接由以太网帧承载，不装在IP包内。

以太网/IPv4的ARP内容28 B：硬件类型2 B、协议类型2 B、两种地址长度各1 B、操作码2 B、发送方MAC/IP 6+4 B、目标MAC/IP 6+4 B。请求操作码1，回答2。

理解例子：A=192.168.1.10/24发给192.168.2.20，网关192.168.1.1。

1. A按掩码判断目标不在本子网。
2. A查询网关MAC，必要时广播ARP请求。
3. 网关回复MAC。
4. A发帧：目的MAC是网关，目的IP仍是192.168.2.20。
5. 网关在下一链路按新的下一跳再次封装。

主机到主机、主机到路由器、路由器到主机、路由器到路由器，都遵循**解析当前出口链路的下一跳**这一规则。缓存可能过期，不能把每条记录视为永久绑定。

### 5.2.10 ICMP、ping与traceroute

**ICMP**传递IP差错或诊断消息，由IP承载。起始字段Type、Code、Checksum分别8、8、16位，其余随类型变化。

| IPv4类型 | 值 | 作用 |
| --- | --- | --- |
| 回显请求、回答 | 8、0 | ping常用，观察往返可达性 |
| 目的不可达 | 3 | Code进一步说明原因 |
| 重定向 | 5 | 提示更合适下一跳，受配置限制 |
| 超时 | 11 | TTL耗尽或重组超时 |
| 参数问题 | 12 | 报告首部问题 |

**traceroute**依次用TTL=1、2、3……探测，观察各跳超时响应。探测可用UDP、ICMP或TCP，依实现不同。

某跳不回答可能是过滤或回程原因，不能确定该跳断网；ping成功也不能证明目标Web服务正常。时间戳、地址掩码等是课件列出的历史类型，不代表所有现代网络都在使用。

### 5.2.11 IPv4多播与IGMP

**多播**向一组接收者传数据，组地址范围224.0.0.0/4。**IGMP**管理本地链路成员资格，路由器之间怎样分发则由多播路由机制处理。

IPv4多播映射到以太网：固定前缀`01:00:5e`加组地址低23位。课件的`6e`为笔误。

**课件例子：**225.128.47.81的低23位为00:2f:51，所以MAC为`01:00:5e:00:2f:51`。28位组地址部分只取23位，会有32个IP组地址映射到同一MAC，接收方还要在IP层筛选。[RFC 1112](https://www.rfc-editor.org/rfc/rfc1112.html)

课件重点IGMPv1：8 B报文，包含版本、类型、校验和、组地址等。路由器查询，成员随机延后报告；听到同组报告可抑制自己的报告。v1靠查询超时判断离组，不代表全部版本都没有离组消息。

IGMP的IP协议号为2，但多播业务数据仍可用UDP等协议，不能把所有多播数据都当作IGMP。

## 5.3 IPv6协议

### 5.3.1 基本首部与扩展首部

IPv6地址128位，基本首部固定40 B，不含IPv4式首部校验和。**扩展首部**把额外功能放在基本首部之后，通过Next Header串起来。

| 字段 | 位数 | 作用 |
| --- | --- | --- |
| Version | 4 | 值为6 |
| Traffic Class | 8 | 流量类别 |
| Flow Label | 20 | 流标识 |
| Payload Length | 16 | 基本首部之后的字节数，普通情况包含扩展首部 |
| Next Header | 8 | 指出紧跟的首部类型 |
| Hop Limit | 8 | 跳数限制 |
| 源、目的地址 | 各128 | IPv6通信地址 |

```text
IPv6基本首部 → 路由扩展首部 → 分片扩展首部 → UDP
每一段用Next Header指出下一段。
```

常见编号：逐跳选项0，路由43，分片44，ESP 50，AH 51，目的选项60，TCP 6，UDP 17。ESP、AH是IP安全相关首部，本章先辨认名称与位置。

扩展首部的长度规则并不统一：部分选项首部以8 B为单位表示额外长度，分片首部固定8 B，不应套用一张图的规则解释全部。

**IPv6路由器不分片，必要分片由源端执行。**过大的包会按条件触发“Packet Too Big”反馈，帮助源端调整大小。[RFC 8200](https://datatracker.ietf.org/doc/html/rfc8200)

### 5.3.2 地址表示与零压缩

地址一般写成8组十六进制数，每组16位。两条基本缩写规则：

1. 组内前导零可省略。
2. 一段连续零组可用`::`省略，一处地址最多一次。

理解例子：

```text
2001:0db8:0000:0000:0008:0800:200c:417a
2001:db8:0:0:8:800:200c:417a
2001:db8::8:800:200c:417a
```

展开时已有6组，`::`补2组。若用两处`::`，无法知道各省了几组，所以非法。

规范输出推荐小写、压缩最长零串、平局选最左，不用`::`压缩单个零组。**合法写法与推荐的规范写法不同。**[RFC 5952](https://www.rfc-editor.org/rfc/rfc5952)

### 5.3.3 地址类型

| 类型 | 指向谁 |
| --- | --- |
| 单播 | 一个接口 |
| 任播 | 一组接口中的一个，按路由规则选择 |
| 多播 | 一组接收接口 |

IPv6没有广播。任播的“最近”按路由意义判断，不保证地理最近，也没有与单播完全独立的外观。

| 地址或范围 | 用途 |
| --- | --- |
| `::` | 未指定地址 |
| `::1` | 环回 |
| `fe80::/10` | 链路本地，局限于相应链路 |
| `fc00::/7` | 唯一本地地址范围，常见本地生成形式从fd开始 |
| `2000::/3` | 课件介绍的常见全球单播范围 |
| `ff00::/8` | 多播，包含作用域等信息 |

URL写IPv6并带端口时用方括号，如`http://[2001:db8::1]:8080/`，避免地址中的冒号与端口分隔混淆。

### 5.3.4 NDP、SLAAC与接口标识

**NDP，邻居发现协议**用ICMPv6进行邻居解析、路由器发现、重复地址检测等；IPv6不使用IPv4的ARP。

| 消息 | 类型 | 做什么 |
| --- | --- | --- |
| RS | 133 | 请求路由器通告 |
| RA | 134 | 发布前缀、默认路由等信息 |
| NS | 135 | 邻居请求，解析或检测地址 |
| NA | 136 | 邻居通告，提供相应反馈 |

**SLAAC，无状态地址自动配置**让主机按RA中的前缀和规则生成地址，不必逐个租用服务器地址。课件的SLACC应写SLAAC。默认路由器信息来自RA，不是从自己的地址推算。

**接口标识**是地址中用于识别接口的部分。修改EUI-64是课件介绍的一种生成办法，不是全部系统必须采用的方法。

课件MAC为`08-70-5a-90-1a-01`：

```text
插入ff-fe：08-70-5a-ff-fe-90-1a-01
翻转首字节U/L位：08 XOR 02 = 0a
接口标识：0a70:5aff:fe90:1a01
```

不能把整个首字节取反；隐私等机制可使用其他标识生成方式。

### 5.3.5 被请求节点地址与DAD

为解析邻居，主机使用目标地址低24位构造**被请求节点多播地址**：加到`ff02::1:ff00:0/104`之后。

理解例子：目标末尾为`1234:5678`，低24位是34:56:78，得到`ff02::1:ff34:5678`；以太网多播地址对应`33:33:ff:34:56:78`。

**DAD，重复地址检测**在正式使用新地址前检查是否冲突，可用源地址`::`发NS。没有冲突反馈后按规则启用，但故障导致的无响应不能证明任何环境下绝对无冲突。

IPv6组成员管理用MLD，即多播侦听发现，与IPv4的IGMP区分。

### 5.3.6 IPv4与IPv6过渡

| 方法 | 做什么 | 关键区别 |
| --- | --- | --- |
| 双栈 | 同时支持IPv4、IPv6 | 选择相应协议通信 |
| 隧道 | 给原包再加外层封装 | 中间网络只处理外层，出口去掉 |
| 协议转换 | 转换地址与协议表示 | 改变协议语义，可能需映射状态 |

NAT64可让IPv6客户端访问IPv4服务；DNS64可合成相应IPv6地址帮助访问。能否支持反向主动连接依具体映射与配置，不能一概说任意双向互通。

隧道里的IPv6包没有变成IPv4语义的包，只是装在IPv4外层中传。额外首部还会影响MTU。

## 5.4 互联网路由

### 5.4.1 AS、IGP与域间路由

**AS，自治系统**是一组采用统一管理与路由策略的网络。一个运营商或大型组织可按需要组织AS，不能只凭公司名字判断数量。

**IGP**是域内路由协议，主要在AS内工作；域间路由处理AS之间的可达性和策略。

| 协议 | 方法 | 本课重点 |
| --- | --- | --- |
| RIP | 距离向量 | 跳数、16不可达、邻居更新 |
| OSPF | 链路状态 | 拓扑数据库、最短路径、区域 |
| BGP | 路径向量 | AS路径与策略，使用TCP 179 |

### 5.4.2 OSPF与区域

OSPF用Hello发现邻居，通过数据库描述、链路状态请求、更新和确认交换信息，再算最短路径。

**区域**把大型网络的路由信息组织成多个部分，减少各处需要维护的规模；骨干区域是Area 0。链路成本可与带宽有关，但参考值可配置，不是固定的历史默认数值。

周期刷新是维护信息有效性，拓扑变化也能触发通告。多条等代价路径可以参与转发，具体认证和策略依配置而定。

### 5.4.3 BGP与路径向量

BGP通告可达前缀以及路径属性。**AS_PATH**记录所经过的AS，看到自己的AS可识别相应环路。

BGP会考虑管理和商业策略，不能仅用“跳数最少”解释所有选路。TCP负责消息可靠传输，不保证通告本身在业务策略上正确。

公共首部19 B：Marker 16 B、Length 2 B、Type 1 B。

| 消息 | 作用 |
| --- | --- |
| OPEN | 建立会话参数 |
| UPDATE | 发布或撤销路由 |
| KEEPALIVE | 维持会话 |
| NOTIFICATION | 报告差错并结束 |
| 路由刷新扩展 | 请求重新通告相应信息 |

### 5.4.4 路由器内部结构

**控制平面**运行路由协议、计算并维护转发信息；**数据平面**按照已有规则快速转发实际分组。

```text
输入端口 → 交换结构 → 输出端口
接收、查表    内部搬运    排队、调度、发送
```

交换结构可基于内存、总线或交叉开关。多个输入争同一个出口时仍要排队，即使内部很快也不能提高该出口容量。

**队首阻塞**指队首分组等待繁忙出口，挡住后面本可送往空闲出口的分组。路由表可含较多控制信息，转发表可为快速查询另行组织。

## 5.5 软件定义网络

### 5.5.1 SDN的控制与转发分离

**SDN**让控制逻辑通过可编程接口管理转发设备。控制器具有逻辑上的集中视角，物理上可由多个节点实现。

- **北向接口**：应用向控制系统描述需求或策略。
- **南向接口**：控制系统向设备下发规则、获取状态。
- **流表规则**：按地址、端口等匹配，执行转发、丢弃、修改或上送等动作。

理解例子：新流到达，设备没有匹配规则时按配置通知控制器；控制器计算策略并装规则，后续数据由设备直接处理。

不是每个数据包都经过控制器，也不是所有SDN采用同一南向协议。控制器可用性、一致性和规则规模仍需设计，分离控制没有消除队列与容量限制。

<a id="s5.6"></a>

## 5.6 MPLS与段路由

### 5.6.1 MPLS标签转发

**MPLS，多协议标签交换**在相应网络内按短标签转发。入口压入标签，中间换标签，出口按规则弹出。

**FEC，转发等价类**是采用相同转发处理的一组分组；**LSP，标签交换路径**是按标签转发的路径。

理解例子：入口给某类包标签100，中间节点根据标签查表，换为205并从指定出口发，出口移除标签。100与205可有局部意义，并非目的主机地址。

标签栈项32位：Label 20位，TC 3位，S 1位，TTL 8位；TC是类别信息，S=1表示栈底。push、swap、pop分别指压入、交换、弹出。

它可用于业务承载和流量工程，即按需求组织流量走向；路径仍需控制机制建立，标签不会自行知道全网路径。

### 5.6.2 段路由与SRv6

**段路由**用有序段列表表达希望执行的节点或动作。**SID**是段标识，SRv6用IPv6地址形式表示它；**SRH**是携带段列表的路由扩展首部。

普通IPv6中间路由器按当前目的地址转发；执行相应SID行为的段端点，才推进下一段。

理解例子：希望依次执行A、B、C，SRH反向索引保存`[C,B,A]`。

```text
开始：Segments Left=2，当前目的A
A执行段行为：减为1，目的改B
B执行段行为：减为0，目的改C
```

不能每经过一个普通中间路由器就减Segments Left。SID可表示节点或函数，实际行为由SID定义，不把上例套为所有行为的完整处理流程。

**Last Entry**是最后一个列表索引，3项时是2，不是3。SRH还含Next Header、长度、Routing Type、标志、Tag等。

IPv6的Next Header=43指出路由扩展首部，SRH内Routing Type=4进一步识别SRH。段列表一般不是每执行一段就删除一项，也不记录全部实际中间节点。[RFC 8754](https://datatracker.ietf.org/doc/html/rfc8754)
