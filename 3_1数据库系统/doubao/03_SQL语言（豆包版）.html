SQL 语言

SQL 是这门课的"普通话"，也是数据库行业几十年不变的标准语言。这一单元从最基础的 select 三要素讲起，一路走到外连接、视图、完整性约束、授权，再到 JDBC/ODBC、存储过程、触发器、递归查询和 OLAP，完整覆盖入门、中级、高级三个层次。

开篇导读：SQL 从哪里来

SQL 最初叫 Sequel，是 IBM 圣何塞研究室 System R 项目的一部分，后来才改名为结构化查询语言（Structured Query Language）。它的标准由 ANSI 和 ISO 维护，课件列出的版本依次是 SQL-86、SQL-89、SQL-92、SQL:1999、SQL:2003。

商业系统大多提供 SQL-92 的绝大部分功能，再加上后续标准的部分特性和各自的私有扩展，所以课件提醒：不是这里的每个例子都能在你手头的系统上直接运行。学习时要抓"标准语法和核心思想"，把具体系统的差异当成实现细节。

1

数据定义语言与域类型

SQL 的第一大类语句是数据定义语言（DDL），负责建表、删表、改表。建表之前先得知道：每一列可以放什么类型的数据。

内置域类型

类型含义注意点
char(n)定长字符串，长度 n短了会自动补空格，比较时系统会把空格因素考虑进去
varchar(n)变长字符串，上限 n有多长存多长，不补空格
int / integer整数依赖机器的有限精度
smallint小整数同样是机器相关精度，占空间更小
numeric(p,d)定点数，共 p 位、小数 d 位如 numeric(3,1) 能存 44.5，要求精确金额时用它
real / double precision单精度、双精度浮点数机器相关精度，有舍入误差
float(n)至少 n 位精度的浮点数精度仍可能与机器有关

create table 建表

建表时要给出表名、每一列的名字和类型，还可以在列上直接写约束。以部门表为例：

create table department (dept_name varchar(20), building varchar(15), budget numeric(12,2), primary key (dept_name)); create table instructor (ID varchar(5), name varchar(20) not null, dept_name varchar(20), salary numeric(8,2), primary key (ID), foreign key (dept_name) references department);

这里出现了三种约束：not null 表示这一列不允许空值；primary key 声明主键，系统会保证主键非空且唯一；foreign key … references 声明外键，意思是 instructor 里的 dept_name 必须能在 department 表的主键里找到，否则这条数据插不进去。

注意：外键默认是"立即检查"

先建被引用的 department 表、再建引用它的 instructor 表，顺序不能反。往 instructor 里插数据时，对应部门必须已经存在。

删表与改表

drop table r 把表 r 连同里面的数据一起删掉；delete from r 只清空数据、保留表结构。alter table r add … 可以给已有表加列，比如：

alter table instructor add A D; -- A 是列名，D 是类型

新列在已有元组上的取值一律为空。

2

基本查询结构：select-from-where

生活类比

把一次查询想象成"填表三步"：先告诉系统从哪张表取（from），再说明要哪些列（select），最后给出筛选条件（where）。几乎所有 SQL 查询都是这三个部分的组合。

三个子句各管什么

select列出结果里要出现的属性
from涉及哪些关系（表）
where用条件过滤元组

例如"找出所有教师的名字"：

select name from instructor;

SQL 里关系是多集（multiset），不是严格集合：默认不会去重，所以多个同名教师会出现多行。select distinct 才强制去重，select all 显式保留重复（也是默认行为）。

select distinct dept_name from instructor;

select * 里的星号表示"所有列"，常用于快速查看整张表。

where 子句与算术表达式

where 里可以用逻辑连接词 and、or、not，以及比较运算符 =、≠、<、≤、>、≥。还可以对数值列做算术运算，比如给每位教师涨 10% 工资后显示：

select ID, name, dept_name, salary * 1.1 from instructor where dept_name = 'Comp. Sci.';

select 后面允许出现 +、−、*、/ 组成的算术表达式，作用在常量或列上。注意这只是"显示值变了"，原表数据并没有被修改。

3

连接查询与重命名

真实问题往往要同时用到多张表。比如"列出计算机系教师的名字和他们所在的教学楼"，名字在 instructor 表，楼在 department 表，就得把两张表拼起来。

笛卡尔积：先全部配对，再过滤

在 from 里写两个表，系统先做笛卡尔积——把 instructor 的每一行和 department 的每一行两两配对，再用 where 挑出"部门名相同"的那些配对：

select name, instructor.dept_name, building from instructor, department where instructor.dept_name = department.dept_name and salary > 70000;

当两张表有同名列（比如都叫 dept_name）时，必须用表名.列名消歧，否则系统不知道你指哪一个。

自然连接：让系统自动按同名列配对

natural join 会自动找出两张表中所有同名的列，只保留这些列取值完全相等的配对，并且同名列在结果里只留一份：

select name, course_id from instructor natural join teaches natural join section where semester = 'Fall';
自然连接的陷阱：同名不一定同义

natural join 会按所有同名列匹配。如果两张表恰好有一个同名列但含义不同（比如都叫 name，一个是教师名一个是学生名），系统照样拿它当匹配条件，结果可能错得离谱。课件特别强调了这个风险。

as 重命名：表别名与列别名

as 有两个用途。给表起短别名，让长查询更简洁；给列或表达式起别名，让结果表头更友好。

select T.name as instructor_name, S.dept_name, T.salary * 1.1 as new_salary from instructor as T, department as S where T.dept_name = S.dept_name;

表别名在同一个查询里还能让一张表"扮演两个角色"，这在自连接（比如员工表里找"谁和谁同部门"）时必不可少。

4

字符串、排序与集合运算

字符串匹配：like 与两个通配符

精确匹配用等号，模糊匹配用 like。它有两个通配符：百分号 % 代表任意长度（包括零长度）的任意字符，下划线 _ 代表恰好一个字符。

select name from instructor where name like '%dar%'; -- 名字里含 dar where name like '_dar%'; -- 第二个字符起是 dar

字符串里还可以用 || 做拼接，用 upper()、lower() 转大小写。如果要匹配的内容本身就含 % 或 _，可以用 escape 指定一个转义字符，比如 like 'ab\%cd%' escape '\' 中第一个 % 就是字面的百分号。

排序：order by

SQL 不保证查询结果的默认顺序，想要有序输出必须显式写 order by。asc 升序（默认），desc 降序，还可以按多列依次排：

select * from instructor order by salary desc, name asc;

含义是：先按工资从高到低，工资相同的再按名字字母顺序排。

between 与元组比较

between 是闭区间的简写，salary between 90000 and 100000 等价于 salary ≥ 90000 且 salary ≤ 100000。SQL 还支持元组比较，可以把多个值打包比较：

where (dept_name, salary) = ('Biology', 70000) where (dept_name, salary) in (select dept_name, salary from instructor where name='Einstein')

集合运算：并、交、差

两个结构相容的查询结果可以做集合运算，注意这三个运算默认自动去重：

运算写法含义
并union出现在任一结果里的元组
交intersect两个结果里都有的元组
差except在第一个结果里、但不在第二个里

带上 all 后缀——union all、intersect all、except all——则保留重复，按副本计数规则处理。比如某元组在第一个结果出现 3 次、第二个出现 1 次，except all 后它还剩 2 次。

5

空值与聚集函数

null 与三值逻辑

null 表示"值未知或不存在"，它不是 0，也不是空字符串。判断空值不能用等号，要用专门的 is null 和 is not null。

一旦比较里混进 null，结果就不再是简单的真或假，而是出现第三种逻辑值 unknown。where 子句只保留条件为真的行，所以 unknown 按假处理。课件给出的规则是：unknown and true = unknown，unknown and false = false，unknown or true = true，unknown or false = unknown，not unknown = unknown。

聚集函数

聚集函数把多行"聚成一个数"。标准的五个是：

avg平均值
min/max最小/最大
sum求和
count计数
select avg(salary) from instructor where dept_name = 'Comp. Sci.';

关键规则：除了 count(*)，所有聚集函数在计算前都会先把 null 丢掉。如果丢掉后没有值了，count 返回 0，其他函数返回 null。

分组：group by 与 having

想求"每个系"的平均工资，而不是全表一个数，就要用 group by 按部门分组：

select dept_name, avg(salary) as avg_sal from instructor group by dept_name having avg(salary) > 42000;
两条必须记住的规则

① select 里出现的非聚集属性，必须出现在 group by 里——否则同一组里它可能有多个值，系统不知道取哪个。② where 是分组前对行过滤，having 是分组后对组过滤，所以 having 里可以用聚集函数，where 里不能。

6

嵌套子查询

子查询就是套在另一个查询里的 select。它让复杂问题可以拆成"先查一个小集合，再拿它去筛大表"。

in 与 not in

比如"找出 2009 年秋季学期开过课的教师"，先从 section 查出该学期的课程号，再到 teaches 里匹配：

select distinct ID from teaches where (course_id, sec_id, semester, year) in (select course_id, sec_id, semester, year from section where semester='Fall' and year=2009);

some 与 all

把子查询结果当成一组值来比较。> some 表示"大于其中至少一个"，> all 表示"大于全部"。经典例子"找出工资比生物系所有教师都高的教师"：

where salary > all (select salary from instructor where dept_name='Biology');

exists 与相关子查询

exists 只判断子查询有没有返回行，返回真或假。当子查询引用了外层查询的变量时，就叫相关子查询，它会对外层的每一行重新求值。not exists 配合全称语义能表达"所有……都……"这类问题。

其他工具

  • unique：判断子查询结果里有没有重复元组，没有重复才为真。
  • 派生关系：from 里直接放一个子查询，用 as 给它起表名，当成临时表用。
  • with 子句：把一个子查询命名后在主查询里反复使用，避免重复书写，逻辑更清晰。
  • 标量子查询：只返回单个值的子查询，可以出现在任何需要一个值的位置。
  • lateral：让 from 里的子查询能引用同一 from 中其他表的属性（SQL:2003）。
7

数据库修改：增、删、改

delete 删除

delete 可以带 where 只删满足条件的行，不带 where 就清空整表。还可以用子查询做条件，比如删除数学系教师的所有开课记录：

delete from instructor where dept_name = 'Finance';

课件提醒一个易错点：删除时 where 里引用的是删除前的关系，所以可以先做一次 select 子查询再删，不会因为边删边查而混乱。

insert 插入

既可以直接给值，也可以把一个查询的结果批量插入：

insert into instructor values ('10211', 'Smith', 'Biology', 66000); insert into instructor select ID, name, dept_name, 18000 from student where dept_name='Music' and tot_cred>144;

没给全的列会被置为 null（前提是该列允许空）。

update 更新与 case

update 用 set 改值，同样可以配合子查询。需要按不同条件给不同值时，用 case 一次性表达：

update instructor set salary = case when salary <= 100000 then salary * 1.05 else salary * 1.03 end;

case 按顺序判断，取第一个满足的分支，都不满足则走 else。标量子查询也能出现在 set 里，实现"用另一张表的统计结果更新这张表"。

8

连接表达式与视图

外连接：不让信息丢失

普通（内）连接只保留两边都匹配上的行。可现实中有些行暂时没有匹配对象——比如某门课还没登记先修课，这些行会在内连接里直接消失。外连接就是为了"不丢信息"，把没匹配上的行也保留，缺的列用 null 补齐。

类型写法保留哪些行
左外连接left outer join左表全部行，右表没匹配上就补 null
右外连接right outer join右表全部行
全外连接full outer join两边所有行都保留
select * from course natural left outer join prereq;

连接条件除了 natural，还可以用 on 写任意条件（inner join prereq on course.course_id = prereq.course_id），或用 using (course_id) 指定只按某几个同名列匹配，从而避开自然连接"全部同名列"的陷阱。

视图：看得见但不实际存储的"虚表"

不是每个用户都该看到全部数据。比如发工资的人之外，其他人只需要知道教师的工号、姓名、部门，不该看到工资。视图就是把一个查询包装成一张"虚拟关系"呈现给用户：

create view faculty as select ID, name, dept_name from instructor;

关键理解：建视图不是把查询结果存成一张新表，而是保存了一个表达式。以后查询用到 faculty 时，系统把这个定义替换进去（这叫视图展开），再对真实表执行。视图可以建立在其他视图之上，由此形成依赖关系；一个视图若依赖自己，就叫递归视图。

视图能不能更新

往 faculty 插一行，系统可以翻译成往 instructor 插一行、工资列补 null。但很多视图的更新无法唯一翻译，比如由两张表连接而成的视图，插入一行时根本不知道该往哪张表补数据。所以多数系统只允许更新简单视图：

  • from 里只有一个真实关系；
  • select 里只有直接的列名，没有表达式、聚集、distinct；
  • 没列出的列可以置 null；
  • 没有 group by 或 having。

还有一种情况完全不允许：往"只含历史系教师"的视图里插入一个生物系教师，这行插入后会立刻从视图里消失，语义上自相矛盾，系统直接拒绝。

完整性约束

完整性约束的作用，是替数据库把住"合法数据"这道关，让经过授权的修改也不会破坏数据一致性。比如支票账户余额必须高于某个数、雇员工资不能低于法定时薪、客户必须有非空电话。

单表上的四种约束

not null

该列不允许空值，如姓名、预算。

primary key

主键，非空且唯一。

unique

声明候选键，允许为 null（这是它和主键的区别）。

check (P)

谓词 P 必须为真，如学期只能是四个值之一。

check (semester in ('Fall', 'Winter', 'Spring', 'Summer'))

参照完整性与级联动作

外键保证一个表里出现的引用值，在被引用表的主键里一定存在。定义外键时可以指定"被引用行被删/被改时怎么办"：

foreign key (dept_name) references department on delete cascade on update cascade

cascade 表示跟着级联删除或更新；另外两个可选动作是 set null（置空）和 set default（置为默认值）。

事务中的约束检查与复杂约束

有些表自引用（比如 person 表的父母 ID 也指向 person 自己），第一行数据无论先插谁都会违反外键。这时可以把约束声明为 deferred（延迟检查），让它到事务提交时才检查，给中间过程留余地。

check 里写子查询能表达更复杂的条件（如"每个教学班至少有一名教师"），但课件指出：几乎没有数据库支持 check 里放子查询，独立的 create assertion 断言机制也没人真正实现，实际中这类需求改用触发器完成。

数据类型进阶与授权

日期时间类型

类型含义示例
date年、月、日date '2005-7-27'
time时、分、秒（可带小数）time '09:00:30.75'
timestamp日期加时间timestamp '2005-7-27 09:00:30.75'
interval一段时间interval '1' day

两个日期相减得到 interval，interval 又能加回日期。列还可以用 default 给默认值，用 create index 建索引加速查询。

大对象、自定义类型与域

照片、视频这类大块数据用 blob（二进制大对象，解释权交给应用程序）和 clob（字符大对象）存放，查询返回的是指针而非整个对象。create type 能定义用户自定义类型（如把 Dollars 定义为 numeric(12,2)），create domain 能定义带约束的域（如限定学位只能是三个值之一）。

授权：谁能对数据做什么

对数据本身有四类权限：read（读）、insert（插入）、update（改）、delete（删）。修改模式结构另有四类：index（建删索引）、resources（建新关系）、alteration（增删列）、drop（删关系）。

grant select on instructor to U1, U2, U3; revoke select on instructor from U1, U2, U3;

授权对象可以是具体用户、public（所有合法用户）或角色。角色可以授予用户，也可以授予另一个角色，形成层级。在视图上授权并不自动带来底层表的权限。此外还有 references 权限（控制能否建外键引用该表）和 grant option（允许被授权者再把权限转授他人）；收回权限时，依赖它的权限会被连带收回，cascade 与 restrict 控制这种连带行为。

11

从编程语言访问数据库

SQL 擅长数据操作，但没有完整的循环、界面、文件处理能力。实际系统用通用编程语言写界面和逻辑，再通过标准接口调用 SQL。

JDBC：Java 数据库连接

JDBC 是 Java 与支持 SQL 的数据库通信的 API，通信模型四步：打开连接 → 创建 statement 对象 → 用它执行查询或更新 → 用异常机制处理错误。

Connection conn = DriverManager.getConnection(url, user, passwd); Statement stmt = conn.createStatement(); ResultSet rset = stmt.executeQuery( "select dept_name, avg(salary) from instructor group by dept_name"); while (rset.next()) { System.out.println(rset.getString("dept_name") + " " + rset.getFloat(2)); }

结果字段可以按列名或按位置取（getFloat(2) 表示第二列）。null 值要用专门的 wasNull() 判断。更新操作用 executeUpdate，返回受影响行数。

预编译语句与 SQL 注入

永远不要拼接用户输入

课件给出的注入例子：用户不输入名字，而输入 X' or 'Y' = 'Y，拼进字符串后 where 条件恒真，整张表被读走；甚至能插入 X'; update instructor set salary=salary+10000; -- 这样的破坏性语句。

正确做法是用 PreparedStatement，用问号占位，再把用户输入作为参数传入，驱动会负责转义，注入字符串被当成普通数据：

PreparedStatement p = conn.prepareStatement( "insert into instructor values(?,?,?,?)"); p.setString(1, "88877"); p.setString(2, "Perry"); p.setString(3, "Finance"); p.setInt(4, 125000); p.executeUpdate();

JDBC 还能通过元数据接口查询库里有哪些表、列名和类型；事务控制用 setAutoCommit(false) 关闭自动提交，再显式 commit() 或 rollback()；调用存储过程用 CallableStatement；大对象用 getBlob/getClob。SQLJ 则是把 SQL 直接嵌进 Java、让编译器提前查错的方案。

ODBC 与嵌入式 SQL

ODBC（开放数据库连接）是更早的标准 API，供 C、C++、C#、Visual Basic 等使用，每个数据库厂商提供自己的驱动库；ADO.NET 等接口就构建在 ODBC 之上。程序先分配环境句柄和连接句柄，再 SQLConnect 连接，用 SQLExecDirect 发命令、SQLFetch 取行、SQLBindCol 把结果列绑定到 C 变量。标准分 Core、Level 1、Level 2 三个一致性级别。

嵌入式 SQL 用 EXEC SQL … END_EXEC 把 SQL 写进宿主语言，由预处理器处理。查询返回多行时要声明游标（cursor）：open 执行查询，fetch 逐行取到宿主变量，SQLSTATE 变成 '02000' 表示没有更多数据，close 删除临时结果。游标还能声明 for update，配合 where current of c 更新当前行。动态 SQL 则允许程序在运行时构造并 prepare 一条带占位符的语句再 execute。

12

过程化结构与触发器

函数与存储过程

SQL:1999 支持函数和过程，可以用 SQL 本身写，也可以用外部语言写。函数返回一个值，比如给定客户名返回其账户数：

create function account_count(customer_name varchar(20)) returns integer begin declare a_count integer; select count(*) into a_count from depositor where depositor.customer_name = customer_name; return a_count; end

SQL:2003 增加了表函数，能返回一整张关系，用 from table(函数名(...)) 调用。过程用 in/out 参数，通过 call 调用。同名函数允许重载，只要参数个数或类型不同。

过程化控制结构

  • 复合语句 begin … end，里面可声明局部变量；
  • 循环：while、repeat（until 条件）、for（直接遍历一个查询的结果行）；
  • 条件：if-then-elseif-else，以及类似 C 的 case；
  • 异常：declare condition 定义条件，declare handler 声明处理器，signal 抛出异常，exit 型处理器会退出所在的 begin/end。

也可以声明用 C/C++ 等写的外部语言例程，优点是效率高、表达力强，缺点是代码在数据库地址空间运行有破坏和泄密风险。安全对策是用沙箱（如 Java 这种安全语言）或放进独立进程、通过进程间通信传递参数，两者都有性能开销。

触发器：修改引发的自动动作

触发器是系统在数据库被修改时自动执行的语句。设计触发器要规定两件事：在什么条件下执行（触发事件 insert/delete/update），以及执行什么动作。课件的透支例子：账户更新后若余额为负，就把余额清零、同时按透支金额建一笔贷款：

create trigger overdraft_trigger after update on account referencing new row as nrow for each row when nrow.balance < 0 begin atomic insert into loan values (nrow.account_number, nrow.branch_name, -nrow.balance); update account set balance = 0 where account.account_number = nrow.account_number; end

update 触发器可以限定到具体列；用 referencing old row / new row 引用修改前后的值；before 触发器能充当额外约束（比如把空格转成 null）。除了行级 for each row，还有语句级 for each statement，用过渡表 old table/new table 一次性处理所有受影响行，批量更新时效率更高。

课件也指出触发器不该滥用：过去用它维护汇总数据、做数据库复制，如今物化视图和内置复制设施是更好的选择；能用封装方法解决的，也尽量不用触发器。

13

递归查询

有一类问题普通查询很难表达：在员工-经理关系里，找出"直接或间接"汇报给某经理的所有人，也就是经理的经理、经理的经理的经理……层级数事先不知道。SQL:1999 用递归视图解决，写法是 with recursive：

with recursive empl(employee_name, manager_name) as ( select employee_name, manager_name from manager union select manager.employee_name, empl.manager_name from manager, empl where manager.manager_name = empl.employee_name ) select * from empl;

第一部分是基查询（直接上下级），第二部分是递归部分（在已有结果上再连一层）。系统迭代地一遍遍执行，直到不再产生新元组，最终结果叫递归定义的不动点（fixed point），数学上就是 manager 关系的传递闭包。

为什么必须有递归

不递归、不迭代的程序只能把 manager 自连固定次数，也就只能查固定层数；总能构造一个层数更多的数据库让它失效。递归视图还要求单调性：增加输入元组后，结果只能变多、不能变少。

14

高级聚集与 OLAP

cube 与 rollup

cube 对指定属性的每个子集都做一次 group by 再取并集。三个属性就产生 2³ = 8 种分组，包括空列表（= 全表总计）：

select item_name, color, size, sum(number) from sales group by cube(item_name, color, size);

rollup 则只对属性列表的每个前缀分组，三个属性产生 4 种分组，天然适合层级汇总（如"商品 → 类别 → 总计"）。分组里缺失的属性用 null 表示，函数 grouping() 返回 1 标明这是"代表全部"的 null，配合 decode 可以把它显示成 all。

排名与窗口函数

排名函数配合 over (order by …) 使用。rank 会留空挡（两个并列第 1，下一个就是第 3），dense_rank 不留空挡（下一个是第 2）；还有 percent_rank、cume_dist（累计分布）、row_number（重复时结果不确定）、ntile(n)（把行均分成 n 个桶）。加 partition by 可以在每个分区内单独排名，nulls first / nulls last 控制空值位置。

select student_id, rank() over (order by marks desc) as s_rank from student_marks;

窗口函数还能做滑动计算，比如移动平均：用 between rows 1 preceding and 1 following 框住当前行及前后各一行；用 rows unbounded preceding 可以对账户流水逐行累计余额。

OLAP：联机分析处理

OLAP 指以可忽略的延迟，对数据做交互式、多角度的汇总分析。数据被分成度量属性（可被聚合的数值，如销量）和维度属性（观察角度，如商品、颜色、尺寸），合称多维数据。

交叉表（cross-tab，也称透视表）把一个维度放行表头、另一个放列表头，单元格里放聚合值；数据立方体是它在 n 个维度上的推广，交叉表可看作立方体上的一个视图。常见操作有：pivoting（换维度）、slicing/dicing（固定一个或多个维度取值后切片）、roll up（从细粒度汇总到粗粒度）、drill down（反向钻取细节）。

实现上分三类：用内存多维数组存立方体的 MOLAP，只用关系数据库特性的 ROLAP，以及部分汇总放内存、基础数据放关系库的混合 HOLAP。预计算全部聚合代价很高（2ⁿ 种分组），实际只预计算部分聚合，其余从已算好的粗粒度结果推导（中位数等少数"不可分解"聚合除外），并用一次排序同时算出多种分组来优化。

本章小结与自测

三句话串起整个 SQL

基础层：select-from-where 是一切查询的骨架，配合连接、分组、聚集、子查询能表达绝大多数检索需求，null 带来三值逻辑、聚集默认丢弃空值。

中级层：外连接保证信息不丢，视图用"存表达式"的方式隔离和隐藏数据，完整性约束（含外键级联）和授权机制共同守住数据的合法与安全。

高级层：JDBC/ODBC 让程序与数据库对接，预编译语句防注入；过程化结构和触发器把逻辑搬进数据库；递归查询求传递闭包，cube/rollup 与 OLAP 支撑多维分析。

一句话记忆：SQL 不只是查询语言，它同时管定义、约束、安全、过程逻辑和分析。
