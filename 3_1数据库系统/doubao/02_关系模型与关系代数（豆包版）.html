关系模型与关系代数

这一单元解决两件事：一是关系模型里的"表"在数学上到底是什么，二是怎么用一套严谨的符号语言对表提问。关系代数是过程化的"操作手册"，而元组、域关系演算是声明式的"提要求"，三种语言表达能力等价，却代表了两种不同的思维方式。

开篇导读：这一单元学什么

如果你用过 Excel，就已经在直觉上理解了"关系"：一张工作表有列标题、有一行行数据。但数据库里的关系比 Excel 表格更讲究——它有严格的数学定义，还配套了一套像代数公式一样可以层层组合的查询语言。

学完这一单元，你应该能达到下面几个目标：

说清关系、域、原子性
能写出关系模式的形式化定义
区分四类键
超键、候选键、主键、外键
熟练运用关系代数符号
六大基本运算 + 连接、外连接、除、聚集
读懂两种关系演算
理解量词、安全性与三值逻辑
1

关系的基本结构

1.1 属性、元组与域

一张关系表有两个观察方向：竖着看是一列列属性（attributes，也叫列），横着看是一行行元组（tuples，也叫行）。每个属性都有自己的取值范围，这个范围就叫该属性的域（domain）。比如"工资"这个属性的域是某个数值集合，"姓名"的域是字符串集合。

课件同时强调了两个关键约定：属性值（通常）要求是原子的（atomic），也就是不可再分；而特殊值 null 是每个域的成员，它会给很多运算的定义带来麻烦，这一点我们后面专门讲。

生活类比

"原子性"可以理解成课程表上的一格：一个格子里只写一门课，你不能把两门课挤进同一个格子。如果一个字段里塞了"吉林省长春市"这种还能再拆的内容，在严格的关系模型看来就不够原子。当然，原子与否取决于用途——"地址"在只做整体寄送时可以算原子，要按省份统计时就得拆开。

1.2 关系模式与关系实例：形式化定义

设 A1, A2, …, An 是属性，那么 R = (A1, A2, …, An) 就是一个关系模式。课件给的例子是：

instructor = (ID, name, dept_name, salary)

形式化地说，给定集合 D1, D2, …, Dn（每个 Di 是对应属性的域），关系 r 是笛卡尔积 D1 × D2 × … × Dn 的一个子集。也就是说，关系是若干 n 元组 (a1, a2, …, an) 的集合，其中每个 ai 都属于 Di。

这里要分清两个概念：关系的当前取值（关系实例）由一张表给出；表中的每一个元素 t 就是一个元组，对应表里的一行。模式是"表头"，相对稳定；实例是"表里此刻装的数据"，会不断变化。

1.3 元组是无序的

关系在数学上是元组的集合，而集合没有顺序，所以元组的排列次序无关紧要，可以按任意顺序存储。课件展示了同一张 instructor 关系的不同行序，它们在关系模型里是完全相同的关系。这一点和 Excel 不同：Excel 的行号是有意义的，而关系表里你不能说"第 3 行"，只能用属性值来定位元组。

1.4 一个数据库由多张关系组成

一个组织的信息被拆成若干部分，分别放进不同的关系，比如大学数据库里有 instructor、student、advisor 等多张表。课件特意对比了一种坏设计：把所有信息塞进一张大表 univ(instructor-ID, name, dept_name, salary, student_Id, …)。这样做会带来两个直接后果：

  • 信息重复：两个学生同属一位导师，导师的信息就要重复两遍；
  • 被迫使用 null：比如一个没有导师的学生，导师相关字段只能填 null。

怎么设计"好"的关系模式，正是规范化理论（第 8 章）要解决的问题，这里先记住"拆表"的直觉。

2

键：怎么唯一认出一个元组

现实里我们靠身份证号认人，靠学号认学生。关系模型里也需要这样的"识别字段"，而且分成好几个层次，这是考试特别爱考的概念辨析。

2.1 超键、候选键、主键

设 K 是关系模式 R 的属性子集（K ⊆ R）。

  • 超键（superkey）：如果 K 的取值足以在任何可能的关系实例中唯一识别一个元组，K 就是超键。课件举例：{ID} 和 {ID, name} 都是 instructor 的超键——加了 name 之后当然还能唯一识别，只是有冗余。
  • 候选键（candidate key）：如果一个超键是极小的（minimal），即再去掉任何一个属性就不再是超键，它就是候选键。比如 {ID} 是 instructor 的候选键，而 {ID, name} 不是候选键，因为去掉 name 后 {ID} 仍然够用。
  • 主键（primary key）：从候选键中选一个作为主键。为什么还要选？因为一张表可能有多个候选键（比如教师表同时有"工号"和"身份证号"两个候选），需要指定一个主要的、系统默认用来识别和建立外键引用的键。
易混点提醒

这三个概念是层层收窄的：候选键一定是超键，主键一定是候选键。判断"极小"时要逐个属性试：把该属性删掉，看剩下的字段还能不能唯一识别。能，就说明这个属性是多余的，整个集合就不是候选键。

2.2 外键：跨表的引用

外键约束（foreign key constraint）说的是：一个关系里的某个取值，必须在另一个关系中真实出现。这里有两个角色：

  • 参照关系（referencing relation）：持有外键、发出引用的表；
  • 被参照关系（referenced relation）：被引用的表，外键值要能在它的主键里找到。

比如学生表的 dept_name 字段引用院系表的主键 dept_name，那么任何学生所在的系，都必须是院系表里真实存在的系，想填一个不存在的系名，系统会拒绝。这条约束是保证跨表数据一致的核心手段，课件还展示了大学数据库完整的模式图，表与表之间的连线就是外键关系。

知识点说明

外键通常引用对方的主键，但形式上它引用的是被参照关系上的"候选键"（实际系统几乎总是主键）。主键和外键配合，构成了关系模型表达"表与表之间联系"的方式——关系是独立的表，联系不靠单独的指针，而靠这些值的引用。

3

关系查询语言概览

第 1 章已经埋过伏笔：查询语言分过程化和非过程化（声明式）两类。课件把三种"纯"理论语言列在一起，它们正是这一单元后半段的主角：

语言风格基本思想
关系代数过程化用一组运算逐步操作关系，输出新关系
元组关系演算声明式以元组为变量，描述"想要满足什么条件的元组"
域关系演算声明式以域（属性值）为变量，直接描述各列取值条件

这三种语言在表达能力上是等价的：任何一种语言能表达的查询，另外两种也能表达。关系代数是 SQL 的理论基础，理解了它，再看 SQL 就像看代数公式的"自然语言写法"。

4

关系代数：六大基本运算

关系代数是过程化语言，它的运算以一个或两个关系为输入，产生一个新关系为结果。课件定义了六个基本运算，先记住这张总表，再逐个理解。

运算符号一句话作用
选择 selectσ按条件挑行
投影 projectΠ挑列并去重
并 union∪合并两个相容关系
集合差 set difference–留下只在前者出现的元组
笛卡尔积 Cartesian product×把两表的元组两两配对
重命名 renameρ给结果或关系起新名字

4.1 选择运算 σ

记法是 σp(r)，其中 p 叫选择谓词（selection predicate）。形式化定义是：

σp(r) = { t | t ∈ r 且 p(t) }

谓词 p 是命题演算公式，由若干项通过 ∧（与）、∨（或）、¬（非）连接而成；每一项的形式是"属性 op 属性"或"属性 op 常量"，op 可以是 =、≠、>、≥、<、≤。课件给的例子是：

σdept_name = "Physics"(instructor)

意思是从教师表里挑出物理系的教师。选择运算只减少行数、不改变列，结果关系的模式和原关系相同。

4.2 投影运算 Π

记法是 ΠA1, A2, …, Ak(r)。它的结果是一个 k 列的关系，做法是把没列出的列全部抹掉。有一个关键细节：因为关系是集合，结果里重复的行要去掉。比如对教师表投影系名，即使有 50 位教师，同系名也只留一行。

课件给的例子是去掉 instructor 的 dept_name 属性：

ΠID, name, salary(instructor)
易混点提醒

理论关系代数里投影会自动去重，但 SQL 的 select 默认保留重复，要写 select distinct 才去重。这个差异后面讲多集关系代数时会解释，先建立"集合去重、SQL 留重"的印象。

4.3 并运算 ∪

记法 r ∪ s，定义为：

r ∪ s = { t | t ∈ r 或 t ∈ s }

并运算不是随便两个表都能做，必须满足两个条件：第一，r 和 s 有相同的目（arity，属性个数）；第二，对应属性的域要相容，比如 r 的第 2 列和 s 的第 2 列处理的是同一类值。课件给的例子是找出 2009 年秋季学期、或 2010 年春季学期、或两个学期都开设的课程：

Πcourse_id(σsemester="Fall" ∧ year=2009(section)) ∪ Πcourse_id(σsemester="Spring" ∧ year=2010(section))

4.4 集合差运算 –

记法 r – s，定义为：

r – s = { t | t ∈ r 且 t ∉ s }

它同样要求两个关系相容（同目、域相容）。课件的例子是找出 2009 年秋季开设、但 2010 年春季不开的课程，把上面并运算例子里的 ∪ 换成 − 即可。

4.5 笛卡尔积运算 ×

记法 r × s，定义为：

r × s = { t q | t ∈ r 且 q ∈ s }

它把 r 的每个元组和 s 的每个元组两两拼接，结果行数是两表行数之积。课件假设 r 和 s 的属性互不相交（R ∩ S = ∅）；如果属性有重名，就必须先用重命名运算区分，否则会出现两个同名字段。

知识点说明

笛卡尔积本身常常产生大量"无意义配对"，所以它几乎总是和选择运算配合使用：先做积，再用选择把"对得上"的配对留下。这种"积 + 选择"的组合，其实就是后面要讲的连接运算的内部实现方式。

4.6 重命名运算 ρ

重命名有两个用途：给关系代数表达式的结果命名以便引用，以及让同一个关系以多个名字出现。基本形式是 ρx(E)，它以名字 X 返回表达式 E。如果 E 的目是 n，还可以连属性一起改名：

ρx(A1, A2, …, An)(E)

重命名最大的用武之地是让一张表和自己比较。课件讲"找全校最高工资"时，就把 instructor 复制一份命名为 d，再比较两份工资。

4.7 运算的组合与形式化定义

关系代数表达式可以像算术公式一样层层嵌套，比如 σA=C(r × s)。课件给出了表达式的形式化定义：基本表达式是数据库中的一个关系，或一个常量关系；在此基础上，若 E1、E2 是表达式，则 E1∪E2、E1–E2、E1×E2、σp(E1)、Πs(E1)、ρx(E1) 都是合法表达式。这保证了无论多复杂的查询，都能由六个基本运算搭建出来。

4.8 经典例题：找最高工资

这个例题非常能体现"重命名 + 差"的思路，分两步：

第一步，找出"比某些教师工资低"的工资，也就是非最高工资。把 instructor 复制一份命名为 d，做积后选择满足 instructor.salary < d.salary 的配对，再投影出工资：

Πinstructor.salary(σinstructor.salary < d.salary(instructor × ρd(instructor)))

第二步，用全部工资减去非最高工资，剩下的就是最高工资：

Πsalary(instructor) − Πinstructor.salary(σinstructor.salary < d.salary(instructor × ρd(instructor)))

课件还给出另一个例题：找物理系教师的姓名和他们教过的课程 ID，两种写法等价——区别只在于"先选系再做积"还是"先做积再选"，结果相同。

5

附加运算：交集、连接、赋值、外连接

这些运算不会增加关系代数的表达能力——它们都能用六个基本运算改写——但能让常见查询写起来简单得多。

5.1 集合交集 ∩

r ∩ s = { t | t ∈ r 且 t ∈ s }

同样要求同目、域相容。课件给出了它与基本运算的等价关系，记住这个式子就理解了"附加"的含义：

r ∩ s = r − (r − s)

5.2 自然连接 ⋈

设 r、s 的模式分别是 R、S。自然连接 r ⋈ s 的结果模式是 R ∪ S，做法是：对每一对元组 tr（来自 r）和 ts（来自 s），如果它们在公共属性 R ∩ S 上的取值全部相同，就把两元组拼成一个新元组 t，t 在 r 的属性上取 tr 的值、在 s 的属性上取 ts 的值。

课件给了一个形式化例子：R=(A,B,C,D)，S=(E,B,D)，结果模式是 (A,B,C,D,E)，自然连接等价于：

Πr.A, r.B, r.C, r.D, s.E(σr.B=s.B ∧ r.D=s.D(r × s))

这正好印证了前面说的："自然连接 = 笛卡尔积 + 选择 + 投影"的组合。

自然连接的两个性质

  • 结合律：(instructor ⋈ teaches) ⋈ course 等价于 instructor ⋈ (teaches ⋈ course)；
  • 交换律：instructor ⋈ teaches 等价于 teaches ⋈ instructor。

5.3 theta 连接

theta 连接是带任意条件的连接，定义非常直接：

r ⋈θ s = σθ(r × s)

自然连接要求公共属性相等，而 theta 连接允许你写任意条件 θ（比如工资比较），适用范围更广。

生活类比

自然连接像两个部门按"工号"对名单：工号相同的才是同一个人，把两边的信息并到一起；theta 连接则像"找出所有比自己组长工资高的员工"，比较条件不局限于相等，是更灵活的配对。

5.4 赋值运算 ←

赋值运算让复杂查询可以写成"顺序程序"：先把中间结果用一系列 ← 赋给临时关系变量，最后再写一个表达式显示结果。注意赋值只能赋给临时关系变量，它类似于编程里把长表达式拆成带名字的中间变量，让查询更易读。

5.5 外连接：避免信息丢失

普通连接会把"配不上对"的元组直接丢掉，外连接则把这些元组补回来，缺失的列用 null 填充。课件用 instructor1 和 teaches1 两张表演示了三种外连接，对应三种信息保留策略：

外连接保留哪些元组例子中的关键差异
左外连接左表所有元组都保留，右表配不上的填 null没教课的 Mozart 保留，course_id 为 null
右外连接右表所有元组都保留，左表配不上的填 null没人教的 BIO-101 保留，姓名等为 null
全外连接两边元组都保留，缺的都填 nullMozart 和 BIO-101 同时保留

外连接也能用基本运算表达，比如左外连接可以写成"自然连接的结果，∪ 左表中没匹配上的元组（与全 null 元组做积）"。它的意义在于：连接之后信息不丢失，这在统计类查询里特别重要。

6

除运算与扩展关系代数

6.1 除运算 ÷：表达"所有"的利器

给定关系 r(R) 和 s(S)，且 S ⊂ R，r ÷ s 是满足"t × s ⊆ r"的最大关系 t(R−S)。直觉上，它回答的是"哪些主体与 s 里的每一个对象都建立了联系"。

课件的例子：r(ID, course_id) 是学生选课记录，s(course_id) 是生物系开设的所有课程，那么 r ÷ s 给出的就是选了生物系全部课程的学生。注意"所有"这个词——这正是除运算区别于普通连接的地方。它可以用基本运算改写：

// temp1：所有可能的主体 temp1 ← ΠR−S(r) // temp2：缺了至少一门的主体 temp2 ← ΠR−S((temp1 × s) − ΠR−S, S(r)) result = temp1 − temp2

6.2 广义投影

广义投影把投影扩展为允许在投影列表里使用算术函数，形式为 ΠF1, F2, …, Fn(E)，每个 Fi 是由常量和 E 中属性组成的算术表达式。课件的例子：教师表存的是年薪，想得到月薪，就写：

ΠID, name, dept_name, salary/12(instructor)

6.3 聚集函数与分组

聚集函数接收一组值、返回一个值，课件列出五个：avg 平均、min 最小、max 最大、sum 求和、count 计数。关系代数里的聚集运算（有些书用 γ 表示）形式为：

G1, G2, …, Gn ℱ1(A1), F2(A2), …, Fm(Am)(E)

其中 G1…Gn 是分组属性（可以为空），Fi 是聚集函数。不分组时对整个关系做聚集（如求全部工资之和）；分组后每个组返回一行。课件给的例子：r 表 C 列四个值 7、7、3、10，sum(C) 得到 27；按系名分组求平均工资，每个系一行。聚集结果默认没有名字，可以用重命名（或在运算里直接用 as）命名，例如 avg(salary) as avg_sal。

6.4 多集关系代数：向 SQL 语义靠拢

纯关系代数基于集合、会去掉所有重复；但 SQL 保留重复（最初为效率，如今成为特性）。为此定义了多集（multiset）关系代数，重复元组按副本计数：

  • 选择：满足条件的元组保留与输入相同的副本数；
  • 投影：每个输入元组对应一个输出元组，即使重复也保留；
  • 笛卡尔积：r 中有 m 份 t1、s 中有 n 份 t2，结果就有 m×n 份；
  • 并：m+n 份；交：min(m,n) 份；差：max(0, m−n) 份。

课件还给出 SQL 与多集代数的对应：select … from … where … 等价于 Π(σ(r1×r2×…))；带 group by 的查询对应分组聚集运算，select 里的非聚集属性必须是 group by 属性的子集。这组对应关系把 SQL 彻底"翻译"成了代数。

7

空值与三值逻辑

null 表示值未知，或值不存在。它不是一个普通的"零"或"空字符串"，而是一个特殊标记，会让运算规则变得复杂。

7.1 空值在运算中的规则

  • 任何包含 null 的算术表达式，结果都是 null；
  • 聚集函数（和 SQL 一样）直接忽略 null 值；
  • 去重和分组时，null 被当作普通值，两个 null 视为相同（SQL 语义）。

7.2 为什么要引入 unknown：三值逻辑

与 null 比较时，结果不是简单的真或假，而是第三个真值 unknown（未知）。课件解释了为什么必须这样：如果把 unknown 当成 false，那么 not (A < 5) 就不再等价于 A ≥ 5，逻辑会自相矛盾。三值逻辑的运算规则如下：

运算规则
ORunknown OR true = true；unknown OR false = unknown；unknown OR unknown = unknown
ANDtrue AND unknown = unknown；false AND unknown = false；unknown AND unknown = unknown
NOTnot unknown = unknown

课件补充：SQL 里谓词 P 求值为 unknown 时，"P is unknown"为真；而选择谓词若求值为 unknown，结果按 false 处理——也就是含 null 的行不会被普通 where 条件选中，除非显式用 is null 判断。

易混点提醒

两个 null 用等号比较结果是 unknown，不是 true！所以判断空值必须写 is null，写 = null 永远选不出行。这是初学者最常踩的坑，也是查询结果莫名为空的常见原因。

8

数据库修改：删除、插入、更新

关系代数不仅能查询，也能表达三类修改，它们都可以用赋值运算书写。

8.1 删除

删除请求的写法和查询类似，只是选中的元组不显示给用户，而是从数据库移除。注意只能删除整个元组，不能只删某几列上的值（那是更新）。关系代数表达为：

r ← r − E

课件的银行例子包括：删除 Perryridge 支行的全部账户；删除位于 Needham 各支行的全部账户（先连接找出相关账户，再从 account 和 depositor 中分别减去）；删除金额在 0 到 50 之间的贷款记录。

8.2 插入

插入有两种方式：直接指定一个元组，或写一个查询、把结果元组批量插入。关系代数表达为：

r ← r ∪ E

插入单个元组时，让 E 是含一个元组的常量关系。课件例子：记录 Smith 在 Perryridge 支行 A-973 账户有 1200 元（同时向 account 和 depositor 插入）；给 Perryridge 支行所有贷款客户赠送 200 元储蓄账户，用贷款号当账号——先选出贷款客户，再用投影批量生成新账户。

8.3 更新

更新在不改变整个元组的情况下修改其中某些值，用广义投影实现：没更新的属性取原属性，更新的属性写一个只含常量和原属性的表达式。课件例子：所有账户余额增加 5%（balance × 1.05）；余额超过 10000 的账户加 6%、其余加 5%，用两个选择分开处理再并起来。

知识点说明

注意三类修改的代数形式有清晰的对应：删除是"减"，插入是"并"，更新是"广义投影覆盖"。它们都借助赋值 ← 完成，这也是为什么课件说所有修改都能用赋值运算表达。

9

元组关系演算

关系代数是过程化的，你要一步步规定怎么取；元组关系演算反过来，是非过程化的，你只描述"想要的元组满足什么条件"。

9.1 基本形式

每个查询形如 {t | P(t)}，它是所有使谓词 P 为真的元组 t 的集合。几个记号约定：

  • t 是元组变量，t[A] 表示元组 t 在属性 A 上的取值；
  • t ∈ r 表示元组 t 属于关系 r；
  • P 是类似谓词演算的公式。

9.2 谓词公式的组成

  • 属性和常量的集合；
  • 比较运算符：<、≤、=、≠、>、≥；
  • 连接词：and（∧）、or（∨）、not（¬）；
  • 蕴含（⇒）：x ⇒ y 表示"若 x 为真则 y 为真"，等价于 ¬x ∨ y；
  • 量词：
    • 存在量词 ∃：∃ t ∈ r (Q(t)) 表示关系 r 中存在一个使 Q 为真的元组；
    • 全称量词 ∀：∀ t ∈ r (Q(t)) 表示对 r 中所有元组，Q 都为真。

9.3 例题：从简单到带量词

找工资超过 80000 的教师（输出完整四列）：

{t | t ∈ instructor ∧ t[salary] > 80000}

同样的查询但只输出 ID 列，需要借助存在量词，并在模式 (ID) 上隐式定义一个关系：

{t | ∃ s ∈ instructor (t[ID] = s[ID] ∧ s[salary] > 80000)}

找所在系位于 Watson 楼的教师姓名，需要同时连接 instructor 和 department：

{t | ∃ s ∈ instructor (t[name] = s[name] ∧ ∃ u ∈ department (u[dept_name] = s[dept_name] ∧ u[building] = "Watson"))}

课件还演示了学期组合查询：用 ∨ 表达"秋季或春季"，用 ∧ 表达"两个学期都有"，用 ¬∃ 表达"秋季有但春季没有"。

9.4 表达式的安全性

元组演算可能写出产生无限关系的表达式，比如 {t | ¬ t ∈ r}，如果某个属性的域是无限的，"不在 r 里的元组"就有无穷多个。为防止这种情况，只允许安全表达式：{t | P(t)} 中 t 的每个分量都必须出现在 P 所涉及的某个关系、元组或常量中。

知识点说明

安全性不只是语法条件。课件举例：{t | t[A] = 5 ∨ true} 就不安全，因为 "∨ true" 让条件对任何元组都成立，定义了无限集合。判断时要看结果值是否都能在公式提到的有限数据里找到来源。

9.5 全称量词例题

找选了生物系全部课程的学生：

{t | ∃ r ∈ student (t[ID] = r[ID]) ∧ (∀ u ∈ course (u[dept_name] = "Biology" ⇒ ∃ s ∈ takes (t[ID] = s[ID] ∧ s[course_id] = u[course_id])))}

课件特别提醒：如果不对 student 做存在量词限定，当生物系没开任何课时，这个查询会不安全。这也说明除运算和全称量词查询在语义上是对应的。

10

域关系演算

元组演算的变量是整行元组，域关系演算的变量则是单个属性值（域变量），它与元组演算表达能力等价，也是非过程化语言。

10.1 基本形式

{< x1, x2, …, xn > | P(x1, x2, …, xn)}

其中 x1…xn 是域变量，分别对应结果的各列；P 是类似谓词演算的公式。"< i, n, d, s > ∈ instructor"表示这四个域变量的取值组合构成 instructor 中的一行。

10.2 例题

找工资超过 80000 的教师（完整四列）：

{< i, n, d, s > | < i, n, d, s > ∈ instructor ∧ s > 80000}

只输出 ID：

{< i > | < i, n, d, s > ∈ instructor ∧ s > 80000}

找所在系在 Watson 楼的教师姓名，需要量词引入 department 的域变量：

{< n > | ∃ i, d, s (< i, n, d, s > ∈ instructor ∧ ∃ b, a (< d, b, a > ∈ department ∧ b = "Watson"))}

学期组合查询同样用 ∨、∧ 连接，写法与元组演算平行，只是把元组变量拆成了逐个域变量。

10.3 安全性与全称量词

域演算的安全条件有三条：结果元组中的所有值都来自 dom(P)（出现在 P 或其涉及关系的元组中）；每个存在子公式 ∃x(P1(x)) 为真，当且仅当 dom(P1) 中存在使 P1 为真的值；每个全称子公式 ∀x(P1(x)) 为真，当且仅当 dom(P1) 中所有值都使 P1 为真。

找选了生物系全部课程的学生，域演算写法同样用 ∀ 加蕴含，并保留对 student 的存在限定；课件注明这一写法修正了原教材相应位置的一个查询缺陷。

生活类比

元组演算像说"把符合条件的整个人给我"，域演算像说"我只要符合条件的名字那一栏"，并逐栏描述取值要求。后者变量更细、更接近 QBE（实例查询）这种按表格格子填写条件的查询方式。

11

本章小结与自测

把整单元串成一条线

先认识关系的数学定义：关系是域笛卡尔积的子集，元组无序、属性要求原子；再用超键、候选键、主键、外键解决识别与引用问题。关系代数用六个基本运算（σ、Π、∪、–、×、ρ）层层组合表达查询，交集、连接、外连接、除、聚集都是它的简化或扩展；空值带来三值逻辑，修改靠减、并、广义投影。最后，元组演算和域演算用声明式方式描述同样的查询，并以安全性约束避免无限结果。

一句话记忆：关系代数告诉你"怎么算"，关系演算只说"要什么"，三种语言能力等价，而 SQL 就是建立在它们之上的工程实现。
