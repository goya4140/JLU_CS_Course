1. 用学生选课数据贯穿本章

先把“学生选课”变成可以查询的数据，再用同一套小数据检验后面的 SQL 是否回答了题目要求。

1.1 三张表分别记录什么

学校要记录有哪些学生、开了哪些课程，以及每个学生选了什么课。这些信息怎样放进表里，才能分清一行记录的含义？下面用三张表分别记录这三类事实：

表名 一行代表什么 字段含义
student 一位学生 SID 学号，name 姓名，dept 所在系
course 一门课程 CID 课程号，title 课程名，dept 开课系，credits 学分
takes 一位学生选了一门课 SID 学号，CID 课程号，score 成绩

本例不考虑学期和重修，同一学生对同一课程最多有一条选课记录。现实中若要记录多次修读，就需要调整表结构和主码。

表中的列说明记录有哪些方面，例如学号、姓名；每一行给出一个具体对象或一条具体关系的值。“学生表有哪些列”属于表结构，“目前有哪些学生”属于当前数据。建表与插入数据分别处理这两件事。

选课需要独立成表，是因为一位学生可以选多门课，一门课也可以有多位学生。若只在学生表放一个课程号，就无法表达多门选课；takes 用多行记录这些对应关系。

学生表 student：

SID name dept
S1 小林 计算机
S2 小周 数学
S3 小陈 计算机
S4 小吴 数学

课程表 course：

CID title dept credits
C1 数据库 计算机 3
C2 程序设计 计算机 4
C3 高数 数学 5

选课表 takes：

SID CID score
S1 C1 80
S1 C2 90
S2 C1 70
S3 C2 60

1.2 先从数据读出业务事实

写查询前，先从原始数据判断谁选了什么、谁还没有选课，才能核对查询结果。小林选了两门课；小周、小陈各选了一门；小吴没有选课。高数目前没有人选。数学系的小周选了计算机系开设的数据库课，说明跨系选课是允许的。

这里最容易混淆的是两张表中的 dept：student.dept 表示学生所在系，course.dept 表示开课系。列名相同，含义仍可能不同。

除非另行说明，后面的例题都从上面这套原始数据独立计算。某个修改例子的结果不会自动成为下一题的输入。结果表的排列只便于阅读；查询末尾没有 ORDER BY 时，不能依赖返回顺序。

2. SQL 在做什么：语句分类与数据类型

有了数据模型，接下来要决定用什么命令操作数据库，以及每列用什么类型保存值。

2.1 先认识几类语句

建表、查成绩、改成绩分别是不同任务，需要先认清各类语句负责什么。SQL 是结构化查询语言。DBMS 是管理数据库的软件，负责存储数据、执行 SQL 和检查规则。

类别 作用 常见语句
DDL，数据定义语言 建立或调整表等对象 CREATE、ALTER、DROP
DML，数据操纵语言 查询、新增、修改或删除数据行 SELECT、INSERT、UPDATE、DELETE
DCL，数据控制语言 授予或收回权限 GRANT、REVOKE
TCL，事务控制语言 提交或撤销一组操作 COMMIT、ROLLBACK

这是常用的学习分类，SELECT 有时也单独归为查询语言。SQL 主要让你描述所需结果，数据库决定如何读取和处理数据，这种方式称为声明式。

代码中，单引号包围文字值，例如 '计算机'；逗号分隔列或值；分号结束一条语句。关键字写成大写是为了便于辨认。

先分清“名称”和“值”：SID 是列名，'S1' 是这个列可能保存的文字值。WHERE SID = 'S1' 比较每一行的学号；WHERE 'SID' = 'S1' 比较两个固定字符串，无法按学生学号筛选。数字常量如 80 不需要单引号。

2.1.1 读语法前，先分清整体与组成部分

读到一条较长的 SQL 时，怎样看出它整体要做什么、每个部分又负责什么？一条 SQL 中会同时出现语句、子句、表达式和选项。这些名称描述不同层次，不能把见到的每个关键字都当作一种独立操作。

层次 例子 怎样理解
完整语句 SELECT SID FROM student WHERE dept = '计算机'; 完整表达一次查询任务
子句 FROM student、WHERE dept = '计算机' 分别交代数据来源、筛选条件，组成完整语句
表达式或条件 score + 5、dept = '计算机' 算出一个值，或判断一个条件是否成立
组成部分中的选项 ORDER BY score DESC 中的 DESC 为排序方向作选择，不能独立完成查询

后文若给出语法模板，中文名称表示需要替换的内容，方括号表示可省略的部分；模板放在 text 代码块中，不能原样执行。SQL 代码块中的示例会另行说明所需表和数据。阅读时依次问：它属于哪条语句？这一部分负责什么？能选择哪些写法？选定后会怎样影响结果？

2.2 按数据含义选择类型

学号、成绩和开课日期需要不同的表示方式。选择类型，就是为每列确定怎样保存和处理这些值。

类型 含义 适合存什么
CHAR(n) 固定长度字符类型 长度稳定的编号
VARCHAR(n) 有长度上限的可变长度字符类型 姓名、课程名称
INTEGER / INT 整数 人数、整数学分
NUMERIC(p,s) 精确十进制数 成绩、金额
REAL / FLOAT 近似数 允许近似表示的测量值
DATE 日期 开课日期
TIME 时刻 上课时间
TIMESTAMP 日期与时刻 操作发生的时间
BLOB / CLOB 二进制／字符大对象 图片字节、长文本

CHAR(5) 存储较短文字时，通常按固定宽度补空格；VARCHAR(5) 允许实际长度不同，但不能把“可变”理解为无限长。具体长度计量、尾随空格比较和磁盘占用由数据库实现决定。

NUMERIC(5,2) 中，5 是总数字位数，2 是小数位数，例如 123.45。精确小数适合按十进制规则处理金额；浮点数可能无法精确表示某些十进制小数。超出精度时如何舍入或报错，要看产品设置。

这里的 5 不包含小数点或正负号。按这个精度，整数部分最多 3 位，1234.56 就超出了范围。它仍允许负数；“成绩不能为负”要由 CHECK 规定。数据类型说明可以怎样表示值，约束说明业务允许哪些值，二者需要配合。

课程标准风格的日期字面量可写为 DATE '2026-09-01'。日期格式、时区和大对象名称存在产品差异，大对象也未必支持与短文本相同的比较、排序和索引操作。

3. 建表与完整性约束：把业务规则写进数据库

怎样让数据库既能保存选课信息，又能拒绝重复学号、失效引用和越界成绩？建表时需要一起规定结构与合法数据的范围。

3.1 建表时要回答的两个问题

先确定每列存什么，再确定什么数据可以进入表。例如，学号必须能区分学生；选课记录必须对应已有学生和课程；成绩应在 0 到 100 之间。

完整结构是 CREATE TABLE 表名 (列声明, 其他列声明, 表级约束);。一项列声明先给出“列名＋数据类型”，后面可以接该列的约束；跨列规则则另列一项。下面先看三张表如何对应，再在第 3.1.1 节逐项拆开，约束的含义由第 3.2—3.4 节继续解释。

CREATE TABLE student (
    SID CHAR(2) PRIMARY KEY,
    name VARCHAR(30) NOT NULL,
    dept VARCHAR(20)
);

CREATE TABLE course (
    CID CHAR(2) PRIMARY KEY,
    title VARCHAR(40) NOT NULL,
    dept VARCHAR(20),
    credits INTEGER CHECK (credits > 0)
);

CREATE TABLE takes (
    SID CHAR(2),
    CID CHAR(2),
    score NUMERIC(5,2),
    PRIMARY KEY (SID, CID),
    FOREIGN KEY (SID) REFERENCES student(SID),
    FOREIGN KEY (CID) REFERENCES course(CID),
    CHECK (score >= 0 AND score <= 100)
);

先建学生表和课程表，再建引用它们的选课表。上述代码只建立结构，不会自动插入第 1 节的数据。两位编号长度和文本长度是本例的教学选择。

3.1.1 逐项读懂建表语法

要自己写出建表语句，需要看清一列的名称、类型和限制分别写在哪里。以 name VARCHAR(30) NOT NULL 为例：

语句部分 在声明什么
name 列的名称
VARCHAR(30) 列的数据类型和长度上限
NOT NULL 这一列必须填写非空值

CREATE TABLE student (...) 指定表名，括号内以逗号分隔列声明或约束，最后一项后面不加分隔逗号，); 结束整条建表语句。

直接写在某列后面的约束称为列级约束，例如 SID CHAR(2) PRIMARY KEY。另列一项的称为表级约束，例如 PRIMARY KEY (SID, CID)；它便于表达多列共同遵守的规则。单列主码也可以写成单独一项的 PRIMARY KEY (SID)，不应将两种写法同时用来重复声明同一个主码。

约束由数据库在相关数据变更时检查。它保证的是已声明的规则；如果没有声明“姓名必须唯一”，数据库就不会替业务禁止同名。列级与表级约束的写法可参照 PostgreSQL 约束说明。

3.2 各种约束分别防止什么问题

“不能重复”“必须填写”“必须有对应记录”是不同要求，要用各自的约束表达。下面先按它们防止的问题区分。

约束 规则 例子
PRIMARY KEY，主码 标识每行，值唯一且非空 学生学号不能重复
FOREIGN KEY，外码 引用值必须符合与另一表的对应规则 不能给不存在的学生登记选课
NOT NULL 必须提供非空值 姓名不能缺失
UNIQUE 声明另一组唯一值 学生邮箱不能重复
CHECK 检查条件，条件为假时拒绝 成绩不能为 110

PRIMARY KEY (SID, CID) 是组合主码：同一“学生＋课程”组合不能重复。它允许 S1 选 C1、C2，也允许 S1、S2 都选 C1。

下面分别说明两个容易混淆的知识点：主码与 UNIQUE 的区别、两条外码约束的含义。

3.2.1 主码与 UNIQUE 有什么区别

学号和邮箱都可能要求唯一，为什么还要区分主码与 UNIQUE？两者都限制重复；主码还要求非空，并被选作标识每一行的主要依据。

比较项 主码 PRIMARY KEY 唯一约束 UNIQUE
能否重复 不允许主码值或主码组合重复 不允许受约束的非空值或非空值组合重复；涉及 NULL 的规则因产品而异
是否必须非空 是，组合主码中的每一列也必须非空 本身不要求非空；若必须填写，另加 NOT NULL
一张表能定义几个 只能有一个主码约束 可以有多个唯一约束
能否由多列组成 可以，称为组合主码 可以，限制多列组合不重复
主要用途 作为记录的主要身份标识，例如学号 保证其他字段或字段组合不重复，例如邮箱

看一个独立示例：另建学生联系信息表，不改变第 1 节的 student 表。

CREATE TABLE student_contact (
    SID   CHAR(2) PRIMARY KEY,
    name  VARCHAR(30) NOT NULL,
    email VARCHAR(100) UNIQUE
);
  • SID 是主码：学号必须填写，且不能与其他学生重复。
  • name 只有非空约束：姓名必须填写，但允许不同学生同名。
  • email 有唯一约束：填写的非空邮箱不能重复，但 UNIQUE 本身不要求必须填写邮箱。

若邮箱也必须填写，可以把该列改为：

email VARCHAR(100) NOT NULL UNIQUE

此时邮箱也满足“唯一且非空”，可以作为另一组候选身份标识，但这张表指定的主码仍然是 SID。有多组字段能够唯一标识记录，不代表一张表可以声明多个主码。

多列约束看组合，不看每列是否单独重复。例如 PRIMARY KEY (SID, CID) 允许 (S1,C1)、(S1,C2) 同时存在，因为组合不同；两个 (S1,C1) 则不允许。UNIQUE (SID, CID) 也限制组合重复，但它本身不附带主码的非空要求。

未加 NOT NULL 时，UNIQUE 列能否保存多个 NULL、含 NULL 的组合如何判断重复，需要查具体 DBMS 及其选项。本章未指定数据库产品，不能笼统说“所有数据库只允许一个 NULL”或“所有数据库都允许多个 NULL”。

3.2.2 两条外码约束分别是什么意思

登记选课时，怎样阻止录入不存在的学生或课程？这两个要求分别交给两条外码约束。第 3.1 节中，这两行位于 CREATE TABLE takes (...) 内，因此 FOREIGN KEY 后括号里的列都属于当前的选课表 takes：

FOREIGN KEY (SID) REFERENCES student(SID),
FOREIGN KEY (CID) REFERENCES course(CID),
语句部分 含义
FOREIGN KEY (SID) 将当前选课表的 SID 声明为外码
REFERENCES student(SID) 该外码引用学生表 student 的 SID 列
FOREIGN KEY (CID) 将当前选课表的 CID 声明为外码
REFERENCES course(CID) 该外码引用课程表 course 的 CID 列

第一行要求“选课的学生必须存在”。若选课表中填写 SID='S1'，学生表中必须有 S1。第 1 节中没有 S9，因此不能给 S9 登记选课。

第二行要求“所选的课程必须存在”。若选课表中填写 CID='C1'，课程表中必须有 C1。第 1 节中没有 C9，因此不能登记 C9 的选课。

用几条拟插入记录检查这两条规则，均从第 1 节原始数据独立判断：

拟插入记录 学生外码检查 课程外码检查 对外码的判断
S1、C3、88 S1 存在 C3 存在 两条外码均满足
S9、C1、88 S9 不存在 C1 存在 违反学生外码约束
S1、C9、88 S1 存在 C9 不存在 违反课程外码约束

通过外码检查后，还要检查主码、成绩范围等其他约束。例如 S1、C1、88 的学生和课程都存在，但原表已有 S1、C1，因此会违反组合主码约束。

把三条约束放在一起读：

  • PRIMARY KEY (SID, CID)：同一个学生对同一门课程最多登记一次。
  • FOREIGN KEY (SID) REFERENCES student(SID)：登记选课的学生必须存在。
  • FOREIGN KEY (CID) REFERENCES course(CID)：登记选课的课程必须存在。

外码本身不要求选课表中的 SID 或 CID 单独唯一，所以 S1 可以选多门课，C1 也可以有多位学生选。它只检查引用关系，不会自动创建学生或课程，也不会把姓名、课程名复制到选课表中。

一般而言，单列外码本身不强制非空；本例 SID、CID 同时属于组合主码，因此都不能为 NULL。代码末尾的逗号用于分隔建表括号中的项目，这两行不是可以单独执行的完整 SQL 语句。

3.3 用具体记录检查自己是否理解

一条记录可能同时受到多项约束，不能通过其中一项就认定可以插入。

假设第 1 节的数据已经插入，各条试插记录独立判断：

拟插入的选课记录 能否通过本例约束 原因
S1、C3、88 可以 学生和课程存在，组合未重复，成绩合法
S1、C1、88 不可以 S1、C1 已有记录，组合主码重复
S9、C1、88 不可以 学生表没有 S9
S2、C2、110 不可以 成绩检查条件为假
S2、C2、NULL 可以 本例允许成绩尚未公布

最后一条说明 CHECK 与 NOT NULL 的区别。NULL 使成绩比较得到“未知”，标准 SQL 的 CHECK 不会仅因未知而拒绝；如果业务要求成绩必须填写，还要加 NOT NULL。NULL 的完整含义见第 5 节。

成绩声明 是否接受 NULL 是否接受 110
只有 NOT NULL 否 是，未限制范围
只有 CHECK (score BETWEEN 0 AND 100) 是 否
同时有上述两种约束 否 否

在将空字符串与 NULL 区分的数据库中，NOT NULL 不会因为文字是空字符串或只含空格就拒绝；姓名是否真实也需要其他规则。实体完整性主要由主码约束体现，参照完整性由外码约束体现；成绩范围等则是具体业务的完整性要求。

3.4 默认值和引用动作

这两项都可以出现在表定义中，但处理的情境不同：默认值回答“插入时省略列，填什么”，引用动作回答“被引用的记录变化了，已有引用怎么办”。先分别理解，再看 SET DEFAULT 怎样把它们联系起来。

3.4.1 DEFAULT：插入时省略列，采用什么值

如果多数课程都是 3 学分，录入时怎样省去重复填写，同时允许个别课程使用其他学分？DEFAULT 指定插入时省略某列所采用的值，例如 credits INTEGER DEFAULT 3。明确传入 NULL，通常不等于请求默认值。

用独立教学表观察三种情况，不修改主例的课程表：

CREATE TABLE course_default_demo (
    CID CHAR(2) PRIMARY KEY,
    credits INTEGER DEFAULT 3 CHECK (credits > 0)
);

INSERT INTO course_default_demo (CID) VALUES ('D1');
INSERT INTO course_default_demo (CID, credits) VALUES ('D2', 4);
INSERT INTO course_default_demo (CID, credits) VALUES ('D3', NULL);
CID credits 原因
D1 3 没给 credits，使用默认值
D2 4 已给具体值，采用该值
D3 NULL 明确写入缺值，没有请求默认值

这个表没有给 credits 加 NOT NULL，因而 D3 可以插入。默认值本身也必须满足约束，例如把默认学分设为 -1，并不会使负学分合法。默认值处理的是“省略时填什么”，CHECK 处理的是“给定值是否允许”。参见 PostgreSQL 默认值说明。

3.4.2 先确定引用方向，再区分事件与动作

课程 C1 已被选课记录引用。若删除它，或把编号改成 C5，原来的选课记录怎么办？引用动作就是对这个问题的处理约定。takes.CID 引用 course.CID：选课表是引用方，课程表是被引用方；外码要求选课中的课程号有合法对应。

规则由“发生什么变化”与“怎样处理引用”两部分组成，写在对应的外码声明后面：

FOREIGN KEY (引用列) REFERENCES 被引用表(被引用列)
    [ON DELETE 引用动作]
    [ON UPDATE 引用动作]
层次 写法 负责什么
引用事件 ON DELETE 指定被引用行删除时的处理
引用事件 ON UPDATE 指定被引用键值更新时的处理
引用动作 CASCADE 等 指定如何处理引用行
事件与动作组成的处理子句 ON DELETE CASCADE 指定“删除被引用行时，级联删除引用行”
完整外码约束 FOREIGN KEY (CID) REFERENCES course(CID) ON DELETE CASCADE 同时交代引用关系和删除时的处理方式

所以，ON DELETE、ON UPDATE 是事件部分，CASCADE 等才是动作选项。ON DELETE CASCADE 把两部分组合起来，不能与单独的动作作为同一层次并列。删除与更新可分别选择动作，也可以只声明其中一种；未写的部分按所用 DBMS 的默认规则处理。只修改课程名称，没有改变被引用的 CID，不属于这条外码关注的键值更新。

3.4.3 动作表只比较“如何处理引用行”

面对已有引用，可以阻止变更，也可以按规则删除引用行或替换引用值；该选哪种处理，需要看业务要求和约束。下面以课程外码为例。表中不再重复列事件；同一个动作与不同事件组合，具体效果要分别读。

引用动作 与 ON DELETE 组合 与 ON UPDATE 组合 使用条件或注意点
NO ACTION 不自动修复引用；检查时仍有失效引用就拒绝 不自动改引用列；检查时仍有失效引用就拒绝 名称不表示允许违反外码；检查能否延后取决于约束设置和产品
CASCADE 删除引用该课程的选课行 将相关选课的 CID 改成新的课程号 删除传播的是行删除，更新传播的是被引用键值
SET NULL 将相关选课的 CID 设为 NULL 将相关选课的 CID 设为 NULL 引用列必须允许 NULL
SET DEFAULT 将相关选课的 CID 设为该列默认值 将相关选课的 CID 设为该列默认值 替换后仍须满足外码及其他约束

有些资料还会列出 RESTRICT：有相关引用时阻止删除或键值更新。它与 NO ACTION 的检查时点可能不同，例如 PostgreSQL 的 RESTRICT 不允许把该检查推迟。本表保留原资料的四种动作，未把它们视为所有产品的完整选项清单。语法及差异可查 PostgreSQL 外码语法和引用动作说明。

第 3.1 节的 takes.CID 属于主码、不能为 NULL，因此这张表不能直接采用 SET NULL。SET DEFAULT 则使用引用列 takes.CID 的默认值，不是 course.CID 的默认值；若默认值为 C0，课程表还须有合法的 C0 对应。动作不是绕过其他约束的通道。

3.4.4 放回完整建表语句，推导两种级联效果

选定级联后，怎样把它写进外码定义，并判断一次删除或改号会影响哪些数据？下面是第 3.1 节 takes 表定义的另一种方案，增加课程外码的两条级联规则。它用于独立教学场景，替代该节的 takes 定义，不能与同名原表重复建立。仍先建立 student、course，再按第 1 节插入数据。

CREATE TABLE takes (
    SID CHAR(2),
    CID CHAR(2),
    score NUMERIC(5,2),
    PRIMARY KEY (SID, CID),
    FOREIGN KEY (SID) REFERENCES student(SID),
    FOREIGN KEY (CID) REFERENCES course(CID)
        ON DELETE CASCADE
        ON UPDATE CASCADE,
    CHECK (score >= 0 AND score <= 100)
);

两条 ON 子句附属于同一个课程外码，不是另外两条 SQL 语句，也不会改变学生外码的规则。每个 ON 子句后选择一个动作；换行只是便于阅读。

以下两种操作分别从采用上述方案的原始数据出发，不连续执行：

DELETE FROM course WHERE CID = 'C1';

UPDATE course SET CID = 'C5' WHERE CID = 'C1';
独立操作 course 中的变化 takes 中的变化 student 中的变化
删除 C1 C1 行被删除 S1、C1 和 S2、C1 两条选课被删除，剩两条 C2 选课 无
将 C1 编号改为 C5 原课程行的 CID 变为 C5 原两条 C1 选课的 CID 都变为 C5，成绩保留，仍有四条选课 无

若使用第 3.1 节未声明级联的原方案，不能套用这个结果：课程 C1 仍被选课引用时，删除或改号须满足其外码检查规则。是否允许级联，最终要由业务决定；例如删除课程是否应一并清除历史选课记录，不能仅凭语法方便作决定。

3.5 区分改结构与改数据

增加一列、删掉一条选课、移除整张表，改动的对象不同。操作前先分清要改表结构还是表中的数据。

语句 改变什么
ALTER TABLE student ADD email VARCHAR(100); 增加一列
DELETE FROM student; 删除全部学生行，保留表结构
DROP TABLE student; 移除表对象及其数据

这些是语义示例，不要求在本机或真实数据库执行。外码依赖、权限和 DDL 能否回滚由数据库产品决定。

ADD email VARCHAR(100) 中，ADD 表示增加列，email 是新列名，后面是类型。新列如何为已有行赋值，要结合默认值和约束判断。数据修改不会把主码、外码等规则自动取消；例如删除已有选课引用的学生，仍要通过外码检查或按引用动作处理。

4. 单表查询：从筛选行到输出列

当需要的信息都在一张表里时，怎样取出符合条件的行，并只显示需要的列？单表查询从这个问题开始。

4.1 读懂 SELECT、FROM、WHERE

先完成一个具体任务：从学生表中找出计算机系学生，只显示学号和姓名。查询要分别交代数据来源、筛选条件和输出列：

SELECT SID, name
FROM student
WHERE dept = '计算机';

理解时先看 FROM：来源是学生表。再看 WHERE：只保留计算机系学生。最后看 SELECT：只输出学号和姓名。

SID name
S1 小林
S3 小陈

SELECT * 表示输出全部列。查询没有改变原表。

SELECT、FROM、WHERE 是一条查询的不同子句，分号结束整个查询。WHERE 筛掉的是不符合条件的结果行，不会把这些行从原表删除。也可以省略 WHERE 来查询全部行，但 SELECT 输出哪些列仍由选择列表决定。

4.2 根据题意写条件

题目常同时要求某个学生、某门课程或某个成绩范围，怎样把这些要求组成准确的筛选条件？先写出能判断一件事的条件，再用 AND、OR、NOT 组合。比较运算和逻辑组合分属两个层次。

单个条件的写法 含义
score >= 80 成绩至少 80
dept <> '数学' 所在系不等于数学；空值情形见第 5 节
score BETWEEN 70 AND 90 成绩在 70 到 90 之间，包含两端
CID IN ('C1','C2') 课程号是 C1 或 C2
组合条件的写法 含义
P AND Q 两个条件都满足
P OR Q 至少一个条件满足
NOT P 对条件取否定

P、Q 是讲解用的完整条件代号，不是本例的列名；例如 P 可以是 SID = 'S1'。BETWEEN 70 AND 90 中的 AND 分隔上下界，整个 BETWEEN 才是一个范围条件；P AND Q 中的 AND 则连接两个条件。复杂条件用括号表达意图，例如：

SELECT SID, CID, score
FROM takes
WHERE SID = 'S1'
  AND (score >= 80 OR CID = 'C2');

它要求学生是 S1，并且满足括号内至少一个条件。结果是 S1 的两条选课记录。

若目标是“查询 S1，并且只要 C1 或 C2”，应把两个课程条件括在一起。写成 SID = 'S1' AND CID = 'C1' OR CID = 'C2' 时，通常先结合 AND，S3 的 C2 也会被保留。括号直接说明哪些条件作为一个整体，比依赖优先级更清楚。

4.3 LIKE：按文字模式查找

只记得姓名里有一个字，而不知道完整姓名时，需要按文字模式查找。LIKE 是条件中的匹配运算，结构为 文字表达式 LIKE 模式。百分号和下划线是模式内部的通配符；'%小%' 是一个模式值，name LIKE '%小%' 才是可交给 WHERE 判断的完整条件。

SELECT SID, name
FROM student
WHERE name LIKE '%小%';

% 匹配任意长度文字，包括零个字符；_ 匹配一个字符。本例四位学生姓名都含“小”，所以全部返回。

模式 含义
'小%' 以“小”开头
'%小' 以“小”结尾
'%小%' 包含“小”
'小_' “小”后面恰好还有一个字符

要查找字面上的 % 或 _，应使用数据库的转义规则。文字比较是否区分大小写，由数据库及其排序规则决定。

LIKE 的模式匹配整个字符串。LIKE 'g' 只匹配名字恰好为 g 的情况；找名字中包含 g 才写 LIKE '%g%'。姓名“小”可以匹配 '小%'，因为百分号允许零个字符，却不能匹配 '小_'，因为下划线要求恰好再有一个字符。

4.4 DISTINCT：对输出的整行去重

要知道学生来自哪些系，直接查询 dept 会反复出现同一个系。DISTINCT 用来让相同的输出行只保留一次：

SELECT DISTINCT dept
FROM student;

结果只有“计算机”“数学”两行。SQL 默认可以返回重复行，DISTINCT 让相同输出只出现一次。

去重对象是选择列表的整体。SELECT DISTINCT SID, dept FROM student 仍返回四行，因为学号各不相同。它不会删除学生表的数据。

DISTINCT 不会自动知道业务上“一位学生”是什么意思。如果只输出姓名，两个同名学生可能被合成一行；如果要按学生身份去重，应保留学号。去重也不等于排序，需要顺序仍须 ORDER BY。

4.5 计算列、别名与排序

如果结果需要显示加分后的成绩、起一个便于阅读的列名，并按成绩排列，该怎样组合这些要求？这一节有三个可以组合的步骤：表达式计算输出值，AS 为结果命名，ORDER BY 决定显示顺序。先看它们在整条查询中的位置：

SELECT 原有列, 计算表达式 AS 输出列别名
FROM 来源表 [AS 表别名]
ORDER BY 排序表达式 [ASC 或 DESC], 后续排序项;

SELECT SID, CID, score, score + 5 AS adjusted_score
FROM takes
ORDER BY score DESC, SID ASC, CID ASC;

AS 给计算列起名。DESC 是降序，ASC 是升序；后面的排序项在前面相同时继续区分。

SID CID score adjusted_score
S1 C2 90 95
S1 C1 80 85
S2 C1 70 75
S3 C2 60 65

score + 5 只计算显示值。要改变原成绩，需要使用第 10 节的 UPDATE。

复杂查询中，既需要简洁地指代来源表，也需要为计算结果起一个可读的列名。下面区分这两种别名的对象：

写法 别名针对谁 改变什么
FROM student AS s 来源表 当前查询用 s 指代 student
score + 5 AS adjusted_score 输出列 当前结果给计算值起列名

两种 AS 都用于命名，但不会把基础表或基础列永久改名。表别名在声明它的查询范围内使用，相关子查询还可以引用外层别名；列别名通常可用于 ORDER BY。为了保持可移植性，不在同层 WHERE 中直接写 adjusted_score >= 85，而应写 score + 5 >= 85，或用派生表后在外层引用这个名字。参见 PostgreSQL 选择列表与列名说明。

排序默认一般为升序，本章显式写 ASC、DESC。成绩相同后按 SID、CID 继续排序，能区分本例每条选课；若只按成绩排，同分记录之间没有固定先后。

5. NULL：先分清“没有值”与“值为零”

成绩尚未公布时，不能随意填成 0 分。怎样表示缺值，又怎样让查询正确处理它？这需要理解 NULL 及其判断规则。

5.1 为什么需要第三种判断结果

不知道某人的成绩，就无法断定他是否及格；这个判断结果怎样在 SQL 中表示？另设一份独立成绩通知 grade_notice(SID, score)，不改变原始 takes：

SID score
S1 80
S2 0
S3 NULL

S2 是已知零分，S3 是没有已知成绩。NULL 也不同于标准概念中的空字符串 ''，尽管个别产品的处理不同。

判断 score >= 60 时，S1 得到真，S2 得到假，S3 得到未知。SQL 用真、假、未知三种结果处理这类条件，称为三值逻辑。WHERE 只保留结果为真的行。 因此 S3 不会出现在及格名单中，也不能据此断定 S3 不及格。

5.2 判断缺值要用 IS NULL

要找成绩尚未公布的学生，需要直接判断“有没有值”，而不是把缺值当作普通分数比较：

SELECT SID
FROM grade_notice
WHERE score IS NULL;

结果是 S3。IS NOT NULL 表示非空。不要写 score = NULL，因为普通等号与 NULL 的比较得到未知；即使 NULL = NULL 也不会得到真。

COALESCE(score, 0) 返回第一个非空参数，可把缺值显示成零。这是你选择的显示规则，不能说明原成绩确实为零。

例如成绩未知时，score + 5 仍为 NULL。COALESCE(score, 0) + 5 才会得到 5；后者已经额外采用了“先将缺值按零处理”的规则。

5.3 三值逻辑怎样组合

一个条件已知、另一个条件未知时，组合后的条件是否还能确定？下面看 AND、OR、NOT 怎样处理未知。用 T、F、U 分别表示真、假、未知：

P NOT P
T F
F T
U U
P Q P AND Q P OR Q
T T T T
T F F T
T U U T
F F F F
F U F U
U U U U

交换 P、Q 不改变表中 AND、OR 的结果。理解时可以问：已知部分是否足以确定整体？“假且未知”一定是假；“真或未知”一定是真。

在成绩通知例子中，NOT (score >= 60) 只会选出零分的 S2，仍不会选出 S3，因为 NOT 未知仍为未知。如果要明确找“不及格或未公布”，需要写 score < 60 OR score IS NULL。

三值逻辑主要说明条件判断。DISTINCT 对输出去重、GROUP BY 分组时，NULL 使用各自的重复和分组规则；不能据 NULL = NULL 为未知，就断言两个 NULL 永远无法放在同一个组里。

例如独立名单的系值为“计算机、NULL、NULL”，SELECT DISTINCT dept 得到“计算机”和 NULL 两行；按 dept 分组计数，则得到计算机 1 人、未知系这一组 2 人。它不会把未知的实际系名补出来。

5.4 NOT IN 遇到 NULL 为什么容易出错

想排除名单中的学生，如果名单本身含有未知学号，“不在名单里”的判断会怎样变化？假设名单中有 S1 和一个未知学号：

SELECT SID
FROM student
WHERE SID NOT IN ('S1', NULL);

对 S2，它要求“S2 不等于 S1，并且不等于那个未知学号”。前半句是真，后半句未知，整体未知，不能通过 WHERE。本例最终没有学生返回。

如果题意是“找没有对应选课记录的学生”，通常可以用相关 NOT EXISTS 表达，见第 9 节。它仍需要正确的匹配条件，也不能自动识别未知学号。

6. 连接查询：把分散在不同表的事实组合起来

想在同一行显示学生姓名和选课成绩，但它们分存在不同表里，该怎样配对？连接写在 FROM 子句中，用来产生查询的数据来源。理解连接时，要分别回答几个问题；这些答案可以组合，不能都当作互斥的“连接类型”。

要决定什么 常见选择 选择之间的关系
未匹配行是否保留 内连接、LEFT／RIGHT／FULL 外连接 决定哪些行进入连接结果
配对条件怎样指定 显式 ON、USING、NATURAL ON 写条件；USING 指定同名列；NATURAL 自动选择所有同名列
是否需要条件 有条件连接、CROSS JOIN CROSS JOIN 不筛选配对，产生所有两两组合
两个来源是否为同一张表 不同表连接、自连接 自连接说明来源角色，可使用内连接或外连接

本章优先用显式 ON 表达业务关系。NATURAL 不等于外连接，自连接也不等于一种新的匹配规则；例如 student AS a LEFT JOIN student AS b ON ... 同时属于自连接和左外连接。连接写法参见 PostgreSQL 表表达式说明。

6.1 先判断需要哪些表

题目要查“数据库课选课人的姓名和成绩”。姓名在 student，成绩和课程号在 takes，所以要按学号把两张表连接，再筛选 C1。

本例采用内连接，其结构是 左侧来源 JOIN 右侧来源 ON 配对条件。JOIN 放在 FROM 中，ON 附属于连接，WHERE 则筛选连接产生的行。先给来源起别名，后面的 别名.列名 才能明确指向对应列。

SELECT s.SID, s.name, t.score
FROM student AS s
JOIN takes AS t ON s.SID = t.SID
WHERE t.CID = 'C1';

s、t 是当前语句中的表别名；s.SID 表示学生表的学号。ON 说明哪些行应当配对。这里的 JOIN 是内连接，只保留成功匹配的组合。

SID name score
S1 小林 80
S2 小周 70

连接后，一名学生可以出现多行，因为他可能选了多门课。要先想清楚结果的一行代表“学生”还是“选课”，再决定是否需要去重。

6.1.1 外码已经关联了表，为什么还要写 JOIN？

takes 已有学生外码，为什么查询它仍看不到姓名？先区分“保证引用合法”和“在结果中组合信息”这两个任务。

对比项 外码约束 JOIN
作用 维护数据的引用规则 为本次查询组合来源行
写在何处 表定义等约束声明中 查询的 FROM 子句中
是否补出姓名、课程名 不会 可连接后选择这些列
是否要求先有外码 它本身就是约束 没有外码也可连接，但正确性须自己判断

takes 的学号外码保证 S1 有对应学生，不会在每次查询 takes 时自动输出“小林”。JOIN 中的 s.SID = t.SID 则明确告诉本次查询怎样配对。

对 S1 的 C1 记录，匹配学生表里的 S1，得到姓名和成绩；S1 的 C2 记录还会再匹配一次。这解释了连接结果为什么可以重复出现同一个学号。

两张表都有 SID 时，单写 SID 可能无法判断指哪张表的列；s.SID、t.SID 明确各自来源。连接条件中的等号是在查询中比较值，不是把一边的值赋给另一边。

6.2 三表连接与自然连接的陷阱

要给每条选课同时补上学生姓名和课程名，就需要连接三张表，并明确每一步按哪些列配对：

SELECT s.name, c.title, t.score
FROM student AS s
JOIN takes AS t ON s.SID = t.SID
JOIN course AS c ON t.CID = c.CID;
name title score
小林 数据库 80
小林 程序设计 90
小周 数据库 70
小陈 程序设计 60

自然连接 NATURAL JOIN 自动要求所有同名列相等。若这里连续使用自然连接，dept 也会被当作匹配条件，小周的跨系选课就可能消失。因此应明确写出业务需要的 ON 条件。

若两侧匹配列同名，JOIN takes AS t USING (SID) 可以明确只按 SID 相等配对，并在连接输出中合并这对同名列。USING 的括号中写列名，ON 后写条件；NATURAL 则连列名也自动选择。三者是在指定匹配方式，不能理解为三个保留未匹配行的选项。

CROSS JOIN 则生成所有两两组合。4 位学生与 4 条选课记录交叉连接有 16 行，其中大多数不是正确对应关系。

6.3 外连接：没有匹配的对象也要保留

要列出所有学生，包括没选课的小吴：

SELECT s.SID, s.name, t.CID, t.score
FROM student AS s
LEFT JOIN takes AS t ON s.SID = t.SID;
SID name CID score
S1 小林 C1 80
S1 小林 C2 90
S2 小周 C1 70
S3 小陈 C2 60
S4 小吴 NULL NULL

左外连接保留左侧每行，没有匹配时把右侧列补为 NULL。右外连接对称保留右侧，全外连接保留两侧未匹配行；后两种语法的支持情况要按产品确认。

6.4 ON 与 WHERE 放同一条件，结果可能不同

想列出所有学生，同时只显示他们的高分选课，条件放在哪里才能保留没有高分匹配的人？如果在上述查询末尾加 WHERE t.score >= 80，小吴补出的 NULL 行无法通过条件，小周和小陈的低分行也会被去掉。

若要求“保留所有学生，只展示各人的高分选课”，把成绩条件放到 ON：

SELECT s.SID, s.name, t.CID, t.score
FROM student AS s
LEFT JOIN takes AS t
  ON s.SID = t.SID AND t.score >= 80;

结果有 5 行：小林的 C1、C2 两行，以及小周、小陈、小吴各一条右侧补 NULL 的行。这里补 NULL 表示“没有符合高分条件的匹配记录”，不一定表示完全没选课。

条件位置 先做什么 是否保留所有学生
高分条件在 ON 中 只让高分选课参与匹配，未匹配学生仍补空 是
高分条件在 WHERE 中 先连接并补空，再筛掉成绩条件不为真的行 否

不能为了保留未匹配者就把所有条件移到 ON。若题目只要计算机系学生，WHERE s.dept = '计算机' 是对学生范围的合理筛选；保留范围由题意决定。

6.5 自连接：同一张表也可以扮演两个角色

要找同系学生的不同配对，既要检查一位学生，也要检查另一位学生，两者都来自 student：

SELECT a.SID AS first_sid, b.SID AS second_sid, a.dept
FROM student AS a
JOIN student AS b ON a.dept = b.dept
WHERE a.SID < b.SID;

结果为 S1、S3、计算机，以及 S2、S4、数学。a 和 b 是同一张表在查询中的两个角色，不会创建两张新表。a.SID < b.SID 排除自己配自己，并只保留一对中的一个方向。编号的比较顺序依赖数据库文字规则；本例只涉及 S1—S4。

7. 分组统计：先确定统计对象，再计算

明细能说明每次选课，但“选了多少人”“平均分是多少”需要把多行一起计算。先确定统计对象，再决定是否分组。

7.1 聚集函数把多行汇成一个值

先回答全体选课共有多少条、成绩平均是多少，看看多行怎样汇成一个统计值。“按哪些行计算”与“算出什么”要分别确定：GROUP BY 决定如何分组，COUNT、AVG 等聚集函数决定每组如何计算。下面暂不分组，对全部选课一起计算。COUNT 是函数名，COUNT(score) 才是一次具体调用；括号内写不同对象，统计含义也会改变。

对原始成绩 80、90、70、60：

表达式 计算内容 结果
COUNT(*) 全部行数 4
COUNT(score) 成绩非空的行数 4
COUNT(DISTINCT SID) 不重复且非空的学生学号数 3
SUM(score) 成绩总和 300
AVG(score) 平均成绩 75
MIN(score) 最低成绩 60
MAX(score) 最高成绩 90 
SELECT COUNT(*) AS record_count,
       COUNT(DISTINCT SID) AS student_count,
       AVG(score) AS avg_score
FROM takes;

结果是一行：4 条选课、3 位学生、均分 75。选课条数与选课人数不同。

除 COUNT(*) 外，表中针对某列的这些聚集会忽略 NULL。因此第 5 节成绩通知的均分是 (80 + 0) / 2 = 40，不是除以 3。空输入时，COUNT 返回 0，SUM、AVG、MIN、MAX 返回 NULL。

“忽略 NULL”不等于忽略零，零是已知值，参与平均分的分母。AVG(COALESCE(score, 0)) 会先把缺值按零处理，成绩通知的均值就变为 80 / 3，它与“只对已知成绩求平均”采用了不同统计口径。

7.2 GROUP BY：每组产生一行统计结果

如果要分别统计每门课的人数和均分，就不能把所有选课合成一个值，需要按课程划分计算范围：

SELECT CID, COUNT(*) AS n, AVG(score) AS avg_score
FROM takes
GROUP BY CID;

先按课程号分组：C1 包含 80、70，C2 包含 90、60。然后分别统计：

CID n avg_score
C1 2 75
C2 2 75

C3 没在 takes 中出现，因此没有 C3 的组。

若输出中再放一个未经聚集的 SID，一个课程组有多个学生，就不能确定输出谁的学号。入门时采用清楚的写法：非聚集输出列写入 GROUP BY。部分标准和产品支持函数依赖等例外，这里不依赖这些规则。

多列分组按组合划分。例如 GROUP BY SID, CID 将同一个学生、同一门课放到同一组；本例组合主码使每组恰好一条选课，不能用它代替“每门课一组”的 GROUP BY CID。

写法 处理什么 是否汇成统计行
GROUP BY CID 配合聚集 按课程划分计算组 每个课程组输出一行
ORDER BY CID 调整结果显示顺序 不会合并行
SELECT DISTINCT CID 去掉相同课程号输出 只保留名单，未计算人数或平均分

分组后是否按课程号显示，仍要由 ORDER BY 指定。没有 GROUP BY 的聚集查询将全部输入作为一组；有 GROUP BY 时，空输入没有分组，因此返回零行，而不是凭空补出每个课程的零计数。

7.3 WHERE 筛行，HAVING 筛组

要找平均成绩至少为 75 的课程，需要先计算各课程的平均分，再筛选符合要求的课程组：

SELECT CID, AVG(score) AS avg_score
FROM takes
GROUP BY CID
HAVING AVG(score) >= 75;

C1、C2 都保留。HAVING 检查的是已经形成的组。

如果改为先用 WHERE score >= 80，分组前就只剩 80 和 90，C1、C2 的均分会变成 80、90。两种写法回答的问题不同。

条件 放在哪里 原因
只统计 C1 的选课 WHERE CID = 'C1' 判断单条记录即可
只统计已公布成绩 WHERE score IS NOT NULL 先筛掉缺值记录
只保留选课数至少 2 的组 HAVING COUNT(*) >= 2 必须先算组内数量

WHERE 与 HAVING 可以同时出现。例如“在计算机系学生的选课中，找选课记录至少两条的课程”：

SELECT t.CID, COUNT(*) AS n
FROM takes AS t
JOIN student AS s ON t.SID = s.SID
WHERE s.dept = '计算机'
GROUP BY t.CID
HAVING COUNT(*) >= 2;

先筛掉小周的记录，剩小林 C1、小林 C2、小陈 C2；分组得到 C1 一条、C2 两条；HAVING 最后只保留 C2、2。题目中的“计算机系学生”在筛选学生范围，“至少两条”在筛选统计后的组。

7.4 零选课也要统计：外连接后数哪一列

统计每门课的选课人数时，高数虽然没有选课，也应显示为 0。怎样保留它，并避免把外连接补出的空行数成一次选课？

SELECT c.CID, COUNT(t.SID) AS n
FROM course AS c
LEFT JOIN takes AS t ON c.CID = t.CID
GROUP BY c.CID;
CID n
C1 2
C2 2
C3 0

C3 有一条补 NULL 的行。COUNT(*) 会把它数成 1；COUNT(t.SID) 只数真实选课行，因为真实选课的学号非空。

如果改数 COUNT(t.score)，遇到已选课但成绩未公布的记录，就会少算。统计“选课数”应数真实选课的键，统计“已公布成绩数”才数 score。选对函数后，还必须选对被统计的列。

7.5 把完整查询按逻辑顺序读一遍

一个查询同时包含连接、筛选和分组时，怎样判断每一步给下一步留下了哪些行？书写时常见顺序是：

SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY

理解普通分组查询时，可按下面的顺序推导：

确定来源与连接 → WHERE 筛行 → GROUP BY 分组
→ 计算组内聚集值 → HAVING 筛组
→ 形成 SELECT 输出 → DISTINCT 去重 → ORDER BY 排序

其中 GROUP BY、HAVING、ORDER BY 是子句，COUNT、AVG 是可写在 SELECT 或 HAVING 等位置的函数，DISTINCT 是 SELECT 的去重选项。完整查询可同时使用它们；“选用哪个子句”和“在子句里调用哪个函数”是两个问题。HAVING 能判断平均分，是因为它检查的已经是组及其聚集值。

这是帮助理解结果的逻辑顺序，数据库优化器的实际执行计划可能不同。窗口函数等进阶功能还有自己的计算阶段。

8. 集合运算：组合两份查询结果

已经分别查出两份学生名单，怎样得到“任一名单中的人”“共同出现的人”或“只在第一份中的人”？完整结构是 左侧查询 集合运算符 右侧查询。先分别得到两份结果，再决定取并集、交集还是差集。ALL 是保留出现次数的修饰选项；UNION ALL 是 UNION 的一种完整写法，不是与并、交、差平行的第四种基本集合关系。

选 C1 的学生名单是 S1、S2；选 C2 的名单是 S1、S3。

运算写法 要找什么 结果
UNION 至少在一个名单中 S1、S2、S3
INTERSECT 两个名单都有 S1
EXCEPT 在左名单，且不在右名单 S2
UNION ALL 合并并保留出现次数 S1 两次，S2、S3 各一次

选 C1 但没选 C2：

SELECT SID FROM takes WHERE CID = 'C1'
EXCEPT
SELECT SID FROM takes WHERE CID = 'C2';

EXCEPT 有方向，交换两侧会得到 S3。普通 UNION、INTERSECT、EXCEPT 对结果去重；带 ALL 的版本按出现次数处理，支持情况不同。

两侧输出列数必须相同，对应位置的类型要兼容，不能只看列名是否一致。多个集合运算混用时要明确分组和最终排序的作用范围，具体语法按产品调整。

例如“选过 C1 或 C2 的学生学号”：

SELECT SID FROM takes WHERE CID = 'C1'
UNION
SELECT SID FROM takes WHERE CID = 'C2';

把 UNION 换成 INTERSECT 就是“两门都选过”；换成 UNION ALL 则保留两个名单中的每次出现。集合查询比较两侧 SELECT 的输出行，本例只输出 SID，因此 S1 的两次出现可以合并。如果输出还包含 CID，则 (S1,C1) 与 (S1,C2) 是不同的行，不会被合并。

对比项 JOIN UNION 等集合运算
在组合什么 不同来源中可配对的行及其字段 结构兼容的查询结果
典型目的 给选课补上姓名 合并两份学生名单
如何判断对应 ON 中的条件 输出列按位置对应

JOIN 后一行可以同时有学生和选课信息；UNION 的两侧则需要输出相同列数，不能用它直接给选课附加姓名。

9. 子查询：把复杂问题拆成可以回答的小问题

有些筛选条件依赖另一份名单、一个统计值或另一条记录是否存在。先用内层查询回答这个小问题，再供外层完成整体任务。

9.1 先判断内层结果是什么

内层可能返回一个值、一份名单或多列结果，外层该怎样使用它？子查询是一条查询嵌在另一条语句里。选择写法时分开考虑三个角度：

角度 要问的问题 例子
结果形状 外层需要一个值，还是一组行列？ 标量子查询提供一列至多一行；其他用法可以处理多行
使用位置和目的 外层要比较、判断存在，还是把结果当作来源？ 比较位置、IN／EXISTS 条件、FROM 中的派生表
对外层的依赖 内层是否引用当前外层行？ 相关子查询引用外层列；非相关子查询不引用

这些不是互斥分类：标量子查询也可以相关，EXISTS 的子查询也可以不相关。WITH 则用于给当前语句中的辅助查询命名，不是判断结果属于名单还是单值的新类别。

明确这三点后，再按题意选常用表达：

外层要回答的问题 常用组合写法
得到一份名单 IN (SELECT ...)
得到一个值 标量子查询，如平均分
与一组数比较 SOME / ANY / ALL
是否存在匹配记录 EXISTS
是否不存在匹配记录 NOT EXISTS
是否每个要求都满足 寻找反例，常用双重 NOT EXISTS

表中列的是解题方式。例如 IN (SELECT ...) 由 IN 条件与内层查询组成；双重 NOT EXISTS 则是两层存在性条件的组合，不是一个单独关键字。

子查询是不是真正“先执行”，由优化器决定。这里按内外层来读，是为了理解条件。

9.2 IN：名单中有没有这个学生

要找选过 C1 的学生，可以先查出选课学号名单，再检查学生表的学号是否在名单中：

SELECT SID, name
FROM student
WHERE SID IN (
    SELECT SID
    FROM takes
    WHERE CID = 'C1'
);

内层得到 S1、S2，外层找到这两位学生，结果为 S1 小林、S2 小周。内层没有引用外层变量，称为非相关子查询。

IN 关心当前学号是否属于名单，名单中重复出现同一学号不会让外层学生重复输出。子查询选出的列应与左侧比较值对应；本例左侧是 SID，内层就应输出学号，不应误选课程号。

9.3 标量子查询：把平均分当作一个比较值

要找高于全体平均分的选课，比较基准不是固定常量，需要先用查询算出这个值：

SELECT SID, CID, score
FROM takes
WHERE score > (SELECT AVG(score) FROM takes);

平均分为 75，结果是 S1、C1、80 和 S1、C2、90。

标量子查询应返回一列、至多一行。按课程 SQL 口径，返回零行时得到 NULL，返回多行时出错。没有 GROUP BY 的聚集查询即使输入为空，也会给出一个聚集结果行，例如 AVG 的结果为 NULL。

标量子查询用在需要一个值的位置。若把内层换成 SELECT score FROM takes，它会得到四行，不能作为一个普通比较值使用；此时要根据题意选择 IN、SOME、ALL 或先聚集，不能任意取一行来消除报错。

9.4 SOME 与 ALL：至少一个，还是每一个

要把一个成绩与内层的多个成绩比较，是超过其中至少一个就算满足，还是必须超过每一个？SOME／ANY／ALL 说明比较要满足多少个内层值，前面的比较运算符才说明怎样比较。基本结构是 比较值 比较运算符 SOME／ANY／ALL (子查询)，例如 score > ALL (...)。不能把 ALL 自己理解成“大于所有值”；写成 < ALL 时，要求的是小于所有值。

SOME 与 ANY 同义。以 C1 的成绩集合 {80, 70} 为例：

比较值 大于至少一个值：> SOME 大于每个值：> ALL
90 真 真
75 真 假
60 假 假

课程风格的例子：

SELECT SID, CID, score
FROM takes
WHERE score > ALL (
    SELECT score FROM takes WHERE CID = 'C1'
);

结果只有 S1、C2、90。SOME/ANY/ALL 并非所有数据库都支持。结果中含 NULL 时，需要按三值逻辑判断；子查询为空集时，ALL 为真，SOME 为假。

空集情况下，ALL 没有任何反例，所以成立；SOME 找不到一个成立的比较，所以不成立。有 NULL 时，也不能简单把 ALL 改成“比最大值大”：对 {80,NULL}，90 大于 SOME 为真、大于 ALL 为未知；60 大于 ALL 为假，因为它已经不大于 80。可核对 PostgreSQL 子查询条件说明。

9.5 EXISTS：当前学生有没有选课

如果只想列出选过课的学生，每人出现一次，就只需判断当前学生是否存在选课记录。EXISTS (子查询) 是一个判断真假的条件，不是把内层结果列复制到外层。内层先说明“找哪些记录”，EXISTS 再判断有没有这样的行。下面用内层的 t.SID = s.SID 将这个判断限定到当前学生。

SELECT s.SID, s.name
FROM student AS s
WHERE EXISTS (
    SELECT 1
    FROM takes AS t
    WHERE t.SID = s.SID
);

对当前外层学生，内层检查有没有对应选课。结果是小林、小周、小陈。内层用了外层的 s.SID，称为相关子查询。

SELECT 1 只表达“有行即可”，这里的 1 不是计数，也不要求内层返回恰好一行。EXISTS 根据有没有行判断，不要求那些行的输出值非空。

把 EXISTS 改为 NOT EXISTS，得到没选课的小吴。若漏掉 t.SID = s.SID，检查的就变成整个选课表有没有记录，四位学生都会满足 EXISTS。

当前外层学生 内层使用的匹配条件 找到几条选课 EXISTS
S1 t.SID = 'S1' 2 真
S2 t.SID = 'S2' 1 真
S3 t.SID = 'S3' 1 真
S4 t.SID = 'S4' 0 假

这是理解相关性的逐人推导，数据库不一定真的按这种逐人循环执行。s.SID 指当前外层学生，t.SID 指内层检查的选课记录，不能省略这层对应关系。

查询目标 合适的表达
只要知道学生是否选过课 IN 或正确相关的 EXISTS
还要显示每门课程的成绩 JOIN，把选课明细组合进来
要找完全没有选课的学生 正确相关的 NOT EXISTS

在原数据上，内连接会产生四条选课结果，EXISTS 则保留三位学生各一次。选择方法先看结果的一行要代表什么，不需要为了展示姓名之外并未要求的信息而增加连接。

9.6 双重 NOT EXISTS：把“全部满足”改写为“没有缺项”

另有必选课程表 required(CID)，含 C1、C2。要找两门都选过的学生，允许他们还选了其他课。

直接想“所有课都选了”容易绕。换成“没有一门必选课是他没选的”，就能分层写出条件：

SELECT s.SID, s.name
FROM student AS s
WHERE NOT EXISTS (
    SELECT 1
    FROM required AS r
    WHERE NOT EXISTS (
        SELECT 1
        FROM takes AS t
        WHERE t.SID = s.SID AND t.CID = r.CID
    )
);

从内到外读：

  1. 最内层查“当前学生是否选了当前必选课”。
  2. 内层 NOT EXISTS 为真，表示这门课缺了。
  3. 中层收集这个学生所有缺的必选课。
  4. 外层 NOT EXISTS 要求缺课名单为空。
学生 缺的必选课 是否留下
S1 小林 无 是
S2 小周 C2 否
S3 小陈 C1 否
S4 小吴 C1、C2 否

结果只有小林。如果必选课表为空，每位学生都没有缺项，所以全部满足条件。若业务还要求“至少选一门”，需要再加一个存在性条件。候选学生来自 student，不能默认与直接对 takes 做关系除法的候选范围相同。

9.7 派生表与 WITH：给中间结果起名字

复杂查询常需要先统计、再筛选。怎样把中间结果当作来源读取，让每一步的用途更清楚？先区分命名位置：派生表写成 FROM (子查询) AS 别名，外层通过别名读取它的列；CTE 写成 WITH 名称 AS (辅助查询) 主查询，主查询再把该名称作为来源。这里的 AS 用来引出辅助查询或给来源命名，不能脱离所在结构理解成永久改名。

把“每课平均分”先写成一个中间结果，可以降低外层查询的阅读难度。放在 FROM 中的子查询称为派生表：

SELECT x.CID, x.avg_score
FROM (
    SELECT CID, AVG(score) AS avg_score
    FROM takes
    GROUP BY CID
) AS x
WHERE x.avg_score >= 75;

同样的逻辑也可用公共表表达式 CTE：

WITH course_average AS (
    SELECT CID, AVG(score) AS avg_score
    FROM takes
    GROUP BY CID
)
SELECT CID, avg_score
FROM course_average
WHERE avg_score >= 75;

两种写法都得到 C1、75 和 C2、75。WITH 定义的是这条语句内可引用的名字，不是建立永久表，也不保证物理上只计算一次。

在派生表写法中，内层 SELECT 输出 CID 和 avg_score，外层把它作为 x 使用，所以写 x.avg_score。内层的原始 score 没有作为输出列提供，外层不能把它当作 x 的列读取。WITH 写法中的 course_average 起同样的命名作用；别名和临时结果的可见列，都由对应层的定义决定。

9.8 扩展：LATERAL 与 UNIQUE 谓词

如果 FROM 中的内层查询也要按当前学生计算，怎样引用外层提供的学号？LATERAL 允许 FROM 中的子查询引用左侧来源的当前行。例如对每位学生单独统计选课数：

SELECT s.SID, x.n
FROM student AS s,
LATERAL (
    SELECT COUNT(*) AS n
    FROM takes AS t
    WHERE t.SID = s.SID
) AS x;

预期结果为 S1、2；S2、1；S3、1；S4、0。它是原资料中的进阶语法，支持情况和替代写法取决于产品。

其中 s 是左侧的当前学生，侧向子查询引用 s.SID，x 为该学生的计数结果起名，x.n 读取它的计数列。这里不带 GROUP BY 的 COUNT 即使没有匹配选课也产生一行计数 0，因此 S4 仍有对应结果。普通 FROM 子查询不能任意引用相邻来源，LATERAL 明确允许这种依赖。

有时只需要判断一份查询结果有没有重复，而不需要把重复行去掉。UNIQUE (子查询) 是课程介绍的“子查询结果是否无重复”的谓词，区别于建表时的唯一约束。它支持有限，含 NULL 时还有比较细节；先掌握 DISTINCT 和分组检查，再学习此谓词即可。

例如 SELECT SID FROM takes 会产生 S1、S1、S2、S3，存在重复；SELECT DISTINCT SID FROM takes 则产生 S1、S2、S3。判断重复、去除重复、禁止将来写入重复是三种用途，分别对应这类谓词、DISTINCT 和表上的 UNIQUE 约束，不应互相替代。

10. 数据修改与 CASE：区分改变数据和计算显示值

新增学生、取消选课和更正成绩需要改变已保存的数据；按成绩显示“及格”标签则只需计算输出值。先按任务区分操作。

10.1 INSERT：增加一条记录

新生入学后，需要在学生表中新增一行，而不是改掉已有学生。本例在原始数据上增加数学系学生小赵：

INSERT INTO student (SID, name, dept)
VALUES ('S5', '小赵', '数学');

列名与值按位置对应。结果是学生表新增 S5 这一行，不会自动为他生成选课。若学号已存在，则违反主码约束。

INSERT INTO 目标表(列) SELECT ... 可把查询结果插入另一张表，列数、类型和约束仍必须符合要求。

例如另建高分记录表，并复制原始数据中至少 80 分的两条选课：

CREATE TABLE high_score_copy (
    SID CHAR(2),
    CID CHAR(2),
    score NUMERIC(5,2),
    PRIMARY KEY (SID, CID)
);

INSERT INTO high_score_copy (SID, CID, score)
SELECT SID, CID, score
FROM takes
WHERE score >= 80;

目标表得到 S1、C1、80 和 S1、C2、90。SELECT 提供要插入的行，INSERT 按目标列顺序写入。这是复制当时的值，以后 takes 的成绩变化不会自动更新这份副本；重复执行时还可能违反目标表主码。

10.2 DELETE：删除符合条件的行

取消一次选课，应删除对应的选课记录。下面独立从原始数据出发，取消小周的 C1 选课：

DELETE FROM takes
WHERE SID = 'S2' AND CID = 'C1';

选课表剩三行；学生表中的小周仍存在。省略 WHERE 会删除选课表全部行，但保留表结构。

10.3 UPDATE：更改已有行

成绩录错后，需要定位已有选课行并更正成绩。下面独立从原始数据出发，将小周的 C1 成绩更正为 75：

UPDATE takes
SET score = 75
WHERE SID = 'S2' AND CID = 'C1';

只有这条选课记录的成绩变化。SET 指定新值，WHERE 决定修改哪些行。若目标是更正一次选课，条件就应能定位那次选课。

SET score = score + 5 左边的 score 表示被修改的列，右边的 score 表示当前行原来的值。它与 SET score = 5 不同：前者在原值上加 5，后者直接改为 5。更新后的值仍须满足主码、外码和 CHECK 等约束。

操作 原选课行数 操作后的选课行数
INSERT 新选课 4 合法插入一条后变为 5
DELETE 小周的 C1 4 3
UPDATE 小周的 C1 成绩 4 4

三种操作分别新增行、删除行、改变已有行的值。UPDATE 省略 WHERE 会尝试修改所有行；计算显示值的 SELECT 则不会执行这些修改。

这些修改语句用于说明例题效果，不要求执行。实际修改前，可以先用相同条件的 SELECT 确认目标行，再结合事务处理。

10.4 CASE：根据条件选一个值

要把分数显示成“及格”“不及格”等标签，需要根据每行的条件选择一个输出值。CASE 是计算值的表达式，可放入 SELECT 的输出列表或 UPDATE 的 SET 中；它本身不是修改数据的语句。本节使用的条件型结构如下：

CASE
    WHEN 条件1 THEN 值1
    WHEN 条件2 THEN 值2
    [ELSE 其余情况下的值]
END

CASE 与 END 包围整个表达式，WHEN／THEN 组成分支，ELSE 是可选的兜底分支。选择值的规则与“这个值最后用来显示还是写入”是两个层次。下面把完整表达式放到 SELECT 中，再用 AS 为它的输出命名。

SELECT SID, CID, score,
       CASE
           WHEN score IS NULL THEN '未公布'
           WHEN score >= 80 THEN '达标'
           ELSE '待提高'
       END AS status
FROM takes;

WHEN 后是条件，THEN 后是条件为真时的值，ELSE 处理其余情况，END 结束表达式。按顺序选择第一个条件为真的分支。

原始数据中，小林两条记录为“达标”，小周、小陈为“待提高”。本例没有空成绩，但提前写出缺值分支，避免把未知成绩误归为待提高。

同一段 CASE 放进 UPDATE takes SET score = CASE ... END 时，才会把算出的值用于修改成绩；其中的分支返回值还必须适合 score 的类型。本例返回的是文字标签，适合显示状态，不能直接用来更新数值成绩。

例如将分段顺序写成“先 score >= 60，再 score >= 80”，80 分会先命中前一个条件，后一个分支就不会被采用。范围重叠时应先判断较具体的高分段；条件不为真时才继续检查下一分支。没有 ELSE 且无条件为真时，CASE 的结果为 NULL。

11. 视图：保存一份查询定义

同一份筛选查询经常重复使用，能否把它保存成一个名称，以后直接引用？普通视图保存的就是这份查询定义。

11.1 为什么需要视图

经常查询计算机系学生，可以把这份查询命名：

CREATE VIEW cs_student AS
SELECT SID, name, dept
FROM student
WHERE dept = '计算机';

然后使用：

SELECT SID, name
FROM cs_student;

结果为小林、小陈。普通视图保存查询定义，通常不独立存一份完整查询结果；基础表变化后，查询视图会反映相应变化。物化视图保存结果，需要按其刷新机制维护，两者不能混淆。

视图可以简化重复查询、只展示某些列或行。是否真正限制访问，还需要配合权限设置。

读代码时，CREATE VIEW cs_student 指定视图名，AS 后的 SELECT 是它保存的查询定义，student 是基础表。以后查询 cs_student，就按这个定义取得当时符合条件的学生。

形式 名字在哪个范围使用 保存什么
一条普通 SELECT 本次查询 产生本次结果
WITH course_average AS (...) 同一条语句内 给中间查询起名字
CREATE VIEW cs_student AS ... 创建后可在后续语句中引用，直到对象被移除 保存查询定义
将 SELECT 结果 INSERT 到另一张表 目标表继续存在 保存插入时的数据值

视图适合反复使用的查询定义，WITH 适合组织当前这条复杂查询。普通视图也不同于复制出的 high_score_copy，不会把当前结果冻结成一份独立数据。

11.2 为什么有些视图不能直接更新

能从视图读取数据，是否也能直接修改它？这取决于视图中的变更能否明确对应到基础表。单表筛选视图中的一行，通常能明确对应基础表的一行；聚集视图中的一行则可能代表多条记录。

例如视图显示“C1 的平均分是 75”。把它改成 85，究竟应修改谁的成绩、各改多少？只有这个要求，无法确定基础表怎样变化。

包含聚集、分组、去重和集合运算的视图通常不能按简单规则更新。连接视图、触发器支持的更新等情况由产品决定。判断可更新性时，要问“这次修改能否明确转换为基础表修改”，不能只看视图能不能查询。

假设数据库支持这个简单单表视图的更新，经 cs_student 将 S1 的姓名改为“小林同学”，可以明确对应 student 中的 S1 行。更新的是基础表，不会另外生成一位“视图里的学生”。插入视图还要考虑它没展示的基础表必填列，不能仅凭单表结构就保证任何插入都合法。

各产品对普通视图更新支持不同。本文件使用的 SQLite 校验不能证明视图可直接更新；这里说明的是映射是否明确，实际支持需核对所用 DBMS。

11.3 WITH CHECK OPTION：修改后仍须留在视图范围内

通过“计算机系学生”视图修改学生的系后，他可能从视图中消失。若希望禁止这类变更，就需要检查修改后是否仍符合视图条件。先把视图定义分成三部分：CREATE VIEW 名称 AS 创建命名对象，SELECT 定义可见内容，末尾可选的 WITH CHECK OPTION 规定经视图变更后的检查要求。这项选项依附于 CREATE VIEW，不是另一条独立语句。

虽然同样出现 WITH，WITH CHECK OPTION 与第 9.7 节开头的 WITH 名称 AS (...) 不是同一种结构：前者为视图增加检查，后者定义当前语句的 CTE。识别关键词还要看它的位置和后续组成。

CREATE VIEW cs_student_checked AS
SELECT SID, name, dept
FROM student
WHERE dept = '计算机'
WITH CHECK OPTION;

通过这个视图插入或修改数据后，仍须符合“所在系是计算机”的条件。若通过它把小林改为数学系，就会违反检查选项。

它约束的是经该视图进行的变更，不代表基础表通过其他入口也不能修改。具体可更新条件以及嵌套视图的 LOCAL、CASCADED 检查范围，要按产品确认。

在产品支持该视图更新的前提下，比较两种情况：

通过视图修改什么 是否符合视图条件 CHECK OPTION 的判断
小林的姓名改为“小林同学” 仍是计算机系 不因视图条件被拒绝，仍需满足其他约束
小林的系改为“数学” 不再是计算机系 拒绝

没有 CHECK OPTION 时，某些支持更新的产品可以完成第二种修改，随后该学生从视图中消失。CHECK OPTION 检查视图的筛选条件，表上的 CHECK 检查基础表规则，两者范围不同。参见 PostgreSQL 视图与检查选项说明。

12. 事务：让一组操作作为整体提交

转账需要扣款和入账一起成功；只完成一半就会留下错误余额。事务用来规定这一组操作何时整体提交、何时撤销。

12.1 为什么两条更新需要放在一起

另有独立教学表 transfer_account(owner, balance)：甲有 500 元，乙有 300 元。甲转给乙 200 元，扣款和入账应作为一个整体。

START TRANSACTION;

UPDATE transfer_account
SET balance = balance - 200
WHERE owner = '甲';

UPDATE transfer_account
SET balance = balance + 200
WHERE owner = '乙';

COMMIT;

成功提交后，甲 300、乙 500。若在提交前发生失败并执行 ROLLBACK，应撤销这次事务的变更，回到甲 500、乙 300。

阶段 本事务内甲的余额 本事务内乙的余额 是否已经整体提交
开始前 500 300 原状态
只执行扣款 300 300 否，仍是中间状态
再执行入账 300 500 否，等待提交
COMMIT 成功后 300 500 是
提交前选择 ROLLBACK 恢复为 500 恢复为 300 本次变更撤销

成功时 COMMIT，取消或处理失败时 ROLLBACK。不能先提交，再期待回滚撤销已提交的转账。其他事务能看到什么取决于隔离规则；此表只推导本事务内的变化。

12.2 提交、回滚与自动提交

一组更新已经执行后，怎样决定保留它们还是撤销它们？还需要确认环境是否已自动提交。事务是一组操作的处理边界，COMMIT、ROLLBACK 是控制这个边界的命令，自动提交是运行环境的提交方式。它们不是四种并列的事务类型。

层次与概念 含义
事务开始 开始一组需要整体处理的操作
COMMIT 提交本次事务
ROLLBACK 撤销尚未提交的事务变更
自动提交 环境可能默认每条语句各自提交

若两条 UPDATE 已分别自动提交，之后回滚不能自动撤销先前已提交的扣款。事务开始语法和自动提交设置存在产品差异。

语句出错后，系统是撤销该语句、使整个事务进入失败状态，还是采用其他处理，产品之间不同。应用应检查结果并按规则回滚，不能默认任何错误都会自动完成所需恢复。参见 PostgreSQL 事务教程。

这个例子用于理解边界，不是完整转账程序。业务还需检查账户是否存在、余额是否足够、修改行数是否符合预期，并正确处理并发。事务原理可接着阅读第 6 单元。

13. 权限与角色：规定谁能做什么

多人共用数据库时，并非每个账号都应有权读取或修改所有表。需要按使用者的职责规定操作范围，并管理授权。

13.1 GRANT 与 REVOKE

让老师读取课程表、以后再收回这项权限，该怎样说明允许的操作、对象和接收者？对象授权的基本结构是 GRANT 权限 ON 对象 TO 接收者；撤回则是 REVOKE 权限 ON 对象 FROM 接收者。先选允许的操作，再明确操作对象和接收者。SELECT 在 GRANT 中是权限名称，不是接在后面执行的一条 SELECT 查询。

教师账号需要读取课程表，可以授予 SELECT 权限：

GRANT SELECT ON course TO teacher_user;

若需要撤回这一授权：

REVOKE SELECT ON course FROM teacher_user;

两条语句分别展示授予和撤回，不要求连续执行。常见权限还有 INSERT、UPDATE、DELETE、REFERENCES，部分产品也支持列级权限。账号和对象须已存在，执行者须具备相应授权能力。

拆开第一条语句看：GRANT 表示授予，SELECT 是允许的操作，ON course 是操作对象，TO teacher_user 是接收账号。REVOKE 则收回某项授权来源。

权限 允许的操作 不自动包含什么
SELECT 读取数据 不自动授予修改权限
INSERT 插入数据 不免除主码、外码等检查
UPDATE 修改数据 不自动授予再向他人授权的能力
DELETE 删除数据行 不等于 DROP 表结构权限
REFERENCES 建立相应外码引用所需的权限 不等于读取被引用表全部数据

账号可能从直接授权、角色等多个来源获得权限。撤回一条来源后，还需检查其他来源，才能判断是否彻底失去某项操作能力。

13.2 角色用于集中管理权限

多位老师需要相同权限，逐个账号授权容易遗漏；可以先把共用权限集中到一个角色中。这里有两步授权：先将对象权限授给角色，再将角色授给账号。它们是 GRANT 的两种形式，而不是把角色名当作操作权限：

授予内容 写法结构 例子中的含义
对象权限 GRANT 权限 ON 对象 TO 接收者 teacher_role 得到课程读取权限
角色成员资格 GRANT 角色 TO 接收者 teacher_user 获得 teacher_role 的成员资格 
CREATE ROLE teacher_role;
GRANT SELECT ON course TO teacher_role;
GRANT teacher_role TO teacher_user;

先给“教师角色”权限，再把角色赋予教师账号。角色是可命名的权限集合。用户可以拥有多个角色，启用和继承规则由产品决定。

三行代码依次创建角色、给角色课程读取权限、把角色授给账号。若有十位教师，可让他们按产品规则加入同一角色，统一管理权限。

角色授权中的 TO teacher_user 说明谁获得角色；对象授权中的 ON course 说明权限针对哪个对象。这两类 GRANT 的意义要分别读。

13.3 WITH GRANT OPTION 与授权传播

获得读取权限的人，是否还可以把它授给别人？允许操作与允许转授，需要分别决定。WITH GRANT OPTION 是对象授权语句末尾的可选部分，回答“接收者能否继续授出收到的权限”。它不是另一种数据操作权限，也不是用于命名辅助查询的 CTE。先确定授出什么，再决定是否允许转授。

GRANT SELECT ON course TO teacher_user WITH GRANT OPTION;

它允许接收者继续向他人授予收到的对象权限。假设表拥有者 O 授给甲，甲再授给乙，授权路径可写成 O → 甲 → 乙。

撤回甲的授权来源时，乙依赖这条路径的权限可能随之撤回。若乙还直接获得 O 的授权，就要考虑另一条有效路径，不能直接断言乙失去全部同类权限。

CASCADE 表示传播撤回，RESTRICT 表示存在依赖时阻止撤回；可用语法和多路径处理规则按产品核实。角色成员资格与对象权限的转授规则也可能不同。

在支持这种写法的产品中，下面展示两个独立方案，都假设甲从拥有者获得可转授的读取权限，乙仅依赖甲的转授。其中 teacher_user 代表甲，且执行者有权收回这条授权：

REVOKE SELECT ON course FROM teacher_user CASCADE;

REVOKE SELECT ON course FROM teacher_user RESTRICT;

第一种允许连带撤回乙依赖该路径的权限；第二种在这类依赖仍存在时拒绝撤回。CASCADE、RESTRICT 是 REVOKE 如何处理授权依赖的选项，不是 GRANT 的权限名称，也不要求写 ON DELETE。具体规则参见 PostgreSQL REVOKE 说明。

没有 WITH GRANT OPTION 时，能读取 course 不表示能给别人授予这项权限；有该选项时，可转授收到的对象权限，也不意味着自动获得修改课程的能力。角色成员资格的再授予涉及另一套规则，不应照搬对象权限的选项。参见 PostgreSQL GRANT 说明。

这里的 CASCADE 沿授权依赖撤回权限；第 3 节外码中的 CASCADE 沿引用关系改变数据行。同一个关键字，需要结合所在语句理解对象。

以下是进阶内容。首次学习可以先完成第 18、19 节练习，再回来阅读。

14. 用户定义类型与域：复用含义和规则

不同字段可能用同一种基础类型，却代表不同含义；多张表也可能反复使用同一套取值规则。类型与域分别帮助处理这些需求。

14.1 独立类型侧重类型身份

学号与课程号都可以用字符串表示，但将课程号传到需要学号的位置，可能是程序错误。具有独立身份的用户定义类型，可以帮助系统检查是否混用了不同含义的数据。

原资料采用的课程标准风格例子是：

CREATE TYPE StudentId AS VARCHAR(10) FINAL;

StudentId 是类型名，VARCHAR(10) 是底层表示；FINAL 在该语境中说明不能再作为可继承的父类型。具体产品可能不支持此写法，或使用不同的类型体系。

强类型检查关注类型身份是否匹配，并不保证全部业务逻辑正确。

14.2 域侧重在已有类型上附加规则

如果多张表都需要 0 到 100 的成绩，可以定义一个域来复用规则：

CREATE DOMAIN Score AS NUMERIC(5,2)
CHECK (VALUE >= 0 AND VALUE <= 100);

VALUE 代表待检查的值。110 不满足规则；未加非空要求时，NULL 仍遵循 CHECK 的未知处理。

域还要被列声明采用，才会约束该列。例如在支持域的数据库中，另建教学表：

CREATE TABLE exam_result (
    SID CHAR(2) PRIMARY KEY,
    score Score
);

这里 score 使用前面定义的 Score 域，80 通过范围检查，110 不通过。只定义域却继续把列写成普通 NUMERIC，不会让它自动获得域规则。域便于多个列复用规则；定义和使用都需产品支持。

对比角度 独立用户定义类型 域
本节强调的用途 区分数据的类型身份 复用基础类型及其约束
例子 学号类型与课程号类型 合法成绩域
与基础类型的关系 可能需要显式转换 通常更容易互操作

原资料记录的参考答案把差别概括为“类型强检查、域弱检查；域可定义约束”。学习时应限定在课程的类型区分语境，不能把“所有用户定义类型都不能有约束”当成跨产品结论。

15. 程序调用 SQL：把输入值安全地交给数据库

学生在应用中输入学号后，程序怎样查询数据库并显示结果？除了执行 SQL，还要处理连接、传入值和返回数据。

15.1 连接接口与结果集

SQL 写好后，程序还需要把它交给数据库执行，再逐行读取返回结果。JDBC 是 Java 的数据库访问接口，ODBC 是另一种通用访问接口。这里的“连接”指应用与数据库的会话，区别于拼接数据表的 JOIN。

典型过程是：建立连接，准备语句，绑定参数，执行，读取结果集，释放资源。结果集是查询返回的行；查不到学生时可以是零行。

15.2 参数化语句与 SQL 注入

查询条件来自用户输入时，怎样传入学号，又避免输入中的符号改变 SQL 的结构？下面用 JDBC 将学号作为参数绑定：

SELECT SID, name
FROM student
WHERE SID = ?;

? 是接口使用的参数占位符，程序通过绑定方法传入 S1，不是让读者直接把问号当普通值执行。其他接口可能使用不同占位符。

JDBC 的核心调用可以写成下面的片段，假设连接 conn 已建立，资源管理由外层完成：

PreparedStatement stmt = conn.prepareStatement(
    "SELECT SID, name FROM student WHERE SID = ?"
);
stmt.setString(1, "S1");
ResultSet rs = stmt.executeQuery();
while (rs.next()) {
    String name = rs.getString("name");
}

prepareStatement 接收语句模板，setString(1, "S1") 绑定第一个占位符，参数编号从 1 开始。executeQuery 执行查询，next 移到下一结果行；没有匹配行时循环不进入。S1 作为值传入，不需要自己拼接 SQL 单引号。实际代码还需释放语句、结果集等资源。参见 Oracle JDBC 参数化语句教程。

若直接把用户输入拼进 SQL 文本，输入中的引号等符号可能变成查询结构，导致 SQL 注入。参数绑定让输入按值处理。预编译语句可以准备后反复绑定值执行，但是否复用计划、节省多少时间取决于环境。

参数通常不能替代表名、列名。需要动态选择对象时，应限定允许的名称。仅仅“调用了预编译接口”，不能使此前任意拼接的 SQL 自动安全。

15.3 嵌入式 SQL、动态 SQL 与元数据

程序的查询结构可能在运行时变化，返回的列也可能不同，需要分清怎样提供 SQL、怎样了解结果结构。这些术语回答不同问题。JDBC／ODBC 是访问接口；嵌入式、动态 SQL 关注程序如何提供 SQL；宿主语言是写程序的语言；元数据则是程序读取的一类描述信息。它们不构成一张只能选其一的接口列表。

概念 关注什么 含义或所属关系
宿主语言 程序用什么语言写 包围 SQL 的程序语言，例如 Java
嵌入式 SQL SQL 怎样进入源码 将 SQL 写入宿主语言源码，由相应工具处理
SQLJ 嵌入式 SQL 的具体方案 原资料介绍的 Java 嵌入式 SQL 方案
动态 SQL SQL 何时构造或准备 程序运行时构造或准备 SQL，支持变化的查询结构
元数据 程序获取什么描述信息 列名、类型、列数等结构信息

动态 SQL 同样可以绑定参数。应用读取元数据后，可知道结果有哪些列、应如何显示，而不必假定所有查询都返回相同结构。

16. 函数、过程与触发器：谁调用，什么时候执行

有些处理要反复调用，有些要在成绩更新时自动执行。怎样把这些逻辑交给数据库，并确定由谁、在何时调用？

16.1 先用任务区分三者

按学分计算学时、办理成绩更正、自动记录变更日志，触发方式不同。先按任务选择函数、过程或触发器：

对象 主要用途 调用方式 学校业务例子
函数 计算并返回一个值或一张表 通常显式调用 输入 3 学分，返回 48 学时
过程 封装一组业务动作 通常显式调用 办理成绩更正并登记原因
触发器 响应指定事件自动执行动作 事件发生后由数据库触发 成绩更新时记录旧值与新值

三者都可能由数据库保存和执行。具体返回方式、调用语法以及事务限制存在产品差异。

16.2 设计触发器要说明哪些条件

假设审计表为 score_audit(SID, CID, old_score, new_score)。小周的 C1 成绩从 70 改为 75，希望自动写入 S2、C1、70、75。

至少应说明：

  1. 作用对象：takes 表。
  2. 触发事件：更新成绩。
  3. 触发时机：操作之前 BEFORE，还是之后 AFTER。
  4. 触发粒度：每一行，还是整条语句。

引用旧行、新行的方式不同，所以本文件使用动作说明，不混写某款产品的触发器语法。需要判断成绩是否真的变化时，也应明确这一条件。

BEFORE、AFTER 说明相对于触发操作的时机，两者都是按事件触发。行级触发器面向每个受影响行，语句级触发器面向一次语句执行，支持范围由产品决定。

时机与粒度可以组合，例如“AFTER 更新、每行执行”同时指定事件之后处理和逐行处理；AFTER 不是与“行级”并列的另一种粒度。条件则进一步决定某次事件是否需要执行日志动作。按“对象＋事件＋时机＋粒度＋条件＋动作”描述完整需求，再转换为所用数据库的触发器定义。

例如一条 UPDATE 修改三条成绩，在支持对应粒度的产品中，行级触发器分别处理三个行事件，语句级触发器处理一次语句事件。若只想记录真实变更，还要判断旧值与新值是否不同；把 70 再设为 70 仍可能属于 UPDATE 事件，不能默认它一定不会触发。

关于触发时机、粒度和“值未变化仍可能触发”的具体实现示例，可参照 PostgreSQL 触发器说明。

成绩范围限制可以直接用 CHECK 表达；记录修改日志则可以考虑触发器。多个触发器相互触发时，处理过程会更难追踪。

16.3 标量函数、表函数与外部例程

封装一次计算前，先确定调用者需要一个值还是一张表，再考虑用哪种语言实现。这里也有两个分类角度：按返回形状，标量函数返回单个值，表函数返回行列组成的结果；按实现方式，例程可以用数据库支持的 SQL／过程语言编写，也可以由 Java、C 等外部语言实现。外部例程不表示第三种返回形状，其返回方式和部署限制仍需产品支持。

例如，返回“某学生全部选课”的表函数可作为 FROM 来源；返回一个学时数的标量函数可放在 SELECT 表达式中。先确定需要一个值还是多行结果，再选择函数及调用位置。

答题时，“函数显式调用并返回值，触发器由事件自动触发”足以说明主要差别。“触发器无返回值”通常指它不作为普通查询表达式取值使用，不能推广为所有产品都没有任何内部返回机制。

17. 进阶查询：递归、多级汇总与窗口函数

还会遇到更复杂的要求：沿先修关系继续查找、同时显示多个汇总层次，或在明细旁附上统计值。下面分别处理这些问题。

17.1 递归查询：沿先修关系继续向前找

只知道直接先修课，还不够回答“学习 A 之前总共要学哪些课”；需要沿先修关系继续查找。独立教学表 prereq(course_id, prereq_id) 记录直接先修关系：A 要先学 B，B 要先学 C。

course_id prereq_id
A B
B C

除了这两条直接关系，还应得到 A 间接要求 C：

在第 9.7 节 CTE 结构上，WITH RECURSIVE 允许辅助查询引用自身。括号内仍是一份查询定义，只是由“基础项＋集合运算＋递归项”组成；最后的 SELECT 才负责读取递归结果。本例基础项读原始关系，递归项用已得到的关系继续接下一段。

WITH RECURSIVE prereq_path(course_id, prereq_id) AS (
    SELECT course_id, prereq_id
    FROM prereq
    UNION
    SELECT p.course_id, q.prereq_id
    FROM prereq_path AS p
    JOIN prereq AS q ON p.prereq_id = q.course_id
)
SELECT course_id, prereq_id
FROM prereq_path;

第一部分是基础项，先产生 A→B、B→C。递归项把已知关系接到下一段，新增 A→C。没有新配对时结束。最终结果为 A、B；B、C；A、C，这种直接或间接可达关系称为传递闭包。

推导 A→C 时，p 是已知关系 A→B，q 是原表关系 B→C。p.prereq_id = q.course_id 在 B 处接上两段；SELECT 保留 p 的起点 A，取 q 的终点 C。开头 prereq_path(course_id, prereq_id) 为结果两列命名，递归项的 prereq_path 引用递归计算中已产生的关系，而 prereq 引用原始直接关系。

这里用 UNION 对有限编号对去重。若换成 UNION ALL，或不断记录新的路径信息，遇到环可能持续产生新行，需要防环或终止规则。递归关键字及限制由产品决定。

17.2 多级汇总：按哪些角度分组

一份销售报表常同时需要“年＋地区”明细汇总、年小计和总计，怎样在一次查询中得到多个层次？另设销售表 sales(year, region, amount)，每行是一笔销售，均非空：

year region amount
2025 东区 10
2025 西区 20
2026 东区 30

年份、地区是分析维度，金额是度量。

先选分组规则，再用 SUM 计算各组金额。ROLLUP、CUBE、GROUPING SETS 都写在 GROUP BY 中，用来指定多套分组；它们不是求和函数。后面介绍的 GROUPING(列) 则读取汇总标志，也不负责产生新分组。

SELECT year, region, SUM(amount) AS total_amount
FROM sales
GROUP BY ROLLUP(year, region);

ROLLUP(year, region) 产生“年＋地区”“年”“全部”三层分组：

年份 地区 金额 分组含义
2025 东区 10 年＋地区
2025 西区 20 年＋地区
2026 东区 30 年＋地区
2025 全部地区 30 年小计
2026 全部地区 30 年小计
全部年份 全部地区 60 总计

表中的“全部”是讲解标签，真实结果通常在省略的维度列上显示 NULL。GROUPING(列) 可判断该列是否因汇总被省略，区别于原始数据的 NULL。

写法 分组范围
ROLLUP(year, region) 年＋地区，年，全部
CUBE(year, region) 年＋地区，年，地区，全部
GROUPING SETS ((year,region),(year),()) 明确指定三套分组，与这里的 ROLLUP 相同

CUBE 还会得到东区总额 40、西区总额 20，因此本例共 8 行。() 表示不按任何维度区分、全体作为一组。这些高级语法并非所有产品都支持。

ROLLUP 中的列顺序表示汇总层次：ROLLUP(year, region) 保留按年小计，ROLLUP(region, year) 则保留按地区小计。它与 ORDER BY 的作用不同：前者决定有哪些统计组，后者决定结果怎样排列。

按年小计行 (2025,NULL,30) 中，GROUPING(region) 为 1，表示地区列因汇总被省略；原始东区、西区明细行中为 0。这个标志帮助识别统计层次，不会自动把 NULL 改成“全部地区”。

17.3 窗口函数：保留明细，旁边附上统计值

要在每条选课旁显示均分或名次，同时保留学生、课程和成绩明细，该怎样计算？普通 GROUP BY 会把每组汇成一行；窗口函数则保留明细，并为每行附上统计值。

先把一个窗口表达式拆成“函数调用＋OVER 窗口说明”：

函数调用 OVER (
    [PARTITION BY 分区列]
    [ORDER BY 窗口内排序列]
    [窗口框架说明]
)
组成部分 回答什么问题 例子
函数调用 要计算什么？ AVG(score) 求平均，RANK() 求名次
OVER 这次调用按哪个窗口计算？ 与前面的函数一起组成窗口表达式
PARTITION BY 哪些行属于同一分区？ CID 相同的选课放在一起
窗口内 ORDER BY 分区内按什么顺序计算？ 按 score 降序求名次
窗口框架 对 SUM、AVG 等，本行具体使用分区内哪段记录？ 从分区开头累计到当前行，见第 17.4 节

这些是组合关系，不是五种窗口函数。哪些部分必需、框架是否影响结果，要看函数和产品规则；本章的排名例子依赖排序，均值例子可以不排序。AVG(score) OVER () 没有分区、排序或框架说明，对当前查询处理后的全部输入求平均；这个“全部”不包括已经被 WHERE 筛掉的行。

下面的查询同时放入一个均值窗口表达式和一个排名窗口表达式，它们各自有自己的 OVER：

SELECT SID, CID, score,
       AVG(score) OVER () AS overall_avg,
       RANK() OVER (ORDER BY score DESC) AS rank_no
FROM takes
ORDER BY score DESC, SID, CID;
SID CID score overall_avg rank_no
S1 C2 90 75 1
S1 C1 80 75 2
S2 C1 70 75 3
S3 C2 60 75 4

OVER () 用全部行作为计算范围。PARTITION BY CID 则按课程划分计算范围；这里的分区不指物理分区表。

RANK 遇并列会跳号，DENSE_RANK 不跳号。例如 90、90、80 分别排名为 1、1、3 和 1、1、2。窗口内部的 ORDER BY 用于计算，不保证最终显示顺序，所以例子末尾另写 ORDER BY。

按课程单独计算平均分，可以写：

SELECT SID, CID, score,
       AVG(score) OVER (PARTITION BY CID) AS course_avg
FROM takes
ORDER BY CID, SID;

仍返回四条选课：C1 的两条记录旁都附均分 75，C2 的两条记录旁也附均分 75。

写法 如何使用相同课程号的记录 输出行数
GROUP BY CID 配合 AVG 汇成课程统计行 本例 2 行
AVG(score) OVER (PARTITION BY CID) 保留明细，对每行附上所在课程的均值 本例 4 行

OVER 标明窗口计算，PARTITION BY 划定各自范围，窗口内 ORDER BY 指定排名或有序计算所用顺序。WHERE 先筛掉的明细不会进入该查询的窗口统计，所以窗口并非无条件统计原表全部记录。参见 PostgreSQL 窗口函数教程。

ROW_NUMBER() 为窗口内每行分配不同序号。90、90、80 的序号为 1、2、3，但只按成绩排序不能确定同分者谁为 1；要确定先后，应补唯一排序列。RANK 与 DENSE_RANK 若希望同分并列，排名条件则应保留这种并列关系。

如果要筛选计算出的名次，应先在子查询或 WITH 中算出 rank_no，再在外层 WHERE 中筛选；同层 WHERE 的逻辑阶段早于窗口计算。排名函数与并列规则可核对 PostgreSQL 窗口函数参考。

17.4 窗口范围：累计到当前行

要显示每笔销售发生后的累计金额，本行就只能累计到当前位置，不能直接使用全体总额。PARTITION BY 先确定分区，窗口框架再确定对当前行取该分区中的哪一段。此例不分区，因此三笔销售一起参与累计；若增加 PARTITION BY region，就改为每个地区各自累计。

所需框架是 ROWS BETWEEN 起点 AND 终点。ROWS 表示按排序后的行位置划范围，BETWEEN／AND 连接两个边界，UNBOUNDED PRECEDING、CURRENT ROW 是本例选择的起点和终点。整段说明附属于 OVER，不能独立执行。

SELECT year, region, amount,
       SUM(amount) OVER (
           ORDER BY year, region
           ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
       ) AS running_total
FROM sales
ORDER BY year, region;

ROWS 按行定义范围，UNBOUNDED PRECEDING 是从最前一行，CURRENT ROW 是到当前行。

“有 ORDER BY”不等于“已经明确逐行累计”。例如 PostgreSQL 的有序窗口默认框架会包含与当前排序值相同的并列行；本例显式指定 ROWS，表达按行累计的意图。排名函数 RANK、DENSE_RANK 按排序的并列关系排名，不靠这个累计框架定义名次。参见 PostgreSQL 窗口框架说明。

若按“2025 东区、2025 西区、2026 东区”排序，累计金额依次为 10、30、60。地区的实际排序取决于排序规则；本例这一展示顺序是教学约定。真实表若同一年、地区有多笔销售，还要补充能唯一确定行序的编号。

17.5 OLAP：从不同维度观察数据

分析销售时，既可能只看某一年，也可能查看总额后再展开地区细节，需要改变观察数据的范围和层次。OLAP 是联机分析处理。用上面的销售数据理解几种操作：

操作 例子
切片 只看 2025 年，得到东区 10、西区 20
切块 同时限制年份和地区，只看 2025—2026 年东区，得到 10、30
上卷 将地区明细汇总为各年总额，2025、2026 都是 30
下钻 从年总额继续查看各地区明细

这些是分析动作的名称，不是所有数据库都提供的同名 SQL 关键字。

18.1 五道基础题

先用五道基础题检查能否解释概念的用途和差别，再进入需要组合多张表的综合题。

题一：CHAR 与 VARCHAR 有什么区别？

CHAR(n) 是固定长度字符类型，短值通常补空格；VARCHAR(n) 是最大长度受限的可变长度字符类型。具体存储和比较规则因产品而异。

答题重点是固定长度与可变长度，不应将 VARCHAR 理解为没有上限。

题二：查询名字中含 g 的学生学号、姓名

原题学号列名为 ID，不同于本章主例的 SID：

SELECT ID, name
FROM student
WHERE name LIKE '%g%';

教学名单 Wang、Li、Zhang 中，Wang 与 Zhang 匹配。两个 % 允许 g 前后有任意长度文字；大写 G 是否匹配取决于比较规则。

题三：函数与触发器有什么异同？

两者都可以由数据库保存并执行，用于封装处理逻辑。函数通常显式调用，返回值或表；触发器绑定事件，由数据库自动触发。它通常不作为表达式中手工调用的返回值函数使用。

题四：DISTINCT 的作用是什么？

消除查询结果中的重复行，比较整个选择列表的组合。它只改变本次查询输出，不删除基础表数据。

题五：用户定义类型与域有什么差别？

在本课程的区分语境下，独立类型侧重类型身份和强类型检查；域建立在已有类型上，可附加约束和默认值，通常更易与基础类型互操作。不能把这一简答扩大为所有产品的类型系统规则。

18.3 小问一：创建六张表

先建分行和客户，再建账户、贷款，最后建对应关系表。字符串长度和金额精度是示例设计选择，不是题目已经证明的业务上限。

CREATE TABLE branch (
    branch_name VARCHAR(15) PRIMARY KEY,
    branch_city VARCHAR(30),
    assets NUMERIC(16,2)
);

CREATE TABLE customer (
    customer_name VARCHAR(40) PRIMARY KEY,
    customer_street VARCHAR(60),
    customer_city VARCHAR(30)
);

CREATE TABLE loan (
    loan_number VARCHAR(20) PRIMARY KEY,
    branch_name VARCHAR(15) NOT NULL,
    amount NUMERIC(16,2) CHECK (amount >= 0),
    FOREIGN KEY (branch_name) REFERENCES branch(branch_name)
);

CREATE TABLE account (
    account_number VARCHAR(20) PRIMARY KEY,
    branch_name VARCHAR(15) NOT NULL,
    balance NUMERIC(16,2) NOT NULL,
    FOREIGN KEY (branch_name) REFERENCES branch(branch_name)
);

CREATE TABLE borrower (
    customer_name VARCHAR(40),
    loan_number VARCHAR(20),
    PRIMARY KEY (customer_name, loan_number),
    FOREIGN KEY (customer_name) REFERENCES customer(customer_name),
    FOREIGN KEY (loan_number) REFERENCES loan(loan_number)
);

CREATE TABLE depositor (
    customer_name VARCHAR(40),
    account_number VARCHAR(20),
    PRIMARY KEY (customer_name, account_number),
    FOREIGN KEY (customer_name) REFERENCES customer(customer_name),
    FOREIGN KEY (account_number) REFERENCES account(account_number)
);

一个主码不要重复声明。组合主码允许张三持有 A1、A3，也允许张三、李四共同持有 A3，但不允许“张三、A3”重复登记。

18.4 小问二：找 Brighton 分行的存款客户、账户号和余额

姓名在 depositor，账户余额和分行在 account，因此按账户号连接：

SELECT d.customer_name, a.account_number, a.balance
FROM depositor AS d
JOIN account AS a ON d.account_number = a.account_number
WHERE a.branch_name = 'Brighton';

李四 A2 3000

这里一行代表一条持有关系，题目需要的姓名已经在 depositor 中，不必为了凑齐六张表而连接 customer。

18.5 小问三：找账户平均余额小于 5000 的分行

目标是按分行筛选账户平均余额，需要先按分行统计，再判断每个分行的均值：

SELECT branch_name, AVG(balance) AS avg_balance
FROM account
GROUP BY branch_name
HAVING AVG(balance) < 5000;

Brighton 均值是 (1000 + 3000) / 2 = 2000，Riverside 均值是 8000，所以结果只有 Brighton、2000。

本题统计的是账户。若先连接 depositor，共同账户会重复进入统计，可能改变均值。没有账户的分行不会在这个查询中形成组；若题目要求包含它们，需要另外设计外连接，并规定无账户均值的含义。

本例若把 account 与 depositor 连接，A3 会出现两次。由于 Riverside 目前只有 A3，分行均值碰巧仍是 8000，不能据此认为连接后统计一定正确；如果统计全行账户均值，就会把 1000、3000、8000、8000 平均成 5000，而正确账户均值为 4000。计算前应先确定“一行代表一个账户”还是“一条持有关系”。

18.6 小问四：找有贷款但没有账户的客户

需要同时满足“有贷款”和“没有任何账户”。从借款名单出发，逐人检查是否存在持有账户的记录：

SELECT DISTINCT b.customer_name
FROM borrower AS b
WHERE NOT EXISTS (
    SELECT 1
    FROM depositor AS d
    WHERE d.customer_name = b.customer_name
);

张三有贷款也有账户，被排除；王五、赵六有贷款而没有账户，留下。DISTINCT 避免同一客户借多笔贷款时重复输出。

“没有账户”指没有持有关系，不是账户余额恰好为零。按本题姓名非空的约束，用 NOT IN 也能表达同一条件；NOT EXISTS 更直接地写出“不存在匹配持有记录”。

18.7 小问五：给余额高于原平均值的账户加 3% 利息

原均值为 (1000 + 3000 + 8000) / 3 = 4000。只有 A3 应加息，新余额为 8000 × 1.03 = 8240。

课程写法：

UPDATE account
SET balance = balance * 1.03
WHERE balance > (SELECT AVG(balance) FROM account);

若先单独求均值再更新，还要保证两步之间的并发变化得到正确处理。这里的结果表是按题意推导的目标结果，不代表所有 DBMS 都已验证。

19. 自测：先做题，再看答案

读懂例子后，还需要检查能否独立选择条件、连接和统计方法。以下四题均从第 1 节原始数据独立出发。先写出预期结果，再选择查询方法。

题号 任务 主要练习什么
1 找选了 C1、但没选 C2 的学生学号和姓名 存在与不存在
2 找至少有两条选课记录的学生学号和选课数 分组与 HAVING
3 显示所有学生的学号、姓名和选课数，包含零选课者 外连接与计数
4 找选过全部计算机系开设课程的学生学号和姓名 全称条件与反例

19.1 答案一：选了 C1，但没选 C2

C1 名单为 S1、S2，C2 名单为 S1、S3，差集只有 S2。需要姓名时，可在学生表中同时检查两种存在性：

SELECT s.SID, s.name
FROM student AS s
WHERE EXISTS (
    SELECT 1 FROM takes AS t
    WHERE t.SID = s.SID AND t.CID = 'C1'
)
AND NOT EXISTS (
    SELECT 1 FROM takes AS t
    WHERE t.SID = s.SID AND t.CID = 'C2'
);

结果：S2、小周。两个子查询的 t 分属不同作用域。

不能把题意简化为一条选课记录同时满足 CID = 'C1' AND CID <> 'C2'。一条 C1 记录本来就不是 C2，这样无法检查该学生是否另有 C2 记录。

19.2 答案二：至少两条选课记录

这里要判断一位学生共有多少条选课记录，应先按学号分组，再筛出计数至少为 2 的组：

SELECT SID, COUNT(*) AS n
FROM takes
GROUP BY SID
HAVING COUNT(*) >= 2;

各组数量为 S1、2；S2、1；S3、1。最终只有 S1、2。组的数量要在分组后判断，不能改写成 WHERE COUNT(*) >= 2。

19.3 答案三：所有学生及选课数

既要统计选课数，又要显示零选课学生，需要以所有学生为起点，保留没有匹配选课的行：

SELECT s.SID, s.name, COUNT(t.CID) AS n
FROM student AS s
LEFT JOIN takes AS t ON s.SID = t.SID
GROUP BY s.SID, s.name;
SID name n
S1 小林 2
S2 小周 1
S3 小陈 1
S4 小吴 0

以学生为左表才能保留小吴；数真实选课的非空课程号，才能将他的选课数算为零。

19.4 答案四：全部计算机系课程都选过

这里要检查的是 course.dept，不是学生所在系。计算机系开设 C1、C2，只有小林两门都选过。

SELECT s.SID, s.name
FROM student AS s
WHERE NOT EXISTS (
    SELECT 1
    FROM course AS c
    WHERE c.dept = '计算机'
      AND NOT EXISTS (
          SELECT 1
          FROM takes AS t
          WHERE t.SID = s.SID AND t.CID = c.CID
      )
);

结果：S1、小林。中层寻找“当前学生缺的计算机系课程”，外层要求一门也找不到。

如果计算机系不开任何课程，全部学生都没有缺项，都会通过。这是全称条件在空范围上的结果；需要排除这种情况时，应额外要求相关课程存在。

  1. 不能、不能。NOT NULL 只要求有值；范围 CHECK 拒绝为假的条件，未知不因此被拒绝。要求“必须填写合法成绩”应同时声明两项约束。

  3. 都不改变。它只为本次结果计算一个值并给输出列命名。
  4. 不会。外码维护引用规则；查询要显示姓名，还需连接学生表或采用适当子查询。

遇到新题或结果不符时，怎样按步骤确定查询含义、找出错误？最后把前面的规则整理成做题和复习时可用的检查方法。

20.1 将题意变成 SQL 的步骤

面对一段题目描述，先确定结果应该长什么样，再选择需要的表和处理步骤：

  1. 说清结果的一行代表什么：学生、选课、课程统计，还是账户？
  2. 找到必要的列及所在表，按业务对应关系写连接。
  3. 区分条件：单行条件放 WHERE，组统计条件放 HAVING，存在性条件考虑子查询。
  4. 检查是否需要保留未匹配对象、是否要去重，以及 NULL 会怎样影响条件和计数。
  5. 用小数据手工推导结果，核对 SQL 回答的是否就是题目要求的问题。

20.2 常见错误对照表

查不到缺值行 用了 = NULL 改用 IS NULL

20.3 学完后应能独立解释

复习时需要确认自己能解释规则和结果，而不只是认出关键字。可以用下面的清单逐项检查。

  • 主码、外码、非空、唯一和 CHECK 各约束什么。
  • SELECT、FROM、WHERE 的职责，以及查询的逻辑处理顺序。
  • NULL 为什么导致未知，WHERE 为什么只保留真。
  • 内连接与外连接的区别，ON 与 WHERE 在外连接中的影响。
  • COUNT(*)、COUNT(列)、COUNT(DISTINCT 列) 在数什么。
  • WHERE 与 HAVING 为什么不能随意互换。
  • 集合运算与连接各在组合什么，EXCEPT 为什么有方向。
  • 如何按“名单、单值、存在、所有”选择子查询写法。
  • 如何从内到外读懂双重 NOT EXISTS，并解释空范围情况。
  • 查询、修改、视图、事务和权限分别解决什么问题。
  • 函数与触发器的调用方式，以及进阶语法需要确认的产品支持。
  • 能拆开列声明，区分类型、默认值、非空和范围检查各自负责的规则。
  • 能区分表别名与输出列别名，说明各层查询可见哪些列。
  • 能解释视图、WITH 和复制到普通表的查询结果有什么区别。
  • 能逐步推导事务内余额变化，说明提交与回滚的边界。
  • 能区分对象权限与角色授予、外码级联与授权级联。
  • 能比较分组统计与窗口统计的输入范围和输出行数。
  • 能区分引用事件、动作和完整外码约束，分别推导删除与改号的级联效果。
  • 能说明哪些分类可以组合，例如自连接与外连接、标量与相关子查询。
  • 能把 WITH、AS、CASCADE 等词放回所在语句，解释当前含义。
  • 能从完整表达式中拆出窗口函数、分区、排序和框架，而不把它们当作并列函数。
