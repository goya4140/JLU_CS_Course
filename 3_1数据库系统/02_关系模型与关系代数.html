1. 从学生选课业务认识关系模型

1.1 先交代背景：学校需要保存哪些事情

假设学校在安排一个学期的课程，需要保存三类信息：

  • 学生是谁，属于哪个系；
  • 开设了哪些课程，每门课由哪个系开设，有多少学分；
  • 哪个学生选了哪门课，成绩是多少。

我们用三张表分别记录这三类事情：student 是学生表，course 是课程表，takes 是选课表。英文表名只是给表取的名字；知道它们的中文含义，就能理解后面的计算。

以下均为教学用数据。 为了只讨论本章的运算，约定：一名学生在这组数据中对同一门课程至多有一条选课记录，暂不考虑跨学期重修；学号不重复，课程号不重复。表中所有成绩都已确定。

1.2 学生表：每一行代表一个学生

student 的三个字段如下。“字段”在这里就是一列数据。

字段名 中文含义 本例中的用法
SID 学号 S1、S2 等是用于区分学生的编号
name 姓名 记录学生的名字
dept 所在系 记录学生属于哪个系

学生表的全部数据：

SID name dept
S1 小林 计算机
S2 小周 数学
S3 小陈 计算机
S4 小吴 数学

例如第一行表达一个完整事实：“学号 S1 的学生叫小林，属于计算机系。”

1.3 课程表：每一行代表一门课程

course 的字段含义如下：

字段名 中文含义 本例中的用法
CID 课程号 C1、C2 等是用于区分课程的编号
title 课程名称 如数据库、程序设计
dept 开课系 说明哪个系开设这门课
credits 学分 用数字表示课程学分

课程表的全部数据：

CID title dept credits
C1 数据库 计算机 3
C2 程序设计 计算机 4
C3 高数 数学 5

注意，学生表和课程表都使用了 dept 这个字段名。前者表示“学生属于哪个系”，后者表示“课程由哪个系开设”。学生可以跨系选课，因此这两个系不一定相同。后面学习连接时，这个区别十分重要。

1.4 选课表：每一行代表一次选课

takes 的字段含义如下：

字段名 中文含义 本例中的用法
SID 学号 表示谁选了这门课，对应学生表中的 SID
CID 课程号 表示选的是哪门课，对应课程表中的 CID
score 成绩 本例使用 0 至 100 的分数

选课表的全部数据：

SID CID score
S1 C1 80
S1 C2 90
S2 C1 70
S3 C2 60

逐行读一遍：小林选了数据库，成绩 80；小林还选了程序设计，成绩 90；小周选了数据库，成绩 70；小陈选了程序设计，成绩 60。

小吴 S4 没有出现在选课表中，表示他在本例中没有选课；高数 C3 没有出现在选课表中，表示这门课还没有人选。没有选课记录与选了课但成绩尚未确定是两种不同情况。

全章的数据约定：除非明确说“另设一个独立场景”，学校例子都使用上面三张表。每个例子独立从这些原始数据出发，不会继承上一个例子假想的修改。教学表为了便于阅读有排列顺序，但结果的行顺序不影响关系代数答案。

1.5 把熟悉的“表、行、列”换成专业术语

现在再介绍术语，它们都能在刚才的表中找到对应物。

术语 通俗解释 对应本例
属性 attribute 表中的一列，用来描述某一种信息 SID、name、dept
元组 tuple 表中的一行，按各列顺序放好的一组值 (S1, 小林, 计算机)
域 domain 某一列允许采用的值的范围或集合 score 允许 0 至 100 的分数
关系 relation 在关系模型中，符合规则的一张数据表 当前学生表中的四行数据组成一个关系

“集合”可以先理解为一批不同的元素组成的整体。例如学号集合 {S1,S2} 包含 S1、S2 两个元素；写成 {S2,S1} 不改变集合，重复写一次 S1 也不会多出一个新元素。

关系把完整的一行当作集合中的一个元素，因此纯关系模型具有这些特点：

  • 同一关系不能有完全相同的重复行。 但两行可以在某几列上相同，例如小林和小陈的所在系相同。
  • 行没有固定的先后意义。 把小周放在第一行，不会改变“有哪些学生”。
  • 一行中的每个值必须对应正确的属性。 不能把姓名填到学号列。书写一行时按表头给出的列顺序读取。
  • 后面介绍的纯关系代数沿用这种集合规则。SQL 是下一章使用的数据库语言，它的查询结果默认可以保留重复行，不能直接照搬这里的去重结论。

1.6 关系模式与关系实例：表的结构和表里的数据

学校增加一个新生时，需要在学生表中增加一行，但表头仍然是学号、姓名、所在系。这说明“表的结构”和“当前有哪些数据”是两件事。

关系模式描述一张表叫什么、有哪些属性，并配有类型和约束等结构信息。常见简写是：

student(SID, name, dept)

逐项读：student 是关系名；括号中依次列出三个属性。这个简写没有列出具体学生，也没有完整列出所有约束。

教材也会抽象写成 R(A1,A2,...,An)：R 代表任意关系名，A1 至 An 代表它的各个属性，省略号表示中间还可以有其他属性。它是一种通用模板。

关系实例是某一时刻表中实际存放的数据。第 1.2 节的四行就是一个学生关系实例；新生入学后，实例改变了，模式可以不变。如果学校新增“联系电话”一列，模式也改变了。

把学生、课程、选课这几张表的结构及相互约束放在一起，就是关系数据库模式；把这些表在某一时刻的全部实际数据放在一起，就是关系数据库实例。

2. 域、原子性与空值

认识列名还不够：成绩能填什么、一个格子能否放多个课程号、分数未知时怎么表示，都会影响查询的含义。本节先明确输入数据的约定，再进入运算，避免让公式在未经说明的空值或多值数据上工作。

2.1 域：不是随便什么值都能填进一列

学校规定成绩使用 0 至 100 的整数。于是 80 是合法成绩，150 超出范围，“计算机”也不是一个成绩。这里允许填写的全部值，就构成成绩列的域。

域比“存的是数字还是文字”更具体：数字类型说明值的表示方式，业务规则还可以进一步限制范围。设计表时说明域，是为了避免把不合理的数据当成正常数据保存。

2.2 原子性：一个格子中保存一个可作为整体使用的值

假设有人把小林所选课程全部塞进学生表的一个格子，写成“C1,C2”。以后查“谁选了 C2”时，就得先拆开这个字符串；给一门课记录成绩也不方便。

本章的做法是用选课表保存两行：

SID CID score
S1 C1 80
S1 C2 90

一个格子保存一个课程号，一行表达一次选课。关系模型把这种在当前模型中当作一个整体使用的值称为原子值。在通常的入门关系模型中，每个格子都存原子值，是满足第一范式的基本要求。范式可以先理解为“检查表结构是否符合某些规则的标准”；第一范式简称 1NF，详细设计理论见第 5 单元。

这里的“不可再分”取决于模型怎样使用这个值，不是说文字在物理上不能拆成字符。例如姓名“小林”虽然有两个字，系统仍可把它当一个姓名值。若要分别管理多个电话号码，通常应将号码逐个保存，而不是把多个号码拼在一个格子里。

不要把这里的“属性值原子性”与第 6 单元的“事务原子性”混淆：前者讨论一个格子存什么，后者讨论一组业务操作是否全部成功或全部撤销。

2.3 NULL：目前没有一个可用的普通值

另设一个独立场景：学校正在公布一次考试成绩，小周确实得了 0 分，小陈的试卷还没批完。这里用临时成绩表 grade_notice(SID,score) 表示公布情况；它不是对本章选课表的修改。

SID score
S1 80
S2 0
S3 NULL

NULL 是一个空值标记。在这张表里，它表示“小陈的分数目前未知”。它与 0 不同：0 是已经确定的分数，NULL 表示还不知道分数是多少。它也与空字符串不同：空字符串是长度为零的一段文字，不能自动表示“未知”。

空值在其他业务中还可能表示“没有这个值”或“此项不适用”。例如一个人没有中间名，与名字尚未登记，是不同原因；如果都用 NULL 表示，阅读数据的人需要结合业务背景判断。

如果问“小陈是否及格，即 score >= 60”，目前既不能说真，也不能说假，只能说未知，记为 UNKNOWN。这就引出了三值逻辑：条件的结果除了真 TRUE、假 FALSE，还可能是未知 UNKNOWN。

本章前面的普通选择等运算先按没有空值的数据理解；第 7 节再说明带空值的扩展规则。下一章 SQL 中判断空值要用 IS NULL，不能用普通的 = NULL 比较。

3. 为什么需要码

查询和修改都需要知道“哪一行代表同一个对象”。姓名在当前样本里不同，不代表未来不会重名。因此码来自业务上的识别规则，而不是从几行现有数据猜出来的规律。下面按“能否识别”和“是否有多余属性”分两步判断。

3.1 从“怎样找到同一个学生”开始

教务员要修改某个学生的资料时，必须知道自己改的是谁。如果只凭姓名，遇到同名学生就可能认错人。因此学校给每名学生分配不重复的学号。

唯一标识的意思是：拿到这个值或这组值，至多对应一个对象。在本例的业务规则中，学号可以唯一标识学生；姓名虽然在当前四行里没有重复，学校却没有保证以后永不重名，因此不能据此把姓名认定为唯一标识。

数据库把用于唯一标识一行的一组属性称为码，也常称为“键”。

3.2 超码：这组属性足以区分行

看学生表：

  • 只给出 SID=S1，就能确定是小林这一行，所以属性集合 {SID} 是一个超码。
  • 同时给出 SID=S1、name=小林，也能确定这一行，所以 {SID,name} 也是超码。

花括号这里表示“一个属性集合”，不是一行实际数据。超码只要求能区分行，允许其中带着多余属性。

3.3 候选码：足以区分，而且没有多余属性

{SID,name} 中的姓名可以去掉，剩下 SID 仍能区分行。因此它不是最精简的识别方式。

候选码是没有多余属性的超码。 正式定义中的“最小”是指：删去其中任何一个属性，就不能保证唯一标识。它不是在所有候选码之间比赛谁的属性数最少。

如果集合 B 中的每个元素都在集合 A 中，就说 B 是 A 的子集；B 还比 A 少一些元素时，叫真子集。例如 {SID} 是 {SID,name} 的真子集。因此“候选码的任何真子集都不是超码”，就是“再删属性就不够用了”。

在本例的规则下，{SID} 是学生表的候选码；{SID,name} 不是候选码。

3.4 主码与复合码

一张表可能存在不止一种没有冗余的唯一标识方法。这些方法都可以是候选码；设计者从中选一个作为主要标识，称为主码或主键。

主码可以由多个属性组成，这种码叫复合码。为什么有时必须用多个属性？看选课表：

  • 学号 S1 出现两次，因为小林选了两门课，所以 SID 单独不能区分选课记录。
  • 课程号 C1 出现两次，因为不止一个学生选了数据库，所以 CID 单独也不行。
  • 两列放在一起，(S1,C1) 表示“小林选数据库”这一条记录，(S1,C2) 表示另一条。

按本章“一名学生对同一门课至多一条选课记录”的约定，{SID,CID} 是选课表的候选码，可以选为复合主码。若业务允许跨学期重修，同一组合就可能重复，届时必须重新设计码，不能照搬本例。

3.5 外码与参照完整性：表之间怎样对上号

选课表的一行 (S2,C1,70) 没有再次写“小周”和“数据库”，而是使用 S2、C1 到其他表中查找对应对象。

  • takes.SID 中的值对应 student.SID，所以它是引用学生表的外码。
  • takes.CID 中的值对应 course.CID，所以它是引用课程表的外码。

这里的点号表示“某张表的某一列”，例如 takes.SID 就是“选课表中的学号”，不是小数点。

外码要求引用关系中非空的引用值能在被引用关系的相应键中找到。这种保证叫参照完整性。例如选课表若出现 S9，但学生表没有 S9，就会产生“一个不存在的学生选了课”的问题。

外码在引用表中可以重复：S1 可以出现在多条选课记录中。外码与主码回答不同的问题：主码用来区分本表的行，外码用来把本表的记录关联到别的记录。实际 SQL 的外码声明和空值规则见第 3 单元。

4. 查询语言与公式的读法

接下来会出现符号、条件和完整表达式。先分清它们的层次：一个运算符说明动作，下标说明动作参数，括号中的关系提供输入；把它们组合起来才构成一个完整查询表达。关系演算则从答案必须满足的条件出发描述同一类问题。

4.1 “查询”是在问什么

查询就是从已经保存的数据中取得信息。例如“找出计算机系学生姓名”，输出应是小林、小陈，而不是直接改变学生表。

关系代数把处理过程写成若干表运算：先按所在系筛行，再留下姓名列。它是过程式的，指表达式说明了逻辑上的操作步骤；这不意味着数据库必须按这个顺序实际扫描磁盘。

关系演算直接描述答案满足的条件，例如“返回属于计算机系的学生姓名”，不先指定筛行和选列的操作序列。这样的表达方式叫声明式。SQL 更接近声明式语言。

在只讨论本章经典查询运算，并将关系演算限制为后文介绍的安全表达式时，两者能表达相同的一类查询。“表达能力相同”不表示写法相同，也不包含后来所有聚集、递归等扩展功能。

4.2 本章统一采用什么记号

后面每种运算都会单独解释。先记住几条书写约定：

  • 表名放在括号内时，表示把这张表交给外面的运算处理。
  • 运算符_{说明}(表名) 中的 _{说明} 是纯文本中表示“下标”的方式，写在纸上时可以把说明写在符号下方。它不是要输入数据库的程序代码。
  • 两层括号表示先做里面的运算，再把结果交给外面的运算。
  • 一个运算的结果仍然是一张关系表，所以可以继续交给另一个运算使用。结果没有任何行时，仍然保留应有的列。
  • 除非明确引入扩展，公式采用集合规则，重复的完整行只保留一次。
  • 第 5 至第 7 节的教学公式只计算结果表，不会删除或修改本章的原始表。

5. 六种基本关系代数运算

本节学习六种基础操作。可以把它们看成积木：先会用一块积木，之后才能读懂由多种运算组合出的表达式。

5.1 选择 σ：按条件留下整行

如果需要的数据已经在一张表里，第一步通常是判断哪些记录符合要求。这里的“选择”只回答保留哪些行，条件里的等号、并且等只是判断方法，不能把它们当成另一种表运算。

先看学校要查什么

教务员想找出所有计算机系学生，保留他们的学号、姓名和所在系。输入是第 1.2 节的学生表：

SID name dept
S1 小林 计算机
S2 小周 数学
S3 小陈 计算机
S4 小吴 数学

手工检查：小林、小陈的所在系符合条件，保留；小周、小吴属于数学系，排除。这里每次保留或排除的是整行。

把这个动作写成公式

σ_{dept='计算机'}(student)
  • σ 读作“西格玛”，表示选择，也就是按条件筛行。
  • dept='计算机' 是条件。等号要求这一列的值与“计算机”相同；单引号表示里面是文字值。
  • 下标部分写明条件，括号内的 student 写明输入表。

结果为：

SID name dept
S1 小林 计算机
S3 小陈 计算机

结果仍有三列。选择改变哪些行被返回，不负责决定只显示哪些列，也不会把不符合条件的人从原表删除。

条件不止一个时怎样读

学校还可能问“找出选了数据库且成绩至少 75 分的选课记录”。数据库的课程号是 C1，所以条件有两个：CID 是 C1，score 至少为 75。

σ_{CID='C1' ∧ score>=75}(takes)

这里 >= 表示“大于或等于”；∧ 表示“并且”，要求两项都成立。选课表里 S1 的 C1 成绩为 80，符合；S2 的 C1 成绩为 70，不符合；两条 C2 记录的课程不符合。因此结果只有：

SID CID score
S1 C1 80

以后还会遇到 ∨，读作“或者”，至少一个条件成立即可；¬ 读作“非”，把一个条件否定。例如 ¬(CID='C1') 表示课程号不是 C1。复杂条件应用括号明确范围。

5.2 投影 π：只保留需要的列

筛选完后，名单往往不需要全部字段。投影只留下要显示的列，并按保留下来的完整行去重。这一步可能让两名同系学生变成一个系名，因此必须先确定结果的一行究竟代表学生，还是一个系。

为什么还需要另一种操作

现在教务员只想看学生所在系的名单，不需要学号和姓名。手工做法是取出每一行的 dept 值：

计算机、数学、计算机、数学

如果问的是“有哪些不同的系”，同一个系只应列一次。关系代数把保留指定列，并按完整结果行去重的操作叫作投影。

π_{dept}(student)

π 读作“派”，表示投影；下标 dept 表示保留所在系这一列；输入仍是 student。

结果为：

dept
计算机
数学

去重发生在保留列之后，因为删除学号和姓名后，两个“计算机”成为完全相同的结果行。

要多列时，去重比较的是整行

如果保留学号和所在系：

π_{SID,dept}(student)

逗号分隔要保留的属性，结果为：

SID dept
S1 计算机
S2 数学
S3 计算机
S4 数学

S1 和 S3 的系相同，但整行不同，因此都保留。投影不是“每一列分别去重”。

把选择和投影接起来

题目变成“只列出计算机系学生的姓名”。手工顺序是先筛出计算机系学生，再取姓名列：

π_{name}(σ_{dept='计算机'}(student))

从最内层读：student 提供原始表；选择得到第 5.1 节的两行；外层投影取出姓名。

name
小林
小陈

若先执行 π_{name}(student)，中间结果已经没有 dept 列，后面就无法再根据 dept 筛选。因此写长表达式时，需要检查下一步要用的列是否仍然存在。

5.3 并 ∪：出现在任一名单中就保留

先把两份名单做出来

学校想找“选过数据库或者程序设计的学生学号”。数据库是 C1，程序设计是 C2。

先筛出 C1 的选课记录，再投影学号，得到第一份名单。本节把它简称为 R：

π_{SID}(σ_{CID='C1'}(takes))
R 的 SID
S1
S2

按相同步骤筛 C2，得到第二份名单，简称 S：

π_{SID}(σ_{CID='C2'}(takes))
S 的 SID
S1
S3

R、S 只是本节给中间结果取的短名字；S 这个表名与 S1 这个学号不要混淆。

把两份名单合起来，S1 虽在两边都有，也只列一次：

R ∪ S

∪ 表示并，读作“R 与 S 的并集”。结果为：

SID
S1
S2
S3

完整表达式是：

π_{SID}(σ_{CID='C1'}(takes))
∪
π_{SID}(σ_{CID='C2'}(takes))

上下排版只为方便阅读，两边仍分别是一个完整的输入。

什么叫并相容

并运算是在合并同一种结构的记录，要求两边并相容：

  1. 列数相同；
  2. 对应位置的列取值类型或域相容，能作为同一种属性比较。

采用按属性名识别列的记法时，还应让对应列名一致，必要时用第 5.6 节的更名。

本例两边都是“学号”这一列，满足要求。若左边是“学号、姓名”两列，右边只有“学号”一列，就不能直接并。即使学号和课程号都用字符串表示、形式上可能可比较，把它们并成一份“编号”名单也通常不符合题意：形式合法与业务有意义需要分别检查。

5.4 集合差 −：在第一份名单中，但不在第二份中

沿用刚才两份名单：R 是选 C1 的 S1、S2，S 是选 C2 的 S1、S3。学校现在想找“选了数据库，但没选程序设计的学生”。

从 R 出发：S1 在 S 中出现，排除；S2 不在 S 中，保留。

R − S

− 在这里是两个关系的集合差，不是对学号做数值减法。结果为：

SID
S2

展开后是：

π_{SID}(σ_{CID='C1'}(takes))
−
π_{SID}(σ_{CID='C2'}(takes))

差运算也要求并相容，否则无法判断两边是不是“同一条记录”。它还具有方向：S − R 会得到 S3，表示选 C2 但未选 C1 的学生，与原题不同。

5.5 笛卡尔积 ×：列出所有可能配对

为什么要先列“可能配对”

学校想检查选了数据库的学生是否也选了另一门指定课程。检查前，可以先列出“每名待检查学生，与每门待检查课程”的所有组合。

待检查学生是上一节的 R：

SID
S1
S2

待检查课程在这个例子中指定为 C1、C2，用 Q 表示这份课程号名单：

CID
C1
C2

将 R 的每一行与 Q 的每一行拼接，得到：

R × Q

× 读作“笛卡尔积”，结果为：

SID CID
S1 C1
S1 C2
S2 C1
S2 C2

R 有 2 行，Q 有 2 行，所以有 2×2=4 种组合。这里公式中的乘号作用于表，计算行数时的乘号才是普通乘法。

这张结果表表示可能配对，不自动表示实际选课。 原选课表没有 S2 选 C2 的记录，但笛卡尔积仍会产生这个组合。后面学习连接和除法时，会继续判断哪些组合应该保留。

若两张输入表有同名列，应先更名，或用表名限定来区分。本例一边只有 SID、一边只有 CID，没有重名问题。

5.6 更名 ρ：给中间结果或列换一个名字

名字为什么会影响读题

某份名单的学号列叫 SID，另一份叫 student_no。两列都表示学号，但如果要统一比较，就需要先让名字对齐。另一个常见需求是让同一张表在公式中出现两次，并给两份副本不同的名字，以便说明“谁与谁比较”。

更名用 ρ 表示，读作“柔”（rho）。它改变名称，不改变实际值。

仍使用 R 中的 S1、S2，现在把关系名改为 eligible，把列名改为 student_no：

ρ_{eligible(student_no)}(R)

逐项读：输入是 R；新关系名为 eligible，意思是“符合条件的名单”；括号内的 student_no 是新的列名。结果为：

student_no
S1
S2

若有多列，按原表的列顺序列出对应的新名字，不能漏列或把含义对应错。

只需要给关系换名时，可写 ρ_{A}(student)，表示将学生表的这一份输入称为 A。这样的名字只在表达式中用于区分和引用，不会去修改存储中的原表。将同一张表的两份副本进行连接，称为自连接；“自”指数据来自同一张表，不表示把每行机械地与自己配对。

6. 附加关系代数运算

“附加”表示这些操作可以用基本运算表达，但单独命名后更容易读。它们同样属于课程重点。

6.1 交 ∩：两份名单中都出现

学校想找“数据库和程序设计两门都选了”的学生。仍使用第 5.3 节的两份学号名单：

R：选 C1 S：选 C2
S1 S1
S2 S3

上表的两列是两份独立名单的并排展示，不表示同行学生之间另有联系。

逐个检查：S1 在两边都有；S2 只在 R；S3 只在 S。因此：

R ∩ S

∩ 表示交集，结果只有：

SID
S1

交也要求并相容，因为要判断两边的完整记录是否相同。

教材写成基本运算时，常给出：

R ∩ S = R − (R − S)

等号表示两边得到相同结果。先算括号内的 R−S，得到“只选 C1 的 S2”；再从 R 中去掉 S2，留下 S1。这样就用两次差运算实现了交。

6.2 θ 连接与等值连接：配对之后按条件留下正确组合

姓名和成绩分在不同的表中，不能直接并排摆放就认定对应。连接要先规定哪些两行表示同一项业务事实，再把这些行的列组合到一起。θ 连接说的是配对条件；“等值”进一步说明条件只采用相等比较。

先说明要查什么

教务员想让每条选课记录同时显示学生姓名。姓名在 student，选课和成绩在 takes，因此需要把两张表关联起来。

两表关联的业务依据是学号：选课记录中的 SID，与学生表的 SID 相等时，才表示同一个学生。S2 的成绩不能拼到 S1 的姓名旁边。

手工怎样配对

学生表有 4 行，选课表有 4 行，全部可能组合有 16 个。用下表逐一标出是否保留；列标题中的“学号/课程号”只是标识对应的选课行：

学生行 takes 中 S1/C1 takes 中 S1/C2 takes 中 S2/C1 takes 中 S3/C2
S1 小林 保留 保留 排除 排除
S2 小周 排除 排除 保留 排除
S3 小陈 排除 排除 排除 保留
S4 小吴 排除 排除 排除 排除

只留下两边学号相同的 4 个组合。

公式怎样写

student ⋈_{student.SID=takes.SID} takes

⋈ 是连接符号；下标中的条件说明什么样的两行可以拼在一起。点号用于区分两张表中同名的 SID。

这种“按一个条件连接”的操作一般称为 θ 连接。θ 读作“西塔”，是“连接条件”的占位记号，不是表中真实存在的一列。对于本例，θ 就是 student.SID=takes.SID。

用基本运算表示为：

r ⋈_{θ} s = σ_{θ}(r × s)

r、s 表示任意两张输入关系；右边先列所有配对，再按 θ 筛选。这是在解释连接的逻辑含义，不要求真实数据库必须先生成巨大中间表。

因为本例的条件使用等号，所以它也是等值连接。结果暂时保留两边的 SID，用限定名区分：

student.SID name dept takes.SID CID score
S1 小林 计算机 S1 C1 80
S1 小林 计算机 S1 C2 90
S2 小周 数学 S2 C1 70
S3 小陈 计算机 S3 C2 60

S1 有两行，因为他选了两门课；S4 没有行，因为没有选课记录与他匹配。

若题目进一步要求成绩至少 80，可把 θ 写成 student.SID=takes.SID ∧ score>=80。此时既比较学号，又比较成绩，结果只保留上表的前两行。θ 连接允许这样的条件；只使用相等条件的情况才称为等值连接。

6.3 自然连接：同名列自动对齐，只留一份

为什么还要介绍一种连接

前一节两边的 SID 明明表示同一个学号，结果却显示了两列。自然连接把常见的“按同名列相等进行匹配，并合并重复的同名列”写得更简洁。

student ⋈ takes

没有写下标条件时，这里表示自然连接。两表共同的属性名只有 SID，因此自动要求两边 SID 相等，输出中只留一个 SID：

SID name dept CID score
S1 小林 计算机 C1 80
S1 小林 计算机 C2 90
S2 小周 数学 C1 70
S3 小陈 计算机 C2 60

这张表与前面的等值连接表达相同的配对关系，只是同名连接列合并了。自然连接要检查的是所有同名属性，不是自动判断哪一列是主码。

一个容易查错的例子

如果直接写 student ⋈ course，两表的共同属性名是 dept，于是匹配条件变成“学生所在系等于课程开课系”。结果为：

SID name dept CID title credits
S1 小林 计算机 C1 数据库 3
S1 小林 计算机 C2 程序设计 4
S2 小周 数学 C3 高数 5
S3 小陈 计算机 C1 数据库 3
S3 小陈 计算机 C2 程序设计 4
S4 小吴 数学 C3 高数 5

这可以回答“每名学生所在系开设了哪些课程”，却不能回答“学生实际选了哪些课”。例如小吴没有选课，仍会与数学系的高数配对；小周跨系选的数据库反而不在结果中。

自然连接只认列名和相等条件，不理解业务。写它之前，先列出共同列名，再确认这些相等要求是否都是题目需要的。若没有共同属性，自然连接会退化为所有行的配对，即笛卡尔积。

6.4 除 ÷：检查是否覆盖要求中的每一项

找到一条匹配只能说明“某一项满足”，不能说明全部课程都满足。除运算把要求名单作为独立输入，再逐项检查某个学生是否缺课。它的输出是合格对象的名单，不是给每条选课做数值除法。

业务背景：怎样判断“全部选过”

计算机系开了数据库 C1、程序设计 C2。学校想找出“这两门课全部选过”的学生。只选其中一门不够，选课记录里出现过一次也不够。

先从 course 中筛计算机系课程，再只保留课程号，得到必须覆盖的课程名单：

π_{CID}(σ_{dept='计算机'}(course))
CID
C1
C2

再从 takes 中只保留学号和课程号。成绩与“是否选过”无关，可以去掉：

π_{SID,CID}(takes)
SID CID
S1 C1
S1 C2
S2 C1
S3 C2

先不写公式，逐个检查

学生 是否有 C1 是否有 C2 是否全部满足
S1 小林 有 有 是
S2 小周 有 无 否，缺 C2
S3 小陈 无 有 否，缺 C1
S4 小吴 无 无 否，两门都缺

所以答案是 S1。

关系代数用除运算表达这种“一个对象必须与要求名单中的每一项都有对应记录”的查询：

π_{SID,CID}(takes)
÷
π_{CID}(σ_{dept='计算机'}(course))

左边提供“谁选了什么”的配对，右边提供“必须选哪些”的名单。÷ 在这里不计算分数，不是把两张表的行数相除；它筛出完整覆盖右侧名单的左侧对象。

输出只保留学号：

SID
S1

若还要姓名，需要用 S1 回到 student 中找到小林；第 8 节会把这一步写进完整表达式。

读懂通用写法 r(X,Y) ÷ s(Y)

  • r 是保存配对的关系，X 表示结果要保留的属性，Y 表示需要逐项检查的属性。
  • s 是要求名单，包含的属性正好是 Y，并与 r 中对应属性相容。
  • X、Y 都可以代表一组属性，不一定只是一列。
  • 在本例中 X 是 SID，Y 是 CID，结果回答“哪些 SID 与 s 中每一个 CID 都在 r 中配对出现”。

候选的 X 值取自 r 中已经出现的 X。这个范围在右侧名单为空时尤其重要，后面会单独说明。

为什么除可以用基本运算实现

把“全部满足”换成“没有缺少的项”更容易理解。对本例，先列出配对表中出现过的候选学生 S1、S2、S3，再让每人都与 C1、C2 配一次，得到“如果全部选齐，应该有的组合”：

SID CID
S1 C1
S1 C2
S2 C1
S2 C2
S3 C1
S3 C2

从这张“应该有”的表减去真实配对表，剩下缺少的组合：

SID CID
S2 C2
S3 C1

投影学号，得到不合格名单 S2、S3；再从候选名单 S1、S2、S3 中减去它们，得到 S1。

以上过程对应通用公式：

r ÷ s = π_X(r) − π_X((π_X(r) × s) − r)

从内向外逐项读：

  1. π_X(r) 列出候选对象。
  2. π_X(r) × s 列出每个候选对象应有的全部配对。
  3. 再减去 r，找出缺失的配对。
  4. 对缺失配对投影 X，找出至少缺一项的对象。
  5. 从全部候选对象中减去这些对象，剩下全部满足者。

如果要求名单为空，答案范围是什么

假设某个系这一学期没有开任何课，那么“找出一门该系课程是这个学生没选的”就找不到反例。因此按数学上的全称条件，所有候选对象都满足要求。

但是标准除运算的候选对象来自左侧配对表：本例的 takes 只出现 S1、S2、S3，所以空除数时返回这三人，不会自动带上从未选课的 S4。若题目要求以所有注册学生为候选者，应从 student 取候选名单，再用前面的“排除缺失者”思路计算。这不是符号细节，而是题目要求的对象范围不同。

6.5 赋值 ←：给中间结果取名

除法公式已经比较长。为了避免反复抄写，我们可以给每一步的结果取一个名字：

required_courses ← π_{CID}(σ_{dept='计算机'}(course))
enrolled_pairs ← π_{SID,CID}(takes)
qualified_students ← enrolled_pairs ÷ required_courses

← 读作“将右侧结果记为左侧名字”。这里三个名字分别表示必选课程、实际选课配对、全部满足要求的学生。

因此 required_courses 有 C1、C2 两行，enrolled_pairs 有本节展示的四条配对，qualified_students 只有 S1。后面可以直接使用这些名字，而不必重新写长公式。

赋值在这里是给结果命名，类似在草稿纸上把一个算式结果记为 A。它不是 SQL 的数据更新命令，不会把原始 course 或 takes 改掉。

7. 扩展关系代数运算

前面的运算擅长筛行、选列和组合数据。实际查询还可能需要“计算新值”“统计每组数据”“保留没有匹配项的人”。本节介绍相应扩展，并说明空值出现后需要增加的规则。

7.1 广义投影：输出列可以是算出来的

学校现在需要什么结果

假设教师想查看“每条选课记录的成绩加 5 分后是多少”，用来比较一种假想的加分方案。这只是教学用计算，不实际修改已保存的成绩；本例原成绩最高为 90，加 5 后也没有超过 100。

普通投影只能保留已有列。广义投影允许输出一个由已有列计算出的值：

π_{SID,CID,(score+5)→adjusted_score}(takes)
  • SID、CID 说明这条成绩属于谁和哪门课。
  • score+5 表示读取这一行的原成绩再加 5。
  • →adjusted_score 表示把算出的这一列命名为 adjusted_score，中文可读为“调整后成绩”。
  • 这里的右箭头给结果列命名，与上一节给整张中间表取名的左箭头 ← 不同。

逐行算出结果：

SID CID adjusted_score
S1 C1 85
S1 C2 95
S2 C1 75
S3 C2 65

例如第一行从 80 算出 85，第二行从 90 算出 95。输出没有 score 列，是因为公式没有要求保留它；若想同时显示原成绩，也应把 score 列写进投影列表。计算结果仍是一张查询结果表，原选课表中的 80、90、70、60 没有改变。

7.2 聚集与分组 γ：先分堆，再对每堆算一个结果

为什么单纯筛行不能回答统计问题

学校想知道“每个系开了几门课，平均每门课多少学分”。输入是课程表：

CID title dept credits
C1 数据库 计算机 3
C2 程序设计 计算机 4
C3 高数 数学 5

我们先按照开课系把行分堆：计算机系一堆，包含 C1、C2；数学系一堆，只有 C3。这样的过程叫分组。

再对每堆的多条数据计算一个统计值，这叫聚集：

组 包含的课程 课程数 平均学分的计算
计算机 C1、C2 2 (3+4)÷2=3.5
数学 C3 1 5÷1=5

聚集运算用 γ 表示，读作“伽马”。本章统一采用下面这种下标写法：

γ_{dept; count(CID)→course_count, avg(credits)→avg_credits}(course)

逐项读：

  • 括号中的 course 是输入表。
  • 分号前的 dept 是分组依据：dept 相同的行放到同一组。
  • 分号后列出每组要计算什么。
  • count(CID) 表示统计该组课程号的数量；course_count 是结果列名。
  • avg(credits) 表示计算该组学分的平均数；avg_credits 是结果列名。
  • 逗号分开两项统计计算；箭头仍表示给算出的列命名。

结果为：

dept course_count avg_credits
计算机 2 3.5
数学 1 5

每一行现在代表一个系的统计结果，不再代表一门课程。因此结果没有某一门课的 title，也不能把课程明细列随意塞进来。

课件有时把分组属性写在 γ 左侧，例如 dept γ_{avg(credits)→avg_credits}(course)。它与本章 γ_{dept;avg(credits)→avg_credits}(course) 表达同一种分组思路；读题时先找到分组属性和统计表达式。

常用聚集函数各在算什么

“函数”在这里就是一种命名好的计算规则。以计算机系的两个学分 3、4 为输入：

写法 中文意思 本例计算 结果
sum(credits) 求和 3+4 7
avg(credits) 求平均值 (3+4)÷2 3.5
count(CID) 计数 数一数 C1、C2 2
min(credits) 求最小值 比较 3、4 3
max(credits) 求最大值 比较 3、4 4

平均值的分母是组内参与计算的数值个数，不是全表的行数。重复出现的数值也会按其所在行参与统计，例如两个不同课程各为 3 学分，求和是 6；不要先把数值去重再求和。

不分组时会怎样

若学校想求所有选课成绩的平均数，就把 takes 整张表作为一组：

γ_{avg(score)→avg_score}(takes)

平均分为 (80+90+70+60)÷4=75，结果是一行一列：

avg_score
75

没有写分组属性，表示统计整个输入。这里按四条选课记录计算，小林的两门课各参与一次；它不是“先求每名学生平均分，再对学生求平均”。

统计后还要筛选怎么办

如果只要“至少开了两门课的系”，先把完整统计表记为 dept_stats，再筛其 course_count：

dept_stats ← γ_{dept;count(CID)→course_count,avg(credits)→avg_credits}(course)
σ_{course_count>=2}(dept_stats)

结果为：

dept course_count avg_credits
计算机 2 3.5

course_count 是聚集之后才产生的列，不能在原 course 上直接用它做选择。这解释了为什么必须先统计、再筛统计结果。

7.3 外连接：没有匹配项，也可以保留

背景：学校不想漏掉没选课的学生

前面的 student ⋈ takes 只有四行选课结果，小吴 S4 被排除了，因为他没有匹配的选课记录。这种只保留成功配对的连接，通常也叫内连接。

现在学校需要“全部学生的选课情况，包括没选课的学生”。我们仍然按 SID 匹配，但找不到右侧选课记录时，也要给左侧学生保留一行。这样的操作叫左外连接：

student ⟕ takes

⟕ 是左外连接符号。这里按自然连接的方式匹配同名 SID，并保留左侧 student 的全部学生。没有匹配的右侧列使用 NULL 补齐：

SID name dept CID score
S1 小林 计算机 C1 80
S1 小林 计算机 C2 90
S2 小周 数学 C1 70
S3 小陈 计算机 C2 60
S4 小吴 数学 NULL NULL

S4 的学号、姓名和所在系来自左表，所以都有值；课程号与成绩需要来自右表，但没有相应选课行，因此补空。这里的 NULL 表示没有匹配选课信息，不表示小吴得了 0 分。

“保留左表所有行”不等于结果行数一定与左表相同。S1 匹配了两条选课记录，仍会展开为两行；本例 4 名学生产生了 5 行结果。

右外连接与全外连接

  • 右外连接 ⟖：保留右边关系的每一行；左边没有匹配时补 NULL。
  • 全外连接 ⟗：两侧没有匹配的行都保留，缺失的一侧补 NULL。

对于同一组输入，student ⟖ takes 保留每条选课记录。由于 takes 中每条记录都能找到已有学生，本例结果与内连接相同：

SID name dept CID score
S1 小林 计算机 C1 80
S1 小林 计算机 C2 90
S2 小周 数学 C1 70
S3 小陈 计算机 C2 60

student ⟗ takes 则与前面的五行左外连接结果相同：多出的未匹配行只有 S4，没有“找不到学生的选课记录”。

这只是本组数据的结果，不表示右外连接总等于内连接，或全外连接总等于左外连接。区别取决于哪一侧存在未匹配行。

7.4 空值扩展：筛选和统计要怎样理解

外连接可能产生原表没有的 NULL 占位值；成绩未公布也可能带来 NULL。此时只会普通真/假的规则不够：要区分“明确不符合”和“还不能判断”，再看筛选与统计各怎样处理。

普通比较遇到未知值时不能硬作判断

左外连接的 S4 行中 score 为 NULL。如果接着选择 score>=60，S4 的比较结果是 UNKNOWN。采用 SQL 风格的空值扩展时，选择只保留 TRUE 的行，因此 S4 不会被保留。

这说明即使前一步使用左外连接，后一步的筛选仍可能排除补空行。如果目标是“保留及格者和没有选课的人”，需要明确写出两类条件；判空条件的具体符号可能随教材扩展记法不同，在 SQL 中使用 IS NULL。

UNKNOWN 与 FALSE 为什么不一样

继续使用第 2 节“成绩还没公布”的独立场景。如果既不知道小陈是否及格，也就不能断言“小陈不及格”。因此否定 UNKNOWN 仍是 UNKNOWN。

遇到组合条件，可用下面的小表理解关键规则：

条件组合 结果 原因
TRUE ∧ UNKNOWN UNKNOWN 还不知道第二项，不能确认两项都真
FALSE ∧ UNKNOWN FALSE 已有一项为假，不可能两项都真
TRUE ∨ UNKNOWN TRUE 已有一项为真，足以满足“或者”
FALSE ∨ UNKNOWN UNKNOWN 能否成立仍取决于未知的那项
¬UNKNOWN UNKNOWN 不知道真伪，否定后仍不知道

本节是带空值的扩展语义，不能拿普通二值逻辑的直觉强行替代。

空值参加统计时的约定

本章涉及 NULL 的聚集例子采用常见的 SQL 风格规则：

  • count(*) 中的星号表示统计行数，包括含 NULL 的行。
  • count(score) 只数 score 有非空值的行。
  • sum、avg、min、max 忽略对应列中的 NULL。
  • 对没有可用数值的输入，count 返回 0，其他上述聚集通常返回 NULL；没有分组属性的整体聚集仍可返回一行统计结果，而分组聚集在完全没有输入行时没有实际组可输出。

例如成绩为 80、0、NULL 时，行数是 3，非空成绩数是 2，平均分是 (80+0)÷2=40。不能把 NULL 当作 0 算成 80÷3。经典关系代数本身没有规定这些 SQL 扩展细节，考试应结合课程给定的语义。

8. 怎样把一句题意写成表达式

8.1 完整示范：谁选完了计算机系的全部课程

题目要求输出学生学号和姓名。背景仍为第 1 节学校数据，计算机系有 C1、C2，学生可以跨系选课。这里要求的是“选了该系全部课程”，没有额外要求学生本人属于计算机系。

先做四步：

  1. 从 course 筛出计算机系课程，投影课程号。
  2. 从 takes 保留学号与课程号，得到实际配对。
  3. 用除法找出全部满足要求的学生学号。
  4. 把合格学号与 student 按 SID 匹配，取出姓名。

写成中间结果：

required_courses ← π_{CID}(σ_{dept='计算机'}(course))
enrolled_pairs ← π_{SID,CID}(takes)
qualified_students ← enrolled_pairs ÷ required_courses
qualified_details ← qualified_students ⋈ student
answer ← π_{SID,name}(qualified_details)

每一步的表结构及结果如下：

中间结果 包含的列 本例的全部行
required_courses CID C1；C2
enrolled_pairs SID、CID (S1,C1)；(S1,C2)；(S2,C1)；(S3,C2)
qualified_students SID S1
qualified_details SID、name、dept (S1,小林,计算机)
answer SID、name (S1,小林)

最后答案：

SID name
S1 小林

每一步都能说清以后，再合并成长表达式：

π_{SID,name}
(
  (π_{SID,CID}(takes) ÷ π_{CID}(σ_{dept='计算机'}(course)))
  ⋈ student
)

换行不改变计算含义。先算最深层括号，再计算除法、连接，最后投影。做题时完全可以先写中间表版本，以减少漏条件或提前丢列。

8.2 写公式前，先回答五个问题

要问的问题 为什么需要问
最终要返回哪些列？ 防止答成学号却忘记姓名，或多带无关信息
这些列和条件分别在哪张表？ 决定需要哪些输入关系
表之间靠什么关联？ 防止漏连接条件或误用同名列
题目说“至少一个”“没有”还是“全部”？ 这三种要求对应不同逻辑
每步之后还剩哪些列？ 防止后续条件引用已被投影掉的列

可以把题目关键词当提示，但不能机械套公式：

题意 可以考虑的操作 仍要检查什么
至少有一次符合的记录 筛选、连接，再投影对象 重复记录怎样去重
同时属于两份名单 交 两边是否都是同一种对象
有 A，但没有 B 差 左右方向是否写反
满足要求名单中的每一项 除或排除缺失者 候选对象范围、要求名单是否为空
每组平均值达到条件 分组聚集后再选择 分组依据与平均值分母

8.3 怎样用反例检查自己的答案

如果公式看起来正确，可以拿一个边界人物检查：小吴 S4 没选课，你的“没有选课学生”查询能否找出他？小周 S2 跨系选了数据库，你的“所有选课记录”查询有没有误把他排除？

尤其不要随意把 student ⋈ takes ⋈ course 当作正确的三表选课查询。第一步已有学生所在系 dept，第二步又会匹配 course 的开课系 dept，导致跨系选课被排除。需要两种系都出现在结果时，应先把课程表的 dept 更名，例如：

course_info ← ρ_{course_info(CID,title,course_dept,credits)}(course)
student ⋈ takes ⋈ course_info

course_info 与原课程表的数值和列顺序相同，只把第三列名称改为 course_dept。于是两条连接分别依靠 SID 和 CID，不再额外要求两种系相同。完整结果为：

SID name dept CID score title course_dept credits
S1 小林 计算机 C1 80 数据库 计算机 3
S1 小林 计算机 C2 90 程序设计 计算机 4
S2 小周 数学 C1 70 数据库 计算机 3
S3 小陈 计算机 C2 60 程序设计 计算机 4

这样小周的跨系选课也被正确保留。

9. 元组关系演算

前面用一串运算说明怎样得到答案。现在换一个角度：能不能直接规定答案必须满足哪些条件？元组关系演算让变量代表一整行，再用条件约束它。这种改变的是表达方式，不是把同一批学生换成另一种数据。

9.1 先说答案的条件，再学符号

还是查询“计算机系的全部学生记录”。用普通话说，答案应该包含这样的行：

这行必须来自 student，而且这一行的 dept 必须是“计算机”。

元组关系演算用一个变量代表整行数据，再描述这行必须满足的条件。所谓“变量”，就是暂时代表某个对象的名字；这里用 t，t 可以依次代表学生表里的不同记录。

{ t | t ∈ student ∧ t[dept]='计算机' }

这次花括号是一种集合描述，含义是“收集所有满足后面条件的 t”。它与前面 σ_{条件} 中表示下标的花括号用途不同。

记号 本例中的意思
t 一个待检查的完整学生元组
竖线 | “使得”或“满足下面条件”
t ∈ student t 必须是学生表中的一行；∈ 读作“属于”
t[dept] 取 t 这一行的 dept 值
∧ 两个条件都要成立

对四行学生逐一检查，只有 S1、S3 满足，所以结果为：

SID name dept
S1 小林 计算机
S3 小陈 计算机

它与选择公式得到同一张结果表。两者的区别在表达方式：选择公式指定运算，演算公式列出结果必须满足的条件。

教材写成 {t | P(t)} 时，P(t) 就是“关于 t 的判断条件”的通用名字，不是另一个需要查找的数据表。

9.2 “存在一条记录”怎样写

学校想找出至少选了数据库 C1 的学生，并返回完整学生资料。普通话条件是：

学生 t 属于 student，并且能在 takes 中找到某一行 u；u 的学号与 t 相同，课程号为 C1。

“存在某一行”用 ∃ 表示：

{ t |
  t ∈ student
  ∧ ∃u (
      u ∈ takes
      ∧ u[SID]=t[SID]
      ∧ u[CID]='C1'
    )
}

∃u 读作“存在一个 u”。括号中的要求必须由同一条选课记录 u 同时满足：来自 takes、学号正确、课程正确。

逐人检查：

学生 能找到的 C1 选课记录 是否返回
S1 小林 (S1,C1,80) 是
S2 小周 (S2,C1,70) 是
S3 小陈 没有 否
S4 小吴 没有 否

最终结果：

SID name dept
S1 小林 计算机
S2 小周 数学

t 决定返回哪一行，称为自由变量；u 被 ∃ 引入，只在相关条件中用于寻找证据，称为受约束变量。这里不返回 u 的选课行，而是返回对应的 t 学生行。

9.3 “所有”与“不存在反例”

把要求说成“对每门计算机系课程，都存在这名学生的一条选课”，可写成下面的有界量词示意。量词后的 c∈course、u∈takes 说明候选记录来自哪里；⇒ 表示仅在左侧条件成立时要求右侧成立。

{ t | t∈student ∧ ∀c∈course (
    c[dept]='计算机' ⇒ ∃u∈takes (
        u[SID]=t[SID] ∧ u[CID]=c[CID]
    )
) }

对 S1 检查 C1、C2 都能找到记录，所以保留。对 S2 检查 C2 找不到，所以排除。C3 属于数学系，左侧条件不成立，不会被误当作必选课。这里外层 t 来自全部 student；如果计算机系没有开课，四名学生都没有缺项，和候选范围来自 takes 的标准除运算要分别理解。

另一个量词是 ∀，读作“对每一个”或“所有”。如果要求选完 C1、C2，意思就是：对要求名单中的每门课程，都能找到这名学生的选课记录。

也可以改说：“不存在一门要求课程，是这名学生没有选过的。”其中“不存在”可写作 ¬∃，即“非”与“存在”的组合。第 6.4 节除法中“先找缺失配对，再排除缺失者”，正是在做同一件事。

理解时要明确量词的范围：“全部课程”可能指 course 中的全部课程，也可能只指计算机系课程。范围不同，答案就可能不同，不能只看到“所有”两个字就跳过条件。

10. 域关系演算与安全表达式

如果只想返回姓名，可以让变量分别代表学号、姓名、系，而不必每次用变量代表整行。这就是域关系演算的出发点。无论选哪种演算，还要把变量范围限制在与数据库有关的值中，避免产生无限、与业务无关的答案。

10.1 每个变量只代表一个格子的值

元组关系演算用 t 代表整行。域关系演算改用多个变量，各自代表某个属性值。

仍查询计算机系学生的全部资料。令 s 代表学号，n 代表姓名，d 代表所在系；这些小写字母是变量名，和前面某份名单 S 的名字没有关系。

{ <s,n,d> | <s,n,d> ∈ student ∧ d='计算机' }
  • <s,n,d> 表示按学生表的三列顺序组成的一行；这里的尖括号是在包装一组值，不是比较大小。
  • <s,n,d> ∈ student 要求这三个值组成的行确实存在于 student。
  • d='计算机' 限定第三个值是计算机。
  • 竖线左侧写要返回的值，右侧写这些值需要满足的条件。

结果仍为：

SID name dept
S1 小林 计算机
S3 小陈 计算机

如果只要姓名，把左侧改为 <n> 还不够，需要说明其余变量从哪里来：

{ <n> | ∃s ∃d (<s,n,d> ∈ student ∧ d='计算机') }

这表示“收集姓名 n，只要能找到学号 s 和所在系 d，让三者组成一条计算机系学生记录”。s、d 被存在量词约束，不作为答案返回。结果为：

name
小林
小陈

10.2 为什么要限制为安全表达式

假设有人写：

{ <x> | x ≠ 'S1' }

≠ 表示“不等于”。这条式子要求返回所有不等于 S1 的 x，却没有说 x 必须来自哪张表。如果允许 x 是任意字符串，那么 S2、苹果、无限多种其他文字都符合，结果可能无限大，也与学生业务无关。

对数据库查询，我们需要答案能由数据库中有限的数据和表达式中的常量构成，而不是跑到无限的字符串世界中寻找。“结果受到这种有限范围约束”的要求，就是理解安全表达式的入口。

若真正想找“学生表中除 S1 之外的学号”，可以写：

{ <s> | ∃n ∃d (<s,n,d> ∈ student ∧ s ≠ 'S1') }

此时 s 必须来自某条 student 记录，候选范围是 S1、S2、S3、S4，结果为：

SID
S2
S3
S4

仅仅说“x 是字符串类型”并不能解决问题，因为字符串类型仍可能有无限多种值。初学时重点检查：输出变量是否有明确的数据来源，量词作用在哪些变量和条件上。复杂的安全性形式判定超出本节的入门要求。

容易误解的地方 应怎样检查
把选择当作选列 选择按条件保留整行；投影才决定保留哪些列
觉得每种运算都只减少行数 笛卡尔积会组合行，连接也可能让同一对象出现多次

12.1 题目一：主码设计

原题与 PPT 参考答案

在学生表中，将学号（ID）和姓名（name）的组合设计为该表的主键是否合理？为什么？

PPT 参考答案：

不合理。因为这种情况下，允许有多个姓名不同的学生对应相同学号的情况。

先理解问题的背景

学校给学生分配学号，约定每个学生的学号唯一。题目中的 ID 就是本章学校示例里的 SID，只是换了字段名；name 仍表示姓名。

现在有人提议：数据库不要只检查学号是否重复，而是检查“学号与姓名组合”是否重复。这会造成什么结果？

假设尝试保存以下两条记录：

ID name
1001 张三
1001 李四

如果只检查两列组合，(1001,张三) 与 (1001,李四) 确实不同，因此单独的复合主键约束可能允许这两行同时存在。但学校要求学号本身唯一，1001 不应代表两名不同学生。

从候选码定义再检查一次

若 ID 本身就被业务规定为唯一，{ID} 已经足以区分学生，是候选码。{ID,name} 也能区分，但去掉 name 后仍能区分，所以它是含多余属性的超码，不是最小超码。

因此合理设计是把 ID 作为主码，name 作为普通姓名属性。若额外又为 ID 单独声明唯一约束，虽然可以阻止上述重复学号，复合主码仍然加入了无必要的姓名信息。题目考查的是业务唯一性与候选码的最小性，不是说 SQL 语法绝对禁止声明两列主键。

12.2 题目二：银行数据库关系代数

原题

已知银行企业的数据库由以下表组成：
①分行表 branch(branch-name, branch-city, assets)
②客户表 customer(customer-name, customer-street, customer-city)
③贷款明细表 loan(loan-number, branch-name, amount)
④客户贷款表 borrower(customer-name, loan-number)
⑤存款明细表 account(account-number, branch-name, balance)
⑥客户存款表 depositor(customer-name, account-number)
注：带下划线的属性为主码，假设客户的名字不相同。
（1）用 SQL 语句创建表。
（2）使用关系代数和 SQL 语句找出在 Brighton 银行中有存款的所有客户的姓名、存款号和存款额。
（3）使用关系代数和 SQL 语句找出账户平均余额小于 5000 元的支行，显示支行名称及账户平均余额。
（4）使用关系代数和 SQL 语句找出所有在银行中有贷款但无账户的客户。
（5）使用关系代数和 SQL 语句对所有存款余额大于平均存款额的账户付 3% 的利息。

本章分析（2）至（5）的关系代数部分。（1）的 SQL 建表和其他 SQL 答案在第 3 单元。原题用连字符连接字段名，下文统一改用下划线，例如 branch-name 写成 branch_name，以免与减号混淆。

银行业务背景：为什么需要六张表

分行是银行在不同地点开展业务的单位。客户可以在某个分行开账户，也可以申请贷款。“客户是谁”“账户里多少钱”“哪位客户拥有哪个账户”是不同事实，所以分别记录。

关系模式 每一行表示什么 各属性含义
branch(branch_name,branch_city,assets) 一个分行 分行名称、所在城市、分行资产
customer(customer_name,customer_street,customer_city) 一名客户 姓名、居住街道、居住城市
loan(loan_number,branch_name,amount) 一笔贷款 贷款号、所属分行、贷款金额
borrower(customer_name,loan_number) 一名客户参与一笔贷款 客户姓名、贷款号
account(account_number,branch_name,balance) 一个存款账户 账户号、开户分行、账户余额
depositor(customer_name,account_number) 一名客户拥有一个账户 客户姓名、账户号

borrower 连接客户与贷款，depositor 连接客户与账户。一个客户可以拥有多个账户，一个账户也可以由多人共同持有，因此不能只在客户表中放一个账户号。题目假定姓名互不相同，所以此处用姓名识别客户；这只是题目约定。

（2）找出 Brighton 分行存款客户的姓名、账户号和余额

PPT 情况：PPT 给出 SQL，没有给关系代数答案。下文是按题意补充的关系代数分析。

题目中的“存款号”对应 account_number，“存款额”在本题查询中对应账户余额 balance。Brighton 在表中是分行名称，不是客户姓名或城市。

第一步，在 account 中按分行筛选：

brighton_accounts ← σ_{branch_name='Brighton'}(account)
account_number branch_name balance
A1 Brighton 1000
A2 Brighton 3000

第二步，要知道这些账户由谁持有，按共同的 account_number 与 depositor 自然连接：

brighton_owners ← depositor ⋈ brighton_accounts
customer_name account_number branch_name balance
张三 A1 Brighton 1000
李四 A2 Brighton 3000

第三步，只保留题目要求的三列：

π_{customer_name,account_number,balance}(brighton_owners)
customer_name account_number balance
张三 A1 1000
李四 A2 3000

完整表达式：

π_{customer_name,account_number,balance}
(
  depositor ⋈ σ_{branch_name='Brighton'}(account)
)

为什么不必再连接 customer？因为题目只要姓名，而 depositor 已有姓名；只有还要住址等信息时才需要 customer。若某个 Brighton 账户由两人共同持有，应返回两条“客户—账户”记录，不能为了账户号不重复而丢掉一名持有人。

（3）找出账户平均余额小于 5000 元的支行

题目要比较的是每个分行内部的账户平均余额。同一个账户有几位持有人，不应该影响它在平均值中的权重，因此从 account 直接统计。

第一步，按 branch_name 分组：

  • Brighton 组的账户是 A1、A2，平均值为 (1000+3000)÷2=2000。
  • Riverside 组只有 A3，平均值为 8000÷1=8000。

公式与中间结果：

branch_avg ← γ_{branch_name;avg(balance)→avg_balance}(account)
branch_name avg_balance
Brighton 2000
Riverside 8000

第二步，筛选平均值严格小于 5000 的组：

σ_{avg_balance<5000}(branch_avg)
branch_name avg_balance
Brighton 2000

如需显式列出输出列，完整答案可写成：

branch_avg ← γ_{branch_name;avg(balance)→avg_balance}(account)
π_{branch_name,avg_balance}(σ_{avg_balance<5000}(branch_avg))

不能先筛 balance<5000 再求平均，因为那会先丢掉高余额账户，计算出不同的问题。也不能先连接 depositor 后直接求平均，否则共同持有的账户可能被重复计入。

如果某分行没有账户，它不会在 account 的分组中形成一组。本题没有要求显示零账户分行；若题意改变，需要以 branch 为起点补足，并说明无账户时的平均值含义。

（4）找出有贷款但无账户的客户

先把题意拆成两份客户名单：“有贷款的人”和“有账户的人”，再从第一份减去第二份。

第一步，只从 borrower 取客户姓名：

loan_customers ← π_{customer_name}(borrower)
customer_name
张三
王五
赵六

第二步，只从 depositor 取客户姓名：

account_customers ← π_{customer_name}(depositor)
customer_name
张三
李四

张三、李四各有多个持有关系，但投影后相同姓名只出现一次。

第三步，作差：

loan_customers − account_customers
customer_name
王五
赵六

张三虽然有贷款，但也有账户，应排除；李四本来就不在贷款名单里；王五、赵六都只出现在贷款名单中，所以保留。

完整表达式：

π_{customer_name}(borrower) − π_{customer_name}(depositor)

两边都是同一种客户姓名列，满足并相容。直接连接两张表会找到同时有贷款和账户的人，与“有贷款但无账户”相反。

（5）给余额高于平均余额的账户增加 3% 利息

PPT 情况：PPT 给出 SQL UPDATE。经典关系代数是查询表达方式，下面使用扩展运算构造更新后应得到的结果表；把这张结果真正写回数据库，需要 SQL 更新等数据修改机制。

题目中的平均值是所有账户更新前余额的平均值，不是各分行平均值。先计算一次，再据此决定哪些账户加息。

第一步，算全体账户平均值：

A ← γ_{avg(balance)→avg_balance}(account)

A 是本题临时给平均值结果取的表名，不是账户 A1。计算为 (1000+3000+8000)÷3=4000：

avg_balance
4000

第二步，为每个账户附上同一个平均值。A 只有一行，因此 account 与 A 的笛卡尔积仍是三行：

account × A
account_number branch_name balance avg_balance
A1 Brighton 1000 4000
A2 Brighton 3000 4000
A3 Riverside 8000 4000

第三步，把账户分成两组。H 表示高于平均值、需要加息的账户，L 表示其余账户：

H ← σ_{balance>avg_balance}(account × A)
L ← σ_{balance<=avg_balance}(account × A)

H 的全部内容：

account_number branch_name balance avg_balance
A3 Riverside 8000 4000

L 的全部内容：

account_number branch_name balance avg_balance
A1 Brighton 1000 4000
A2 Brighton 3000 4000

“高于”是严格大于，因此恰好等于平均值的账户应放入 L。这里假定 balance 非空，所以 > 与 <= 能覆盖所有账户。

第四步，用广义投影给 H 加息。增加 3% 表示原余额加原余额的 0.03 倍，即乘以 1.03。A3 得到 8000×1.03=8240：

changed ← π_{account_number,branch_name,(balance*1.03)→balance}(H)
unchanged ← π_{account_number,branch_name,balance}(L)

changed 只有 (A3,Riverside,8240)，unchanged 有 (A1,Brighton,1000)、(A2,Brighton,3000)。两边都恢复为原 account 的三列；avg_balance 已完成比较任务，不再需要。

第五步，把两组结果合并：

account_new ← unchanged ∪ changed
account_number branch_name balance
A1 Brighton 1000
A2 Brighton 3000
A3 Riverside 8240

整套表达式可整理为：

A ← γ_{avg(balance)→avg_balance}(account)
H ← σ_{balance>avg_balance}(account × A)
L ← σ_{balance<=avg_balance}(account × A)

account_new ←
  π_{account_number,branch_name,balance}(L)
  ∪
  π_{account_number,branch_name,(balance*1.03)→balance}(H)

account_new 是构造出的结果，不表示原 account 已实际被改写。平均值也不随每一行的加息反复重算；否则不同处理顺序可能改变哪些账户符合条件。若题目允许空余额，还必须明确未知余额的保留规则，不能直接套用上面的两组划分。

15. 表运算、条件和连接名称怎样分层理解

表达式 π_{name}(σ_{dept='计算机'}(student)) 有完整结构，不能把每个符号都当成一条独立查询。

层次 当前例子 负责什么
完整查询表达式 最外层投影包住选择 回答“哪些计算机系学生的姓名”
表运算 π、σ 分别输出列、筛选行
运算的参数 name、dept=计算机 指定留下哪列或采用哪个条件
条件中的判断 =、∧、∨、¬ 比较和组合判断结果
输入关系 student，或某个内层结果 为这一层提供行和列

连接名称也不是都在同一个角度分类：

要回答的问题 名称或写法 可以怎样组合
怎样确定配对 θ 条件、等值条件、自然的同名列条件 自然连接同时涉及同名列合并
未配对者是否留下 内连接、左/右/全外连接 外连接可以采用显式条件，也可以采用自然匹配
两个输入是否来自同一表 自连接、不同表连接 自连接也可使用内连接或外连接

运算先后是否可换，要检查结果所需信息。先取姓名会丢掉 dept，因而不能再按系筛选；如果先投影保留 name 和 dept，仍有条件列，就可以继续筛选，最后再只输出姓名。不是“选择和投影永远不能交换”，而是不能提前丢掉之后还需要的属性。

还要分清集合语义和多重集语义：本章经典代数对完整行去重；某些 SQL/扩展代数允许同一行出现多次。把“选课记录数”和“不同学生数”混成同一个数，往往是没有先问清对象与重复处理规则。
