1. 自底向上分析要做什么

1.1 从输入的单词逐步搭回开始符

自底向上分析从输入 Token 出发，把已识别的局部结构归约成非终结符，直到完整程序被归约为开始符。相比自顶向下先展开文法，它先看见具体输入，再逐层确认结构。

四种动作是：移入，把当前输入 Token 压栈并前进输入；归约，用一条规则左部替换栈顶对应右部；接受，确认完整输入与开始结构匹配；报错，当前格局没有合法动作。

核心不是“有没有一段文字等于某规则右部”，而是“它是否是此时应该撤销的最右推导步骤”。例如表达式中看到 T 时，既可能归约成 E，也可能还需等待 *F，不能任选。

1.2 课件 (a+t)*c 的完整结构归约

词法把 a、t、c 都归为终结符 i。文法为 E→E+T|T、T→T*F|F、F→(E)|i，输入 (i+i)*i。下面栈底左、栈顶右，表中动作在该行格局上执行：

1.3 LR 名字的含义

L 表示从左到右扫描，R 表示最右推导的逆过程，即规范归约。括号内数字表示归约决策所用的向前看 Token 数；LR(0) 不为完成项目附展望符，LR(1) 采用一个。

LR(0) 也必须读取当前输入以决定移入哪条终结符边；“不看输入”是指其普通归约项目对所有头符都要求归约，并非驱动完全没有读头。课件点名算符优先、简单优先等找句柄方法，本组课件展开的是 LR 家族，未给出前两者的完整算法。

2. 符号与规范活前缀

2.1 记号说明

记号 含义
VT、VN 终结符、非终结符集合
α、β、π 任意文法符号串；π 在相关定义中代表句柄
ε、# 空串；输入结束记号
A→β 一条产生式
⇒rm、⇒rm* 一步、零步或多步最右推导
· 项目圆点，标记已识别部分与待识别部分的界线
Ii 第 i 个项目集，同时作为一个分析状态
CLOSURE、GO 项目闭包、状态转换
ACTION[i,a] 当前状态 i 和输入 a 决定的动作
GOTO[i,A] 归约出非终结符 A 后从状态 i 转到哪里
sj、rk、acc 移入到 j；按第 k 条规则归约；接受
FIRST、FOLLOW 串可能的首终结符；非终结符可能的后继

FOLLOW 不含 ε；FIRST(βa) 中的 a 是一个真正展望 Token 或 #。项目中的圆点不是输入字符。

2.2 句柄必须带结构和位置

规范句型由最右推导产生。若 S⇒rm*αAβ⇒rmαπβ，其中使用 A→π，且 β 为终结符串，则 απβ 中这次出现的 π 是要逆向撤销的句柄。重复拼写时必须指明是哪一位置。

把任意右部匹配片段都称为句柄会误归约。句柄不仅包含右部文字，还关联具体产生式及规范推导位置。

2.3 规范前缀、活前缀与可归前缀

课件规范前缀α 满足存在规范句型 αβ，β 为终结符串或空串。活前缀是不越过当前句柄右端的这种前缀；它可能尚未包含完整句柄，也可能恰好以完整句柄结束。后一种称可归前缀。

直观上，栈保存已处理部分，不应把句柄右边的结构也一并压过头。可归前缀只要求“某规则已完整”，是否现在执行归约还由当前状态和所采用方法决定。

2.4 派生定理与 aAc 例

课件给可归前缀派生规律：开始符规则的右部是可归前缀；若 αAβ 是可归前缀且 A→π 是规则，则 απ 也是可归前缀；可归前缀可如此派生。

对 S→aAc、A→dbb|b，可归前缀为 aAc、adbb、ab。为什么不是 adbbc？adbb 已以 A 的句柄 dbb 结束，再移入尾部 c 就越过该句柄；应先归约 A，再把 c 接到 aA 上完成 S。

可归前缀集合可能无限，项目集自动机用有限状态识别这些分析进度。自动机输入是 VT∪VN 的文法符号，而源码 Token 流本身仍只有终结符；非终结符由归约后产生。

3. LR(0) 项目及三个运算

3.1 圆点表示进度

LR(0) 项目是在产生式右部加入一个圆点。S→aAc 有四种：

S→·aAc   尚未识别此右部
S→a·Ac   已识别 a，等待 A、c
S→aA·c   已识别 aA，等待 c
S→aAc·   整个右部已经识别，可提出归约

点后是终结符时可移入该 Token；点后是非终结符时需要识别其结构，不能从输入直接“移入非终结符”；点在末尾时是完成/归约项目。空规则 A→ε 只有 A→·，从开始就完成，不能把 ε 当作待移入字符。

3.2 投影：圆点越过同一符号

项目集 I 关于 X 的投影为 I(X)={A→αX·β | A→α·Xβ∈I}。只取点后恰为 X 的项目，点右移一位。

若 I={S→a·Ac,A→·dbb,A→·b}，则 I(A) 为 {S→aA·c}，I(d) 为 {A→d·bb}，I(b) 为 {A→b·}；I(a)、I(c)、I(S) 为空。课件投影例里 A→dbb 的编号误排，这里按原规则身份处理。

3.3 闭包：等待 A 就加入 A 的所有开头

CLOSURE(I) 先包含 I；若有 B→α·Aβ，则加入 A 的每条规则 A→·γ，再对新增项目继续检查，直到没有新项。它表达“接下来要识别 A，因此 A 的所有起始方式也可能处于当前分析进度”。

例如 {S→a·Ac} 的闭包为 {S→a·Ac,A→·dbb,A→·b}。只加点后非终结符的规则，不能把文法全部规则无条件塞入每个状态。

3.4 GO：投影后闭包

GO(I,X)=CLOSURE(I(X))。投影说明读/归约出 X 后进度变化，闭包补足新位置上可能开始的结构。空投影的 GO 为空，不建立边。

闭包是一个项目集内部补项，GO 是项目集之间转换；两者不能混同。项目集合整体相同才是同一个 LR(0) 状态，排列顺序不影响身份。

4. 构造 LR(0) 状态机

4.1 增广与接受约定

统一增加新开始符 S'，规则 S'→S。初态为 CLOSURE({S'→·S})，S'→S· 且头符 # 时接受。S' 不出现在任何规则右部。

课件有些例子直接在原开始规则完成时接受，有的用 S→E$ 并移入 $，这些采用不同约定。本资料使用统一增广，不把课件 $ 和 # 混合；因此可能比不增广课件多一个接受状态。

4.2 待处理队列构造

从初态开始，对每个未处理 I 和每个 X∈VT∪VN 算 GO。非空且新集合出现，就加一个新状态；若已存在，连接到旧状态。直到全部已知状态都处理完。

因为产生式与圆点位置有限，可能项目集有限，构造会终止。实现要按集合去重；课件的 NO 是“尚未处理”的工作标记，不是状态属性或源码内容。

4.3 基本项目与派生项目

基本/核心项目通常来自前驱转换，即圆点移动后的种子项，初态还包括增广起始项；派生项目由闭包补入，点在右部最左。饱和项目集是已求完闭包的项目集。

注意后文 LALR 的“状态心”按课件定义指忽略展望符后的 LR(0) 项目集合，不可把术语与只取部分核项目混用。

5. 分析表与通用驱动

5.1 ACTION 与 GOTO 分工

ACTION 的列是 VT∪{#}，GOTO 的列是 VN。移入由点后终结符边决定；归约由完成项目和方法规定的展望范围决定；接受只填增广完成状态的 # 列；未填格报错。

LR(0) 普通完成项目 A→β· 要在全部终结符及 # 列填该规则归约。如果同格还要移入或另一个归约，表有冲突，不能悄悄覆盖其中一个。

5.2 归约为何先弹栈再查 GOTO

状态栈初始 [0]，符号栈初始 [#]。当按 A→β 归约，令 n=|β|，从符号栈弹 n 个文法符号，状态栈也弹 n 个状态；用弹出后的栈顶 s 查 GOTO[s,A]，再压 A 和新状态。

例如 β 长 3，就撤销识别这三个符号带来的三次状态推进。若用归约前栈顶查 GOTO，会找错前驱。ε 规则 n=0，不弹任何项，仍查当前栈顶 GOTO 并压左部。

5.3 通用驱动伪代码

状态栈=[0]；符号栈=[#]；a=当前 Token
循环：
    action=ACTION[状态栈顶,a]
    若 sj：压 a 和 j，取下一 Token
    若 rk：取规则 A→β，弹 |β| 对符号/状态
           j=GOTO[新的状态栈顶,A]；压 A 和 j
    若 acc：接受（不应仍有未处理普通 Token）
    若 Error：报告当前位置与状态允许的 Token

只识别合法性时可只保留状态栈，符号由转换隐含；若要构树或执行语义动作，则还要维护相关值。课件同时画两个栈是清楚的教学表示，不能因此断言所有实现都必须保存独立符号栈。

5.4 出错与恢复

遇到空格动作可及时报错，指出实际 Token 和当前允许类别。错误恢复可跳过输入或弹状态寻找同步点，但不能把任意恢复后到 acc 的路径当成原程序完全合法。第三章所讲定位、恐慌恢复等原则仍适用。

6. LR(0) 完整构表与冲突

6.1 简化表达式练习

课件文法为 E→E+T|T、T→id|(E)。只有加法与括号，不是同时有加乘的常见文法。它的完成项目状态没有同时要求移入的终结符边，因此是 LR(0)。不能凭“表达式文法一般不是 LR(0)”直接下结论。

本题规则编号：

(0) S' → E
(1) E → E + T
(2) E → T
(3) T → id
(4) T → ( E )

全部项目集（同一项目的展望符合写成集合）：

I0:

6.4 两类冲突与“二义性状态”的边界

移入/归约冲突是在同一 ACTION 格既填 s 又填 r；归约/归约冲突是在同格要求不同 r。点后为非终结符的未完成项目本身不直接产生移入动作，所以“任何未完成项与完成项共存都冲突”过于粗略。

课件称冲突状态为二义性状态，但表冲突不等于文法一定二义。冲突可能只是该方法提供的上下文信息不够，换 SLR 或 LR(1) 可以消除；一个二义文法则无法成为本章无冲突的确定 LR 文法。

7. SLR(1)：用 FOLLOW 限制归约

7.1 相同状态机，更小的归约范围

7.3 SLR 无冲突条件

在每个状态中，设完成项目左部为 A1…An，点后终结符集合为 Shift。必须有：每个 FOLLOW(Ai) 与 Shift 不交；不同归约项目的 FOLLOW 两两不交。多个移入项目同样指向某个字符不构成不同动作时，不必将它们视为冲突。

正式标准仍是每个 ACTION 格最多一个动作。增广完成项目只提出 # 接受，单独处理。若条件失败，指出具体状态、Token 和竞争规则，比笼统说“它不是 SLR”更有解释力。

7.4 全局 FOLLOW 为什么不够精确

课件 Z→BaBbBc、B→d 中三次 B 的后继分别为 a、b、c，但 FOLLOW(B)={a,b,c}，忽略了当前是哪个 B。这个例子说明精度损失，本身不自动证明发生表冲突。

讲者备注进一步给：

A→d
B→d

初始读 d 后同时出现 A→d· 和 B→d·。FOLLOW(A)={b}、FOLLOW(B)={a,b,c}，在 b 列有归约/归约冲突。

但在这个具体位置，Z 的第一分支中第一个 B 只能后接 a，第二分支中 A 只能后接 b。若分别记住这两个局部后继，冲突就可消除，这正是 LR(1) 的思路。

8. LR(1)：给项目增加展望符

8.1 展望符解释的是完成后的后继

LR(1) 项目是 [A→α·β,a]。a 是一个展望符，表示该位置上的 A 结构完整结束后允许跟随的 Token，不是圆点后紧接着必须移入的字符。

[A→x·y,#] 仍先等待 y，不能因为展望符是 # 就跳过 y。只有 [A→xy·,#] 完成后，# 才限定归约。合写 {a,b} 等于同一 LR(0) 项目配两个不同展望符，不是一次看两个 Token。

8.2 LR(1) 闭包的 FIRST(βa)

若 [B→α·Aβ,b] 在闭包中，则对每条 A→γ、每个 a∈FIRST(βb)，加入 [A→·γ,a]。

为什么看 βb？A 结束后先遇到后面的 β；若 β 能消失，才遇到外层的 b。例如 β 以终结符 c 开头，A 的后继就是 c；若 β=ε，才继承 b；若 β 能空也能以 c 开头，则两者都保留。

不能一律复制原展望符，也不能只算 FIRST(β) 后忘记可空情形。b 是终结符或 #，所以 βb 整体不为空，结果不会把 ε 当作展望符。

8.3 投影、GO 与状态构造

投影把 [A→α·Xβ,a] 改成 [A→αX·β,a]，保持展望符；GO 是投影后求 LR(1) 闭包。初态为 CLOSURE({[S'→·S,#]})，待处理构造同 LR(0)。

判断规范 LR(1) 状态相同必须同时比较点位与展望符。只忽略展望符去重，已经是 LALR 合并的思路，不能再称完整规范 LR(1)。

8.4 LR(1) 构表

点后终结符 a 的 GO 边填移入；[A→β·,a] 只在 a 列填该归约；增广 [S'→S·,#] 填 acc；非终结符边填 GOTO。归约范围由项目的局部展望符提供，不用全局 FOLLOW 代替。

SLR 失败备注例中读初始 d 后的完成项为 [A→d·,b] 和 [B→d·,a]，a 归约 B、b 归约 A，互不冲突。语义相同的非终结符不同出现，被具体项目上下文区分。

10. LALR(1)：合并同心状态

10.1 为什么合并

规范 LR(1) 对上下文区分较细，可能出现许多仅展望符不同的状态，导致表增大。项目的心是去掉展望符后的 LR(0) 项目；按课件，状态的心 Core(I) 是其所有项目心组成的集合。心相同称同心状态。

LALR(1) 合并同心状态，把相同项目的展望符取并，转换边也映射到合并后的目标。它保留 LR(0) 规模的状态骨架，又使用比全局 FOLLOW 更精确的展望信息。

这与第二章 DFA 最小化不是同一算法：这里按同心条件合并并检查分析动作，不能仅凭“未来接受同样串”随意混合 LR 栈的状态。

10.3 合并算法与传播

最直观算法先构造完整 LR(1)，按相同心分组、并展望、映射边，再按 LR(1) 规则构表。这样源状态的全部展望已算齐。

若采用“发现同心立即合并”增量实现，新增展望还须继续传播到闭包及后继，重复到稳定。只把新状态并入后就停止处理，会漏掉沿边产生的新展望符。

10.4 为什么可能新增归约/归约冲突

在原规范 LR(1) 已经无冲突的前提下，同心状态有相同的终结符移入边；任何归约展望若与这些边相交，原状态就已冲突，因此合并不会新增移入/归约冲突。

但两个不同状态可以分别要求“a 归约 A，b 归约 B”和“b 归约 A，a 归约 B”，各自无冲突，取并后 a/b 都要求两个归约，于是产生新冲突。

课件反例：

Z→aAd | bAc | aBc | bBd
A→e
B→e

初态读 ae 后，[A→e·,d]、[B→e·,c]；读 be 后，[A→e·,c]、[B→e·,d]。同心合并后两条完成项目都允许 {c,d}，两列均归约/归约冲突。因此该文法是 LR(1)，不是 LALR(1)。

13. 课件例题回查与知识路线

13.1 方法比较

方法 状态项目 普通归约允许的列 主要特点
LR(0) LR(0) 项目 所有终结符及 # 简单、限制较强
SLR(1) 同一 LR(0) 项目集 FOLLOW(左部) 全局后继可能不够精确
LR(1) 项目配局部展望 完成项目自己的展望 区分精细、状态可能较多

文法类包含关系为 LR(0)⊂SLR(1)⊂LALR(1)⊂LR(1)。在同样增广和可达构造约定下，状态数通常满足 LR(0)=SLR(1)=LALR(1)≤规范LR(1)；课件写严格小于，但某文法可相等。包含关系谈能处理哪些文法，状态数谈同一文法的构造规模，不能混为一个概念。

13.2 做题步骤

统一增广与结束约定 → 编号规则 → 构闭包和所有 GO → 按方法填移入/归约/接受 → 检查每格冲突 → 无冲突时模拟输入。SLR 额外先算 FOLLOW；LR(1) 每次闭包用 FIRST(后缀＋原展望)；LALR 先确保所有同心状态展望已正确并集并传播。

13.3 自检与参考解释

1. 归约会读下一 Token 吗？ 不会；只有移入消费输入。

2. 空规则为什么不弹栈？ 右部长度为 0，未识别任何符号，但仍压左部并查 GOTO。

3. GOTO 用归约前还是归约后栈顶？ 弹完右部后剩余的状态。

4. 项目点后是非终结符是否直接移入？ 不直接从 Token 流移入；通过识别该结构并归约后走 GOTO。

5. LR(1) 展望就是点后字符吗？ 不是，解释的是整个左部结构完成后的允许后继。

6. FOLLOW 相同是否表示 LR(1) 所有展望相同？ 不表示；展望关联不同项目上下文，可比 FOLLOW 更小。

7. 完成项目与未完成项目共存一定冲突吗？ 应查具体 ACTION 格；非终结符点后项不直接提出移入。

8. 分析表冲突能证明二义吗？ 不能，可能只是当前方法信息不足。

9. LALR 任意两状态都可合吗？ 不可，需相同状态心；合后仍要查冲突。

10. LALR 合并不会新增任何冲突吗？ 在原 LR(1) 无冲突前提下不新增移入/归约，但可能新增归约/归约。

11. LR 是否必须消除左递归？ 本章 LR 可以处理许多左递归文法，不必照搬预测递归下降要求。

12. 一个输入成功能证明文法 LR(1) 吗？ 不能，要核对完整可达项目集与全表单值性。

14.1 答案与理由

  1. LR(0)在所有终结符列要求A归约，所以a列同时移入，冲突。SLR只在#归约A，a仍移入，二者不交；这个局部冲突消失，但要检查其余状态后才能判整个文法为SLR。
  2. FIRST(Cb)={c,b}。C可以先产生c，也可以为空后见外层b；加入每条A→·γ时分别配c与b。ε不作为展望符。
  3. 右部长度零，不弹原栈，压新状态8，得到[0,3,6,8]；符号栈压A，当前输入不变。错误地弹一个状态会从错误前驱查GOTO。
  4. 合并后A、B两个完成项目的展望都为{c,d}，c与d上都有两个归约，故归约/归约冲突。原两状态各自单值并不保证合并后单值。
