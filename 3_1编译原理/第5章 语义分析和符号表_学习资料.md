## 1. 语义分析要解决什么问题


### 1.1 结构正确不保证使用正确

词法规定字符怎样组成单词，语法规定单词怎样组成结构，**语义**规定这些结构表达什么含义、哪些使用被允许。`x()` 有函数调用外形，但 x 如果是整数变量，调用就不合法。`x+y` 结构完整，也不能保证操作数类型允许加法。

**语义分析**把名字的使用与声明联系起来，检查类别与类型，为中间代码和地址分配准备属性。**符号表**是编译器保存名字及相关信息的数据结构；一项可能记录它属于变量还是函数、类型、作用域、存储属性等。

### 1.2 课件 C 片段逐项判断

课件有全局 `int x=10`，main 中 `x()`、`f=x`，之后的函数 f 中先 `int x=20,y` 再 `float x`。

| 出现 | 问题或结论 |
| --- | --- |
| 全局 x 与 f 内局部 x | 不同作用域，可按遮蔽规则共存 |
| x() | x 绑定整数变量，不具备被调用类别 |
| f=x | 若此时没有 f 的声明，先有未声明问题；即使绑定到函数，也不能按普通可赋值变量赋值 |
| f 内的 int x 与 float x | 同一局部作用域重复声明，类型不同不使它们合法 |
| x+x | 若绑定允许加法的类型，类型层面可成立 |

这只是说明语义检查的片段，不是可直接编译的完整 C 源程序；还缺头文件及一些完整语句约定。不能因为函数体后面出现 f，就自动认为使用位置已经有合法声明。

### 1.3 静态与动态

**静态语义**在编译期检查，如未声明、类别错误、参数数量、类型不兼容。**动态语义**涉及运行状态，如依赖输入的下标越界、除数是否为零。

课件“编译程序只能做静态检查”用于区分阶段：一般不能只凭类型知道任意输入会使除数为零。但若表达式明显是 `10/0`，编译器可能提前诊断；也可生成运行时检查。已知常数可检查的情形不能一律拖到运行期。

### 1.4 检查范围与实现安排

| 检查对象 | 必须确认 |
| --- | --- |
| 条件 | 教学语言是否要求 boolean；C 则可用规定的标量条件 |
| 运算 | 操作符允许哪些类型，是否需要转换 |
| 赋值 | 左部可写，双方类型兼容 |
| 调用 | 被调对象是过程/函数，数量、类别、方式、类型匹配 |
| 数组 V[E] | V 的类型支持下标，E 是允许的序数类型，维数正确 |
| 字段 V.id | V 是记录/结构，该类型确有字段 id |
| 解引用 | 操作对象是允许解引用的指针或课件相应文件类型 |
| 返回值 | 与函数声明的结果类型相容 |

声明时查本层重复并填表，使用时从内到外查绑定；表达式类型检查可随语法分析或中间代码生成进行，也可独立遍历语法树。**语法制导**是按识别到的语法结构执行相应处理，不必要求语义阶段独占一遍。

## 2. 术语与记号入门


| 名称 | 含义 |
| --- | --- |
| Kind / Type | 标识符类别 / 数据类型，前者与后者不能互代 |
| Ptr / NULL | 指向一个描述结构的引用 / 没有引用 |
| Size | 该类型或活动记录需要的存储单位数 |
| Level / Off | 层数 / 相对于所属活动记录首地址的偏移 |
| dir / indir | 直接访问 / 通过槽中保存的地址间接访问 |
| AR | 过程活动记录，一次调用所需的运行时空间 |
| SP | 本课程中当前活动记录的首地址 |
| Scope 栈 | 保存当前有效局部化单位的标识或表起点 |
| s、ℓ | 最新表项位置、作用域管理的当前深度 |
| Low、Up、ElemType | 数组下界、上界、元素类型 |
| actual / formal | 有自身代码体的实在过函 / 作为形参接收的过函 |
| Mem[a] | 地址 a 中保存的内容，区别于地址 a 本身 |

**种类**与**类型**的例子：一个整数常量、一个整数变量、一个返回整数的函数都与 int 有关，但允许的使用不同。只保存 int 无法判断能否赋值或能否调用。

## 3. 声明、使用与名字分类


### 3.1 两类出现与绑定

**声明性出现**引入名字或说明属性，如 `int x`、参数声明和函数头；**使用性出现**引用已声明对象，如 `x=x+1` 中左、右两处 x。赋值左边仍是使用某个声明，并不是重新声明变量。

**绑定（理解补充）**是把某次名字使用连到其对应声明。先根据作用域选择声明，再依据该项属性检查语义。不同名字可以类型相同，同名也可以在不同作用域指不同对象。

后面优化中的“定义”常指给变量赋新值，如 `x=1`，与此处引入标识符的声明不同。术语要在所属阶段下解释。

### 3.2 五类名字

| 类别 | 例子 | 独有信息 |
| --- | --- | --- |
| 常量标识符 | `const n=100` | 类型与值，不是普通可改变量 |
| 类型标识符 | `typedef int T` | 引用一个类型描述 |
| 变量标识符 | 普通变量、值形参、地址形参 | 类型、访问方式、地址与可选初值 |
| 过程/函数标识符 | f、有形参的回调 g | 签名、实在/形式、入口或槽位置 |
| 域名标识符 | `s.age` 中 age | 所属记录的字段类型和内部偏移 |

值形参接收实参值的一份拷贝；**变参/地址形参**接收对象地址，通过地址修改对象。课件 Pascal `var y` 是这一模式。C 的 `int* y` 本身仍按值传递一个指针，用 \*y 修改调用者对象；不能因此称 C 原生具有 Pascal var 参数语法。

**实在函数**有自己的函数体；**形式函数**是接收函数作为参数的名字，签名用于检查，将来由实参提供入口和环境。形式函数没有一份独立的固定函数体。

## 4. 标识符的内部表示


### 4.1 常量与类型名

常量项可为 `(Name,Kind=constKind,Type,Value)`。Type 指向类型描述，Value 指向或直接保存常量值。课件 pai=3.14、count=100 对应 real/int 及具体值。

课件用 `#define` 作例，但真实 C 宏先做预处理文本替换，并非语义阶段天然保留同样的常量符号表项。这里用它解释“名字代表值”，不把宏与 const 变量混为一类。

类型名项为 `(Name,Kind=typeKind,Type)`。`typedef int t1` 指向 int 描述；`typedef int t2[10]` 指向下界 0、上界 9、元素 int、大小 10 的数组描述。类型名不是运行时普通数据变量，不为每次引用分配变量槽。

### 4.2 变量项与访问方式

变量项为 `(Name,Kind=varKind,Type,Access,Level,Off,Value)`。Value 若存在表示声明时初值，不是编译器实时追踪运行值的通用字段。

直接变量槽位置 `slot=base+Off`，其值是 `Mem[slot]`。间接变量先读 `addr=Mem[slot]`，其对象值是 `Mem[addr]`。它们访问层数相差一次读地址。

课件 `int x=10; float y; float* z;` 从 off 起，不加对齐时 x 在 off，y 在 off+1，z 的指针槽在 off+3，下一空位 off+4。real 占 2、地址占 1，所以不是每次都加 1。

课件将指针相关变量记为 indir 是其对象访问模型。实际语义中必须区分“z 指针本身”与“\*z 所指对象”：读写 z 的槽是一层访问，读写 \*z 还需读地址。Type 是 pointer(real)，不能把 z 自身的类型误写成 real。

### 4.3 过程/函数的字段逐项解释

| 字段 | 含义 |
| --- | --- |
| Name、Kind | 名字；routKind 表示过程/函数 |
| Type | 函数返回类型；无返回值过程可为空 |
| Level | 课件给过函的定义层数 |
| Off | 形式过函在所属记录内的参数槽偏移；实在过函通常不用此字段 |
| Param | 有序形参表，记录类型、类别与传递方式 |
| Class | actual / formal |
| Code | 实在过函的入口地址，未生成时可待回填 |
| Size | 实在过函一次调用所需活动记录大小 |
| Forward | 是否是等待后续实体的超前声明 |

**超前声明**先提供签名，后提供体，使使用位置能够检查调用，也便于互相递归。实体出现时须核对与已有签名一致，不能另建不相关同名函数。

参数信息即使局部符号表退出，仍需留给后面的调用检查，因此删除式表组织须保存独立、持久的签名。Code 与 Size 应在信息齐全时回填；具体哪一阶段可确定依实现而定，不能在未生成代码时编造入口。

### 4.4 带形式函数的课件例

```text
function f(x:integer; var y:real;
           function inc(a:integer):integer):integer
```

f 的三项形参是值参 x、地址参 y、形式函数 inc。a 是 inc 的参数，属于 inc 的签名，不是 f 的第四个实参。若参数区起点 d，x 占 1 在 d，y 地址占 1 在 d+1，inc 的入口/环境占 2 在 d+2、d+3，下一空位 d+4。

调用 f 时，对应第三实参必须是签名兼容的函数；不是任意一个整数或零参数函数。类型与 Param 描述共同提供这些检查信息。

## 5. 类型的内部表示


### 5.1 类型描述的两种用途

**类型描述符**保存类型结构，用于合法性与兼容性检查，也用于计算空间和访问操作。课件按标准类型、子界/枚举、数组/记录/联合、指针分类。

基本类型有 Kind 与 Size：int/bool/char 为 1，real 为 2。此单位是教学抽象，不是 C sizeof 的固定字节结论。真实类型布局还需目标机对齐等约定。

### 5.2 子界与序数类型

**子界类型**限定某个有序离散基本类型的连续区间，如整数 1..10、字符 'a'..'z'。可以保存 BaseType、Low、Up、Size。**序数类型**能按离散先后次序对应序号，适合数组索引；任意实数并不适合作这种离散索引。

备注中形如 `a[-3..3]` 的区间须有明确分隔，不应误读成小数 -3.3。数组下标类型与一个独立子界类型是相关但不同的描述字段。

### 5.3 数组与多维数组

数组描述 `(Kind=ArrayTy,Low,Up,ElemType,Size)`，大小：

```text
Size=(Up-Low+1)×sizeof(ElemType)
```

端点都包含，元素个数要加 1。若 Up<Low，是否允许空数组需另按语言规则，不能无条件套负长度。

`int A[10]` 描述为 Low=0、Up=9、元素 int、Size=10。`char B[5][10]` 是“5 个每项含 10 个 char 的数组”：内层大小 10，外层元素大小 10，外层总大小 50。不能只保存两维数字而漏元素类型，否则中间代码阶段不知道每次下标后还有什么类型。

### 5.4 结构体与联合体

记录/结构类型保存 Size、Kind 与 RecBody/FieldList。字段项含 Name、Type、Off、link，link 指下一字段。字段偏移相对本结构对象首地址，不是相对某函数的 AR。

忽略对齐时，`Date{int year,month,day}` 大小 3，字段偏移 0、1、2。`s.month` 地址应是 s 的对象首地址+1。

联合体多个字段共享存储，`union{char ch;int i;real f}` 在教学规则下大小 max(1,1,2)=2，所有字段偏移 0。写一个字段可能改变其他解释下的内容，不能当作三份独立空间。

真实结构体可能有填充，真实联合体还受对齐影响。课件数值在不考虑对齐的模型中成立。

### 5.5 指针与枚举

指针描述 `(Kind=pointTy,Size=地址长度,BaseType)`。int\* 与 real\* 可同占 1 个地址单位，但所指对象大小和允许操作不同；指针槽大小不等于对象大小。

枚举描述保存 enumTy、Size、ElemList。每枚举常量记录 Name、Value。课件 `color{red,yellow,blue}` 得 0、1、2；`red=10,yellow=red+2,blue` 得 10、12、13。blue 续接前一值，不会重新从 0 编号。枚举变量大小与元素个数不是一回事，课件用 1 个教学单位。

## 6. 抽象地址与空间分配


### 6.1 为什么编译时不能给每次调用同一真实地址

**静态分配**预先安排固定的数据位置；**动态分配**在运行中按调用或申请取得空间。递归中同一局部变量声明同时有多次活动实例，如果它们共用一槽，内层就会覆盖外层值。

编译可以知道 x 在函数空间内偏移为 3，却不知道第几次调用最终位于哪个实际地址。所以保存**抽象地址** `(Level,Off)`：层数帮助定位所属记录，偏移确定记录内槽。它不是把一个整数真实地址换个名字，而是保留以后计算地址的结构。

指针槽可静态或栈分配，所指对象可固定或堆分配。课件“指针不支持静态分配”应限于需要动态申请的对象，不能推广成所有指针变量必在堆上。

### 6.2 活动记录的四个区域

**活动记录 AR**保存一次函数/过程调用需要的信息，课件结构为管理区、形参区、局部变量区、临时变量区。管理区含返回地址、链接和现场等；后三区按参数、声明、生成临时结果的顺序分配。

局部 direct 对象地址为所属 AR 首地址+Off；外层对象要先找到外层记录首地址，不能都用当前 SP。具体寻找方法在第六章展开。

### 6.3 两套层数必须分别记

Pascal 教学约定主程序层 0，直接定义的 P 层 1，P 内 Q/S 层 2，Q 内 R 层 3。**变量登记层数**为所在过程层+1：

| 对象 | 课件层数 | 所属记录的过程层 |
| --- | --- | --- |
| 主程序 ep | 0 | 0 |
| P | 1 | P 层 1 |
| P 的 i/j/k | 2 | 1 |
| Q、S | 2 | 2 |
| Q 的 real a/b | 3 | 2 |
| R | 3 | 3 |
| R 的 bool a/b | 4 | 3 |
| S 的 char c/e | 3 | 2 |

过函的 Level 与其变量的 Level 不同：后续若 Display 按过程层下标，变量 Level=Lv 对应 `Display[Lv-1]`。如果另一本教材直接把变量记为所属过程层，其公式就不减 1；计算前必须统一。

C 教学模型中全局对象与函数层 0，参数和局部变量层 1。C 的嵌套花括号会增加作用域深度，但仍在同一函数活动记录中，所以不会把这些对象的地址层数改成 2、3。

### 6.4 分配原则与课件修正

| 对象 | 占用大小 |
| --- | --- |
| 普通局部变量、值形参 | 类型 Size |
| 地址形参 | 一个地址单位 |
| 形式过函 | 入口与环境共两个单位 |
| 临时变量 | 课件假设 1，真实情况依类型及目标 |

设 S 的形参为 `x:int,var y:int,function f():int`，局部 c/e:char，起点 d，则 x=d，y=d+1，f=d+2（占两槽），c=d+4，e=d+5，下一位 d+6。课件 14 第 10 页写 f=d+3、c=d+5、e=d+6，未说明额外对齐或槽，因此不能由其分配规则推出；这里不假造那个额外单元的用途。

C 的 `a:int,b/d:real` 从 d 开始，应 a=d、b=d+1、d变量=d+3，下一空位 d+5。课件第 11 页偏移按实数 1 写，与 real=2 规则冲突。

### 6.5 嵌套块槽是否复用

课件 C 多块例按不复用分配：

| 块 | 声明 | 偏移（从 0） |
| --- | --- | --- |
| 1 | a:int,b:real,d:real | 0、1、3 |
| 2 | c:int,a:real | 5、6 |
| 3 | d:int,c:real | 8、9 |
| 4（位于3内） | d:real | 11 |
| 5（与3同级、在3退出后） | d:char | 13；若安全复用退出块空间，可为 8 |

同时活动的块不能随意共用仍有用的槽。块 3 退出后，块 5 可以复用相应空间的前提是生命周期和访问关系允许。作用域是否结束、空间如何复用、符号表是否保留，是三个不同问题。

## 7. 作用域与局部化单位


### 7.1 可见范围与生存期

**作用域**规定源码某位置能引用哪个声明；**生存期**规定运行时对象何时存在。前者是源码组织关系，后者是动态执行关系。静态局部对象可以在函数返回后仍存在，但名字仍只在局部可见；堆对象也可超出创建它的函数生存。

**局部化单位**是允许声明并形成局部范围的结构，如主程序、函数、过程或 C 语句块。范围可以嵌套或并列，不交叉；因此用栈管理当前有效范围方便。

### 7.2 遮蔽与由内到外查找

内层声明与外层同名时，内层名字**遮蔽**外层名字，不是改写外层声明。退出内层，外层恢复可见。是否从声明位置起可见、是否允许超前引用，依具体语言规定；本章多数例采用先声明后使用。

课件 `P: x/y int，Q: x/z real`：Q 内 x 是 Q 的 real，z 是 Q 的 real，y 从 P 找到 int；P 体内 x/y 是 P 的变量，Q 的 z 不可见。

### 7.3 P/Q/R/S 的可见性

定义树为 ep→P，P→Q、S，Q→R。R 内 bool a/b 遮蔽 Q 的 real a/b；R 的 i 从 P 找到。Q 内 a/b 是自己的 real，i 也来自 P。S 内 c/e 是自身 char，可见 P 的 i/j/k，但不能因 Q 与它同层就引用 Q 的局部 a/b。

P 体也不能访问子过程 Q/R 的局部变量。名字 Q、S 的可见性与它们体内数据可见性不同：在所属声明区及允许范围内可以调用过程，却不能因此任意读取其局部对象。课件 S 体示意 a/b 未在可见链中声明时，应报告未声明，不能取正在运行的 Q 的变量补上。

## 8. 符号表的组织与管理


### 8.1 三个组织维度

课件讨论总体单表/多表、表项线性/有序/散列、局部化全局式/局部式。它们可组合，不是互斥的三选一。

单表可统一保存不同 Kind 的记录；多表可把共有名字索引与不同属性描述分开。线性表便于顺序追加和逆查；有序表利于查找但新增维护有成本；散列表按名字散列查找，仍须处理冲突和作用域。

**全局式符号表**表示整个编译过程用一张集中表，里面也有局部变量；不等于只装全局变量。**局部式**是每个局部化单位一张表。

### 8.2 四项基本操作

进入范围：记本层起点或建立局部表；遇声明：只查本层，重复则报错，允许时填属性；遇使用：从本层向外查，找到最近有效声明；退出：使本层表项不再参加名字查找。

声明重复检查不能查到任意外层同名便报错，否则会禁止合法遮蔽。使用查找不能只查当前层，否则会漏掉合法外层引用。Scope 管的是当前编译位置的有效范围，不是目标程序此刻的函数调用栈。

### 8.3 全局线性表的真删除法

用 Scope 栈记各范围起点，s 记末项。进入范围把 `s+1` 压栈；填项追加，使用从 s 逆向找最近同名；退出把有效末项改为 `Scope.top-1`，弹 Scope。

这里的“删除”是符号数据管理操作，可以缩短有效数组长度，并不涉及删除电脑文件。实体函数名放在父范围，参数和局部在函数范围，所以退出函数只作废其局部项，仍保留父层函数项和持久签名。

### 8.4 驻留法与跳转项

**驻留法**保留历史表项，但让查找跳过无效范围。课件退出时追加 `(#,Scope.top-1)`，其中 # 表示特殊跳转项，指针指向刚退出范围之前的最后项。

逆查读到跳转项就直接跳向保存位置，不逐项查看已退出块。例如退出 Q，追加指向 Q 起点前一项的跳转，P 中后续查找不会找到 Q 的 a/b。

重复声明检查也须跳过已失效内层项，不能仅从当前起点扫描所有曾出现的文字。每项显式作用域标记是另一种可行实现；核心要求是只有当前有效声明参加判断。

### 8.5 局部表与表栈

每进入范围建立表并压 Scope；声明只查顶表，使用由顶向底查；退出弹表。为了调试、后续分析或签名引用，表实体可以保留，但从有效查找栈移除即可。

课件“局部表只有删除法”是其讲授方案，不是禁止持久保留局部表的理论定理。逻辑有效性、物理对象是否保留必须分开解释。

## 9. 课件实例的完整查表过程


### 9.1 f、g、main 按编译顺序管理

课件全局 x/y，f 有参数 z，g 有 u/v，main 使用 `g(x,f(2))`：

| 编译位置 | 有效范围栈 | 关键变化 |
| --- | --- | --- |
| 全局声明 x/y | [全局] | 两项可见 |
| 声明 f、进入 f | [全局,f] | f 的名字在全局，z 在 f |
| f 中 x=x+1 | [全局,f] | x 在 f 未找到，再找到全局 x |
| 退出 f | [全局] | z 失效，f 签名保留 |
| 进入/退出 g | [全局,g]→[全局] | u/v 只在 g 有效 |
| 进入 main | [全局,main] | x、g、f 均由全局查到，z/u/v 不可见 |

这张表描述编译器处理源码，不是运行 `g(x,f(2))` 时的实际调用先后。运行时会调用函数，编译期会进入声明范围，两者不应混用同一个 Scope 栈。

### 9.2 C 嵌套块输出

```text
块1：a=1,b=1
    块2：b=2
        块3：a=3 → 输出 a=3,b=2
    块4：b=4 → 输出 a=1,b=4
块1末尾：输出 a=1,b=1
```

块3 的 a 来自自身，b 来自块2；块4 已不在块2 中，a 来自块1，b 来自自身；全部内块退出后恢复块1。退出不把内层的 2、3、4 复制给外层对象。

### 9.3 swap 的参数槽与所指对象

课件 `swap(int* a,int* b)` 中 `tmp=*a; *a=*b; *b=tmp`，main 传 `&x,&y`。全局 x/y 在层 0，地址参数 a/b 与 tmp 在层 1。起点 d，则 a=d、b=d+1、tmp=d+2。

调用时把 x、y 的地址写进 a/b 槽。执行 `tmp=*a` 先取 a 槽的地址，再读 x 值；`*a=*b` 先读 b 指向的 y 值，再写 a 指向的 x；最后把 tmp 写到 y。交换的是对象值，不是将两个参数槽中的地址换位。

值参传指针与地址引用对象有相似用途，但 C 的参数 a 本身是一份指针值拷贝。给 a 重新赋指针不会自动改调用者的指针变量。

### 9.4 后续阶段怎样继续使用属性

中间代码可引用持久符号描述或复制 Kind、Type、Level、Off、Access 等必要属性。若使用会被作废或覆盖的局部表项地址，后续阶段可能读到错误名字。

因此选“真删除法”时必须同时设计持久签名与 IR 属性保存方式。保留信息的生命周期应覆盖所有使用阶段，不能仅为当前查表方便就丢弃后端仍需的内容。

## 10. 综合应用：历年快速排序片段的驻留符号表


**来源：**期末题第二大题第1问，第2页。要求变量写名字、种类、类型、层数、偏移，函数写名字、种类、类型、层数，采用全局符号表驻留。局部偏移从off0开始，int占1个教学单元。

原题只给int宽度，未显式写指针宽度。以下沿用课件“地址占1个单元、无对齐填充”的模型；如果教师另规定指针宽度，应重算a、b、arr后续偏移。C数组形参`int arr[]`在函数签名中按指针处理，不能按一个未知长数组分配整个值副本。

### 10.1 分配游标与每个范围的独立性

swap的参数a、b各占一个地址槽，t占一个整数槽，下一偏移off0+3。退出swap后不把这3个槽累计到partition；另一个函数重新从off0开始。partition形参arr、low、high后依次声明pivot、i、for块的j；采用不复用局部槽方案。

| 顺序 | 名字 | 种类 | 类型 | 地址层数 | 偏移 | 所在范围/作用 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | swap | 函数 | void，参数(int\*,int\*) | 0 | 不适用 | 全局可调用 |
| 1 | a | 变量/形参 | pointer(int) | 1 | off0 | swap中保存对象地址 |
| 2 | b | 变量/形参 | pointer(int) | 1 | off0+1 | swap中保存对象地址 |
| 3 | t | 局部变量 | int | 1 | off0+2 | swap临时保存元素值 |
| 4 | # | 退出跳转项 | 指向0项 | 不适用 | 不适用 | 跳过1—3，swap本身仍有效 |
| 5 | partition | 函数 | int，参数(int\*,int,int) | 0 | 不适用 | 全局可调用 |
| 6 | arr | 变量/形参 | pointer(int) | 1 | off0 | 数组形参指针 |
| 7 | low | 变量/形参 | int | 1 | off0+1 | 分区下界 |
| 8 | high | 变量/形参 | int | 1 | off0+2 | 分区上界 |
| 9 | pivot | 局部变量 | int | 1 | off0+3 | 接收arr[high]当前值 |
| 10 | i | 局部变量 | int | 1 | off0+4 | 已处理小元素区尾部 |
| 11 | j | for块局部变量 | int | 1 | off0+5 | 仅在for语句范围可见 |
| 12 | # | 退出跳转项 | 指向10项 | 不适用 | 不适用 | for块退出后跳过j |
| 13 | # | 退出跳转项 | 指向5项 | 不适用 | 不适用 | partition退出后跳过6—12 |

表号只是本资料的0起始表项编号，不是内存地址。#跳转項属于符号表管理数据，不占目标程序普通变量槽；它也不是输入结束Token。

### 10.2 用两次查找核对驻留是否正确

在for体内，j绑定11项，i绑定10项，swap先从局部逆查，最后到全局0项。for结束后查j，从12项跳10，越过11，不应查到j；i仍能查到10项。partition结束后从13项直接跳5项，arr/low/high/pivot/i/j都退出有效查找。原表内容保留，作用域可见性已经改变。

这份表保留函数签名。未来调用partition时需要参数类型，不能因为局部范围退出就把整个函数信息当无效。若采用逐层表保存，也须让IR引用的必要属性持续存在。

## 11. 静态错误练习：把已知事实与诊断能力分开


**来源：**期末题第二大题第2问，第2—3页。以下按题意分析，不执行原错误片段；C具体版本和编译器未指定，故“能证明”与“所有编译器必须报错”分别列出。

| 原片段 | 主要问题 | 可在哪发现 | 判断前提与理由 |
| --- | --- | --- | --- |
| `int i=0; float b; b=2/i+8;` | 整数除零 | 可由常量/数据流分析提前发现；一般运行数据则动态判断 | 这里没有中间改写i，可以证明0；但源程序类型结构本身成立，不能断言基本语法检查必然报错。b是float不会让2/i自动变成浮点除法 |
| `int a; int b=a(3);` | 普通整数被调用 | 静态语义 | 查a的Kind/Type，不是可调用对象 |
| 已声明二参数`x_pos`却调用`x_pos(3,4,5)` | 实参数量不匹配 | 静态语义 | 已有函数签名，期望2项而实际3项 |
| `int a[50]; a[30]]=8;` | 多一个右方括号 | 语法 | 下标结构完成后不能再接该`]`；30本身未越界 |
| `const i=10; i=5;` | 常量对象被赋值；声明本身还有版本问题 | 按题意主要静态语义，按某些C版本声明也需诊断 | 为比较赋值问题，可明确改写成`const int i=10; i=5;`。原题少类型不能静默当作所有版本合法 |

具体工具是否诊断第一项、诊断严重级别如何，需在选定工具和选项下测试；本资料没有这项实机编译结论。其他明确类别或结构问题有对应规则依据。题意改写和原文差异已经列出，学生不会把改写误当原题。

## 12. 课件例题回查与知识路线


### 12.1 知识路线与计算步骤

```text
语义检查 → 声明绑定 → Kind/Type/专有属性
  → 类型描述 Size → AR 中分槽 → Level/Off 抽象地址
  → 作用域规则 → 有效表项组织 → 中间代码与目标访问
```

偏移题先确定单位与对齐假设，再分对象类别；从起点累加 Size，地址参加地址长度，形式过函按入口/环境大小加；进入不同函数重新建立其分配游标，不能把嵌套函数的局部算进外层变量区。

### 12.2 自检与参考解释

**1. 同样 Type=int 就能相同使用吗？** 不能，Kind 区分常量、变量、函数等，决定可赋值与可调用性。

**2. 赋值左边出现 x 是声明吗？** 不是，是对已有对象的使用；优化中值定义是另一术语。

**3. 内层 x 是否修改外层 x 的属性？** 不会，是另一个声明遮蔽外层。

**4. 数组 [5][10] 为什么不是大小 15？** 是 5 个长度 10 的数组，总 50 个 char。

**5. 指针 Size 为何不随元素大小变化？** 槽保存地址，大小由地址表示决定；BaseType 记录对象类型。

**6. C 花括号多一层，Level 一定加 1 吗？** 本章地址模型不加，Scope 深度增加；它们不是同一层次。

**7. Pascal Level=3 的变量属于几层过程？** 按课件变量层=过程层+1，属于过程层 2。

**8. 形式函数 inc 的参数 a 是外层 f 的参数吗？** 是 inc 签名内部参数，不是 f 的第四项。

**9. 驻留就是所有旧名字仍可见吗？** 不是，物理保留但查找必须跳过无效项。

**10. 全局式表是否只能存全局变量？** 不是，全程序各范围集中存，作用域由辅助信息区分。

**11. sizeof(real)=2 是否是 C 标准规定？** 不是，仅本课存储单位假设。

**12. 动态语义错误都不能预先发现吗？** 已知常数或可证明情形能提前诊断；一般运行数据还需运行期判断。

## 13. 自测与答案


| 题号 | 学习任务 | 检查能力 |
| --- | --- | --- |
| 1 | 教学模型下依次声明int x、real y、int\* p，起点d，各偏移与下一空位是什么？ | 按类型大小分配 |
| 2 | 一个内块声明同名x，退出后查x会找到谁？是否把外层x的值自动改成内层值？ | 区分遮蔽与修改 |
| 3 | 退出for后驻留表中仍有j项，为什么不能再引用？ | 区分存在与有效 |
| 4 | C函数内多一层花括号，Scope层数和地址Level分别如何变化？ | 区分两套层次 |

### 13.1 答案与理由

1. x=d，占1；y=d+1，占2；p=d+3，占地址1；下一空位d+4。p所指对象大小不决定p槽大小，真实平台还要另算对齐。
2. 内块中绑定内层声明，退出后恢复外层声明。两个对象独立，退出只改变可见性，不复制值，也不修改外层声明属性。
3. 查找遇退出跳转项越过j；记录被保留供复查，不表示现在有效。判断依据是当前有效范围链。
4. Scope反映块嵌套，进入内块加深；本课程C地址模型的局部Level仍为1，因为仍属于同一函数AR。若函数递归，新AR首址改变，Level和Off仍可不变。
