# 第5章 语义分析和符号表：从声明到类型检查与地址定位

`x()` 看起来是一条函数调用，但如果 `x` 声明为整数变量，这个调用就不合法。语法分析认出了结构，语义分析还要回答：这里的名字指向哪个声明？这个对象能否这样使用？以后执行程序时，到哪里取得它的值？

本章沿着“读声明 → 保存属性 → 检查使用 → 计算空间和位置 → 管理名字的有效范围”学习。例子使用 C 声明和 Pascal 声明；两种语言的规则会分别说明，不把一种语言的写法当成另一种语言的规则。

## 1. 语义分析要解决什么问题

### 1.1 结构正确，还要检查对象能否这样使用

考虑以下 C 片段，各行只用于分析相应问题：

```c
int x = 10;
/* 在 x 可见的位置： */
x + x;
x();
```

`x+x` 和 `x()` 都能形成相应的表达式结构。但编译器查到 `x` 是整数变量后，会得到不同结论：整数可以相加，所以 `x+x` 的结果类型是 `int`；整数变量不可调用，所以 `x()` 有语义错误。

**语义** 是语言对程序含义和允许使用方式的规定。**语义分析** 根据声明和语言规则，检查程序中的使用是否成立，并保存后续翻译所需的属性。它不是在编译时把整个程序运行一遍。

**符号表** 是保存名字及相关属性的数据结构。例如 `x` 的表项可以记录名字 `x`、类别“变量”、类型 `int`、所属范围和存储位置。遇到 `x()` 时，语义分析就依据这些信息拒绝调用。

### 1.2 从一个错误片段看“先绑定，再检查”

先确定名字指哪个声明，才知道该检查什么。

小例子：当前范围只声明整数n，表达式写成`n+u`。查n能找到整数变量项；查u失败，所以应先报告u未声明，不能替它猜一个类型再完成加法检查。若之后另一个范围声明了u，也不会自动成为本次使用的可见声明。

这说明“先绑定，再检查操作”有先后依赖。包含多个函数和同层冲突的题另放综合诊断练习。

### 1.3 静态语义与依赖运行状态的问题

若有 `int a; a(3);`，仅凭声明就能发现整数被调用，不需要知道输入值。这类可以在编译期检查的约束属于**静态语义** 。

再看函数内的片段 `int q = 10 / n;`，假定整数参数 `n` 来自运行输入。声明只能说明 `n` 是整数，不能保证它非零。除数是否为零需要结合实际运行值；数组下标是否越界也可能有相同情况。这些问题涉及**动态语义** 和运行状态。

不能据此断言“除零和越界绝不能提前发现”。`10/0` 的除数已知，`int a[3]; a[5]=1;` 的越界也可由常量证明。编译器可能提前诊断，也可以为一般情况生成运行时检查；是否诊断、采用何种级别，取决于语言要求和实现。

### 1.4 具体检查哪些内容

| 使用场景 | 一个具体判断 | 需要的属性或规则 |
| --- | --- | --- |
| 条件 | Pascal 的 `if` 要求 Boolean 条件；C 的 `if(1)` 可以成立 | 当前语言对条件类型的规定 |
| 运算 | `int x; x+1` 可成立，结构体对象通常不能直接相加 | 操作数类型、运算符规则及必要转换 |
| 赋值 | `const int k=3; k=4;` 试图修改只读对象 | 左边是否可修改，双方类型是否相容 |
| 调用 | 已有 `int add(int,int);`，`add(1)` 缺少实参 | 可调用性、参数个数、顺序、类型和传递方式 |
| 下标 | `int a[10]; a[2]` 的结果是整数元素；`a[2.5]` 的下标类型不符合 C 要求 | 数组或指针类型、下标类型、元素类型；范围另作判断 |
| 字段 | `struct Box {int value;}; struct Box b;` 中 `b.value` 合法，而 `b.other` 找不到字段 | 所属结构的字段表，例中只有 value:int |
| 解引用 | `int *p; *p` 的类型是 `int`；`int x; *x` 不成立 | 指针及其所指类型；地址是否有效仍需额外保证 |
| 文件访问 | Pascal 的 `f^` 可表示文件缓冲变量，不与普通指针混同 | 文件类型及该语言的访问规则；本章不展开文件实现 |
| 返回值 | `int f(void)` 的返回表达式须满足结果类型要求 | 返回类型、转换和返回语句规则 |

### 1.5 语义分析可以怎样安排

处理 `int x; x=x+1;` 时，可以在语法分析识别声明时登记 `x`，识别赋值时查表和检查类型；也可以先建语法树，再单独遍历声明结点与表达式结点。生成中间代码时同样会使用类型，例如决定是否先把整数转换为实数。

**语法制导** 指根据识别到的语法结构执行相应处理：识别变量声明就登记属性，识别加法就检查两个分量并计算结果类型。它是一种组织处理的方法，不要求语义分析必须独占一遍扫描。

## 2. 术语与记号入门

后面既要表示编译器保存的描述结构，也要表示目标程序中的变量地址。两类“指针”不能混为一谈。先看一个整数变量 `x`：它的表项中 `Type=intPtr` 表示“引用整数类型描述”，并不表示源程序把 `x` 声明成了指针。

| 记号 | 含义 | 在小例子中怎样读 |
| --- | --- | --- |
| `Name` | 名字的拼写 | `Name=x` |
| 标识符项的 `Kind` | 名字代表哪类对象 | `varKind` 为变量，`routKind` 为过程/函数 |
| `Type`、`intPtr` | 类型描述的引用、整数描述的引用名 | `x.Type=intPtr`，沿引用找到 `(Kind=intTy,Size=1)` |
| 类型描述的 `Kind` | 类型本身属于哪一类 | `intTy` 为整数，`ArrayTy` 为数组；与 `varKind` 不是同一层次 |
| `Ptr`、`NULL` | 描述结构的引用、无引用 | 字段链末尾 `link=NULL` 表示没有下一字段 |
| `Size` | 占用的存储单位数 | `real.Size=2`；不等于“当前存着数值 2” |
| `Low`、`Up`、`ElemType` | 下界、上界、元素类型 | `int[10]` 的描述是 `0、9、intPtr` |
| `Level`、`Off` | 地址层数、相对所属记录首址的偏移 | `(1,3)` 表示按层数找到所属空间，再加 3 |
| `dir`、`indir` | 直接取槽内数据、先从槽中取出对象地址再访问 | 普通整数槽直接访问；地址形参所代表的对象间接访问 |
| `AR`、`base`、`SP` | 活动记录、其首址、本章教学记号中的当前活动记录首址 | `base=100,Off=3` 时槽地址为 103；其他教材的 SP 未必有相同含义 |
| `Mem[a]` | 地址 `a` 中保存的内容 | `Mem[103]=10` 表示地址 103 中的值为 10 |
| `Scope`、`s`、`ℓ` | 有效范围栈、线性表末项下标、当前范围深度 | `Scope=[0,2]` 表示两个有效范围的表起点；栈右端为顶 |
| `actual`、`formal` | 实在过程/函数、作为参数接收的形式过程/函数 | 有自身函数体的 `f` 为 actual，形参函数 `inc` 为 formal |

**本章空间计算约定：** `int、bool、char` 各占 1 个教学单位，`real` 占 2 个，数据地址占 1 个，不计对齐填充。C 例子中的 `float` 在此布局模型中映射为 `real`。这些是手算约定，不是 C 的固定字节数；常量 `3.14` 的真实 C 类型也不能据此直接写成 `float`。

例如依次分配 `int x; float y;`，从偏移 0 开始，`x` 占 0，`y` 占 1、2，下一空位为 3。若题目另给大小或对齐规则，就用题目规则重算。各例独立计算，只有明确说明承接时才沿用前例状态。

## 3. 声明、使用与名字分类

### 3.1 同样写出 x，可能是在引入名字，也可能是在使用它

```c
int x = 0;
x = x + 1;
```

第一行中的 `x` 是**声明性出现** ：说明这里有一个整数对象。第二行左右两个 `x` 都是**使用性出现** ：左边使用该对象作为写入位置，右边使用它的值。左边不是重新声明一个变量。

把使用位置连到对应声明，称为**绑定** 。本例两次使用都绑定到第一行。优化中把 `x=1` 称为一次“定义”，通常是指产生一个新值，与此处引入名字的声明不同。

### 3.2 为什么只知道 int 还不够

比较教学常量 `count=100`、变量声明 `int x;`、函数原型 `int f(void);`。三者都与整数有关，但 `x=2` 可以成立，修改常量不成立，`f()` 可以调用而 `x()` 不可以。因此需要同时保存对象类别 `Kind` 和类型信息 `Type`。

| 名字类别 | 声明或使用例子 | 需要知道的独有信息 |
| --- | --- | --- |
| 常量标识符 | Pascal `const count=100;` | 值为 100、类型为整数，不能像普通变量一样赋新值 |
| 类型标识符 | C `typedef int T;`，随后 `T x;` | `T` 指代整数类型；`T+1` 不能把类型名当整数值 |
| 变量标识符 | `int x;`，以及函数形参 | 类型、访问方式、所属空间与偏移 |
| 过程/函数标识符 | `int f(int x);` | 返回类型、参数表、入口或参数槽等 |
| 域名标识符 | `struct S { int age; };` 中的 `age` | 所属结构的字段类型及内部偏移；`s.age` 要查 `s` 的类型字段表 |

字段名按所属结构查找。例如 `struct A{int n;}; struct B{char n;};` 中两个 `n` 分属不同字段表；访问 `a.n` 时必须先知道 `a` 的结构类型，不能在普通名字表中任取一个 `n`。

### 3.3 普通变量、值形参和地址形参

考虑 Pascal 声明片段：

```pascal
procedure P(x: integer; var y: integer);
```

若调用前 `a=3,b=4`，执行 `P(a,b)` 时，`x` 接收 3 的副本，`y` 接收对 `b` 的引用。在过程体执行 `x:=8; y:=9`，结果是局部 `x=8`、调用者 `a` 仍为 3、`b` 变为 9。前者是**值形参** ，后者是**变参/地址形参** ；这里的“变参”不指 C 的可变参数列表。

C 的 `void P(int x,int *y);` 可以通过 `P(a,&b)` 达到类似的修改效果，但 C 仍按值传递：第二个形参接收的是指针值的副本，通过 `*y` 写入 `b`。给 `y` 本身改地址，不会自动改变调用者的指针变量。

### 3.4 实在函数与形式函数

在声明片段 `int f(int x,int (*g)(void));` 中，假定 `f` 后面有自身函数体，`f` 是实在函数；`g` 是用来接收函数指针的形参，承担形式函数的作用。若另有 `int h(void);`，调用 `f(1,h)` 时，`g` 的调用目标来自实参 `h`，不是由 `g` 独立定义一个固定函数体。

参数 `g` 的签名要求“无参数、返回整数”。一个需要两个整数实参的函数不能仅因同样返回整数，就当成相同签名传入。

## 4. 标识符的内部表示

名字的类别不同，后续要问的问题也不同：对常量要取值，对变量要定位，对函数要检查调用。下面把这些问题落实为表项字段。字段名是教学数据结构的记号，不要求某种编译器实际采用完全相同的结构体。

### 4.1 常量项与类型名项

教学常量可保存为 `(Name,Kind=constKind,Type,Value)`：

| 名字 | Kind | Type | Value | 一次使用怎样处理 |
| --- | --- | --- | --- | --- |
| `pai` | constKind | realPtr | 3.14 或其值描述的引用 | `pai+1` 取得常量值并按实数运算规则处理 |
| `count` | constKind | intPtr | 100 或其值描述的引用 | `count+1` 可得到整数值 101；`count=2` 不允许修改常量 |

这是“常量名字代表固定值”的抽象表示。C 中 `#define pai 3.14`、`#define count 100` 是预处理宏，使用位置先做文本替换，并不意味着语义阶段必然存在这样的两个常量表项；C 的 `const int count=100;` 则声明只读对象，可能具有存储空间。三者不能直接等同。

类型名项保存 `(Name,Kind=typeKind,Type)`。对以下 C 声明：

```c
typedef int t1;
typedef int t2[10];
```

`t1.Type=intPtr`，`t2.Type` 则指向数组描述 `(Kind=ArrayTy,Low=0,Up=9,ElemType=intPtr,Size=10)`。以后 `t2 a;` 才声明数组对象 `a`。类型别名 `t2` 本身不占一份运行时数组空间，`a` 才需要 10 个单位。

### 4.2 变量项：声明属性与运行时值分开

变量项可写作 `(Name,Kind,Type,Access,Level,Off,Value)`。`Value` 若使用，表示声明初值，不是自动跟随每次赋值更新的“运行值记录”。例如 `int x=10;` 后运行 `x=20;`，改变的是目标程序对象，不能据此假定编译器的初值字段同步变为 20。

设当前地址层数为 `L`，起始偏移为 `d`，依次处理：

```c
int x = 10;
float y;
float *z;
```

| 对象 | Type | 本对象槽占用 | Off | 下一空位 |
| --- | --- | --- | --- | --- |
| x | intPtr | 1 | d | d+1 |
| y | realPtr | 2 | d+1 | d+3 |
| z | pointer(real) 的描述引用 | 地址槽 1 | d+3 | d+4 |

三者 `Kind` 都是 `varKind`，`Level` 都是 `L`。`z` 的类型是“指向实数的指针”，不能只填 `realPtr`；它自己的槽占 1，不按所指实数的 2 来分配。

`Access` 必须和当前访问对象一起解释。普通变量 `x` 可按 `dir` 取槽内值；地址形参所代表的对象按 `indir` 访问。若用 `indir` 标记通过 `z` 访问所指对象，就表示要再读一次地址；这不意味着读写指针变量 `z` 本身也等同于读写 `*z`。

具体设 `base=100,d=0`，`z` 槽地址为 103，`Mem[103]=500`，所指实数从 500 开始：读取 `z` 得到地址 500；读取 `*z` 才访问 500 处的实数对象。两种访问的类型和效果不同。

### 4.3 过程/函数项：签名、入口与空间各管什么

声明 `int add(int x,int y);` 后，即使尚未生成机器指令，也已经能检查 `add(1,2)` 的参数。这依赖**签名** ，即返回类型及有序参数信息；执行时跳到哪里、一次调用需要多少空间，是另外两件事。

| 字段 | 含义 | `add` 或形式函数中的具体用途 |
| --- | --- | --- |
| Name、Kind | 名字与过程/函数类别 | add、routKind |
| Type | 返回类型描述；无结果过程可用 NULL | add 返回 int，故指向 intPtr |
| Level | 过程/函数的定义层数 | C 教学模型中 add 为 0 |
| Param | 有序形参表的引用 | 两个值形参，均为 int；数量与顺序不能丢 |
| Class | actual / formal | add 有自身实现，为 actual；另设由参数传入的函数 h，则 h 为 formal |
| Off | 形式过程/函数在所属记录中的参数槽偏移 | 若 h 从偏移4占入口、环境两槽，则从4、5取得调用信息 |
| Code | 实在过程/函数的目标代码入口 | 生成后回填；形式函数的调用入口来自实参，不固定在这里 |
| Size | 实在过程/函数的活动记录大小 | 调用时需要预留多少空间，不是代码指令条数 |
| Forward | 是否仍是等待实体定义的超前声明 | 只有声明头时可记 true，匹配到定义后改为 false |

**超前声明** 先给出签名，后给出函数体。例如先写 `int add(int x,int y);`，后写 `int add(int x,int y){return x+y;}`，中间位置已经能检查调用。若后面的定义改为一个参数，就与既有签名冲突，不能另建一个无关的同名函数来掩盖问题。

入口 `Code` 可能尚未知，活动记录中的临时空间也可能尚未确定，应在对应阶段回填。例如已知“两个整数形参、返回整数”，不代表已知入口一定是 1000，更不代表 `Size=2`：管理区、局部区和临时区也可能需要空间。

### 4.4 带形式函数的声明怎样逐项处理

下面是 Pascal 风格的函数头片段：

```pascal
function f(x: integer; var y: real;
           function inc(a: integer): integer): integer;
```

`f` 返回整数，接收三项实参：整数值、可引用的实数变量、一个接收整数且返回整数的函数。`a` 属于 `inc` 的签名，不是 `f` 的第四项形参。

设参数区起点 `d`，使用“函数入口和环境引用各占 1”的教学传递模型：

| 次序 | 形参 | 保存什么 | 起始偏移 | 占用 | 下一空位 |
| --- | --- | --- | --- | --- | --- |
| 1 | x | 整数值副本 | d | 1 | d+1 |
| 2 | y | 实数变量的地址 | d+1 | 1 | d+2 |
| 3 | inc | 函数入口、声明环境引用 | d+2 | 2 | d+4 |

若已有整数变量 `m`、实数变量 `r`，以及签名兼容的函数 `h(t:integer):integer`，则 `f(m,r,h)` 在这些参数条件上匹配；`f(m,3.5,h)` 的第二项不是可供 `var` 参数引用的变量，不能这样传递；把无参数函数放在第三项，也不满足 `inc` 的签名。

保存环境引用，是因为被传入的嵌套函数还可能使用其外层变量。这里只需知道“入口确定执行哪段代码，环境确定外层对象到哪里找”；它与 C 的普通函数指针并非统一占两单位的规则。

### 4.5 字段项与信息保存期限

字段项保存名字、类型、相对对象的偏移及下一字段引用。

小例子：无对齐模型中，类型Pair只有两个整数域left、right，每个占1，内部从0排起。字段表为`left:(int,Off=0,next=right)`、`right:(int,Off=1,next=NULL)`。对象p首址300，则p.right在301；字段偏移1相对p，不是相对某个函数帧。

信息还要活到使用结束。另一个独立小情境：已读过函数声明`int twice(int v);`，处理完它的函数体后遇到`twice(4)`，仍要查到“一项整数参数、返回整数”的签名。参数名字v退出局部查找，不意味着可以丢掉签名。

## 5. 类型的内部表示

变量项只写“这是数组”还不够：数组有多长、每项是什么类型、一次下标后得到什么，都需要进一步描述。**类型描述符** 就是保存这些类型结构的数据。下面从一条声明出发，展示描述结构怎样建立，又怎样用于判断和计算。

### 5.1 类型描述的两种用途：同一个描述怎样同时支撑检查和布局

设 C 声明 `int a[3];`，数组对象起始地址取 100，各整数占 1 个单位。编译器可建立以下关系，箭头表示对描述结构的引用：

```text
名字表项 a：Kind=varKind，Type ──→ 数组描述
数组描述：Kind=ArrayTy，Low=0，Up=2，Size=3
          ElemType ──→ 整数描述：Kind=intTy，Size=1
```

建立过程是：从 `int` 找到整数描述；由 `[3]` 得到 3 个元素，C 下界为 0、上界为 2；将元素类型引用设为 `intPtr`；最后计算 `3×1=3`，填入数组的 `Size`。

现在分别完成两项任务：

| 任务 | 从描述中取出什么 | 怎样处理 | 具体结果 |
| --- | --- | --- | --- |
| 检查 `a[1]+2` | a 是数组，元素为 int | 整数下标 1 可用于取元素；元素与整数 2 相加 | 表达式的类型为 int |
| 检查 `a[1.5]` | a 支持下标，但下标还有自身类型 | C 要求这里的下标为整数类型，1.5 不满足 | 下标类型错误 |
| 检查常量范围 `a[3]` | Low=0、Up=2 | 3 不在闭区间 [0,2] | 可证明越界；不据此断言所有编译器都必须报错 |
| 为整个 a 分配空间 | Size=3 | 从 100 起预留 3 个单位 | 槽位为 100、101、102 |
| 定位 `a[1]` | Low=0、元素 Size=1 | `100+(1-0)×1` | 元素地址为 101 |

前面三项是在回答“操作是否允许、结果是什么类型”，后面两项是在回答“占多少空间、到哪里访问”。**类型描述保存的是类型结构，既不保存数组的所有运行值，也不等于对象地址。** 两个同类型数组可以引用同一份类型描述，却占用不同的对象空间。

基本类型的描述较简单：整数为 `(Kind=intTy,Size=1)`，实数为 `(Kind=realTy,Size=2)`，布尔和字符分别为 `boolTy`、`charTy`，均占 1。`intTy` 与 `realTy` 表示类型类别；变量项的 `varKind` 表示名字类别，不能互换。

<a id="ch05-type-subrange"></a>

### 5.2 子界与序数类型：描述允许的值，再把它用于数组下标

有时“整数”这个范围太大。例如只允许一个变量取 -3 到 3，或让数组只接受这一段下标。需要保存基本类型和上下界，而不只是写一个 `int`。

**序数类型** 的值具有离散次序，可以逐个对应序号；整数、字符、布尔和枚举都是常见例子。**子界类型** 是某个序数类型的连续一段。例如 `-3..3` 包含七个整数，`'a'..'z'` 表示从字符 a 到字符 z 的一段。这里的两个点是区间分隔符，不是小数点。[Pascal 序数与子界规则](https://docs.freepascal.org/docs-html/current/ref/refsu4.html)。

看一个 Pascal 声明片段：

```pascal
type Index = -3..3;
     Vector = array[Index] of real;
var k: Index;
    a: Vector;
```

为手算采用“子界沿用基本整数的存储大小”这一模型，得到：

```text
Index 类型名 ──→ 子界描述 I
I：Kind=subrangeTy，BaseType=intPtr，Low=-3，Up=3，Size=1

Vector 类型名 ──→ 数组描述 V
V：Kind=ArrayTy，IndexType=I，Low=-3，Up=3
   ElemType=realPtr，Size=14

k.Type=I                         a.Type=V
```

`subrangeTy` 是本章用于子界的描述类别名。`IndexType` 表示“数组允许什么下标类型”的引用；简单整数下标数组也可以把下界、上界直接存在数组描述中。字段的具体拆分依实现而定，重要的是不丢下标约束和元素类型。

逐项使用这些信息：

| 操作或问题 | 使用哪个描述 | 推导 | 结论 |
| --- | --- | --- | --- |
| `k:=2` | 子界 I | 2 是整数，且 -3≤2≤3 | 取值满足范围 |
| `k:=5` | 子界 I | 5 超过上界 3 | 违反子界约束；常量情形可提前发现 |
| `a[2]` | V 的下标约束和 ElemType | 2 在范围内，元素描述为 real | 取得一个实数元素 |
| `a[4]` | V 的上界 | 4 不在 [-3,3] | 越界 |
| a 占多少空间 | V 的区间及元素大小 | 元素数 `3-(-3)+1=7`，总大小 `7×2=14` | Size=14，不能把它填成子界的 Size=1 |
| 若 a 首址为 200，`a[-1]` 在哪里 | V 的下界和元素大小 | `200+((-1)-(-3))×2=204` | 对象从 204 开始，占两个单位 |

**子界类型的大小、子界的取值个数、以它作下标的数组大小，是三个不同的量。** 本例分别为 1、7、14。只声明 `k:Index` 仅需存一个整数，不是同时存七个数。

字符下标可用序号差计算位置。例如 `array['a'..'c'] of integer` 有 3 个元素；若首址为 300，`'b'` 是该区间第 2 个值，就位于 301。更一般地使用 `ord(下标)-ord(下界)`，其中 `ord` 表示序号。任意实数区间不能照此当成有限个、逐项编号的数组下标集合。

若下标来自运行输入，编译期知道约束，却未必知道它是否满足约束；是否启用运行时范围检查由实现与选项决定。本节没有假定所有语言都会自动检查所有越界。[Pascal 数组边界说明](https://docs.freepascal.org/docs-html/current/ref/refsu14.html)。

<a id="ch05-type-array"></a>

### 5.3 数组与多维数组：外层元素也可以是数组

当所有元素同型并连续排列时，只要知道范围和元素大小，就能计算总空间及元素相对位置。对整数下标、包含两端且非空的区间：

```text
元素数 = Up - Low + 1
数组 Size = 元素数 × 元素类型 Size
元素地址 = 数组首址 + (下标 - Low) × 元素类型 Size
```

若 `Up<Low`，是否允许空数组须按具体语言规定，不能直接把负数当大小。对非整数序数下标，数量和位置由相应序号差决定。

先处理 C 的类型声明 `typedef int A[10];`：下标为 0 到 9，共 `9-0+1=10` 项，元素大小为 1，故 `A.Size=10`。声明 `A x;` 后才为对象 x 分配这 10 个单位。

再看同属 C 类型声明的 `typedef char B[5][10];`。需要先解释内层，再构造外层：

| 描述 | 元素是什么 | Low、Up | 元素 Size | 本层 Size |
| --- | --- | --- | --- | --- |
| 内层行类型 | char | 0、9 | 1 | `(9-0+1)×1=10` |
| 外层 B 类型 | 上述“10 个 char 的数组” | 0、4 | 10 | `(4-0+1)×10=50` |

```text
B 的外层描述 ──ElemType──→ 行描述 ──ElemType──→ char 描述
Size=50                    Size=10              Size=1
```

若声明 `B b;`，首址为 400，则 `b[2]` 先选第 3 行，行首址 `400+2×10=420`，该表达式对应行数组；`b[2][3]` 再取这一行第 4 个字符，地址为 `420+3=423`，最终元素类型为 `char`。5 和 10 描述两层重复关系，所以总数相乘为 50，不能相加为 15。

数组类型与指针类型也不能混为一谈。`B` 对象需要整个 50 单位的数组空间；C 中许多表达式会把数组转换为首元素指针，但不会因此把数组对象本身缩成一个地址槽。

### 5.4 结构体与联合体：分别存放还是共享空间

数组通过下标区分同型元素，结构体通过字段名组合不同信息。为计算 `d.month`，先要在 `d` 的类型中找到字段 `month`，再取其偏移。

```c
typedef struct Date {
    int year, month, day;
} datetype;
```

忽略对齐，从结构内部偏移 0 开始，依次放三个整数：

| 字段 Name | Type | Off | 占用范围 | link |
| --- | --- | --- | --- | --- |
| year | intPtr | 0 | 0 | 下一字段 month |
| month | intPtr | 1 | 1 | 下一字段 day |
| day | intPtr | 2 | 2 | NULL |

结构描述为 `(Kind=structTy,Size=3,FieldList=首字段引用)`，`RecBody` 也是字段表引用的常见名称。假定 `datetype d;` 的对象首址为 500，访问 `d.month` 时：先从字段表找到 `month`，确认结果类型为 int，再计算 `500+1=501`。访问 `d.hour` 则因字段不存在而失败。

结构体字段的 `Off=1` 是相对该对象的偏移。如果整个 d 放在活动记录偏移 8，`month` 相对活动记录首址的总偏移才是 `8+1=9`，不能把这两个基准混在一起。

联合体让不同字段使用同一片空间：

```c
typedef union {
    char ch;
    int i;
    float f;
} data;
```

三个字段大小分别为 1、1、2，全部从内部偏移 0 开始，所以联合体 `Size=max(1,1,2)=2`。若对象首址为 600，三个字段都从 600 开始；它们不是三份独立空间。写入一个字段后，不能假定另一个字段原先的值仍独立保存。

在本章无对齐模型下，结构体大小是依次累加，联合体大小取最大值。真实 C 布局可能有字段间或末尾填充，须另按目标平台的对齐要求计算。

<a id="ch05-type-pointer"></a>

### 5.5 指针与枚举：槽大小不等于所指大小，也不等于成员个数

先看 C 类型声明：

```c
typedef int *T1;
typedef float *T2;
```

| 类型 | Kind | Size | BaseType | 使用区别 |
| --- | --- | --- | --- | --- |
| T1 | pointTy | 1 | intPtr | 解引用得到整数；本模型元素步长为 1 |
| T2 | pointTy | 1 | realPtr | 解引用得到实数；本模型元素步长为 2 |

`pointTy` 表示指针类型，`BaseType` 引用所指类型。两个指针自身都只保存地址，所以同占 1；但其合法操作和解引用结果需要依据所指类型。例如 p 指向整数数组元素、q 指向实数数组元素，且两者都可合法移到下一元素时，本模型 `p+1` 前进 1 单位，`q+1` 前进 2 单位。这个演示不允许对任意无效地址作指针运算。

再看枚举，它给一组离散值命名。C 声明 `enum color {red,yellow,blue};` 的枚举常量值依次为 0、1、2。若改为另一个独立例子 `enum color {red=10,yellow=red+2,blue};`，则逐项得到：

| 常量 | 计算依据 | Value |
| --- | --- | --- |
| red | 显式给值 | 10 |
| yellow | `red+2` | 12 |
| blue | 无显式值，取前一常量值加 1 | 13 |

枚举描述保存 `(Kind=enumTy,Size=1,ElemList=枚举常量表引用)`，常量表项保存 `Name、Value`。`enum color c;` 的 c 只需保存其中一个枚举值，本章给它 1 单位；三个名字并不意味着每个枚举变量需要三个单位。这里枚举变量的大小是教学约定，真实 C 的表示依相应标准和实现规定。

### 5.6 把名字、类型和对象空间放在同一张图里

以 `typedef int A[10]; A x; A y;` 为例：

```text
类型名 A 的表项 ─┐
变量名 x 的 Type ├──→ 数组类型描述(Size=10) ──→ int 描述(Size=1)
变量名 y 的 Type ┘

x 的对象空间：10 个单位，例如 700..709
y 的对象空间：10 个单位，例如 800..809
```

A 说明一种类型，x 和 y 是两个不同对象，类型描述可以共享。检查 `x[2]` 与 `y[2]` 使用相同类型规则，计算地址却分别使用 700 和 800，结果为 702 和 802。这样就把“类型描述的两种用途”与名字、运行空间的关系连起来了。

## 6. 抽象地址与空间分配

### 6.1 为什么编译时先保存相对位置

类型大小告诉我们变量占几格，却还不能给每次函数调用指定同一个对象地址。假定递归函数中整数变量 x 的记录内偏移为 3：外层调用的记录首址为 100，x 在 103；内层调用的记录首址为 200，另一份 x 在 203。两次调用必须拥有不同的活动实例，否则内层会覆盖外层的数据。

**活动记录 AR** 是一次过程/函数调用所需的空间，包括参数、局部变量和管理信息等。**抽象地址** 用 `(Level,Off)` 保存定位信息：层数用于帮助找到所属记录，偏移给出记录内位置。运行时先确定正确的 `base`，再计算 `base+Off`。

**静态分配** 为对象安排固定存储位置；**动态分配** 随调用或申请建立所需空间。全局整数可以具有固定存储位置，递归局部对象通常需要多份记录。指针变量自身也可以放在固定区或栈上，例如全局 `int *p;` 的指针槽；p 将来指向的动态申请对象则是另一份空间。因此不能把“动态对象无法预先固定全部空间”说成“所有指针变量都不支持静态分配”。

### 6.2 一次调用的空间怎样分区

按本章教学布局，活动记录从低偏移向高偏移分为：

```text
AR 首址 base
    管理区：返回地址、链接、保存现场等
    形参区：本次调用接收的值、地址或函数信息
    局部变量区：本次调用的普通局部对象
    临时变量区：计算过程中需要保存的中间结果
```

例如管理区占 4，随后有整数值参 x、实数局部变量 y 和一个占 1 的整数临时量 t：x 在偏移 4，y 从 5 开始占 5、6，t 在 7，记录总大小为 8。若 `base=100`，x 在 104，y 从 105 开始，t 在 107。这里临时量大小 1 是该例约定，其他类型和目标机需要另算。

`Off` 始终要说明相对哪个起点。如果题目给“局部数据区从 off0 开始”，就从 off0 累加；不能自行把 off0 当成 0，也不能在题设之外再猜管理区大小。

### 6.3 地址层数与范围深度是不同的计数

地址层用于选运行记录，范围深度用于选可见声明，二者不总是同一计数。

小例子：Pascal主程序Main位于过程层0，内含过程P（层1），P内含Q（层2）。P声明整数i，Q读取i。本章变量登记层比所属过程层大1，因此i登记Lv=2，实际应定位P的过程层1帧；不能因使用位置在Q就改登记为3。

再看独立的C小片段：一个函数内，外块声明a，内花括号声明b。内块范围深度增加，但a、b仍属于同一次函数调用记录，教学地址Level均为1；全局对象用Level=0。换用另一套层数约定时，相关公式应一起调整。

### 6.4 按大小逐项推进分配游标

分配游标next表示下一空偏移；当前对象从next开始，占多少单位就将next增加多少。

小例子：参数区从d开始，仅有值参p:integer与地址参q:real。约定整数1、实数2、地址1单位，则p起点d，下一空位d+1；q槽只保存地址，起点d+1，下一空位d+2。所指实数需要2单位，不表示地址槽也占2。

形式函数在本章入口／环境两槽模型中占2个地址单位。另一个小例：仅一个形式函数h从偏移4开始，则入口放4、环境放5，下一空偏移6。过程体的游标独立，不能把另一个过程的局部变量追加到这里。

### 6.5 嵌套块的空间是否可以复用

同一函数中，生存期不重叠的局部块可能复用空间，但仍要记住整个函数曾需要的峰值。

小例子：管理区之后从偏移4开始。先进入块A，只有一个占2单位的实数r，使用4、5；A退出后再进入同级块B，只有一个占1单位的字符c。若这些自动对象没有仍需保留的访问关系，B可让c复用4，局部数据峰值仍是2单位，而不是最后只用了1单位。

不复用则c排在6，共需3单位局部空间。符号表是否保留历史项、名字是否可见和运行时槽是否复用是不同判断，不能相互代替。

## 7. 作用域与局部化单位

### 7.1 名字在哪里可用，对象什么时候存在

不同位置可能都写 `x`，所以查表不能只比拼写，还要看使用位置属于哪些有效范围。**作用域** 描述源码中名字的适用范围，**局部化单位** 是形成这类声明范围的结构，如主程序、过程、函数或 C 程序块。

范围可以并列或嵌套，不能出现括号交叉。外块 A 中包含内块 B，离开 B 后再进入同级块 C；此时 C 不能直接使用 B 的局部名字。因此当前有效范围可以按“外 → 内”放进栈。

**生存期** 则描述运行时对象存在多久。例如函数里的 `static int count;` 在多次调用之间保留对象，但 `count` 这个名字仍仅在相应局部范围可见。反过来，递归函数的同一个局部变量声明在源码中只有一处，运行时却可能同时有多份对象。查找名字和管理对象生存期不能合成一个问题。

### 7.2 遮蔽不等于修改外层对象

下面是函数内部的 C 块片段：

```c
int x = 1;
{
    int x = 2;
    x = 3;
}
/* 此处使用 x */
```

内块声明创建另一个对象，内块赋值绑定到该局部声明，令内层对象变为 3。退出内块后，外层 x 恢复可见，其值仍为 1。这个同名选择现象称为**遮蔽** 。

查找按当前范围向外逐层进行，遇到最近的有效同名声明就确定绑定。本章普通变量例子采用先声明后使用；特殊语言规则、函数超前声明和 C 的其他命名空间需要按各自规则处理，不能把所有同名声明都一概判为错误。

### 7.3 用两组嵌套关系检查可见性

小例子：主过程Outer有整数a=1，内含过程Left与Right；Left另有自己的a=2，Right没有a。Right使用a时，按声明链Right→Outer找到1。即使运行时是Left调用Right，Right也不会因此看到Left的2。

若Right自己再声明一个a，则使用它自己的声明；若Outer和Right都没有a，查找失败。可见性由当前位置和声明结构决定，不随调用者临时改变。

## 8. 符号表的组织与管理

### 8.1 先分开三个组织问题

作用域规则已经确定该找哪个声明，接下来选择保存和查找它的数据结构。下面三个角度可以组合，不是互斥的三种实现：

| 角度 | 可选安排 | 在相同小例中的含义 |
| --- | --- | --- |
| 属性总体组织 | 单表或多表 | x 的变量属性、f 的函数属性可放在统一带类别记录里，也可由名字索引分别引用不同属性表 |
| 表项排列与查找 | 线性、有序、散列 | 名字按出现顺序追加；或按名字有序查找；或按散列值进入桶并处理冲突 |
| 范围组织 | 全局式或局部式 | 全程序声明集中存一张表；或每个有效范围各有一张表 |

例如“每个作用域一张散列表，名字项再引用独立类型表”，同时用到了局部式、散列和多表属性组织。**全局式符号表** 的“全局”指集中存储，也包含函数局部变量，不是“只存全局变量”。

线性表中依次追加 a、b、a 时，可以从后往前找到最近有效的 a；有序表需要另外保存范围信息才能选对同名项；散列表即使把两个 a 分到同一桶，也必须依据范围决定绑定。改变容器不会自动实现作用域规则。

### 8.2 进入、声明、使用、退出四项操作

进入、声明、使用、退出分别改变当前名字查找的范围，不能把编译期Scope栈当作目标程序调用栈。

小例子：外层仅声明count:int。进入一个新块时先记录边界；在块内声明flag:bool时只检查本层，再登记；使用count时本层没有，向外找到整数项；块退出后flag不再参与查找，而count仍可见。这四步只需两个名字，无须先读一段完整程序。

若本层已经有flag，再声明同类普通变量flag应按语言规则报告冲突；外层有同名项则是另一个范围问题。

### 8.3 全局线性表的真删除法

约定表下标从 0 开始，`s=-1` 表示空表，Scope 的右端为栈顶。进入范围时压入 `s+1`；普通声明填到 `s+1` 并推进 s；使用从 s 逆查；退出时将有效表末尾退到 `Scope.top-1` 并弹栈。

| 处理事件 | 有效表项 | s | Scope |
| --- | --- | --- | --- |
| 进入全局范围并声明 x | `0:x(外)` | 0 | [0] |
| 进入内层 | 同上；本层起点为 1 | 0 | [0,1] |
| 声明内层 x、y | `0:x(外),1:x(内),2:y(内)` | 2 | [0,1] |
| 使用 x | 逆查在 1 命中内层 x | 2 | [0,1] |
| 退出内层 | 有效表只剩 `0:x(外)` | `1-1=0` | [0] |
| 外层继续使用 x 或 y | x 命中 0，y 查不到 | 0 | [0] |

退出后位置 1、2 可被新表项复用。若中间代码仍引用旧属性，应提前复制必要信息或保存持久描述，见 4.5。

### 8.4 驻留法：表项保留，但查找跳过无效范围

驻留法保留历史表项，但查找必须跳过已经结束的范围。

小例子：表从0编号，外层只声明u，表为`0:u(外)`；内块起点1，只声明v，表为`0:u(外),1:v(内)`。退出内块时追加`2:(#,0)`，目标由起点1减1得到；Scope从[0,1]退成[0]。

此后查u走2(#)→0，成功；查v走2→0→表头外，失败，不能因为1项仍在就绑定它。s停在新增跳转项2，不退回0。这里#是退出跳转项，0是符号表下标，不是u的内存偏移。

一般退出项是`(#,本层起点−1)`；起点0对应−1，表示查找结束。本层重复检查同样要跳过无效范围。

### 8.5 局部表：有效表栈与表对象分开

为外层建立 `T0={x:int,z:int}`，进入内层建立 `T1={x:real,y:int}`，有效表栈为 `[T0,T1]`。查 x 在 T1 命中 real；查 z 先查 T1，再在 T0 命中 int；退出后弹出 T1，栈为 `[T0]`，查 y 失败，查 x 得到外层 int。

弹出有效栈就实现了逻辑失效。T1 的物理对象可以释放，也可以为了后续处理保留；只要它不再参与当前普通名字查找，就不会破坏作用域规则。因此“局部表退出”不等于理论上必须立即销毁全部记录。

## 9. 综合练习：从源码到查表与访问

### 9.1 f、g、main：按编译顺序跟踪名字

下面是用于构表的 C 片段。g 的体内语句用 `...` 省略，不参与本例；片段用于追踪声明，不作为完整可编译程序：

```c
int x, y;
int f(int z)
{
    x = x + 1;
    return z * z;
}
int g(int u, int v)
{
    ...
}
int main()
{
    x = 0;
    g(x, f(2));
}
```

函数名登记在全局范围，参数登记在各自函数范围。先使用真删除法，起始 `s=-1,Scope=[0]`，得到：

| 处理位置 | 有效表项与查找 | Scope |
| --- | --- | --- |
| 全局 x/y | `0:x,1:y` | [0] |
| f 头 | 在 2 登记 f；进入函数后从 3 登记 z | [0,3] |
| f 内 `x=x+1` | 从 3 的 z、2 的 f、1 的 y，找到 0 的 x；左右两处都绑定它 | [0,3] |
| 退出 f | 去掉有效区中的 z；保留 0:x、1:y、2:f | [0] |
| g 头与退出 | g 在 3，u/v 临时占 4/5；退出后 s=3 | [0] |
| main 体 | main 在 4，进入后本层起点 5；x/f/g 都从全局找到 | [0,5] |

若从初始程序重新采用驻留法，表项编号变为：

```text
0:x  1:y  2:f  3:z  4:(#,2)
5:g  6:u  7:v  8:(#,5)
9:main  10:(#,9)    ← main 退出后追加
```

在 main 内找 f，从 9 逆查：`9→8(#跳5)→5→4(#跳2)→2(f)`。z/u/v 仍保存在表中，却已被跳过。两种方法编号不同，绑定的有效声明应相同。

这条轨迹描述编译器处理源码，不能当作 `g(x,f(2))` 的运行顺序。C 不保证实参按源码从左到右求值，尤其 f 会修改全局 x，不能只凭写法断言 g 收到的第一个实参是哪次读取的值。本例只判断绑定和签名，不推断 g 的运行结果。

### 9.2 嵌套块的三次输出怎样找到声明

下面是函数内部的 C 块片段，假定已正确声明 `printf`；仅展示与范围相关的代码：

```c
{
    int a = 1, b = 1;                 /* 块1 */
    {
        int b = 2;                    /* 块2 */
        {
            int a = 3;                /* 块3 */
            printf("a=%d,b=%d\n", a, b);
        }
    }
    {
        int b = 4;                    /* 块4，与块2并列 */
        printf("a=%d,b=%d\n", a, b);
    }
    printf("a=%d,b=%d\n", a, b);
}
```

| 输出位置 | 查 a 的路径 | 查 b 的路径 | 输出 |
| --- | --- | --- | --- |
| 块3 内 | 块3 命中 a=3 | 块3 没有，块2 命中 b=2 | `a=3,b=2` |
| 块4 内 | 块4 没有，块1 命中 a=1 | 块4 命中 b=4 | `a=1,b=4` |
| 块1 末尾 | 块1 命中 a=1 | 块1 命中 b=1 | `a=1,b=1` |

离开块2后，它的 b 不再是有效声明。离开块4也不会把 4 写回块1的 b；声明了同名对象，与给外层对象赋新值不同。

### 9.3 swap：地址参数槽与被交换对象

考虑以下 C 函数，调用位置为 `swap(&x,&y)`，调用前全局整数 x=10、y=20：

```c
void swap(int *a, int *b)
{
    int tmp;
    tmp = *a;
    *a = *b;
    *b = tmp;
}
```

设全局 x、y 地址分别为 100、101；swap 的记录首址为 200，参数区起点 d=4，则 a 槽在 204、b 槽在 205、tmp 在 206。x/y 登记地址层 0，参数和 tmp 登记层 1。

| 步骤 | 读写过程 | x | y | tmp |
| --- | --- | --- | --- | --- |
| 传参 | `Mem[204]=100,Mem[205]=101` | 10 | 20 | 尚无值 |
| `tmp=*a` | 读 204 得 100，再读 100 得 10，写入 206 | 10 | 20 | 10 |
| `*a=*b` | 读 205 得 101，取其值 20；经 204 得目的地址 100，写入 20 | 20 | 20 | 10 |
| `*b=tmp` | 读 206 得 10，经 205 得目的地址 101，写入 10 | 20 | 10 | 10 |

a/b 槽保存的地址始终为 100、101，交换的是 x/y 对象值。形参指针自身按值传递，与通过指针访问调用者对象是两个层次。

### 9.4 后续翻译还要继续使用哪些信息

以 `a[1]=2` 为例，语义分析先确认 a 可下标，元素可赋整数；生成中间代码需要元素大小和下界来计算偏移；目标代码再用 a 的所属空间和 Off 找到首址，然后写入对应单元。

如果语法树或中间代码引用了 a 的属性，名字查找范围退出后，这些引用仍须有效。例如真删除法把表位置复用给另一个变量，不能让旧代码把它误认为原 a。可以复制必要属性，或引用独立保存的对象描述；名字是否仍可见，与后续翻译能否保留已绑定对象的信息不同。

### 9.5 综合诊断练习：先绑定，再检查错误

下面保留 C 片段中的关键声明和错误使用，省略与判断无关的输出语句；它不是可直接编译的正确程序：

```c
int x = 10;
int main()
{
    x();
    f = x;
}
float f()
{
    int x = 20, y;
    float x;
}
```

以 C11 的先声明后使用规则分析：

| 位置 | 先确定哪个声明 | 再检查什么 | 结论 |
| --- | --- | --- | --- |
| `main` 中 `x()` | 找到全局 `int x` | 是否可调用 | 不可调用，语义错误 |
| `main` 中 `f=x` | 此处还没有 `f` 的声明 | 左边名字是否已声明 | 未声明；后面的函数定义不会自动补成此前可见的声明 |
| `f` 中 `int x=20` | 引入一个新的局部 `x` | 是否与本范围已有声明冲突 | 与全局 `x` 不同范围，可以遮蔽全局名字 |
| 随后的 `float x` | 同一函数块内已有局部 `x` | 本范围是否重复声明了对象 | 冲突；换成另一种类型不能使重复声明合法 |

即使在 `main` 前补上函数原型 `float f(void);`，`f=x` 仍不合法：左边绑定到函数后，并不是可以普通赋值的变量。可见“查得到名字”只是第一步，还要检查对象类别和类型。

## 10. 综合应用：快速排序片段的驻留符号表

例题取自《编译原理22级期末题》第二大题第 1 问。题目要求采用全局符号表驻留方法：变量写名字、种类、类型、层数、偏移；函数写名字、种类、类型、层数；局部数据区从 off0 开始，整数占 1 单位。题设片段如下。

```c
void swap(int *a, int *b) {
    int t = *a;
    *a = *b;
    *b = t;
}
int partition(int arr[], int low, int high) {
    int pivot = arr[high];
    int i = (low - 1);
    for (int j = low; j <= high - 1; j++) {
        if (arr[j] < pivot) {
            i++;
            swap(&arr[i], &arr[j]);
        }
    }
    swap(&arr[i + 1], &arr[high]);
    return (i + 1);
}
```

原题未给指针宽度。本解答采用数据地址占 1 单位、无对齐、不复用 partition 内局部槽的模型；若地址宽度另有规定，a/b/arr 及其后续偏移需要重算。C 形参 `int arr[]` 按规则调整为指向 int 的指针，不在参数区复制整个数组。[C11 草案 N1570 §6.7.6.3 第 7 段](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf)。

### 10.1 先找范围，再分配偏移

全局范围登记 swap、partition 两个函数。swap 的 a/b/t 属于 swap；partition 的 arr/low/high/pivot/i 属于 partition；j 属于 for 的范围，for 后不可见。

swap 和 partition 每次分别使用自己的记录，分配游标都从 off0 开始。swap 的 a/b/t 各占 1，下一空位 off0+3；partition 的前五项各占 1，分到 i 后下一空位 off0+5；j 再占 1，位于 off0+5。

下表只给有声明需要退出管理的范围加跳转项，不为没有新声明的 if 空范围另列退出项。若实现也记录这些空范围，表号可以不同，有效绑定应相同。函数的“类型”列先写返回类型，并附参数签名帮助检查；表号从 0 开始，不是目标程序内存地址。

| 表号 | 名字 | 种类 | 类型或跳转目标 | 地址层数 | 偏移 | 所属范围及意义 |
| --- | --- | --- | --- | --- | --- | --- |
| 0 | swap | routKind | void；参数(int*,int*) | 0 | 不适用 | 全局函数名 |
| 1 | a | varKind | pointer(int) | 1 | off0 | swap 的指针值形参 |
| 2 | b | varKind | pointer(int) | 1 | off0+1 | swap 的指针值形参 |
| 3 | t | varKind | int | 1 | off0+2 | swap 的局部变量 |
| 4 | # | 跳转项 | →0 | 不适用 | 不适用 | swap 退出，越过1—3 |
| 5 | partition | routKind | int；参数(int*,int,int) | 0 | 不适用 | 全局函数名 |
| 6 | arr | varKind | pointer(int) | 1 | off0 | 调整后的数组形参 |
| 7 | low | varKind | int | 1 | off0+1 | partition 形参 |
| 8 | high | varKind | int | 1 | off0+2 | partition 形参 |
| 9 | pivot | varKind | int | 1 | off0+3 | partition 局部变量 |
| 10 | i | varKind | int | 1 | off0+4 | partition 局部变量 |
| 11 | j | varKind | int | 1 | off0+5 | for 范围局部变量 |
| 12 | # | 跳转项 | →10 | 不适用 | 不适用 | for 退出，越过11 |
| 13 | # | 跳转项 | →5 | 不适用 | 不适用 | partition 退出，越过6—12 |

Scope 的变化可核对为：全局 `[0]`；进入 swap 后 `[0,1]`，退出恢复 `[0]`；进入 partition 后 `[0,6]`；进入 for 后 `[0,6,11]`，退出恢复 `[0,6]`。三个退出目标分别为 `1-1=0、11-1=10、6-1=5`。

跳转项属于编译器的表管理数据，不占目标程序变量槽，也不与前几章的输入结束符 `#` 共用含义。

### 10.2 用查找路径检查这张表

| 所处位置与查询 | 路径或命中项 | 说明 |
| --- | --- | --- |
| for 内查 j | 命中11 | 本层 j 有效，偏移 off0+5 |
| for 内查 i | 从11往前，命中10 | 外层 partition 变量仍有效 |
| for 内查 swap | 11→…→5→4(#跳0)→0 | swap 的局部 a/b/t 被跳过，函数名仍有效 |
| for 结束后查 j | 12(#跳10)→10→…，无有效同名项 | 表里还在，但已不可见 |
| for 结束后查 i | 12(#跳10)→10 | 仍可使用 |
| partition 结束后查 i | 13(#跳5)→5→4(#跳0)→0→结束 | partition 的所有局部项被跳过 |

函数签名保留在全局函数项或其持久引用中。以后调用 partition，仍须知道三个形参的类型；局部名字失效不等于整个函数信息失效。

## 11. 错误判断练习：能证明什么，在哪个阶段发现

例题取自同一期末题第二大题第 2 问。判断不能只看“这像除零”或“这有括号”，要找出具体违反的规则，并区分可以证明的问题和某个编译器是否必须发出诊断。

| 片段与前提 | 逐步判断 | 问题与可发现阶段 |
| --- | --- | --- |
| 函数内 `int a=2; int i=0; float b; b=2/i+8;` | i 在除法前为 0，且无改写；先计算整数 `2/i`，赋给 float 并不会先把除法变成实数除法 | 整数除零。常量传播/数据流分析可提前证明；基本的类型检查本身不必知道 i 的值 |
| `int a; int b=a(3);` | 查 a，类别为普通整数变量，不能调用 | 静态语义错误 |
| 已有 `int x_pos(int a,int b)`，调用 `x_pos(3,4,5)` | 签名期望 2 个，实参为 3 个 | 参数个数错误，静态语义 |
| `int a[50]; a[30]]=8;` | 一个下标已经闭合，后面多一个 `]`；30 位于 0..49 | 主要是语法错误，不是下标越界 |
| 原题 `const i=10; i=5;` | 在 C11 中声明缺少类型；若按“只读整数对象”本意写成 `const int i=10; i=5;`，第二句又试图修改只读对象 | 原写法有声明约束问题；按补全类型后的片段，赋值是静态语义错误 |

这里以 C11 解释声明和类型约束，未指定具体编译器和选项。除零能否在编译期被报告、报告为警告还是错误，不能单凭语义分类保证。若把 i 换成来自输入且不能证明取值的参数，就需要运行信息或更强的程序分析；不能沿用“已知 i=0”的结论。

## 12. 知识联系与解题路线

### 12.1 从一个数组元素访问连接各部分

设 C 函数中有 `int a[3];`，a 在所属 AR 的偏移为 4，运行时该记录首址为 100。分析 `a[2]=7` 时：

| 顺序 | 要回答的问题 | 使用的信息 | 得到的结果 |
| --- | --- | --- | --- |
| 1 | a 指哪个声明 | 当前有效范围链 | 绑定到本函数的数组 a |
| 2 | 能否使用下标 | a 的数组描述 | 元素类型 int，下标为整数 |
| 3 | 本次取值是否在范围内 | Low=0、Up=2，常量下标 2 | 位于范围内 |
| 4 | 写入 7 是否允许 | 元素可修改，7 为 int | 类型与赋值条件满足 |
| 5 | 数组对象从哪里开始 | 所属 base=100、Off=4 | 数组首址 104 |
| 6 | 第 3 个元素在哪里 | `(2-0)×1=2` | 地址 106，写入整数 7 |

这说明符号表不仅服务语义检查，也为中间代码中的偏移计算和目标代码中的寻址提供信息。若 a 来自外层过程，步骤 5 必须先找到外层记录，不能直接用当前记录首址。

### 12.2 三类题分别怎样下手

类型、空间和查表题可分别用一个新的小情境检查解题路线。

| 题型 | 当前小题的完整条件 | 怎样着手与核对 |
| --- | --- | --- |
| 类型描述 | a为3个整数的数组，整数1单位，下界0，首址40 | 类型保存边界0..2及整数元素类型，大小3；a[1]地址41，a[3]越界 |
| 空间偏移 | 一个整数和一个实数，大小1、2，从偏移4连续安排，无对齐 | 起点4、5，下一空位7；不要把对象个数2当成总大小 |
| 作用域查找 | 外层x:int，内层仅y:real，当前在内层使用x | 内层未命中后向外找到x；退出内层后y不可见 |

完整程序题再组合这些步骤；局部检查不需要回忆另一道题的过程名和表号。

## 13. 自测与答案

先独立写出结果和理由，再展开答案。除特别说明外，沿用本章大小、无对齐和地址宽度约定。

| 9 | 主程序M内声明P，P内并列声明Q和S，a只在Q局部声明。S能否使用a？Q调用S会改变答案吗？ |
| 10 | 给定表项10:i(外)、11:j(已退出内块)、12:(#,10)，从12逆查i/j的路径是什么？跳转目标10是内存偏移吗？ |

<details>
<summary>展开答案与推导</summary>

### 13.1 答案与理由

1. x 是变量，可作可修改对象；f 是返回整数的函数，可调用。名字类别分别为 varKind、routKind，函数还要参数签名。只存 int 不能判断能否赋值和调用。

2. 取值个数 `4-2+1=3`；k 只存一个子界整数，占 1；a 有三个实数，占 `3×2=6`；a[3] 地址为 `100+(3-2)×2=102`。个数、单个变量大小和整个数组大小不可互换。

3. 外层 ElemType 指向大小为 10 的“char[10] 行数组”描述。b[2] 对应一行数组，b[2][3] 才是 char 元素；在多数 C 表达式上下文中，行数组还会按规则转换为首元素指针，不能因此抹掉类型描述中的这一层数组。

4. 结构体 c 从 0 占 1，r 从 1 占 2，n 从 3 占 1，总大小 4；联合体各字段都从 0 开始，大小 max(1,2,1)=2。真实对齐布局须重新计算。

5. x=d，y=d+1，p=d+3，下一空位 d+4。p 自身只存地址，占 1；所指 int 的大小用于解引用和元素步长，不增加指针槽大小。

6. x=d，占 1；y=d+1，占地址 1；f=d+2，占两个槽至 d+3；c=d+4，占 1；next=d+5。

7. 真删除法将有效 s 退到 `1-1=0` 并弹 Scope，1/2 可复用。驻留法追加 `3:(#,0)`，保留旧项，再弹 Scope。两种方法都只能找到外层 x，找不到 y；驻留查找从3跳0，不能查看已经失效的2。

8. Scope 深度增加，但本章 C 地址 Level 仍为1，因为仍属同一次函数调用。递归产生新的 AR 首址，声明的 Off 可以保持不变，通过不同 base 得到不同对象地址。

9. 不能，S 的声明链为 S→P→M，不含 Q 的局部范围。Q 调用 S 不会改变词法作用域；要让 S 使用某个值或对象，应通过语言允许的可见声明或参数传递。

10. 从 #12 跳到10，恰好跳过11的 j，命中10的 i。10是符号表项号；i 的目标程序偏移是 off0+4，两者所属数据结构不同。

</details>

## 14. 排错与复习

| 现象或疑问 | 可能混淆 | 怎样核对 | 正确理解 |
| --- | --- | --- | --- |
| 把 x 的 Kind 写成 intTy | 名字类别与类型类别 | 沿 x.Type 再看类型描述 | x 项为 varKind，整数描述才是 intTy |
| 子界 -3..3 的变量大小写成 7 | 值个数与存储宽度 | 问“只存一个值，还是存全部元素” | 本模型单变量1，值个数7，real数组总大小14 |
| char[5][10] 大小写成15 | 两层重复关系 | 先算行大小，再乘行数 | 5行×每行10，共50 |
| 指针槽按 real 的2来分 | 指针本身与所指对象 | 分别查 pointer.Size 与 BaseType.Size | 槽1，所指实数2 |
| 内层同名一律报错 | 本层冲突与外层遮蔽 | 标记每项所属范围 | 普通内层变量可遮蔽外层，不能仅凭拼写判重复 |
| 驻留表里有j就继续使用 | 物理存在与当前可见 | 实际走一遍退出跳转 | 已退出范围必须被跳过 |
| 所有查找都用当前SP加Off | 当前记录与对象所属记录 | 先问声明属于哪个过程 | 外层对象先找外层base，再加偏移 |
| 退出块后把最大空间写小 | 当前next与峰值需求 | 记录分配中的最大值 | 复用降低新增需求，不抹去此前峰值 |
| 后端读到另一变量属性 | 保存的引用指向已复用表位 | 对照绑定对象与属性保存期 | 复制所需信息或引用持久对象描述 |

学完后应能解释一个名字绑定到谁、类型描述每层引用谁、一次操作为何允许，并独立计算对象大小、偏移和查表路径。只背“由内到外”“按 Size 累加”而写不出一个具体过程，仍需回到相应例子重新推导。
