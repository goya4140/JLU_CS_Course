运行时存储空间管理

程序运行时，内存被划分为代码、静态、栈、堆等区域。这一章解决核心问题：如何把变量的抽象地址映射到真实存储地址。栈式管理用过程活动记录随调用压栈、随返回退栈，再通过 Display 表或静态链构造变量访问环境，实现包括非局部变量在内的所有变量寻址。

01

运行时管理概述

OVERVIEW

运行时存储空间管理，指目标程序运行时存储空间如何管理。核心问题是如何把变量的抽象地址与存储空间中的真实地址进行映射：运行时空间怎么划分管理，存储空间如何访问。

生活类比
抽象地址像“某小区某栋某层”的门牌描述，运行时管理则是真正把这个门牌对应到地面上的具体位置：先有小区地块（内存分区），再按门牌找到房间（地址映射）。

存储分配的本质是建立变量名与存储位置的关联，该位置用于容纳变量的值。源语言的结构、数据类型、作用域和生存期规则，决定了分配策略的复杂程度。

02

目标程序运行时的内存划分

MEMORY LAYOUT
库代码区 library标准库代码
目标代码区 code编译生成的程序
静态区 static全局/静态变量
堆区 heap动态申请
栈区 stack过程活动记录
  • 库代码区：存放标准库函数目标代码，如 sin、cos 及 #include 包含的库代码；
  • 目标代码区：存放连接装配后的目标程序；
  • 静态区：编译时可确定地址、能编进目标代码的数据，如静态变量、全局变量；
  • 栈区：存放过程活动记录，调用压栈、结束退栈；
  • 堆区：非连续模式的动态分配，存放 malloc/free、new/delete 管理的数据。
总原则
尽可能多做静态分配以缩短运行时间；必须动态分配的，也尽量放栈区，因为堆区分配代价高于栈区。各区边界不固定，栈、堆相遇即内存溢出。
03

存储管理模式分类

STRATEGY

影响分配策略的语言特征：过程能否递归、返回后局部变量是否保留、能否访问非局部数据、参数传递方式、过函能否作为结果传递、存储块能否动态分配、是否必须显式释放。

静态存储分配

编译时分配，运行时保持不变。

栈式动态分配

把存储器当栈管理，AR 随调用压栈。

堆式动态分配

把存储器当堆管理，支持自由申请释放，常与栈式组合使用。

04

静态存储分配

STATIC

完全采用静态分配的语言必须满足：

  1. 不允许递归过程；
  2. 数据对象长度和内存位置编译时可知；
  3. 不允许动态建立的数据结构（动态数组、指针）。

现代语言可分配在静态区的有：全局变量（运行期间大小固定）、C 的 static 变量（全局/局部）、常量及信息表（常量表）。

int sum=0; int square(int i){ int j; j=i*i; return j; } void main(){ int j; j=square(n); sum=sum+j; } // 静态分配：sum、i、j、t1 等位置编译期固定
05

栈式动态存储分配

STACK

最常见的模式：每调用一个函数，其活动记录就动态分配在栈顶，退出即释放。每个 AR 的大小和内容项是静态确定的。

  • 不支持动态申请（new、malloc），不支持可变长数组；
  • 生命周期长于函数的变量不能用栈式，如 static 变量；
  • 栈式解决了递归问题，也解决了空间共享问题。

栈区设两个指针（通常在寄存器中）：sp 指向当前活动记录起始位置，top 指向第一个可用存储单元。因为各函数 AR 大小不同，需要两个指针才能正确退栈。

堆式何时需要
若空间使用不服从“先申请后释放、后申请先释放”，就不能用栈式。如 malloc 后指针长期保留，需在堆区管理；堆区申请释放代价大，非必要不用。
06

过程活动记录的结构

AR STRUCTURE

活动记录是为管理过程一次活动所需信息而在栈区分配的连续空间。从高地址到低地址包含：

临时变量区：寄存器不足时存放表达式中间结果；局部变量区：保存过程局部声明的数据；形参变量区：存放调用提供的实参。

  • 变量访问环境：提供非局部变量访问环境；
  • AR 大小、过程层数：无 top 时用 sp+size 算栈顶；层数辅助寻址；
  • 寄存器状态：保存调用前机器状态（程序计数器、寄存器值）；
  • 返回值：存放返回值的空间地址；返回地址：调用指令下一条；
  • 动态链指针（控制链）：指向调用者的 AR，返回时恢复。
AR 不含全部信息
非局部数据不在 AR 中；运行时生成的动态变量也不在 AR 中，通常堆式分配。
07

AR 申请释放、调用链与动态链

CALL CHAIN

7.1 申请与释放

  • 申请（call）：①产生新 AR，sp=top，top=top+size；②保存现场、填写管理信息（返回地址、动态链指针）；
  • 释放（return/endfunc）：①恢复现场；②释放当前 AR，top=sp，sp=动态链指针；③按返回地址生成跳转。

7.2 调用链与动态链

调用链是过程名序列，头是主程序名 M；R 中调用 S 则链延长。同一过程的调用链不唯一，每个对应一个动态调用序列。动态链是调用链对应的 AR 序列 [AR(M),…,AR(S)]。

08

变量访问环境

VISIT ENV

8.1 活跃活动记录 LAR

一个过程 S 在动态链中可有多个 AR，但只有最新的 AR(S) 可访问，称活跃活动记录 LiveAR(S)。

8.2 声明链与访问环境

声明链 DeclaChain是过程声明的嵌套序列；若 DeclaChain(Q)=(M,…,P,Q)，则 Q 的变量访问环境为各层活跃 AR 序列 [LAR(M),…,LAR(P),LAR(Q)]。

变量访问由声明链决定，而非调用链

例：R 的声明链 (M,P,Q,R)，调用链 (M,P1,P2,Q1,R1,R2,R3)，则 R 的访问环境是 [AR(M),AR(P2),AR(Q1),AR(R3)]——取的是各静态外层的活跃 AR。

8.3 非局部变量访问

Q 中定义在 Q、M、P 的变量，地址分别为对应 LAR 起始地址加各自偏移。只要知道 AR 的访问环境，就能访问包括非局部变量在内的所有变量。

  • 递归：Pi 与 Pi+1 同层，声明链相同；
  • 同层调用：P、Q 层数相同，有共同外层；
  • 直接外层：P 层数 N−1 调用 N 层 Q；
  • 内嵌多层：P 层数大于 Q。

定理：VarVisitEnv(AR(Q)) = VarVisitEnv(AR(P)) 的前 N 项 ⊕ AR(Q)，即可由先行过程的访问环境求得。

09

Display 表方法

DISPLAY

9.1 局部 Display 表

对每个 AR 求出变量访问环境，以地址表（Display 表）保存在 AR 中，每个 AR 自带。若 P 的访问环境为 [AR0,…,ARn]，则 [ar0,…,arn] 是其 Display 表。

NewAR.Display = CurrentAR.Display 的前 N 项 ⊕ newsp

变量 X(L+1,off) 地址：

  • L 等于当前层：addr(X) = sp + off（局部变量）；
  • 否则：addr(X) = CurrentAR.Display[L] + off。

9.2 全局 Display 表

每个程序设一个总 Display 表，长度为最大嵌套层数，D[i] 存放第 i 层最新 AR 指针。依据：任何一点相同层数的声明只能有一个有效。AR 中设 Resume 单元临时保存旧 D[i]。

  • 调用 j 层 Q：NewAR.ResumeAddr = D[j]，再 D[j] = NewAR 地址；
  • 退出 Q：D[j] = CurrentAR.ResumeAddr；
  • 变量访问：addr(X) = D[L] + off。
10

静态链方法与比较

STATIC CHAIN

局部 Display 表中每个 AR 都存一整张地址表，较费空间。静态链方法把它压缩成一个单元：静态链指针指向当前层过程的静态外层活跃 AR 起始地址，实践中放在原动态链指针位置。

k = CurrentAR.level − NewAR.level + 1
NewAR.StaticChainPointer = Indir(sp, k)（sp 的 k 次间接内容）

变量 X(L+1,off) 地址：

  • L 等于当前层：addr(X) = sp + off；
  • 否则：k = CurrentAR.level − L，addr(X) = Indir(sp,k) + off。

10.1 三种方法比较

方法代价特点
局部 Display产生花空间返回时无需恢复环境
全局 Display产生、返回都花时间节省存储单元
静态链产生花时间共享化的局部 Display，返回无需恢复，省单元

寄存器较少时用 Display 表合适；机器间接操作能力强时可选静态链。
