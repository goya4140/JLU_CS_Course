01

词法分析概述

OVERVIEW

词法分析程序是编译程序的一部分，是整个编译过程的第一步工作。它的作用可以概括成三件事：分离单词、生成 Token、检查词法错误。

1.1 什么是单词

单词是具有独立含义的最小语义单位。注意“最小”这个限定——它不能再往下拆，拆开就没有独立意义了。看课件里这段程序：

int main( ) { int x1; x1 = 1; if ( x1 > 0 ) x1 = x1 + 10; }
  • int 是一个单词（保留字），main、x1 各是一个单词（标识符）；单独的 x 或 1 不是单词，没有独立意义。
  • 10 是一个单词（常量），分开的 1 和 0 不是单词；(、)、{、+、=、; 各自是一个单词。
  • x1 > 0 不是一个单词，因为它不是最小单位，还能继续拆成 x1、>、0 三个单词。

1.2 什么是 Token

Token 是单词的具体表示，是一种数据结构。它应包含哪些信息没有统一规定，通常有两种设计：

两元组<单词类别（语法），单词内容（语义）>
三元组<行号，单词类别，单词内容>

类别信息用于语法分析，告诉后面这个单词在语法上扮演什么角色；内容信息用于语义分析，记录它具体是哪个标识符、什么数值。例如课件里的 Token 可写成 (1,id,main)、(1,(,-) 这样的形式。

生活类比
词法分析就像给一整段话逐词加词性标注：先把句子切成词，再给每个词标上“名词、动词、标点”这类标签，同时记下它具体是哪个词。后面的语法分析拿到的就是这串带标注的词，而不是一个个孤立的字母。
02

形式语言基础

FORMAL LANGUAGE

在描述单词之前，先要建立一套严格的概念体系，否则后面的规则容易产生二义性。这一节从字母表出发，一步步走到闭包。

2.1 字母表与符号串

（1）字母表 alphabet

字母表是元素的非空有穷集合，其中一个元素称为一个字母，也叫符号或字符。字母表具有非空性和有穷性，通常用 ∑ 表示。

Σ = {a, b, c, d}　　Σ = {0, 1}　　Σ = {男, 女}　　Σ = ASCII

抽象来看，任何一种程序设计语言都有一个标准字符集，它就是一个字母表。

（2）符号串

由字母表中的符号组成的任何有穷序列，称为该字母表上的符号串，一般用 α、β、x、y、z 表示。ε 表示空串，对任一字母表，ε 都是它上面的符号串。

2.2 前缀、后缀与子串

设 x = yz 是符号串，则 y 是 x 的前缀，z 是 x 的后缀。当 z ≠ ε 时，y 是真前缀；当 y ≠ ε 时，z 是真后缀。

概念（以 x = abc 为例）具体内容
前缀ε, a, ab, abc
真前缀ε, a, ab（不含 abc 本身）
后缀abc, bc, c, ε
真后缀bc, c, ε
子串abc, ab, bc, a, b, c, ε

子字符串：一个非空字符串删去它的一个前缀和一个后缀后得到的字符串。如果删去的前缀和后缀不同时为 ε，称为真子串。特别注意：ac 并不是 abc 的子串，因为子串必须是连续的一段。

2.3 连接与方幂

（1）符号串连接

把 β 的所有符号顺次接在 α 的所有符号之后，记为 α·β，点可省略即 αβ。例如 α = abc、β = de，则 αβ = abcde；α·ε = α。

（2）符号串的方幂

把 α 自身连接 n 次得到的符号串，称为 α 的 n 次幂，记作 αn。

α0 = ε　　α1 = α　　α2 = αα　　αn = αα…α（n 个 α）

2.4 符号串集合及其乘积

若集合 A 中所有元素都是某字母表上的符号串，则称 A 为该字母表上的符号串集合，用 A、B、C 表示。两个集合的乘积定义为：

AB = { xy | x ∈ A 且 y ∈ B }

例：A = {a, bc}，B = {de, f}，则 AB = {ade, af, bcde, bcf}，注意 AB ≠ BA。两条特殊规则：

  • ∅A = A∅ = ∅，其中 ∅ 是空集——一个集合取不到元素，乘积自然为空。
  • {ε}A = A{ε} = A。
易混点
空集 ∅ 不同于空串集 {ε}。∅ 里面什么都没有，而 {ε} 是一个含有空串的集合，二者在集合运算中的行为完全不同。

集合的方幂：A0 = {ε}，A1 = A，A2 = AA，依此类推。例如 A = {a, b}，则 A2 = {aa, ab, ba, bb}。

2.5 正闭包与星闭包

方幂只能表示固定次数。要表达“任意次数”乃至无穷多种情况，需要闭包。

正闭包 A+

A+ = A1 ∪ A2 ∪ A3 …

至少出现一次，由 A 中元素组成的任意长度串。

星闭包 A*

A* = A0 ∪ A1 ∪ A2 …

又称自反闭包、Kleene 闭包，即 A* = A0 ∪ A+，多包含一个空串。

例：A = {ab, cd}，则 A+ = {ab, cd, abab, abcd, cdab, cdcd, …}，而 A* 比 A+ 仅多一个 ε。

03

正则表达式

REGULAR EXPRESSION

正则表达式是符号串的描述工具，它所表示的符号串集合称为正则集（正规集），记为 L(r)。

3.1 正则表达式与正则集的递归定义

设 ∑ 为字母表，∑ 上的正则表达式和正则集递归定义如下：

  1. ε 和 ∅ 是 ∑ 上的正则表达式，所表示的正则集分别为 {ε} 和 ∅；
  2. 对任何 a ∈ ∑，a 是正则表达式，所表示的正则集为 {a}；
  3. 若 r、s 都是正则表达式，正则集分别为 R、S，则 (r)、r|s、r·s、r*、r+ 也是正则表达式，正则集分别为 R、R∪S、RS、R*、R+；
  4. 有限次使用上述规则构成的表达式，才是 ∑ 上的正则表达式。
为什么要规定 ε 和 ∅
它们是为了保证运算的封闭性而引入的两个特殊符号，让任何正则运算的结果仍然是合法的正则表达式。

3.2 运算符优先级与结合性

优先级：( ) 最高　→　*　→　·　→　|　最低　　结合性：左结合

例：∑ = {a, b}，则 a|b 表示 {a, b}，a·b 表示 {ab}，a* 表示 {ε, a, aa, aaa, …}。

正则表达式 r正则集 L(r)
(a|b)(a|b){aa, ab, ba, bb}
ab*{a, ab, abb, …} = {abn | n ≥ 0}
a(a|b)+{a(a|b)n | n ≥ 1}

3.3 等价与性质

若两个正则表达式的正则集相等，即 L(r) = L(s)，则称 r 和 s 等价，记作 r = s。例如 a*a = aa*，b(ab)* = (ba)*b。

  1. 交换律：A | B = B | A
  2. 结合律：A | (B | C) = (A | B) | C；A(BC) = (AB)C
  3. 分配律：A(B | C) = AB | AC；(A | B)C = AC | BC
  4. 同一律：Aε = εA = A
  5. 幂等律：A** = A*

利用这些性质，可以对正则表达式进行等价变换和化简。

3.4 经典构造例题

例 1：值为 2 的倍数的二进制数（∑ = {0,1}）

思路是“宽泛 → 严格”逐步缩小范围。所有串为 (1|0)*；二进制数表示为 1(1|0)* | 0；能被 2 整除的数末位必为 0：

1(1|0)*0 | 0

例 2：包含偶数个 x 的串（∑ = {x,y,z}）

0 个 x 时基本元是 (y|z)；含 x 则至少两个，基本元为 (y|z)*x(y|z)*x；整体可重复若干次：

((y|z)*x(y|z)*x)*(y|z)*

例 3：不包含连续两个 y 的串

有一个 y 就必须跟一个 x 或 z，基本元为 x | z | yx | yz；末尾还可单独留一个 y 或空：

(x | z | yx | yz)*(y | ε)

练习

  • 长度为偶数的串：((0|1)(0|1))*，不能写成 (0|1)*，后者长度不限。
  • 以 1 结尾且不含子串 00：(01|1)+。写成 (01|1)* 会包含 ε，写成 (01|1)*1 会漏掉 01 的情况。

3.5 用正则表达式描述单词

设 L 表示所有字母，D 表示所有数字，各类单词的正则描述如下：

单词类型正则表达式
标识符L(L|D)*，其中 L = A|B|…|a|b|…|z，D = 0|1|…|9
整数(+|-|ε)(D1D*) | 0，其中 D1 = 1|2|…|9
实数(+|-|ε)(D1D* | 0).D*
保留字while | if | for | …
运算符+ | - | * | …
分界符{ | } | ; | [ | ] | ( | ) | …
控制符\t | \0 | \n …

特殊符号数量有限，用枚举方式表示即可。

3.6 正则表达式的局限性与应用

两个局限

  • 不能描述配对结构：如 {α c α}，无法保证两边的 α 是同一个串。
  • 不能描述嵌套结构：如算术表达式的嵌套。

典型应用

  • 文本的查找、替换；
  • 号码地区识别软件；
  • 软件安全检测；
  • 程序分析；网络爬虫。
04

确定有限自动机 DFA

DETERMINISTIC FA

正则表达式抽象、精确，但从实现角度看不易直接落地。有限自动机是另一种单词描述工具，它更接近程序，也更便于实现。

4.1 DFA 的五元组定义

M = ( S , ∑ , f , S0 , Z )
  • S：有穷状态集，每个元素称为一个状态；
  • ∑：有穷字母表，每个元素称为一个输入字符；
  • f：状态转换函数 S × ∑ → S，是单值函数。f(Si, a) = Sk 表示当前状态 Si 遇到字符 a 时，唯一地转换到后继状态 Sk；
  • S0 ∈ S：唯一的初始状态；
  • Z ⊆ S：终止状态集（可接受状态集），Z 可以为空。
“确定性”的三个体现
  • 初始状态唯一；
  • 转换函数 f 是单值函数，对任何状态和符号，至多确定一个后继状态；
  • 转换边上不能标 ε，即不允许没有任何输入就进行状态转换。

“有限性”则体现在：定义在有限状态集和有穷字母表上。

4.2 表示方法一：状态转换矩阵

用状态作行标、∑ 中的字符作列标，矩阵元素表示转换函数。约定第一行表示开始状态，或在右上角标“+”；标“*”或“-”的状态为终止状态；空白部分表示函数无定义，即非法转换。

状态ab

用有向图表示自动机：结点表示状态，非终止状态用单圆圈、终止状态用双圆圈，开始状态由一个箭头指向；有向边表示转换函数，f(Si, a) = Sk 就从 Si 画一条标 a 的边到 Sk。

05

DFA 接受的语言

LANGUAGE L(M)

5.1 接受串的定义

对 ∑* 中的任何字符串 α，若存在一条从初始结点到某一终止结点的路径，且这条路上所有弧的标记符连接成的字符串等于 α，则称 α 可被 DFA M 接受（识别）。M 所能接受的全部字符串，称为它识别的语言，记为 L(M)。

关键理解：终态不是“进入即停”
识别过程并不是进入终止状态就终止，而是当自动机处理完整个输入串时，恰好停留在终止状态，才接受这个串。因此“接受状态”比“结束状态”更准确——终止状态上仍可以继续发生转换。

特别地，若初始状态同时又是终止状态，则空字符串 ε 可被接受。

自动机接受的语言
L(M1){ε, b, bb, bbb, …} = {bn | n ≥ 0}
L(M2){a, ab, abb, …} = {abn | n ≥ 0}
L(M3){aba, abaa, abab, …} = {aba(a|b)n | n ≥ 0}

5.2 应用实例：描述离散状态系统

DFA 能描述任何“有限状态、靠事件驱动切换”的系统。课件举了咖啡机的例子：待机、待选择、冲调、待取、金额不足等状态，靠投币、选择、金额充足、超时、退款等事件相互转换。

例：能被 3 整除的合法二进制数（不含先导 0）

一个二进制数模 3 的余数只有 0、1、2 三种，因此设三个状态分别表示余数。二进制左移一位相当于乘 2，末位再加 0 或 1，于是：

新余数 = (旧余数 × 2 + 新位) mod 3

从余数 0 状态出发、处理完输入后回到余数 0 状态，就说明该数能被 3 整除。

5.3 用 DFA 描述单词

用 L 表示字母、D 表示数字，可以分别画出标识符、无符号整数、带符号整数、实数、特殊符号的自动机。它们的思路完全一致：

  • 标识符：初态读到字母进入状态 1，之后读到字母或数字都停在状态 1（终态）。
  • 整数：初态读到非零数字 D1 后进入循环读数字的状态；单独的 0 也可直接到终态。
  • 实数：在整数路径上读到小数点 “.” 后，再进入读小数位数字的状态。
  • 特殊符号：如 {、+、EOF 等，靠枚举从初态直接转到对应终态。
如何区分单词类型
实际词法分析程序把这些小自动机的初始状态合并成一个大自动机。停在不同终止状态上，就反映识别出不同类型的单词；是否可接受看是否到达终态，是哪类单词看停在哪个终态。
06

DFA 的实现

IMPLEMENTATION

自动机的实现，就是用程序完成自动机的功能：对任意输入串，判断它能否被接受。抽象机器由输入带、读头、有限状态控制器组成。初态时读头指向输入带最左单元，每读一个字符就进入下一状态；读完全部字符后，若停在终态则接受，否则报错。

6.1 直接转向法（基于状态转换图）

这是程序中心法：把自动机看成流程图，每个状态对应一个带标号的条件语句，转向边对应 goto 语句。

Li: switch ( CurrentChar ) { case 'a': NextChar(); goto Lj; case 'b': NextChar(); goto Lk; default : Error(); } // 非终止状态的 switch Li: switch ( CurrentChar ) { case 'a' : NextChar(); goto Lj; case 'b' : NextChar(); goto Lk; case 'EOF': Accept(); default : Error(); } // 终止状态的 switch：多了 EOF → Accept

6.2 状态转换矩阵法（基于矩阵）

这是数据中心法：把自动机看成一种数据结构（二维数组），由一个统一的控制程序驱动字符在表上运行。

  1. 当前状态 State 置为初始状态；
  2. 读一个字符 CurrentChar；
  3. 若 CurrentChar ≠ EOF 且 T(State, CurrentChar) ≠ error，则 State = T(State, CurrentChar)，读下一字符，重复本步；
  4. 若当前字符为 EOF 且当前状态属于终止状态，则接受；否则报错。

6.3 两种方法对比

对比项直接转向法状态转换矩阵法
中心程序中心（流程图）数据中心（数据结构）
优点占存储空间少程序短，不同 DFA 主体相同，只换矩阵表
不足程序较长，换自动机需全部重写需存储转换矩阵，占存储多
适用状态数较少的情形通用，换机只换表
共同前提
两种方法的基础都是 DFA 转换的确定性。如果某状态遇到给定字符可能到达不同状态（即 NFA 的情形），就无法直接用这两种方法实现，必须先确定化。
07

非确定有限自动机 NFA

NON-DETERMINISTIC FA

有时用 DFA 描述问题并不方便：某些情况下转换函数不是单值，或需要多个起点、空边。于是引入非确定有限自动机。

7.1 NFA 的五元组

NFA = ( S , ∑ , f , S0 , Z )
  • f：从 S × (∑ ∪ {ε}) 到 S 的子集的映射，即 S × (∑ ∪ {ε}) → 2S，一次转换可能到达一个状态集合；
  • S0 ⊆ S：是初始状态集，可以有多个初始状态；
  • Z ⊆ S：终止状态集。

与 DFA 的三点区别

  • 一个状态遇相同符号可转向多个状态，f 不再单值；
  • 允许有多个初始状态；
  • 允许有 ε 边。

接受的语言

定义与 DFA 相同：从任意初态到任意终态所接受的串集合。但同一串往往有多条路径，都要测试，因此实现比 DFA 困难。

7.2 ε 边让描述更简洁

课件用一个带 ε 边的 NFA 描述所有整数（无符号和有符号），比 DFA 更直观易懂：起点先经可选的正负号，再汇入读数字的主干。

NFA 怎么实现
方法是转换成等价的 DFA。下一节先给出“自动机等价”的结论，再讲确定化算法。
08

NFA 到 DFA 确定化

DETERMINIZATION

8.1 自动机等价

设 A1、A2 是同一字母表上的自动机，若 L(A1) = L(A2)，则称它们等价。定理：对于每一个非确定自动机 A，都存在一个确定自动机 A'，使 L(A) = L(A')。下面给出的确定化算法，就是这个定理的构造性方法。

8.2 两个关键运算

（1）状态集 I 的 ε 闭包 ε_CLOSURE(I)

  • 若 q ∈ I，则 q ∈ ε_CLOSURE(I)；
  • 若 q ∈ I，那么从 q 出发经任意条 ε 弧能到达的任何状态 q'，也都属于 ε_CLOSURE(I)。

例：ε_CLOSURE({1}) = {1, 2}；ε_CLOSURE({1, 5}) = {1, 5, 2, 6}。

（2）状态集 I 的 a 转换

若 I = {S1, …, Sm}，a ∈ ∑，则定义 Ia = ε_CLOSURE(J)，其中 J = f(S1, a) ∪ … ∪ f(Sm, a)。即先把 I 中各状态经 a 边能到的状态全部并起来，再求它们的 ε 闭包。

8.3 确定化算法

  1. 令 I0 = ε_CLOSURE(S0) 作为 DFA 的初始状态；
  2. 若每个状态都处理过则转步骤 3；否则任选一个未处理状态 Si，对每个 a ∈ ∑：计算 Sj = Ia；若 Sj ≠ ∅，则令 f(Si, a) = Sj，若 Sj 还不是 DFA 状态就把它加为新状态；重复本步；
  3. 若某个 DFA 状态中包含 NFA 的任一终止状态，就把它定为 DFA 的终止状态。
核心思想
把 NFA 的“一个状态集合”整体看成 DFA 的“一个状态”。由于 NFA 状态数有限，其所有子集也有限，所以构造过程一定会在某个时刻收敛、不再产生新状态。

09

DFA 最小化

MINIMIZATION

9.1 为什么要化简

同一个语言可以对应多个 DFA，它们的复杂程度差别很大。DFA 的化简，就是找到一个状态数最少的 DFA M'，使 L(M') = L(M)。状态数直接影响两种实现方法的开销，所以越少越好。

9.2 三类关键状态

（1）等价状态与可区分状态

对两个状态 q1、q2，如果从它们出发，对任意输入串 x，总是同时到达接受状态或拒绝状态，则称 q1、q2 等价；否则称它们可区分。显然，终止状态和非终止状态一定可区分。

（2）无关状态

若从初始状态开始没有到达状态 S 的路径，或从 S 开始没有到达终止状态的路径，则 S 是无关状态。这类状态可直接删除。

（3）最小自动机

如果一个 DFA 既没有无关状态，也没有等价状态，就称为最小自动机。任一 DFA 都可以化为最简自动机。

9.3 状态分离法

判断两个状态等价很难（要穷举所有串），但判断它们不等价相对容易。状态分离法的思路是：先把肯定不等价的终态与非终态分开，再不断把转换到不同组的状态拆开，直到每组都不能再分。

目标：SS = SS1 ∪ SS2 ∪ … ∪ SSn，各组互不相交，且每组内状态全部等价

算法三步：

  1. STEP 1 求初始划分：SS = 非终止状态集 ∪ 终止状态集；
  2. STEP 2 若每个子集对每个字符 a 都不可区分则转 STEP 3；否则对可分的子集按相应字符划分，重复 STEP 2；
  3. STEP 3 每个子集合并为一个状态，含初态的集合为初态，含任一终态的集合为终态，对边作相应调整。

正则与自动机互转

EQUIVALENCE

正则表达式和有限自动机是等价的两种描述工具，可以互相转换。

10.1 正则表达式 → 自动机（Thompson 构造）

定理 1：对 ∑ 上每个正则表达式 R，都存在一个 NFA M，使 L(M) = L(R)。

构造方法：

  1. STEP 1：先构造 NFA 的初始状态 S 和终止状态 Z，由 S 发出一条指向 Z 的弧，标记整个正则表达式 R；
  2. STEP 2：反复利用替换规则对 R 分解，直到所有弧上标记的都是 ∑ 中的单个元素或 ε 为止。
  • 连接 ab：状态 1 经 a 到中间状态，再经 b 到状态 2，两段串接；
  • 并 a|b：引入上下两条并行路径，分别标 a、b，两端用 ε 边汇合；
  • 闭包 b*：新增状态，用 ε 边构成回路，允许重复零次或多次。

课件例：为 (a|b)*aa 构造等价 NFA，先拆成 (a|b)* 与 aa 的连接，再分别把闭包和并展开，最终所有边都只剩单个字符或 ε。

a* 的 ε 边何时不能省
当 a* 是独立的正则表达式时，转换中的 ε 边可以省略；但当 a* 并非独立、要与其他部分连接时（如 ab|d*），ε 边不可省，否则会让本来不该接的字符错误地接上。这些 ε 边最后可通过确定化算法消除。

10.2 自动机 → 正则表达式（状态消解法）

定理 2：对 ∑ 上每个 NFA M，都存在正则表达式 R，使 L(R) = L(M)。M 也可以是 DFA，因为 DFA 是 NFA 的特例。

  1. STEP 1：在状态图中加入唯一的开始节点 S 和终止节点 Z，从 S 用 ε 弧连到所有初始状态，从所有终止状态用 ε 弧连到 Z；
  2. STEP 2：反复用替换规则消解中间状态，直到只剩 S 和 Z，S 指向 Z 的弧上标记的表达式就是答案。

课件例：对一个含 6 个状态的 NFA，逐步消解中间节点，最终得到正则表达式 a(ab|ba)a*b。

10.3 综合例：求最简 DFA

课件给出与正则表达式 (a|b)(c|d)*(e|f) 等价的最简 DFA，完整走一遍“正则 → NFA → 确定化 → 最小化”的链条：

  1. 先用 Thompson 法构造 NFA；
  2. 确定化得到含 A、B、C、D 四个状态的 DFA；
  3. 最小化时先划分 {A,B,C} 与 {D}，再把 {A,B,C} 拆成 {A} 与 {B,C}，最终得到 3 个状态的最简 DFA。
11

词法分析器设计

SCANNER DESIGN

掌握了两个工具和三个转换算法，最终目标是设计一个真正可用的词法分析器。设计步骤共六步：

  1. 确定手工编写还是自动生成词法分析程序；
  2. 确定词法分析器与语法分析器的接口；
  3. 确定单词的种别；
  4. 确定 Token 的结构；
  5. 给出单词的描述；
  6. 设计算法。

11.1 与语法分析器的两种接口

作为独立的一遍

词法分析的输出放在一个中间文件中，语法分析再从该文件读取 Token。简化编译器设计、使语法逻辑更清晰，也便于单独优化读写效率。

作为语法分析的子程序

每当语法分析需要单词时，就调用词法分析程序输出一个 Token。省去中间文件和取送符号的工作，大多数编译器都采用这种方式。

11.2 确定单词种别

不同语言的单词种类和构成略有差别，需要考虑关键字是否保留。单词类型的划分基于语义而非构成，整体分为四大类：

大类子类 / 说明例子
保留字语言预先定义if / while / for / do
标识符用户命名x / y / area / age
常量各种字面量10 / 1.0 / 'a' / true
特殊符号运算符、界限符、格式符+ / ( / ; / 空格 / TAB

11.3 Token 结构与四张表

各类单词的种别与内容可以这样设计：

  • 保留字：一个保留字作为一类，类别即代表内容，如 (if,-)；或所有保留字作一类、用内容区分，如 (rev,if)。
  • 标识符：所有标识符作一类，用内容区分，如 (id,x)、(id,y2)。
  • 常量：所有常量作一类，或按类型分类，如 (intC,1000)、(realC,3.14)。
  • 运算符 / 界限符：每个作为一类，如 (plus-op,-)、(comma,-)。

课件给出一种可行方案：事先建好保留字表、特殊符号表，随词法分析进行建立标识符索引表、常量索引表。标识符种别填 1、常量种别填 2，内容填其在索引表中的位置；保留字和特殊符号的种别填对应数字，内容填空。

11.6 实现时应注意的问题

  • 保留字的识别：可建保留字表，或在自动机上区分；
  • 复合单词的识别：如 >= 拆开仍是单词，需读后续字符判断；
  • 数的转换：识别出的是字符而不是数，要明确这个概念并做转换；
  • 向前看若干字符：如正负号需结合上下文判断；
  • 格式字符的处理：对执行无意义，但对调试很重要；
  • 注释的处理：词法分析时直接忽略；
  • 其他：C 语言的宏替换、#include 等预处理。
