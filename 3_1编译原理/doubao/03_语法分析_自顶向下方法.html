01

语法分析概述

OVERVIEW

词法分析器把字符串形式的源程序识别为 Token 序列，这些 Token 就是上下文无关文法中的终极符。语法分析器把 Token 序列作为输入，按文法规则从中识别出各类语法成分（非终极符），同时进行语法错误检查，为语义分析和代码生成做准备。

1.1 常见的语法错误

程序中的错误分为词法错误、语法错误、语义错误三类。常见语法错误有：

  • 开始/后继单词错：表达式或语句的开头单词不对，或后继单词不对（如该出现 )、+、;、} 的位置出错）；
  • 标识符和常量错：如结构体域名不是标识符，switch 的分量不是允许的常量；
  • 括号类错误：( )、[ ]、{ }、if-else 不配对；
  • 分隔符错：赋值语句左部后面不是赋值号，标识符表的分隔符错。

1.2 错误恢复策略

发现错误后应适当恢复，以便继续分析、让错误不断被指出；恢复不当会产生大量伪错误，甚至引入语义伪错误。

  1. 紧急方式恢复：每次跳过一个输入记号，直到遇到某个同步记号（如 ; 、]）；
  2. 短语级恢复：对剩余输入做局部纠正，用能使分析继续的串代替前缀，如用 ; 代替、删除多余 ;、插入遗漏的 ;；
  3. 出错产生式：扩充文法，增加产生出错结构的产生式；
  4. 全局纠正：寻找代价最小的修正算法，尚处于理论研究阶段。
02

文法

GRAMMAR

文法 Grammar是程序语言的生成系统。用文法可以精确定义一个语言，并依据文法构造出识别该语言的自动机。

2.1 文法的四元组

G = ( VN , VT , S , P )
  • VN：非空有限集合，元素称非终极符（非终极符、中间符），一般用大写字母表示。它是一个语法范畴，表示一类具有某种性质的符号。符号集 V = VN ∪ VT，且 VN ∩ VT = ∅；
  • VT：非空有限集合，元素称终极符，一般用小写字母表示，是语言不可再分的基本符号——每个 Token 就是一个终极符；
  • S：特殊的非终极符，称开始符号，S ∈ VN；
  • P：产生式的有限集合。产生式也称产生规则，是按一定格式书写、定义语法范畴的文法规则。

2.2 产生式与候选式

产生式形式为 α → β 或 α ::= β。α 称左部（α ∈ V+，且至少含一个非终极符），β 称右部（β ∈ V*）。箭头读作“定义为”或“由…组成”。本章只讨论上下文无关文法，限定产生式左部只能是一个非终极符。

当同一非终极符 A 对应多条产生式 A → α1、A → α2、…、A → αn 时，可合并写成 A → α1 | α2 | … | αn，其中每个 αi 称 A 的一个候选式。开始符号必须至少在某产生式左部出现一次；默认第一条产生式左部为开始符。

2.3 文法的简写

不必显式给出 VN、VT、S：只在产生式右部出现的符号一定是终极符，只在左部出现的一定是非终极符，第一条产生式左部即开始符。因此文法可只保留产生式集合，例如：

文法 G： S → aAd | abcd | aSd A → bAc | bc
03

文法的分类

CHOMSKY HIERARCHY

1956 年语言学家乔姆斯基把文法分为四类，从 0 型到 3 型产生式限制越来越严、描述能力越来越弱、处理越来越简单。

类型名称产生式形式识别自动机
0 型短语文法 PSGα→β，α、β ∈ V*，α 至少含一个非终极符图灵机
1 型上下文有关 CSGαAβ→αγβ，γ ∈ V+；或 |α| ≤ |β|线性有界自动机
2 型上下文无关 CFGA→γ，左部是一个非终极符下推自动机
3 型正则文法 RGA→a 或 A→aB（右线性）/ A→Ba（左线性）有限自动机
编译中的分工
用 3 型（正则文法）描述语言的词法部分，用 2 型（上下文无关文法）描述语法结构，如算术表达式、各种语句。后续“文法”一词如无特殊说明，均指上下文无关文法 CFG。

典型例子

  • 文法 S → aSb | ab 是 2 型，L(G) = {anbn | n ≥ 1}；
  • 文法 S → 0S | 0 是 3 型，L(G) = {0n | n ≥ 1}。
04

推导与归约

DERIVATION

4.1 直接推导与直接归约

若文法 G 中有产生式 A → δ，且 α、β ∈ V*，则称 αAβ 可直接推导出 αδβ，记作 αAβ ⇒ αδβ。其逆过程 αδβ ⇒ αAβ 称直接归约。注意 ⇒ 是推导符号，→ 是产生式定义符，二者含义不同。

如果存在直接推导序列 α1 ⇒ α2 ⇒ … ⇒ αn，则称 α1 推导出 αn，记为 α1 ⇒+ αn（一步或多步）；若允许零步（含相等），记为 α1 ⇒* αn。每一步只能替换一个非终极符。

文法 E → E+E | E*E | (E) | i i+i*i 的一种推导： E ⇒ E*E ⇒ E+E*E ⇒ i+E*E ⇒ i+i*E ⇒ i+i*i

4.2 句型、句子与语言

  • 句型：若 S ⇒* β 且 β ∈ (VN ∪ VT)*，则 β 是句型，开始符 S 本身也是句型；
  • 句子：只含终极符的句型，即 S ⇒* β 且 β ∈ VT*；
  • 语言：L(G) = { u | S ⇒+ u 且 u ∈ VT* }，即文法 G 所有句子的集合。

4.3 最左推导与最右推导

为使推导过程确定，规定每一步替换的非终极符：

  • 最左推导 ⇒lm：每步替换最左非终极符，得到左句型；
  • 最右推导 ⇒rm：每步替换最右非终极符，得到右句型，又称规范推导；其逆过程称规范归约（最左归约）。
与分析方法的对应
每个句子都存在最左推导和最右推导（句型不一定）。自顶向下分析对应最左推导，自底向上分析对应最左归约（规范归约）。语法分析的实质，就是判定程序是否是文法的一个句子。
05

短语、简单短语与句柄

PHRASE & HANDLE

5.1 三个概念

  • 短语：若 S ⇒* αAδ 且 A ⇒+ β，则称 β 是句型 αβδ 关于非终极符 A 的短语；
  • 简单短语（直接短语）：若 A ⇒ β，即 β 由一次规则直接导出，则 β 是简单短语；
  • 句柄：一个句型中最左的简单短语。
易错点
一个句型的简单短语可能有多个，但无二义时句柄唯一。例如 id*id 是 id+id*id 的短语，但它不是简单短语——因为它不是一次规则直接导出的。

5.2 完整例子

文法 S → cAdBf、A → ab | a、B → e | eB，句型 cabdef：

概念结果
简单短语e、ab（均由一条规则直接导出）
句柄ab（最左的简单短语）

再如句型 (T+i)*F+i，简单短语为 T、两个 i，句柄为 T。

06

语法树

PARSE TREE

线性推导依赖具体推导过程、不直观。语法树以图形化方式把句子分解成各个组成部分，与符号的先后推导顺序无关，涵盖了一个句型的所有可能推导。

6.1 语法树的定义

满足下列条件的树为文法 G 的一棵语法树：

  • 每个结点用一个终极符或非终极符标记；
  • 根结点标开始符 S；
  • 非叶结点一定标非终极符；若 A 从左到右有子结点 B1…Bn，则 A → B1…Bn 必是产生式；
  • 标 ε 的结点必为叶结点，且是其父结点唯一子结点。

构造时以 S 为根，非终极符被替换时产生下一代结点，候选式每个符号产生一个新结点。生长中任意时刻，叶结点自左至右的排列都是一个句型。

6.2 语法树与语法概念的对应

子树是某结点连同所有后代；简单子树是只有单层分支的子树。对应关系：

树的部分对应的语法概念
所有叶结点连接句型
子树的叶结点连接短语
简单子树的叶结点简单短语
最左简单子树的叶结点句柄
句型 i+i 的语法树（E→E+T，T→F，F→i）

给定文法和串，最实用的办法是画出语法树：能画出来就说明是句型，每棵子树叶子对应短语，单层的对应简单短语，最左的对应句柄。例如句型 (T+i)*i+F 有 8 个短语、4 个简单短语（T、两个 i、F），句柄为 T。

07

二义性文法

AMBIGUITY

若至少存在一个句子有两棵或两棵以上不同语法树，则该句子是二义性的；包含二义性句子的文法称二义性文法。句子指终极符串，所以举例时必须用句子，不能用含非终极符的句型。

7.1 表达式二义

文法 E → i | E+E | E*E 对句子 i+i*i 有两棵不同语法树：

解释一：先算 +

E ├─E (i) ├─+ └─E ├─E (i) ├─* └─E (i)

体现不出运算优先级，(i+i)*i 式的结合。

解释二：先算 *

E ├─E │ ├─E (i) │ ├─+ │ └─E │ ├─E(i) │ ├─* │ └─E(i) └─（顶层为 *）

体现 * 优先于 +，i+(i*i)。

7.2 if 语句二义

文法 Stm → if Exp then Stm else Stm | if Exp then Stm，对句子 if e1 then if e2 then s1 else s2，else 可与外层 then 配对，也可与内层 then 配对，形成两棵树（悬空 else）。

7.3 二义的判定与利用

目前不存在一般性方法判断文法是否二义。经验上，S → SS | a 能推出 SSS、S → S+S 能推出 S+S+S，必有二义。

二义性的利用
消除二义会使文法符号数和复杂度迅速升高。可以保留二义文法、针对具体问题加入语义规则：规定运算优先级与左结合；规定 else 与离它最近的 then 匹配（如需改变则用 begin/end 类似花括号界定）。这样既利用了二义文法状态少、分析快的优点，又使语义确定。
08

文法等价变换

EQUIVALENT TRANSFORM

四类等价变换：提取左公共前缀、消除直接左递归、消除间接左递归、增加拓广产生式。

8.1 提取左公共前缀

同一非终极符几条产生式右部有相同前缀，自顶向下就无法选规则。把公共前缀 α 提出：

变换前：A → αβ1 | αβ2 | … | αβn | γ1 | … 变换后：A → αA' | γ1 | … A' → β1 | β2 | … | βn

例：A → aB | aC | aD 变为 A → aA'，A' → B | C | D。

8.2 消除直接左递归

若有 E → Eα 形式，称直接左递归；自顶向下分析会陷入无限递归。简单情形 A → Aα | β 变换为：

A → βA' A' → αA' | ε

一般情形 A → Aα1 | … | Aαm | β1 | … | βn，变换为 A → (β1|…|βn)A'，A' → (α1|…|αm)A' | ε。

E → E+T | T  ⇒  E → TE'，E' → +TE' | ε T → T*F | F  ⇒  T → FT'，T' → *FT' | ε F → (E) | i（保持不变）

8.3 消除间接左递归

例：S → Qc | c，Q → Rb | b，R → Sa | a，其中 S、Q、R 都是左递归。步骤：

  1. 非终极符排序：S、Q、R（排序不同结果不同）；
  2. 按序替换，使每条产生式右部只能出现排在后面的符号，出现前面的就替换，把间接变直接再消除；
  3. 必要时消除无用产生式。
R → Sa | a，替换 S 得 R → Qca | ca | a 再替换 Q 得 R → Rbca | bca | ca | a 消除直接左递归： R → (bca | ca | a) R' R' → bcaR' | ε

8.4 增加拓广产生式

LR 类分析要求开始符唯一且不出现在任何产生式右部。若不满足，加一条 Z → S，Z 为新开始符，语言不变。

09

自顶向下分析与回溯

TOP-DOWN & BACKTRACK

自顶向下分析从文法开始符出发，试图为输入串建立最左推导（或构造语法树）。

生活类比
像走迷宫：站在入口（开始符），遇到岔路（多个候选式）先选一条走，走不通就退回岔路口换下一条——这就是回溯。区别在于：聪明的走法会在路口看一眼路标（输入符号），直接判断该走哪条，不必每条都试。

9.1 非确定的自顶向下

推导时随机选择产生式，匹配成功则继续，某步不成功则回溯，直到所有可能都尝试过。这是一种深度优先搜索，分析效率低。

Z → aBd，B → bB | c | d 判断 abd：先用 bB 替换 B，推出 abdd，失败； 回溯，改用 d 替换 B，推出 abd，成功。

“失败不一定是真失败”——只有把所有候选式都试过仍推不出，才能断定不是句子。

9.2 确定的自顶向下

利用输入流信息（通常看一个符号）确定性地选择产生式，避免回溯。确定方法包括 LL(1) 与递归下降。

文法条件：对 A 的任意两条不同产生式，Predict(A→α) ∩ Predict(A→β) = ∅

满足该条件，同一个输入符号至多对应一条候选式，选择唯一。为计算 Predict，需要先掌握 First、Follow 两个集合。

10

三个重要集合

FIRST / FOLLOW / PREDICT

10.1 定义

  • First(β)：β 经推导能出现在最前面的终极符集合，即 {a | β ⇒* a…}；若 β ⇒* ε 则还含 ε；
  • Follow(A)：句型中能紧跟在非终极符 A 后面的终极符，{a | S ⇒+ …Aa…}；若 A 可出现在末尾则含 #（# 是输入流结束标志）。Follow 只对非终极符定义；
  • Predict(A→β)：ε ∉ First(β) 时等于 First(β)；ε ∈ First(β) 时等于 (First(β) − {ε}) ∪ Follow(A)。

10.2 计算规则

First：终极符 X 的 First(X)={X}；非终极符收集各产生式首符，有 X→ε 则含 ε；若首符是可空非终极符，则递归向后传递，直到遇到不可空符号。

Follow：开始符 Follow(S)={#}，其余初始为空；对产生式 A→xBy：若 ε ∈ First(y)，则把 (First(y)−{ε}) ∪ Follow(A) 加入 Follow(B)，否则加入 First(y)；反复迭代直到收敛。

10.3 表达式文法完整实例

文法 E → TE'，E' → +TE' | ε，T → FT'，T' → *FT' | ε，F → id | (E)。

符号FirstFollow
E{ id, ( }{ ), # }
E'{ +, ε }{ ), # }
T{ id, ( }{ +, ), # }
T'{ *, ε }{ +, ), # }
F{ id, ( }{ *, +, ), # }

同一非终极符各候选 Predict 两两不相交，故该文法是 LL(1) 文法。

11

LL(1) 分析

LL(1) PARSING

LL(1) 是确定的自顶向下方法，是 LL(k) 的特例：第一个 L 表示自左至右扫描输入，第二个 L 表示产生最左推导，括号 1 表示每步只看一个输入符号就能确定产生式。

11.1 分析器的组成

逻辑上由四部分组成：输入流（待分析符号串）、符号栈（存放分析过程中的文法符号）、LL(1) 分析表（表示文法全部信息的矩阵）、驱动程序。

四种动作：替换（栈顶非终极符，用规则右部逆序压栈替换）、匹配（栈顶终极符与输入首符相同则双双弹出）、成功（格局 #,#）、出错。

11.2 LL(1) 分析表

分析表 T：VN × VT → P ∪ {Error}。T(A,t) = A→α 当 t ∈ Predict(A→α)，否则 Error。对每条产生式，按其 Predict 中每个终极符填入该产生式，其余为 error（实际可填错误编号对应处理程序）。

i+*()#
E[1][1]
E'[2][3][3]
T[4][4]
T'[6][5][6][6]
F[7][8]

数字为产生式编号，空格处为 error。

11.3 驱动程序与分析过程

初始格局 (#S, a1…an#)。栈顶终极符匹配则弹出并读下一符；栈顶非终极符查表，命中则弹出并把右部逆序压栈，error 则报错；(#,#) 成功。

错误串如 i+i*+i，会在 LL(F,+) = Error 处报错（运算符后不能直接接运算符）。

12

递归下降法

RECURSIVE DESCENT

递归下降法采用分而治之：识别一个语法结构时，按产生式分成几部分，终极符直接识别，非终极符调用相应子程序。

12.1 基本原理

产生式 While_Stm → while Exp do Stm 对应子程序：

void While_Stm(){ Match(while); // 终极符匹配 Exp(); // 非终极符调用子程序 Match(do); Stm(); }

非终极符有多个候选式时，根据当前 token 属于哪个候选式的 Predict 集来选择分支，都不命中则 error。

12.2 程序构成与编写规则

  • 一个全局变量 token：记录输入流当前符号；
  • 每个非终极符一个函数，多候选式用 Predict 选择分支；
  • 一个主函数：先 ReadToken，再调用开始符函数，最后 Match('#') 验证是否到末尾；
  • 两个辅助函数：ReadToken() 读入下一符号；Match('a') 成功则 ReadToken，否则 error。

对 A → β1 | … | βn，函数 A 内依次判断 token 是否 ∈ Predict(A→βi)，命中则执行该候选式：非终极符调用其函数，终极符 Match，ε 写成空语句。

void E(){ if (token=='i' || token=='(') { T(); E'(); } else error(1); } void E'(){ if (token=='+') { Match('+'); T(); E'(); } else if (token==')' || token=='#') ; // E'→ε，空语句 else error(2); }

12.3 名字由来与优缺点

终极符产生匹配命令、非终极符产生调用命令，因文法递归、子程序也递归，故称递归下降。分析能力与 LL(1) 等同，对文法限制相同。

优点

构造简单，直接照文法写即可。

缺点

程序较长；频繁函数调用影响效率；文法改变时整个程序要随之改动，而 LL(1) 只需改分析表。
