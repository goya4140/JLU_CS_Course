语法分析 · 自底向上方法

自底向上分析从输入串出发，自左向右扫描，反复找到当前句型的句柄并归约，直到归约为开始符。LR 类方法用“带圆点的项目”构造识别活前缀的状态机，把“句柄在哪、用哪条产生式”变成查表动作；从 LR(0) 到 SLR、LR(1)、LALR，逐步利用输入信息、化解冲突。

01

自底向上的语法分析

SHIFT-REDUCE

基本思想（移入-归约分析）：从待分析符号串开始，自左向右扫描、自下而上分析，通过反复查找当前句型的句柄，并把找到的句柄归约为相应产生式左部的非终极符，直到把输入串归约为开始符。

生活类比
像拆毛衣：先把线头一个个挑到针上（移入），当针上凑成完整的一圈（句柄），就把这一圈收成一针（归约）；反复收针，整件毛衣最后收成一个线团（开始符）。

1.1 分析动作

  • 移入：把输入流的头符压入符号栈；
  • 归约：把符号栈栈顶的句柄，用某一非终极符替换；
  • 成功：归约到开始符；失败：无法继续。
核心问题
①如何判断符号栈栈顶出现了句柄？②替换时用哪个产生式？关键是确定句柄——不同找句柄的方法构成不同的自底向上方法：算符优先、简单优先、LR 类。

1.2 LR 类方法的基本思想

L 表示从左到右扫描输入串，R 表示分析过程是最右推导的逆过程（最左归约）。LR 分析法对文法限制很少，大多数能用 CFG 描述的程序语言都可有效分析，且能准确及时发现错误。包括 LR(0)、SLR(1)、LR(1)、LALR(1)。

02

规范活前缀与可归前缀

VIABLE PREFIX
  • 规范句型：用最右推导导出的句型，也称右句型；
  • 规范前缀：若存在规范句型 αβ，且 β 是终极符串或空串，则称 α 为规范前缀；
  • 规范活前缀（活前缀）：规范前缀 α 不含句柄，或含一个句柄且形式为 α'π（π 是句柄）；
  • 归约规范活前缀（可归前缀）：含句柄的活前缀，且句柄在最右端，即 α = α'π。

LR 分析过程就是不断判断符号栈内容是否为可归前缀：不是则移入一个符号再判断，是则对栈顶句柄归约，直至归约为开始符。

2.1 可归前缀的派生定理

  1. 开始符产生式的右部是可归前缀；
  2. 若 αAβ 是可归前缀，且 A→π 是产生式，则 απ 也是可归前缀；
  3. 任何可归前缀都可按上述方法派生。

例 4.3：文法 S→aAc[1]、A→dbb[2]、A→b[3]，可归前缀为 aAc、adbb、ab。

03

LR(0) 项目

LR(0) ITEM

LR(0) 项目是带一个圆点的产生式，每个项目标志分析时的某一状态。圆点像一个“进度条”，表示已经识别了产生式右部的多少。

产生式 S→aAc 对应四个项目：

S → •aAc  符号栈不含句柄任何部分
S → a•Ac  包含句柄中的 a
S → aA•c  包含句柄中的 aA
S → aAc•  包含完整句柄 aAc，可归约

3.1 项目的两种类型

  • 归约型项目：形如 A→π•，圆点在最右，已识别完整右部，应归约；
  • 移入型项目：形如 A→α•β，圆点后还有符号，应继续移入。
空产生式
空产生式 A→ε 对应的项目只有一个 A→•，且为归约型项目（右部为空，圆点已在末尾）。
04

项目集的闭包与 GO 函数

CLOSURE & GO

4.1 投影

项目集 IS 关于符号 X 的投影集：把圆点跨过 X 的项目挑出来。

IS(X) = { A→αX•β | A→α•Xβ ∈ IS }

例：IS 含 S→a•Ac、A→•dbb、A→•b，则 IS(A)={S→aA•c}，IS(d)={A→d•bb}，IS(b)={A→b•}。

4.2 闭包

圆点后面是非终极符时，意味着接下来要识别它，于是把它的所有产生式（圆点在最左）加入：

CLOSURE(IS) = IS ∪ { A→•π | Y→β•Aη ∈ CLOSURE(IS)，A→π 是产生式 }
CLOSURE({S→a•Ac}) = { S→a•Ac，A→•dbb，A→•b }

4.3 GO 函数

GO 表示读入一个符号 X 后到达的新项目集，即先投影再求闭包：

GO(IS, X) = CLOSURE(IS(X))
GO({S→•aAc}, a) = CLOSURE({S→a•Ac}) = { S→a•Ac，A→•dbb，A→•b }
05

LR(0) 状态机的构造

BUILD LRSM0

为使“成功”状态易于识别，LR 文法要求开始符唯一且不出现在产生式右部，因此先加拓广产生式 Z→S，Z 为新开始符。

5.1 构造步骤

  1. Step 1：构造初始状态 IS0 = CLOSURE({Z→•S})，标记 NO；
  2. Step 2：任选一个标 NO 的状态 IS，删除标记，对每个符号 X 令 ISj = CLOSURE(IS(X))；ISj 非空时，若已存在则画 X 边，若不存在则作为新状态并标 NO，同样画 X 边；
  3. 重复 Step 2，直到没有标 NO 的状态。

每个状态对应一个饱和项目集：一部分由先驱分出（基本项目），一部分由基本项目扩展（派生项目），派生项目的圆点在产生式右部最左侧。

LR(0) 分析方法与冲突

LR(0) TABLE

LR(0) 是 LR(k) 中 k=0 的情况：每一步仅根据当前符号栈的状态，无需向前看输入符号即可确定动作。真正的 LR 用状态栈（而非符号栈），分析表分 Action 和 Goto 两部分。

6.1 Action 与 Goto 表

  • Action（状态×终极符）：移入 S、归约 R、接受 Acc、出错；
  • Goto（状态×非终极符）：归约后转向的状态。

例：文法 S→aAd[1]、A→Bc[2]、B→b[3]，其 Action 表（归约型状态对所有终极符都填同一归约动作，因为不看输入）：

abcd#
0S1
1S2
2R3R3R3R3R3
3S5
4S6
5Acc
6R2R2R2R2R2

6.2 冲突与 LR(0) 文法

  • 归约/归约冲突：一个状态含两个或以上归约项目；
  • 移入/归约冲突：同时含移入项目和归约项目；

有冲突的状态称二义性状态；没有二义性状态的文法称 LR(0) 文法。

冲突根源
状态 T→F• 与 T→F•*T 共存：到底归约还是等 * 移入？LR(0) 完全不看输入流，无法判断。这正是它的局限——通过引入输入信息，发展出 SLR、LR(1)、LALR。
07

SLR(1) 方法

SIMPLE LR

SLR(1) 的状态机与 LR(0) 结构完全相同，区别只在归约时向前看一个符号，用 Follow 集化解冲突。

7.1 冲突如何解决

  • 移入-归约：状态含 A→α• 与 D→μ•dγ；当前输入符在 Follow(A) 中则归约，为 d 则移入；若 d 也在 Follow(A) 则无法解决；
  • 归约-归约：状态含 A→α•、B→β•；输入符在 Follow(A) 则按 A 归约，在 Follow(B) 则按 B 归约；同时属于两者则无法解决。
SLR(1) 条件：各归约项目的 Follow(A1)…Follow(An) 与移入符 {a1…am} 两两不相交

7.2 分析表构造

归约项目 A→α• 不再对所有列填归约，而只对 Follow(A) 中的终极符填 Rj；移入、Accept、Goto 规则同 LR(0)。

例：M→T、T→F、T→F*T、F→a，Follow(M)={#}、Follow(T)={#}、Follow(F)={*,#}：

a*#TF
0S213
1Acc
2R4R4
3S4R2
4S253
5R3

分析表单值、无冲突即 SLR(1) 文法。它比 LR(0) 强，因为用 Follow 集考虑了输入符。

08

SLR(1) 的分析过程与局限

SLR LIMITATION

8.1 分析过程

驱动方式与 LR(0) 相同：状态栈、符号栈、输入串。以 a*a*a 为例，关键格局：

0 # a*a*a# S2 02 #a *a*a# R4 → 3 03 #F *a*a# S4 034 #F* a*a# S2 ...（不断移入、归约）... 01 #T # Acc

8.2 SLR 的问题：不区分不同出现

文法 Z→B1aB2bB3c，B→d。B 在右部出现三次：B1 的后继只能是 a，B2 的后继只能是 b，B3 的后继只能是 c。但 Follow(B) = {a,b,c} 把三者混在一起，SLR 据此归约就失去了精度。

改进方向
一个非终极符在不同位置出现，允许的后继符不同。LR(1) 针对不同产生式上的非终极符分别定义后继符集（展望符），从而减少冲突。
09

LR(1) 方法

CANONICAL LR

LR(1) 对非终极符的每个不同出现求后继符，而不是给每个非终极符一个统一 Follow，这就是展望符集。

9.1 LR(1) 项目

项目是 LR(0) 项目加一个展望符的二元组 [A→α•β, a]，其中 a ∈ VT∪{#}。初始项 Z→•α 的展望符为 #。

投影：IS(X) = {[A→αX•β,a] | [A→α•Xβ,a] ∈ IS}。

闭包：CLOSURE(IS) = IS ∪ {[A→•β,a] | [B→α1•Aα2,b] ∈ CLOSURE，A→β 是产生式，a ∈ First(α2 b)}。新添项目的展望符由后面符号串求 First 得到（可空则用 b）。

GO：GO(IS,X) = CLOSURE(IS(X))。构造步骤与 LR(0) 相同，初始 IS0 = CLOSURE({[Z→•S,#]})。

9.2 分析表与 LR(1) 文法

  • 归约项 [A→α•, a]：只在展望符 a 列填 Rj；
  • 移入项 [A→α•aβ, b]：Action 填 S；Goto 同前；[Z→α•,#] 填 Acc。

例：Z→BB、B→aB、B→b，其分析表（注意状态数比 LR(0) 多）：

ab#B
0S6S41
1S5S32
2Acc
3R3
4R3R3
6S6S47
7R2

表中无冲突动作即 LR(1) 文法。它最精确，但状态数最多。

10

LALR(1) 方法

LOOK-AHEAD LR

LR(1) 最主要问题是状态太多，大语言难以在资源有限的机器上实现。LR(1) 状态机中有许多同心状态，LALR(1) 把它们合并以减少状态数。

10.1 心与同心状态

  • 项目的心：LR(1) 项目 [A→α•β,b] 中的 LR(0) 部分 A→α•β；
  • 状态心 Core(S)：状态所有项目心之和；
  • 同心状态：两个状态具有相同的心（仅展望符不同）。

构造时先建 LR(1) 状态机再合并同心状态，或边构造边合并。例文法中 4 和 9、5 和 11、6 和 12 等均为同心状态，合并后展望符取并集。

10.2 LALR 的定位

状态数

与 LR(0)、SLR 相同，远少于 LR(1)。

分析能力

介于 SLR(1) 与 LR(1) 之间，兼具状态少与适用广。

10.3 合并可能带来的冲突

合并同心状态时一定不会产生移入/归约冲突，但可能产生归约/归约冲突。例子文法 Z→aAd、Z→bAc、Z→aBc、Z→bBd、A→e、B→e：LR(1) 图中无冲突，但把对应同心状态合并后，A→e 与 B→e 的展望符发生交集，产生归约/归约冲突。

实际地位
实际中合并引发冲突的情况不多，而状态数大幅下降，因此 LALR(1) 是目前应用最广泛的 LR 方法。分析表、驱动程序与分析过程均与 LR(1) 相同。
11

LR 方法总结

SUMMARY
分析能力：LR(0) < SLR(1) < LALR(1) < LR(1)
状态数：LR(0) = SLR(1) = LALR(1) < LR(1)
移入-归约 反复找句柄归约，直到开始符；四动作。
可归前缀 句柄在最右端的活前缀，是归约信号。
LR(0) 项目 带圆点产生式；归约型/移入型。
闭包 GO 闭包补非终极符产生式，GO=投影再闭包。
LR(0) 不看输入，易冲突，理论意义。
SLR(1) 用 Follow 集看一个符号解冲突。
LR(1) 项目带展望符，最精确、状态最多。
LALR(1) 合并同心状态，应用最广。
