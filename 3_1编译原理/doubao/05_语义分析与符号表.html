语义分析与符号表

语法正确不代表有意义。语义分析在变量的声明与使用之间建立联系，检查重复声明、未声明和类型相容等问题；它把标识符和类型的属性组织成内部表示，用“层数+偏移”的抽象地址描述位置，并通过符号表与作用域管理，让每个名字在有效范围内可查、出了范围失效。

01

语义分析概述

OVERVIEW

词法管允许出现哪些字符和单词，语法管结构上合法的程序，语义则管结构合法的程序的意义。一个语法正确的程序不能保证有意义，常见语义错误有标识符未声明、重复声明、操作数类型与操作符不匹配等。

1.1 静态语义与动态语义

  • 静态语义：编译阶段可检查的语义，如未声明、重复声明、把变量当函数用；
  • 动态语义：运行时才能检查的语义，如除零溢出、数组下标越界。
边界
编译程序只能进行静态语义检查；动态语义错误要等目标程序运行时才暴露。

1.2 语义分析的主要任务

  1. 根据声明部分建立符号表。符号表是保存源程序各种信息的数据结构，每个条目含一个标识符的属性，可据此检查语义错误和分配地址；
  2. 在整个程序范围内检查常见语义错误，主要是与标识符声明和使用相关的错误。

1.3 语义分析的实现

  • 不独立成遍：一般语义检查与语法分析结合，遇声明查重复声明并填表，遇语句查未声明；类型检查可安排在中间代码生成时；
  • 独立成遍：以语法分析树和符号表为输入，判定是否有语义错误。无论哪种，都可用语法制导方法完成。

03

标识符在程序中的出现

OCCURRENCE
  • 声明性出现：变量声明、函数声明部分出现的标识符。如 int x;、int a[10]; 中的 x、a，int f(int m,int* n){...} 中的 f、m、n；
  • 使用性出现：表达式、语句部分出现的标识符。如 x=x+1; 中的 x，a[0]=x+f(a[2]); 中的 a、x、f。
生活类比
声明性出现像在前台登记名字，使用性出现像之后凭登记的名字办事。没登记就办事（未声明），或同一名字登记两次（重复声明），都会被拦下。

08

类型的语义表示

TYPE

类型语义信息有两个作用：类型的语义检查、确定分配空间的大小。约定 RealSize=2，IntSize、BoolSize、CharSize=1。

标准类型

含 Kind、Size：intTy/boolTy/charTy 大小 1，realTy 大小 2。

指针类型

pointTy，Size 为地址长度（一般 1），BaseType 指向所指类型。

8.1 数组类型

Size = (Up − Low + 1) × sizeof(ElemType)
  • Kind=ArrayTy；Low 下标下界（C 为 0），Up 上界；ElemType 指向成分类型；
  • 例 int A[10]：Low0、Up9、Size10；char B[5][10]：Low0、Up4、Size50，元素为 10 字符数组。

8.2 结构体与联合体

structTy/unionTy，RecBody 是域链表，每个域含 Name、Type、Off（相对结构体起始的偏移；联合体各域偏移相同可省）、link。

  • struct Date{year,month,day}：域偏移 0/1/2，Size 3；
  • union{ch,i,f}：各域共用同一偏移，Size 取最大者 2。

8.3 枚举类型

enumTy，ElemList 指向枚举常量表，每常量含 Name 和 Value（整数）。

  • enum color{red,yellow,blue}：值 0/1/2；
  • {red=10,yellow=red+2,blue}：值 10/12/13。
09

抽象地址

ABSTRACT ADDRESS

9.1 静态分配与动态分配

  • 静态分配：编译期就为所有数据对象分配固定地址，运行时不变；直观但不支持动态申请（指针、递归）；
  • 动态分配：编译期分配的是抽象地址而非真实地址，运行时再映射为物理地址。

9.2 过程活动记录 AR

每次函数被调用时分配的一片空间，存储顺序即处理先后顺序；运行时通过 AR 起始地址 sp + 偏移 offset 找到变量。

┌──────────────┐ 高地址 │ 临时变量区 │ ├──────────────┤ │ 局部变量区 │ ├──────────────┤ │ 形参区 │ ├──────────────┤ │ 管理信息 │ 固定大小（返回地址、寄存器现场） └──────────────┘ 低地址 sp

9.3 层数定义

  • 嵌套式（Pascal）：主程序 0 层，其直接定义的函数 1 层，L 层函数直接定义的为 L+1 层；
  • 并列式（C）：全局变量和所有函数为 0 层，函数中声明的变量为 1 层。

9.4 抽象地址结构与分配原则

抽象地址是二元组 (层数, 偏移)：层数帮助确定 AR 起始地址 sp，偏移是相对 AR 的相对偏移。

对象分配单元
值参按类型大小分
变参分 1 个单元（存地址）
过/函形参分 2 个单元（入口地址、Display 表信息）
局部变量按类型大小（int 1、float 2、char 1）
临时变量分 1 个单元（假设）

作用域与局部化单位

SCOPE

作用域是标识符有效的程序段，在作用域内标识符有效、可见。局部化单位是允许有声明的部分，通常是子程序或分程序；局部化单位可以嵌套，不能交叉。

嵌套作用域原则
标识符的作用域从声明位置开始，到所在局部化单位结束。若内层有与外层同名的标识符，外层标识符的作用域要把内层单位剔除——内层同名者“遮蔽”外层。

局部化处理的本质：在程序某点 P 处，对它有效的声明是包含 P 的嵌套局部化单位中的声明。因此编译器要在每点判断哪些表项有效。

10.1 局部化处理的基本思想

  1. 进入一个局部化单位，用 Scope 栈记住本层符号表起始地址；
  2. 遇声明性标识符，查本层符号表，有同名则报错，否则填入；
  3. 遇使用性标识符，从当前位置向前查整个符号表，查不到则报错；
  4. 结束一个局部化单位，“删除”本层符号表。
两个“层”别混淆
这里的层是局部化单位嵌套引起的 Scope 栈层次；抽象地址里的层数是函数定义层数，二者概念不同。
11

符号表管理

TABLE MANAGEMENT

符号表在编译各阶段都要用：语义分析时用于语义检查，中间代码生成时用于类型检查和强制转换，目标代码生成时作为地址分配依据。

组织符号表要解决三个问题：总体组织（单表/多表）、表项排列（线性表/散列表/有序表）、局部化（局部/全局）。

11.1 全局式与局部式

  • 全局式：整个程序一个符号表，建表查表单位是整个表，用 Scope 栈记录各层起始地址；
  • 局部式：每个局部化单位一张独立表，作为建表查表单位。

11.2 “删除”的两种实现

  • 真删除法：物理删除，退出时把本层表项从表中弹出，直到 Scope 栈顶指向位置；
  • 驻留法：保留表项但加标记，或在末尾加跳转项 (#,ptr)，ptr 指向本层第一个表项的前一项，从后向前访问时跳过失效区。
适用范围
删除法、驻留法之分基于全局表；局部表只有删除法。

11.4 C 与 Pascal 的比较

  • C（并列式）：函数并列，主程序/函数/分程序是局部化区；全局量和函数为 0 层，局部量为 1 层；分程序嵌套不影响层数；
  • Pascal（嵌套式）：过函嵌套，主程序/函数是局部化区；L 层函数中声明的标识符为 L+1 层，处理更复杂。
