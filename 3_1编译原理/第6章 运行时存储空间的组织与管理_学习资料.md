# 第6章 运行时存储空间的组织与管理：调用怎样取得空间并访问正确的变量

递归调用会让同一个局部变量声明同时对应多个对象。程序既要给每次调用独立空间，又要在使用外层名字时找到正确对象。本章先跟踪活动记录的建立与回收，再比较 Display 与静态链的寻址过程。

## 1. 运行时管理要解决什么问题


### 1.1 抽象位置与具体调用实例

编译时可确定 x 在函数记录内偏移 5，但递归调用会让同一声明对应多个实际对象。函数 f 的第 1 次调用 x 在地址 105，第 2 次调用可能在 117；一份函数代码要正确访问各自的 x。

**运行时存储管理**安排对象在哪里、存在多久，以及代码怎样从抽象地址找到当前应访问的对象。核心是“所属记录首地址＋偏移”，首地址随调用实例变化，偏移通常由编译确定。

### 1.2 决策依据是语言规则

课件列七项影响因素：是否递归；返回后局部值是否保留；是否访问非局部数据；参数如何传递；过函是否可作为结果；是否能动态申请；是否要求显式释放。

这些因素解释为什么不能给所有对象统一一种存储方式。递归参数适合随调用建立；返回后仍存在的对象不能随着当前栈帧一起消失；嵌套函数还需要正确保存词法环境。

## 2. 内存区域与三种分配策略

全局对象、递归局部对象和动态申请对象的生存规律不同，不能都分配到一套固定槽中。先区分逻辑存储区域，再看静态、栈和堆怎样满足这些需求。

### 2.1 课件划分的五个区域

| 区域 | 用途 | 时间与边界 |
| --- | --- | --- |
| 库代码区 | 标准库等被调用程序代码 | 需链接或运行环境支持 |
| 目标代码区 | 编译后的用户程序指令 | 代码布局经链接/装载进一步确定 |
| 静态区 | 全局、static 对象、需保留的常量等 | 布局可预定，生命周期通常长 |
| 栈区 | 当前未返回调用的活动记录 | 调用建立、返回回收 |
| 堆区 | 按运行需求申请的数据对象 | 生命周期不必与调用嵌套一致 |

图是逻辑模型，并非所有平台的实际连续地址布局。代码与只读数据的保护、共享库、虚拟地址、栈增长方向均由实现规定。#include 通常引入声明等源码内容，库函数机器代码通过链接/装载安排，不能说 #include 本身就把库机器码复制进代码区。

### 2.2 静态分配

**静态分配**在编译/链接等运行前阶段确定数据布局，执行中不随普通调用增减。完全采用这一路线要求对象长度和数量可预定，不允许需要多份并存记录的普通递归，也不能自由创建任意数量的动态对象。

课件 square 例：全局 sum、square 的参数 i/局部 j/临时 t1、main 的局部 j/临时 t2/t3，都可各放固定槽，因为示意程序不递归，square 调用不会重入。但例中的 n 未声明，必须补充合法输入或声明才能作为完整程序执行。

现代混合实现仍把全局和 static 对象放静态区。指针可以指向静态对象，指针本身也可以静态分配；课件“不能有指针”的表述应限于需要动态创建的对象，不是所有指针都强制堆分配。

### 2.3 栈式动态分配

**栈式分配**遵守后进先出：调用取得一帧，内部调用先返回，最后当前帧回收。递归每次取得独立 AR，因此参数与局部不会互相覆盖；不同时间的调用又可复用栈区空间。

课件采用每种函数帧大小静态确定的模型，这使 TOP 加 Size 即可分配。由此不支持其模型中未知大小的局部区域；但真实栈并非理论上绝不能支持变长数组或动态调整，只是须增加相应记录与回收机制。

普通自动局部在返回时失去有效存储，不能把它的地址当作长期有效结果。static 局部是例外，因为其对象放在静态区，局部作用域不等于栈生存期。

### 2.4 堆式动态分配

**堆式分配**支持申请与释放不必按嵌套顺序。例如先申请 A、再申请 B，也可以先释放 A而保留 B。分配器需记录空闲区域及对象大小，可能合并空闲块，因此通常比简单栈顶加减复杂。

`int* p` 的指针槽可在栈，malloc 得到的 int 对象在堆。离开函数只回收 p 槽，不自动推出其对象也已释放；对象如何释放按语言/运行时规则，显式 free 与垃圾回收是不同方案。

课件倡导满足正确性前提下尽量使用较简单的分配。不能为了减少堆成本，把需要逃出函数的对象移进会被回收的普通栈帧；生存规则优先于省时。

## 3. 符号与活动记录结构

栈式分配不仅要保存局部变量，还要记住返回到哪里、谁是调用者、参数和结果放在哪里。把一次调用所需信息组织成一帧，才能统一完成建立、访问和回收。

### 3.1 本章记号

SP 指当前活动记录的首地址，TOP 指下一空闲位置；以下示例栈向地址增大的方向生长。

| 记号 | 含义 |
| --- | --- |
| AR(Pi) | P 第 i 次活动的一帧 |
| SP、TOP | 当前帧首址、下一空闲地址 |
| Size、d | 帧大小、参数区开始前控制信息大小 |
| Mem[a] | 地址 a 的内容，而不是 a 本身 |
| Lv、L | 变量登记层数、所属过程层；Pascal 约定 L=Lv-1 |
| Off | 相对所属 AR 首地址的偏移 |
| DL、SL | 动态链、静态链指针 |
| RA | 返回地址，即调用后继续执行的位置 |
| Display[L] | 保存过程层 L 对应词法环境帧首址 |
| prefixN(E) | E 的前 N 项，下标 0…N-1 |
| E⊕AR(Q) | 在 E 后追加新帧 Q |
| Indir(SP,k) | 沿静态链走 k 次；零次就是 SP |

### 3.2 各字段的作用

| 区域/字段 | 作用 |
| --- | --- |
| 动态链指针 | 指向调用者帧，返回时恢复 SP |
| 返回地址 | 控制回到调用后的下一条指令 |
| 返回结果或结果地址 | 交付函数值，具体布局须约定 |
| 保存寄存器 | 调用可能破坏的现场 |
| 过程层数、帧大小 | 支持环境与栈位置管理 |
| 变量访问环境 | 定位词法外层数据 |
| 形参 | 保存传来的值、地址或过函信息 |
| 局部变量 | 当前这一次调用的局部数据 |
| 临时变量 | 表达式中间结果等 |

非局部数据本体不都在当前帧，堆对象也不必在帧内；当前帧保存可用于找到它们的信息。

课件 20 说返回字段存“结果存放地址”，课件 22 又示意固定结果槽。两种布局都可实现，但返回时操作不同。本章先讨论共同流程，在 4.3 分别解释；不得把一个字段同时当地址和结果值使用。

## 4. 调用与返回的完整过程

活动记录的字段已经确定，接下来要让一次调用正确取得新帧，返回时恢复原帧。关键是先保存旧指针、结果和控制信息，再更新或回收空间。

### 4.1 分配时必须先保存旧 SP

设调用前 SP=p、TOP=t，被调函数大小 s。新帧首址 new=t。保存旧现场和必要信息，设置新帧 DL=p、RA=返回位置，安排参数和访问环境，再令 `SP=new、TOP=new+s`，转到函数入口。

若先覆盖 SP 再写 DL，可能把新帧自身地址当调用者，返回无法找到旧帧。新 TOP 表示已占区域末尾之后的第一空位，不是最后已用单元。

### 4.2 带数字的申请与回收

主帧从 100 开始，大小 10，初始 SP=100、TOP=110。调用 f，Size=7：新 f 在 110，DL=100，SP=110、TOP=117。f 再调用 g，Size=5：g 在 117，DL=110，SP=117、TOP=122。

| 执行点 | SP | TOP | 当前帧 |
| --- | --- | --- | --- |
| 主程序 | 100 | 110 | 主 |
| f 内 | 110 | 117 | f |
| g 内 | 117 | 122 | g |
| g 返回 f | 110 | 117 | f |
| f 返回主 | 100 | 110 | 主 |

g 返回时先保存其 RA/DL，读取/交付结果及恢复必要环境，再 `TOP=旧SP(117)、SP=DL(110)`，跳 RA。回收改变有效范围，内存字节未必立刻清零；后来帧可以覆盖这段，所以旧局部地址不能继续有效使用。

### 4.3 函数值与共同退出

若结果字段存调用者提供的目的地址，return 通过该地址写值；若规定固定结果槽，调用者返回后读取槽，且必须在复用该空间前读出。调用协议要与参数、字段顺序和生成代码一致。

return 与函数末尾都是可能的退出位置。可以让 return 跳统一退出段，也可以在各退出点生成恢复流程，但一次退出只能回收一帧。不能执行 return 回收后又落到 ENDFUNC 再回收一次。

### 4.4 课件 P/S/Q/R 的调用链

P 为主程序，P 内 Q/S，Q 内 R，R 可以递归。示意调用：`P→S→Q→R1→R2`，帧链为 `[AR(P),AR(S),AR(Q),AR(R1),AR(R2)]`。R2 的动态链指向 R1，R1 指向 Q，Q 指向 S。

R2 返回只释放 R2，R1 仍存在并继续执行；再逐次返回到 Q、S、P。每次 R 有独立 u/v/c/d 槽。课件体中的 c/d 初值未给，不能据该片段推算具体算术结果；这里核对的是结构与调用管理。

## 5. 抽象地址怎样分配

运行时能按 Size 申请帧，编译时仍须先确定每个参数和局部变量在帧内的位置。分配游标记录下一空位，按对象大小前进；进入另一个过程时使用独立游标。

### 5.1 分配游标的含义

`(ℓ,off)` 表示当前可用地址层次与下一空偏移。普通变量 T 从 off 开始，随后 `off+=Size(T)`；值参同样按类型大小；地址参加 1；过函形参加 2。

标签、常量名、类型名的声明不增加普通变量区偏移。实在过函的体有自己的 AR，因此完整处理它后恢复外层游标。进入函数头保存外层 `(ℓ,off)`，切换到 `(ℓ+1,d)`；不能把内部参数算进外层变量区。

### 5.2 课件完整游标例

开始 `(ℓ,10)`，声明 Label 100/200、Const pai、Type arr[1..10]int 后仍为 `(ℓ,10)`。声明 x:int 后为 `(ℓ,11)`，a:[1..5]int 后为 `(ℓ,16)`。进入函数 f 切到 `(ℓ+1,d)`。

| f 的参数 | 当前偏移 | 大小 | 下一偏移 |
| --- | --- | --- | --- |
| var x:real | d | 1 个地址 | d+1 |
| a:arr，值参 | d+1 | 10 | d+11 |
| var c:arr | d+11 | 1 个地址 | d+12 |
| Procedure G | d+12 | 入口/环境 2 | d+14 |
| Function F():real | d+14 | 入口/环境 2 | d+16 |

实在 f 的结果 real 不因此成为父层普通变量；返回值按管理协议安排。体处理完后回到外层 `(ℓ,16)`。大写 G/F 用于课件标记形式过函，不是所有语言都靠大小写决定类别。

### 5.3 并列式语言的地址映射

C 教学模型全局 Level=0，用静态基址 SP0；函数内 Level=1，用当前 SP。直接对象槽为 `SP0+Off` 或 `SP+Off`。嵌套块增加 Scope 深度但不增加地址层。

嵌套式语言则要区分静态外层记录，下面三种方法解决同一定位问题。

## 6. 调用链、声明链与变量访问环境

当前帧可以定位自己的变量，外层名字却不一定属于调用者。要访问非局部变量，必须先区分运行中谁调用谁与源码中谁定义在谁内部，再选出正确的外层活动记录。

### 6.1 动态与静态两种关系

**调用链**记录运行中谁调用谁，例如 `(M,G,H,R,S)`；对应每次调用的 AR 组成**动态链**。**声明链**记录源码中谁定义在谁内部，由词法嵌套确定。

动态链用于返回；声明链用于决定非局部名字来自哪个范围。S 由 R 调用，不代表 S 可以访问 R 的局部。若 S 与 R 同在 H 内，它们是词法同级。

### 6.2 LAR 与课件递归例

课件 **LAR（活跃活动记录）**在其直接调用模型中取某过函尚未返回实例中的最新一帧。调用链 `(M,P1,P2,Q1,R1,R2,R3)`，声明链 `(M,P,Q,R)`，当前环境为 `[AR(M),AR(P2),AR(Q1),AR(R3)]`。

P1/R1/R2 仍在栈中，不能说它们已销毁。这里只是当前 R3 的词法访问环境选取 P2/Q1/R3；返回后之前实例继续执行。

若支持带保存环境的过函参数，具体环境应来自其保存的词法实例，不能全局按“某过程最新帧”猜。课件 LAR 简写须与直接调用假设一起使用。

### 6.3 四种调用情况的统一前缀规则

对可按当前词法可见关系直接调用的 Q，若其过程层 N，调用者环境 E 中前 N 项是 Q 所需外层，则：

```text
Env(Q)=prefixN(E)⊕AR(Q)
```

前 N 项是过程层 0…N-1，追加自身 N，结果长度 N+1。

| 情况 | 新环境 |
| --- | --- |
| 递归，同层 N | 保留外层前 N 项，把本层旧帧换成新帧 |
| 同共同外层的同级调用 | 保留共同外层，追加被调同级新帧 |
| 调用直接内层 N | 保留调用者全部外层与自身，再加子帧 |
| 内层调用外层过程 | 截到被调者的静态外层，再加被调者新帧 |

例如 E=[M,P,Q,R1]，R1 递归 R2 得 [M,P,Q,R2]；R1 调用其外层 Q 的新实例 Q2 得 [M,P,Q2]，不是把 R1 保留为 Q2 的外层。此规则不替代间接调用时显式传来的捕获环境。

## 7. 局部 Display 表

已经知道变量属于哪一词法层，还需要快速取得该层当前应使用的帧首址。局部 Display 在每帧保存一份按层排列的基址表，访问时先查表再加偏移。

### 7.1 每帧保存自己的外层地址表

**Display** 是按过程层数排列的记录首地址表。局部 Display 保存在各自 AR 内。例如过程层 2 的 S，词法外层为 M、R，表为 `[arM,arR,arS]`。虽然调用链可能含 Q，但 Q 若不是 S 的词法外层就不进入其表。

新 Q 过程层 N 时，复制当前环境表前 N 项，再在第 N 项写新 SP。返回以后调用者帧中的旧表仍在，恢复 SP 就能重新使用，无需逐项把被调者表改回去。

### 7.2 地址公式为什么有一次取内容

变量登记层 Lv，对应过程层 L=Lv-1。槽地址：

```text
slot(X)=SP+Off                    自身局部
slot(X)=CurrentAR.Display[L]+Off  外层对象
```

若 Display 从 AR 内偏移 D 起，每项占一个地址单位，则完整第二式为：

```text
slot(X)=Mem[SP+D+(Lv-1)]+Off
```

SP+D+L 是**表项本身的地址**，Mem 读出其中保存的外层 AR 首地址，再加变量偏移。课件 21 第 19 页少这一次取内容，不能直接写成 `SP+D+L+Off`。

### 7.3 课件 M/Q/R/S 的数字展开

M 层 0，Q/R 层 1，S 层 2，S 是 R 内过程。调用 M→Q→R→S。设帧首址 M=100、Q=200、R=300、S=400，Display 偏移 D=6，则 S 的表项在 406/407/408，分别保存 100/300/400。

| 变量 | 登记层与偏移 | 槽地址 |
| --- | --- | --- |
| X，S 的局部 | (3,16) | 400+16=416 |
| Y，R 的局部 | (2,10) | Mem[400+6+1]+10=300+10=310 |
| Z，M 的局部 | (1,12) | Mem[400+6+0]+12=100+12=112 |

实际布局中变量区须避开控制与 Display 区；这里 X 的偏移 16 位于表项之后。数字用于说明先读表再加偏移，不指定真实平台布局。

### 7.4 空间与时间

每次调用复制一段表、每帧占若干地址单位，空间与嵌套深度相关；变量访问则可直接按已知下标取基址。返回不需恢复全局表内容，但仍需恢复 SP、现场与控制信息。

## 8. 全局 Display 表

局部 Display 在每帧复制外层基址，可能重复存储许多相同项。全局 Display 改用一份共享表；难点随之变为调用时怎样保存旧项、返回时怎样恢复。

### 8.1 一个共享表加保存项

**全局 Display** 为程序设置 D[0…maxLevel]。调用过程层 j 的 Q 时：新 AR.Resume 保存旧 D[j]，再把 D[j] 设为新 Q 首址；返回时把保存值还给 D[j]。

只改当前被调层对应项。更深层可能留有旧值，但当前词法范围不会把它们当可见对象使用；访问只能按正确声明链选择合法层。

槽地址 `D[Lv-1]+Off`。全局表保存的是帧首址，不是对象值。递归必须每帧各自保存旧 D[j]，否则内层返回后找不到上一实例。

### 8.2 P/Q/R/S/T 的更新与恢复

课件 P 层 1，Q/R 层 2，S/T 层 3；Q 与 R 同属 P，S/T 同属 R；调用 P→Q→R→S→T。

| 当前过程 | D[1] | D[2] | D[3] | 新帧保存的原项 |
| --- | --- | --- | --- | --- |
| P | arP | 旧值 | 旧值 | 旧 D[1] |
| Q | arP | arQ | 旧值 | 旧 D[2] |
| R | arP | arR | 旧值 | arQ |
| S | arP | arR | arS | 旧 D[3] |
| T | arP | arR | arT | arS |

T 内 X(Lv=2) 在 P，Y(Lv=3) 在 R，Z(Lv=4) 在 T。返回 T 时 D[3] 还原 arS；返回 S 还原先前 D[3]；返回 R 时 D[2] 还原 arQ。

这说明“同过程层有多个帧在栈中”不矛盾：D 选择当前词法环境的一份，其他记录尚未回收，旧表值保存在各帧 Resume 中。

### 8.3 与局部表比较

共享表减少每帧重复的整段 Display 空间，但每次调用/返回要保存改写项。非局部读取仍可按层号直接取得基址。局部表复制成本与深度相关，全局表每层恢复有固定操作；具体选择还要考虑寄存器、间接访问和间接调用环境支持。

## 9. 静态链

如果不想每帧保存整段外层地址表，可以只记住直接词法父帧。访问较远外层时逐层追踪这条链接，用多次读取换取较少的环境存储。

### 9.1 一帧只保存直接词法父帧

**静态链 SL** 指向当前过程的直接词法外层活动记录。沿它连续走可到更外层。动态链 DL 指向调用者，两者用途不同，值也可能不同。

M→G→H→R→S 中层数 0、1、2、3、3，R/S 同在 H 内。S 的 DL 指 R，而 SL 指 H；静态链路径 S→H→G→M，动态链路径 S→R→H→G→M。

因此不能仅凭 DL 找非局部变量，不能让一个指针单元无条件同时承担两种不同链接。课件称 SL 放在原 DL 位置，是字段布局讨论；若两功能都需要，须另有保存调用者的字段或机制。

### 9.2 调用时怎样设置 SL

调用者过程层 m，被调者层 n；要找到 n-1 层的词法父帧。直接调用且词法环境一致时：

```text
k=m-n+1
newAR.SL=Indir(SP,k)
```

子过程 n=m+1，k=0，SL 直接指当前 SP；同级 n=m，k=1，SL 指当前静态父帧；内层调用外层，k 更大，沿链到被调者父帧。

这里 Indir 指沿**静态链字段**，不是任意读 Mem[SP]；字段偏移必须按布局使用。过函参数带环境时应从保存环境取得父帧，不能机械从当前调用者层数算。

### 9.3 使用变量时怎样走链

当前层 m，变量登记层 Lv，所属层 L=Lv-1：

```text
k=m-L
slot(X)=Indir(SP,k)+Off
```

自身 L=m 时 k=0，变成 SP+Off。每走一次 SL 从一层到其词法父层，因此只需按层差走到所属环境。

### 9.4 课件 G/H/R/S 寻址例

设 M=100、G=200、H=300、R=400、S=500，当前层 m=3，S 的 SL 为 H=300，H 的 SL 为 G=200，G 的 SL 为 M=100。

| 变量 | 登记层 Lv | 所属层 L | 走链次数 | 槽地址 |
| --- | --- | --- | --- | --- |
| Z，S 局部 | 4 | 3 | 0 | 500+OffZ |
| Y，H 局部 | 3 | 2 | 1 | 300+OffY |
| X，G 局部 | 2 | 1 | 2 | 200+OffX |

若错误沿 DL 找 Y，第一步到 R=400，就会访问另一个记录。类型和偏移可能都对，基址错误仍导致整个值错误。

### 9.5 三种方法的取舍

| 方法 | 每帧环境信息 | 调用/返回 | 非局部访问 |
| --- | --- | --- | --- |
| 局部 Display | 一段基址表 | 复制前缀；返回使用旧帧表 | 直接下标取基址 |
| 全局 Display | 旧同层项保存等 | 改共享项；返回恢复 | 直接下标取基址 |
| 静态链 | 一个父帧指针 | 定位父帧；返回无需修链 | 按词法层差逐级走 |

Display 用空间或共享表维护换直接定位；SL 省整段表但远外层访问可能多次读。课件的机器条件建议是设计取舍，不能不测具体工作负载就给出绝对性能排序。

## 10. 直接、间接访问与过函参数


### 10.1 找到槽以后还要看 Access

前面的计算只回答“参数或变量槽在哪里”。地址形参的槽中放的是另一个对象的地址，还需区分直接取值与先读地址再取值，才能访问正确对象。

上述公式先取得变量槽地址。direct 的对象就位于槽，值为 Mem[slot]；indir 的槽保存真正对象地址，对象地址为 Mem[slot]，值为 Mem[Mem[slot]]。

例如地址形参 y 在当前帧偏移 8，SP=500，Mem[508]=212，Mem[212]=7。y 的对象值是 7；对 y 赋 9 要写 Mem[212]，不能把 Mem[508] 的地址覆盖成 9。

形式过函、指针及数组地址临时结果也须区分“地址值”与“地址指向的普通值”。地址加法处理基址数值，不应把基址先当对象值读出。

### 10.2 为什么过函形参占两个单位

嵌套函数代码相同，在不同外层调用实例中捕获的数据可能不同。因此传入实在函数时，只有入口地址不足，还须传相应词法环境，如先行 Display 或外层帧引用；形式函数调用利用这对信息建立自己的环境。

这里仅解释课件的入口与环境两槽模型：环境在被调用时必须仍然有效。函数返回后怎样继续保留其局部环境，超出本章已展开的分配方案，不另引入实现算法。

## 11. 综合应用：历年题第二次调用 g 时，哪些对象已经改变


**来源：**期末题一.3，第1—2页。全局 `int x=2`；f(n)内部有`static int x=3`，依次执行`g(n);x--;`；g(m)有局部`y=m-1`，若y>0则执行`x--;f(y);g(y);`；main有局部`x=2`，执行`g(x)`。

这里有三个不同x。只用“当前x=几”记录，会让本来互不影响的对象混在一起。首先按词法范围绑定：main内x属于main；f内x属于f的static对象；g内没有局部x，其使用绑定全局x。然后才按调用次序计算值。

### 11.1 时间点必须说清楚

题目“第2次调用函数g时”没有明确是在入口还是执行`y=m-1`后。以下先给入口情况，再给局部初始化后的情况，保证不把未初始化对象写成已知0。两者栈结构相同，只有新g帧中y是否已有值不同。

| 步骤 | 正在执行的动作 | 调用链 | 全局x | f的static x | 参数/局部变化 |
| --- | --- | --- | --- | --- | --- |
| 1 | main局部x=2，调用g(x) | main→g₁ | 2 | 3 | main.x=2，g₁.m=2 |
| 2 | g₁计算y=m-1 | main→g₁ | 2 | 3 | g₁.y=1 |
| 3 | y>0，执行g₁中的x-- | main→g₁ | 1 | 3 | 此x绑定全局 |
| 4 | g₁调用f(y) | main→g₁→f₁ | 1 | 3 | f₁.n=1 |
| 5 | f₁执行g(n)，进入第二次g | main→g₁→f₁→g₂ | 1 | 3 | g₂.m=1；y尚未初始化 |
| 6 | g₂执行y=m-1 | main→g₁→f₁→g₂ | 1 | 3 | g₂.y=0 |

此时f₁中的x--还没有执行，因为它必须等g₂返回；g₁中后面的g(y)也还没执行。按源码文本顺序把所有x--先算完会提前改变值。

### 11.2 静态区和栈区的文字图

```text
静态区：全局x=1；f内部static x=3（名字局部可见，对象仍在静态区）

栈顶  AR(g₂)：m=1，y=0（仅在完成初始化后）；DL→AR(f₁)
      AR(f₁)：n=1；DL→AR(g₁)；static x没有每调用一份的新槽
      AR(g₁)：m=2，y=1；DL→AR(main)
栈底  AR(main)：局部x=2；DL→外部启动环境/无前驱（题目简化时记NULL）
```

这些调用均为并列定义的C函数，本题只要求动态链。不能把DL当作C变量查找链，让g₂去找f₁的static x。两个g帧参数和y彼此独立；static x共用一份对象，且当前还没有减值。

g₂的y=0使if体不执行，随后返回f₁；f₁才将自己的static x从3减到2，再返回g₁；g₁之后调用第三次g(1)。这些动作发生在 g₂ 返回之后，不能画进“第二次 g 尚未返回”的当前栈。

## 12. 三种非局部访问方法在同一数字例中的结果

三种方法最终都应找到同一个外层变量。下面固定声明关系、调用关系和帧基址，只改变环境表示，检查它们算出的槽地址是否一致。

采用前文嵌套过程M(0)→G(1)→H(2)，H内同级R/S(3)，运行调用M→G→H→R→S。帧基址M=100、G=200、H=300、R=400、S=500；变量Y属于H，Off=10。

| 方法 | 当前保存的环境信息 | 访问Y的具体过程 | 得到的槽地址 |
| --- | --- | --- | --- |
| 局部Display | S的表为[100,200,300,500] | 取下标2基址300，再加10 | 310 |
| 全局Display | 当前D[2]=300 | 直接读D[2]再加10 | 310 |
| 静态链 | S.SL=300 | 从S走一次静态链到H，再加10 | 310 |
| 错用动态链 | S.DL=400 | 走到调用者R再加10 | 410，属于错误记录 |

三种正确方法解决同一问题，输出均是槽地址；如果Y是地址形参，该槽保存另一个对象地址，还要再按Access取地址或取值。静态链与Display都是定位词法环境的实现，动态链则帮助返回调用者，不在这个位置作为同层备选。

## 13. 知识联系与复习


### 13.1 做题顺序

先画声明树并标过程层，再画当前调用实例链；区分 SP/TOP、DL/SL，按当前词法链建立 Display 或 SL。变量登记层减 1 得所属过程层，先求槽，再按 Access 决定是否读地址。调用返回题先保存旧信息，再更新指针，返回前读取结果与控制信息。

### 13.2 自检与参考解释

**1. 同名变量为何有多份地址？** 多次同时活动的调用各有一帧，声明同一份但对象实例不同。

**2. SP 与 TOP 是否总相同？** 不同，SP 是当前帧首址，TOP 是帧末后下一空位。

**3. 返回把栈内容清零吗？** 不必，关键是回收其有效空间；旧地址不能继续合法使用。

**4. 谁调用 S，就用谁的变量吗？** 非局部访问按词法声明链，而返回按调用链。

**5. 变量 Level=3，Display 下标是多少？** Pascal 课件约定是 2；C 的两层模型另按其约定。

**6. `SP+D+L` 等于外层帧地址吗？** 是 Display 表项的地址，必须先读 Mem 得到基址。

**7. 同级调用的 SL 指调用者吗？** 通常指共同静态外层，DL 才指调用者。

**8. 全局 Display 递归返回如何恢复？** 每帧 Resume 保存旧同层项，返回按该帧还原。

**9. 地址参数的大小等于对象大小吗？** 不等于，保存地址的槽按地址长度分。

**10. 函数作为参数为何不能只传入口？** 嵌套函数还需要其对应词法环境。

**11. 普通栈能保留返回后的局部对象吗？** 通常不能；需静态或堆等满足生命周期的策略。

**12. 帧 Size 已知是否意味所有数据静态分配？** 不是，Size 可编译确定，帧数量和具体首址仍在调用时动态变化。

## 14. 自测与答案


| 题号 | 学习任务 | 检查能力 |
| --- | --- | --- |
| 1 | 上述第二次g入口时，两个g的y可否都写为1？ | 区分实例与初始化时点 |
| 2 | 设SP=110、TOP=117，调用大小5的g；它返回时SP/TOP如何变？ | 申请与回收流程 |
| 3 | 当前过程层3调用同级过程层3，静态链应走几次？指向谁？ | 独立计算词法父帧 |
| 4 | 一个函数返回自己的自动局部地址，函数返回后该地址通常还能作为有效对象访问吗？ | 生存期约束 |

### 14.1 答案与理由

1. 不可。g₁.y已是1；g₂入口的y尚未初始化，完成初始化后为0。相同声明的两份运行实例不能混写同一个值，也不能把未初始化写成0。
2. 新帧首址117，DL=110；调用后SP=117、TOP=122。返回先读取所需控制/结果信息，再TOP=117、SP=110，恢复调用者。回收不要求把117—121的所有字节清零。
3. k=3-3+1=1，沿当前SL到共同词法外层，作为新帧SL。新帧DL仍指调用者；二者可能不同。
4. 普通自动对象随返回失去有效存储，旧字节暂未覆盖也不等于对象仍活着。若语言允许保留环境，应采用能延长生存期的静态/堆或其他机制；课件普通栈模型本身不解决这个问题。
