# 07_5 哈希表

## 从问题出发

前面的查找方法（顺序、折半、BST、AVL、B 树）都是基于**比较**的。有没有一种方法可以直接算出元素的位置，不需要比较？

答案是：**哈希表**。它的核心思想是：通过一个函数，把关键字直接映射到存储地址。

```
关键字 key ──→ 哈希函数 h(key) ──→ 存储地址
```

理想情况下，哈希表的查找时间复杂度是 $O(1)$。

## 哈希表的基本概念

**哈希表（Hash Table）** 是根据关键字直接进行访问的数据结构。它通过**哈希函数**将关键字映射到表中的一个位置，以加快查找速度。

**相关术语**：

- **哈希函数**：$h: \text{key} \rightarrow \text{address}$
- **哈希地址**：哈希函数计算出的存储位置
- **冲突（Collision）**：不同的关键字映射到同一个地址，$h(k_1) = h(k_2)$ 且 $k_1 \neq k_2$
- **同义词**：发生冲突的不同关键字

## 哈希函数的设计

好的哈希函数应该：

1. **计算简单**：函数本身不能太复杂
2. **地址均匀**：尽量让关键字均匀分布在整个地址空间，减少冲突

### 常用哈希函数

#### 1. 直接定址法

$$h(key) = key \quad \text{或} \quad h(key) = a \times key + b$$

适用于关键字分布基本连续的情况。

#### 2. 除留余数法

$$h(key) = key \mod p$$

$p$ 通常选择**小于等于表长的最大素数**。例如表长为 100，取 $p = 97$。

这是最简单、最常用的哈希函数。

#### 3. 平方取中法

取关键字平方值的中间几位作为哈希地址。

```
key = 1234
key² = 1522756
取中间 3 位：227
h(1234) = 227
```

适用于关键字位数不多且各位分布不均匀的情况。

#### 4. 折叠法

将关键字分割成位数相同的几部分，然后叠加求和。

```
key = 123456789
分成：123 | 456 | 789
h(key) = 123 + 456 + 789 = 1368
```

## 冲突处理方法

冲突是不可避免的。当冲突发生时，需要有一种策略来找到下一个可用的位置。

### 开放定址法

所有元素都存放在哈希表数组中。发生冲突时，按照某种**探测序列**寻找下一个空位置。

#### 线性探测

$$h_i(key) = (h(key) + i) \mod m, \quad i = 0, 1, 2, \cdots$$

即：冲突后依次检查下一个位置，直到找到空位。

```
表长 m = 7, h(key) = key % 7

插入 18: 18 % 7 = 4, 放到位置 4
插入 25: 25 % 7 = 4, 冲突！
         (4 + 1) % 7 = 5, 位置 5 空，放入
插入 32: 32 % 7 = 4, 冲突！
         位置 5 也冲突！
         (4 + 2) % 7 = 6, 位置 6 空，放入

位置: [0] [1] [2] [3] [4]  [5]  [6]
      空  空  空  空  18   25   32
                    ↑h(18) ↑h(25)↑h(32)
```

**优点**：实现简单。

**缺点**：容易产生**聚集（Clustering）**现象。连续的冲突会导致一大片连续空间被占用，查找时需要探测很多位置。

#### 平方探测

$$h_i(key) = (h(key) + i^2) \mod m, \quad i = 0, \pm 1, \pm 2, \cdots$$

或更常见的：

$$h_i(key) = (h(key) + c_1 i + c_2 i^2) \mod m$$

平方探测可以减小聚集现象，但不能探测到所有位置（当表长为合数时）。

**条件**：表长 $m$ 必须是形如 $4k + 3$ 的素数，才能保证探测到所有位置。

#### 双哈希法

使用两个哈希函数：

$$h_i(key) = (h_1(key) + i \times h_2(key)) \mod m$$

例如：
- $h_1(key) = key \mod m$
- $h_2(key) = key \mod (m - 2) + 1$（保证不为 0）

双哈希法产生的探测序列更均匀，是开放定址法中最好的方法之一。

### 链地址法（拉链法）

每个哈希地址对应一个链表，冲突的元素直接插入对应链表中。

```
表长 m = 5, h(key) = key % 5

插入 10: 10 % 5 = 0  →  [10]
插入 15: 15 % 5 = 0  →  [10] → [15]
插入 20: 20 % 5 = 0  →  [10] → [15] → [20]
插入 7:  7  % 5 = 2  →  [7]
插入 12: 12 % 5 = 2  →  [7] → [12]

哈希表:
  0: 10 → 15 → 20
  1: ∅
  2: 7 → 12
  3: ∅
  4: ∅
```

**优点**：
- 不会产生聚集
- 插入简单（在链表头部插入）
- 表的大小可以动态变化

**缺点**：
- 需要额外的指针空间
- 链表过长时查找效率下降

### 两种冲突处理方法的比较

| 特性 | 开放定址法 | 链地址法 |
|---|---|---|
| 存储 | 所有元素在表中 | 元素在链表中，表存指针 |
| 冲突处理 | 探测其他位置 | 同一位置链成链表 |
| 聚集 | 可能产生 | 不会产生 |
| 空间利用 | 负载因子必须 < 1 | 可以 > 1 |
| 删除 | 复杂（需要标记） | 简单（链表删除） |
| 适用 | 数据量确定，元素较小 | 数据量不确定，元素较大 |

## 哈希表的查找

### 开放定址法的查找

```cpp
// 线性探测
int search(int key) {
    int addr = h(key);
    for (int i = 0; i < m; i++) {
        int pos = (addr + i) % m;
        if (table[pos] == key) return pos;      // 找到
        if (table[pos] == EMPTY) return -1;     // 遇到空位，说明不存在
    }
    return -1;  // 表满且未找到
}
```

### 链地址法的查找

```cpp
Node* search(int key) {
    int addr = h(key);
    Node* p = table[addr];
    while (p) {
        if (p->key == key) return p;
        p = p->next;
    }
    return nullptr;
}
```

## 哈希表的删除

### 开放定址法的删除

不能直接删除元素（否则会导致查找时提前终止）。通常采用**逻辑删除**：标记该位置为"已删除"（DELETED），而不是"空"（EMPTY）。

```cpp
// 查找时需要区分 EMPTY 和 DELETED
int search(int key) {
    int addr = h(key);
    for (int i = 0; i < m; i++) {
        int pos = (addr + i) % m;
        if (table[pos] == key) return pos;
        if (table[pos] == EMPTY) return -1;
        // DELETED 继续探测
    }
    return -1;
}
```

### 链地址法的删除

直接在链表中删除结点即可，不影响其他元素的查找。

## 性能分析

**装填因子（负载因子）**：

$$
\alpha = \frac{n}{m}
$$

其中 $n$ 为元素个数，$m$ 为表长。

| 方法 | 查找成功 ASL | 查找失败 ASL |
|---|---|---|
| 线性探测 | $\frac{1}{2}(1 + \frac{1}{1-\alpha})$ | $\frac{1}{2}(1 + \frac{1}{(1-\alpha)^2})$ |
| 双哈希 | $-\frac{1}{\alpha} \ln(1-\alpha)$ | $\frac{1}{1-\alpha}$ |
| 链地址法 | $1 + \frac{\alpha}{2}$ | $\alpha$ |

**结论**：
- $\alpha$ 越小，冲突越少，但空间浪费越多
- 开放定址法通常要求 $\alpha < 0.75$
- 链地址法可以容忍更大的 $\alpha$，但链表不能太长

## 哈希表的应用

1. **编译器的符号表**：变量名到内存地址的映射
2. **数据库索引**：快速查找记录
3. **缓存系统**：URL 到页面内容的映射
4. **去重**：快速判断元素是否已存在
5. **密码学**：哈希函数用于数据完整性校验

## 小结

- 哈希表通过哈希函数直接计算存储位置，理想情况下查找 $O(1)$。
- **冲突不可避免**，需要好的哈希函数 + 有效的冲突处理策略。
- **开放定址法**：元素都在表中，冲突时探测其他位置。线性探测简单但易聚集，双哈希法更好。
- **链地址法**：每个位置存一个链表，冲突的元素链在一起。实现简单，删除方便。
- 装填因子 $\alpha$ 是衡量哈希表性能的关键指标。
