# 00 课程导览

## 数据结构课程解决什么问题

计算机处理的是数据，但数据不是简单堆砌就能高效使用的。数据结构研究的是：**如何在计算机中组织和存储数据，使得我们能够高效地访问和修改它们**。

想象一个图书馆：

- 如果所有书随意堆放，找一本书需要逐一检查——这就是**无序存储**，查找效率极低。
- 如果按分类和编号排列在书架上，我们可以直接走到对应区域——这就是**有序存储**，查找效率大幅提升。
- 如果需要同时支持"按书名查找"和"按作者查找"，单一排列方式就不够了，可能需要建立多索引——这就是**多对多关系**的存储问题。

数据结构正是为不同的问题场景提供不同的数据组织方案。

## 各章节之间的依赖关系

```
01 绪论
  │
  ├──→ 02 线性表、栈与队列 ──┐
  │                          │
  ├──→ 03 数组、矩阵与字符串  │
  │                          │
  └──→ 04 树与二叉树 ────────┼──→ 07 查找
                              │       （BST、平衡树、哈希）
  ┌───────────────────────────┘
  │
  └──→ 05 图 ──→ 06 排序
                 （拓扑排序依赖图）
```

**依赖说明：**

- **01 绪论**是所有章节的基础，提供分析工具（复杂度）和基本概念（ADT）。
- **02 线性结构**是最基础的数据组织形式，栈和队列广泛应用于后续章节（如树的层次遍历、图的 BFS）。
- **04 树与二叉树**中的二叉搜索树是 07 查找的核心内容之一。
- **05 图**中的拓扑排序概念会引出 06 排序中的部分思想。
- **06 排序**的复杂度分析工具和比较思想依赖 01 绪论。
- **07 查找**大量使用树结构（BST、AVL、B 树）和哈希表，需要先理解 04 树的基本操作。

## 推荐学习顺序

### 主线顺序（适合第一次系统学习）

```
01 → 02 → 03 → 04 → 07 → 05 → 06
```

这个顺序的好处是：先掌握线性结构和树结构，再学查找（大量用树），然后进入图（需要之前所有基础），最后学排序（相对独立，且复杂度分析工具已准备好）。

### 按依赖定位（已有部分基础）

- **看不懂递归和树遍历**：回到 04，重点理解递归的本质和遍历框架。
- **不会分析算法复杂度**：回到 01，重新跟随递推关系的完整推导。
- **图算法总是混淆**：回到 05，用手动模拟 DFS/BFS 的完整执行过程。
- **排序代码写不对**：回到 06，使用交互演示逐步观察执行过程。

## 理论、代码和交互演示之间的关系

本课程每章包含三个层次的内容：

| 层次 | 内容 | 目的 |
|---|---|---|
| **理论讲解** | 问题背景、ADT 定义、算法设计思路、正确性分析、复杂度推导 | 建立概念框架，理解"为什么"和"怎么样" |
| **代码实现** | 完整、可编译运行的 C++ 参考代码 | 将理论转化为实践，观察具体实现细节 |
| **交互演示** | 浏览器端的可视化动画（排序、树遍历、图遍历） | 直观观察算法的完整执行过程，验证理解 |

**建议的学习方式**：先读理论理解核心思想，再看代码掌握实现细节，最后用交互演示验证和加深理解。三个层次互为补充，不要跳过任何一个。

## 学习中的常见误区

1. **只背结论，不理解推导过程**：时间复杂度的结论需要自己会推导，否则遇到变形问题无法分析。
2. **只看代码，不动手运行**：数据结构的代码细节很多（指针操作、边界条件），必须实际运行和调试才能发现问题。
3. **忽视 ADT 的抽象层**：直接跳进代码实现，不理解"逻辑结构 → 存储结构 → 操作实现"的分层思想，导致知识零散。
4. **混淆不同结构的适用场景**：每种数据结构都有它擅长和不擅长的事情，理解场景比记住操作更重要。
