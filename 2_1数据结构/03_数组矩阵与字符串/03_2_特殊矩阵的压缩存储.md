# 03_2 矩阵的压缩存储

普通 $n\times n$ 矩阵需要 $n^2$ 个存储单元。如果大量位置可以由结构规律推知，就没有必要逐个保存。压缩存储的核心是：只保存独立信息，并建立坐标到紧凑数组下标的映射。

## 对称矩阵

对称矩阵满足 $a_{ij}=a_{ji}$。只保存下三角（含主对角线）需要

$$1+2+\cdots+n=\frac{n(n+1)}2$$

个元素。采用 0 起始下标并按行存储下三角时：

$$
k=\begin{cases}
i(i+1)/2+j,& i\ge j\\
j(j+1)/2+i,& i<j
\end{cases}
$$

第二种情况先利用对称性把 `(i,j)` 映射到 `(j,i)`。

## 三角矩阵与对角矩阵

上三角或下三角矩阵只需保存一个三角区域，另加一个位置保存区域外共同的常量。带状矩阵则只保存主对角线附近的若干条对角线；映射通常由“行偏移 + 行内偏移”构成。

设计映射时应先回答三个问题：哪些位置必须保存、它们按什么顺序排列、一个合法坐标之前共有多少个已保存元素。

## 稀疏矩阵

当非零元素数量 `t` 远小于 `rows * cols` 时，可用三元组 `(row, col, value)` 保存每个非零元素。

```cpp
struct Triple {
    int row;
    int col;
    double value;
};

struct SparseMatrix {
    int rows;
    int cols;
    std::vector<Triple> entries; // 按 row、col 递增
};
```

空间从 $O(mn)$ 降到 $O(t)$，代价是不能再用一个乘加直接定位任意元素。若三元组有序，可二分查找；若按行频繁运算，通常进一步保存每行起始位置。

## 稀疏矩阵转置

普通转置可以按目标列依次扫描全部三元组，时间为 $O(nt)$。快速转置先统计原矩阵每一列的非零数，再通过前缀和计算它们在结果数组中的起始位置，最后扫描一次元素，时间为 $O(n+t)$。

设 `count[c]` 是第 `c` 列非零数，`start[c]` 是转置后第 `c` 行的起始位置：

```text
start[0] = 0
start[c] = start[c-1] + count[c-1]
```

放置一个来自第 `c` 列的元素后，将 `start[c]` 加一。这里的前缀和把“某类元素之前有多少项”一次算好，避免反复扫描。

## 压缩的边界

压缩不是无条件更快。规则矩阵的映射计算很便宜，通常值得；稀疏矩阵若逐渐变密，三元组的字段开销和间接访问可能超过普通数组。选择表示方式时，应同时考虑非零比例、访问模式和更新频率。
