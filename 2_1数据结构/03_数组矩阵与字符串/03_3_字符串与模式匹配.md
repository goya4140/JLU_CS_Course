# 03_3 字符串与模式匹配

## 串的定义

**串（字符串）** 是由零个或多个字符组成的有限序列。串是一种特殊的线性表，其数据元素只能是字符。

$$
S = "a_1 a_2 \cdots a_n" \quad (n \geq 0)
$$

其中 $n$ 为串的长度。$n = 0$ 时称为**空串**，用 `""` 表示。

> 注意区分**空串** `""`（长度为 0）和**空格串** `" "`（长度为 1）。

## 串的基本操作

| 操作 | 说明 |
|---|---|
| `StrAssign(&S, chars)` | 赋值，将 chars 赋给 S |
| `StrCopy(&S, T)` | 复制，将 T 复制给 S |
| `StrEmpty(S)` | 判空 |
| `StrCompare(S, T)` | 比较（字典序） |
| `StrLength(S)` | 求长度 |
| `SubString(&Sub, S, pos, len)` | 求子串 |
| `Concat(&T, S1, S2)` | 连接 |
| `Index(S, T)` | 定位（模式匹配） |
| `ClearString(&S)` | 清空 |

## 串的存储结构

### 顺序存储

用定长数组或动态数组存储，末尾以 `'\0'` 或长度标记结束。

```cpp
// 定长顺序串
#define MAXLEN 255
struct SString {
    char ch[MAXLEN + 1];  // ch[0] 闲置或存长度
    int length;
};
```

### 堆分配存储

在程序运行期间动态分配内存。

```cpp
struct HString {
    char* ch;    // 基址
    int length;  // 长度
};
```

C++ 的 `std::string` 就是一种堆分配存储的实现。

### 块链存储

用链表存储，每个结点存储多个字符（块）。

```
┌───┬───┬───┬───┬───┐    ┌───┬───┬───┬───┬───┐
│ # | H | e | l | * │ -> │ l | o | _ | W | * │ -> ...
└───┴───┴───┴───┴───┘    └───┴───┴───┴───┴───┘
  # = 块内字符数    * = 填充符
```

块链存储适合非常长的字符串，但在实际中很少使用，因为 `std::string` 已经足够高效。

## 模式匹配问题

**模式匹配**：在主串 $S$ 中查找子串 $T$ 的位置。$S$ 称为**主串**，$T$ 称为**模式串**。

例如：$S = "abcabaabcac"$，$T = "abaabc"$，求 $T$ 在 $S$ 中的起始位置。

## 朴素模式匹配（BF 算法）

**Brute-Force 算法**是最直观的模式匹配方法：

1. 从主串的第 $i$ 个字符开始，逐个与模式串比较
2. 如果匹配成功，返回位置
3. 如果匹配失败，$i$ 后移一位，重新比较

```cpp
int index_BF(const std::string& S, const std::string& T) {
    int i = 0, j = 0;
    while (i < S.length() && j < T.length()) {
        if (S[i] == T[j]) {
            i++;
            j++;
        } else {
            i = i - j + 1;  // i 回到本轮起始位置的下一个
            j = 0;          // j 回到模式串开头
        }
    }
    if (j >= T.length()) {
        return i - T.length();  // 匹配成功
    }
    return -1;  // 匹配失败
}
```

### 复杂度分析

**最坏情况**：每次比较到最后一个字符才失配。

例如 $S = "aaaaaaab"$，$T = "aaab"$。

| 主串位置 | 比较次数 |
|---|---|
| 0 | 4 |
| 1 | 4 |
| 2 | 4 |
| 3 | 4 |
| ... | ... |

总比较次数约为 $(n - m + 1) \times m$，其中 $n = |S|$，$m = |T|$。

**最坏时间复杂度：$O(nm)$**

## KMP 算法

### 从 BF 的问题出发

BF 算法效率低的原因是：**每次失配后，主串指针 $i$ 都要回溯。**

```
S: a b a b a b c a b c a
T: a b a b a b c a d
            ↑
          失配！

BF: i 回退到位置 2，j 回退到 0，重新开始
KMP: i 不回退！只移动 j
```

KMP 的核心思想：利用**已经匹配的部分**的信息，避免不必要的比较。

### 关键观察

假设在某次匹配中，模式串的前 $j$ 个字符已经与主串匹配，在第 $j+1$ 个字符处失配：

```
S: ... a b a b a b d ...
T:    a b a b a b c
          ↑
        j=6 处失配（下标从1开始）

已匹配部分："ab abab"
```

模式串 `"abababc"` 的前 6 个字符 `"ababab"` 中，前缀 `"abab"` 与后缀 `"abab"` 相等。

这意味着：如果我们把模式串向右滑动，让前缀 `"abab"` 与后缀 `"abab"` 对齐，就可以继续比较，而不需要回退主串指针。

```
滑动前：
S: ... a b a b a b d ...
T:    a b a b a b c
            ↑ 失配

滑动后：
S: ... a b a b a b d ...
T:        a b a b a b c
                ↑ 继续比较
```

### next 数组

KMP 算法需要预先计算模式串的 **next 数组**。`next[j]` 的含义是：

> 当模式串的第 $j$ 个字符与主串失配时，模式串应该回退到第 `next[j]` 个字符继续比较。

形式化定义：

$$
\text{next}[j] = \max\{k \mid 1 \leq k < j, \text{且 } p_1 \cdots p_{k-1} = p_{j-k+1} \cdots p_{j-1}\}
$$

通俗地说：`next[j]` 等于模式串前 $j-1$ 个字符组成的子串中，**最长的相等前缀和后缀的长度 + 1**。

### 计算 next 数组

```cpp
void getNext(const std::string& T, int next[]) {
    int i = 1, j = 0;  // i 扫描模式串，j 记录前缀长度
    next[1] = 0;
    
    while (i < T.length()) {
        if (j == 0 || T[i] == T[j]) {
            i++;
            j++;
            next[i] = j;
        } else {
            j = next[j];  // j 回退
        }
    }
}
```

**手动模拟**：计算 `"abababc"` 的 next 数组（下标从 1 开始）

| j | 子串 | 最长相等前后缀 | next[j] |
|---|------|-------------|---------|
| 1 | "" | 无 | 0 |
| 2 | "a" | 无 | 1 |
| 3 | "ab" | 无 | 1 |
| 4 | "aba" | "a" | 2 |
| 5 | "abab" | "ab" | 3 |
| 6 | "ababa" | "aba" | 4 |
| 7 | "ababab" | "abab" | 5 |

### KMP 匹配过程

```cpp
int index_KMP(const std::string& S, const std::string& T) {
    int* next = new int[T.length() + 1];
    getNext(T, next);
    
    int i = 1, j = 1;  // 下标从 1 开始
    while (i <= S.length() && j <= T.length()) {
        if (j == 0 || S[i - 1] == T[j - 1]) {
            i++;
            j++;
        } else {
            j = next[j];  // i 不回退！
        }
    }
    
    delete[] next;
    if (j > T.length()) {
        return i - T.length() - 1;  // 转换为 0-based
    }
    return -1;
}
```

### KMP 复杂度分析

- **预处理**：计算 next 数组，$O(m)$
- **匹配过程**：$O(n)$
- **总时间复杂度：$O(n + m)$**

> 对比 BF 的 $O(nm)$，KMP 在主串很长时优势明显。

## next 数组的优化（nextval）

KMP 还有一个可以优化的地方：如果 `next[j]` 指向的字符与 `T[j]` 相同，那么回退后仍然会失配，可以继续回退。

```cpp
void getNextVal(const std::string& T, int nextval[]) {
    int i = 1, j = 0;
    nextval[1] = 0;
    
    while (i < T.length()) {
        if (j == 0 || T[i] == T[j]) {
            i++;
            j++;
            if (T[i] != T[j]) {
                nextval[i] = j;
            } else {
                nextval[i] = nextval[j];
            }
        } else {
            j = nextval[j];
        }
    }
}
```

优化后的数组称为 `nextval`，可以进一步减少不必要的比较。

## 小结

- 串是特殊的线性表，元素为字符。
- **BF 算法**：暴力匹配，最坏 $O(nm)$，实现简单。
- **KMP 算法**：利用已匹配信息避免主串回退，时间 $O(n + m)$。
- KMP 的核心是 **next 数组**，表示失配时模式串应该回退的位置。
- 理解 KMP 的关键在于理解"最长公共前后缀"的自我匹配思想。
