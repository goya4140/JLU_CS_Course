# 01_1 数据结构与抽象数据类型

## 从问题出发：为什么需要数据结构

假设你正在开发一个通讯录应用，需要存储大量联系人信息，并支持以下操作：

- 添加新联系人
- 删除某个联系人
- 查找某个联系人的电话号码
- 按姓名排序显示所有联系人

你会怎么存储这些数据？

**方案 A**：把所有联系人信息放在一个普通数组中。

- 添加：如果数组满了，需要申请更大的空间并全部复制过去。
- 查找：从头到尾逐一比较，最坏情况下要检查所有元素。
- 排序：每次显示前都要对整个数组重新排序。

**方案 B**：将联系人按姓名的字典序组织成一棵二叉搜索树。

- 添加：从根结点出发，根据大小关系走到合适的位置插入。
- 查找：同样从根出发，每次都能排除一半的数据。
- 排序：中序遍历即可得到有序结果。

不同的组织方式（数据结构）直接决定了操作的效率。数据结构不是对数据的简单"摆放"，而是**针对特定操作需求设计的组织方案**。

## 基本概念

### 数据、数据元素、数据项

- **数据**：所有能输入到计算机中并被处理的符号的总称。可以是整数、浮点数、字符串，也可以是图像、音频等。
- **数据元素**：数据的基本单位。在通讯录中，一条完整的联系人记录就是一个数据元素。
- **数据项**：构成数据元素的不可分割的最小单位。例如联系人的"姓名"、"电话号码"分别是不同的数据项。

### 数据结构

**数据结构**是相互之间存在一种或多种特定关系的数据元素的集合。数据结构包含三方面内容：

1. **逻辑结构**：数据元素之间的逻辑关系
2. **存储结构（物理结构）**：数据在计算机内存中的实际存储方式
3. **运算**：施加在数据上的操作

## 逻辑结构

逻辑结构描述的是数据元素之间的关系，与计算机的存储方式无关。常见的逻辑结构有四类：

### 集合

数据元素之间除了"同属于一个集合"之外，没有其他关系。

```
  {A}  {B}  {C}  {D}
```

### 线性结构

数据元素之间是一对一的关系。每个元素（除了第一个）有且仅有一个直接前驱，每个元素（除了最后一个）有且仅有一个直接后继。

```
A → B → C → D
```

线性表、栈、队列都是线性结构。

### 树形结构

数据元素之间是一对多的层次关系。每个元素可以有多个后继，但只有一个前驱（根结点除外）。

```
      A
     / | \
    B  C  D
   / \
  E   F
```

### 图形结构

数据元素之间是多对多的关系。每个元素可以有多个前驱和多个后继。

```
A —— B
|  / |
| /  |
C —— D
```

## 存储结构

同样的逻辑结构，在计算机内存中可以有多种存储方式。

### 顺序存储

把逻辑上相邻的元素存储在物理位置上也相邻的存储单元中。通常借助数组实现。

**特点**：
- 可以随机存取（通过下标直接访问任意元素）
- 插入和删除需要移动大量元素
- 需要预先分配固定大小的空间

```
逻辑: A → B → C → D
物理: [A][B][C][D][_][_][_]
      0  1  2  3
```

### 链式存储

不要求逻辑上相邻的元素在物理位置上也相邻，通过指针（引用）来表示元素之间的逻辑关系。

**特点**：
- 只能顺序存取（必须从表头开始逐个访问）
- 插入和删除不需要移动元素，只需修改指针
- 空间动态分配，不需要预先确定大小

```
逻辑: A → B → C → D
物理: [B] at 0x100   [A] at 0x200   [D] at 0x300   [C] at 0x400
      A: data + next→0x100
      B: data + next→0x400
      C: data + next→0x300
      D: data + next→nullptr
```

### 索引存储

在存储数据元素的同时，建立一张索引表，索引表中的每一项（索引项）包含关键字和对应元素的地址。

**特点**：
- 检索速度快
- 需要额外的索引表空间
- 适用于数据量较大且查询频繁的场景

### 散列存储（哈希存储）

根据元素的关键字，通过哈希函数直接计算出该元素的存储地址。

**特点**：
- 查找速度极快，理想情况下 $O(1)$
- 需要处理哈希冲突
- 不适合范围查询

## 抽象数据类型（ADT）

### 什么是抽象数据类型

**抽象数据类型（Abstract Data Type, ADT）** 是指一个数学模型以及定义在该模型上的一组操作。ADT 的定义与它的具体实现无关，只描述"做什么"，不描述"怎么做"。

> **抽象**的本质：分离"接口"和"实现"。使用者只需要知道 ADT 提供了哪些操作、这些操作能做什么，不需要关心内部是如何实现的。

### ADT 的形式定义

ADT 可以用三元组表示：

$$
\text{ADT} = (D, S, P)
$$

其中：
- $D$ 是数据对象（数据元素的集合）
- $S$ 是 $D$ 上的关系集合
- $P$ 是对 $D$ 的基本操作集合

### 示例：线性表的 ADT

```text
ADT List {
    数据对象：D = {a_i | a_i ∈ ElemSet, i = 1, 2, ..., n, n ≥ 0}
    数据关系：R = {<a_{i-1}, a_i> | a_{i-1}, a_i ∈ D, i = 2, ..., n}
    
    基本操作：
        InitList(&L)      // 初始化一个空线性表
        DestroyList(&L)   // 销毁线性表
        ListEmpty(L)      // 判断线性表是否为空
        ListLength(L)     // 返回线性表的长度
        GetElem(L, i, &e) // 获取第 i 个元素
        LocateElem(L, e)  // 查找第一个值为 e 的元素的位置
        PriorElem(L, cur, &pre)  // 获取 cur 的前驱
        NextElem(L, cur, &next)  // 获取 cur 的后继
        ListInsert(&L, i, e)     // 在第 i 个位置插入元素 e
        ListDelete(&L, i, &e)    // 删除第 i 个元素
        TraverseList(L)   // 遍历线性表
}
```

注意，这个 ADT 定义只说明了线性表"是什么"以及"能做什么"，但完全没有涉及这些数据是存在数组里还是链表里——这就是"抽象"的含义。

### 为什么需要 ADT

1. **降低复杂度**：使用者不必关心实现细节，只需掌握操作的语义。
2. **便于切换实现**：同一个 ADT 可以用多种存储结构实现。例如线性表既可以用顺序表实现，也可以用链表实现，对使用者的接口保持不变。
3. **支持模块化设计**：ADT 提供了清晰的模块边界，不同模块通过 ADT 的接口交互。

### ADT 与数据结构的关系

```
        抽象数据类型（ADT）
              │
    ┌─────────┴─────────┐
    ▼                   ▼
逻辑结构           基本操作集
    │                   │
    └─────────┬─────────┘
              ▼
        存储结构（实现）
              │
    ┌─────────┴─────────┐
    ▼                   ▼
顺序存储           链式存储
（数组）           （指针）
```

**数据结构**是实现 ADT 的物理实体，是 ADT 的**一个具体实现**。同一个 ADT 可以对应多种数据结构（例如"列表"这个 ADT 可以用数组实现，也可以用链表实现）。

## 数据结构的三要素

理解一个数据结构，需要从三个维度把握：

| 要素 | 关注点 | 示例（线性表） |
|---|---|---|
| **逻辑结构** | 数据元素之间的关系 | 一对一的线性关系 |
| **存储结构** | 数据在内存中的实际布局 | 顺序存储（数组）或链式存储（链表） |
| **运算** | 可以执行的操作及其实现 | 插入、删除、查找、遍历 |

学习任何一种新数据结构时，建议按照这个框架去理解：

1. 先问：**这种结构的逻辑关系是什么？**（线性？树？图？）
2. 再问：**有哪些存储方式可以实现这种逻辑关系？各有什么优缺点？**
3. 最后：**基本操作在不同存储方式下是如何实现的？复杂度如何？**

## 小结

- 数据结构研究的是数据的**组织方式**，不同的组织方式决定了操作的效率。
- 逻辑结构有四种：集合、线性、树形、图形。
- 存储结构主要有：顺序存储、链式存储、索引存储、散列存储。
- **ADT** 是数据结构的抽象定义，分离了接口和实现，是理解和使用数据结构的关键概念。
