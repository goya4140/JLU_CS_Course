# 01_2 算法与复杂度分析

## 什么是算法

**算法**是对特定问题求解步骤的一种描述，它是指令的有限序列。一个算法应具备以下五个特性：

| 特性 | 含义 |
|---|---|
| **有穷性** | 算法必须在执行有限步后结束，且每步在有限时间内完成 |
| **确定性** | 算法的每条指令必须有确切的含义，相同的输入只能得到相同的输出 |
| **可行性** | 算法中描述的操作都可以通过已经实现的基本运算执行有限次来实现 |
| **输入** | 一个算法有零个或多个输入 |
| **输出** | 一个算法有一个或多个输出 |

> 注意：**程序 ≠ 算法**。程序可以不满足有穷性（如操作系统是一个无限循环的程序），而算法必须有穷。

## 算法效率的衡量

同一个问题往往有多种算法可以解决。如何比较它们的优劣？

### 事后统计 vs 事前分析

**事后统计**：把算法写成程序，实际运行，测量执行时间和内存占用。

缺点：
- 依赖具体的硬件和软件环境，结果难以比较
- 需要先把算法实现出来才能评估
- 测试数据的选取可能影响结论

**事前分析**：在算法实现之前，通过数学分析估算其效率。

优点：
- 独立于具体环境，结果具有一般性
- 不需要实现就可以比较
- 能够揭示算法的本质性能特征

我们主要采用**事前分析**的方法。

## 时间复杂度

### 语句频度

算法执行时间 ≈ 所有语句执行次数之和。我们把一条语句的**执行次数**称为它的**语句频度**。算法的时间开销可以用所有语句频度的总和来刻画。

**示例 1**：计算 $1 + 2 + \cdots + n$

```cpp
int sum = 0;                    // 执行 1 次
for (int i = 1; i <= n; i++) { // i=1 执行 1 次; i<=n 执行 n+1 次; i++ 执行 n 次
    sum += i;                   // 执行 n 次
}
```

总执行次数：$1 + 1 + (n+1) + n + n = 3n + 3$

**示例 2**：嵌套循环

```cpp
for (int i = 1; i <= n; i++) {      // 外层循环执行 n 次
    for (int j = 1; j <= n; j++) {  // 内层循环执行 n 次
        c[i][j] = 0;                // 执行 n² 次
        for (int k = 1; k <= n; k++) { // 最内层循环执行 n 次
            c[i][j] += a[i][k] * b[k][j]; // 执行 n³ 次
        }
    }
}
```

核心操作（乘法）的执行次数为 $n^3$。

### 渐近分析：大 O 记号

实际中，我们不需要精确计算每条语句的执行次数，因为：

1. 不同的编程语言、编译器、硬件会影响常数因子
2. 我们只关心当输入规模 $n$ 很大时算法的增长趋势

因此，引入**渐近分析**，用大 O 记号描述算法的时间复杂度。

#### 大 O 记号的定义

设 $T(n)$ 是算法执行时间的实际函数。如果存在正常数 $C$ 和 $n_0$，使得当 $n \geq n_0$ 时，有：

$$
T(n) \leq C \cdot f(n)
$$

则记为 $T(n) = O(f(n))$。

通俗地说：**$T(n)$ 的增长速度不超过 $f(n)$ 的增长速度**。

#### 简化规则

1. **忽略低阶项**：$3n^2 + 2n + 5 = O(n^2)$，因为当 $n$ 很大时，$n^2$ 项主导了增长
2. **忽略常数系数**：$100n = O(n)$，$0.01n^2 = O(n^2)$
3. **只保留最高阶项**

#### 常见的时间复杂度等级

| 复杂度 | 名称 | 说明 |
|---|---|---|
| $O(1)$ | 常数时间 | 与输入规模无关 |
| $O(\log n)$ | 对数时间 | 每步将问题规模减半 |
| $O(n)$ | 线性时间 | 与输入规模成正比 |
| $O(n \log n)$ | 线性对数时间 | 分治算法常见 |
| $O(n^2)$ | 平方时间 | 双重循环常见 |
| $O(n^3)$ | 立方时间 | 三重循环常见 |
| $O(2^n)$ | 指数时间 | 穷举所有子集 |
| $O(n!)$ | 阶乘时间 | 穷举所有排列 |

**增长速度对比**（$n = 10^6$ 时）：

```
O(1)       < O(log n)   < O(n)       < O(n log n) < O(n²)      < O(n³)      < O(2ⁿ)
1          < ~20        < 10⁶        < ~2×10⁷     < 10¹²       < 10¹⁸       < 爆炸
```

## 空间复杂度

**空间复杂度** $S(n)$ 表示算法执行过程中所需**额外存储空间**的量度，也是输入规模 $n$ 的函数。

> 注意：空间复杂度通常只考虑**辅助空间**，不包括输入数据本身占用的空间。

**示例**：数组逆序

```cpp
// 方案 A：使用额外数组
void reverse(int a[], int n) {
    int* temp = new int[n];   // 辅助空间：n 个 int
    for (int i = 0; i < n; i++) {
        temp[i] = a[n - 1 - i];
    }
    for (int i = 0; i < n; i++) {
        a[i] = temp[i];
    }
    delete[] temp;
}
// 空间复杂度：O(n)

// 方案 B：原地交换
void reverse(int a[], int n) {
    for (int i = 0; i < n / 2; i++) {
        swap(a[i], a[n - 1 - i]);  // 只使用常数个额外变量
    }
}
// 空间复杂度：O(1)
```

## 递归算法的时间复杂度

递归算法的时间复杂度分析需要先建立**递推关系**，然后求解。

### 示例：阶乘

```cpp
int factorial(int n) {
    if (n <= 1) return 1;
    return n * factorial(n - 1);
}
```

设 $T(n)$ 为计算 $factorial(n)$ 的时间，则：

$$
T(n) = T(n-1) + O(1)
$$

展开：

$$
\begin{aligned}
T(n) &= T(n-1) + c \\
     &= T(n-2) + 2c \\
     &= \cdots \\
     &= T(1) + (n-1)c \\
     &= O(n)
\end{aligned}
$$

### 示例：归并排序

```cpp
void mergeSort(int a[], int left, int right) {
    if (left >= right) return;
    int mid = (left + right) / 2;
    mergeSort(a, left, mid);      // T(n/2)
    mergeSort(a, mid + 1, right); // T(n/2)
    merge(a, left, mid, right);   // O(n)
}
```

递推关系：

$$
T(n) = 2T(n/2) + O(n)
$$

使用**主定理**（Master Theorem）或展开法求解：

$$
\begin{aligned}
T(n) &= 2T(n/2) + cn \\
     &= 2[2T(n/4) + c(n/2)] + cn = 4T(n/4) + 2cn \\
     &= \cdots \\
     &= n \cdot T(1) + cn \log_2 n \\
     &= O(n \log n)
\end{aligned}
$$

### 主定理（简化版）

对于形如 $T(n) = aT(n/b) + f(n)$ 的递推式：

- 如果 $f(n) = O(n^{\log_b a - \epsilon})$（某个 $\epsilon > 0$），则 $T(n) = \Theta(n^{\log_b a})$
- 如果 $f(n) = \Theta(n^{\log_b a})$，则 $T(n) = \Theta(n^{\log_b a} \log n)$
- 如果 $f(n) = \Omega(n^{\log_b a + \epsilon})$，则 $T(n) = \Theta(f(n))$

> 初学者不必死记主定理，理解**展开法**的思想更重要：把递归树画出来，逐层求和。

## 最好、最坏、平均情况

同一个算法，不同输入可能导致不同的执行时间。

**示例**：在无序数组中查找某个元素

```cpp
int search(int a[], int n, int key) {
    for (int i = 0; i < n; i++) {
        if (a[i] == key) return i;  // 找到即返回
    }
    return -1;
}
```

| 情况 | 条件 | 时间复杂度 | 说明 |
|---|---|---|---|
| **最好情况** | 第一个元素就是要找的 | $O(1)$ | 不太可能每次都发生 |
| **最坏情况** | 要找的元素在末尾或不存在 | $O(n)$ | 给出了性能上界 |
| **平均情况** | 元素等概率分布在任意位置 | $O(n)$ | 更反映典型性能 |

> 通常我们说一个算法的时间复杂度，指的是**最坏情况**下的时间复杂度，因为它给出了算法性能的上界保证。

## 时间复杂度例题

### 例题 1：嵌套循环

```cpp
int func(int n) {
    int sum = 0;
    for (int i = 1; i <= n; i *= 2) {
        for (int j = 1; j <= n; j++) {
            sum++;
        }
    }
    return sum;
}
```

分析：外层循环 $i$ 从 1 开始每次乘以 2，执行次数为 $\log_2 n$。内层循环执行 $n$ 次。总次数 $= n \log n$。**时间复杂度：$O(n \log n)$**

### 例题 2：次数随外层变量变化

```cpp
void func(int n) {
    for (int i = 1; i <= n; i++) {
        for (int j = 1; j <= i; j++) {
            printf("*");
        }
    }
}
```

分析：内层循环次数为 $1 + 2 + 3 + \cdots + n = \frac{n(n+1)}{2}$。**时间复杂度：$O(n^2)$**

### 例题 3：递归调用树

```cpp
int fib(int n) {
    if (n <= 1) return n;
    return fib(n - 1) + fib(n - 2);
}
```

递推关系：$T(n) = T(n-1) + T(n-2) + O(1)$

展开后形成一棵递归树，每个结点分裂为两个子结点，树的高度约为 $n$。总结点数为 $O(2^n)$。**时间复杂度：$O(2^n)$**

> 这个效率极低，实际计算斐波那契数应使用迭代法（$O(n)$）或矩阵快速幂（$O(\log n)$）。

## 小结

- **时间复杂度**用大 O 记号表示，描述算法执行时间随输入规模增长的趋势。
- 分析时**忽略常数和低阶项**，只保留最高阶项。
- 常见复杂度从低到高：$O(1) < O(\log n) < O(n) < O(n \log n) < O(n^2) < O(n^3) < O(2^n)$。
- 递归算法的时间复杂度通过建立和求解**递推关系**来分析。
- 通常分析**最坏情况**，给出性能上界保证。
- **空间复杂度**关注算法使用的辅助空间。
